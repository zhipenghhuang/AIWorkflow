## 5. 做法

### 技能 `acceptance-and-launch`

# 验收与上线（技能 · 随包生效）

> 用于：`release` 工作流、`change`/`iterate` 的发布交接、`defect-fix` 含部署的收尾。  
> 产出：`{workroot}/50-verification/` 的 UAT/验收记录，`{workroot}/60-release/` 的上线检查单、发布记录、回滚记录。  
> 原则：**没有证据不发布；验证失败先止损，不恋战。**

## 1. UAT / 业务验收

- **范围**：对照需求基线的 AC 与关键用户旅程；明确不验项与理由。  
- **前置**：构建/环境可用；测试账号/数据就绪；已知问题已列；测试报告已出（如有）。  
- **执行**：逐条场景 → 步骤 → 预期 → 实际 → 证据；失败项分类（产品/实现/环境/数据）。  
- **结论**：通过 / 有条件通过 / 不通过；有条件通过必须列明缺口、风险和用户接受记录。  
- **签收**：业务/产品/QA 至少一方签收；未签收不得进入发布审批（除非用户明确豁免并记录）。

## 2. 发布就绪检查（go/no-go 前）

- 构建/版本/提交号一致；制品可追溯。  
- 代码评审、单测、集成/契约测试、安全/依赖扫描结果齐；存量失败有基线对账。  
- 提测单/测试报告/UAT 结论齐；已知问题不瞒报。  
- 配置/数据迁移/依赖/证书/白名单已核对；迁移脚本幂等并已在预发验证。  
- 回滚预案可执行：触发条件、步骤、决策人、数据一致性说明。  
- 监控/告警/日志/值班就绪；发布窗口与影响面已通知。  
- 变更审批/发布审批已取得（按项目档案）。  
- 任一硬项不过 → **NO-GO**；不得以“先上再补”绕过。

## 3. 部署执行

1. 记录发布前状态：版本、构建、数据库/配置快照、健康检查基线。  
2. 按发布说明逐步执行；每步可核对；失败即停。  
3. 部署后先跑**主链路冒烟**，再跑关键回归；不要先跑全量。  
4. 观察日志/指标/告警；观察期内不进行无关变更。  
5. 记录实际步骤、耗时、异常与处置。

## 4. 发布后验证

- 按发布说明“线上验证要点”逐条核；每条有结果与证据。  
- 对照发布前基线看错误率、延迟、吞吐、关键业务指标。  
- 异常分级：可观察/需修复/需回滚；回滚触发条件成立就回滚。  
- 观察期结束出具发布结论：成功 / 带风险成功 / 回滚；遗留项进 `{workroot}/80-retrospectives/`。  
- 更新发布记录、 `{workroot}/INDEX.md`、`activeContext.md`。

### 4.1 渐进发布 / 特性开关 / SLO

- **渐进**：能灰度不一次全量；按用户/租户/地域/比例分批；每批有进入/退出条件与观察窗。
- **开关**：新功能默认关；开关有 owner、默认值、生效范围、清理期限；禁止永久开关堆积。
- **SLO/错误预算**：发布前确认关键 SLI/SLO 与预算；预算不足时降级发布或只修可靠性，不硬上。
- **观察**：对照发布前基线看错误率/延迟/吞吐/业务量；异常按“可观察/需修复/需回滚”分级。
- **回滚演练**：高风险发布前至少验证一次回滚路径（预发/演练环境），记录耗时与数据影响。
- 可观测细则见 `skills/observability-and-instrumentation/SKILL.md`；AI 功能发布另见 `skills/ai-application-engineering/SKILL.md`。

## 5. 回滚

- 触发条件必须可判定（错误率/主链路失败/数据异常/资损风险）。  
- 回滚步骤可执行（谁、在哪、多久、命令/操作序）；数据回滚说明清楚。  
- 回滚前确认决策人；回滚后复跑冒烟与关键回归。  
- 回滚不是失败掩盖：记录时间线、影响、根因，进入复盘。
