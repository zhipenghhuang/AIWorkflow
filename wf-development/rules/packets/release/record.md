# 步骤卡 · release/record

> 状态 = 本 step；全局规则见 `rules/core/global-rules.md`（每步先读并逐条过）；方法在 §6 指定节（打开→执行→回包）。不读他步 packet / 大手册。

## 1. 元信息

- **workflow / step**：`release` / `record`（发布记录）
- **packet**：`rules/packets/release/record.md`
- **角色**：`delivery-lead`（交付/发布/验收编排）。提测就绪 → UAT/验收 → 发布审批 → 部署 → 冒烟/监控 → 发布记录/复盘；本步只做该角色职责；越界交回或升级。
- **上游**：`postrelease`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）
- **后续**：`retro`（进 `retro` 前的 `when=incident_or_major_release`）
- **失败去向**：停在本步，按 §4 门与 §5 规则补齐或升级；不得静默跳过。
- **条件判定 `when:has_deployed`**：本轮部署步骤已成功执行；满足→真，否则跳过本步（不打开本包）。
- **轻量路径**：纯文档/无行为/无 UI/未命中时，可将预检、前端硬门标 `na`（一句理由）；**必开技能与 Claim/HITL 不降**。

## 2. 本步目标

- **目标**：发布记录
- **产出**：发布汇报/发布记录（{workroot}/60-release/）

## 3. 本步硬约束（全局规则 + 本步边界）

> **全局规则**：每步读 `rules/core/global-rules.md` 并逐条过；本步未读不得写 `global=ok`。首行锚带 `global=ok`（偏离写 `global=dev:<原因>`）。

### 本步边界

- 只读本包 + §6 技能 + §7 模板；不通读他步/大手册。
- 必开技能打开→执行→回包；未过 §4 门不得宣称完成。

## 4. 本步门

- 本步无额外 hitl/gate；仍遵守开局意图确认与完成口径。
- **推进**：本步完成后沿父链进入下一未跳过步；口令为单步（只出方案/只出轻量方案/只评审/代码评审/方案评审/只提测/只出清单）或动作清单写明停止/跳转时，以口令/清单为准，即停并输出收尾骨架。

## 5. 本步动作

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

- **本步必开技能（质量不降）**：`acceptance-and-launch` → 见 §6 闭环。

### 本步动作清单

- 技能见 §6 `acceptance-and-launch`（收尾/记录）。
- 汇总：版本/构建、发布内容、实际步骤、验证结果、观察结论、遗留项、回滚（如有）。
- readiness=NO-GO 时记录 NO-GO 原因与下一步，不得写“已发布”。
- 更新 `{workroot}/60-release/发布说明-{版本}.md`、`发布记录-{版本}.md`、根 `CHANGELOG.md`、`{workroot}/INDEX.md`、`activeContext.md`。
- 根 CHANGELOG：产品发版史（版本/日期 + 用户可见capabilities/破坏性/迁移·兼容/安全；产品语言；禁验证命令/接入/文档治理/过程项——验证写发布记录）。
- **多包输入**：优先产品对外变化摘要（工作日志「发布决策」/产品发布说明/范围差量）。
- 无则本包发布说明+缺口一句。
- **软序**：有产品包宜已有发布决策或等价确认。
- 有测试且本版要求准出宜无挡发版 P0。
- 缺他包不阻塞。
- 细则 文档治理规则（工作根/原件根/索引/关版整夹） 版本记录。
- **同时**追加 `{workroot}/work-log.md` 事件=`发版`（索引+条目；链到发布说明与根 CHANGELOG 版本节）。
- 无则按模板建。
- **三分清**：根 CHANGELOG＝发版史。
- 工作日志＝里程碑。
- 计划执行日志＝过程——功能清单勿只写工作日志却漏根/发布说明。
- 发布完成后**建议**是否发 `REL` 结果包。
- 确认后才 `handoff.send`。
- 未回执不得写“已接收”。
- 更新开发计划：S8 发布=完成/回滚，发布记录/证据/下一步链接。
- 输出发布汇报。
- 未verify/未观察项明示。

### 本步规则卡：文档治理

- 外部输入先入站：落 `inbound/{ver|topic}/` 或 `_common/`；登记 `inbound/INDEX.md`；确认后才改名/归档；不把原件迁出 inbound。
- 迭代关账：确认后将迭代绑定文档迁入 `{workroot}/_archive/{yyyyMMdd}-{ver}/`；主档关闭时快照、主档不移动；「并行不关」只落新资料、不归档现行主档。
- 清理只删已知临时/缓存/未引用失败产物；不确定移 `_archive/_pending-cleanup/{yyyyMMdd}/` 并写清单。

本步无前端硬门。不改界面、不做界面验收 → 不跑 capture / parity。
