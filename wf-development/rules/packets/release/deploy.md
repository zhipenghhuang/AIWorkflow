## 1. 元信息

- **workflow / step**：`release` / `deploy`（部署）
- **packet**：`rules/packets/release/deploy.md`
- **角色**：`delivery-lead`（交付/发布/验收编排）。提测就绪 → UAT/验收 → 发布审批 → 部署 → 冒烟/监控 → 发布记录/复盘；本步只做该角色职责；越界交回或升级。
- **上游**：`approval`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）
- **后续**：`verify`（进 `verify` 前的 `when=has_deployed`）
- **失败去向**：停止发布，按回滚预案处理；不得隐瞒失败或继续观察
- **条件判定 `when:release_approved`**：`confirm_deploy` 已批准；满足→真，否则跳过本步（不打开本包）。

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

- **本步必开技能（质量不降）**：`acceptance-and-launch` → 见 §6 闭环。

### 本步动作清单

- 技能见 §6 `acceptance-and-launch`（先读再执行）。
- 按项目档案 发布方式/命令执行。
- 部署前记录版本/构建/配置/数据快照/健康基线。
- **仅生产/正式环境**。
- test/staging 部署不走本步，记录归 S7/`{workroot}/60-release/`（环境部署记录见 readiness 前置说明）。
- 按发布说明步骤逐步执行，每步可核对。
- 失败即停，按回滚预案处置，不继续后续步骤。

- 不要先跑全量。
- 发布说明/发布记录纳入拟提交（如尚未提交）。
