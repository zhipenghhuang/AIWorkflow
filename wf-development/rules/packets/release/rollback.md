# 步骤卡 · release/rollback

> 状态 = 本 step；全局规则见 `rules/core/global-rules.md`（每步先读并逐条过）；方法在 §6 指定节（打开→执行→回包）。不读他步 packet / 大手册。

## 1. 元信息

- **workflow / step**：`release` / `rollback`（回滚）
- **packet**：`rules/packets/release/rollback.md`
- **角色**：`delivery-lead`（交付/发布/验收编排）。提测就绪 → UAT/验收 → 发布审批 → 部署 → 冒烟/监控 → 发布记录/复盘；本步只做该角色职责；越界交回或升级。
- **上游**：`verify`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）
- **后续**：`postrelease`（进 `postrelease` 前的 `when=has_deployed`）
- **失败去向**：升级事故处理；不重复无效操作，不掩盖数据/业务影响
- **条件判定 `when:release_failed_or_direct_rollback`**：入口=回滚，或部署/发布验证失败触发回滚；满足→真，否则跳过本步（不打开本包）。
- **轻量路径**：纯文档/无行为/无 UI/未命中时，可将预检、前端硬门标 `na`（一句理由）；**必开技能与 Claim/HITL 不降**。

## 2. 本步目标

- **产出**：回滚记录

> **全局规则**：每步读 `rules/core/global-rules.md` 并逐条过；本步未读不得写 `global=ok`。首行锚带 `global=ok`（偏离写 `global=dev:<原因>`）。

## 4. 本步门

- **HITL `confirm_rollback`**：出示触发信号/步骤/数据影响/预计时长；确认后执行
- **推进**：本步完成后沿父链进入下一未跳过步；口令为单步（只出方案/只出轻量方案/只评审/代码评审/方案评审/只提测/只出清单）或动作清单写明停止/跳转时，以口令/清单为准，即停并输出收尾骨架。

## 5. 本步动作

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

- **本步必开技能（质量不降）**：`acceptance-and-launch` → 见 §6 闭环。

### 本步动作清单

- 条件步：部署失败或发布验证失败/触发回滚条件才走。
- 技能见 §6 `acceptance-and-launch`。
- confirm_rollback 出示触发信号/回滚步骤/数据影响/预计时长。
- 按发布说明回滚步骤执行。
- 回滚后复跑冒烟与关键回归。
- 记录时间线/影响/证据。
- 回滚不是失败掩盖：进入 postrelease/retro，更新发布说明结论。

本步无前端硬门。不改界面、不做界面验收 → 不跑 capture / parity。
