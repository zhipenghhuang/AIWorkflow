- **workflow / step**：`control` / `check`（阶段门检查）
- **packet**：`rules/packets/control/check.md`
- **角色**：`reviewer-agent`（代码评审/独立核验）。RP/AC/SC↔改动文件↔验证输出对账；只报正确性/需求覆盖/安全/性能/范围/体验三维缺口；核验不替代机器门禁；本步只做该角色职责；越界交回或升级。
- **上游**：`sync`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）

- **失败去向**：停在本步，按 §4 门与 §5 规则补齐或升级；不得静默跳过。

## 4. 本步门

- **GATE `dev-plan` when=dev_plan_required**：**checklist**：跑 `rules/tools/validate_dev_plan.py`（可用时）+ 阶段表/门/证据/下一步人工核；缺项不过
- **条件判定 `gate:dev_plan_required`**：L2+ 或已有 `development-plan.md`；满足→真，否则跳过该闸（步骤不跳过）。
- **推进**：本步完成后沿父链进入下一未跳过步；口令为单步（只出方案/只出轻量方案/只评审/代码评审/方案评审/只提测/只出清单）或动作清单写明停止/跳转时，以口令/清单为准，即停并输出收尾骨架。

## 5. 本步动作

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

- **本步必开技能（质量不降）**：`development-plan` → 见 §6 闭环。

### 本步动作清单

- 技能见 §6 `development-plan`。
- 只读检查，不改代码。
- 可运行 `python rules/tools/validate_dev_plan.py <开发计划路径>`（可用时）。
- 核验：阶段表与当前阶段一致。
- 每阶段“技能”列已填。
- 本阶段输入/产出/证据齐。
- 下一阶段输入具备。
- 风险/变更已更新。
- L2+ 开发计划存在。
- 交接核验：本阶段应发/应收的 HO 是否有回执。
- `handoff-ledger.md` 与计划 是否一致。
- 阻断下游的包是否已升级。
- 未回执不得判阶段完成。
- 多波次（若计划含 W1/W2/波次）：计划总控表（当前阶段/门）带当前波次。
- 门结论有 G{n}-W{k}。
- S2～S5 禁因某波次已过就整行「完成」且输入/证据波次不得陈旧（见 §6 `development-plan` ）。
- 缺口按「阶段/门/缺什么/影响/建议」列出。
- 不替代机器门禁与测试结论。
- 不过门 → 回到对应阶段补。
- 不得把「计划写了」当「已执行」。

本步无前端硬门。不改界面、不做界面验收 → 不跑 capture / parity。
