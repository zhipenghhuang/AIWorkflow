## 1. 元信息

- **workflow / step**：`control` / `sync`（同步阶段与证据）
- **packet**：`rules/packets/control/sync.md`
- **角色**：`iterate-lead`（迭代交付编排）。方案/需求 → 任务清单（含 DoR/DoD）→ 确认节奏 → 编排实施（实施交 implementer）→ 评审/门禁 → 提测 → 总结拟提交；本步只做该角色职责；越界交回或升级。
- **上游**：`run`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）
- **后续**：`check`
- **失败去向**：停在本步，按 §4 门与 §5 规则补齐或升级；不得静默跳过。

## 2. 本步目标

- **目标**：同步阶段与证据
- **产出**：更新后的开发计划

## 3. 本步硬约束（全局规则 + 本步边界）

> **全局规则**：遵守 `rules/core/global-rules.md`（重读按 §7）；本步未按 §7 复核不得写 `global=ok`。首行锚带 `global=ok`（偏离写 `global=dev:<原因>`）。

### 本步边界

- **主从**：本包=本步目的/门槛/门/推进；§6 技能=做法；§7 模板=壳；global-rules=跨步场规则。本步专属门槛以本包为准，不把技能当第二套流程。
- 只读本包 + §6 技能 + §7 模板；不通读他步/大手册。core/defects/collaboration 等具名索引按需打开当前节。
- 必开技能打开→执行→回包；未过 §4 门不得宣称完成。

## 4. 本步门

- 本步无额外 hitl/gate；仍遵守开局意图确认与完成口径。
- **推进**：默认本步完成后即停（仍输出收尾骨架），不打开下一步。仅当本会话是按链、继续、按计划执行或全链入口时，才进入阶段表的下一未跳过步。

## 5. 本步动作

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

- **本步必开技能（质量不降）**：`development-plan` → 见 §6 闭环。

### 本步动作清单

- 本步只同步进度/状态，不自动进入下一阶段。
- 要推进说「按开发计划执行」。
- 先扫 `inbound/` 未登记/变化文件与 `{workroot}/INDEX.md`：有未登记/未吸收文件 → 先走 `intake` 流程/`materials`，不直接改计划。
- 同步 `handoff-ledger.md`：已发送未回执/退回/有条件接收逐条对账。
- 阻断下游的项写入 当前阻塞/下一动作。
- 未回执不得把阶段标完成。
- 读开发计划 → 对照本轮实际进展更新： 计划状态/当前阶段/当前门/下一动作/需人工/健康度/下一步 3 件事。
- 阶段状态/产出/证据/下一步。
- 各阶段对应节链接/结论。
- 风险/决策。
- 变更记录。
- 执行日志（追加）。
- 计划状态：草稿/已确认/执行中/变更中/待关闭/已关闭。
- 门结论写「通过/不通过/有条件通过 + 批准人/日期/条件」。
- 多波次：总控表带当前 Wn。
- 门结论 `G{n}-W{k}`。
- S2～S5 叠写各波次，禁假完成/陈旧输入（§6 `development-plan` ）。
- 波次切换须同轮改总控表+阶段表+门结论。
- 只写现行有效。
- 不复制 PRD/方案/任务正文。
- 证据链接必须可打开。
- 未验证写「未验证」。
- 发现开发计划与代码/文档不一致 → 以代码/本轮验证为准，先修开发计划。
- 输出：当前阶段、门状态、缺口、下一步。
- 需要用户决策的放最前。

本步无前端硬门。不改界面、不做界面验收 → 不跑 capture / parity。
