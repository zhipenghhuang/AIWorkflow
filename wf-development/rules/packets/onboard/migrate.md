## 3. 本步硬约束

### 全局硬约束（本包已带齐 · 每步都遵守）

- 1. 先判后动；未确认禁写/禁结论；批量不豁免。
- 2. 先查事实；仍不明一次一问（附候选/推荐）。
- 3. 核前提/来源/变量/成本；不迎合；用户有误直接指出。
- 4. 劣解先说依据+主推；用户坚持记 `deviation=`。
- 5. 先权衡；失败 2 次换路径。
- 6. 改前说文件；最小改动；超范围先停。
- 7. 完成只认 `-Claim` → `CLAIM: ALLOWED`；无 ALLOWED 不写完成/通过/可提测。有 UI 按本包前端硬门；无 UI 标 `na`。
- 8. 收尾六点；只读 2～3 行；主动发现 ≤3。
- 9. 只写现行；删除即移除；不写历史/旧方案。
- 10. 读链：开局卡 → `_chain` → 当前包 → §6 skill → 模板 ≤1；同时只 1 包。
- 11. §6 必开 skill 打开→执行→回包；禁粘贴代替。
- 12. 切步/过门心跳带 `packet=`/`role=`/`task=`；长任务先报进展。
- 13. 用户当轮指令优先；与硬门冲突先说明再二选一。
- 14. 证据先于结论；禁刷绿；密钥零入库。
- **效力**：以上为执行摘要（全文见开局卡 §1）；开局已读则中段不重开全文，**每步仍须逐条遵守**；与开局卡重复不影响。

- **不靠跳转拼流程**：本步所需规则已写在本文；他步/他链可有相同条文，互不依赖。

## 4. 本步门

- **HITL `confirm_docs_migration`**：出示分类/覆盖对照/拟归档或清理清单与目标；确认后执行
- **条件判定 `hitl:docs_migration_needed`**：将搬迁/归档/清理且清单未确认；满足→真，否则跳过该门。
- **推进**：本步完成后沿父链进入下一未跳过步；口令为单步（只出方案/只评审/代码评审/方案评审/只提测/只出清单/轻量方案）或动作清单写明停止/跳转时，以口令/清单为准，即停并输出收尾骨架。

## 5. 本步工作规则（编排）

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

### 本步动作清单

- 「重新接入」先扫描旧结构，按 本包 §5 文档治理规则 做覆盖对照，列迁移/改名/归档候选，经 `confirm_docs_migration` 确认后执行，不静默丢文件。
- docs 步不再重复确认。 **工作根**按 本包 §5 文档治理规则 定位。
- **原件根 `inbound/`** 只登记/整理，主副本不迁入 `{workroot}/`。 `keep`/`mix`/`replace` 只管原件结构（仍无 `_archive/`）。
- 均允许索引/复制/吸收。原件禁止迁入 `{workroot}/`。 旧 `inbound/项目文档/{ver}/`、`inbound/原始素材/`、旧扁平前缀 → `inbound/{ver|topic}/` 或 `inbound/_common/`。
- 旧工作区 `inbound/` 副本先判定，不直接当原件。
- 材料库只收定稿。 更新 `project-profile.md`、`{workroot}/INDEX.md`、`inbound/INDEX.md`、`docs/materials/INDEX.md`、开发计划链接、activeContext。
- `activeContext` 合并节 `### 洞见 偏好 易踩坑` → 按 工作记忆：偏好/洞见/坑 ≤3 行 拆为 `### 生效中的偏好` + `### 洞见与易踩坑`，逐条补范围/期限/来源并删过期项。
- 不新增空节。冲突/无法判断先问一次，不覆盖。 迁移后核对链接，再进入 docs/control 步。

### 本步规则卡：文档治理

- 外部输入先入站：落 `inbound/{ver|topic}/` 或 `_common/`；登记 `inbound/INDEX.md`；确认后才改名/归档；不把原件迁出 inbound。
- 迭代关账：确认结束当前迭代后，主计划/四卷/报告/CR/交接落 `{workroot}/_archive/`；「并行不关」只落新资料，不归档现行主档。
- 清理只删已知临时/缓存/未引用失败产物；不确定移 `_archive/_pending-cleanup/{yyyyMMdd}/` 并写清单。

本步无前端硬门。不改界面、不做界面验收 → 不跑 capture / parity。
