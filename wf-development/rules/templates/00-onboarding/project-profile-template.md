## 5. 同步规则

1. **任务开始**：按 `AGENTS.md` §0 硬短读本档案 **§1 + §2 表**（名称/一句话定位/阶段/协作模式/流程偏好 + 代码地图与命令）；§2 命中且足以支撑本任务 → 免重复探查。细节节按任务命中再读，禁止每任务通读全文。  
2. **资料不足升级**：§1/§2 空壳/占位/命令不可用/与代码冲突 → 入口判定 §5（README + 有界探查）→ 同轮回写命中节与 `activeContext` 总览；收尾【资料补强】提示后续受益。  
3. **收尾回写**：任务中新发现的目录/入口/命令/坑/决策 → 就地补进对应节；只写**现行有效**（删即去，不堆历史；**覆盖终态**，不追加过程句）；接入/迁移/归档事件进工作日志或归档清单，不进档案格；推断标「假设/待验证」。  
4. **与实现冲突**：以代码与本轮验证为准，先更新档案再动手。§1「更新服务器部署」与 §8.1 / 本轮部署事实冲突（含「无/未接入」却已有现行命令）→ 同轮改正；源码托管 URL 不进部署格。  
5. 档案变更**不**触发包自检；`wf-development/rules/tools/Test-Template.ps1` 仅改包后 / 点名自检时运行（`rules/core/maintenance.md` §2）。  
6. **可用工具**：状态变化时更新 `{workroot}/capabilities/00-能力清单.md`，并刷新 §6 索引。  
7. **项目规范（§7）**：技术栈/约束变化 → 就地更新。  
8. **交付治理（§8）**：环境/发布/审批/门禁变化 → 就地更新。  
9. **文档（§9）**：文档根/分类/归档变化 → 就地更新并同步 `{workroot}/INDEX.md`。
10. **长期记录（§9）**：用户可见版本关闭/发布 → 更新根 `CHANGELOG.md`（产品发版史）；岗位里程碑写 `{workroot}/work-log.md`；归档按 `rules/doc-governance.md` §7 执行。
