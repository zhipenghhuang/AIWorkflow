# 实施质量门（开发轨）

> **单一出处**：防「方案写复杂、实现简化、自测锁错、沿用免验、裁剪变永久缺口、先主路径后补防护」。  
> **优先级（硬）**：**理解正确 → 一次做对**；自测/完成门/缺陷修复只是兜底，不得用「以后靠验证捞」代替忠实落地。  
> `AGENTS.md` / 技能 / workflow 步注只留指针；细则与判定只认本文。  
> **读取时机**：`plan` 拆单前；`implement`/`solo.build` **动手前必读** DEV-IQ-09/10/**12** 与 §4；`verify`/`deliver` 前；缺陷 `triage`/`fix` 归因时；维护改规则时。  
> **不适用**：纯文案/配置且无行为变化（L0）；写「不适用 + 理由」即可，不硬套全表。

### 1.1 原型解码与前端对齐（DEV-IQ-13/14 执行法）

1. **先确认原型载体**：单 HTML 原型常把 `app.js`/`views-*.js` 以 `data:text/javascript;base64,...` 或 `data:text/javascript;charset=utf-8,...` 嵌入 `<script type="importmap">`。
   - 不要用 `grep 回票 file.html` 判定缺失；先跑 `python rules/tools/extract_prototype_modules.py <原型.html> <输出目录>` 解码模块。
   - 至少枚举：路由名、`nav-btn`/`nav-child`、`extends DocsView`/`extends DocDetailView`、列表列、详情区块、状态/空态。
2. **写对齐矩阵（任务卡内）**：

   | 路由 | 导航层级/文案 | 复用组件 | 列表列/详情区块 | 状态/空态 | 与方案冲突 |
   | --- | --- | --- | --- | --- | --- |

3. **写冲突清单**：原型 vs 方案 vs 现有实现，逐条标 `采用/待确认/OPEN`；命名、单合同/多合同、详情路由单复数、统计页 vs 单据列表都算冲突。
4. **只允许两种实现**：复用现有页面壳/组件并做最小扩展；或按原型新组件但必须矩阵明确。**禁止**“路由有了就自己写一个表”。
5. **验收**：桌面 + 移动截图；与同类页面并排对照；截图不可见 → `UNVERIFIED`。DOM 有文字、接口 200、class 名正确均不能替代视觉验收。
6. **执行回指（持续对照）**：任务卡 SC/AC 必须带来源文件 + 章节；`implement` 每条 SC 编码前回看对应来源，`review`/`verify` 抽核也回指原文章节；禁止只凭记忆或摘要。来源更新、出现新版本/新输入、或到波次检查点（CP）时，必须重跑来源覆盖矩阵并更新差异；未回指不得标完成。

## 2. 判断维度（取轻 / 取重）

| 维度 | 取轻 | 取重 |
| --- | --- | --- |
| 决策影响 | 纯展示/文案 | 权限、资金、合规、发布准出、多人协作验收 |
| 不可逆性 | 可逆配置 | 数据迁移、唯一约束、状态终态、破坏性 API |
| 协调面 | 单模块单角色 | 多角色、多表面（列表/详情/预览/打印/归档）、跨系统 |
| 证据强度 | 解释/草稿 | 对外承诺、提测、准出、审计 |

命中任一「取重」→ DEV-IQ-01～03、05～06、**09～10、12** 不可省；拿不准按取重。  
有行为变化的 L1+ → **至少** DEV-IQ-09（短预检）+ 命中面的 DEV-IQ-10；有方案/PRD 行为条款 → **另加** DEV-IQ-12（抽全差集=0 + 禁语义替换）。

## 3. 实施预检与重要面硬补（DEV-IQ-09 / 10）

> AI **必须自主判定**，不因用户未提安全/性能/失败路径而跳过。  
> 输出可短；**禁止**通读全部子技能——仅加载命中面当前节。

### 3.1 扫描表（写代码前逐行判）

| 面 | 命中信号（示例，非穷尽） | 命中后必须（硬补最小集） | 技能（只读当前节） |
| --- | --- | --- | --- |
| 鉴权/权限 | 登录态、角色、资源级、写 API、菜单/按钮可见 | 角色正反自测；UI 可见 ⇒ API 允许；服务端校验 | `cross-layer-consistency` 权限矩阵 |
| 写路径/幂等 | 创建/更新/上传/提交/回调/重试入口；方案「X→Y」生成/下发；扩表后旧 insert/save | 第二次写 + 冲突业务码 + 并发或重试各 ≥1 自测；**同批**接到既有创建/生成/下发入口（禁止只做查询补齐/旁路服务且旧入口未改）；扩 NOT NULL/默认列须在旧写路径赋值或等价 `onInsertValue`，禁止指望「旁路完成旧路径碰巧可用」 | `cross-layer-consistency` 写路径矩阵 |
| 状态/多表面 | status/草稿/正式/归档；列表≠详情文案 | 非法跃迁自测；多表面标签一致；单一谓词 | 同上 · 状态矩阵 |
| 安全敏感 | 密钥、PII、上传、对外回调、鉴权旁路、公共 API | 输入校验；至少 1 条越权/注入/泄露负面用例；密钥零入库 | `threat-modeling` 相关威胁节 |
| 外部调用/失败 | HTTP、队列、第三方、文件 IO、超时 | 超时；错误映射；幂等重试边界；禁空 catch | `engineering-quality` §1#4 / §2#6 |
| 数据/约束 | 唯一约束、迁移、终态、破坏性 API | 冲突码非 500；回滚/开关或债项；取重升档 | `database-design`（涉库时） |
| 输入校验形态 | 方案写正整数/精度/日期顺序/枚举/可空未知；数量或日期写入口 | **拒绝**非法输入（业务码）；禁止静默截断、默认改写、近邻算法顶替（DEV-IQ-12） | 本文 §4.2 |
| 页面字段清单 | 方案/原型列了列表列、筛选项、表单枚举 | 列/筛/枚举与原文同批落地或债项；禁止「详情有、列表后补」口头化 | 本文 §4.1 |
| 性能敏感 | 列表/批量/导出/循环查库/无界集合 | 量级假设或债项；防 N+1/无界；禁止静默「以后优化」 | `performance-and-capacity` §1～§3 |
| 异步/可观测 | 新异步任务、动作码、需对账终态 | 提交+终态可关联（DEV-IQ-07）；缺则债项 | `observability-and-instrumentation`（新观测点时） |

- **兼容/过渡层**：必须有显式开关或迁移标记；禁止用「权限为空/无角色/旧角色标签」推断旧模式，防止新用户/停用角色回退越权。
- **旧测试更新**：旧断言与新 AC/产品结论冲突时，允许更新断言，但必须引用 AC/决策并登记；禁止无理由删除/跳过/改断言迁就实现（DEV-IQ-02）。

未命中行写「不适用 + 一句理由」；**禁止**整表空白或只写「无风险」。

### 3.2 【实施预检】最小形状

```text
【实施预检】level=L? | 命中=鉴权,写路径 | 不适用=性能(单条查询无列表) | 拟补SC/测/防护=SC-0x… | 技能=cross-layer§2.2
```

落点：对话首条实施回执 **或** 任务卡「实施预检」行；L2+ 建议同步 `acceptance.implement_preflight=done`（未跑=`missing`；L0=`na`）。

### 3.3 禁止合理化

| 借口 | 处理 |
| --- | --- |
| 先跑通再补安全/失败/并发 | 违规 DEV-IQ-10；同批硬补或 DEV-IQ-05 债项 |
| 用户没提就不做负面路径 | 违规 DEV-IQ-09；自主扫描 |
| 框架/ORM/前端隐藏会处理鉴权 | 仍要服务端校验 + 拒绝路径自测 |
| 小改动不用预检 | L0 无行为可 `na`；有行为变化至少短预检 |
| 先做查询补齐/旁路，生成时再接 | 违规写路径硬补；方案写「生成/创建/下发时」须同批落真实写入口，或 DEV-IQ-05 债项 |
| 新模块单测绿即可，旧 save/insert 下轮再验 | 违规写路径硬补与 DEV-IQ-06；扩表/旁路同批验旧写入口 |
| 先主路径，列表字段/枚举/追溯下轮再补 | 违规 DEV-IQ-10/12；同批落地或 DEV-IQ-05 点名债项 |
| 类型强转/默认值「也能用」代替拒绝 | 违规 DEV-IQ-12 §4.2；方案写拒绝则必须拒绝 |
| 未支持方法套近邻已实现算法先绿 | 违规 DEV-IQ-12；须明示不可用或债项，禁止静默顶替 |
| 验证/QA 会扫到，开发可先简化 | 违规优先级句；验证是兜底不是理解替代 |

## 4. SC 清单与执行忠实（DEV-IQ-01 / 12）

写入任务卡（可用表）：

| SC | 原文要点（必须/允许/不得/Then） | 来源§ | 实现落点 | 入口类型 | 自测/证据 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| SC-01 | {…} | {文档§} | {文件/接口/列} | create/generate/submit/query-enrich/na | {命令/用例} | 未开始/完成 |

**入口类型**：方案写「生成/创建/下发/提交时」→ 只允许 `create|generate|submit`；`query-enrich` **不得**单独支撑该类 SC（无债项则开工非法）。

### 4.1 抽全差集（开工前）

**每个 Then / 异常分支至少一行。** 有则必抽，无则写不适用：

1. 主路径一次成功  
2. 第二次写 / 补传 / 重试  
3. 同内容异名或同键冲突  
4. 未确认 vs 已确认（或等价中间态）  
5. 冲突时的人工处置入口（不得只有硬拦且无可操作下一步）  
6. 角色允许 + 拒绝；UI 可见 ⇒ API 允许  
7. **业务触发链（有则必抽）**：方案/AC 写「X 发生 → 产生或更新 Y」时，须有独立 SC；「实现落点」列必须写**真实写入口**（创建/生成/下发/提交等生产路径的类或接口），**禁止**只写「查询时补齐 / enrich / 打开详情再算」且无债项；「自测/证据」列须指向对该入口的红探针（先于或同批于实现）  
8. **字段/枚举/可空（有则必抽）**：方案或原型列出的列表列、筛选项、表单枚举、可空与「未知」标记 → 各至少一行 SC 或债项  
9. **跨章通用规则（有则必抽）**：文档中约束本写入口的通用校验（数量精度、日期顺序、单位、整数/小数等），即使不在本功能专章，也须**挂到本模块写入口 SC**；禁止「只抽本功能专章」

开工门：**未进 SC 且无债项的本期条款数 = 0**；预检命中面 → **先扩 SC 再实现**。  
无 SC 表 → 不得进入 `implement`（L0 无行为变化除外）。  
触发链落点未钉真实写入口 → 未满足 DEV-IQ-01/12，不得开工写旁路。

### 4.2 禁止语义替换（通用反模式）

编码时**不得**把方案约束改成「近义但更省事」的行为（拿不准 → OPEN，禁止猜）：

| 原文语义（示例类） | 禁止改成 |
| --- | --- |
| 生成时 / 创建时 / 提交时固化或写入 | 仅查询/打开详情时再补齐 |
| 拒绝 / 校验失败 / 不得入库 | 静默截断、夹紧、默认改写后成功 |
| 未支持 / 暂不可用 | 套用近邻已实现算法并返回成功 |
| 可空 / 未知可留空并标记 | 改成必填，或留空但不标未知 |
| 生命周期起点（首建/首版/首次登记） | 只做补交/修订/二次路径 |
| 列表须展示的列/筛 | 仅详情可见，列表省略且无债项 |

### 4.3 编码纪律（SC 驱动）

- 只按未完成 SC 逐条改代码；每条 SC 完成须可指回 diff/接口/列。  
- **半实现 = 未完成**：缺字段、缺枚举、缺状态落态、缺首建入口、追溯关键字段空壳 → 不得标该 SC/功能完成。  
- **类型不得吞掉方案精度**：方案要求整数/小数/单位精度时，入口类型必须能保留原始值并显式校验；禁止用会静默截断的类型接收后再校验（截断后已丢失原始事实）。  
- **批量更新须排除新插入行**：先插入新版本/新行、再按状态批量更新旧行时，必须按版本号/主键显式排除新行，并加“新行不被覆盖”回归。  
- 扩表/新约束时：**同批**保证旧写入口（保存草稿/报工生成/门户首建等）仍符合 SC，或点名债项（与 DEV-IQ-06/10 同向）。

## 5. 自测诚信（DEV-IQ-02）

- 先对方案，再对代码；绿测证明「实现与 SC 一致」，不是「实现与自己一致」。  
- 发现用例在断言方案禁止/未要求的行为 → 停：改实现，或提产品改方案并走变更；**禁止**改测试预期刷绿。  
- 边界/错误路径至少各 1；命中跨层或 DEV-IQ-10 面时，按该面最小自测集留证（角色正反、第二次写、空缓存+既有行、越权/超时等）。  
- **证据保真（触发链）**：方案/AC 写「X 发生时 → Y」时：
  1. 单测可测谓词与分支；  
  2. 任务 `COMPLETE` / 提测声称该 AC「主路径通过」时，须至少 1 条**真实入口**证据（走业务创建/生成/下发等入口，或等价集成调用真实写入路径；命令+结果或浏览器均可）；  
  3. **禁止**仅手工插库行、仅 mock `insert`、或仅打开预置对象再查询，冒充该触发链 AC 已全覆盖；  
  4. 合成数据 / 纯 API 代替点名 UI → 只能标「组件/谓词通过」，不得标该 AC 全覆盖（与测试包「仅 API 绿 ≠ 该条通过」同向）。

## 6. 裁剪与债项（DEV-IQ-05）

待决项或任务卡登记示例字段（示例非穷尽）：

| DEBT/OPEN | 豁免的 Then/AC | 理由 | 补齐触发 | 阻塞提测？ | 状态 |
| --- | --- | --- | --- | --- | --- |
| DEBT-01 | {US-xx Then …} | {成本/依赖} | {下一迭代/条件} | 否（已声明）/是 | 开放 |

- 提测单「已知问题与限制」必须能对上债项 ID 或明确写「无裁剪」。  
- 测试验收边界 = **本期承诺 AC ∪ 未豁免基线 Then**；不得默认「DOC 全文已交付」。  
- 重要面硬补若本期砍掉 → **必须**债项化，禁止口头推迟。  
- 功能开关「仅声明未接线」或「本期实现却验收关」→ 走 DEV-IQ-11 + 本表债项，禁止口头豁免。

## 7. 基线再验（DEV-IQ-06）

增量交付前，对声明「沿用」的模块跑最小冒烟（按项目裁剪，缺项写不适用+理由）：

| 检查 | 通过标准 |
| --- | --- |
| 角色正反 | 开放角色可完成主路径；拒绝角色 API/UI 一致 |
| 多值/第二次写 | 补传/重传不 500；冲突有业务码与处置 |
| 状态多表面 | 同一状态在列表/详情/预览/打印/归档标签与水印不矛盾 |
| 异步可观测 | 提交与终态（成功/失败）可关联查询（或已债项化） |
| 本期新建写入口 | 本期新增/改写的创建草稿、生成任务、下发请求等入口至少 1 次真实触发成功（或写不适用+理由）；证据保真同 §5 |

证据写入开发自验/提测自检；无证据不得写「基线无回归风险」。

## 8. 与完成门的关系

- 机器门（`completion-gate`）仍只认脚本可检项；本文条目以 **checklist / 验收清单字段 / 评审记录** 为载体。  
- L2+ `.gate/acceptance.yaml` 建议含：`implement_preflight`（done/na/missing）、`sc_trace`、`cross_layer`、`baseline_smoke`、`debts`。有行为变化却 `implement_preflight=missing`，或取重缺项 → verify 不得报「通过」完整完成（可 `PARTIAL` 并列缺口，或 `BLOCKED`）。  
- 报告措辞：未满足 DEV-IQ-* 不得使用「完成/已修复」声称全覆盖。

## 9. 降级路径

| 情况 | 处理 |
| --- | --- |
| L0 无行为变化 | 全文不适用；一句理由（含预检 `na`） |
| L1 有行为、未命中跨层/重要面 | DEV-IQ-09 仍须短预检；03/06/10 可写不适用；01/02/04/**12**（有方案条款时）仍有效 |
