> **读取级别：参考（词典）**。日常 implement **先勾** `iq-checklist.md`；有 UI 运行时只认当前步骤包内「前端硬门」（维护真源 `frontend-gate.md`）。  
> **本文**：DEV-IQ ID 释义与长表；按命中节读，禁止通读当开局必读。

> `AGENTS` / 技能 / workflow 只留指针。

### 1.1 原型解码与前端对齐（DEV-IQ-13/14/17 执行法）

1. **先确认原型载体**：单 HTML 原型常把 `app.js`/`views-*.js` 以 `data:text/javascript;base64,...` 或 `data:text/javascript;charset=utf-8,...` 嵌入 `<script type="importmap">`。
   - 不要用 `grep <业务关键字> file.html` 判定缺失；先跑 `python rules/tools/extract_prototype_modules.py <原型.html> <输出目录>` 解码模块。
   - 至少枚举：路由名、导航按钮/子菜单（或项目等价选择器）、页面壳/基类（或项目等价结构）、列表列、详情区块/字段网格、筛选项、日期/期间控件、状态/空态、权限可见性。
2. **写对齐矩阵（任务卡内 + `.gate/frontend/parity-matrix.md`）**：

   | 路由 | 导航层级/文案 | 复用组件 | 列表列/详情区块/字段网格 | 交互/筛选/日期 | 状态/空态/权限 | 与方案冲突 |
   | --- | --- | --- | --- | --- | --- | --- |

   - 详情/表单类页面必须逐字段列网格，不得用「简化单列」代替；金额区/状态区/按钮位置单列。
   - 日期/期间控件必须写清页面语义：是「截至当前累计」「按期间」还是「按自定义区间」；禁止把通用筛选生搬到不适用页面。
3. **写冲突清单**：原型 vs 方案 vs 现有实现，逐条标 `采用/待确认/OPEN`；命名、单实体/多实体语义、详情路由单复数、统计页 vs 明细列表、入口层级都算冲突。
4. **写路由/菜单/深链台账（`.gate/frontend/route-coverage.json`）**：
   - 一级/二级菜单逐条：`label/level/route/visible/reachable`；在 1440×900 与 1280×720 下都要可见或可滚动到达，展开项不得把同级挤出可视区。
   - 深链逐条：`route/expected/status/evidence`；新建、详情、授权、统计钻取等关键深链必须直达，不得 404/落列表。
   - 路由逐条：`route/page/status/desktop/mobile/console_errors/failed_requests`；每条路由都要桌面+移动截图，截图哈希不得跨路由复用。
5. **只允许两种实现**：复用现有页面壳/组件并做最小扩展；或按原型新组件但必须矩阵明确。**禁止**“路由有了就自己写一个表”。
6. **验收**：桌面 + 移动截图；与同类页面并排对照；逐路由看 `route-coverage.json` 是否覆盖；截图不可见 → `UNVERIFIED`。DOM 有文字、接口 200、class 名正确、测试绿均不能替代视觉验收。
7. **前端回指**：UI 项按 DEV-IQ-22 先对齐方案/原型原文（含文案/布局/空态等细节；原型先解码），再结合分析/矩阵理解，实施时现场择优；矩阵与分析不替代方案完整覆盖。
8. **缺陷族全量审计（DEV-IQ-18）**：用户报前端一点，或补测/完善波次开工 / 同批 UI 缺陷 ≥5 → 先跑全量菜单/深链/路由扫描（含交互诚实族），输出缺陷族清单；按族修复，逐族补截图/断言；禁止只改被点名处。
9. **根因先行 + 共享模块单例（DEV-IQ-19）**：404/403/空白/旧页，或确认后无请求/偶发丢权限 → 先记路由、模块 URL（含 `?v=`）、缓存、`/auth/me`、Network，再改码。带模块级可变状态的共享 JS 须单一入口（import map/bare/单例）；禁止多 chunk 各挂不同缓存戳；bump 戳须同批对齐入口真源并跑项目 token 自检（有则必跑）。
10. **全栈方案覆盖（DEV-IQ-21）**：后端/功能同样写 `.gate/plan-coverage.md`：方案条款/AC/SC → 接口/字段/状态/权限/错误码/迁移 → 实现文件/端点 → 测试/证据；前端 → 页面/路由/字段/交互 → 截图。原型/方案是下限：至少达到原型标准；原型有明显缺陷或可优化，按实际择优并写偏离理由/影响/确认，禁止“能跑就行”或静默降级。

### 4.1 抽全差集（开工前）

**每个 Then / 异常分支至少一行。** 有则必抽，无则写不适用：

1. 主路径一次成功  
2. 第二次写 / 补传 / 重试  
3. 同内容异名或同键冲突  
4. 未确认 vs 已确认（或等价中间态）  
5. 冲突时的人工处置入口（不得只有硬拦且无可操作下一步）  
6. 角色允许 + 拒绝；UI 可见 ⇒ API 允许  
7. **业务触发链（有则必抽）**：方案/AC 写「X 发生 → 产生或更新 Y」时，须有独立 SC；「实现落点」列必须写**真实写入口**（创建/生成/下发/提交等生产路径的类或接口），**禁止**只写「查询时补齐 / enrich / 打开详情再算」且无债项；「自测/证据」列须指向对该入口的红探针（先于或同批于实现）  
8. **字段/枚举/可空（有则必抽）**：方案或原型列出的列表列、筛选项、表单枚举、可空与「未知」标记 → 各至少一行 SC 或债项  
9. **跨章通用规则（有则必抽）**：文档中约束本写入口的通用条款，即使不在本功能专章，也须**挂到本模块写入口 SC**；禁止「只抽本功能专章」。类别示例（非穷尽）：数量精度/日期顺序/单位；**批量结果形态**（分条成败 vs 整批阻断——以已裁决方案为准）；**上传→正式可下载态门禁**（危险/损坏/类型上限；故障可见）；权限/幂等/版本冲突等已声明的共同边界  
10. **覆盖声明对齐（有则必检）**：任务/公共底座若写「覆盖某组通用条款 / 场景族 / 共同边界」，则组内每条「必须/不得/Then」须有对应 AC 或 SC，或显式债项；**禁止**覆盖面写宽、验收条写窄后标完成  
11. **交互诚实（有 UI 则必抽）**：方案/PRD 写入口并列、灰显/禁用原因、空态分因、筛选语义、术语权威名、主操作与阻断关系 → 各至少一行 SC 或债项；有禁用/主 CTA/筛选/空列表却无对应 SC = 未抽全（不得只抽接口/库表）

开工门：**未进 SC 且无债项的本期条款数 = 0**；预检命中面 → **先扩 SC 再实现**。  
无 SC 表 → 不得进入 `implement`（L0 无行为变化除外）。  
触发链落点未钉真实写入口 → 未满足 DEV-IQ-01/12，不得开工写旁路。  
覆盖声明未对齐 → 未满足 #10，不得标该公共/横切任务完成。

### 4.2 禁止语义替换（通用反模式）

编码时**不得**把方案约束改成「近义但更省事」的行为（拿不准 → OPEN，禁止猜）：

| 原文语义（示例类） | 禁止改成 |
| --- | --- |
| 生成时 / 创建时 / 提交时固化或写入 | 仅查询/打开详情时再补齐 |
| 拒绝 / 校验失败 / 不得入库 | 静默截断、夹紧、默认改写后成功 |
| 未支持 / 暂不可用 | 套用近邻已实现算法并返回成功 |
| 可空 / 未知可留空并标记 | 改成必填，或留空但不标未知 |
| 生命周期起点（首建/首版/首次登记） | 只做补交/修订/二次路径 |
| 列表须展示的列/筛 | 仅详情可见，列表省略且无债项 |
| 批量动作分条返回成败及原因 | 空成功体 / 仅「操作成功」；或静默跳过非法项仍报全部成功 |
| 危险/损坏不得进入正式可下载版本 | 仅做令牌/摘要/鉴权两阶段，内容门禁缺失仍进正式态 |
| 整批同事务阻断（旧口径）与分条独立（新口径）冲突 | 静默第三路径（两边都不像）；须 OPEN 裁决后再实现（DEV-IQ-04） |
| 禁用/灰显须说明原因与下一步 | 仅灰显无可读原因；或状态已阻断仍突出可点主 CTA |
| 加载中不得给出确定性空结论 | 先渲染「0 项 / 无数据」再回填真实数量 |
| 筛选展示与请求同构；清空即不带参 | 控件已空/已改，请求仍带旧默认参；或控件显示与实际过滤不一致 |
| 空态须分因（未输入/无数据/无权限/格式错） | 一律「暂无数据」或「请先输入」且已查询无匹配时仍提示未输入 |
| 方案权威术语跨表面一致 | 列表/详情/待办/预览同义不同名且无矩阵登记偏离 |
| 须提供对象级/明细/下钻/证据入口 | 仅汇总文本、原始 JSON、不可点提示，且无债项 |
| 须逐项确认后才可启用发布/破坏性主操作 | 全选勾选或旁路字段即可启用，确认态未真实变更 |
| 条件不满足则不可比较/不可操作 | 仍保留可点入口且无「为何不可」说明 |

### 4.3 编码纪律（SC 驱动）

- **可验证单元 = 一条 SC**：先定如何证明（失败/边界探针）→ 实现 → 证明通过 → 下一条；「页面能开 / 接口 200」单独不算单元完成。  
- 只按未完成 SC 逐条改代码；每条 SC 完成须可指回 diff/接口/列。  
- **半实现 = 未完成**：缺字段、缺枚举、缺状态落态、缺首建入口、缺方案点名的明细/证据入口、追溯关键字段空壳 → 不得标该 SC/功能完成。  
- **跨表面单一源**：同一业务状态词、同一 KPI 名·单位·取值口径，须由**一份映射/谓词**（或同源字段）产出；列表/详情/预览/页脚/评价表只引用，禁止各表面手写不同文案或换算。  
- **有阻断则先不可用**：条件不满足的主操作，先实现灰显/阻断 + 原因 + 解除下一步，再实现可点主路径；禁止先做亮按钮后补诚实。  
- **最小改动 ≠ 裁剪 Then**：少动无关文件；已进 SC 的条款不得以「最小」省略，砍则 DEV-IQ-05 债项。  
- **类型不得吞掉方案精度**：方案要求整数/小数/单位精度时，入口类型必须能保留原始值并显式校验；禁止用会静默截断的类型接收后再校验（截断后已丢失原始事实）。  
- **批量更新须排除新插入行**：先插入新版本/新行、再按状态批量更新旧行时，必须按版本号/主键显式排除新行，并加“新行不被覆盖”回归。  
- **批量写响应诚实**：实现批量接口时，响应契约须与已裁决方案一致（分条明细 **或** 整批失败+失败项）；禁止「HTTP/业务码成功 + 空 data + 静默漏项」。  
- **正式附件态诚实**：方案要求危险/损坏不进可下载正式版时，上传/提交路径须有可测门禁或故障态；仅 STAGED/令牌/hash ≠ 该条款完成。  
- 扩表/新约束时：**同批**保证旧写入口（保存草稿/报工生成/门户首建等）仍符合 SC，或点名债项（与 DEV-IQ-06/10 同向）。

## 5. 自测诚信（DEV-IQ-02）

- 先对方案，再对代码；绿测证明「实现与 SC 一致」，不是「实现与自己一致」。  
- 发现用例在断言方案禁止/未要求的行为 → 停：改实现，或提产品改方案并走变更；**禁止**改测试预期刷绿。  
- 边界/错误路径至少各 1；命中跨层或 DEV-IQ-10 面时，按该面最小自测集留证（角色正反、第二次写、空缓存+既有行、越权/超时等）。  
- **证据保真（触发链）**：方案/AC 写「X 发生时 → Y」时：
  1. 单测可测谓词与分支；  
  2. 任务 `COMPLETE` / 提测声称该 AC「主路径通过」时，须至少 1 条**真实入口**证据（走业务创建/生成/下发等入口，或等价集成调用真实写入路径；命令+结果或浏览器均可）；  
  3. **禁止**仅手工插库行、仅 mock `insert`、或仅打开预置对象再查询，冒充该触发链 AC 已全覆盖；  
  4. 合成数据 / 纯 API 代替点名 UI → 只能标「组件/谓词通过」，不得标该 AC 全覆盖（与测试包「仅 API 绿 ≠ 该条通过」同向）。

## 6. 裁剪与债项（DEV-IQ-05）

待决项或任务卡登记示例字段（示例非穷尽）：

| DEBT/OPEN | 豁免的 Then/AC | 理由 | 补齐触发 | 阻塞提测？ | 状态 |
| --- | --- | --- | --- | --- | --- |
| DEBT-01 | {US-xx Then …} | {成本/依赖} | {下一迭代/条件} | 否（已声明）/是 | 开放 |

- 提测单「已知问题与限制」必须能对上债项 ID 或明确写「无裁剪」。  
- 测试验收边界 = **本期承诺 AC ∪ 未豁免基线 Then**；不得默认「DOC 全文已交付」。  
- 重要面硬补若本期砍掉 → **必须**债项化，禁止口头推迟。  
- 功能开关「仅声明未接线」或「本期实现却验收关」→ 走 DEV-IQ-11 + 本表债项，禁止口头豁免。

## 7. 基线再验（DEV-IQ-06）

增量交付前，对声明「沿用」的模块跑最小冒烟（按项目裁剪，缺项写不适用+理由）：

| 检查 | 通过标准 |
| --- | --- |
| 角色正反 | 开放角色可完成主路径；拒绝角色 API/UI 一致 |
| 多值/第二次写 | 补传/重传不 500；冲突有业务码与处置 |
| 状态多表面 | 同一状态在列表/详情/预览/打印/归档标签与水印不矛盾 |
| 异步可观测 | 提交与终态（成功/失败）可关联查询（或已债项化） |
| 本期新建写入口 | 本期新增/改写的创建草稿、生成任务、下发请求等入口至少 1 次真实触发成功（或写不适用+理由）；证据保真同 §5 |

证据写入开发自验/提测自检；无证据不得写「基线无回归风险」。

## 8. 与完成门的关系

- 机器门（`completion-gate`）仍只认脚本可检项；本文条目以 **checklist / 验收清单字段 / 评审记录** 为载体。  
- L1+ 有代码：验收清单须含可解析的 `implement_preflight`、`sc_trace`（done/na+理由，或 Markdown SC 表/实施预检行）；缺或 `missing` → 完成门 **BLOCKED**；命中 profile `shared_globs` 另须 `impact_map`（调用方/模块 + 回归集；缺/空 → BLOCKED）。L2+ `.gate/acceptance.yaml` 另建议 `cross_layer`/`baseline_smoke`/`debts`；**必含** `nfr.security` / `nfr.performance`（done+证据 或 na+具体理由；触及鉴权/列表等路径时空话 `na` 不放行）。取重缺项 → 不得报全覆盖通过。  
- 报告措辞：未满足 DEV-IQ-* 不得使用「完成/已修复」声称全覆盖。

## 9. 降级路径

| 情况 | 处理 |
| --- | --- |
| L0 无行为变化 | 全文不适用；一句理由（含预检 `na`） |
| L1 有行为、未命中跨层/重要面 | DEV-IQ-09 仍须短预检；03/06/10 可写不适用；01/02/04/**12**（有方案条款时）仍有效 |
| L1+ 命中重要面 | DEV-IQ-10 硬补不可省（或 DEV-IQ-05 债项）；有方案条款时 12 同批 |
| 本期有功能开关/灰度 | DEV-IQ-11：验收环境打开已实现范围；前后端同开；声明接线或债项 |
| 用户二次明确覆盖某条 | 按 `rules/core/global-rules.md` §11 执行；收尾 `deviation=` 写明 ID |
| 时间压力要求砍验 | 只允许经 DEV-IQ-05 债项化后砍，禁止静默跳过 |

## 10. 规则缺口回流（DEV-IQ-08）

defects/复盘发现「规范有字但未拦住」→ 输出：缺口在门/技能/模板/哪一步；拟改一处 owner；用户确认后改母版或项目适配。不在业务会话堆长文新规。
