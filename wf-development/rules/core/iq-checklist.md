# 实施质量勾选（开发轨）

> **读取级别：implement / plan / verify 命中**。本页可勾选即干活；ID 释义与长表只在 `implementation-quality.md`（参考，按节读）。  
> 不适用（L0 无行为）：写「na + 理由」一行即可。  
> **本页是实施纪律，不是事后检测清单**：勾空或跳步 = 未开工/未完成。

## 动手前（DEV-IQ-09/12）

- [ ] SC/AC 已从方案/PRD **完整抽全**（含 UI 文案/标题/按钮/提示、空态/加载/禁用、布局区块/列/控件、交互诚实 §4.1#11、跨表面术语）；**未进 SC 且无债项 = 0**；SC 行须有可打开来源+落点+入口类型（`validate_tasklist` 机检）
- [ ] **方案 → 分析理解 → 实施择优**（DEV-IQ-22）：① 先打开方案按目录盘全细节（含 UI/文案；漏则先补 SC/OPEN）；② 再结合理解包/分析吃透补漏；③ 再实施，现场择优挂在实施（不得择优裁掉未债项化要求）；理解包不抢入口、不替代方案完整覆盖；禁先看分析再找方案；改语义/砍细节 → OPEN 或一问
- [ ] 已输出【实施预检】；**命中面已落成新增 SC-xx 或债项 ID**——只写「命中=…」未扩表 = 预检无效，**禁改业务代码**；L1+ 有代码须写入验收清单 `implement_preflight` / `sc_trace`（门禁硬拦）
- [ ] 文档冲突已 OPEN 或已关闭；禁静默选边
- [ ] 新增页面/控件/工具/脚本前已盘点既有组件与相邻实现；复用或写明自造理由（UI 见 `frontend-gate` §4）
- [ ] 有原型/UI → 已读**本步包内「前端硬门」**并完成解码+矩阵（或 na；维护真源 `frontend-gate.md` 仅改规时读）

## 编码中（DEV-IQ-10/12/13）

- [ ] **可验证单元 = 一条 SC**（含诚实/跨页 SC）；该条未自证（红→绿或等价探针）前不开下一条；禁「主路径先合」
- [ ] 命中重要面 → 同批防护 + 负面测；砍验只能债项化（DEV-IQ-05）
- [ ] 禁语义替换（词典 §4.2）：对象级/明细/下钻入口 ≠ 汇总或 JSON；逐项确认 ≠ 全选即可发；不适用 ≠ 仍可点
- [ ] 状态词 / KPI 名·单位 → **单一映射源**，列表/详情/预览/页脚只引用；禁各页各写文案
- [ ] 有阻断/条件操作 → **先落地不可用态（原因+下一步），再做可点主路径**
- [ ] 「最小改动」= 少动无关文件，**≠** 少交付已进 SC 的 Then（砍则债项）
- [ ] 前端：不自造一级导航/壳；字段网格按矩阵；`design-qa` #3/#14/#20 按条文（非空勾）

## 完成前（DEV-IQ-02/14/17/21）

- [ ] 自测断言指回 SC/AC；禁刷绿；**不把 QA/验证站当第一道条款覆盖**
- [ ] 方案→分析→实施已留痕：方案细节盘点已关；已结合分析理解；实施择优偏离有依据；P0/高风险 SC 逐条回指方案，其余按来源抽查；差异全部进 `OPEN`/债项
- [ ] 有 UI → `frontend-gate` 产物齐 + capture/parity
- [ ] 重型验证前已冻结代码/测试/采集脚本；同一 diff 只跑一次全量；`-Claim` 后未再改文件
- [ ] L2+ → `.gate/plan-coverage.md`（模板 `verify/templates/plan-coverage.md`）无阻塞行
- [ ] `-Claim` → `CLAIM: ALLOWED` 后才可写完成；并更新进行中状态
