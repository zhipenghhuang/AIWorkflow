# 门面同步（开发）

> **读取级别：参考**（事件触发时读；收尾不再强制 `facade=` 字段）。
> **真源**：档案 / `activeContext` / 计划；根 README 只镜像已核实对外句。
> **不替代**：热层同拍只认 `global-rules.md` §8；事件矩阵见 `execution-contract.md` §4。

## 1. 目的

把本轮已核实、对外可见的入口/运行/目录变化，轻量同步到根 README（及档案要求的对外句）；并在必触发时做**冷层定点核对**，防止只改热层。

## 2. 触发

| 级别 | 何时 |
| --- | --- |
| 必 | 版本 bump、迭代关闭、发布/上线、对外入口命令实质变化 |
| 按需 | 本轮核实的 README 已断句/过时句 |
| 免 | 纯内部实现、未改对外可见事实 |

## 2.1 冷层定点核对（必触发时 · 禁全扫）

命中 §2「必」时，只打开下列**已存在**的命中行（无文件/无格 → 该项 `na`，不新建、不全扫）：

1. **版本展示**：产品版本 SSOT（如根 `VERSION` / 档案现行版本）↔ 根 README 现行版本展示句（有则必须一致）。
2. **部署格**：档案 §1「更新服务器部署」↔ §8.1 / 本轮部署事实（有现行部署方式却写「无/未接入」=冲突，同轮改正；源码托管 URL 不进本格）。
3. **其它对外句**：本轮已核实且 README/档案已有对应句断了 → 只改该句。

预算：≤3 次定点打开。热层（计划/`activeContext`）已更新而冷层仍写旧现行值 → **不得**收尾称同步完成。

## 3. 做法

1. 先改档案/`activeContext`/计划命中行，再改根 README 对应句；禁只改 README。
2. 只改**本轮已变**相关句；禁止为「保险」通读全文或重排章节。
3. 无根 README → 版本/部署核对仍做（有 SSOT/档案格则核）；README 项记 `na`。
4. 用户确认推迟 → 收尾写推迟原因；必触发未做且未推迟 → 不得收尾称同步完成。

## 4. 收尾表述

命中 §2「必」：`sync=` 须含 `冷层:ok|na|deferred:<因>`（可与热层同拍并列）；未命中可不写冷层。有门面句改动时第 6 点一句说明。**不另造** `facade=` / `triad=` 字段。
