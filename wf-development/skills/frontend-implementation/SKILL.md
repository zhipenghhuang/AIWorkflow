# 前端实现（技能 · 随包生效）

> 用于：S4 编码自测中涉及页面/路由/组件/表单/交互/前端数据流的任务。  
> **硬门运行时**：当前步骤包内「前端硬门」（本技能不重复门条款）。维护真源 `rules/core/frontend-gate.md`（改后须重生包）。  
> 质量条：`skills/engineering-quality/SKILL.md`。

## 0. 必做（先于编码）

1. 读本步包内「前端硬门」；L0 无 UI → 整技能 na。  
2. 有单 HTML 原型 → 先 `extract_prototype_modules.py` 解码；已构建 SPA → 浏览器按 hash 路由提取「改动清单/导航/主区结构/截图」到 `.gate/prototype/`；禁反写矩阵。**无原型** → 读 `frontend-design` §3/§4，先写设计基线再实现。  
3. 写/更新 `.gate/frontend/parity-matrix.md`（含字段网格；冲突裁决）；有交互 → 先有/更新 `interactions.yaml`（flow/状态/迁移/不变量/用例映射），缺规格不写交互代码。  
4. 实现时不自造一级导航/页面壳；优先复用现有列表/详情壳；弹窗/表单按复用组件的受控契约（回调归属/接口层）。  
5. 每页做完立即对照矩阵；深链直达；菜单视口可达。  
6. A/B UI：按 flow 做，每条 transition/invariant 有 `[CASE:id]` 用例并通过；先跑流用例再进下一 flow；点通/接口 200 不算。  
7. L2+：`frontend.capture` → `evidence.json`；再 `frontend_parity --require-audit --require-interactions`；手写通过无效。capture/流用例降级 → 该波 `degraded`，不得标完成，S5 前必须重拍/重跑复评。  
8. 能力可达：列「后端写端点 → 页面入口/动作」，无入口标 `non-ui:<理由>` 并确认；不得以接口可调替代页面。  
9. 回执 `skills=frontend-implementation`（+ 分析步则含 product-doc-analysis）。

## 0.1 禁做

- 用 API 200 / DOM 文本 / 测试绿代替截图验收。  
- 骨架屏/登录页当完成证据。  
- 用户报一点只修一点（须缺陷族全量审计）。

## 1. 结构与路由

- 先读产品设计/交接；需要补设计时读前端设计说明，不另起视觉。
- **原型单源（DEV-IQ-13）**：单 HTML 原型可能把模块以 `data:`/base64 嵌在 importmap；先跑 `python rules/tools/extract_prototype_modules.py <原型.html> <输出目录>` 解码模块并枚举路由/导航/组件，禁止只搜原始 HTML 文本就判断“原型没有该页”。**已构建 SPA**（无 importmap、浏览器直接打开可运行）按 `frontend-gate` §3-1b 运行解码，矩阵只引用解码结果。
- 开工前给出「原型对齐矩阵」：路由→导航层级/文案→复用组件→列/区块/字段网格→交互/筛选/日期→状态/空态/权限；**冲突以方案/PRD 为主**（业务口径/命名/单实体与多实体语义/权限/路由），布局/组件/视觉以原型为主；现有同类页面/设计系统一并对照，择优复用；按方案偏离原型要在矩阵标 `按方案`，重大偏离先 `OPEN-*` 确认。
- **路由/菜单/深链台账（DEV-IQ-17）**：同步写 `.gate/frontend/route-coverage.json`；一级/二级菜单在 1440×900 与 1280×720 下必须可见或可滚动到达，展开项不得把同级挤出；新建/详情/授权/统计钻取等关键深链必须直达；每条路由配桌面+移动截图，哈希不得跨路由复用。
- **持续回指**：每条 SC/AC 标注来源文件+章节；编码、review、verify 都回看原文，并与原型/现有同类页面对照，不凭记忆；到波次检查点/来源更新时重跑矩阵并更新差异。
- **不得自造一级导航/页面壳/表格/详情**：优先复用现有列表/详情壳与组件（具体名称见项目档案/设计文档）；新增列表必须复用现有 tokens、表格、空态、错误态。项目专属组件名只写在项目文档/档案，不写进通用规则。
- 页面/布局/路由/菜单/权限入口；路由守卫与深链。
- 组件边界：容器/展示、复用组件、目录与项目约定一致。
- 全局/页面/局部状态；避免重复状态与不一致。
- **共享模块单例（DEV-IQ-19）**：store/确认框/会话等带模块级状态的文件须单一入口（import map 或项目约定）；禁止多 chunk 各挂不同 `?v=`；局部 bump = 双例风险（确认无请求、权限偶发丢）。有 token 自检同批跑。
- 请求统一走封装层；鉴权失效统一处理。
- tokens/组件从设计系统单一来源取；禁止页面散落硬编码颜色/间距/圆角。

## 2. 页面状态与交互流（缺一不可 · 交互诚实）

- **交互流（A/B 硬）**：按 `interactions.yaml` 的 flow 实施；每个 flow 先定 `states/transitions/guards/effects`，再写用例；生命周期按类模板：overlay（打开初始化/取消不写/ESC·遮罩·关闭一致/提交锁/失败保持/重开重置/焦点返回）、list（筛选→页码重置/刷新保留/选择范围/批量部分失败）、form（校验时机/首错聚焦/提交锁/离开确认/草稿）、linked（A→B 清空/禁用/重查/默认/重置）。  
- **组件契约**：复用 Modal/Button/Select/Form 的受控字段与回调；接口调用只在页面/hook，弹窗只回调；不得在弹窗内直接改列表 state。  
- **异步/竞态**：提交中禁用+单次请求；关闭时中止或忽略旧响应；旧响应不得覆盖新状态；乐观更新须可回滚。  
- **持久化**：筛选/Tab/分页是否进 URL、刷新/返回是否保持，按 `interactions.yaml` 的 `persistence` 实现并测。  
- 加载、空态、错误、超时、重试、禁用、无权限。
- **加载诚实**：未就绪只允许 skeleton/加载态；禁止先渲染确定性「0 项 / 无数据」再回填。
- **空态分因**：未输入 / 无数据 / 无权限 / 格式错误分文案；已查询无匹配不得仍提示「请先输入」。
- **禁用可解释**：灰显/禁用须可见「原因 + 解除下一步」；不满足条件的提交须灰显或阻断并说明原因。
- **主 CTA 诚实**：页内已阻断（待检未清/状态不允许等）→ 不得仍突出可点主按钮；错 Tab/错状态不得保留误导性新建/完工入口。
- **实现顺序**：有阻断/条件操作时，**先落地不可用态（原因+下一步），再做可点主路径**；禁止先做亮按钮后补诚实。
- **筛选同构**：控件展示值 ≡ 实际请求参数；清空控件 ≡ 请求不带该参；默认筛须与方案一致且生效可证。
- **术语 / 状态 / KPI 单一源**：方案权威名与业务状态词、KPI 名·单位·取值口径，由**一份映射/谓词**（或同源字段）产出；列表/详情/预览/页脚/待办只引用；偏离须在对齐矩阵登记，禁止各页手写不同文案或换算。
- **入口忠实**：方案写对象级明细/下钻/证据入口 → 须可发现可点，禁止用「仅有汇总或 JSON」顶替（无债项时）。
- 表单：校验时机、字段级错误、提交中、重复提交、草稿。
- 列表：分页/排序/筛选/无限滚动/空结果/深翻。
- 弹窗/抽屉/返回栈/刷新保持；移动端/响应式；破坏性操作相邻须降误触。

## 3. 数据与交互

- 请求取消/竞态；缓存/失效；乐观更新与回滚。
- 防抖/节流；批量操作；危险操作二次确认。
- 权限：按钮/字段/路由级控制；后端仍须校验。
- 埋点/日志：关键行为与失败上报，避免敏感信息。

### 3.1 可见即可用（权限/状态一致）

- 每个可见菜单/按钮/字段都要能指到同权限 API；没有对应权限 → 隐藏或禁用并说明原因，不能“先展示，失败再说”。
- 前端隐藏不是授权；服务端仍须资源级校验。
- 列表/详情/预览/打印/归档的状态标签、水印、可操作项、KPI 展示由同一份状态/指标映射产生；禁止各页面各写一套。
- 按角色做正反走查：允许角色能完成，拒绝角色得到明确 403/404/空态，而不是 500 或自相矛盾的“无权限 + 有入口”。
- 命中权限/状态/多值数据时，按 `skills/cross-layer-consistency/SKILL.md` 填矩阵并留证据。

## 4. 性能与质量

- 包体/首屏/交互预算；懒加载/代码分割/图片优化。
- 长列表虚拟化；避免无意义重渲染。
- 可访问性：键盘/焦点/ARIA/对比度；国际化（如适用）。
- 错误边界/降级 UI；浏览器/分辨率兼容按项目档案。
- **运行时 API**：新用 `crypto.randomUUID` / Clipboard / 仅安全上下文等 API → 目标浏览器/WebView 冒烟或 polyfill；缺能力须可操作降级；console error 不得标完成。

## 5. 测试与证据

- 单测：纯逻辑/格式化/校验；组件测试：状态与交互；E2E：主链路。
- 手工自测：主路径 + 空/错/权限/重复提交。
- 证据：截图/录屏、控制台无报错、网络请求/响应、性能面板（如涉及）。
- **视觉验收（DEV-IQ-14）**：桌面 + 移动截图，并与同类页面/原型对照；接口 200、DOM 有文字、class 正确都不算视觉验收。截图不可用/窗口不可见 → 标 `UNVERIFIED`。**具体呈现形式（状态用色/标签/文字/图标、列宽、缩进）按原型/设计系统/场景择优，不设死规则；同类页面要一致、可辨识、可访问。**
- 未验证项明示；不把“页面能打开”当“功能通过”。

## 6. 设计还原与设计 QA

- 对照设计说明逐页核：页面/路由/状态矩阵/组件/tokens/文案/权限。
- 视觉：字号阶、间距、圆角、阴影、密度、对齐与设计说明一致；不出现第二套 tokens。
- 响应式：手机/笔记本/超宽屏；移动主任务可完成；无意外横向滚动。
- 无障碍：键盘走查、焦点可见、label/alt、对比度、目标尺寸、`prefers-reduced-motion`；表单 `type/autocomplete/name`、图标按钮 `aria-label`、图片显式宽高与懒加载、异步提示 `aria-live`。
- 状态与导航：筛选/Tab/分页等状态可深链/刷新保持；危险操作二次确认或可撤销；长文本有截断/换行，空态不出现坏 UI。
- 性能：LCP/INP/CLS 或项目预算；首屏资源、图片尺寸、字体、长列表虚拟化。
- 证据：至少一组关键页面截图（含空/错/权限态）+ 键盘/焦点证据 + 控制台/网络摘要；有设计说明时做差异清单。
- **无样例数据**：正式入口不得用固定样例/演示数兜底；缺数据显示空态/未配置。
- **能力可达**：新增/变更写接口须有页面入口或 `non-ui:<理由>`；页面动作能指到同权限 API。
- 文案减法：无标语/重复说明/装饰标签；必要操作/状态/风险/金额/权限/错误文案齐全；删后首屏仍可理解。
- 删后不清楚 → 改布局/层级/分组/渐进披露/默认值/就地提示，不加回说明文字。
- 三维影响：UX（截图/走查）、DX（命令/可维护）、AX（路径/单一出处）各一句；净退化须说明取舍。
- 设计缺口回写设计说明/任务清单，不在实现里静默改交互。

## 7. 常见坑

- 只做 happy path；空/错/权限态缺失。
- 页面直写请求地址；错误提示泄露内部信息。
- 重复提交、竞态覆盖、缓存不一致。
- 组件过大、状态散落；样式/交互与项目规范不一致。
- 忽略移动端/浏览器兼容/可访问性。
- 直接复制原型 HTML/内联样式；绕过设计 tokens；设计说明与实现两张皮。
- 用说明文字补布局/层级问题；删文案删到操作/状态/风险不可理解。

## 8. 自检

- [ ] happy path / 空态分因 / 错误态 / 权限态 / 加载诚实 / 禁用原因+下一步都有实现。
- [ ] 主 CTA 与阻断结论一致；筛选展示 ≡ 请求；术语与方案一致或已登记偏离。
- [ ] 可见动作能指到同权限 API；角色正反走查通过（拒绝不是 500/自相矛盾）。
- [ ] 请求走统一层，错误提示不泄露内部信息；无重复提交/竞态覆盖。
- [ ] 组件边界/状态归属清楚；无超大组件与散落全局状态。
- [ ] 设计 tokens/组件复用；无内联样式复制原型。
- [ ] 有原型时已解码；operations 来自原型并逐项点通，未从实现反抄。
- [ ] 后端写端点均有页面入口或已确认 `non-ui`；正式页无固定样例数据。
- [ ] capture 未降级，或降级已登记并在本门/S5 前复评。
- [ ] 移动端/目标浏览器/可访问性（键盘/焦点/对比度）已核；新 Web API 已冒烟或 polyfill。
- [ ] 每条路由桌面+移动截图、菜单/深链台账、`route-coverage.json` 已齐；哈希不重复、无旧图。
- [ ] 截图/console/network 证据齐；`design-qa` #8/#9/#14 按条文通过；设计缺口已回写。

## 9. 完善审计（独立角色 · 有 UI）

> 由 `ui-auditor` 在 implement/build 之后、review 之前执行；审计者≠实施者；不改代码，只出缺口与证据。C 档（纯文案/列名/颜色）免独立审计，文案/状态核对并入 `design-qa`。
> 产物：`.gate/frontend/ui-audit.md`（模板 `rules/templates/20-design/ui-audit-template.md`）；机检 `frontend_parity.py --require-audit`。

### 9.1 输入与边界

- 方案/PRD 原文（含 UI 文案/状态/权限细节）、锁定的原型（先解码）、`interactions.yaml`、理解包 §10/§11 或方案卡 §0.1/§1。
- parity-matrix / route-coverage / design-qa / tier / 截图 / `playwright-results.json`；任务卡 AC/SC。
- 不读实施者自评/聊天解释；实现说明只作定位线索。审计是用户可见切片的功能/一致性核查，不替代全量 AC、组合负面与版本准出。

### 9.2 逐路由逐操作（硬）

1. 列本轮全部变更/新增路由 + 菜单 + 深链，与 `route-coverage.json` 对齐；缺一记缺口。
2. 每个 flow 对 `interactions.yaml` 的每条 transition/invariant 核 `[CASE:id]` 结果；`skip`/失败 = 缺口；再对可见操作实点作探索（入口→结果/接口/错误码/权限态）。
3. 每个操作至少 1 条真实成功；写操作至少 1 条失败/拒绝（校验或权限），或指向已跑 SC 证据。
4. 只点页面不改数据；需造数时按项目档案/测试数据规则，不污染正式库；探索发现新迁移 → 回写 spec + test。

### 9.3 状态与跨页

- 每页核：空/加载/错误/超时/无权限/禁用/重复提交/边界；对照 §2 的交互诚实。
- 跨页一致：术语、状态词、KPI 名/单位、组件、密度、主操作位置、日期/筛选语义、空态/错误文案；不一致记缺口并指回方案/原型。
- 后端可达：每个写端点 → 页面入口/动作；无入口标 `non-ui:<理由>` 并确认；页面能开但操作无入口 = 缺口。
- 真实数据：稀疏/空/大数三形态各验一次；只满数据截图 = 未验证。

### 9.4 缺陷族与回归

- 同类路径（同模型写入口/同谓词/同权限/同状态表面/同组件）一并扫；不只修点名处。
- 原型缺陷先列清单（稀疏失真/空态缺失/文案错误/死交互），逐条标 `照搬` 或 `择优：收益`；发现仍照抄 = 未完成。
- 缺口回 implement 修；修后跑「原缺口 + 同族 + 冒烟」；审计只认修复后的证据。

### 9.5 结论

- 按模板：§2 每路由 `###` 区块 + operations 对账；§3 20 维全 pass/na；§4 flow 的 transition/invariant 有 pass 用例；§5 一致性/§6 后端可达/§7 真实数据/§9 结论通过/§10 `INDEPENDENT_REVIEW: PASS`；任何待验/未点通/skip/缺口 = 不通过。
- 结论写「通过」才进 review；UI 缺口不得债项化；审计不替代测试/准出。

## 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| 「UI 通了就提交」 | 须浏览器证据；无障碍/状态/错误态至少各验一次。 |
| 「有 disabled 就算状态齐」 | 须原因+下一步；加载不得先报空；筛选须与请求同构。 |
| 「样式先 hardcode」 | 有设计说明/tokens 时对齐；禁止另造视觉源。 |
| 「权限只藏按钮」 | UI 可见动作须同权 API；禁纯前端鉴权。 |
| 「页面能开/接口 200 = 操作通」 | 必须逐操作点通并留接口/错误/权限证据；静态图不算。 |
| 「只审我改的页就够了」 | 同族路径与跨页一致必须扫；否则同类不一致会复发。 |
| 「审计就是再跑一遍 design-qa」 | design-qa 是实施自填；审计是独立实操 + 跨页一致 + 后端可达。 |
| 「缺口先挂债，下轮补」 | UI 缺口不得债项化；未修 = 未完成。 |
