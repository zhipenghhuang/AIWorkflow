# 实现与自测（技能 · 随包生效）

> 用于：implement / verify；通用工程方法与自测。  
> **勾选**：先 `rules/core/iq-checklist.md`；词典 `implementation-quality.md`（按节）。  
> **按端**：UI → `frontend-implementation`（+ `frontend-gate`）；API/数据 → `backend-implementation`；全栈两端都读。  
> **质量条**：`engineering-quality` §1～§4。

## 0. 必做

1. 读任务卡 AC/SC/DoD；SC 差集=0（未进 SC 且无债项 → 不开工）。  
2. 输出【实施预检】（DEV-IQ-09）；命中面同批硬补（DEV-IQ-10）。  
3. 编码只跟 SC；禁语义替换；预期只认 SC/AC（禁刷绿）。  
4. 有 UI → 遵守 `frontend-gate`；有原型 → 已加载 product-doc-analysis。  
5. 完成前：自测证据 +（L2+）plan-coverage；`-Claim` 仅在 ALLOWED 后写完成。  
6. 回执 `skills=implementation-and-selftest`（+ 端技能名）。

## 0.1 实现前确认

- 命中权限/状态/数据基数/多表面 → `cross-layer-consistency`。  
- 文档冲突 → OPEN，禁静默选边（DEV-IQ-04）。  
- 复用既有写法须与 SC 动词一致。

## 0.5 实施预检（自主 · 强制 · DEV-IQ-09/10）

> **写任何业务代码之前**完成本节。细则与扫描表只认 `rules/core/implementation-quality.md` §3；此处只写执行顺序。

1. **自主扫描**：按实施质量门 §3.1 逐面判定命中/不适用（不等用户点名安全、性能、失败路径）；方案有「X→Y」时写路径面默认命中。
2. **出示预检**：输出【实施预检】一行（形状见实施质量门 §3.2）；写入任务卡「实施预检」或对话首条实施回执。L0 无行为 → `na` + 理由后可跳过下面 3～4。
3. **命中则加载**：只读该面指向技能的**当前节**（禁通读）；把硬补项扩进 SC 表；触发链 SC「实现落点」钉真实写入口（实施质量门 §4 第 7 条）。
4. **先红后绿**：重要面/触发链的失败用例/探针先写（或先定命令预期）→ 再实现 → 证明通过。探针须打**真实写入口**（或等价集成调用该入口）；禁止先实现查询补齐/旁路再指望自验发现主路径不通。
5. **砍验**：只能 DEV-IQ-05 债项化；禁止口头「以后再补」。

反合理化见实施质量门 §3.3；与 `engineering-quality` §7.1 一致。

## 1. 小步红绿（自带验证的实现法）

- 每完成一个可验证单元：先想「我怎么证明它对」（失败用例/边界探针）→ 实现 → 证明通过 → 再进下一个；**预检命中面优先**做对应单元。
- 触发链单元：红探针 = 真实创建/生成/下发（或调该入口）；绿 = 同入口可观察结果符合 SC；禁止用合成插行/mock insert 作为该单元的唯一绿灯。
- 扩表或新增旁路时：同一步验旧 save/insert 仍成功（或债项）；不把「旧入口再验」留到提测。
- 缺陷轨的「修前红证」是同一方法的强制版（`rules/defects/fix-collaboration.md`）。
- 禁攒大招：一个改动大到无法快速验证时，拆。

## 2. 最小改动 · 手术式修改

- 只动与目标相关的行；不顺手重排/重命名/升级无关依赖。
- 开发阶段优先删旧结构/旧数据/死代码，不保留兼容层；上线/真实数据/外部契约除外（`skills/engineering-quality/SKILL.md` §1.2）。
- 动手前说明拟改文件（`AGENTS.md` §0.5）；改动面超出预期先停下说明。

## 3. 调试方法论（先析因后动手）

1. **复现**：拿到稳定复现（最小步骤+数据）。
2. **假设**：列出 2～3 个候选根因（不是猜一个就改）。
3. **二分**：日志/断点/替换/注释把范围对半切，直到锁定。
4. **修因**：修根因不修表象；禁「加个 try 先绕过」。
5. **回归**：按修复路径+影响面验证；留证据。
- 方案无效 **2** 次：换假设或换手段，禁同命令空重跑（`AGENTS.md` §0.3-7）。

## 4. 自测标准（提交前过）

### 4.0 完成声称铁律（证据先于结论）

> 吸收自 verification-before-completion：未在**本轮**跑出验证命令并读完输出前，禁止任何「完成/通过/修好了/可以提交」表述（含同义与满意语气）。

```text
声称前五步（不可跳）：
1. IDENTIFY：哪条命令/探针证明该声称？
2. RUN：本轮完整执行（禁止复述「刚才应该过了」）
3. READ：读退出码与失败计数，不只扫摘要
4. VERIFY：输出是否真支持声称？否 → 报实际状态
5. ONLY THEN：带证据声称
```

| 声称 | 需要 | 不够 |
| --- | --- | --- |
| 测试通过 | 本轮测试命令 0 fail | 上次绿 / 「应该过」 |
| 构建成功 | 本轮 build exit 0 | 仅 lint 过 |
| Bug 已修 | 原症状复现路径本轮通过 | 只改了代码 |
| 需求满足 | SC/AC 逐条勾核 | 仅测试绿 |
| 子代理做完 | 看 diff/产物再核 | 采信子代理自述 |

### 4.1 清单

- 每条验收点有对应验证动作与结果（命令+输出）。
- **逐条 SC 自测**：方案条款清单每条至少一条验证；有否定/边界/重复/权限/状态则补对应项；不把 QA 当第一道覆盖。
- **预期诚信（DEV-IQ-02）**：断言/探针必须能指回 SC/AC/Then；与方案冲突 → 停工，禁止改断言迁就代码（禁刷绿）。
- 边界与错误路径至少各试 1 条（空值/非法/重复/越权其一）。
- 命中权限/状态/多值对象时：角色正反、第二次写、并发/重试、既有行但缓存空，至少各 1 条；同类路径扫描结果一并记录。
- **预检命中面**：实施质量门 §3.1 该面「命中后必须」每条有自测/证据；缺一项不得标任务完成。
- 新增动作码/审计/异步任务：中文标签与提交+终态同批（DEV-IQ-07）；否则债项化，不得静默用技术码冒充完成。
- 未验证路径显式写「未验证」（`rules/workflow.md` §3.1）。
- 收尾写三维影响：UX/DX/AX 各一句；无证据的维度标「未验证」（`skills/engineering-quality/SKILL.md` §1.1）。
- 可测逻辑同步补测；装配 unit-test-gen 时按覆盖缺口驱动（`capabilities/00-contract.md`）。

## 5. 测试层次与工程动作

- **单测**：纯逻辑/边界/异常；红→绿→重构；禁无断言凑覆盖率。  
- **集成/契约**：跨服务/接口字段/错误码；契约先行，改约先确认。  
- **E2E/冒烟**：主链路 + 关键分支；发布前跑最小充分集。方案写「X→Y」的触发链须走真实入口（DEV-IQ-02 §5）；合成/mock 不得冒充该 AC 全覆盖。  
- **迁移/配置**：幂等、可回滚/前滚；先小环境验证；大表看锁与时长；开发阶段允许重建 schema/数据/夹具，不写旧字段/旧记录兼容。  
- **开关/降级**：高风险变更用特性开关；基线默认值安全；**联调/验收环境打开本期范围**；前后端构建变量与服务端同开；关则入口+接口双拒（或 OPEN 标声明位）；回滚路径可执行（DEV-IQ-11）。  
- **文档**：行为/接口/配置变化与实现同变更；只写现行有效。

## 6. 提交卫生

- 一类改动一提交；提交信息按 `rules/workflow.md` §2；无文件变更不硬造提交。
- 提交前确认：改动范围、验证证据、未验证项、文档同步、敏感信息零入库。
- **提交/收尾前**：必须满足 §4.0；无本轮验证证据不得进拟提交。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| 「应该过了 / 看起来对了」 | 本轮未 RUN+READ=未验证；按 §4.0。 |
| 「lint 过了就能提交」 | lint ≠ build ≠ 行为自测。 |
| 「子代理说修好了」 | 独立看 diff 与命令输出。 |
| 「预检太慢，先写主路径」 | DEV-IQ-09/10/12 先于代码；重要面硬补与字段/枚举不可口头延期。 |
| 「只差一点，先合再说」 | 差一点也要证据；半实现≠完成；完成门不认口头。 |
| 「拒绝太严，截断/套近邻也能用」 | DEV-IQ-12 禁语义替换；方案写拒绝/未支持就必须拒绝或明示不可用。 |
| 「批量 200 空 data / 附件有 token 就算安全」 | 写路径/安全敏感硬补：混合分条或整批失败定位；正式态内容门禁；细则实施质量门 §3.1/§4.2。 |
| 「QA/验证会扫到」 | 验证是兜底；理解与落地错误须在编码前消掉。 |
