# 协作面与公开面

把本文发给**任意项目**里的 AI，说「按协作面与公开面配置」或「配置公开面 / 双面 / 开源面」即可。  
AI 读本文后：**轻探查 → 先出短【大方向确认】停问 → 大方向确认后再做细节择优 → 再出【公开面核对】总表供最终确认** → 确认后落盘。  
**独立通用**：不依赖、不假定某一托管商、某一多仓管理仓库、某一脚本名或固定目录名。旁路管理仓（若本机另有）**仅作实现参考**；未接入则按附录 F 在本项目落地同步能力。  
**一次配好**：落盘后日常真源是**项目内**允许列表 / 清洁 ignore / README 裁剪 / remote·分支 / §3.3 / §3.5 薄规则 / **可执行的公开同步入口**；配完后日常会话**只读这些项目文件**，不必再打开本文。改范围或发现夹带时，按项目薄规则做核对与同步（见 §4）。

**执行要求（给 AI）**

1. **先探查、后动手**：未获**大方向确认**、未出示【公开面核对】并获**最终确认**，不得改 remote/默认分支、不得推公开目标、不得强推、不得重置公开史；不得改允许列表 / ignore / README 标记 / 拟公开正文。  
2. **交互分层（硬）——大方向必问，细节 AI 择优**（与同仓「开发/正式分支」同一口径）：  
   - **顺序**：先问清大方向并停等 → 确认后再输出总核对 → 最终确认后再落盘。禁止首轮就甩路径/夹带长表。  
   - **大方向**（§1.1）：必须让用户**明确点头**；可一次并列问完；口令已写清的只**复述确认**，不得静默假定。禁止用「细节整包 OK」吞掉大方向。  
   - **细节**：部署形态、路径归类、夹带 A/B/C/D、元数据目录名、ignore、同步脚本路径、运行环境拉取对象记实况等 → **自行择优写入总核对（一项主推 + 一句依据）**；勿整表勾选、勿「一次回齐」长串代替分析。用户可点名改行。  
   - **不可逆**归入**本轮动作**或缺 URL 时停问；真阻塞一次一问。  
2b. **须选项沉底（硬）**：凡要用户**选择或拍板**的内容，一律放在**该条消息最下方**「请你确认」区，短列表一眼可见；探查摘要、依据、细节主推放上面当只读。禁止把选项夹在长表中间。  
3. **本文范围（硬）**：只做协作面与公开面的**路径划分**、拓扑与同步入口落地，以及对拟公开正文的**协作向夹带**扫描（附录 C）。夹带处理写入核对表主推（默认 A）；**细节确认前不改正文**。**B 仅为去掉夹带、使公开步骤不指向缺失文件的最小改写**，不得扩大为全文重写。  
4. **公开正文不讲分面机制（硬）**：公开可见正文按**普通对外说明**来写。分面机制说明、仅协作入口、引导克隆协作全量仓的第二托管表述 → **细节主推**进 omit 或拟剥离；**禁止**在公开段向访客解释分面机制。  
5. **禁止顺带质量改动**：不得在分面任务中擅自做 README/文档的文案优化、结构调整、徽章与排版、「更高质量开源仓」类改动。  
6. **公开面优化建议（可选、分离）**：可另附【公开面优化建议】，**仅输出供用户勾选**；未采纳不得动手。与核对表分开。  
7. **文档必查**：对拟进公开面的文本做附录 C 扫描；路径在允许列表中 ≠ 可原样公开。  
8. **三分表**：拟公开 / 拟剥离 / 不确定。能按附录 B 启发式归类的**写入拟公开或拟剥离并标主推**；不确定仅真阻塞，一次一问。  
9. **对用户只给结论 + 待确认项**；不把修改方案/对话过程写入项目正式文档。  
10. **正式正文只写现行**：删除即移除；不写「已废弃/不要再用」类留痕。  
11. **按实况裁剪**：库/工具/文档仓/无服务端等 → 「部署起来」或整类路径标「不适用」并一句理由写入核对**细节**；禁止臆造文件。  
12. **已有配置先复述**：大方向先复述现行再问是否改；无则从零问大方向并起草细节（元数据常见 `.public/`）。  
13. **配完必须可日常使用（硬）**：填实 §3.3；写入 §3.5；**§3.3「公开同步入口」不得长期为空**（择优见第 2 步），不摊「三选一菜单」。声明日常只维护项目内配置与薄规则 + 走同步入口。

## 1. 概念（现行）

| 面 | 是什么 |
| --- | --- |
| **协作面** | 团队日常真源：完整工作树（源码 + 过程文档 + 规范/档案 + 本机入口等）。可以很大。 |
| **公开面** | 有意裁剪后的派生视图（或镜像同内容）。默认只服务：**跑起来**、**部署起来**（若需要），外加必要对外说明（产品是什么、许可证、致谢、对外 API/架构摘要等）。 |
| **仅本地** | 永不进任何远程：密钥、本机写死路径工具、个人草稿（选择不入库时）。用协作侧 ignore 排除。 |

### 1.1 大方向 vs 细节（分层；须选项沉底）

| 层 | 含什么 | 怎么对待 |
| --- | --- | --- |
| **大方向**（必问） | **简化分支**；**拓扑粗向**；**公开发布目标是否已有**；**本轮动作** | 先短问、选项沉底；确认后再出总核对 |
| **细节**（AI 择优） | 部署形态、元数据目录名、路径、夹带、ignore、同步入口路径、运行环境拉取记实况等 | 写入总核对只读区；用户可在底部点名改 |

| 概念 | 是什么 | 不是什么 |
| --- | --- | --- |
| **部署形态** | 应用怎样跑起来/部署起来；属**细节**择优。 | 不是 git 怎么分面。 |
| **公开拓扑** | 协作与公开在 git 上怎么摆；粗向属**大方向**。见附录 A。 | 不是服务器进程形态。 |
| **公开同步** | 导出树更新到公开目标；入口路径属细节，是否本轮推送属本轮动作。 | 不是「环境更新/上线」本身。 |
| **本轮动作** | 只落盘 / 落盘+配 remote / +首次导出或同步 / +推公开 | 不是路径表本身 |

**部署形态（细节择优；写入总核对）**

| 取值 | 含义（现行） | 对公开路径的影响 |
| --- | --- | --- |
| 单进程 / 直接跑 | 安装依赖后启一个进程或一组进程 | 依赖清单、启动说明、必要配置模板 |
| 容器 | 镜像构建 + 编排（如 Compose） | Dockerfile / compose 等（有则拟公开，无则不臆造） |
| 静态站点 | 构建产物由静态服务器或对象存储托管 | 构建命令与产物说明；不一定公开服务端 |
| 可执行包 / 安装包 | 发布二进制或安装包 | 打包说明与校验方式；源码是否进公开另析 |
| 不适用 | 库、文档、纯规范等无「部署」 | 不要硬凑编排文件；公开侧重跑通示例/说明 |

### 1.2 铁律

1. 未公开内容靠「不出现在公开树」实现；不要靠公开树 `.gitignore` 点名隐藏内部目录。  
2. 公开 ignore 只写公开消费者需要的规则（依赖、构建产物、`.env` 模式等）。  
3. 允许列表、清洁 ignore、裁剪元数据**默认不进公开树**。  
4. 根目录协作用 `AGENTS`（若有）默认只留协作面；公开侧以 README / LICENSE / 必要对外文档为准。  
5. 「部署起来」按细节择优的部署形态准备；不适用则跳过并写明。  
6. 协作推全量；公开推**导出树**（镜像模式除外）。同步遵守附录 D + F。  
7. **运行环境拉取对象**：能从现有环境更新脚本判断则写入实况；仅当用户确认「上线跟公开 tip」时才写公开目标；生产跟协作正式分支或其它基线 → 记实况或「不适用」，**勿默认改成拉公开**。

## 2. 执行步骤（照做）

### 第 0 步 · 大方向确认（硬；先于细节长表）

轻探查 → 输出**短**【大方向确认】（§3.0：上简要依据、**下沉底请确认**）并**停等**。  
口令已写清的项复述请确认；未写清的**必须问**。本步**禁止**附路径三分、夹带表或允许列表草案。

**【大方向确认】须覆盖（选项只出现在消息底部）**

1. **简化分支**：瘦公开裁剪 / 镜像同内容 / 仅交付包？  
2. **拓扑粗向**：分远程 / 同仓分支 / 外置协作 / …？  
3. **公开发布目标**：已有 URL/remote 还是待建？（缺 URL → 必问）  
4. **本轮动作**：只落盘 | 落盘+配 remote | +首次导出或同步 | +推公开？

| 用户确认后 | 走法 |
| --- | --- |
| 镜像 | 细节择优 → 【公开面核对】总表 → **最终确认** → 收束 |
| 交付包 | 细节三分+夹带 → 总表 → **最终确认** → 清单/ZIP |
| 瘦公开 | 第 1～3 步细节 → 第 4 步总表 → **最终确认** → 落盘 |
| 大方向未齐 | **继续停问**，不出总核对 |

公开用途默认「跑起来 +（如需）部署起来 + 必要对外说明」；额外必须公开的大类仅口令暗示时在大方向底部列入待选项。

### 第 1 步 · 探查（大方向确认之后；为细节择优）

- 工作区结构、README、构建/运行/部署相关文件。  
- 本机提交入口；公开 ignore、README 标记、同步入口、旁路管理仓能力。  
- 项目类型粗判 → 拟公开默认集与部署形态。  
- 与分面无关的归档 tip/旁支 → 忽略。

### 第 2 步 · 细节择优（部署形态、元数据、同步入口）

大方向已确认的简化分支/拓扑/目标直接沿用。对**细节**：**分析 → 一项主推 + 一句依据**；勿再把大方向当细节问一遍。旁路只支持部分拓扑时：主推避开未支持项并写明限制。

- **部署形态（§1.1 表）**：按仓库实有编排/启动择优；库/文档等主推「不适用」。  
- **元数据目录（瘦公开 / 交付包）**：无冲突 → 主推 `.public/`。镜像可无。  
- **公开同步入口（必有归宿）**：已有则复用；瘦公开需重复同步 → 主推附录 F 最小脚本；交付包/极少同步 → 主推维护说明手工步骤；旁路已有等价且在用 → 填该入口。禁止假定外部命令、禁止摊菜单。  
- **运行环境拉取对象**：记实况；勿默认改成拉公开（除非用户大方向/口令确认跟公开 tip）。  
- **缺 URL / remote 名冲突** → 停问；「配 remote / 推公开」只进本轮动作。

### 第 3 步 · 路径与文档分面（硬；瘦公开 / 交付包；属细节）

| 类 | 含义 |
| --- | --- |
| 拟公开 | 跑起来 /（如需）部署起来 / 必要对外说明所需 |
| 拟剥离 | 过程文档、档案、本机一键/凭据、内部钩子、协作 AGENTS、裁剪元数据等 |
| 不确定 | **仅**附录 B 启发式仍无法归类、或含泄密/不可逆歧义的灰区 |

按附录 B **主动归类**。夹带表主推默认 **A**（分面机制、引导克隆协作全量仓同）。

### 第 4 步 · 出示【公开面核对】总表 → 最终确认

大方向已定后才输出 §3.1 总表：**上面**只读复述已定大方向 + 细节主推；**最下面**「请最终确认」沉底列出须拍板项。  
确认前**不落盘、不推送、不改正文**。可选另附【公开面优化建议】（勿插在「请最终确认」之上淹没选项）。

### 第 5 步 · 落盘（仅按确认结果）

在协作面写入（路径以核对确认的主推为准；瘦公开常见 `.public/`）：

- 允许列表（镜像可省略）  
- 公开用清洁 ignore 正文（导出时作为公开树 `.gitignore`）  
- README：一份 + 协作段标记（导出去掉）。推荐：`<!-- public:omit -->` … `<!-- /public:omit -->`（可改，写入 §3.3）  
- 拓扑相关 git remote（按用户所给 URL/名；仅本轮动作含配 remote 时执行）  
- **公开同步入口**：按第 2 步落盘脚本或把附录 F 步骤写入项目内维护说明  

元数据目录与允许列表默认不进允许列表。

### 第 6 步 · 试导出 / 预览 → 再确认 → 才推送

仅当本轮动作含「首次导出/同步」或「推公开」，或用户另令同步时执行：

- 调用本项目同步入口的**预览/dry-run**（若有）；否则按允许列表列出公开文件集并走附录 F 至「预览」为止。  
- 出示【导出预览】（§3.2；须选项沉底）。  
- 用户再次确认后才：推公开 / 仅本地导出 / 打交付包 / 取消。  
- 遵守附录 D。

### 第 7 步 · 完成

填实 §3.3；写入 §3.5；向用户声明日常用法见 §4。  
若有环境更新脚本：仅当 §3.3「运行环境拉取对象」为公开目标时，核对是否已指向公开 tip；否则保持实况并写「不适用/跟其它基线」。

### 3.5 日常薄规则（配完必须写入项目）

将下列正文写入 §3.3「日常薄规则落点」（尖括号换成本项目实值）。日常 AI **只读此段 + 允许列表 + 同步入口**，不再检索配置用长文。

```text
## 公开面（日常）

- 配置真源：允许列表 `<路径或镜像>`；README 协作段标记 `<如 public:omit>`；公开 ignore 源 `<路径或无>`；公开发布目标 `<remote/分支或交付说明>`；同步入口 `<脚本或手工步骤位置>`。
- 日常开发：在协作真源提交并推送全量即可；**不必**每次推公开。
- 触发检查（命中任一才巡检，否则不巡检）：
  1. 新增/移动/重命名「跑起来或部署起来」可能需要的路径，或不在允许列表中的构建/运行入口；
  2. 修改已在允许列表内的说明文（尤其根 README），或公开段新增指向过程文档/档案/本机入口/仅协作脚本的链接或路径；
  3. 用户明确要求改公开范围或同步公开目标（口令如「同步公开面」）。
- 检查动作：对照允许列表做拟公开 / 拟剥离；能按项目既有口径归类的直接主推写入简短核对；扫夹带（死链、本机入口、真实主机、引导克隆协作全量、向访客讲分面等）。仅真不清写入待确认，**一次一问**；不得静默改清单或正文。
- 确认后：更新允许列表与（如需）omit/最小改写 → **走同步入口**更新公开目标（先预览，用户确认再推）。只改协作过程文档且不影响公开段 → 不动清单、不同步。
- 改清单/推公开/强推前：先给简短核对结论，用户确认后再执行。
```

镜像模式可将「允许列表」写为「镜像同内容」，触发检查侧重密钥/PII 与推送策略；同步入口为「推公开 remote」或项目实况。

## 附录 B · 默认路径口径与启发式（供 AI 择优）

**通常拟公开**：可运行/可构建所需源码与依赖清单；与**部署形态**匹配的最小编排/启动说明与示例配置（无真实密钥）；对外 README；LICENSE / THIRD_PARTY / 必要对外变更说明；随应用可跑、无业务密钥的测试（若公开侧也要跑通）；用户已明示可公开的规范/模板包。

**通常拟剥离**：过程文档树、档案、会话上下文、内部交接与客户原件；本机一键/凭据；绑定私有环境的特化发版钩子（公开侧用通用步骤，或已脱敏且用户确认可公开）；裁剪元数据；协作专用 AI 入口全文；运维长文/内部手册（公开靠 README 摘要）；纯研发探针（bench / diagnose / e2e 手工等）。

**启发式（优先消化灰区，勿默认甩「不确定」勾选）**

| 情形 | 主推 |
| --- | --- |
| `scripts/` 含公开可用的通用启动/构建，且其余为本机/探针 | 仅通用启动/构建进公开；本机与探针拟剥离 |
| 半对外 ADR / 设计长文 | 拟剥离；对外摘要留 README（除非口令点名公开） |
| 评测基线 / 演示账号 | 无密钥且口令要公开 → 拟公开；含业务数据或口令未提 → 拟剥离 |
| 测试夹具 | 无业务数据/密钥 → 可随源码拟公开；否则拟剥离或不确定（泄密则阻塞单问） |
| README 第二托管 / 引导克隆协作全量 | 夹带主推 A（进 omit）或去掉引导 |
| 脱敏后的通用更新/部署步骤 | 拟公开；机器特化钩子拟剥离 |
| 多包仓范围 | 按对外「跑起来」实际需要的包拟公开；其余拟剥离；多解等价才停问 |
| 示例配置含真实主机名 | 不确定或主推脱敏/拟剥离（阻塞则单问） |
| 与分面无关的归档 tip/旁支 | 配置忽略，不进不确定表 |

**原则**：公开树给可复制的通用步骤与示例；机器特化路径留协作面。部署形态为「不适用」时不要硬凑编排文件。

## 附录 C · 正文夹带（允许路径仍须扫）

| 信号 | 风险 |

- **C** 从本次公开范围排除该文件

## 附录 D · 导出机械卫生

1. 仅按允许列表进入公开树；元数据与清单本身不得出现在公开树（镜像除外）。  
2. 公开 `.gitignore` 用清洁正文，不得含仅协作路径字样。  
3. README 标记导出后不得残留；不得残留仅协作入口；公开正文不得残留分面机制说明（附录 C）。  
4. 协作面根 AGENTS（若有）默认不拷入公开树。  
5. 密钥、真实 PII、内网独占地址不得进入应公开的提交。  
6. 公开目标曾有全量历史时：过滤推送不够；是否清史/轮换密钥须用户确认。  
7. **协作 tip 隔离**：导出/同步在协作工作树外进行（临时目录或独立 worktree/clone）。禁止把公开 tip checkout/reset 到协作默认分支再推协作侧。结束后协作仓 HEAD 与同步前一致（或仅含用户确认的协作侧改动）。  
8. 强推、清史、改默认分支须先用户确认。

## 附录 F · 通用最小同步（不依赖旁路管理仓）

配瘦公开且项目尚无同步入口时：由 AI **择优**落地——默认主推项目内脚本（可重复）；交付包或极少同步可主推维护说明中的手工步骤。路径/语言按项目实况主推，写入核对表确认。**任何推送/强推前须用户确认。**

### F.1 目标

从当前协作工作树，按允许列表生成导出目录 → 叠到公开目标 tip →（确认后）推送。镜像模式：无需导出裁剪，按约定直接推公开 remote。交付包：导出目录打 ZIP/交目录即可。

### F.2 步骤（瘦公开 · 分远程或同仓公开分支）

1. **读取配置**：允许列表路径、公开 ignore 源、README 标记名、公开 remote/分支（均来自 §3.3）。  
2. **建导出目录**：在系统临时目录（或用户指定目录）建空文件夹；**不要**在协作工作树内直接改成公开 tip。  
3. **拷贝**：按允许列表把文件/目录拷入导出目录（目录项拷整树）；跳过元数据目录与清单自身。  
4. **README**：若使用标记块，导出副本中删除标记及其间仅协作段，并去掉标记行。  
5. **`.gitignore`**：若有公开 ignore 源，写入导出目录根为 `.gitignore`（清洁正文）。  
6. **预览**：向用户列出导出顶层条目与文件数（或 diff 摘要）→【导出预览】→ 等待确认。  
7. **叠到公开 tip**（确认后）：  
   - 用独立 worktree 或临时 clone 检出公开分支（分远程则 fetch 公开 remote；同仓则检出公开分支到独立 worktree）；  
   - 用导出目录内容替换该 tip 的工作树文件（保留该 tip 的 `.git`）；  
   - 若无变更可跳过提交；有变更则提交（说明写「sync public tree」类现行摘要，由用户或约定生成）；  
   - **确认后**再 `push` 到公开发布目标。  
8. **收尾**：删除临时导出目录；确认协作工作树 HEAD 未被换成公开 tip。

### F.3 禁止

- 在协作默认分支上 `checkout`/`reset` 成公开 tip 再推回协作远程。  
- 未确认的强推、清史、改默认分支。  
- 假定某管理仓、某固定脚本名已存在。

### F.4 项目内脚本（主推落盘方式）

核对确认后，将 F.2 做成本项目脚本（路径按主推，例如元数据目录下 `sync-public`），§3.3「公开同步入口」填该路径。脚本须支持：**仅预览**与**确认后推送**（AI 代跑须走参数，禁止无人确认推送）。

旁路管理仓已有等价同步：§3.3 填该入口即可，仍须满足附录 D；本文不绑定其文件名或安装方式。
