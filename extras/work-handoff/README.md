# 工作交接包（通用 · extras）

> **与 AIWorkflow 三包内 `handoff`（REQ/QA/REL…）无关。**  
> 那是交付物/跨角色节点交接；本目录是**岗位/职责面的工作交接**——为让接手人能独立续作而整理的完整资料包。

把本目录（或其中 `AGENTS.md` + `规则/` + `模板/`）交给任意项目里的 AI，并说「按工作交接规范生成交接包」即可。

---

## 何时用

- 需要把当前岗位/项目侧职责整理成一份可交给别人的包  
- 轮岗、扩编、备份负责人、远程异步交接、资料沉淀  
- **不绑定原因**：不写、不问「为什么交接」

## 何时不用

- 提测、发布、PRD 定稿、缺陷签收 → 用三包内 `workflows/handoff.yaml`  
- 只交一份文档快照、要正式签收回执 → 用 `{包}/交接/{HO-ID}/`

## 怎么用

1. 复制本目录到目标项目任意位置（建议 `docs/work-handoff-spec/` 或项目根 `工作交接规范/`），或把文件内容贴进对话。  
2. 对项目 AI 说：「按 `工作交接规范` 生成工作交接包」或「整理一份完整工作交接」。  
3. AI 按 `AGENTS.md` 探查仓库与现行文档，填模板，落盘到约定目录（默认 `工作交接/{yyyyMMdd}/`）。  
4. 人核对敏感项与「待确认」字段；需要时再指定接手人并勾选验收演练。

## 目录

| 路径 | 用途 |
| --- | --- |
| `AGENTS.md` | 给 AI 的执行入口（口令、落点、红线） |
| `规则/工作交接规范.md` | 完整规范（结构、优先级、完成定义） |
| `模板/` | 交接包内各文件骨架 |

## 设计参考（口径，非抄袭条款）

企业实践常见要素已吸收进规范：按**职责/领域**建台账（而非堆文件夹）、按影响面排序、进行中事项显式移交、系统与运维清单、联系人与协作约定、隐性知识与决策背景、权限只写**位置与开通方式**、以可演练项作为「交得清」的证据。接收方与交接原因均为可选。
