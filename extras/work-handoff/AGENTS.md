# AGENTS.md — 工作交接包（通用）

> **用途**：本文件是「工作交接」专题的 AI 入口。与项目内产品/开发/测试包的 `handoff`（交付物交接）**互不替代、互不串跑**。  
> **用法**：用户把本目录交给项目 AI，或点名本规范后，按下列口令生成**通用完善的工作交接包**。  
> **原则**：目的=工作可顺利接续；**不要求**说明交接原因；**不强制**指定接收人（可写「待定 / 任意接任者」）。

## 0. 边界（硬）

1. **不是** `产品|开发|测试/交接/{HO-ID}/` 那套 REQ/QA/REL 包；不要套用 `validate_handoff.py`、不要写 HO-ID 类型矩阵。  
2. **不问、不写**交接动机类字段（如个人去向、编制变动理由）；用户主动提也不展开成包内必填项。  
3. **不写密钥/密码/恢复码/会话 Cookie**；权限章只写系统名、角色名、申请入口或保管位置。  
4. 事实字段（URL、负责人、环境、日期、仓库地址）必须来自仓库/配置/权威文档/用户确认；未核实写「待确认」。  
5. 优先引用仓库内已有文档路径，**少复制大段正文**；包内写摘要 + 链接/相对路径；仅当外部原件无稳定路径时才拷入 `附件/`。

## 1. 口令 → 动作

| 命中（任一） | 动作 |
| --- | --- |
| 生成工作交接包 / 整理工作交接 / 按工作交接规范交接 / 输出岗位交接资料 / 工作交接 | 按 §2 全量生成或增量补全 |
| 补全工作交接 / 更新交接包 / 刷新交接台账 | 读已有包 → 只更新变化项与日期 |
| 交接验收清单 / 交接演练项 | 只生成或更新 `09-验收演练清单.md` |
| 工作交接规范 / 交接包怎么用 | 简述 README + 规范 §1～§3，不落盘 |

首条回执建议：`route=work-handoff | action=generate|update|checklist | out=<路径> | reason=…`

## 2. 生成步骤（必须按序）

1. **读规范**：`规则/工作交接规范.md` 当前全文（本专题允许通读；控制在本目录内）。  
2. **探查项目**（有仓则做，无则标待确认）：
   - 根 README、`AGENTS.md`、档案/基线/`activeContext`（若有）
   - 主要目录与技术栈线索（`package.json` / `go.mod` / `pom.xml` / `docker-compose` / `Dockerfile` 等）
   - 近 6～12 个月活跃路径（可选：`git log --since=… --name-only` 汇总目录热度；无 git 则跳过）
   - 文档树：`docs/`、`产品/`、`开发/`、`测试/`、`运维` 等现行入口
   - CI/CD、部署脚本、监控/告警入口（若有）
3. **建包目录**（默认，可被用户改）：

```text
工作交接/{yyyyMMdd}/
├─ 00-交接包说明.md
├─ 01-职责与领域台账.md
├─ 02-领域知识地图.md          # 可按领域拆多份：02-{领域}.md
├─ 03-进行中与待办.md
├─ 04-系统资产与仓库.md
├─ 05-运维发布与值班.md
├─ 06-联系人与协作约定.md
├─ 07-隐性知识与决策背景.md
├─ 08-权限与访问位置清单.md
├─ 09-验收演练清单.md
├─ 交接索引.md
└─ 附件/                       # 仅无稳定仓内路径的外部件；可空
```

4. **填模板**：以 `模板/` 为骨架；删不适用节时写「不适用 + 一句理由」，禁止留大量 `{占位}` 充数。  
5. **接收人**：默认 `接收方：待定（任意接任者可读）`；用户点名再写入。  
6. **自检**（写入 `00` 末尾勾选）：
   - [ ] 职责台账覆盖主要日常与突发职责  
   - [ ] 高影响领域有地图或明确「已知缺口」  
   - [ ] 进行中 PR/承诺/排期有归属建议或「待指派」  
   - [ ] 无明文密钥  
   - [ ] 索引与各文件互相可跳转  
7. **对人**：列出「待你确认」表（仅阻塞项：敏感系统是否可写进包、对外联系人是否可公开到包内等）。

## 3. 深度与裁剪

| 档 | 何时 | 产出 |
| --- | --- | --- |
| 轻量 | 小项目/单人工具/用户只要「一页总览」 | `00` + `01` + `03` + `交接索引`；其余合并进 `00` 附录或标不适用 |
| 标准（默认） | 一般业务项目 | 00～09 齐全 |
| 加强 | 多系统/有值班/有对外厂商 | 标准 + `02` 按领域拆分 + `05`/`08` 加细 + `09` 含独立演练项 |

不确定用**标准**；用户说「简单点」再降到轻量。

## 4. 与三包交接的关系

| | 本专题工作交接包 | 三包 `handoff` |
| --- | --- | --- |
| 单元 | 职责 / 领域 / 岗位续作 | 一次交付物（提测、发布…） |
| 目录 | `工作交接/{日期}/`（可改） | `{产品\|开发\|测试}/交接/{HO-ID}/` |
| 接收方 | 可待定 | 通常有明确角色 |
| 完成 | 资料齐 + 建议演练项 | 包校验 +（正式时）回执 |

二者可并存：工作交接包里用路径**引用**近期 HO 包或提测单，不要把 HO 整包复制进来。
