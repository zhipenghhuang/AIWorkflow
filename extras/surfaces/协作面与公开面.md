# 协作面与公开面（通用说明）

> **读取级别：可选专题（默认不读）**  
> 复制到任意项目后，仅在用户点名「协作面 / 公开面 / 双面 / 开源面」时参考。  
> 本文是**规则与模式教材**，不绑定具体托管商或某套管理脚本；实例选择（分仓、分支名等）由项目自己的配置或统一管理工具决定。

---

## 1. 三个面

| 面 | 含义 | 典型内容 |
| --- | --- | --- |
| **协作面** | 团队日常真源：完整工作树 | 代码 + 工作文档 + 协作专用材料 + 可提交的上下文 |
| **公开面** | 对外可见的派生视图 | 开源子集、交付源码、服务器只需的公开代码与对外文档 |
| **仅本地** | 永不进入任何 git 远程 | 本机路径写死的工具、含密钥的本地配置、个人草稿若选择不入库 |

铁律：

1. **未公开内容靠「不在公开树里」实现**，不要靠公开仓的 `.gitignore` 点名隐藏内部路径（避免公开 ignore 变成内部结构说明书）。
2. 公开面若需要 ignore，使用**清洁的公开用 ignore**（只写公开消费者需要的规则，如依赖目录、`.env` 模式）。
3. 「仅本地」文件在协作仓的 ignore 中排除即可；它们既不进协作远程，也不进公开远程。

---

## 2. 拓扑模式（并列；无唯一真理）

按团队约束任选其一（或组合）。统一管理工具可能只实现其中一种——**以该工具文档为准**；本文描述通用选项。

### 2.1 分远程（双托管）

- 协作远程：全量 `main`（或团队主分支）。
- 公开远程：仅公开子集（常映射为公开仓的 `main`）。
- 适合：已有两个托管地址；服务器只 clone 公开远程。

### 2.2 同仓不同分支

- 同一 remote：例如 `main` = 协作全量，`public` / `release` = 公开子集。
- 推送时分支分流；对外默认分支可指向公开分支。
- 适合：只维护一个托管仓，但仍要隔离可见内容。

### 2.3 单公开仓 + 协作外置

- git 只保留公开面；协作文档在 Wiki / 文档仓 / 其它私有仓。
- 适合：开源为主、协作文档本就不想进应用仓。

### 2.4 交付包 / 过滤导出

- 不维护第二 git 史；按清单打 ZIP/目录交付或发版。
- 适合：给客户源码包、一次性导出。

### 2.5 模式对照（简）

| 模式 | 第二历史 | 服务器常见拉法 | 复杂度 |
| --- | --- | --- | --- |
| 分远程 | 有（另一 remote） | 拉公开 remote | 中 |
| 同仓分支 | 有（另一 branch） | 拉公开分支 | 中 |
| 外置协作 | 无（在仓外） | 拉唯一仓 | 低（仓内） |
| 交付包 | 无 | 不依赖 git | 低～中 |

## 3. 清单

每个启用双面的项目维护**机器可读允许列表**（文件名自定，常见 `public-surface.txt`）：

- 一行一个路径；目录建议以 `/` 结尾表示整树。
- `#` 开头为注释。
- 未列出 = 默认不进公开面。
- 可选另备 `public.gitignore`：随公开面发布；**禁止**写入仅协作/仅本地路径名。

建议分类：

| 类别 | 公开？ |
| --- | --- |
| 对外源码、LICENSE、对外 README、公开 API/ADR | 通常是 |
| 协作专用扩展目录、个人/团队过程上下文、内部交接包、客户原件 | 通常否 |
| 本机专用脚本（路径写死） | 否（仅本地 ignore） |

---

## 4. 公开面卫生

1. 导出/同步后，公开树中**不存在**未允许路径。
2. 公开 `.gitignore` **不出现**仅协作或仅本地路径字样。
3. 密钥、真实 PII、内网地址不得进入任何应公开的提交；协作面也要脱敏。
4. 若曾把全量历史推到将公开的 remote：过滤推送不够，需轮换密钥并视情况重置公开史。

---

## 5. 与统一管理工具的关系

若项目由「多仓统一提交/部署」类工具管理：

- **是否双面、推哪一侧、服务器拉哪一侧** → 以该工具的登记配置为准。
- 本文只提供概念、模式与清单骨架；**不要求**每个项目实现全部拓扑。
- 点名「按公开面清单同步」时：先读本项目清单与工具配置，再出【公开面核对】，确认后才推送/导出。

---

## 6. 点名执行协议（给 AI）

触发词示例：协作面、公开面、双面、开源面、导出公开包、同步公开。

1. 读本项目公开清单（无则按本文骨架起草候选，停问）。
2. 扫描工作区 → 拟公开 / 拟剥离 / 不确定。
3. 出示【公开面核对】（含公开 ignore 是否清洁）。
4. 用户确认后，按项目选用的拓扑执行（分远程 / 分支 / 打包…）。
5. 未确认不推公开、不改默认分支、不强制推送。
