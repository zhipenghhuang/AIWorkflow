# 工作交接

把本文发给**任意项目**里的 AI，说「按工作交接生成交接文档」即可。  
AI 探查仓库与现行文档后，按下方骨架输出**一份**完整交接文档（可直接保存为 `工作交接.md`），表格填实；无内容写「无」或「不适用」，禁止大段空占位。  
**独立通用**：不依赖、不假定某一托管商、某一多仓管理仓库或固定目录结构；有什么写什么，没有的整节标「不适用」并一句理由。

**生成要求（给 AI）**

1. 面向可能完全不熟项目的接手人：先讲清项目是什么、怎么跑起来、现在做到哪。  
2. 优先写可操作信息（地址、账号、命令、路径、联系方式）；按实际需要写入接手必需信息。  
3. 探查整个仓库里的文档、配置、脚本与代码结构；能引用路径处写路径，重要结论仍写进正文。  
4. 事实来自仓库、配置、文档或向用户确认；找不到的标「待确认」，**不要臆造**；不确定就问用户（一次一问），不要留空表充数。  
5. **按项目类型裁剪**：库/工具/文档仓/无上线/无 CI 等 → 构建发布、监控值班等节可整节「不适用」；禁止按「典型 Web 生产」编造入口。  
6. 按影响面详略：核心系统与进行中事项写细，边角可一行带过。  
7. 只输出一份交接文档正文，不要另造多级目录或说明书套娃。  
8. **敏感信息**：写入前问用户是否允许明文写入本交接档、以及本档是否只放协作侧/禁止进公开远程；用户不同意明文则写「位置/变量名/索取方式」，不写口令正文。  
9. 生成后列出「待确认」表（仅仍不确定项）；已核实的不要重复盘问。
