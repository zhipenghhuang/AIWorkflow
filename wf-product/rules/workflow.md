> **读取级别：参考**（按节读取；按 `读取索引` 只读当前 step 节，禁止通读全本）。

> **计划同步/变更传播/自主边界**：见 `core/execution-contract.md` §2/§4；本文不重复。

## 1. 铁律（不可让）

1. **PRD 定稿前不排期**（`confirm_prd`）；未定稿只做洞察/评审。
2. **无变更单不实施变更**（`confirm_change`）；口头变更一律先落单。
3. **UAT 未过不发布**（`confirm_release`）；带条件通过须列遗留/责任/接受人。
4. 每条需求有**可判定验收标准**；无优先级不排期。
5. 引用可回查（来源+日期）；**禁臆造**数据/反馈/竞品结论。
6. 上线必须定义**成功指标与埋点**（不适用须写原因）。
7. **新产品先立项**（`confirm_go`）：未过立项不写全量 PRD；结论只能 Go / Hold / Kill。
8. **计划总领**：`{workroot}/product-plan.md` 为版本/范围/里程碑的单点；计划未确认（`confirm_plan`）不进入 PRD/排期；计划不替代 PRD。单需求可用已批准的 `confirm_scope` 范围结论作为 PRD 依据，不强制完整产品计划。  
9. **原型未过设计评审不交开发**（`confirm_prototype`）；原型为静态 HTML/CSS，不等于生产代码。  
10. **受理先定性**：新需求/变更/缺陷/开发不确定先入受理单（`change` 工作流）并分诊；已在需求池/立项书/产品计划范围内，或点名补 PRD 的，可直接写/改 PRD，不重复受理。  
11. **产品缺陷有依据**：产品缺陷必须有 PRD/设计原文 + 现网/测试证据 + 相符证明；实现缺陷退回开发/测试，不改 PRD；无依据不得判产品缺陷。  
12. **联动不留旧版**：变更/缺陷处置后，按受理单 §6 更新所有受影响产物并标「已更新/不适用/待补」；未回写、未验证不得关闭。  
13. **平台回写有确认**：拉取/只读不设门；备注/附件/状态/指派回写必须 `confirm_remark`；备注与状态同轮；附件回查挂载；禁删缺陷；无权限/未适配走 `export`，不得声称已回写。  
14. **交接内容优先、包按需**：默认交自洽主文档（PRD/设计结论/变更单等）；对照发出前合格线；HO 包仅多文件/签收/仓外/点名时先问后发。多包同仓直读不转发；收件走入站/吸收；未回执不得称「已接收/已交接完成」；正式签收/C2·C3/发布须回执；仅通知/同仓直读/用户代收 → 已发送+用户确认可关；C2/C3 重基线；有平台已回写不强制 BUG 整包。  

## 2. 产物与过程（相对项目根）

```text
{workroot}/                         # 产品工作区唯一根；原件根 inbound/、权威文档库 docs/materials/ 不属本树
├─ product-plan.md                # 总领单点：总控表 + 路线图 + 本期执行
├─ requirement-pool.md            # 滚动单点（去重/分级/状态）
├─ work-log.md                    # 岗位里程碑侧记（非根 CHANGELOG）
├─ 00-governance/                    # 接入核验、能力/技能体检等治理产物
├─ user/                          # 对外交付：快速开始/用户手册/FAQ/发布说明/培训材料
├─ {ver}/
│   ├─ 10-requirements/              # 立项书、洞察、PRD、评审
│   ├─ 20-design/                    # 设计情境、IA、线框、高保真、tokens、工程化检查、设计评审、可用性、开发交接
│   ├─ 30-changes/                   # 受理、变更单、产品缺陷处置
│   ├─ 40-delivery/                  # 交付计划、UAT、GTM
│   ├─ 50-showcase/                  # 展示需求、故事线、演示脚本、一页纸、Deck、检查单、反馈
│   └─ 90-retrospectives/            # 复盘
├─ capabilities/                  # 实例能力清单/绑定
├─ handoff/                       # outbound|inbound/{category}/ + handoff-ledger.md
└─ _archive/
    ├─ {yyyy-Qn}/产品计划-{yyyy-Qn}.md   # 季度快照（主档不移动）
    └─ {yyyyMMdd}-{ver}/                    # 版本/结项工作文档
```

- 外部输入原件在 `inbound/`；定稿、完整、可发送的产品文档发布到 `docs/materials/{ver}/`（`01-requirements`、`02-design`、`06-release` 等域）。
- 材料库不设 `_archive`；旧版本保留，`INDEX.md` 标 `current/superseded`。

- 单点滚动：`{workroot}/requirement-pool.md` 只留现行状态；同一需求的多份文档就地更新，不写历史过程。  
- 受理/变更：一条需求/问题一份受理单；变更单只在改动已定稿基线时产生；受理单链接变更单、PRD、交付计划、UAT，联动清单未闭合不得关闭。  
- **计划总控**：每阶段完成 → 更新 `{workroot}/product-plan.md` §0 状态/当前门/下一动作、§10 执行日志；「继续 / 按产品计划执行」从当前状态续跑；计划偏离走 §8 决策记录（变更/缺陷另走 `change` 受理与变更单）。  
- **计划状态**：草稿 / 已确认 / 执行中 / 变更中 / 待关闭 / 已关闭；计划未确认不进入 PRD/排期。  
- **主档不移动**：`{workroot}/product-plan.md` 常青；季度结束复制当期执行到 `{workroot}/_archive/{yyyy-Qn}/产品计划-{yyyy-Qn}.md`，主档保留 §11 历史索引并重置当前季度。  
- 归档：版本/换代/结项 → 当期目录整体移入 `{workroot}/_archive/{yyyyMMdd}-{ver}/`（用户点名）；旧季度只归档快照，不移动主档。确认采纳且 S1/S2/S3 → 工作区旧稿同批进 `_archive/{yyyyMMdd}-{ver}/`；inbound 原件只改 INDEX 状态，不归档。  
- 素材进 `inbound/{ver|topic}/` 或 `_common/`（禁 `项目文档/`、禁强制类型前缀；类型写索引；登记 `inbound/INDEX.md`）；正式产物不进 `inbound/`；定稿发布 `docs/materials/`。  
- 新资料先按 `rules/doc-governance.md` §3 入站意图（T1～T9）+ §4 收取/覆盖对照，输出候选；**用户确认后**才改名/登记/标记旧文件失效/同批归档。  
- **资料 vs 工作文档**：`inbound/` 只放外部输入；本包 PRD/原型/评审等工作文档在 `{workroot}/{ver}/`；`{workroot}/user/` 放对外交付文档。分类/覆盖对照/失效/归档以 `rules/doc-governance.md` 为准。单包优先闭环，不自动跑他包。

## 3. 拟提交（`hitl: confirm_commit` 时）

> 与收尾第 2 点「待提交摘要」分工：摘要在收尾；本块仅确认门一次出示。三包共用下列字段；默认仅本地提交，推送须点名并单独确认。

```text
【拟提交】
- 文件：{清单}
- .gitignore 现状：{一句}
- 当前分支：{名}；跟踪远程：{origin/xxx 或无}
- 本次动作：仅提交（默认） / 提交并推送（须点名）
- 推送目标/CI：{不推送 / remote+分支+CI；仅点名推送时填}
请确认后执行。
```

未确认不得提交/推送；真实用户数据/PII 不入库。提交信息：`产品 {版本/主题}：{简述}`；一次提交一类文档。  
**尽早提交**：重要改动确认后尽早本地提交，勿长期只停在工作区。  
**多 remote / 异形 tip 隔离（条件硬）**：仓库另有 remote，或存在与日常工作分支内容不同形的 tip 时——禁止在当前工作树对该 tip 做 `checkout`/`reset`；对该 tip 的同步或历史改写只在临时目录或独立 worktree。仅单 remote 且日常即在该 tip → 跳过。

## 4. 阶段护栏

- **洞察**：来源分层（用户/客服/数据/销售/竞品/合规）；每条留来源与日期；同问题去重合并。
- **竞品**：模式 S（竞品分析）= 拆解 + 借/改编/不借 + 回绑问题；模式 P（竞品对标）= 矩阵 + 差距候选项；进版本均须确认；禁功能清单直接 Must。
- **0→1 / 立项**：先验证问题/市场/用户/竞品学习（立项书），Go 才进入定义；未过不写全量 PRD；Hold 列待验证项与责任人。
- **计划**：目标/KR/路线图/本期范围/里程碑进计划；计划确认后才排期；计划只做总领，不写需求细节。
- **原型/设计**：无设计师时 PM 出原型；IA → 线框 → 视觉 → 高保真 → 设计评审 → 交接；状态/响应式/无障碍必做；文案减法（删冗余文案/标签，删后不清楚改布局）；未过评审不交开发。
- **PRD**：要素齐（模板为准）；验收标准可判定；状态机/权限矩阵/异常边界不得省；埋点与指标写清。
- **评审**：独立复核（不替写）；只报缺口；需修回 PRD，同回合重审≤1。  
- **受理/分诊**：对话/文档/缺陷单统一入受理单；先判新需求/变更/答疑/产品缺陷/实现缺陷/技术不确定；产品缺陷须有相符证明；实现缺陷退回开发。  
- **缺陷平台**：按 `rules/defects/platform-collaboration.md` 拉取指派给产品的缺陷，读全 steps/备注/附件/方案；分析后走 change 处置；回写备注/附件/状态/指派前 `confirm_remark`；未配置走粘贴/export。  
- **交付/变更**：PRD 定稿才排期；变更走单（影响/成本/风险/回滚）；答疑书面留痕；实质变更重审后才恢复定稿。  
- **联动**：处置后更新 PRD/AC、原型、评审、交付计划、产品计划、需求池、UAT、发布检查与通知回执；每项标状态，未闭环不关闭。  
- **协作/交接**：需求/设计/计划/变更/UAT/发布按 `rules/collaboration/handoff.md` 交主文档/按需发包；正式签收/C2·C3/发布须回执；仅通知类已发送+用户确认可关；未回执不得称已接收；C2/C3 重基线；计划/台账/索引同轮回写。  
- **UAT/发布**：逐条对照验收标准（结果+证据）；产品缺陷≠实现缺陷；发布就绪（回滚/公告/客服/监控）才发。
- **上市（GTM）**：定价/渠道/物料/销售客服赋能；与 UAT 发布门咬合；对外承诺须已确认。
- **展示/介绍**：受众/目标 → 故事线/Mermaid 流程图 → 演示脚本（点击级）→ Demo 检查单 → 材料/用户文档 → 彩排；对外前 `confirm_materials`；与当前 PRD/原型/构建一致，未实现不演示。
- **复盘**：目标 vs 实际、指标达成、根因、改进项→回需求池（含责任人/期限）。

## 5. 收尾骨架

所有完整任务统一用 `rules/templates/90-handoff/closeout-skeleton.md` §1 通用占位（6 点字段下限；按项目事实填，禁照抄他例）；下表只规定第 1 点可带的领域要点，**不另造汇报句式**。第 1 点须短段 +「影响：」；「汇报」独立成块（六点前）。【今日工作总结】见骨架 §2 / 口令表行 0。

| 任务类型 | 第 1 点领域要点（写入「完成了什么」或「影响」；汇报仍用结论说明体） |
| --- | --- |
| PRD | 主题/版本、落盘路径、要素自检与引用抽验、待决项 |
| 计划 | 周期、目标/KR、路线图、本期范围（含 §3.0 Brief+差量表）、里程碑/风险、计划确认 |
| 立项 | Go/Hold/Kill、依据、待验证项、立项书路径、竞品学习摘要（若有） |
| 竞品分析/对标 | 模式 S/P、文档路径、学习决策或差距候选项数、是否进版本 |
| 原型 | IA/线框/视觉方向/高保真路径、设计评审结论、交接要点 |
| 评审 | 通过/需修、缺口（条目/问题/建议）、记录路径 |
| 受理/处置 | 受理编号/类型、分诊依据/结论、处置、联动变更、最新产物路径、回执/待办、verify/关闭 |
| 缺陷平台 | 拉取/产品缺陷/实现缺陷/立即修/下版/不修/退回/补充信息；回写成功/待回写/失败；每条处置与最新文档 |
| 交付/验收 | 范围/进度、变更单清单、UAT 结论、发布就绪项 |
| 展示/文档 | 受众/目标、故事线/流程图、演示脚本/材料/用户文档路径、项目对齐检查、彩排/反馈、拟提交 |
| 复盘 | 目标 vs 实际、指标、根因、改进项（回池）、责任人/期限 |

## 6. 受理与变更（短指针）

步骤顺序与条件链以 `workflows/change.yaml` 为准；方法见 `rules/playbooks/change.md` + `skills/change-management/SKILL.md`。P0/P1 必走 `intake→triage→apply→verify`（改基线才 decide）。关单回执：正式签收/C2·C3/发布须回执；仅通知/同仓直读/用户代收 → 已发送+用户确认可关。未verify/联动未闭合不得关闭。

## 7. 子代理编排（摘要 · 单一出处 `rules/collaboration/subagents.md`）

- **取档**：工具 → 直做 → 分片 → 拆分；达阈值应拆或 `deviation=subagent_skipped`；开跑声明 `mode=`。  
- **并行**：只读扇出与文件不相交写分片可并行≤3；同一 PRD/计划/受理单/`index.html` 禁并行写。  
- **降级**：超时/空产物/违规 → 同回合直做 + `subagent_degraded`；宿主无子代理 → `unavailable`。  
- **回收**：返回 ≤30 行；独立核验只收产物＋验收＋证据；批末核验后再下一批。  
- **边界**：子代理不过门、不 git、不平台、不对外发布；判断/五选一/发布/回写集中。
