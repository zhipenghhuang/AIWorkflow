# 门面与对外事实同步（产品）

> **读取级别：参考**（事件触发时读；收尾不再强制 `facade=` 字段）。

> **定位**：根 `README.md` 与档案中**对外可见句**的事件触发同步。  
> **不替代**：状态「三处同拍」（计划 §0 ↔ 导航 INDEX ↔ `activeContext`）只认 `global-rules.md` §8；事件级同步矩阵见 `execution-contract.md` §4（参考）；关账/materials 仍认 `doc-governance.md` §7。  
> **禁每轮全扫**：未命中下表触发 → 不打开、不对账根 README；日常身份短读仍只读档案。  
> **写法**：轻量改已有对应句；结构大动走 `project-readme.md` 偏好确认。实例面禁写工作流包用途/装载/升级（见 `AGENTS.md` 多包·实例面）。  
> **根 CHANGELOG**：本包**不写**；发版史由开发包维护。

## 2. 触发矩阵（事件 × 必/可）

| 触发 | 档案/总览 | 根 README | materials README | 根 CHANGELOG | 三处同拍 |
| --- | --- | --- | --- | --- | --- |
| 日常 / 语义未变 | 否* | 否 | 否 | — | 可只改进行中 |
| 阶段·门·焦点·下一步语义变 | 否* | 否 | 否 | — | **必** |
| 本轮核实的**对外可见事实**变（产品定位句、对外文档链等，且 README/档案已有对应句或本应有） | **必**（命中行） | **必**（对应句；无产品句则 `na`） | 否 | — | 按需 |
| **版本/迭代主题 bump**（对外版本或迭代名变） | **必** | **按需**† | 关账时 | — | 阶段变则必 |
| **迭代关闭**（确认后 §7.1） | **必**（指向下期） | **按需**† | **必** | — | **必** |
| **发布 / 上线**（产品侧交付收口；正式记录归开发） | **必** | **按需**（产品对外句） | 按发版 | — | **必** |
| 资料不足升级 | **必** | 有缺口则**必**补；无=`na` | 否 | — | 热层 |

\*纯状态跳变不改档案地图。  
†README 仍写已关闭迭代为「当前」或产品入口已断 → 必须改；否则可 `facade=na`。

**对外可见事实（判定）**：会出现在根 README 或对外产品说明上的现行值；内部 PRD 过程句、待决讨论、仅 AI 工作流路径不算。

## 2.1 冷层定点核对（矩阵「必」触发时 · 禁全扫）

命中上表对档案/README 为「必」的行时，只核**已存在**命中句（无则该项 `na`）：

1. **对外版本/迭代名**（档案或 README 现行展示）与本轮核实一致。
2. **产品定位/对外文档入口句**（README/档案已有对应句）未断、未指已关闭迭代为「当前」。
3. 其它本轮已核实且已断的对外句 → 只改该句。

预算：≤3 次定点打开。热层已更、冷层仍写旧现行值 → 不得称同步完成。

## 3. 执行顺序与预算

1. 先改身份真源，再改根 README 对应句；禁只改 README；禁写根 CHANGELOG。  
2. 只改**本轮已变**相关句；禁止为「保险」通读全文。  
3. 无根 README 或无可改产品句 → README 项 `na`；档案命中行仍按矩阵回写。  
4. 推迟 → 收尾 `冷层:deferred:<原因>`；必触发未做且未 defer → 不得称同步完成。

## 4. 收尾 `sync=`

命中矩阵「必」：`sync=` 须含 `冷层:ok|na|deferred:<因>`；未命中触发 → 写「无门面变化」（不必读本文件全文）。有门面句改动时第 6 点一句说明。
