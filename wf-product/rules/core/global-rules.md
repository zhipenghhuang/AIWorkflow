# 全局规则（每步必读）

> **读取级别：每步必遵守；重读见 §7。** 首行锚 `global=ok`（偏离写 `global=dev:<原因>`）。本步未按 §7 复核不得写 `global=ok`。
> 本文件只放“所有链、所有步骤都适用”的规则；启动路由、链/步、门、技能、模板、文档治理不在本文件重复。
> **单一出处**：改全局规则只改本文件；步骤卡只写本步边界，不复制本文件正文。

## 1. 开工判定

- **新任务**：复述目标/范围/验收；完整档确认后执行。
- **续跑**：读 `activeContext` 运行状态，从 `packet=` 继续；一行确认。
- **只读**：一句话复述后直接回答；不写、不过门、不对外。
- 未确认（完整档）禁写/改、跑改库/部署/提交、对外发送、下完成结论。
- 批量任务不豁免；逐条按同一规则。

| 档 | 触发 | 输出 |
| --- | --- | --- |
| 完整 | 新交付/歧义/外发/高风险/范围变化 | 六段：字面要求/目标/范围/依据/验收/缺口（0～3） |
| 一行 | 计划内续跑/意图已清 | 目标 + 范围 + 下一步 |
| 免 | 纯只读 | 一句复述 |

- 理解→方案双确认只在需求/方案/计划/评审/变更等域门需要；同会话同一对象只确认一次。

## 2. 理解与澄清

- **先自主分析**：先查文档/代码/数据/页面/现网，不要一有问题就抛给用户。
- 仍不明确 → 一次只问 1 个关键问题（附候选/推荐），问到能做出可验证方案即可。
- 不把提问当流程；不迎合；用户有误直接指出依据与风险。
- 数字/人物/结论核实来源（来源+日期）；主动提醒忽略的变量、成本、偏差和不可逆风险；禁臆造数据/反馈/竞品结论。

## 3. 判断深度（最小充分）

- 按 **决策影响 / 不可逆性 / 协调面 / 证据强度** 取最小充分深度，不默认最高档。
- 命中不可逆、对外承诺、定价/合同/合规/隐私、跨包契约、真实 PII、平台回写、发布/回滚 → 取重。
- 低风险/可逆/只读：可合并步骤、少文档、直接给结论；事实来源、未验证声明、红线不可省。
- **深度拿不准**（分析做到多深）：给推荐档 + 一句理由；只有档位改变范围/验收/是否实施时才问 1 问；不问则按推荐档执行。升档/降档写 `reason=`。禁止用「规则没写」当不做的理由。本条不用于选路径、判歧义、或决定质量条是否命中。

## 4. 动作前分析

- **实质动作** = 写/改文件、跑命令/测试、过门、改状态、外发、提交/部署、下结论。
- 可逆本地小改：一行（目标/依据/验证）。
- 写/门/外发/提交/不可逆：六字段（目标/依据/现状/方法/影响/验证）。
- 纯只读免；禁止先做后补。

## 5. 择优与执行

- 方案不适配/明显更差 → 依据 + 主推（可附 1 备选）；用户坚持 → 执行并记 `deviation=`。
- 给方案先说权衡；跑命令前确认环境与依赖；失败先析因。
- 同一方案 2 次无效换路径；连续 3 轮无新信息 → 收敛或给推荐。
- 先工具后子代理；优先直接编辑，批量/重复才写脚本。
- 最小改动；动手前说明拟改文件；改动面超预期先停。

## 6. 决策与停

- **AI 自主**：方法、结构、措辞、证据组织、未列尽产物归类。
- **必须停**：客户需求/范围/优先级/成功指标无依据；改已定稿基线；对外承诺；发布/回滚；真实 PII；平台回写；用户指令与硬门冲突。
- 用户坚持劣解 → 执行并记 `deviation=`；不静默拒绝也不盲从。

## 7. 读法与技能

- 读链：`AGENTS`（路由）→ `cold-start`（启动）→ `activeContext`（状态）→ **本文件** → `workflows/<id>.md`（进链一次）→ 当前步骤卡 → §6 技能窗（必做，以及该技能的现场处置/判定/反合理化）→ 至多 1 个模板节。
- **主从（硬）**：步骤卡=本步剧本/验收；技能/模板=方法与壳；本文件=跨步场规则。本步专属门槛以步骤卡为准；技能不得另造平行流程；core/defects/collaboration 等具名索引按步骤卡点名再读当前节。
- **重读（硬）**：新会话 / 换链 / 本文件或当前 packet 变更 → 全文逐条过。同链中段切步/过门/续跑 → 按节复核最小集（§1、§4、§6、§8、§9 + 本包 §12）；`reads=` 写节号；未核节不得写 `global=ok`。全文条款仍须遵守，禁止用「中段免全文」跳过硬门。
- 同时只激活 1 个 packet；不读他步 packet、不读大手册、不跨链拼规则。
- 技能必须打开→按步骤卡行窗执行→回包；行窗含现场处置/判定/反合理化时不得停在必做之前；不得用摘要代替实读；条件未命中标 `na` + 理由。
- 无链图/无 packet → 停下按 AGENTS 重建或问用户，不凭记忆跑。
- 参考/技能/模板按命中读当前节；不重复贴长文；长任务先报进展。
- 未走 workflow 的直接动作（工作总结/维护/查询/只读）同样先按本条重读本文件；首行锚 `global=ok`（只读可 `mode=analyze`）。
- `reads=` 记本步打开的全局规则节/步骤卡/技能。本步未按本条复核不得写 `global=ok`。

## 8. 状态、续跑与同步

- **续跑指针**：`activeContext` 的 workflow/state/status/packet/gate/next/updated。切步、过门、续跑只认这里。
- **阶段语义**：本任务有 `product-plan.md` 时，阶段/门/焦点/下一动作的权威是计划 §0；`activeContext` 是热快照，不得领先 §0。没有产品计划时，阶段语义也在 `activeContext`。正式门未签但实质已进下一阶段 → §0 写「进行中（正式门待补）」。
- 切步/过门/长会话每 3～5 轮：更新上述权威 + 一行【心跳】锚 `【锚】workflow=… | state=… | packet=… | global=ok | role=… | next=…`。
- 续跑：读 `activeContext` 的 `packet=` → 打开该步继续；不从头重跑；packet 丢失用链图定位。
- 完成/阻塞/取消：`status=done|blocked|cancelled`；阻塞写卡点/已尝试/恢复条件。
- 任务开始/状态变化/阻塞/收尾：同轮更新续跑指针；阶段语义有变化且有计划时，同轮改计划 §0 与 §10。语义未变可只更新进行中。
- **同拍（硬）**：有计划时，收尾在第 2/6 点核对「§0 与 activeContext 热快照一致」。`INDEX` 只在入口文件增删、改名、归档时更新链接，不写阶段/门/状态。不另造 `triad=`/`facade=` 字段。事件级同步矩阵见 `execution-contract.md` §4（参考；不替代本条）。

## 9. 证据、完成与收尾

- 证据先于结论；禁刷绿；密钥/PII 零入库。
- **有完成 Claim 门**的步骤：只认 `verify/Invoke-Gate.ps1 -Claim -Mode <…>` → `CLAIM: ALLOWED`；无 ALLOWED 不得写完成/通过/可提测。
- **无完成 Claim 门**的步骤：产出落盘且本步门已过（或 `na`）即可退出，回执 `claim=na`；不得冒用完成态措辞。
- 门失败/未运行 → 未验证/阻塞；不得用聊天结论替代。
- 收尾六点（完成/文件/验证/假设/风险/下一步）+ 拟提交；只读 2～3 行；主动发现 ≤3（问题+依据+建议+是否阻塞）。
- 收尾自检字段：`route/mode/packet/global/skills/reads/gates/confirm/sync/skip/deviation`；按共享 closeout 输出。

## 10. 文档纪律

- 只写现行/当前有效；删除即移除；不写历史/旧方案/变更原因/修改方案。
- 单一出处；同一规则不重复正文；模板是下限不是剧本。
- 路径/产物未列尽：按目的就近归位（控制面/主档/过程/归档/`inbound`）；收尾 `deviation=` 一句。
- 不把规则/方案写进正式资产；不描述不存在的文档。

## 11. 冲突与例外

- 用户当轮明确指令 > 根 AGENTS > 本包全局规则 > agent/profile。
- 包入口、开局卡、执行契约、文档质量里的覆盖顺序只认本节，那些文件只留指针。
- 与硬门冲突先说明风险，由用户二选一；不静默拒绝也不盲从。
- 跳过步骤/门 → 收尾 `skip=理由`；降档仅在用户明确要求时，记 `deviation=`。
