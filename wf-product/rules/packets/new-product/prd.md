### 技能 `prd-writing`

# PRD 撰写（技能 · 随包生效）

> 用于：prd 步。按 `rules/templates/10-planning/prd-template.md` 落盘；本技能=把 PRD 写到**可开发、可测试、可追溯**。  
> **写前门槛**：须已完成理解+方案双确认（受理单/澄清记录/需求池确认列）；澄清程序**按 澄清纪律（一次一问、候选答案、未确认不升格）。**未双确认不得**写正式 PRD / 称可开发（可出标「待确认」草稿）。每条 F/R/AC 必须能指到来源；无来源列 `Q-xx`；未确认推断标「假设」。禁止把单个客户/竞品做法/领导偏好写成市场需求。

## 1. 写作顺序（16 节）

元数据 → 摘要 → 背景/依据 → 用户/场景 → 范围/边界 → 功能 F-xx → 业务流程图 → 状态机 → 权限矩阵 → 数据/字段来源 → 校验规则 R-xx → 异常/边界 → NFR N-xx → 埋点/指标 → 验收 A-xx/AC-xx → 追溯矩阵 → 待确认/决策 Q/C → 评审误区/依赖/风险/里程碑/变更。

## 2. 图（Mermaid 必填）

- **主流程**：`flowchart TD`，判断出线标“是/否”；异常/补偿路径可见；复杂流程加子流程。
- **状态机**：`stateDiagram-v2`，状态×事件；每个非法跃迁写拒绝表现；终态重入必须定义。
- 图与文字同源：图中每个节点在功能/rules/验收中有对应；不做“装饰图”。

## 3. ID 与追溯（企业级核心）

- `F-xx` 功能、`R-xx` 校验规则、`A-xx` 验收场景、`AC-xx` 验收标准、`N-xx` 非功能、`Q-xx/C-xx` 待确认/已确认。
- 每个 F 至少 1 条 AC；每个 R 至少 1 个 A；追溯矩阵 F→R→A→AC→原型→测试→版本不能空。
- 测试用例后续用这些 ID 反查；改名/删除 ID 必须同步矩阵与测试。

## 4. 三个最容易漏的结构

- **状态机**：状态×事件矩阵；非法跃迁；终态重入。
- **权限矩阵**：角色×操作×数据域（本人/部门/全部）；未定义标「待确认 + 责任人」。
- **字段来源**：字段/类型/必填/范围/默认/来源/校验；表结构归开发。

## 5. 校验规则（R-xx）

- 完整性、一致性、门槛、唯一性、金额/数量/日期口径；每条写比较对象、失败表现、阻断/提示。
- 不允许“系统自动校验”一句话；写清比较什么、失败怎么办。

## 6. 验收标准写法

- 公式：**条件 + 动作 + 可观测结果**；
- 好：`已登录管理员在X页点[保存]后，列表新增一行且状态=待处理，重复保存不新增`；
- 坏：`保存功能正常`；
- 每条 F ≥1 AC；异常/边界各 ≥1；A-xx 用 Given/When/Then 或步骤+预期。
- 验收矩阵每行补 `优先级 / 类型 / owner / 执行阶段`；类型按 `DEV-AC / QA-AC / REL-AC` 分层。
- 验收矩阵是验收资产，不是开发任务；开发只承接 `DEV-AC`，`QA-AC/REL-AC` 交测试/UAT。
- 独立执行记录用固定列：场景 ID / 构建环境 / 角色及数据单号 / 执行时间 / 实际结果 / 结论 / 证据/缺陷号；结论只能是“通过/失败/未执行”。

## 7. NFR / 指标

- NFR 只写目标/约束 + 验收方式 + 待确认；不写实现。
- 指标：事件/触发/属性/指标/观测窗口/基线；无埋点写「不适用 + 原因」。

## 8. 引用、待定、技术边界

- 引用「来源 + 日期」，可回查；查不到写「待验证」。
- 待定：责任人 + 期限 + 影响；未标注 TBD 不允许。
- 技术边界：产品不写架构/技术栈/DB/API/部署；需要可行性列问题交开发/用户。

### 8.1 AI 产品需求补充（如适用）

- **任务与失败成本**：用户要完成什么；错误输出的后果；哪些场景必须人工确认/转人工。
- **可接受/不可接受输出**：事实错误、越权、泄露、危险建议、格式破坏等；写成可判定验收。
- **数据边界**：哪些数据可输入/可保留/可出境；PII/密钥/商业机密；供应商条款由开发/法务确认。
- **兜底与透明度**：低置信/超时/模型不可用时的行为；是否标注 AI 生成；是否可编辑/撤销。
- **质量度量**：评测集/通过阈值/红队/线上反馈；不只写“准确率≥90%”，要写口径与样本。

### 技能 `prototype-and-interaction`

# 原型与交互（技能 · 随包生效）

> 用于：`prototype` 工作流；`prd` 的原型条件步。  
> 核心：**先项目情境，再结构，再视觉；每页有状态；原型可点击、可评审、可交接。**

## 0. 项目情境与参考基准（不读主读/情境资料不开画）

- 读：PRD（F/A/AC）、产品计划、UAT/验收、现有系统截图、品牌/术语、约束（PC/手机/打印/离线/权限/数据量）。
- 写进 `设计情境-{主题}.md`：
  - 用户/角色、核心任务、频率、环境/设备、数据量、权限、合规；
  - 设计策略与项目适配：产品定位、与现有系统的关系、要借什么/不借什么、明确不做什么；差异化只在产品定位需要时写；
  - 设计原则 3～5 条（如“高密度后台 / 手机采集 / 打印优先”）；
  - 2～3 个竞品/同类系统/设计规范参考（链接+日期），写“借什么/不借什么”；优先引用 `竞品分析`/`竞品对标` 学习行（见 `competitive-intelligence-and-learning` §5）；
  - 关键任务：1 张主用户旅程（步骤/情绪/痛点/机会）或注明「单页工具不适用」；
  - 交付等级：概念 / 线框 / 高保真 / 可交接；交接必须到“可交接”级，并说明开发可优化边界；
  - 覆盖目标：PRD F/A/AC → 页面/路由/状态。
- 可选能力：design-intelligence / browser-mcp / ui-generation；未装=按本技能。

## 1. 信息架构（IA）

- 站点地图 / 导航层级；页面清单：页面 / 目标 / 入口 / 主操作 / 出口 / 角色权限。
- **覆盖矩阵**：PRD F/A/AC → 页面/路由/状态；缺页面=阻断。
- **导航收敛**：侧栏/顶栏项须各自扛**独立主任务**；仅服务父页某操作、低频或单字段配置的能力 → **不占独立导航**，降为父页按钮/行内操作触发的抽屉·弹层·子页，并在页面清单写明入口控件。
- **跳转完备**：遍历本期页面清单中的可跳转控件（按钮/链接/行操作/Tabs 等）；每个目标须已有页面或弹层/抽屉规格，或标「本期不做」；无规格=阻断，先补设计再交开发。
- 关键流程：主路径 + 异常路径；跨页面跳转与返回。
- 范围：本期做 / 不做；桌面 / 移动适配策略。
- 约束：角色与数据域（本人/部门/全部）；未定义权限标「待定」。

## 2. 线框（低保真）

- 区块：导航 / 标题 / 筛选 / 内容 / 操作 / 反馈。
- 层级：一屏一个主任务；主操作唯一且醒目；次要操作降级。
- 标注：点击去哪、校验规则、空态、加载、错误。
- 工具：`rules/templates/20-design/prototype-scaffold.html` 起步；先灰度结构，不定视觉。

## 3. 状态矩阵（每页必填）

| 状态 | 表现 | 文案 | 操作 |
| --- | --- | --- | --- |
| 空/首次 | 说明 + 引导 | 为什么空、下一步 | 主操作 |
| 加载 | 骨架/进度 | 不闪跳 | 可取消（长任务） |
| 失败 | 原因 + 重试 | 说清怎么解决 | 重试/返回 |
| 成功 | 反馈 + 下一步 | 结果可见 | 继续/查看 |
| 禁用 | 灰显 + 原因 | 为什么不能点 | 解锁条件 |
| 无权限 | 申请/联系 | 缺什么权限 | 申请/切换账号 |
| 边界 | 超长/重复/并发/断网 | 具体限制 | 截断/去重/重试 |

> 状态矩阵逐页落到高保真；评审时逐项核，缺主状态=阻断。

## 4. 数据、路由与持久化

- 数据模型：实体/关系/字段；seed 示例数据；重置方式；真实数据脱敏。
- 路由/导航：页面/路由表、历史/返回、深链、未保存提醒；无死路。
- 演示/原型数据与当前 PRD/构建一致；模拟能力（OCR/AI/支付）必须标注“模拟”。

## 5. 交互规则

- 点击 / 悬停 / 聚焦 / 键盘；提交 / 取消 / 撤销；危险操作二次确认。
- 校验：即时或提交时；错误定位到字段；文案说“怎么改”。
- 反馈：loading、toast、inline error、成功页；不要只靠颜色变化。
