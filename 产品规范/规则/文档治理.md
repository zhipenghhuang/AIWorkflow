# 文档治理（资料 + 工作文档）

> 单一出处：入站意图分析、资料/工作区分流、覆盖对照、受影响同步、归档与清理。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/清理**；未确认前只读。
> **单包优先**：仅本包即可闭环；缺开发/测试包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。多包（根下 ≥2 个包 `AGENTS.md`）时共用根级**原始资料根**与交接直读，放入≠分发。
> **反堆积**：确认采纳且 S1/S2/S3 → **同批**失效归档（仅包内 `资料/_归档/` 与工作区归档）；正式档就地覆盖现行结论；禁止默认「只落位、等关版本再清」。根级原始资料根**不归档、不迁出主副本**。
> 安全：**现行**证据（本轮门回执所需）、当前 PRD/原型/计划、源文件、用户文件、密钥、`.git` 永不自动删除；**过期运行态**（`.gate/产品规范/` 下非 JSON 媒体、过期 logs 等）视为临时/过程，可进清理候选；拿不准 → 待确认或移 `产品/_归档/_待清理/`。
> **`.gate` 落点**：`.gate/产品规范/` 只写 JSON 回执，不堆截图/媒体。

## 1. 三个区

| 区 | 放什么 | 不放什么 |
| --- | --- | --- |
| **原始资料根**（推荐 `docs/`） | 项目外部/用户投放的**原始输入主副本**（永久保留） | 本包活文档、包内归档 |
| `产品/资料/` | 本包所需原始输入的**副本**与只读证据 | 本包 PRD/原型/评审/计划/UAT 等**活文档** |
| `产品/` 工作区 | 本包工作文档（`{版本}/` + 计划/需求池/用户文档/工作日志） | 外部原件主副本（在原始资料根）；无内容不建空目录 |

- **工作文档根（硬）**：本包必须有 `产品/`；新产物只落此处。
- **原始资料根（硬）**：项目根级，单包与多包**同一语义、共用一份**。推荐名 `docs/`；若项目已有其它名的原始文档目录 → 登记实际路径并引用，不强制改名为 `docs`。无现成目录 → 接入时默认建 `docs/`。
- **主副本规则**：原始资料根内文件**一律视为项目原始资料**——**禁止迁出/改充当工作区正文**；只做索引、按需复制、按需吸收（含引用）。新文档入库（对话/根散落/投放）须先在此留主副本。跨包只引用；放入 ≠ 自动跑他包。
- **资料模式**（只约束「是否改原始资料根内部结构」；**不**禁止复制/吸收）：

| 模式 | 对原始资料根 | 仍允许 |
| --- | --- | --- |
| `keep` | **结构保持不动**（不改名、不搬迁、不重整） | 建/更新索引；按需**复制**进本包 `资料/`；按需**吸收/引用**进工作区 |
| `mix`（默认） | **只添加整理**（补索引、归位新增件、小幅补齐；不推翻重排） | 同上复制/吸收 |
| `replace` | **完全重整**（AI 出实用方案 → 确认后改名/移动；须同步修引用） | 同上复制/吸收 |

  均须可查可引。**不要求**与包内 `资料/` 树对齐。
- **认根**（原始资料根）：① 用户指定优先；② 否则按判定表推断；③ **不确定必须问用户**，不得猜。判定表见 §2.1。
- **版本记录**：根 `CHANGELOG.md` 仅开发维护（有开发包时）。本包只写 `产品/工作日志.md`（禁写入/补链/创建根）。无开发包 → 不建根 CHANGELOG；岗位史用本包工作日志。发版决策可在工作日志写「对外变化摘要」供开发落笔，本包不代替写根。

## 2. 原始资料根与包内资料

### 2.1 原始资料根（无归档 · 不迁出）

```text
docs/                            # 或档案登记的其它原始资料根路径
├─ 资料索引.md                   # 必有：全量可查可引
└─ …                             # 子目录由实况决定；不强制对齐包内树
```

**认根判定表**（用户未指定时；命中多条或冲突 → 问用户）：

| 优先 | 线索 | 倾向 |
| --- | --- | --- |
| 1 | 用户点名某目录为原始资料/项目文档根 | 采用该路径 |
| 2 | 根下已有 `docs/` 且主要为文档（非代码/构建） | `docs/` |
| 3 | 唯一明显的大文档夹（如 `文档/`、`项目文档/`、`资料/` 在根且非包内） | 该夹 |
| 4 | 多个候选或夹内以代码/配置为主 | **停问** |

- **禁止**：在原始资料根建 `_归档/`；禁止把其中文件**迁移**到 `产品/` 工作区或其它处冒充「搬走活文档」；禁止为对齐包内树强制改结构。
- **中途存量（硬）**：接入时对原始资料根做**索引全登记**；**不**默认全量复制/吸收。复制与吸收按**任务/版本实际需要**分批；可长期「仅索引」。
- **三档处置**（对每份已索引文件，按需升级，可并存）：

| 档 | 做什么 | 何时 |
| --- | --- | --- |
| **索引** | 只写入 `{原始资料根}/资料索引.md`（路径/类型/状态/主题） | 默认；存量必做 |
| **复制** | 复制进 `产品/资料/`（按本包树分类）；原件不动 | 本包要常读/当证据/离线副本时 |
| **吸收** | 见 §2.3；原件不动 | 本包工作区需要可执行 SSOT 或稳定引用时 |

- **入站通道**（新件主副本必留）：① 直接放入；② 根散落文档类 → 先收入原始资料根（AI 定子路径）；③ 对话/附件 → 先落盘到原始资料根。确认前只读分析（落盘保原件除外）。

### 2.2 包内 `产品/资料/`（按需副本 · 可归档）

```text
产品/资料/
├─ 资料索引.md
├─ _通用/
├─ {版本或主题}/
└─ _归档/{yyyyMMdd}-{版本或批次}/
```

- **禁止**：新建 `项目文档/`；禁止新资料长期平铺 `资料/` 根；禁止强制类型前缀改名；**禁止**再用 `资料/交接/` 作交接收件主入口（改走 `产品/交接/入站/`，见协作 §4.0）。
- 仅放**按需复制**来的副本；不是原始资料根的镜像全量。
- 失效副本 → `资料/_归档/`；**不影响**原始资料根。
- **交接分流**：原始资料根分析后，交接类 → `产品/交接/入站/{类别}/` 并打开吸收；其它 → 按需复制本树 + R0～R2。同仓直读对方出站。

### 2.3 吸收深度（实用）

> **吸收 ≠ 迁移**。原件永远留在原始资料根。吸收只改本包工作区（及可选包内 `资料/` 副本）。

| 深度 | 工作区动作 | 适用 |
| --- | --- | --- |
| **R0 引用** | 仅在计划/索引/台账写来源路径 + 一句话用途；不改写正文 | 查阅、待办、非本轮范围 |
| **R1 要点吸收** | 抽取与本任务相关的范围/AC/约束写入受理单、变更单或计划摘要；正文仍以原件为准并挂链接 | 澄清、排期、小改 |
| **R2 结构吸收** | 按本包模板写入/更新工作区 SSOT（如 `{ver}/01` PRD 节、需求池条目）；文首或表记 `来源=` 原始路径；不删原件 | 本版本正式基线、交下游、定稿入口 |

- **默认**：存量 → 索引；当前任务命中文件 → 至少 R0；要改基线/交开发/定稿 → R1 或 R2（按级别，不确定取低一档并问一次）。
- **禁止**：把原件整文件挪进 `产品/{ver}/` 冒充已吸收；禁止为「分流活文档」清空或搬空原始资料根。
- **SSOT**：工作区正式结论以吸收后的工作文档为准；原件是证据与溯源。冲突 → T8。

## 3. 入站意图分析（每次新文档/口述变更）

先判**意图类型**，再落点。输出四列：`类型 | 落点 | 同步 | 归档/覆盖`。

**先判替代关系**：T1 全量替代才归档旧 PRD/基线；T2/T4 增量/局部，保留未被覆盖的 PRD 基线/原型，只归档被替代的增量与旧稿。  
**T1～T9 是处置维度框架**；线索列为校准示例（非穷尽）；未列类型仍按最近意图归入对应 T 档，禁因「表上没有名字」拒入站。

| 类型 | 线索 | 落点 | 本包同步（有则做） | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 替代全文/废止旧版/整份新 PRD | 主副本留/落入原始资料根；按需复制；R1/R2 吸收→`{ver}/01-…` | SSOT、计划指针、需求池、索引 | 旧工作区 SSOT/包内副本可归档；原始资料根不动 |
| T2 方案/设计变更 | 方案 diff、设计结论 | 同上；正文吸收→`01`/`02`/`03` | 变更单、受影响节、计划 | 旧工作区稿可归档；局部就地覆盖 |
| T3 未决确认 | 拍板、澄清答复 | 结论→工作区；原件留根，按需复制/R0 | 关闭未决、回写缺口 | 过程件勿堆第二 SSOT |
| T4 迭代专项/局部 | 修改方案、单模块补丁 | 原件留根；增量→变更单 + 就地改章节 | 影响面、计划摘要 | 禁两份现行整版 PRD |
| T5 范围/优先级 | 砍需求、重排期 | 结论→计划/需求池 | 范围与状态 | 旧通知工作区侧可归档 |
| T6 缺陷/回流 | 判定、处置说明 | 原件留根；结论→`03` | 处置单、受影响交付 | 旧评估可归档 |
| T7 仅参考 | 竞品/调研/无强制采纳 | 索引状态=`参考`；默认可不复制 | 一般不改 SSOT | 不进工作区现行 |
| T8 冲突 | 与现行矛盾未裁决 | 索引=`待确认` | 列冲突，停一次问 | 不覆盖现行直至裁决 |
| T9 交接类 | 跨角色交付/对方交接材料（含非 HO） | 主副本留原始资料根；工作副本→`产品/交接/入站/{类别}/`；同仓直读对方出站 | 打开分析+R0～R2；台账/计划回写 | 出站快照不可改；入站非 SSOT |

变更级别对齐协作：C0 澄清｜C1 同范围增量｜C2 范围/里程碑｜C3 战略/破坏性；C2/C3 须过门/重基线。

**落点关系**：原件∈原始资料根；副本∈`产品/资料/`（按需）；**SSOT∈工作区**（R1/R2）或工作区仅挂引用（R0）。吸收不是把外件挪进 `{版本}/`。

## 4. 资料收取步骤

1. 识别未登记/变化文件（原始资料根优先全量索引；`产品/资料/`；根散落先拟收入原始资料根）。
2. 读标题/目录/变更段 → 判 T1～T9 + 覆盖关系 + 建议档位（索引 / 复制 / R0～R2）。
3. 输出【入站分析】与候选；**确认前不改文件**（新件落盘保原件除外）。
4. **用户确认后同批**：主副本留/落入原始资料根并**登记索引** → 仅对确认需要的文件**复制**进 `产品/资料/` → 按确认深度**吸收**（R0～R2）→ 若有 S1/S2/S3，只归档包内副本/工作区旧稿 → 更新索引/计划/activeContext。原始资料根文件不迁不删。
5. 中途存量：先全索引；本轮未点名复制/吸收的保持「仅索引」。部分/参考保留；冲突→T8。

**覆盖关系**：全量替代｜全量覆盖｜部分覆盖｜增量补充｜仅新增｜重复｜冲突。  
**失效依据**：S1 全量替代；S2 全量覆盖；S3 重复；S4 需求删除/版本取消；S5 用户明确失效。禁按年龄归档。失效只作用于包内副本与工作区，不删除原始资料根主副本。

## 5. 工作文档四类

| 类型 | 动作 |
| --- | --- |
| 长期/固定 | 就地更新，不随迭代整文件搬走 |
| 版本/迭代绑定 | 关闭时归档；期中失去交付入口也可归档 |
| 失效/替代 | 确认后归档；部分覆盖保留未覆盖部分 |
| 过程/临时 | 确认后删或 `_待清理/` |

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `产品档案.md`、`activeContext.md`（含 `### 进行中` 快照） | 长期 | 就地更新；本包只改 `## 产品` 与本包接入行 |
| `产品/工作日志.md` | 长期 | 追加里程碑；过长确认后移块到 `产品/_归档/工作日志/` |
| `产品/产品计划.md` | 长期主档 | 常青；季度快照 `_归档/{yyyy-Qn}/`，主档不移动 |
| `产品/需求池.md` | 长期 | 只留现行状态 |
| `产品/用户文档/` | 长期/当前 | 旧版按版本归档 |
| `产品/{版本或主题}/` | 版本绑定 | 关闭整体进 `产品/_归档/{yyyyMMdd}-{版本}/`；若下一迭代仅增量且仍引用该版 PRD/原型，保留为基线/引用，不整夹归档；主档/需求池不动 |
| `产品/交接/出站/{类别}/`（散文件+`{HO-ID}/`） | 出站快照 | 真源在版本目录；实拷刷新；关版本同批归档；台账常青 |
| `产品/交接/入站/{类别}/` | 收件工作副本 | 须分析吸收；非永久主副本；`资料/交接` 废弃主入口 |
| `**/.draft/` 等 | 临时 | 清理候选 |

**交付入口**：该主题是否仍有未交付的现行 PRD/原型要维护。否 → 旧稿可期中归档。正式文档只写现行有效；旧结论进变更单/归档，不在现行区并排「最终版-2」。

## 6. 更新还是归档

| 情况 | 动作 |
| --- | --- |
| 主档/局部章节变化 | 就地更新（覆盖终态）；过程进变更记录/工作日志；不新开第二份整版现行 PRD；档案等常青格不写接入·迁移·归档事件 |
| T1 全量替代 | 新=现行；旧确认后归档 |
| 版本关闭 | 整夹 `{版本}/` → `产品/_归档/`；若下一迭代仅增量且仍引用该版 PRD/原型，保留为基线/引用，不整夹归档；计划/需求池/用户文档现行保留 |
| 重复/空/未引用临时 | 清理候选 |

归档前做**引用检查**：被当前产品计划、PRD、原型、交付/UAT 引用的文档不得标记失效；先修引用或保留原位。归档清单写明“替代关系/仍被谁引用”。

## 7. 版本/迭代关闭（换迭代 = 关当前版进入下一版）

> **迭代即版本主题**：换下一期方案/新版本目录 = 结束当前迭代并开下一迭代。与「正式发布上线」**不是两套清理标准**——分类、绑定归档、失效资料、临时清理、索引/链接同一套完整分析；差别只在是否做**发版对外项**。

### 7.1 关账清单（按实际裁剪，不是少做）

> **关账前置**：先按 §3 判 T1/T2/T4。T1 全量替代才归档旧 PRD/基线；T2/T4 增量/局部，保留仍被后续迭代引用的 PRD 基线/原型，只归档被替代的增量与旧稿。

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分类 + 更新计划/台账/索引/activeContext | 必做（指向下一迭代） | 必做 |
| 版本绑定 PRD/原型/交付/UAT/复盘 → `_归档/{yyyyMMdd}-{版本或迭代}/`（增量迭代保留仍被引用的 PRD/原型基线）；失效资料 → `资料/_归档/` + 清单 | 必做（已确认结束的） | 必做 |
| 临时/过程/失败/重复清理 + 修断链 | 必做 | 必做 |
| GTM/发布说明/根 CHANGELOG（仅开发写）/对外公告/上线检查 | **跳过**（除非点名发版） | 按发版流程/deliver 门 |

### 7.2 确认结束当前迭代（不确定必问）

出现下一期/换主题/版本升级但当前是否结束不明确（仍在回归、提测未结）→ **STOP** `confirm_iteration_close`：出示当前迭代/未完成项/拟归档/下一迭代；确认「结束并进入下一」才执行 §7.1；「并行不关」→ 只落新资料、不归档现行主档，收尾记假设。已明确「下一期/换版本/关这期」→ 直接执行，不重复问。

### 7.3 触发（自动探测 · 同会话）

1. 新迭代/版本文档采纳且判定换代，或用户确认结束当前
2. 换主题/版本升级/计划范围换代；正式发版/结项口令
3. 点名整理/巡检/清理（可只做清理子集，仍先分类）

未确认零移动；现行证据/现行主档/密钥永不自动删。

## 8. 过程/临时清理
