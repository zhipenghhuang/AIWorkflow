# 文档治理（资料 + 工作文档）

> 单一出处：入站意图分析、资料/工作区分流、覆盖对照、受影响同步、归档与清理。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/清理**；未确认前只读。
> **单包优先**：仅本包即可闭环；缺开发/测试包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。多包（根下 ≥2 个包 `AGENTS.md`）时可用 `项目资料/` 与交接直读，放入≠分发。
> **反堆积**：确认采纳且 S1/S2/S3 → **同批**失效归档；正式档就地覆盖现行结论；禁止默认「只落位、等关版本再清」。
> 安全：证据、当前 PRD/原型/计划、源文件、用户文件、密钥、`.git` 永不自动删除；拿不准 → 待确认或移 `产品/_归档/_待清理/`。

## 1. 两个区

| 区 | 放什么 | 不放什么 |
| --- | --- | --- |
| `产品/资料/` | 外部/上游原件、只读证据 | 本包 PRD/原型/评审/计划/UAT 等**活文档** |
| `产品/{版本或主题}/` 与主档 | 本包工作文档（`01`～`06` + 计划/需求池/用户文档/工作日志） | 外部原件（放 `资料/`）；无内容不建空目录 |

- **资料根**：单包 `产品/资料/`；多包共享 `项目资料/`（外部主副本 → 登记索引 → 只吸收进本包，跨包只引用不复制）。
- **资料模式**：`keep` 原位只读；`mix` 默认；`replace` 可改名/移动（列清单确认）。
- **版本记录**：根 `CHANGELOG.md` 仅开发维护；本包只写 `产品/工作日志.md`（禁写入/补链根）。

## 2. 资料目录（版本/主题子目录）

```text
产品/资料/
├─ 资料索引.md
├─ _通用/                         # 跨版本稳定输入
├─ {版本或主题}/                  # 如 V2.7.0、专项名；文件名保持原名
├─ 交接/{HO-ID}/                  # 收到的外部交接（只读）
└─ _归档/{yyyyMMdd}-{版本或批次}/ # 仅已确认失效资料
```

- **禁止**：新建 `项目文档/`；禁止把新资料平铺在 `资料/` 根（根仅索引与上表保留目录）；禁止强制类型前缀改名（类型写索引）。
- **兼容**：旧扁平 `PRD-*`、旧 `资料/项目文档/`、旧 `产品/_归档/**/资料/` → 重新接入时列迁移候选；未确认不搬。
- 本包 PRD/原型是工作文档；只有外部/合作方原件进 `资料/`。

## 3. 入站意图分析（每次新文档/口述变更）

先判**意图类型**，再落点。输出四列：`类型 | 落点 | 同步 | 归档/覆盖`。

| 类型 | 线索 | 落点 | 本包同步（有则做） | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 替代全文/废止旧版/整份新 PRD | 外件→`资料/{ver}/`；正式版→`{ver}/01-…` | SSOT、计划指针、需求池、索引 | 旧 SSOT/旧资料 **同批归档** |
| T2 方案/设计变更 | 方案 diff、设计结论 | 外件→资料；正文→`01`/`02`/`03` 变更 | 变更单、PRD/原型受影响节、计划 | 不再是交付入口的旧稿 → 期中归档；局部 → **就地覆盖** |
| T3 未决确认 | 拍板、澄清答复 | 结论→工作区（待决/变更/PRD TBD）；外件可作证据进资料 | 关闭未决、回写缺口、计划假设 | 过程确认件勿堆成第二 SSOT；可标参考或归档 |
| T4 迭代专项/局部 | 修改方案、单模块补丁 | 外件→资料；增量→变更单 + 就地改章节 | 影响面章节、计划摘要 | **不**另开第二份现行整版 PRD；被替代增量 → 归档 |
| T5 范围/优先级 | 砍需求、重排期 | 结论→计划/需求池 | 范围与状态 | 被全量替代的旧通知 → 归档 |
| T6 缺陷/回流 | 判定、处置说明 | 外件→资料；结论→`03` | 处置单、受影响 PRD/交付 | 旧评估被替代 → 归档 |
| T7 仅参考 | 竞品/调研/无强制采纳 | `资料/` 状态=`参考` | 一般不改 SSOT | 不进工作区现行 |
| T8 冲突 | 与现行矛盾未裁决 | 资料=`待确认` 或暂不落 | 列冲突，停一次问 | 不覆盖现行直至裁决 |
| T9 交接包 | HO-ID 结构 | 多包直读发送路径；仓外按接收规则 | 接收后回写计划/台账 | 发出包不可改 |

变更级别对齐协作：C0 澄清｜C1 同范围增量｜C2 范围/里程碑｜C3 战略/破坏性；C2/C3 须过门/重基线。

**双落点**：外件在资料、正文在工作区；**SSOT=工作区**；吸收=写入工作区，不是把外件挪进 `{版本}/` 冒充 PRD。

## 4. 资料收取步骤

1. 识别未登记/变化文件（单包 `产品/资料/`；多包加 `项目资料/`）。
2. 读标题/目录/变更段 → 判 T1～T9 + 覆盖关系。
3. 输出【入站分析】与【资料/工作文档候选】；**确认前不改文件**。
4. **用户确认采纳后同批**：落位登记 → 工作区同步（§3 同步列）→ S1/S2/S3 旧文件标 `失效` → 移 `产品/资料/_归档/{批次}/`（资料）或 `产品/_归档/{批次}/`（工作文档）→ 归档清单 → 更新索引/计划/activeContext。
5. 部分覆盖/增量/参考：保留，索引状态准确；**禁止两份同主题都标「现行」且无分工**。冲突→T8。

**覆盖关系**：全量替代｜全量覆盖｜部分覆盖｜增量补充｜仅新增｜重复｜冲突。  
**失效依据**：S1 全量替代；S2 全量覆盖；S3 重复；S4 需求删除/版本取消；S5 用户明确失效。禁按年龄归档。

## 5. 工作文档四类

| 类型 | 动作 |
| --- | --- |
| 长期/固定 | 就地更新，不随迭代整文件搬走 |
| 版本/迭代绑定 | 关闭时归档；期中失去交付入口也可归档 |
| 失效/替代 | 确认后归档；部分覆盖保留未覆盖部分 |
| 过程/临时 | 确认后删或 `_待清理/` |

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `产品档案.md`、`activeContext.md`（含 `### 进行中` 快照） | 长期 | 就地更新；本包只改 `## 产品` 与本包接入行 |
| `产品/工作日志.md` | 长期 | 追加里程碑；过长确认后移块到 `产品/_归档/工作日志/` |
| `产品/产品计划.md` | 长期主档 | 常青；季度快照 `_归档/{yyyy-Qn}/`，主档不移动 |
| `产品/需求池.md` | 长期 | 只留现行状态 |
| `产品/用户文档/` | 长期/当前 | 旧版按版本归档 |
| `产品/{版本或主题}/` | 版本绑定 | 关闭整体进 `产品/_归档/{yyyyMMdd}-{版本}/`；主档/需求池不动 |
| `产品/交接/{HO-ID}/` | 快照 | 不可改；新版 `-v2`；关闭随版本归档；台账常青 |
| `产品/资料/交接/{HO-ID}/` | 外部只读 | 按资料规则 |
| `**/.draft/` 等 | 临时 | 清理候选 |

**交付入口**：该主题是否仍有未交付的现行 PRD/原型要维护。否 → 旧稿可期中归档。正式文档只写现行有效；旧结论进变更单/归档，不在现行区并排「最终版-2」。

## 6. 更新还是归档

| 情况 | 动作 |
| --- | --- |
| 主档/局部章节变化 | 就地更新；过程进变更记录；不新开第二份整版现行 PRD |
| T1 全量替代 | 新=现行；旧确认后归档 |
| 版本关闭 | 整夹 `{版本}/` → `产品/_归档/`；计划/需求池/用户文档现行保留 |
| 重复/空/未引用临时 | 清理候选 |

## 7. 版本/迭代关闭（换迭代 = 关当前版进入下一版）

> **迭代即版本主题**：换下一期方案/新版本目录 = 结束当前迭代并开下一迭代。与「正式发布上线」**不是两套清理标准**——分类、绑定归档、失效资料、临时清理、索引/链接同一套完整分析；差别只在是否做**发版对外项**。

### 7.1 关账清单（按实际裁剪，不是少做）

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分类 + 更新计划/台账/索引/activeContext | 必做（指向下一迭代） | 必做 |
| 版本绑定 PRD/原型/交付/UAT/复盘 → `_归档/{yyyyMMdd}-{版本或迭代}/`；失效资料 → `资料/_归档/` + 清单 | 必做（已确认结束的） | 必做 |
| 临时/过程/失败/重复清理 + 修断链 | 必做 | 必做 |
| GTM/发布说明/根 CHANGELOG（仅开发写）/对外公告/上线检查 | **跳过**（除非点名发版） | 按发版流程/deliver 门 |

### 7.2 确认结束当前迭代（不确定必问）

出现下一期/换主题/版本升级但当前是否结束不明确（仍在回归、提测未结）→ **STOP** `confirm_iteration_close`：出示当前迭代/未完成项/拟归档/下一迭代；确认「结束并进入下一」才执行 §7.1；「并行不关」→ 只落新资料、不归档现行主档，收尾记假设。已明确「下一期/换版本/关这期」→ 直接执行，不重复问。

### 7.3 触发（自动探测 · 同会话）

1. 新迭代/版本文档采纳且判定换代，或用户确认结束当前
2. 换主题/版本升级/计划范围换代；正式发版/结项口令
3. 点名整理/巡检/清理（可只做清理子集，仍先分类）

未确认零移动；证据/现行主档/密钥永不自动删。

## 8. 过程/临时清理

扫描 `产品/` 与根顶层；跳过 `.git`/依赖/模板。候选：已完结 `.draft/`、tmp/bak/log、副本、未引用导出；确认后删/移 `_待清理/`；进行中 draft、现行证据/主档禁动。

**何时扫**：点名 lifecycle 或换迭代/关版本 §7.1；日常收尾不列清理、不追问。

## 9. 输出骨架

```text
【入站分析】意图=Tx | 级别=Cx
| 落点 | 覆盖关系 | 拟同步 | 拟归档/覆盖 |
【受影响更新】| 路径 | 动作 | 已更新/待补/不适用 |
【拟归档】| 文件 | 归档到 | 依据 |
他包建议：无 | 待确认：0～1 个高影响问题
```

## 10. 触发

| 时点 | 动作 |
| --- | --- |
| 接入/重新接入 | 建 `资料/` 结构与索引；旧结构列迁移 |
| 新文档/变更/未决/专项 | §3～§4；确认后同步+归档同批；换代→§7 |
| 换代/换主题/版本升级 | §7 关账；跳过仅发版项 |
| 版本关闭/正式发布 | §7 全表 |
| 巡检/清理 | §7.1 子集或 lifecycle；先分类 |
| 季度可选 | 只出候选，不移动 |
