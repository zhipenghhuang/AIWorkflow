# 缺陷平台协作（拉取 · 分析 · 回写）

> **适用**：产品侧处理禅道/Jira/ONES 等平台的缺陷，尤其是测试提交并指派给产品、开发出方案/附件待产品确认、产品缺陷待评审。  
> **步骤顺序**以 `../workflows/defect.yaml` 为准；分析/处置方法见 `../技能/change-management/SKILL.md`；平台配置见 `产品档案.md` §7。  
> **确认门只认步上 hitl**：`confirm_remark`（平台回写）、`confirm_change`（处置）、`confirm_plan`（计划级）；本文不另造门。

## 0. 启动与输出门

```text
route=workflow:defect | step=… | role=pm-lead | next_action=LOGIN|LIST|PULL|ANALYZE|AWAIT_CONFIRM|WRITEBACK|…
```

| 时机 | 输出 |
| --- | --- |
| 启动 | 启动回执；缺平台配置时说明降级方式，禁只回「请提供编号」 |
| 拉取后 | 缺陷清单摘要（空清单也要输出） |
| 每条分析后 | 分诊/依据/处置建议（写入受理单） |
| 回写前 | 缺陷 id + 结论 + **备注全文** + 附件名 + 状态/指派变更 |
| 回写后 | 回写结果 + 批末总结（成功/待回写/失败） |

## 1. 配置与前置

读 `产品档案.md` §7（provider/baseUrl/凭据来源/默认产品/提交方式/备注格式/适配定义/solutionChannel/附件能力）。  
若同项目已有开发/测试包配置（`项目档案.md` §3/§4、测试包环境基线 §13），优先复用其 provider、端点和凭据来源；本表只记产品侧差异，不重复存凭据。

| 情况 | 处置 |
| --- | --- |
| provider=无 / §7 未填 | 问一次是否现在配置 §7；不配置则降级为「用户粘贴缺陷内容/导出文件」或转 `change` 受理；禁反复索要编号、禁猜接口 |
| 平台可用 | 按 §2 拉取；按 §5 回写 |
| 平台暂不可用（登录/网络/权限） | 输出阻塞说明与已尝试；恢复后回 pull；禁静默排障取代输出 |
| 无回写权限/平台不支持附件或状态变更 | 走 `export`：出可复制回写包（备注 + 附件清单 + 动作），用户执行后回填；标记「待回写」 |
| solutionChannel=manual | 备注/方案附件读不全 → 请用户补关键备注或附件；禁只凭标题分析 |

## 2. 拉取与读取

### 2.1 拉取范围

| 口令 | 默认范围 |
| --- | --- |
| 拉取/查看/我的产品缺陷 / 指派给我 | 当前产品账号被指派、未关闭的缺陷（含 active / resolved）；按默认产品/项目过滤 |
| 点名「产品缺陷 / 待产品确认」 | 先拉指派给当前账号的未关闭单，再按标题/类型/标签/备注分拣；平台有类型字段则叠加过滤 |
| 点名单号（#123 / Bug-123） | 仅拉这些单 |
| 点名「已关闭 / 全部」 | 按点名范围；默认不拉已关闭 |

空清单：输出「拉取 0 条」+ 范围/过滤条件，禁编造。

### 2.2 每条必须读全

标题、steps/复现、severity/pri、status/resolution、提交人/指派、版本/构建/环境、附件、近期备注/讨论、开发方案/附件（如有）、关联需求/PRD（平台有则读）。  
`solutionChannel=manual` 或备注读不全 → 请用户补关键备注；禁只看标题。

### 2.3 建档

每条缺陷落一份 `产品/{版本或主题}/受理-{主题}-{yyyyMMdd}.md`（模板 `规则/模板/受理与处置模板.md`），编号用平台单号（如 `BUG-123`），并记录平台、提交人、指派、状态、附件清单。批末输出清单摘要。

## 3. 分析

按 `../技能/change-management/SKILL.md` §2/§3：

- 现网 ≠ PRD/设计 → **实现缺陷**：退回开发/测试，不改 PRD；给依据、复现/验收要求。
- 现网 = PRD/设计，但口径不合理/有风险 → **产品缺陷**：必须有 PRD/设计原文 + 现网/测试证据 + **相符证明**。
- 无设计依据 → 默认实现缺陷或补充信息；禁把实现缺陷甩成产品缺陷。
- 开发已出方案/附件 → 读全文，评：是否解决原问题、影响哪些 AC/范围/数据/合规/回归/回滚；**技术架构/实现细节不替开发评审**。
- 技术不确定 → 开发 ADR/Spike；涉及产品取舍才回产品。

处置选项：立即修 / 下版 / 不修 / 退回开发 / 补充信息。影响评估与联动更新按 `../workflows/change.yaml` 的 assess/apply 执行。

## 4. 处置与联动

- 立即修（本期）→ 变更单（类型=缺陷修复）+ PRD/AC 更新 + 实质变更重审 + UAT 重验 + 通知开发/测试。
- 下版 → 需求池 + 产品计划 §2 路线图 + 通知；本期不改。
- 不修 → 记录理由、风险、接受人；必要时更新 PRD 说明。
- 退回开发（实现缺陷）→ 产品不改 PRD；给依据与复现/验收要求，回执开发/测试。
- 补充信息 → 一次列清缺什么、谁补、截止；保持打开。

联动清单、重审、验证按 `../workflows/change.yaml`；产品侧只出产品结论/变更单/评审意见，不修改代码或技术方案。

## 5. 回写平台（confirm_remark）

回写前必须出示：

- 缺陷 id / 标题；
- 分诊结论与依据（产品缺陷附相符证明）；
- 处置结论与目标版本；
- **备注全文**；
- 附件名（受理单/变更单/评审意见/PRD 变更摘要，按需）；
- 状态 / 指派变更；
- 需要谁做什么、截止。

确认后执行；备注与状态**同轮**写入。平台普通角色无删除权限，**禁删缺陷**。

### 5.1 备注骨架（按备注格式 html / markdown / text 同构）

```text
【产品缺陷·处置结论】{平台单号} · {标题}
一、分诊：{产品缺陷/实现缺陷}；依据：{PRD §… + 现网/测试证据 + 相符证明}
二、结论：{立即修 / 下版 / 不修 / 退回开发 / 补充信息}
三、影响：{AC/范围/排期/数据/合规/回归}
四、下一步：{变更单 CR-… / 需求 R-… / 开发修复 / 补充信息}
五、附件：{受理单/变更单/评审意见/PRD 变更摘要}
六、目标版本 / 截止：{…}
```

- 实现缺陷退回：结论写「退回开发修复」，附依据、复现/验收要求；不写「产品口径调整」。
- 产品缺陷下版：写「本期不改，进入下版需求池 R-…」。
- 不修：写理由、风险、接受人。
- 补充信息：一次列清所需材料，不反复追问。

### 5.2 批量回写确认包

```text
next_action=AWAIT_CONFIRM
【拟回写】共 {N} 条：立即修 {A} / 下版 {B} / 不修 {C} / 退回 {D} / 补充信息 {E}

- #{id} [{分类}] {标题}
  结论：{…}
  备注全文：（§5.1）
  附件：{受理单/变更单/评审意见/PRD 变更摘要}
  状态/指派：{原 → 新；无则「不变」}
```

确认后逐条执行；一条失败不冒充全部成功，单列失败原因。

## 6. 附件 / 状态 / 指派

| 动作 | 要求 |
| --- | --- |
| 附件上传 | 用平台适配接口；上传后回查挂载（元数据/页面附件区）；失败重试 ≤1，禁反复重传 |
| 状态变更 | 按适配映射；备注与状态同轮；平台不允许代改状态 → 备注说明并请有权限人操作 |
| 指派 | 立即修 → 指派开发/测试；退回 → 指派提交人或开发；补充信息 → 指派提交人；不修/下版 → 按团队约定 |
| 关闭 | 仅产品侧处置完成且验证通过；实现缺陷未修复不得关；下版/不修按团队口径 |
| 失败 | 停，不声称已回写；出 export 包并标「待回写」 |

## 7. 批末总结

```text
【产品缺陷协作总结】{时间}
拉取 {N}；产品缺陷 {A}；实现缺陷 {B}；立即修 {C}；下版 {D}；不修 {E}；退回 {F}；补充信息 {G}
回写成功 {H}；待回写 {I}；失败 {J}

- #{id} [{分类}] {标题}：{处置}｜{回写动作}｜{最新文档}
（无法判定/跳过项也各一行说明）
```

本块置入【任务收尾】第 1 点；第 2～6 点按 `../AGENTS.md` §2。

## 8. zentao 适配（内置）

- Token：`POST /api.php/v1/tokens`；禁浏览器登录页。
- 列表/详情/解决/指派：v1；读全单（steps、历史备注/讨论、附件、状态/指派）。
- 附件：`POST /api.php/v2/files`，字段 **`file`** + `objectType=bug` + `objectID`；非 ASCII 文件名按 UTF-8 原字节写入 multipart `filename`；回查 `GET /api.php/v2/files/{fileId}` 核对 `objectType/objectID`。v1 详情 `files` 可为空数组，**不得**据此判未挂载；以 v2 元数据或缺陷页附件区为准。
- severity/pri：API 传字符串 `"1"`…`"4"`；中文枚举不直接入 API。
- 状态/指派/解决/关闭：按 §1 配置的适配定义与项目状态映射；未适配先补，禁猜接口。
- 备注格式：HTML 用 `<br>` 连接行、块间最多一个 `<p></p>`；禁每行外包 `<p>`、`<br><br>`、`\n\n`。其它格式同构（行间单换行、块间至多一空行）。

## 9. 其它 provider / export

- Jira：mcp-atlassian / 官方 atlassian-mcp-server（许可以仓库为准）；按适配定义读写。
- ONES/TAPD 等无成熟适配：按 `产品档案.md` §7「适配定义」补端点/字段；补不齐走 `export`。
- `export`：AI 出「备注全文 + 附件清单 + 状态/指派动作」可复制包；用户执行后回填单号/结果；未回填前标「待回写」，不得声称完成。

## 10. 安全与格式

- 凭据只从环境变量/本地配置读取，不入产品文档、不入备注、不进提交。
- 备注/附件不写密码、Token、绝对路径、用例/台账路径；真实用户数据/PII 脱敏。
- 写平台文本前按 payload 自检版式；禁把内部路径/密钥带出。
- 回写内容与受理单/变更单/评审记录同源；禁另造一套结论。

## 11. 常见坑

- 只看标题就判产品缺陷，不读 steps/备注/附件；
- 没有相符证明就改 PRD；
- 附件上传不回来查挂载，误判成功；
- 只写备注不改状态，或只改状态不写备注；
- 把实现缺陷当产品缺陷关闭；
- 平台无权限却声称已回写；
- 回写备注与产品文档结论不一致；
- 批量处理时覆盖上一条的结论/附件。
