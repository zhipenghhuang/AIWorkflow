# 维护本包（产品轨）

> 只在改包/自检/维护时读；业务任务不读本节。`AGENTS.md` 只留维护指针。

## 1. 改哪里

- 不变量/路由/读取协议 → `AGENTS.md`
- 步骤 → `workflows/`（0→1：`new-product.yaml`；计划：`plan.yaml`；受理/变更：`change.yaml`；缺陷平台：`defect.yaml`；展示：`showcase.yaml`；原型：`prototype.yaml`）
- 角色契约 → `agents/`
- 红线/输出/门 → `规则/`（门：`规则/门.md`；缺陷平台：`规则/缺陷/缺陷平台协作.md`）
- 澄清协议 → `规则/核心/澄清.md`
- 协作/交接/变更分级 → `规则/协作/协作与交接.md`；交接步骤 → `workflows/handoff.yaml`；回执/台账模板 → `规则/模板/`
- 模板 → `规则/模板/`
- 技能 → `技能/`
- 能力 → `能力/`
- 子代理编排 → `规则/协作/子代理编排.md`（单一出处），workflow/agent 只留指针
- 读取索引 → `规则/读取索引.md`（改 step/reads 后同步）

## 2. 自检

```powershell
powershell -ExecutionPolicy Bypass -File "产品规范/规则/tools/Test-Template.ps1"
python 产品规范/规则/tools/validate_prd.py <PRD.md>
```

自检覆盖：引用/锚点/workflows→agents/步标记/能力名/版本单点/YAML；另跑文档卫生检查（`规则/tools/Test-Template.ps1` 已含）。

## 3. 规则撰写标准

**有用、不冗余（单一出处，其余指针）、不误导、高性价比**；阻塞式确认门必须在 YAML 步上有对应 `hitl`；默认可完成的动作不写；强调集中在不可让项。

## 4. 文档粒度

常驻最小、按需加载：被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。

## 5. 宿主无关

本包文本与 YAML 只写能力名（清单见 `能力/00-能力注册表.md`）；宿主具体值与本地路径只写实例档案与 README「宿主适配」节。
