# 维护本包（产品轨）

> 只在改包/自检/维护时读；业务任务不读本节。`AGENTS.md` 只留维护指针。  
> **能力/技能体检**走 `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`。

## 1. 改哪里

- 不变量/路由/读取协议 → `AGENTS.md`
- 无口令/自然语言入口判定 → `规则/核心/入口判定.md`（改五元组/意图类 A～L/状态修正/置信度时同步；并核 AGENTS §3 指针与读取索引「无口令」行；附录仅校验勿当词典）
- 规则心跳/重锚 → `规则/核心/规则重锚.md`（同步 AGENTS §0 第 8 条、执行契约 §7、activeContext `rule_card`）
- 步骤 → `workflows/`（含 `skill-audit.yaml`；0→1：`new-product.yaml`；计划：`plan.yaml`；受理/变更：`change.yaml`；缺陷平台：`defect.yaml`；展示：`showcase.yaml`；原型：`prototype.yaml`）
- 角色契约（决策权）→ `规则/协作/角色契约.md`；角色 YAML IO → `agents/`
- 红线/输出/门 → `规则/`（门：`规则/门.md`；缺陷平台：`规则/缺陷/缺陷平台协作.md`）
- 澄清协议 → `规则/核心/澄清.md`
- 协作/交接/变更分级 → `规则/协作/协作与交接.md`；交接步骤 → `workflows/handoff.yaml`；回执/台账模板 → `规则/模板/`
- 模板 → `规则/模板/`
- 文档质量标准/类型矩阵 → `规则/核心/文档质量标准.md`
- 适配边界：模板/规则/技能可按项目适配（确认后改本包并登记）；能靠产出文档解决的优先改产出
- 技能 → `技能/`（体检能力确认后可就地改；通用最优：「通用优化技能」）
- 能力契约/参考目录 → 包内 `能力/`；实例 → `产品/能力/`（`规则/能力/实例纪律.md`）
- 能力/技能体检 → `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`
- 子代理编排 → `规则/协作/子代理编排.md`（单一出处），workflow/agent 只留指针
- 读取索引 → `规则/读取索引.md`（改 step/reads 后同步）

## 1.1 体检 vs 装配 vs 维护

| 口令 | 用途 |
| --- | --- |
| 装配能力 | 安装并向 `产品/能力/` 写入 |
| 体检能力（及同义） | 外部能力改 `产品/能力/` + 随包技能可改本包；HITL |
| 通用优化技能 | 同上，mode=generic |
| 维护/查询 | 改规则/自检；深度技能能力分析转体检口令 |

## 2. 自检

```powershell
powershell -ExecutionPolicy Bypass -File "产品规范/规则/tools/Test-Template.ps1"
powershell -ExecutionPolicy Bypass -File "产品规范/规则/tools/Test-DocHygiene.ps1"
python 产品规范/规则/tools/check_skills.py 产品规范 --strict
python 产品规范/规则/tools/validate_prd.py <PRD.md>
```

> **`check_skills.py` 必须带包根**（上例 `产品规范` 或包内 `.`）；裸跑 `--strict` 会假报 `SKILL_DIR_MISSING`。

自检覆盖：引用/锚点/workflows→agents/步标记/能力名/版本单点/YAML/技能；文档卫生见 `Test-DocHygiene.ps1`。

## 3. 规则撰写标准

**有用、不冗余（单一出处，其余指针）、不误导、高性价比**；阻塞式确认门必须在 YAML 步上有对应 `hitl`；默认可完成的动作不写；强调集中在不可让项。

## 4. 文档粒度

常驻最小、按需加载：被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。

## 5. 宿主无关

本包文本与 YAML 只写能力名（⊆ `能力/00-能力契约.md`）；选型/绑定只写 `产品/能力/`；档案 §6 仅索引；宿主要求见 README「宿主适配」。
