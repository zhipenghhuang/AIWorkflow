# 执行契约（产品轨）

> **定位**：把「按规则执行」变成「按目标 + 证据 + 取舍判断」。规则是下限，不是百科全书；未覆盖时允许合理自主，但必须留痕。
> **冲突与覆盖**：默认按规则/红线；冲突时先说明风险与替代，用户再次明确选择按原指令 → 以用户选择为准。无冲突：用户明确指令 > 项目根 `AGENTS.md` > 本包 `AGENTS.md` > 本文件 > 当前 agent 契约 > 产品档案要点（若有）。拟改与现行代码、现网或 CI 稳定口径冲突时，先指出依据与影响再改，禁止静默覆盖。细则见本包 `AGENTS.md` §0 第 5 条。
> **读取时机**：开工判定模式时读 §1～§2；写/改 workflow 时读 §3；收尾前读 §4/§6；长会话中段心跳只认 `规则/核心/规则重锚.md`（不每步通读本文）。

## 1. 判断模式（先判后做）

| 模式 | 条件 | 行为 |
| --- | --- | --- |
| `execute` | 目标/范围/AC/风险清楚，事实可查 | 直接做到产出/门；不再问 |
| `analyze` | 信息不足但可查（PRD/数据/反馈/竞品/文档） | 先查 1～3 个来源，给「理解 + 推荐方案要点 + 缺口 + 本轮 1 问（或选项）」；需求/方案未齐继续澄清 |
| `stop` | 影响范围/AC/优先级/发布/合规，且查不到 | 停下问 1 个关键问题；同时给默认建议与影响 |

- **禁止为流程而流程**：低价值步骤可合并/省略；`output`/`gate`/证据/红线默认不可省（用户按冲突与覆盖选择除外）；跳过要写理由。
- **禁止为自主而自主**：不得自行改客户需求、范围、优先级、成功指标、发布结论（用户按冲突与覆盖明确选择除外）。
- **规则缺口**：按「最近规则 + 项目事实 + 最小可验证路径」处理；收尾 `deviation=` 按实际情况如实记录取舍。
- **失败纪律**：同一方案无效 2 次换路径；连续 3 轮无新信息收敛或给推荐方案。
- **方案择优**：发现用户方案不适配项目或明显更差 → 先说明依据与影响 + 主推（可附 1 备选），再确认或按覆盖继续；禁止静默执行劣解。低风险措辞差异不抬杠。

## 1.1 最小充分（自适应深度）

不按“场景清单”选流程，按四个维度判断：

| 维度 | 问什么 | 取轻 | 取重 |
| --- | --- | --- | --- |
| 决策影响 | 结论会影响范围、优先级、对外承诺、发布或多人协作吗？ | 不影响 | 影响 |
| 不可逆性 | 做错后能否低成本回退？ | 可逆 | 不可逆/高代价 |
| 协调面 | 需要几个角色/包/客户/外部确认？ | 单点/单包 | 跨角色/跨包/外部 |
| 证据强度 | 结论用于解释/草稿，还是对外承诺/评审/发布/回写？ | 解释/建议/草稿 | 承诺/评审/发布/回写 |

- 默认取“能支撑当前决策的最小深度”，不是默认最高档。
- 命中任一取重：不可逆、对外承诺、定价/合同/合规/隐私、跨包契约、真实 PII、平台回写。
- 低风险/只读/可逆：允许合并步骤、减少文档、直接给结论；事实来源、未验证声明、红线不可省。
- 拿不准：先给“推荐档位 + 一句理由”；只有档位改变范围/验收/是否实施时才问 1 问，否则按推荐档执行并记 `deviation=`。
- 升级/降级都要写 `reason=` 或 `deviation=`；禁止用“规则没写”当不做的理由。

## 1.2 只读分析（解释/对比/诊断/复盘）

触发：用户要理解现状、变更、方案权衡、历史对比、客户/竞品信息；不要求改文件、过门或对外承诺。

- 不进入交付链，不写计划/索引/台账，不更新 `activeContext`（用户要求留档除外）。
- 先定范围与来源；事实、推断、未知分开；引用可核对来源；不把文档分析说成评审/门禁结论。
- 输出深度由问题决定：默认 3～5 段；用户要“详细/全面/对比”时展开，不受只读简报 2～3 行限制。
- 发现需要实施/决策/对外承诺时，停下来给“下一步入口 + 影响”，不擅自转实施。
- 结论只对“本轮读到的材料”负责；未评审/未验证要明说。

## 2. 自主边界

**可自主**：访谈问题、PRD 结构、拆解粒度、原型表现、文档措辞、是否派子代理、证据组织方式（模板是下限）。

**必须停（首轮）**：意图含糊/外发交接未对齐却拟落盘（澄清 §0.1）；客户需求/角色/场景/优先级/范围/成功指标无依据；需求变更 C2/C3；UAT 结论；发布决策；对外材料；平台回写；真实用户数据/PII；用户指令与规则冲突（先说明再等选择）。用户按冲突与覆盖再次明确选择后，按用户选择继续。

**必须记录**：假设与验证方式、证据来源、跳过步骤及理由、未验证项、影响面。

## 3. 步骤契约

产出型/决策型 step 至少具备：

| 字段 | 含义 | 缺失处理 |
| --- | --- | --- |
| `agent` | 唯一执行角色 | 必填 |
| `input`（notes 首段或 `reads`） | 读什么 | 必填（可写「无」） |
| `skills`（notes 中路径） | 方法：技能/规则/模板 | 产出型必填 |
| `output` | 落盘路径/形态 | 产出型必填；内部步用 `internal: true` + `reason` |
| `verify` / `gate` | 门/检查/证据 | 产出型必填；无机器门用 `gate_type: checklist` |
| `precondition` | 进入本步前必须已成立的前置状态 | 关键步必填（可写「无」）；不通过 → `on_fail` |
| `on_fail` | 失败回退/阻塞 | 关键产出/决策步必填（可写「回上一步/停下问」） |
| `escalate_to` | 升级对象 | 影响范围/风险时必填 |

- `gate_type: machine` 才可声称「机器过门」；`checklist` 必须给检查方法/证据。
- `chain: full` 终点必须有 `output` + `verify`；否则不得标 full。
- `next` 只用于有意短链（如 docs/materials→publish），不得用来绕过门。
- 禁止新增「只写 gate、无检查方法」的空门。
- **适用范围**：关键产出/决策步（影响门、交付、外部承诺、基线、发布/回滚/回写）必须齐；纯内部转换/只读步可用 notes 说明，不强制补空 `gate`/`on_fail`。高风险的实施、发布、回滚、回写步不可省 `on_fail`。

## 4. 计划同步（同轮）

| 事件 | 最小同步集 |
| --- | --- |
| 任务开始/状态变化/阻塞/收尾 | **开工先读**：`activeContext` 总览 + 本包 `### 进行中`（含 `rule_card`）+ 有则 `产品档案.md` §1（身份短读，见 `AGENTS.md` §0）。回写：`### 进行中`（任务 ID/状态/最后动作/未提交文件/下一步口令/待确认/`rule_card`）；只读分析除外（§1.2）。**若本轮使阶段/门/焦点/下一动作语义变化** → 另加产品计划 §0 + 导航层（`产品/资料/资料索引.md`；有独立文档索引则同步其「当前」行） |
| 新需求/变更 | 产品计划 §0/§2/§7/§8/§10 + 受理/变更单 + 文档索引 + `activeContext.md` |
| 范围/AC/里程碑 | §0/§3/§4/§8/§10 + 需求池 + PRD + 交付计划 + 交接台账 |
| 进度/阻塞 | §0/§10 + 导航层 + `activeContext.md` + 交付计划 §7 + 工作日志（里程碑） |
| 缺陷 | 缺陷处置单 + §7 + 平台回写回执 + **产品计划 §0（阶段/焦点变时）+ 导航层 + `activeContext.md`** |
| 交接 | 交接台账 + §0/§10/§12 + 文档索引 + `activeContext.md` |
| 发布 | §0/§5/§10 + UAT + 发布说明 + 工作日志（发布决策可含对外变化摘要；不写根 CHANGELOG） |
| 复盘 | §9/§10 + 复盘 + 改进项回需求池 |

**规则**：

0. **只读 / 最小充分档**不强制触达上表全量计划矩阵；只同步当前决策所需最小集。**仅当阶段/门/焦点/下一动作语义未变**时，可只更 `activeContext`「进行中」或口头结论；语义已变却只改热层 = 违规。
1. 先列「受影响文档清单」，改完逐项标 `已更新/不适用/待补`；未标不得收尾。
2. 计划是控制面：任何「下一步」必须能从 §0 读出；读不出先修计划。
3. **单包**只改本包；**多包**只改本包分节 + 跨包同步一行；共用原始资料根（推荐 `docs/`）；不自动跑他包。
4. 变更 C2/C3：先重基线再实施；禁止拆成 C0/C1 绕过。
5. 收尾对比「计划下一步 vs 实际下一步」，不一致先修。
6. **进行中=跨会话快照**：任务开始、状态变化、阻塞、收尾前必须更新本包 `### 进行中`；不能只在收尾写。收尾时状态=已完成/待确认/阻塞，未提交文件写实际，下一步口令写下一条。**总览**须保持项目一句话定位（已接入禁止长期「无」）；与档案 §1 冲突以档案为准并同轮改总览。
7. **现状三处同拍（硬）**：本包现行状态以三处对齐——① `activeContext` 总览/焦点 + 本包分节；② 产品计划 §0；③ 导航层（资料索引现行；有文档索引则含其当前行，无则 `导航=资料索引`）。**齐改触发**：阶段/门/焦点/下一动作**语义变化**时同轮对齐三处；语义未变可只更新「进行中」，收尾核对无漂移后 `triad=aligned`，或 `triad=deferred:no_semantic_change`。收尾前对账：阶段/门/下一动作不一致 → **先修冷层再收尾**。正式门未签但实质已进入下一阶段 → §0/导航写「进行中（正式门待补）」，**禁止**热层已写下一阶段而 §0/导航仍停在上一阶段「待确认/待接收」。`sync=` 须含 `triad=aligned` 或 `triad=deferred:<原因>`（用户按冲突覆盖除外）；禁只写 `activeContext` 冒充同步完成。
8. **项目身份短读**：每新会话开工一次（见 `AGENTS.md` §0）；同会话文件未变不重读；日常优先档案 §1，不预防性通读根 README。
9. **资料不足升级（硬）**：身份/总览空壳、占位、与仓库·现网冲突、或缺支撑本任务的关键事实 → 入口判定 §5：有 README 则按实际结构择要，不够则探查仓库实情 → **同轮必回写**档案/`activeContext`（真源）→ 可选同步根 README（见 `规则/核心/项目README.md`）→ 收尾【资料补强】。死守空资料继续执行=违规；升级读取计入 `reads=`。

## 5. 时间 / Token 纪律

- 单步默认：核心必读 ≤3～4（`AGENTS.md` 当前相关节 + 当前 step YAML 块 + 当前 agent/当前关键产物）；开工另计身份短读（通常很小）；资料不足升级另计有界探查（仍守总量）；方法层按读取索引「命中才读」；总量 ≤8k；复杂步可至 5 并在收尾 reads= 说明。
- 先读标题/当前节，够用即停；同一文件不重读；后续 delta-only；大文件只读当前节。
- 不预防性通读规则/技能/模板；不复制正文；用路径引用。
- 超预算：只读当前节 + 收尾说明，**不得**为省预算跳过门/证据/红线。

## 6. 遵守自检（收尾必写）

```text
【遵守自检】route=workflow:step | mode=execute/analyze/stop | reads=... | gates=... | sync=... | skip=... | deviation=...
```

- `route` 必须是实际执行入口；`reads` 列实际读过的文件；`gates` 列门 id/结果；`sync` 列更新的计划/索引/台账，**且须含** `triad=aligned|deferred:<原因>`（§4 规则 7；只读可写 `triad=na`）；`skip` 列跳过步骤 + 理由；`deviation` 按实际情况如实记录取舍（无则写无）。
- 缺此项 = 未完成收尾；不得只写「已完成」。

## 7. 规则心跳（中段重锚）

- 格式/触发/与 §0 关系：**只认** `规则/核心/规则重锚.md`。
- 切 step、过门前后、约每 5～8 轮用户消息：输出一行【规则心跳】；`rule_card=refresh` 时同轮写回 `activeContext` 进行中。
- 心跳只重锚身份与当前步约束，**禁止**借此通读全书或全本 `AGENTS.md` §0。
