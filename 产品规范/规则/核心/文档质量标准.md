# 文档质量标准（产品轨）

> **定位**：产品轨所有文档的**通用合格线**。模板只提供结构；本文件判断“这份文档能不能用、能不能作为决策依据”。
> **适用**：PRD、需求池、原型说明、产品计划、UAT、GTM、演示/一页纸/用户手册、复盘、交接包、工作日志。
> **原则**：按文档位置定内容；PRD 不写技术方案，UAT 不用开发自测替代，GTM 不写未证实宣称。

## 0. 冲突优先级

安全/合规/硬红线 > 用户明确指令 > 项目根 AGENTS > 包 AGENTS > 本文件 > 模板结构 > 历史文档。

模板与本文件冲突：**先修母版模板并升版本 → 自检 → 整包分发**；不按旧模板产出，也不在实例里各自改。

## 0.1 母版 / 实例 / 模板的使用方式

- **母版只维护通用高标准**：不写具体项目环境、端口、账号、组织、版本等实例事实。
- **实例默认不改，但可本地适配**：项目里的 `开发规范/产品规范/测试规范` 默认按母版使用；AI 发现模板/规则/技能不匹配或有更好做法，先输出「拟改内容/原因/影响」，用户确认后只改当前实例，不影响母版。
- **本地适配要留痕**：确认后在项目档案或本地适配记录登记（文件/原因/日期/确认人）；母版整包更新前先备份/比对，避免覆盖；本地适配不自动回灌母版。
- **模板是骨架、标准是底线**：按当前项目实际和文档位置裁剪/补充，不要求逐条机械填写；不适用项写「不适用 + 理由」，不为凑模板写空话。
- **不匹配时先改产出**：模板/标准与项目实际不匹配，优先修改当前项目生成的文档（PRD/UAT/演示等），使其贴合实际并可验收。
- **适配建议回母版需确认**：AI 可向用户说明差异/影响/建议；只有用户确认且属于通用改进时，才回母版修改并升版本；项目特化不回灌母版。

## 1. 通用硬门槛（任一不满足 = 不合格）

1. **目的与读者明确**：开头能看出“给谁、解决什么、用来做什么决定”。
2. **事实有来源**：客户/用户原话、角色、数据、日期、指标、范围、优先级必须来自来源/研究/用户确认；无来源写「假设/待验证」，不得写成事实；未确认先问，禁止用默认/示例/历史值。
3. **范围有边界**：in/out、目标/非目标、本期/后续分开；out 有来源/理由/确认人。
4. **可验收**：每条需求/场景有可观察结果或 AC；禁“体验更好/更完善”等空话。
5. **证据可核对**：引用原文/数据/原型/访谈/评审记录；结论能回到来源。
6. **一致与追溯**：需求 ID/AC/原型/版本互相一致；不出现两套口径。
7. **状态与变更**：版本/日期/负责人/状态/变更记录齐；旧版归档。
8. **安全与合规**：无真实 PII/密钥；客户数据脱敏；合规/隐私边界写清。
9. **语言克制**：只写现行事实与必要说明；禁辩解式/对比式/冗余括注、未经确认的“应该/可能”。
10. **不替开发/测试下结论**：业务规则/验收写清，技术方案/测试准出归开发/测试。

## 2. 产品文档类型矩阵

| 文档 | 位置/作用 | 必须具备 | 不应包含 | 合格判据 |
| --- | --- | --- | --- | --- |
| PRD | 业务需求合同 | 问题/用户/场景/范围/AC/NFR/非目标/来源/追溯 | 技术架构/DB/API 实现 | 开发可拆任务、测试可设计用例 |
| 需求池 | 需求候选管理 | 来源/价值/优先级/状态/负责人/目标版本 | 未确认的排期承诺 | 可排序、可追溯 |
| 原型说明 | UI/交互依据 | 流程/状态/文案/异常/权限/断点 | 后端规则臆测 | 设计与开发可落地 |
| 产品计划 | 版本/里程碑控制 | 目标/范围/里程碑/依赖/风险/决策 | 开发详细排期 | 可检查、可调整 |
| UAT 验收 | 业务验收 | AC/角色/数据/步骤/结果/证据/签收 | 开发自测替代 | 逐条 AC 有结论 |
| GTM | 上市/运营计划 | 人群/价值/证据/渠道/节奏/风险 | 未证实宣称/虚假数据 | 可执行、可合规审查 |
| 演示/一页纸/用户手册 | 对外表达 | 受众/场景/步骤/边界/术语 | 内部黑话、未公开信息 | 目标读者能懂 |
| 复盘 | 改进闭环 | 事实/根因/行动项/负责人/截止/验证 | 追责、空泛口号 | 行动项可验收 |
| 交接包 | 跨角色快照 | 00/01/必带快照/回执可选/版本/缺口 | 密钥、未过门草稿 | 接收方可独立核对 |
| 工作日志/CHANGELOG | 里程碑/发版史 | 版本/日期/变更/迁移/影响 | 过程流水账 | 可追溯、不过期 |

## 3. 评审清单（交付前逐项过）

- [ ] 目的/读者/范围一句话能说清
- [ ] 客户/用户事实有来源；假设已标「假设/待验证」
- [ ] out/非目标有来源/理由/确认人
- [ ] 每条需求/AC 可观察、可验收
- [ ] 原型/文案/异常/权限状态齐
- [ ] 指标/数据有口径与来源
- [ ] 状态/版本/负责人/变更记录齐
- [ ] 无密钥/PII；引用可打开
- [ ] 不替开发/测试下结论

## 4. 参考基线（对齐，不照抄）

- ISO/IEC/IEEE 29148（需求工程）
- Diátaxis（按文档位置定位）
- Atlassian/Product School PRD 实践（问题/用户/AC/非目标）
- MADR（涉及产品技术决策时可引用）
- Keep a Changelog、Semantic Versioning（版本/变更）
- GitHub Docs：Issue Forms、PR 模板、Security Policy、Contributing
- WCAG 2.2（涉及 UI 可访问性）
- Google SRE Workbook（复盘/行动项）

## 5. 维护

- 新增/修改模板时，同步更新本文件 §2 类型矩阵与模板索引。
- 发现“模板有结构但产出不可用” → 先修模板/标准，再修单份文档。
- 版本随包 `template_version` 更新；本文件不单独设版本号。
