# 验证与定稿（产品轨）

> **单一出处**：PRD/评审/UAT/变更/回写的完成状态与报告措辞。`AGENTS.md` 只留指针；`验证/README.md` 是操作入口。
> **读取时机**：`prd.review`、`deliver.uat`、`change.apply`、`defect.writeback` 前。维护读 `规则/核心/规则治理.md`。

## 1. 不变量（带 ID）

| ID | 不变量 |
| --- | --- |
| PRODUCT-VER-01 | PRD 结构完整 ≠ 需求定义完；AC 必须可判定，TBD 必须有责任人/期限。 |
| PRODUCT-VER-02 | 定稿只认门：P2+ `status=APPROVED` 必须有独立评审记录 + `gate_id`；P0/P1 轻量 PRD 用 `prd_level=light` + `review_status=SELF_CHECKED`，免独立评审。 |
| PRODUCT-VER-03 | 评审人 ≠ 作者；评审记录含清单/评分/阻断项；同一会话自评不算独立评审。`gate_id` 由门回执回填，不手编。 |
| PRODUCT-VER-04 | 追溯闭合：F/R/A/AC/原型/测试/发布链路无空链；变更/缺陷联动清单逐项“已更新/不适用/待补”。 |
| PRODUCT-VER-05 | UAT 对照 AC + 证据；有条件通过必须有遗留项、责任人、接受人。 |
| PRODUCT-VER-06 | 平台回写有回执：单号/备注/状态/附件回查；无权限走 export，不得声称已回写。 |
| PRODUCT-VER-07 | 报告先写 `【验证回执】`；非 READY 禁用“已定稿/评审通过/可发布”。 |
| PRODUCT-VER-08 | 机器查结构/追溯/证据/回执；人判断价值/优先级/设计质量；两者都不可省。 |

## 2. 完成状态

| 状态 | 条件 | 报告措辞 |
| --- | --- | --- |
| `READY` | 结构/追溯/独立评审/UAT/联动/回写检查通过 | 已定稿/评审通过/可发布 |
| `DRAFT` | 结构完整但有非阻断待确认/未定稿 | 草稿/待评审；列待确认 |
| `BLOCKED` | 缺评审/缺证据/关键 TBD 无主/断链/无回执 | 未完成/阻塞/未验证 |

**P2+ 定稿顺序**：先写评审记录 → `-Mode review`（写 `.gate/产品规范/review.json`，READY 后取 `gate_id`）→ 回填 PRD/评审记录并置 `status/review_status=APPROVED` → `-Mode prd` 核结构/追溯/gate_id 一致性得 READY。**轻量 PRD**：`prd_level=light`，免独立评审，`-Mode prd` 直接核。回执按包分目录（`.gate/产品规范/{mode}.json`），读前核对 `package`/`mode`/`gate_id`，不符=未验证。

## 3. 分档验证

| 级别 | 验证 |
| --- | --- |
| P0 文案/配置 | 结构 + TBD + 变更留痕；不要求全量 PRD/独立评审 |
| P1 小功能 | 轻量 PRD 节（背景/范围/AC/排除/风险）+ 自检；不强制独立评审 |
| P2 功能/版本 | 完整 PRD + 独立评审 + 追溯 + UAT |
| P3 0→1/战略 | P2 + 立项/计划门 + 用户签收 + 发布决策 |

## 4. 报告契约

```text
【验证回执】verdict=READY|DRAFT|BLOCKED | gate={gateId/时间} | checks={通过}/{总数} | open={n}
```

- 回执在【任务收尾】第 1 点之前。
- `READY` 才可写“已定稿/评审通过/可发布”；`DRAFT` 写“草稿/待评审”；`BLOCKED` 写“未完成/阻塞”。
- 数字/单号/路径与门输出一致。

## 5. 成本纪律

- 不新增 PRD/评审/UAT 文档；门读现有产物。
- 全量 PRD 结构检查用 `validate_prd.py`；轻量 PRD 走 `prd_level=light` 最小校验；语义/独立性/闭合用轻量脚本。
- P0/P1 轻量；P2+ 才独立评审/全量追溯。
- 人只看价值/取舍/设计质量；机器查结构/证据/回执。
