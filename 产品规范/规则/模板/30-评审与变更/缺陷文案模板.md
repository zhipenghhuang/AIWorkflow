# 缺陷文案模板（回写/附件/批末）

> 只在拟回写/批末时读；`规则/缺陷/缺陷平台协作.md` §5～§7 指向本文件。

## 5. 回写平台（confirm_remark）

回写前必须出示：

- 缺陷 id / 标题；
- 分诊结论与依据（产品缺陷附相符证明）；
- 处置结论与目标版本；
- **备注全文**；
- 附件名（缺陷处置单/受理单/变更单/评审意见/PRD 变更摘要，按需）；
- 状态 / 指派变更；
- 需要谁做什么、截止。

确认后执行；备注与状态**同轮**写入。平台普通角色无删除权限，**禁删缺陷**。

### 5.1 备注骨架（按备注格式 html / markdown / text 同构）

> 通用简版；来源=开发评估单优先用 §5.1.1，来源=测试直提优先用 §5.1.2。

```text
【产品缺陷·处置结论】{平台单号} · {标题}
一、分诊：{产品缺陷/实现缺陷}；依据：{PRD §… + 现网/测试证据 + 相符证明}
二、结论：{立即修 / 下版 / 不修 / 退回开发 / 补充信息}
三、影响：{AC/范围/排期/数据/合规/回归}
四、下一步：{变更单 CR-… / 需求 R-… / 开发修复 / 补充信息}
五、附件：{缺陷处置单/受理单/变更单/评审意见/PRD 变更摘要}
六、目标版本 / 截止：{…}
```

- 实现缺陷退回：结论写「退回开发修复」，附依据、复现/验收要求；不写「产品口径调整」。
- 产品缺陷下版：写「本期不改，进入下版需求池 R-…」。
- 不修：写理由、风险、接受人。
- 补充信息：一次列清所需材料，不反复追问。

### 5.1.1 开发评估单复核（来源=开发评估单）

```text
【产品缺陷·评估结论】{平台单号} · {标题}
一、来源：开发评估单 《{文件名}》
二、复核结论：{认可方案 | 修改后认可 | 不认可方案 | 判定实现缺陷 | 判定非问题}
三、依据：{PRD/设计 §章节 + 原文；现网/测试证据；相符证明或排除理由}
四、处置：{立即修/下版/不修/补充信息}；新口径：{…}
五、对开发要求：{改什么/不改什么/验收标准/需同步文档/回归范围}
六、附件：{缺陷处置单/变更单/更新后的 PRD/设计}
七、指派 / 目标版本 / 截止：{开发或测试；…}
```

- 认可/修改后认可 → 必须给新口径或新文档；不能只写「同意」。
- 不认可 → 必须说明不认可哪一条、依据是什么、建议怎么做；不要只写「不是产品缺陷」。
- 判定实现缺陷 → 给实现偏差与验收要求；不改 PRD。
- 判定非问题 → 给设计/需求依据；默认指派开发（或按备注指派测试）。

### 5.1.2 测试直提产品缺陷（来源=测试直提）

```text
【产品缺陷·测试直提处置】{平台单号} · {标题}
一、判定：{产品缺陷 / 实现缺陷 / 非问题 / 重复 / 信息不足}
二、依据：{PRD/设计 §章节 + 原文；现网/测试证据；相符证明/排除理由}
三、处置：{立即修 / 下版 / 不修 / 退回开发 / 补充信息}
四、新口径/文档：{新产品文档名/PRD 变更/AC；无则「不适用」}
五、对开发要求：{改什么/不改什么/验收标准/回归范围}
六、对测试说明：{关闭/补充/复测/转需求}
七、附件：{缺陷处置单/变更单/更新后的 PRD}
八、指派 / 目标版本 / 截止：{开发或测试；…}
```

- 判定产品缺陷 → 必须给新口径/新文档/AC；指派开发，不只写「确认是产品缺陷」。
- 判定实现缺陷 → 指派开发，给依据与验收要求。
- 判定非问题/重复/信息不足 → 指派回测试，给依据与下一步。

### 5.2 批量回写确认包

```text
next_action=AWAIT_CONFIRM
【拟回写】共 {N} 条：产品缺陷 {A} / 实现缺陷 {B} / 非问题 {C} / 重复 {D} / 信息不足 {E} / 补充信息 {F}

- #{id} [{来源}/{分类}] {标题}
  结论：{认可方案/修改后认可/不认可方案/判定实现缺陷/判定非问题/立即修/下版/不修/退回/补充信息}
  备注全文：（§5.1/§5.1.1/§5.1.2）
  附件：{缺陷处置单/变更单/评审意见/PRD 变更摘要}
  状态/指派：{原 → 新；无则「不变」}

【拟回写·底部摘要】（**必有**；无类省略；一类可仅一单）
产品缺陷→开发：#{id}[, #{id}…]
实现缺陷→开发：#{id}[, #{id}…]
非问题/关闭：#{id}[, #{id}…]
重复：#{id}→主单 #{main}
信息不足→回测试：#{id}[, #{id}…]
补充信息：#{id}[, #{id}…]
```

确认后逐条执行；一条失败不冒充全部成功。对照上方样例：包末必有【拟回写·底部摘要】；写回后「完成了什么」短段复述单号清单并单列「影响：」（禁计数空话）。

## 6. 附件 / 状态 / 指派

| 动作 | 要求 |
| --- | --- |
| 附件上传 | 用平台适配接口；上传后回查挂载（元数据/页面附件区）；失败重试 ≤1，禁反复重传；产品处置单/变更单/新 PRD 必须挂载 |
| 状态变更 | 按适配映射；备注与状态同轮；平台不允许代改状态 → 备注说明并请有权限人操作 |
| 指派 | 按 §4.3 指派矩阵：产品缺陷/实现缺陷→开发；非问题/重复/信息不足按来源→测试或开发；补充信息/信息不足→提交人/测试/开发（按来源） |
| 关闭 | 仅产品侧处置完成且验证通过；实现缺陷未修复不得关；下版/不修按团队口径；非问题需给依据 |
| 失败 | 停，不声称已回写；出 export 包并标「待回写」 |

## 7. 批末总结

```text

立即修 {E}；下版 {F}；不修 {G}；退回 {H}；补充信息 {I}
回写成功 {J}；待回写 {K}；失败 {L}

【写回结果·单号】（计数为 0 的类整行省略）
产品缺陷→开发：#{id}, #{id}
实现缺陷→开发：#{id}
非问题/关闭：#{id}
重复/信息不足/补充：#{id}
失败/待回写：#{id} — {原因}

- #{id} [{来源}/{分类}] {标题}：{处置}｜{指派}｜{回写动作}｜{最新文档}
（无法确认/跳过项也各一行说明）
```
