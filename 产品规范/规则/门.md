# 门（产品轨）

> 单一出处：门语义、`when` 词表、门档位。步骤顺序与是否触发以 `../workflows/*.yaml` 为准；**只认步上 `hitl`**，专规不另造门。
> 读取时机：当前步有 `hitl` 时只读本表对应一行；写/改 YAML 时才读全表。不要每次开工通读。
> 质量审计/评分卡参考见 `专项/质量门.md`；它不是额外确认门，执行仍只认步上 `hitl`。

## 1. 门语义

| 门 | 含义 | 必须行为 |
| --- | --- | --- |
| `confirm_go` | 新产品立项 | 出示问题/市场/方案/MVP 假设/成本收益/风险/结论（Go/Hold/Kill）；未过不写全量 PRD |
| `confirm_understanding` | 需求理解 | 出示客户/用户、场景、问题、现有替代、目标结果、范围/非目标、证据/假设、缺口清单、成功标准；确认后才分诊/写 PRD/计划/排期 |
| `confirm_plan` | 产品计划 | 首次计划或范围·指标·版本实质变更：目标/路线图/本期范围/里程碑/风险 一行摘要；未确认不进 PRD/排期 |
| `confirm_design` | 设计方向 | IA/线框/2～3 个视觉方向/tokens；确认后才做高保真 |
| `confirm_prototype` | 原型交接 | 原型路径/设计评审结论/交接要点；确认后才交开发 |
| `confirm_narrative` | 展示叙事 | 受众/目标/故事线/演示范围已成形后确认；仅叙事不明或首次对外演示时停 |
| `confirm_materials` | 对外材料 | 一页纸/Deck/用户文档/发布说明；数字/截图/流程与当前项目一致；仅对外发送、承诺或发布前触发 |
| `confirm_scope` | 单需求立项范围 | 范围（MVP）/排除项/粗排期/风险 一行摘要；条件门：仅跨版本/高价值/未确认范围时停 |
| `confirm_prd` | PRD 定稿/实质变更重审 | 评审结论为「通过（可定稿）」且用户点名定稿/进入排期时出示；定稿前不排期；仅评审不弹门 |
| `confirm_change` | 需求变更/产品缺陷处置/实现缺陷退回 | 出示分诊依据、影响与变更单/处置要点；产品缺陷须有相符证明；无单不实施 |
| `confirm_remark` | 缺陷平台回写 | 出示 id+结论+备注全文+附件名+状态/指派变更；备注与状态同轮；平台不支持出 export |
| `confirm_release` | 发布 | 出示 UAT 结论、回滚预案、公告/客服/监控就绪；未过不发布；已发布仅复盘不重复确认 |
| `confirm_commit` | 拟提交 | 【拟提交】块（文件清单+`.gitignore`+当前分支）；确认后提交；禁擅自切主干/force push/开合并 PR |
| `confirm_handoff` | 交接包发送 | 出示 HO-ID/类型/接收方/必带清单/阻断项/回执截止；确认后才生成/发送；未收回执不得称“已交接” |
| `confirm_gitignore` | 入库策略 | 四选一确认并写 `.gitignore` |
| `confirm_docs_migration` | 资料/工作文档搬迁、归档或临时清理 | 出示分类/覆盖对照/拟归档或清理清单与目标；确认后执行；不擅自删、不覆盖 |
| `gate: product-review` | PRD 评审/定稿门禁 | 运行 `验证/Invoke-Gate.ps1 -Mode review`；评审人≠作者、清单/评分/阻断项、verdict；READY 后取其 `gate_id` 回填；未 READY 不得定稿 |
| `gate: uat-evidence` | UAT 门禁 | 运行 `验证/Invoke-Gate.ps1 -Mode uat`；AC 覆盖、证据、有条件通过的责任人/接受人；未 READY 不得写 UAT 通过 |
| `gate: change-closure` | 变更/缺陷联动闭合 | 运行 `验证/Invoke-Gate.ps1 -Mode change`；§6 每项“已更新/不适用/待补”，待补有责任人/截止；未闭合不得关闭 |
| `gate: writeback-receipt` | 平台回写门禁 | 运行 `验证/Invoke-Gate.ps1 -Mode writeback`；单号/备注/状态/附件回查/回执；无回执不得声称已回写 |

## 2. `when` 词表

`has_pending_commit` 有文件变更待提交｜`has_uat` 本轮有 UAT/验收要求（发布门必须核）｜`change_requested` 改动已定稿基线或产品缺陷/问题处置需确认（不含纯新需求入池）｜`understanding_needs_confirm` 输入为模糊/单点需求、含外部文档或原型、存在实质冲突、或 P2/P3/点名写 PRD/计划时需确认理解；已有**当前任务**理解确认记录/已确认受理单、或信息完整的缺陷单/答疑且已能复述时假｜`plan_needs_confirm` 首次计划或范围·指标·版本实质变更｜`new_requirement_or_scope_change` 新需求/范围变化｜`new_requirement` 分诊为新需求（不含已定稿基线的需求变更）｜`scope_decision_required` 跨版本/高价值/点名立项，需单需求范围确认｜`scope_unconfirmed` 无已确认产品计划且无已批准的单需求范围｜`finalize_requested` 评审通过且用户点名定稿/进入排期（仅评审不触发）｜`has_ui_requirement` 有页面/界面需求或点名画原型｜`narrative_needs_confirm` 受众/目标/演示范围不明或首次对外演示｜`materials_for_external` 材料/文档将对外发送、承诺或发布｜`demo_needs_dryrun` 准备演示/客户介绍/彩排｜`docs_requested` 点名用户手册/快速开始/FAQ/发布说明/培训材料｜`needs_impact_assessment` 变更/缺陷/新需求需影响评估｜`needs_linked_update` 需联动回写与回执（除纯答疑外均为真）｜`substantive_change` 实质变更需重审｜`plan_level_change` 影响版本范围/里程碑/KPI｜`release_decision_needed` 未发布或发布内容/窗口变更｜`remark_writeback` 有拟回写缺陷平台的备注/附件/状态/指派｜`handoff_send_required` 显式生成交接包且接收方/范围/必带文档尚未在上一门确认；已由 `confirm_prd`/`confirm_prototype`/`confirm_release` 等确认同一发送时为假｜`handoff_change_substantive` 交接包内变更达到 C2/C3 或改动已定稿基线｜`prd_ready_for_handoff` PRD 已 `APPROVED` 且 PRD 门 READY，本轮 `confirm_prd` 定稿/进入排期，且台账无同版本 `REQ` 已发送/已接收记录；仅评审不触发｜`docs_migration_needed` 有未登记资料、拟改名/搬迁/归档、工作文档归档或临时文件清理、或旧结构迁移。

条件不满足则跳过该门；未写 `when` 视为无条件。同一确认点只问一次；固定骨架不得省略。

## 3. 门档位（防过度审批）

| 档 | 适用 | 行为 |
| --- | --- | --- |
| autonomous | 只读、低风险、可逆 | 直接做，收尾记录假设 |
| notify | 中风险、可回退 | 展示计划/清单后继续，用户可打断 |
| approve | 高风险/不可逆 | 停：立项、计划、定稿、变更、平台回写、发布、提交、搬迁/归档/清理、交接包发送 |

低风险动作不要升级为 approve；高风险动作不得降为 notify。红线不被“少问/直跑”覆盖。
