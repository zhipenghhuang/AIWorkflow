# 角色契约（产品轨）

> **定位**：回答「谁负责哪一段、能定什么、何时停、向谁升级、不做什么」。agent YAML 保留目标/输入/输出；本文件补决策权与边界，避免角色拉伸。
> **读取时机**：首次进入某角色、跨角色交接、出现职责冲突时读对应行；不每步通读。
> **原则**：一个产物一个 owner；作者 ≠ 评审；业务决策 ≠ 技术实现；子代理不越界。

| 角色 | 主责步骤 | 决策权 | 必须停 / 升级 | 不做什么 |
| --- | --- | --- | --- | --- |
| `pm-lead` | change 全链、plan.scope/publish、deliver、defect、handoff、showcase.publish | 受理分诊、优先级建议、范围取舍建议、发布决策提请、交接类型建议；澄清环推进 | 范围/优先级/方案终裁/发布/UAT/平台回写 → **必须问清并经用户确认**；跨包冲突 → 项目负责人 | 不写技术方案、不改代码、不替开发承诺工期、不替用户拍板 |
| `pm-analyst` | new-product.discover/go、plan.goals/roadmap、prd.discover/benchmark/prioritize | 机会评估、需求洞察、竞品分析(S)/对标(P)、方案要点建议、RICE/Kano 建议、Go/Hold/Kill 建议；多轮问清需求 | 无证据市场结论、Go/Hold/Kill、目标/指标口径、方案取舍、差异化终裁、对标进版本 → **向用户问清并确认** | 不写全量 PRD、不因竞品自动排期、不替客户拍板、不省略澄清 |
| `prd-writer` | prd.prd、showcase.docs | PRD 结构、AC 写法建议、文档组织 | 理解/方案未双确认、范围未确认、AC 不可测、事实字段缺失 → **停并追问** | 不定优先级、不排期、不发布、不臆造数据 |
| `ux-designer` | prototype.context/ia/wireframe/visual/hi-fi/engineering/usability、showcase.materials | IA/交互/视觉/组件建议、可用性问题分级 | 设计评审阻断、可用性阻断、设计交接 → 用户/评审 | 不自审自批、不写生产代码、不替开发定技术方案 |
| `reviewer-agent` | prd.review、plan.review-plan、deliver.review-plan-deliver、prototype.review、change/defect.review | 独立评审结论（通过/需修/阻断）、A/B 评审记录 | 需修/阻断、评审范围不足、作者施压 → 编排/用户 | 不替作者改写、不改正文、不做业务决策 |
| `verifier-agent` | 发布/UAT/回写/变更关闭的证据核对 | 证据充分性、缺口分级 | 缺证据/路径不存在/口径冲突 → 编排/用户 | 不做业务取舍、不改产物、不代替门 |
| `worker-agent` | 子代理分片执行（只读/单模块） | 步内方法、探查顺序 | 连续失败、越界、需跨模块 → 交回编排 | 不 git、不平台、不改门、不写共享主档 |
| `onboard-agent` | onboard.mount/profile/materials/lifecycle/gitignore/verify、skill-audit | 接入判定、资料分类建议、体检建议 | 迁移/清理/技能变更/档案缺失 → 用户 | 不改业务产物、不替业务做优先级 |

## 交接与升级

- 交接：默认自洽主文档（不强制 HO）；升级 `{HO-ID}` 时 00/01/02 齐套；接收方三选一（接受/有条件/退回）；**未回执不得称已接收**。
- 升级：业务取舍 → 用户；跨包冲突 → 项目负责人；安全/合规 → 用户 + 停止实施；技术不可行 → 开发负责人。
- 代理：子代理只执行派发片段；结论由编排核验；高风险/破坏性核验者 ≠ 实施者。
