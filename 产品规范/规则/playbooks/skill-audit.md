# 能力与技能体检（产品轨）

> **读取级别：参考**。仅 skill-audit 或点名体检时读。  
> **改哪里**：能力 → `产品/能力/`；技能 → 本包 `技能/`（HITL）。

## 1. 模式

| 模式 | 触发 | 对照 | 改什么 |
| --- | --- | --- | --- |
| **project** | 体检能力等且有对照 | `产品/能力/`、产品档案索引、阶段、近期降级 | 实例能力 + 包内技能 |
| **generic** | 「通用…」或无档案/清单 | 契约+参考目录、技能完整性 | 可改技能；禁项目选型写入包契约当真源 |

判定：含「通用/不按项目/通用最优」→ generic；无填实档案且无 `产品/能力/00-能力清单.md` → 强制 generic；否则 project。

## 2. 流程

scope → inventory（清单+契约/参考+技能映射）→ fit → propose → apply → wrap。

## 3. 建议卡

```text
ID / 对象（能力名 | 技能/<name>）
现象：与基准的差（证据：清单行 / 门失败 / 用户目标）
判定：缺装 | 达不到要求 | 过重 | 过时 | 重复 | 映射断裂 | 可维持
动作：装配能力 | 改产品/能力/ | 就地改 SKILL.md | 改技能 README 映射 | 维持+降级可接受
优先级：P0 / P1 / P2
成本：安装 · token · 维护
```

## 4. 确认后

- 能力写入 `产品/能力/`；档案 §6 只刷索引。  
- 技能改包内；契约/参考目录仅通用回灌时改。  
- 改包后跑 `规则/tools/Test-Template.ps1`。

## 5. 纪律

未 HITL 零改动；能力 SSOT=`产品/能力/`；浏览器可复用 `测试/能力/` 指针。
