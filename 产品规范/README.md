# 产品规范 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（产品轨）**：声明式 `workflows/*.yaml` + 角色 `agents/*.yaml` + 规则 `规则/` + 内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）。  
主链：**新产品 0→1**（发现 → 立项 → 产品定义 → PRD → 交付 → 上市 → 复盘）与**迭代**（需求洞察 → 优先级/立项 → PRD → 评审定稿 → 排期 → 跟进/变更 → UAT → 发布 → 复盘）；**产品计划**（`产品/产品计划.md`）为总领单点；**展示**（`showcase.yaml`）：受众 → 故事线/流程图 → 演示脚本 → Demo 环境 → 材料/用户文档 → 彩排。  
执行宿主（任意支持 AGENTS 的 AI 编码工具，要求见本文「宿主适配」节）按 YAML 步骤执行；步内实现路径交 AI（框架固定 · 局部自主）。

## 2. 目录

| 路径 | 作用 |
| --- | --- |
| `workflows/` | `new-product`（0→1）· `plan`（产品计划/路线图）· `prd`（洞察/立项/PRD/评审）· `prototype`（IA/线框/视觉/高保真/评审/交接）· `showcase`（演示/介绍/用户文档）· `change`（受理与变更）· `defect`（缺陷平台）· `deliver`（排期/UAT/发布/复盘）· `onboard` |
| `agents/` | pm-analyst / prd-writer / pm-lead / reviewer-agent / ux-designer / onboard-agent |
| `能力/` | 可选能力注册表（技能/工具装配建议；`能力/00-能力注册表.md`） |
| `技能/` | 内置专业技能（每步方法/手艺，随包生效、按步自动加载；`技能/README.md`） |
| `AGENTS.md` | AI 入口（口令→workflow；版本单点） |
| `规则/工作流.md` | 铁律、产物路径、拟提交与收尾骨架 |
| `规则/缺陷平台协作.md` | 缺陷平台拉取/读取/分析/回写、备注骨架、附件与状态映射 |
| `规则/质量门.md` | 7 个质量门、评分卡、追溯/证据/决策台账、审计 |
| `规则/模板/` | 产品档案 / 产品计划 / 立项书 / PRD / 需求池 / 评审记录 / 受理与处置 / 交付计划 / 变更单 / UAT验收 / GTM / 复盘 / 原型说明 / 设计评审 / 原型工程化检查 / 可用性走查 / 原型脚手架 / 演示脚本 / 一页纸与Deck / 用户手册与快速开始 / 发布说明与Changelog / 演示检查单 / 反馈记录 / activeContext / 根 AGENTS 引导样例 |
| `规则/tools/` | 包自检 `Test-Template.ps1`（YAML 语法/schema + 引用/锚点/流程引用/步标记/能力名/版本单点）+ `validate_workflow.py` |

> 实例在项目根：`产品档案.md`（含 §3 产品规范要点——固定内联）、`activeContext.md`；全部产出统一在 **`产品/`**（产品计划、需求池、立项书、各版本 PRD/评审/受理/交付计划/变更单/UAT/GTM/原型/展示/复盘、`用户文档/`、`资料/`、`_归档/`）。  
> **资料 vs 工作文档**：`产品/资料/` 只放外部输入（项目文档/反馈/调研/竞品/数据）；`产品/用户文档/` 放对外交付文档（快速开始/手册/FAQ/发布说明/培训）；`产品/产品计划.md`、`产品/需求池.md`、`产品/{版本或主题}/` 是工作文档。
> **可选联动（不强制）**：本包可独立落地。若项目同时启用其它包，PRD/立项书/产品计划可作为其输入；UAT 有测试报告/提测单则参考；工程部署由开发轨执行（如启用），未启用则由用户安排；复盘可合并；缺陷平台配置可复用开发/测试包同源值（`项目档案.md` §3/§4、测试包环境基线 §13）。输入缺失时提示一次，由用户提供/沿用现有资料，不阻塞。  
> **边界**：产品负责需求/规则/原型/验收；技术架构、技术栈、数据库/API/部署归开发轨（如启用）或由用户安排，产品不越界设计。  

## 3. 上手（快速开始）

1. 复制整个 `产品规范/` 到项目根下一层  
2. 挂载：按 `规则/模板/根AGENTS薄指针.md` 把引导语句补入项目根 `AGENTS.md`（追加不覆盖）  
3. 对 AI 说「接入产品规范」→ 生成 `产品档案.md` 与 `activeContext.md`、确认入库策略、打标  
4. 之后直接说口令：「收集需求」「产品计划」「写 PRD」「画原型」「PRD 评审」「排期」「需求变更」「UAT」「发布」「准备演示」「用户手册」「发布说明」「复盘」  
5. 也可以直接把需求/问题/缺陷发来（对话或文档）：AI 走 `change` 受理 → 分诊 → 处置 → 联动更新，最后给出受理单、变更单（如适用）、最新 PRD/计划/UAT 与开发/测试回执。  
6. 已配置禅道/Jira/ONES：说「拉取我的产品缺陷」→ 读详情/备注/附件 → 分析 → 回写备注/附件/状态/指派；未配置则粘贴/导出，不阻塞。

**三条主链**：

- **新产品（0→1）**：`启动新产品：{一句话}` → 立项书 → 确认 Go → 产品计划 → PRD → 画原型 → 交付 → 上市 → 复盘
- **迭代**：`产品计划` → `写 PRD` → `画原型` → `PRD 评审` → `排期` → `变更` → `UAT` → `发布` → `复盘`
- **展示/文档**：`准备演示：{受众/场景}` → 故事线/流程图 → 演示脚本 → Demo 检查单 → 材料 → 用户文档 → 彩排

有 `产品/产品计划.md` 后，说 **「继续 / 按产品计划执行 / 下一步 / 当前状态」**：按 §0 总控表从当前阶段续跑；`下一步` 只报动作，`按产品计划执行` 执行到下一个门。

落地通常只装本包。意图→包映射见根 README；若磁盘偶发多包并存，同会话只启用一包。

## 4. 自检

```text
产品规范/规则/tools/Test-Template.ps1
```

含 YAML 语法/schema（PyYAML；未装 python 时该项跳过并提示）。PRD 另跑 `python 规则/tools/validate_prd.py <PRD.md>`（元数据/16 节/Mermaid/ID/追溯/技术边界）。自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`产品档案.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；子代理、MCP 按需。
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `产品档案.md` §6（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。
- **MCP 配置落点**：只写宿主本地/用户级配置（路径以宿主官方文档为准）；禁项目内配置作规范入口。  
- **缺陷平台（可选）**：禅道/Jira/ONES 的 MCP/API 配置只写宿主本地/用户级配置；`产品档案.md` §7 只记 provider/凭据来源/适配定义；未配置走粘贴/export，不阻塞。
