# 产品规范 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（产品轨）**：声明式 `workflows/*.yaml` + 角色 `agents/*.yaml` + 规则 `规则/` + 内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）。  
主链：**新产品 0→1**（发现 → 立项 → 产品定义 → PRD → 交付 → 上市 → 复盘）与**迭代**（需求洞察 → 优先级/立项 → PRD → 评审定稿 → 排期 → 跟进/变更 → UAT → 发布 → 复盘）；**产品计划**（`产品/产品计划.md`）为总领单点，**§3.0【业务与变更简报】+本期差量表**为默认权威 Delta（阶段 1 定范围时写入）；独立「迭代变更摘要」仅仓外交接/版本归档/点名时按需生成。变更单含 §2.1 Now→Proposed（改已定稿基线）。**展示**（`showcase.yaml`）：受众 → 故事线/流程图 → 演示脚本 → Demo 环境 → 材料/用户文档 → 彩排。  
执行宿主（任意支持 AGENTS 的 AI 编码工具，要求见本文「宿主适配」节）按 YAML 步骤执行；步内实现路径交 AI（框架固定 · 局部自主）。  
**需求理解（产品核心职责）**：按 `技能/customer-needs-discovery/SKILL.md` + `规则/核心/澄清.md` **多问清需求、完善方案要点、并做理解→方案双确认**；每轮 1 问（或 2～3 互斥选项）；技术细节先给业务向建议请确认；未双确认不得入池承诺/写正式 PRD/定版本；未确认推断标「假设」。  
**体验纪律**：界面减法（删无决策价值文案/标签，删后不清楚改布局）、UX/DX/AX 三维同向；详见 `AGENTS.md` §0.2 第9条、`技能/ui-visual-design-system/SKILL.md` §1.3～1.4。

## 2. 目录

| 路径 | 作用 |
| --- | --- |
| `workflows/` | `new-product`（0→1）· `plan`（产品计划/路线图）· `prd`（洞察/立项/PRD/评审/需求交接）· `prototype`（设计策略/项目适配/IA/线框/视觉/高保真/评审/交接）· `showcase`（演示/介绍/用户文档）· `change`（受理与变更）· `defect`（缺陷平台）· `deliver`（排期/UAT/发布/复盘）· `handoff`（交接包/接收回执/变更通知/状态）· `onboard` · `skill-audit`（能力技能体检） |

| `规则/核心/` | `澄清.md`、`入口判定.md`、`验证规则.md`、`规则治理.md`、`维护.md`、`执行契约.md`、`文档质量标准.md` |
| `规则/协作/` | `协作与交接.md`、`子代理编排.md`、`角色契约.md` |
| `规则/缺陷/` | `缺陷平台协作.md`、`缺陷平台适配.md` |

| `规则/模板/` | 按生命周期分 8 组：`00-接入与治理` / `10-规划与需求` / `20-原型与设计` / `30-评审与变更` / `40-交付与验收` / `50-展示与文档` / `60-复盘与改进` / `90-交接与收尾`；先看 `规则/模板/模板索引.md` |
| `规则/tools/` | 包自检 `Test-Template.ps1`（YAML 语法/schema + 引用/锚点/流程引用/步标记/能力名/版本单点）+ `validate_workflow.py` + `validate_handoff.py`（交接包完整性） |
| `验证/` | PRD/评审/UAT/变更/回写门 `验证/Invoke-Gate.ps1`、检查矩阵、产物校验脚本；独立可复制 |

> 实例在项目根：`产品档案.md`（含 §3 产品规范要点——固定内联）、`activeContext.md`（含 `### 进行中` 快照）；全部产出统一在 **`产品/`**（产品计划、需求池、立项书、各版本 PRD/评审/受理/交付计划/变更单/UAT/GTM/原型/展示/复盘、`用户文档/`、`交接/`、`资料/`、`_归档/`）。  
> **交接**：**内容优先、包按需**——默认交自洽 PRD/设计/变更等主文档；HO 包仅多文件/正式签收/仓外/点名时先问后发。禁静默发包。有平台已回写不重复 BUG 包。多包同仓直读，禁转发对方 `资料/交接/`。
> **资料 vs 工作文档**：`产品/资料/` 只放外部输入（`{版本或主题}/` + `_通用/` + `资料/_归档/` + `资料索引.md`；禁 `项目文档/` 层、禁强制类型前缀扁平）；`产品/用户文档/` 放对外交付文档（快速开始/手册/FAQ/发布说明/培训）；`产品/产品计划.md`、`产品/需求池.md`、`产品/{版本或主题}/` 是工作文档（不回写资料）。入站先意图分析（T1～T9）；确认采纳且 S1/S2/S3 → 同批进 `资料/_归档/`。分类/覆盖对照/归档见 `规则/文档治理.md`。单包优先；主副本在原始资料根（推荐 `docs/`）；`产品/资料/` 放本包副本；放入≠自动跑他包。
> **可选联动（不强制）**：本包可独立落地。若项目同时启用其它包，PRD/立项书/产品计划可作为其输入；UAT 有测试报告/提测单则参考；工程部署由开发轨执行（如启用），未启用则由用户安排；复盘可合并；缺陷平台配置可复用开发/测试包同源值（`项目档案.md` §3/§4、测试包环境基线 §13）。输入缺失时提示一次，由用户提供/沿用现有资料，不阻塞。多包同项目时自动探测并共用原始资料根（推荐 `docs/`） 与 `activeContext.md`；不需要额外协作目录或合同文件，本包仍独立执行。  
> **协作交接**：PRD/原型/排期/变更/UAT/发布等节点可**建议**发包（REQ/DES/PLAN/CHG/UAT/REL）；须你确认后才生成。开发/测试未装包时接收方写负责人名。
> **产品缺陷处置**：测试直提→产品独立定性；开发评估单→产品复核五选一；产品判定后按来源指派开发/测试；处置单/新文档上传平台，三包不要求同目录。  
> **边界**：产品负责需求/规则/原型/验收；技术架构、技术栈、数据库/API/部署归开发轨（如启用）或由用户安排，产品不越界设计。  

### 2.1 文档分层（按需读）

| 层 | 位置 | 读法 |
| --- | --- | --- |
| 入口 | `AGENTS.md` | 每任务读 §0～§3；先路由再读当前 step |
| 路由 | `workflows/*.yaml` | 只读命中 workflow 的当前 step |
| 常驻规则 | `规则/门.md`、`规则/核心/验证规则.md`、`规则/核心/澄清.md`、`规则/读取索引.md`、`规则/文档治理.md` | 只读当前相关节 |
| 参考手册 | `规则/工作流.md`、`规则/协作/协作与交接.md`（标 `读取级别：参考`） | 只读当前 step/阶段节，禁止通读 |
| 技能 | `技能/<name>/SKILL.md` | 命中步才读；不命中不读 |
| 模板 | `规则/模板/模板索引.md` → 当前组 | 只读当前要填的一份 |
| 验证 | `验证/` | 收尾/过门时读；运行态写 `.gate/产品规范/` |

> 读取预算（目标，非硬上限）：核心必读 ≤3～4（`AGENTS.md` 当前相关节 + 当前 step YAML 块 + 当前 agent/当前关键产物）；方法层按读取索引「命中才读」；总量 ≤8k；复杂步可至 5 并在收尾 reads= 说明；不得为省预算跳过门/证据/红线。规则不是越多越稳，读全本会稀释当前 step 约束。

### 2.2 版本目录（新产品默认）

```text
产品/{版本或主题}/
├─ 01-需求与定义/     立项书、洞察、PRD、评审记录
├─ 02-原型与设计/     设计情境、IA、线框、高保真、tokens、工程化检查、设计评审、可用性、开发交接
├─ 03-变更与缺陷/     受理、变更单、产品缺陷处置
├─ 04-交付与验收/     交付计划、UAT、GTM
├─ 05-展示与材料/     展示需求、故事线、演示脚本、一页纸、Deck、检查单、反馈
└─ 06-复盘/           复盘
```

按需建目录，**无内容不建空目录**。旧项目保留原路径，在 `产品档案.md` 记录实际路径；说「重新接入」时再迁移。

## 3. 上手（快速开始）

1. 复制整个 `产品规范/` 到项目根下一层  
2. 挂载：按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 把引导语句补入项目根 `AGENTS.md`（追加不覆盖）  
3. 对 AI 说「接入产品规范」→ 生成 `产品档案.md` 与 `activeContext.md`、确认入库策略、打标  
4. 之后直接说口令：「收集需求」「产品计划」「写 PRD」「设计简报」「画原型」「PRD 评审」「排期」「需求变更」「UAT」「发布」「准备演示」「用户手册」「发布说明」「复盘」「资料收取」「资料整理」「资料归档」「文档巡检」「清理临时文件」  
4.1 **不用口令**：任意自然语言描述需求/反馈/规划即可；AI 按 `规则/核心/入口判定.md` 抽五元组→意图类→状态修正，不抠固定措辞；首条 `route`/`reason`。单条默认受理、批量走洞察、空白新品走 0→1；判断错可一句纠正。  
5. 也可以直接把需求/问题/缺陷发来（对话或文档）：AI 走 `change` 受理 → 分诊 → 处置 → 联动更新，最后给出受理单、变更单（如适用）、最新 PRD/计划/UAT 与开发/测试回执。  
6. 已配置禅道/Jira/ONES：说「拉取我的产品缺陷」→ 读详情/备注/附件 → 分析 → 回写备注/附件/状态/指派；未配置则粘贴/导出，不阻塞。

**三条主链**：

- **新产品（0→1）**：`启动新产品：{一句话}` → 立项书 → 确认 Go → 产品计划 → PRD → 画原型 → 交付 → 上市 → 复盘
- **迭代**：`产品计划` → `写 PRD` → `画原型` → `PRD 评审` → `排期` → `变更` → `UAT` → `发布` → `复盘`
- **展示/文档**：`准备演示：{受众/场景}` → 故事线/流程图 → 演示脚本 → Demo 检查单 → 材料 → 用户文档 → 彩排

有 `产品/产品计划.md` 后，说 **「继续 / 按产品计划执行 / 下一步 / 当前状态」**：按 §0 总控表从当前阶段续跑；`下一步` 只报动作，`按产品计划执行` 执行到下一个门。

落地通常只装本包。意图→包映射见根 README；若同项目装多个包，三包自动探测并共享资料/上下文，不需要额外协作目录；一次会话只执行一个包的 workflow。

## 4. 自检

```text
产品规范/规则/tools/Test-Template.ps1
```

含 YAML 语法/schema（PyYAML；未装 python 时该项跳过并提示）。PRD 另跑 `python 规则/tools/validate_prd.py <PRD.md>`（元数据/16 节/Mermaid/ID/追溯/技术边界）。自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`产品档案.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；子代理（分片/核验，按 `规则/协作/子代理编排.md` 阈值取档）、MCP 按需。  
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `产品档案.md` §6（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。  
- **体检能力**：口令「体检能力」等 → `workflows/skill-audit.yaml`：对照项目（或「通用优化技能」）检查能力 + 随包技能；确认后可就地改本包技能/能力。
- **MCP 配置落点**：只写宿主本地/用户级配置（路径以宿主官方文档为准）；禁项目内配置作规范入口。  
- **缺陷平台（可选）**：禅道/Jira/ONES 的 MCP/API 配置只写宿主本地/用户级配置；`产品档案.md` §7 只记 provider/凭据来源/适配定义；未配置走粘贴/export，不阻塞。
