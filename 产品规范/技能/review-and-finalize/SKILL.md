# 评审与定稿（技能 · 随包生效）

> 用于：review 步（`confirm_prd` 定稿门）。只报缺口、不替写；结论与记录同源。

## 1. 评审清单

| # | 项 | 判定 |
| ---: | --- | --- |
| 1 | 元数据 | doc_id/status/version/owner/updated 齐 |
| 2 | 摘要/目标/指标 | 指标、观测窗口、基线 |
| 3 | 背景/依据 | 来源+日期；无编造 |
| 4 | 用户/场景 | 角色/任务/环境清楚 |
| 5 | 范围/边界 | 做/不做/暂缓 |
| 6 | 功能 F | 编号、优先级、价值、权限、AC |
| 7 | 主流程图 | Mermaid；判断是/否；异常路径 |
| 8 | 状态机 | Mermaid + 状态表；非法跃迁/终态 |
| 9 | 权限矩阵 | 角色×操作×数据域 |
| 10 | 字段来源 | 类型/必填/范围/默认/来源/校验 |
| 11 | 校验规则 R | 比较对象/失败表现/阻断/提示 |
| 12 | 异常/边界 | 空/失败/重复/并发/超限/越权/终态 |
| 13 | NFR | 目标/约束/验收方式/待确认 |
| 14 | 埋点/指标 | 事件/触发/属性/指标/窗口 |
| 15 | 验收 A/AC | 每条 F 有 AC；异常/边界 ≥1 |
| 16 | 追溯矩阵 | F→R→A→AC→原型→测试→版本 无空链 |
| 17 | 决策 Q/C | 待确认有责任人/期限；已确认有依据 |
| 18 | 评审误区 | 本项目误区已列 |
| 19 | 引用抽验 | 随机 2～3 条打开核对 |
| 20 | 技术边界 | 未写架构/技术栈/DB/API/部署 |

## 2. 四个硬门（任一不过 → 不可定稿）

1. **元数据与证据**：元数据齐；关键结论有来源。
2. **图与状态**：至少 1 张主流程图 + 1 张状态图；判断是/否；异常可见。
3. **可测与追溯**：每个 F 有 AC；每个 R 有 A；追溯矩阵无空链。
4. **未知标注**：TBD 有责任人与期限；无编造；技术架构未越界。

## 3. 缺口分级与结论

- **阻断**：无法开发/验收（无 AC、无状态机、追溯断链、技术架构越界）。
- **重要**：会返工/歧义（权限/边界/字段来源缺失）。
- **建议**：文案/体验细节。
- 结论只有：`通过（可定稿）` ｜ `需修后定稿`；不写「基本通过」。

## 4. 流程纪律

- 需修 → 回 prd 步修订；同回合重审 ≤1 次；不过如实上报。
- 评审记录落 `产品/{版本或主题}/评审-{主题}-{yyyyMMdd}.md`；结论与记录同源。
- 定稿后才允许排期；实质变更须重审后才能恢复「已定稿」。

## 5. 质量评分卡（12 项，0～2 分）

完整 / 图 / 可测 / 追溯 / 字段来源 / 规则 / 权限 / 异常边界 / NFR / 指标 / 决策台账 / 技术边界。

> 阻断项必须 2 分；总分 ≥20/24 且无阻断才可定稿。

## 6. 评审边界

- 不替写 PRD、不改正文；不追文风。
- 业务口径拿不准 → 列问题请 PM 确认；不脑补。
- 无原型/数据 → 按文本评，证据缺口记「待补」。
