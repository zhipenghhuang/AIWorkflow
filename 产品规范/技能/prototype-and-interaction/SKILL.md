# 原型与交互（技能 · 随包生效）

> 用于：`prototype` 工作流；`prd` 的原型条件步。  
> 核心：**先项目情境，再结构，再视觉；每页有状态；原型可点击、可评审、可交接。**

## 0. 项目情境与参考基准（不读项目资料不开画）

- 读：PRD（F/A/AC）、产品计划、UAT/验收、现有系统截图、品牌/术语、约束（PC/手机/打印/离线/权限/数据量）。
- 写进 `设计情境-{主题}.md`：
  - 用户/角色、核心任务、频率、环境/设备、数据量、权限、合规；
  - 设计策略与项目适配：产品定位、与现有系统的关系、要借什么/不借什么、明确不做什么；差异化只在产品定位需要时写；
  - 设计原则 3～5 条（如“高密度后台 / 手机采集 / 打印优先”）；
  - 2～3 个竞品/同类系统/设计规范参考（链接+日期），写“借什么/不借什么”；
  - 交付等级：概念 / 线框 / 高保真 / 可交接；交接必须到“可交接”级，并说明开发可优化边界；
  - 覆盖目标：PRD F/A/AC → 页面/路由/状态。
- 可选能力：design-intelligence / browser-mcp / ui-generation；未装=按本技能。

## 1. 信息架构（IA）

- 站点地图 / 导航层级；页面清单：页面 / 目标 / 入口 / 主操作 / 出口 / 角色权限。
- **覆盖矩阵**：PRD F/A/AC → 页面/路由/状态；缺页面=阻断。
- 关键流程：主路径 + 异常路径；跨页面跳转与返回。
- 范围：本期做 / 不做；桌面 / 移动适配策略。
- 约束：角色与数据域（本人/部门/全部）；未定义权限标「待定」。

## 2. 线框（低保真）

- 区块：导航 / 标题 / 筛选 / 内容 / 操作 / 反馈。
- 层级：一屏一个主任务；主操作唯一且醒目；次要操作降级。
- 标注：点击去哪、校验规则、空态、加载、错误。
- 工具：`规则/模板/20-原型与设计/原型脚手架.html` 起步；先灰度结构，不定视觉。

## 3. 状态矩阵（每页必填）

| 状态 | 表现 | 文案 | 操作 |
| --- | --- | --- | --- |
| 空/首次 | 说明 + 引导 | 为什么空、下一步 | 主操作 |
| 加载 | 骨架/进度 | 不闪跳 | 可取消（长任务） |
| 失败 | 原因 + 重试 | 说清怎么解决 | 重试/返回 |
| 成功 | 反馈 + 下一步 | 结果可见 | 继续/查看 |
| 禁用 | 灰显 + 原因 | 为什么不能点 | 解锁条件 |
| 无权限 | 申请/联系 | 缺什么权限 | 申请/切换账号 |
| 边界 | 超长/重复/并发/断网 | 具体限制 | 截断/去重/重试 |

> 状态矩阵逐页落到高保真；评审时逐项核，缺主状态=阻断。

## 4. 数据、路由与持久化

- 数据模型：实体/关系/字段；seed 示例数据；重置方式；真实数据脱敏。
- 路由/导航：页面/路由表、历史/返回、深链、未保存提醒；无死路。
- 演示/原型数据与当前 PRD/构建一致；模拟能力（OCR/AI/支付）必须标注“模拟”。

## 5. 交互规则

- 点击 / 悬停 / 聚焦 / 键盘；提交 / 取消 / 撤销；危险操作二次确认。
- 校验：即时或提交时；错误定位到字段；文案说“怎么改”。
- 反馈：loading、toast、inline error、成功页；不要只靠颜色变化。
- 破坏性操作：确认 + 可撤销/回收站；不可逆操作必须写明。

## 6. 文案（减法优先）

- 删除：无决策价值的标语/口号、重复说明、副标题/眉题、装饰性标签、说明书式段落。
- 保留：操作动词、状态/结果、风险/不可逆、金额/单位/权限/合规、错误原因/恢复路径、空态下一步。
- 删后用户仍不知道「这是什么/该做什么/下一步」→ 改布局/层级/分组/渐进披露/默认值/就地提示/组件选择；不得把说明加回来。
- 按钮 = 动词；标题 = 用户语言；空态 = 解释 + 行动；错误 = 原因 + 解决。
- 禁止「系统错误，请联系管理员」兜底，除非确实无解。
- 同一动作在全站用同一个词（保存/提交/确定不混用）。

## 7. 响应式、打印与无障碍

- 断点：手机 / 平板 / 桌面；触控目标 ≥ 44px；窄屏表格有替代（卡片/横向滚动）。
- 手机必须能完成主任务；不是电脑页缩小。
- 单据/报表类：A4 打印/导出 + 打印门槛（未通过核对不得正式打印）。
- 无障碍：语义 HTML、label、alt、焦点可见、对比度 ≥4.5:1、键盘可达、ARIA 必要；留证据（截图/检查结果）。

## 8. 开发交接与版本

- 用 `规则/模板/20-原型与设计/开发交接模板.md` 落 `开发交接-{主题}.md`：组件/状态/交互/tokens/响应式/无障碍证据/验收对照，另写**设计意图、必须保留、可优化、未提供、需开发决策**；标注「原型≠生产代码」。
- 版本元数据：原型版本、PRD 版本、日期、变更记录。
- 回链 PRD §14 追溯矩阵「原型/页面」列；未过设计评审/可用性走查（`confirm_prototype`）不交开发。
- 开发如需补充设计：先保留设计意图；开发只能改“可优化”项，重大偏离回产品确认并更新交接版本。

## 9. 可用性走查

- 3～5 个关键任务：任务完成/步数/卡点/错误；Nielsen 10 启发式。
- 问题分级（阻断/重要/建议）+ 证据；需修回高保真（同回合≤1）。
- 无真实用户时标注「内部走查」，不冒充用户测试结论。

## 10. 质量评分卡（12 项，0～2 分）

情境贴合 / 覆盖完整 / IA 导航 / 交互反馈 / 状态完整 / 数据真实 / 响应式 / 无障碍 / 视觉与设计系统 / 打印导出 / 可用性 / 版本交接。

> 阻断：缺项目情境、覆盖矩阵断链、主页面缺状态、手机不可完成主任务、无 a11y 证据、单据不可打印、无版本/交接。  
> 通过：≥20/24 且无阻断。  
> 三维体验为横向门：UX（用户）/DX（开发实施）/AX（AI 解析）任一净退化 → 需修，不计分。

## 11. 反模式

- 通用模板套所有项目；只画主路径；状态缺失；标注含糊；组件不一致；过度装饰；忽略权限/空态；把高保真当生产代码。
- 用大段说明文字弥补布局/层级问题；保留无决策价值的标语/副标题/装饰标签。

## 12. DoD

- 项目情境/用户/场景/约束清楚；设计策略能解释“为什么适合”。
- 覆盖矩阵无断链；主页面状态齐（空/加载/错误/权限/极端）。
- 手机可完成主任务；a11y 证据齐；单据可打印（如适用）。
- 版本/交接/设计意图/必须保留/可优化/需决策清楚；原型≠生产代码。
