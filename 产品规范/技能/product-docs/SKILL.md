# 产品用户文档（技能 · 随包生效）

> 用于：`showcase` 的 docs 步；也可单独口令「用户手册 / 快速开始 / FAQ / 发布说明 / 培训材料」。  
> 原则：**按任务写，不按功能清单写；截图/步骤与当前构建一致；不写未发布能力。**

## 1. 文档类型

| 文档 | 读者 | 结构 | 长度 |
| --- | --- | --- | --- |
| 快速开始 | 新用户 | 5 分钟完成首个任务 | 1～2 页 |
| 用户手册 | 日常用户 | 任务章节 + 操作步骤 + 截图 | 按模块 |
| FAQ | 用户/客服 | 高频问题 + 解决步骤 | 1 页起 |
| 发布说明/Changelog | 客户/用户 | 新增/改进/修复/升级步骤/已知问题 | 1 页 |
| 培训材料 | 内部/客户 | 学习目标 + 演示 + 练习 + 检查 | 按场次 |

## 2. 写作顺序

1. **读者与任务**：谁、什么场景、要完成什么、成功标准。
2. **前置**：账号/权限/数据/环境。
3. **步骤**：编号、一步一动作、位置 + 操作 + 预期；截图只放关键步。
4. **异常/FAQ**：常见错误、原因、解决。
5. **下一步**：相关任务/支持入口。

## 3. 快速开始（5 分钟）

- 只选 1 个核心任务，从登录到看到结果。
- 最多 5～7 步；每步一句；配 1～2 张关键截图。
- 结尾给“接下来做什么”和帮助入口。

## 4. 用户手册（任务制）

- 按用户任务分章，不按数据库/代码模块分章。
- 每章：目标 → 前置 → 步骤 → 预期 → 异常 → 相关任务。
- 术语与产品界面一致；同一动作全站同一个词。
- 版本变化：只写现行有效；旧版归档。

## 5. FAQ / 故障

- 问题用用户原话；答案先结论后步骤。
- 能自助解决给步骤；不能则给支持入口/SLA。
- 不把内部错误码、堆栈、内部路径写给用户。

## 6. 发布说明 / Changelog（客户版）

| 区块 | 内容 |
| --- | --- |
| 本次亮点 | 用户价值，不是功能名 |
| 新增 | 能做什么 + 入口 |
| 改进 | 体验/性能/稳定性 |
| 修复 | 用户可感知的问题 |
| 升级/兼容 | 需要用户做什么 |
| 已知问题 | 影响 + 规避 |
| 支持 | 联系方式/文档 |

- 不写 commit、内部工单、技术实现、未发布功能。
- 与 UAT/GTM/构建版本对齐；数字可回查。

## 7. 质量检查

- 非作者按文档能完成任务；
- 截图/按钮/路径与当前构建一致；
- 无内部术语/密钥/真实 PII；
- 版本、日期、适用范围清楚；
- 有反馈入口。

## 8. DoD

- 按用户任务组织；非作者能按文档完成首个任务。
- 截图/按钮/路径与当前构建一致；版本/适用范围/更新日期清楚。
- 无内部术语/密钥/真实 PII；错误/限制/前置条件写清。
- FAQ 覆盖高频问题；有反馈入口；发布说明与版本记录一致。
