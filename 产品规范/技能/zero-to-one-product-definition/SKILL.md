# 0→1 产品定义与验证（技能 · 随包生效）

> 用于：`plan` 的目标/路线图、`new-product` 的发现/立项/定义步。  
> 核心：**先验证问题，再定义方案；先立项，再写全量 PRD。**

## 1. 先判断类型

| 类型 | 起点 | 首要风险 | 先做什么 |
| --- | --- | --- | --- |
| 0→1 新产品 | 想法 / 机会 | 做了没人要 | 问题与市场验证、立项书 |
| 现有产品迭代 | 用户反馈 / 指标 | 做错优先级 | 需求池、产品计划、PRD |

0→1 阶段**不要**直接写全量 PRD；先过 `confirm_go`。

## 2. 研究（证据优先）

- **用户**：访谈问过去行为与代价，不问“你会不会用”；样本写清（角色/数量/日期）。
- **市场**：TAM/SAM/SOM 只要量级与依据；拿不到就写「待验证 + 验证方式」。
- **竞品/替代**：官网、试用、公开资料；写链接 + 日期；禁凭印象。
- **数据**：注明口径、时间窗、样本；真实用户信息脱敏。

## 3. 商业论证（粗略但诚实）

- 收入模式 / 定价 / 客单价；成本（研发/运营/获客）；粗略 ROI / 回收期。
- 自建 / 采购 / 合作的选择理由。
- 算不清就列关键假设与验证方式，不编数字。

## 4. MVP 与实验

- 找**最危险的假设**（用户是否需要 / 是否愿付费 / 能否交付）。
- 设计最小验证：访谈 / 原型 / 预售 / POC / 灰度；写成功标准与时间盒。
- 结果三选一：继续（Go）/ 补验证（Hold）/ 停止（Kill）；记录依据。

## 5. 产品定义（立项通过后）

- 愿景一句话、目标用户、价值主张、MVP 范围、不做什么。
- 成功指标：北极星 + 1～2 个辅助指标；基线 / 目标 / 观测窗口。
- 路线图：Now / Next / Later；每项有证据、依赖、时间窗。

## 6. 反模式（常见坑）

- 方案先行：先想功能，再找用户验证。
- 过早完美：市场没验证就写几十页 PRD。
- 无证据的“用户都说好”；把个别反馈当普遍需求。
- 范围蔓延：MVP 什么都想要；没有“不做”清单。
- 立项即终点：没有验证计划与退出标准。

## 7. 交付给下游

- 立项书 → `产品/{主题}/01-需求与定义/立项书-{yyyyMMdd}.md`
- 产品计划 → `产品/产品计划.md`（总控表 + 路线图）
- 通过后：`技能/prd-writing/SKILL.md` 写 PRD；`技能/requirement-discovery-and-prioritization/SKILL.md` 维护需求池。

## 8. Go / Hold / Kill 判据

| 结论 | 至少满足 | 下一步 |
| --- | --- | --- |
| Go | 问题真实且有证据；目标用户/场景清楚；MVP 可在约束内验证；风险有应对 | 进入产品定义/计划 |
| Hold | 问题可能真实但证据不足；关键假设未验证 | 列验证动作/责任人/截止，限期复审 |
| Kill | 问题不成立/无可行路径/成本收益不成立/合规不可过 | 记录原因、证据、可复用资产，归档 |

- 任一结论都必须写：依据、反证、未验证假设、复审点；禁止只写“感觉可以”。

## 9. 自检 4 项

- [ ] 问题/用户/场景/替代/代价有证据，不是先想功能。
- [ ] 最危险假设已列，验证动作/责任人/截止明确。
- [ ] MVP 有“不做”清单与退出/复审标准。
- [ ] Go/Hold/Kill 结论有依据、反证与复审点。
