# UAT 与复盘（技能 · 随包生效）

> 用于：deliver 的 uat / release 步（`confirm_release`）。

## 1. 验收准备

- 环境/构建/账号角色/数据就绪；验收范围 = PRD §13 验收场景与 AC；多需求版本引用迭代方案验收矩阵。
- 先确认验收资产分层：`QA-AC` 由测试执行，`REL-AC` 由 UAT/发布执行；开发任务不包办验收矩阵。
- 逐条对照：`验收编号 → 结果（通过/不通过/带条件）→ 证据`；
- 每条记录含：场景 ID / 构建环境 / 角色及数据单号 / 执行时间/时区 / 实际结果 / 结论 / 证据或缺陷号；结论只能是“通过/失败/未执行”。
- 证据钉观测点（截图/接口字段/DB 对账），不写「已验证」空话；数量/金额用独立计算，期限用受控时钟。

## 2. 缺陷判定（产品 vs 实现）

| 类型 | 判定依据 | 去向 |
| --- | --- | --- |
| 实现缺陷 | 与 PRD/设计不一致（未做/做错/缺段） | 开发修，修后回归 |
| 产品缺陷 | 实现了 PRD，但口径本身不合理/有风险 | 转 `change` 受理：产品决策（立即修/下版/不修），立即修走变更单 |
| 非缺陷 | 理解偏差/数据问题 | 澄清并记录 |

判定必须有依据（PRD 原文/设计对照），禁拍脑袋。

## 3. 验收结论与发布门

- 结论：`通过` ｜ `不通过` ｜ `带条件通过`；
- 带条件：列遗留项、影响、责任人、**接受人**（谁同意带条件上线）；
- 发布前置：回滚预案（触发条件/步骤）、公告、客服话术、监控指标、发布窗口；
- `confirm_release`：出示要点确认后才发；**未过 UAT 不发布**。

## 4. 复盘（发布后）

- 目标 vs 实际：逐指标对照（含观测窗口与基线）；
- 数据观察：核心指标/异常/用户反馈（来源+日期）；
- 根因：流程/需求/技术/协作（不是「大家不够努力」）；
- 改进项 → 回需求池（责任人+期限），复盘才算闭环。

## 5. 常见坑

- 验收只走「主路径」不看异常/权限；
- 把「实现缺陷」记成「产品缺陷」甩锅；
- 带条件通过没有接受人（上线后无人认账）；
- 复盘只写成绩不写根因，改进项无人跟进。
