# 产品落地文档评审（技能 · 随包生效）

> 用于：PRD / 产品计划 / 迭代范围 / 设计评审与开发交接等**将约束开发·测试实施**的产物。  
> 门：`select_review_mode` →（自行通过｜AI 独立评审）→ 必要时 `confirm_*` 定稿授权。  
> 不替代 `review-and-finalize` 的 PRD 四硬门/评分卡；本技能=**方式选择 + 多产物量规 + 独立性**。

## 1. 必须先停问（不可跳）

落地文档写完、宣称「可评审/可定稿/可交开发」前，**STOP** 出示：

```text
【评审方式】产物={路径/短名}｜级别={P0～P3}
请二选一：
A. 自行评审通过 — 你过目后放行；AI 只留结构自检摘要，review_status=HUMAN_APPROVED
B. AI 独立评审 — 另起评审身份按量规审；产出评审记录；review_status=AI_REVIEWED（通过后仍可再定稿）
（回复 A 或 B；默认可写建议，但不得自选执行）
```

- 同会话同产物只问一次；用户已点名「PRD 评审 / AI 评审」→ 视为 B；点名「我审/自行通过」→ 视为 A。  
- **A 不免除**可测性/追溯等硬红线；用户对放行负责。  
- **B** 评审者 ≠ 作者；禁读作者自评；禁改正文。

## 2. 强制适用（企业高标准）

> **是否合理**：只问「约束下游开发/测试/准出」的落地件；不问过程草稿与纯文案。选 B 时须主动找矛盾/不可测/范围漂移（不只过评分卡）。

| 产物 | 何时必须选模式 |
| --- | --- |
| PRD（P2+） | 写完后 / 定稿前；P0/P1 light 可默认 A 并声明 |
| 产品计划（首版或范围·指标·版本实质变） | publish 前或确认后补评 |
| 迭代/版本范围（含里程碑） | 并入计划或单独范围确认时 |
| 设计评审 + 开发交接 | 交开发前 |
| 交付计划（排期/里程碑/测试窗口） | 发 PLAN 交接包前 |
| 实质变更后的 PRD | change/defect 重审 |

可不强制：纯文案 P0、内部答疑、C0 澄清。
## 3. 量规（按产物裁剪）

### 3.1 PRD（沿用 `review-and-finalize`）

四硬门 + 12 项评分卡 ≥20/24 无阻断；来源可追溯；假设不得当事实。

### 3.2 产品计划 / 迭代方案

| 轴 | PASS | FAIL |
| --- | --- | --- |
| 目标可证伪 | O/KR 有基线·目标·窗口 | 空泛「提升体验」 |
| 范围边界 | 本期做/不做 ≥2 条排除 | 无反范围 |
| 依据 | 需求池/证据可回查 | 竞品/领导偏好直接排期 |
| 里程碑可执行 | 设计/开发/提测/UAT/发布有依赖 | 只有日期无入口条件 |
| 风险显式 | 依赖/产能/合规列出 | 静默假设全就绪 |

### 3.3 设计/原型交接

IA 覆盖 PRD F/AC；状态矩阵（空/载/错/成功）；一致性；a11y 基础；开发交接字段齐；12 项评分卡。

### 3.4 交付计划

范围 ⊆ 已定稿 PRD；里程碑有入口条件；开发/测试窗口不冲突；依赖与风险显式；无「口头排期」。

## 4. 结论与留痕

| 模式 | 留痕 | 结论词 |
| --- | --- | --- |
| A 自行 | 收尾写「HUMAN_APPROVED + 用户确认」；可选短笺 | 自行通过（可定稿/可交接） |
| B AI | `评审-{主题}-{yyyyMMdd}.md`；PRD 跑 `-Mode review` | 通过（可定稿）｜需修后定稿 |

缺口分级：阻断 / 重要 / 建议；严重度表输出。需修 → 回作者修订 → 同回合重审 ≤1。
