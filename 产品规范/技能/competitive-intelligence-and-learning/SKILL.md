# 竞品情报与学习模仿（技能 · 随包生效）

> 用于：`prd.discover`（口令「竞品分析」/0→1 市场验证）、`prd.benchmark`（口令「竞品对标」）、`new-product.discover`、`prototype.context`（设计借鉴时）。  
> **目标**：把同类竞品拆清楚，并把可学习点变成**可验证的本产品决策**——不是抄功能清单，也不是无视市场。  
> **边界**：不写全量 PRD；不替用户定差异化终裁；澄清格式仍认 `规则/核心/澄清.md`。  
> **与相邻技能**：问题还原先 `customer-needs-discovery`；入池/优先级用 `requirement-discovery-and-prioritization`；0→1 立项用 `zero-to-one-product-definition`；体验借鉴用 `prototype-and-interaction` / `ui-visual-design-system`。

## 0. 两档模式（强制先选）

| 档 | 何时用 | 口令/入口 | 产出 | 入池纪律 |
| --- | --- | --- | --- | --- |
| **S 选择性学习** | 0→1、战略、新品定位、点名「竞品分析」 | `prd.discover` / `new-product.discover` | `竞品分析-*.md` | 借鉴项须回绑本产品问题；验证后才承诺版本；**不得**把竞品功能直接当客户需求 |
| **P 对标跟进** | 已有产品线迭代、点名「竞品对标」/功能差距/parity | `prd.benchmark` | `竞品对标-*.md` | 差距项可进需求池**候选项**（来源=`竞品对标`）；排进版本仍须价值/成本初判 + 用户确认范围；证据可只用公开资料+日期 |

- 分不清 → 有产品线且要「我们也要有/对一下功能」→ **P**；空白新品/要定位差异化/Go 决策 → **S**。  
- 同会话可先 S 再 P，不得混成一份无模式标注的文档。

## 1. 对象清单（开拆前）

| 项 | 要求 |
| --- | --- |
| 本产品定位一句话 | 谁 / 什么场景 / 什么结果（可来自档案/计划/用户确认） |
| 竞品集合 | 直接竞品 2～5 + 替代方案（Excel/人工/外包）≥1；写选取理由 |
| 资料来源 | 官网/定价页/帮助中心/试用/应用商店评/公开案例；每条 **链接+日期**；禁凭印象 |
| 能力 | `browser-mcp` 已装则打开页面取证；未装=用户粘贴/截图/链接，不阻塞 |

**扇出**（`规则/协作/子代理编排.md` §2）：≥4 独立竞品/来源 → 按来源只读扇出，返回证据表 ≤30 行；定位/借不借/对标结论**集中**由主 agent 写。

## 2. 模式 S — 选择性学习（分析 → 借/改编/不借 → 验证）

### 2.1 拆解维度（按需全做；缺维写「未覆盖+原因」）

| 维 | 看什么 | 记什么 |
| --- | --- | --- |
| 定位 | 声称服务谁、解决什么 | 一句话 + 证据链接 |
| 用户与场景 | 公开案例/评价里的真实用法 | 场景摘要 |
| 核心流程 | 完成关键任务的步骤数/门槛 | 流程要点 / 摩擦点 |
| 功能簇 | 模块级能力（非按钮级流水账） | 有/弱/无 + 备注 |
| 体验 | 密度、引导、空态、移动/打印 | 可借鉴交互模式 |
| 定价/包装 | 套餐、限免、增购 | 价格带（来源+日期） |
| 获客/信任 | 渠道、社会证明、合规宣称 | 可观察事实 |
| 明显短板 | 差评/缺失/过度复杂 | 机会点 |

### 2.2 学习决策表（每条必填）

| ID | 观察（竞品做法） | 决策 | 对本产品的改编 | 回绑的问题/机会 | 验证方式 | 入池建议 |
| --- | --- | --- | --- | --- | --- | --- |
| L-01 | `{…}` | **借** / **改编** / **不借** | `{怎么用在本产品}` | `{谁/场景/问题}` | `{访谈/原型/数据/试用}` | 入池候补 / 仅设计参考 / 丢弃 |

- **借**：交互/信息结构可近似复用；仍须写「为何适合本用户」。  
- **改编**：学意图不学外形；写清改哪几处。  
- **不借**：写原因（不合定位/合规/成本/已有更好替代）。  
- 禁止空表「全面对标后抄齐」；S 档至少产出 **3 条**学习决策（可含不借）。

### 2.3 差异化一句话

- 相对直接竞品：我们**坚持**什么、**放弃**什么、**独特**什么（各 ≤1 句）。  
- 无差异化也可：写「效率工具，优先一致可预测」+ 依据。  
- 差异化主张进立项书 §3 / 产品计划，**须用户确认**后才当已定定位。

### 2.4 落盘与下游

- 模板：`规则/模板/10-规划与需求/竞品分析模板.md`  
- 路径：`产品/{版本或主题}/01-需求与定义/竞品分析-{主题}-{yyyyMMdd}.md`  
- 资料原件：`产品/资料/`（入站纪律见文档治理）；分析正文在工作区。  
- 下游：洞察综合引用 L-xx；需求池条目带来源 `竞品分析` + 回绑问题；设计情境引用「借/不借」。

## 3. 模式 P — 对标跟进（矩阵 → 差距候选项）

### 3.1 对标矩阵

| 能力项 | 本产品 | 竞品A | 竞品B | 差距 | 客户相关信号 | 建议 |
| --- | --- | --- | --- | --- | --- | --- |
| `{模块/能力}` | 有/弱/无/不适用 | 有/弱/无 | … | 领先/持平/落后 | 工单/销售/无 | 候选项 / 观察 / 不做 |

- 能力项按**用户可感知结果**命名（「导出合规报表」），不按竞品菜单原文堆砌。  
- 本产品「无」且 ≥1 竞品「有」→ 默认进差距清单。  
- **客户相关信号**：有则提高优先级建议；无亦可进候选项，标 `证据=竞品公开+日期`。

### 3.2 差距 → 需求池（放宽但仍可追溯）

每条候选项最少字段：

```text
来源: 竞品对标 | 竞品名+链接+日期
问题陈述: 用户在{场景}需要{结果}（可先写「对标假设」）
现有替代: 本产品现状 / 手工绕过
建议方案要点: 一句话
初判: 价值/成本/风险
状态: 候选项（未承诺版本）
确认: 待确认
```

- **可直接入池为候选项**，不要求先做完完整客户访谈。  
- **不得**因对标自动写成「已立项/已排期」；进版本仍走 `confirm_scope` / 计划范围确认。  
- 用户明确「按对标清单排进本期」→ 出示差距 Top N + 成本粗估，确认后改确认列。

### 3.3 落盘

- 模板：`规则/模板/10-规划与需求/竞品对标模板.md`  
- 路径：`产品/{版本或主题}/01-需求与定义/竞品对标-{主题}-{yyyyMMdd}.md`  
- 同步更新 `产品/需求池.md` 候选项（去重键=能力项+问题域）。

## 4. 与澄清 / 双确认

| 场景 | 要求 |
| --- | --- |
| S → 改变定位/MVP/对外差异化主张 | 须 `confirm_understanding` 或立项门；复述含竞品结论与借/不借 |
| S → 仅资料沉淀、不影响范围 | 可 notify；结论标参考 |
| P → 入候选项 | 可无整包双确认；池内标待确认 |
| P → 承诺版本/写 PRD | 恢复完整澄清：谁/场景/问题或显式接受「对标驱动假设」 |

## 5. 设计侧学习（与原型衔接）

- `prototype.context`：优先引用已有竞品分析/对标的「借/改编」行；无则本步补 2～3 参考 + 借/不借。  
- 视觉/交互只花一次大胆记忆点；B 端默认一致可预测（见 `ui-visual-design-system`）。  
- 开发交接须列「来自竞品借鉴且必须保留」的交互，避免实施时被改没。

## 6. 反模式（出现即停）

- 把竞品功能清单原样粘成需求池「Must」。  
- 无链接/无日期的「业界都有」。  
- S 档只写赞美或只写攻击，无借/改编/不借表。  
- P 档自动排期或自动定稿 PRD。  
- 用竞品差异化话术冒充已验证的客户需求。  
- 只对标 UI 皮，不看关键任务流程与定价包装（S 档）。  
- 编造市场份额/下载量/客户数。

## 7. 红旗

1. 结论段无任何 URL/日期。  
2. 「学习模仿」结果 = 100% 功能对齐，无「不借」。  
3. 对标矩阵能力项 >30 且无优先级/客户信号列。  
4. 与当前产品定位矛盾的「借」未写改编理由。  
5. 口令是「竞品分析」却只交了对标矩阵（或相反）且未改模式标注。

## 8. 验证 / DoD

**S**

- [ ] 竞品集合与选取理由齐；每源链接+日期  
- [ ] ≥3 条学习决策（借/改编/不借）且回绑问题  
- [ ] 差异化或「不做差异化」有依据  
- [ ] 落盘路径正确；影响定位/范围的结论已请用户确认  

**P**

- [ ] 对标矩阵含本产品列与 ≥2 竞品列  
- [ ] 落后项进入需求池候选项或显式「观察/不做」  
- [ ] 无自动「已排期」；进版本有确认痕迹  
- [ ] 落盘路径正确  

## 9. 参考（方法内化）

- Strategic competitive analysis：定位/替代/差异化，而非功能刷清单。  
- Jobs-to-be-Done + 竞品：对标用户要完成的任务。  
- Good / Better / Best 包装与定价页公开信息。  
- 设计系统实践：借模式不借皮肤；借/不借写明。
