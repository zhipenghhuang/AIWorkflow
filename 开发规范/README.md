# 开发规范 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（开发轨）**：声明式 `workflows/*.yaml` + 角色 `agents/*.yaml` + 红线 `规则/` + 内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）+ 文档治理（需求/方案/清单/提测/发布/UAT/复盘统一落位、索引、归档；根 `CHANGELOG.md` 产品发版史 + `开发/工作日志.md` 里程碑 + 发布说明按版本）。  
执行宿主（任意支持 AGENTS 的 AI 编码工具，要求见本文「宿主适配」节）按 YAML 步骤执行；步内实现路径交 AI（框架固定 · 局部自主）。  
**产品文档解析**：输入含 PRD/迭代方案/文档/页面原型/截图时，先按 `技能/product-doc-analysis/SKILL.md` 产出需求理解包——**§0【业务与变更简报】+【本期差量表】置顶**（人类快查本期增/改/删），下钻含引用、冲突、GAP、假设与置信度；确认门主屏出示 §0。再按 `规则/核心/澄清.md` 先分析、只问意图/范围/验收/风险，技术细节给建议，首轮 0～1 问、总≤3，确认后才进需求基线/方案/实施。
**完整链路**：开发计划（L2+）→ 产品文档解析/需求理解（PRD/迭代方案/原型，可选）→ 开发需求基线/技术差距 → 方案/ADR（前端需要补设计时才另出前端设计说明；产品方案完整则直接实现）→ 任务清单 → 实现/自测 → 评审 → 提测 → 测试报告（可选）→ UAT/验收（已有则引用，无则本包补）→ 工程发布审批 → 部署/验证/回滚 → 发布后观察 → 复盘；按变更分级（L0～L3）裁剪。  
**轻量单人轨**：个人小项目/单一想法默认走 `workflows/solo.yaml`：产品定义（按需）→ 一页方案卡 → 一次方案确认 → 实施 → AI 实测（开发自验）→ 完成门 → 收尾；标准档补产品定义卡/轻量测试报告，L2+ 或高风险自动升级完整链。轻量=裁文档厚度，**不**降 AC/完成门/自验；意图/档位拿不准先一问确认。细则见 `规则/核心/轻量交付.md`。  
**独立落地**：本包可单独使用；不要求安装产品/测试包。缺他包产物时一句缺口并用本包模板补（产品最小硬门槛 + 开发自验），**不因「个人/无 QA」降标**。多包同项目时自动探测并共用原始资料根（推荐 `docs/`） 与 `activeContext.md`；本包仍独立执行自己的 workflow；开发自验 ≠ 版本准出。  
**产品缺陷流转**：开发判定产品缺陷 → 出评估单 → **有平台则以平台回写+指派为主**（不强制再打 BUG 交接包）；无平台/点名交接包 → 先问后发自包含评估包。产品确认后回流开发。三包独立；多包同仓直读不转发。  
**全局纪律**：界面减法、UX/DX/AX 三维同向、开发阶段不背旧数据（`AGENTS.md` §0.3-7/8；细则 `技能/engineering-quality` §1.1～1.2、`技能/frontend-design` §5.1）。

### 2.1 文档分层（按需读）

| 层 | 位置 | 读法 |
| --- | --- | --- |
| 入口 | `AGENTS.md` | 每任务读 **§0 硬节**；口令表仅路由未定/首次命中时读；禁止通读 §0～§3 全文 |
| 路由 | `workflows/*.yaml` | 只读命中 workflow 的当前 step |
| 常驻规则 | `规则/门.md`、`规则/核心/验证规则.md`、`规则/核心/澄清.md`、`规则/读取索引.md`、`规则/文档治理.md` | 只读当前相关节 |
| 参考手册 | `规则/工作流.md`、`规则/缺陷/缺陷修复协作.md`、`规则/协作/协作与交接.md`（标 `读取级别：参考`） | 只读当前 step/阶段节，禁止通读 |
| 技能 | `技能/<name>/SKILL.md` | 命中步才读；不命中不读 |
| 模板 | `规则/模板/模板索引.md` → 当前组 | 只读当前要填的一份 |
| 验证 | `验证/` | 收尾/过门时读；运行态写 `.gate/开发规范/` |

> 读取预算（目标，非硬上限）：核心 ≤3～4 个来源（命中才读）+ ≤8k tokens；复杂可至 5；先读当前 step、当前 agent、当前技能节、当前产物，再按需补规则节。规则不是越多越稳，读全本会稀释当前 step 约束。

## 3. 上手（快速开始）

1. 复制整个 `开发规范/` 到项目根下一层；**排除** `.state/`、`.gate/`、`__pycache__/`（这些是运行态/缓存，不是规范）。推荐 `git archive` 或 `robocopy /XD .state .gate __pycache__`。  
2. 挂载：按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 把引导语句补入项目根 `AGENTS.md`（追加不覆盖）。  
3. 对 AI 说「接入开发规范」→ `workflows/onboard.yaml`：建档 → 文档树/索引/归档 → 根 `CHANGELOG.md` + `开发/工作日志.md` → 入库策略 → 打标。  
3.1 **个人小项目/想法**：直接说「我有个想法：…」或「轻量开发」→ `solo`：按需产品定义 → 一页方案卡 → 你确认 → 实施 → AI 实测 → 收尾；L2+ 自动升级完整链。小改也可直接说「改一下…」走 `change` L0/L1。  
3.2 **不用口令**：任意自然语言描述即可；AI 按 `规则/核心/入口判定.md` 抽五元组→意图类→状态修正，不抠固定措辞；首条 `route`/`reason`。轻量/完整由项目状态决定；判断错可一句纠正。  
4. 之后任务**不再**例行落地自检，直接路由执行。  
5. 新文档/变化/确认项：直接把文件发给 AI，或说「这是新一期方案/这个未决项定了/新增需求…」→ `workflows/intake.yaml`：收件→分类→覆盖对照→影响分析→局部更新→变更吸收报告；你只确认实质变更与资料归档。整理现有资料说「资料收取 / 资料整理 / 资料归档 / 资料巡检」；检查工作文档/临时文件说「文档巡检 / 清理临时文件」。  
6. 新项目/新产品：说「开发计划」→ `workflows/control.yaml` init，按 `规则/模板/10-规划与需求/开发计划模板.md` 建 `开发/开发计划.md`（新项目建议 `开发/开发计划.md`；旧项目可保留 `00-项目治理/开发计划.md`）；首次计划经 `confirm_plan` 后从 S0 输入检查开始按阶段/门执行。S3 叫「任务与排期」，不要与开发计划混称。  
6.1 日常推进：说 **「按开发计划执行 / 下一步 / 当前状态」** → `control` 的 run/next；读计划 §0，按当前阶段路由到 change/iterate/release/retro，执行到下一个门停止；每步回写计划与执行日志。  
7. 新功能/迭代：说「按方案实施」或「只出任务清单」→ 任务清单按 `规则/模板/30-计划与任务/任务清单模板.md` 落 `04-计划与任务/`；确认后实施。  
8. 发布：说「发布/上线」→ `workflows/release.yaml`；发布前必须过上线检查单与审批。测试/预发部署不算 S8（A 模式 `rc.N`；B 模式 `0.3.x` QA 批次）；版本口径见 `规则/核心/版本策略.md`。  
9. 复盘：说「复盘/事故复盘」→ `workflows/retro.yaml`。
10. 交接：**内容优先、包按需**。提测默认只交提测单；说「生成交接包…」或命中多文件/签收/仓外/同发发版时先问再 send。接收走 receive。多包同仓直读。

落地通常只装本包。意图→包映射见根 README；若同项目装多个包，三包自动探测并共享资料/上下文，不需要额外协作目录；一次会话只执行一个包的 workflow。

## 4. 自检

```text
开发规范/规则/tools/Test-Template.ps1
开发规范/规则/tools/Test-DocHygiene.ps1
开发规范/验证/Invoke-Gate.ps1 -ProjectRoot "."
```

自检内容：引用可解析、章节锚点、workflows→agents、步标记词表、能力名声明、版本单点、**YAML 语法/基本 schema、开发计划模板 schema**；文档卫生检查 AGENTS 行数、规则超长、孤立模板、读取索引/工作流挂载。  
自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。  
任务清单/开发计划可单独校验：

```text
python 开发规范/规则/tools/validate_tasklist.py <任务清单路径>
python 开发规范/规则/tools/validate_dev_plan.py <开发计划路径>
```

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`项目档案.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；子代理（按 `规则/协作/子代理编排.md`：达阈值分片/文件不相交可并行≤3/超时降级）、MCP（如缺陷平台）按需。  
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。  
- **MCP 配置落点**：只写宿主本地/用户级配置（如 Cursor：`%USERPROFILE%\.cursor\mcp.json`；路径以宿主官方文档为准）；禁项目内配置作规范入口。  
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `项目档案.md` §6（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。  
- **体检能力**：口令「体检能力」等 → `workflows/skill-audit.yaml`：对照项目（或「通用优化技能」按通用最优）检查外部能力 + 随包技能；确认后可**就地改本包** `技能/`·`能力/`。  
- **技能格式**：`技能/*.md` 含 `name/description` frontmatter，兼容 Agent Skills 发现机制；随包加载不依赖安装。

## 6. 文档与归档

- 工作文档根固定 `产品/` · `开发/` · `测试/`；原始资料根推荐 `docs/`（其它名可）；资料模式 keep/mix/replace 只整理原始资料根。  
- 项目根只留代码/构建、README、`CHANGELOG.md`、`产品档案.md`/`产品/`（如启用产品包）、`项目档案.md`、`activeContext.md`、`开发规范/`、`开发/`、`测试/`、`.gitignore`。  
- 标准树：`开发计划.md / 文档索引.md / 资料/（{版本或主题}/ + _通用/ + 资料/_归档/ + 资料索引） / 00-项目治理 / 01-需求基线 / 02-方案设计 / 03-技术设计 / 04-计划与任务 / 05-测试与验收 / 06-发布与交付 / 07-运维与协作 / 08-复盘与改进 / 交接/ / _归档`；根索引为 `开发/文档索引.md`。新项目建议文档根用 `开发/`。  
- 方案进 `02`、契约/ADR 进 `03`、清单进 `04`、提测/发布进 `06`、常青运维进 `07`、复盘进 `08`；L2+ 开发计划在文档根，变更/待决/决策在 `00-项目治理/`，需求台账在 `01-需求基线/`；新文件先落 `资料/{版本或主题}/` 或 `_通用/` 再按 `规则/文档治理.md` 收取；发布说明一版一档；迭代快照移 `_归档/{yyyyMMdd}-{版本}/`（旧项目可用 `历史/`）。  
- **资料 vs 工作文档**：`资料/` 只放外部输入（`{版本或主题}/` + `_通用/` + `资料/_归档/`；禁 `项目文档/`、禁强制类型前缀）；`00～08` 为工作文档（不回写资料）。入站先意图分析（T1～T9）；确认采纳且 S1/S2/S3 → 同批进 `资料/_归档/`。单包优先；主副本在原始资料根（推荐 `docs/`）；本包 `资料/` 放副本；放入≠自动跑他包。分类/覆盖对照/归档见 `规则/文档治理.md`。  
- **版本记录**：根 `CHANGELOG.md`＝仅开发维护的产品发版史（用户可见能力/破坏性/迁移·兼容/安全；禁过程项）；多包时优先产品对外变化摘要，软序见 `规则/文档治理.md` 版本记录。`产品|开发|测试/工作日志.md`＝各岗里程碑（产/测禁写根；无开发包不建根）。`发布说明`＝单版叙事；计划执行日志＝过程。仅正式发版/点名发版更新根；年切片/迭代快照按文档治理 §7。  
- 细则与命名/根目录白名单见 `规则/工作流.md` §5。
