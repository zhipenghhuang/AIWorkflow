# 开发规范 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（开发轨）**：声明式 `workflows/*.yaml` + 角色 `agents/*.yaml` + 红线 `规则/` + 内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）+ 文档治理（需求/方案/清单/提测/发布/UAT/复盘统一落位、索引、归档）。  
执行宿主（任意支持 AGENTS 的 AI 编码工具，要求见本文「宿主适配」节）按 YAML 步骤执行；步内实现路径交 AI（框架固定 · 局部自主）。  
**完整链路**：开发计划（L2+）→ 已有 PRD/需求文档（可选，任意来源）→ 开发需求基线/技术差距 → 方案/ADR → 任务清单 → 实现/自测 → 评审 → 提测 → 测试报告（可选）→ UAT/验收（已有则引用，无则本包补）→ 工程发布审批 → 部署/验证/回滚 → 发布后观察 → 复盘；按变更分级（L0～L3）裁剪。  
**独立落地**：本包可单独使用；不要求安装产品/测试包。若同项目已有 PRD/测试报告/UAT 等资料，可按需复用；缺输入时一句话说明，由用户提供或选择只用已有资料。

## 2. 目录

| 路径 | 作用 |
| --- | --- |
| `workflows/` | 流程定义：`intake`（变更吸收）/ `change` / `defect-fix` / `iterate` / `onboard` / `release` / `retro` / `control`（开发计划） |
| `agents/` | 角色契约：implementer / defect-fixer / iterate-lead / reviewer-agent / onboard-agent / delivery-lead |
| `能力/` | 可选能力注册表（技能/工具装配建议；`能力/00-能力注册表.md`） |
| `技能/` | 内置专业技能 00～08（开发计划/需求/设计+技术选型/数据库/API/前端/安全/性能子技能/实现+前后端子技能/评审/提测/拆单/验收上线/复盘）；结构 `技能/<name>/SKILL.md`，随包、无需安装；编号→路径映射见 `技能/README.md` |
| `AGENTS.md` | AI 入口（口令 → workflow；分级；接入标记；版本单点） |
| `规则/工作流.md` | 护栏、阶段衔接、提交门、文档落位/归档/根目录白名单 |
| `规则/迭代交付.md` | 迭代、任务清单、DoR/DoD、输出骨架 |
| `规则/缺陷修复协作.md` | 缺陷菜单、备注、回写、发布后验证 |
| `规则/模板/` | 项目档案 / 开发计划 / 需求台账 / 变更记录 / 待决项 / 决策记录 / 变更吸收报告 / 需求基线 / 方案 / ADR / 任务清单 / 提测单 / 发布说明 / 上线检查单 / 发布记录 / UAT / 复盘 / 文档索引 / activeContext / 根 AGENTS |
| `规则/tools/` | 包自检 `Test-Template.ps1`、YAML 校验、任务清单校验、文档树初始化 `Initialize-Docs.ps1` |

实例在项目根：`项目档案.md`（§7 项目规范、§8 交付治理、§9 文档归档）、`activeContext.md`、`{文档事实源目录}/`（新项目建议 `开发/`，旧项目可用 `docs/`；含 `{文档事实源目录}/文档索引.md`）。文档分类落位见 `规则/工作流.md` §5。

## 3. 上手（快速开始）

1. 复制整个 `开发规范/` 到项目根下一层。  
2. 挂载：按 `规则/模板/根AGENTS薄指针.md` 把引导语句补入项目根 `AGENTS.md`（追加不覆盖）。  
3. 对 AI 说「接入开发规范」→ `workflows/onboard.yaml`：建档 → 文档树/索引/归档 → 入库策略 → 打标。  
4. 之后任务**不再**例行落地自检，直接路由执行。  
5. 新文档/变化/确认项：直接把文件发给 AI，或说「这是新一期方案/这个未决项定了/新增需求…」→ `workflows/intake.yaml`：收件→分类→影响分析→局部更新→变更吸收报告；你只确认实质变更。  
6. 新项目/新产品：说「开发计划」→ `workflows/control.yaml` init，按 `模板/开发计划模板.md` 建 `{文档事实源目录}/开发计划.md`（新项目建议 `开发/开发计划.md`；旧项目可保留 `00-项目治理/开发计划.md`）；首次计划经 `confirm_plan` 后从 S0 输入检查开始按阶段/门执行。S3 叫「任务与排期」，不要与开发计划混称。  
6.1 日常推进：说 **「按开发计划执行 / 下一步 / 当前状态」** → `control` 的 run/next；读计划 §0，按当前阶段路由到 change/iterate/release/retro，执行到下一个门停止；每步回写计划与执行日志。  
7. 新功能/迭代：说「按方案实施」或「只出任务清单」→ 任务清单按 `模板/任务清单模板.md` 落 `03-计划与状态/`；确认后实施。  
8. 发布：说「发布/上线」→ `workflows/release.yaml`；发布前必须过上线检查单与审批。  
9. 复盘：说「复盘/事故复盘」→ `workflows/retro.yaml`。

落地通常只装本包。意图→包映射见根 README；若磁盘偶发多包并存，同会话只启用一包。

## 4. 自检

```text
开发规范/规则/tools/Test-Template.ps1
```

自检内容：引用可解析、章节锚点、workflows→agents、步标记词表、能力名声明、版本单点、**YAML 语法/基本 schema、开发计划模板 schema**。  
自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。  
任务清单/开发计划可单独校验：

```text
python 开发规范/规则/tools/validate_tasklist.py <任务清单路径>
python 开发规范/规则/tools/validate_dev_plan.py <开发计划路径>
```

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`项目档案.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；子代理、MCP（如缺陷平台）按需。  
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。  
- **MCP 配置落点**：只写宿主本地/用户级配置（如 Cursor：`%USERPROFILE%\.cursor\mcp.json`；路径以宿主官方文档为准）；禁项目内配置作规范入口。  
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `项目档案.md` §6（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。  
- **技能格式**：`技能/*.md` 含 `name/description` frontmatter，兼容 Agent Skills 发现机制；随包加载不依赖安装。

## 6. 文档与归档

- 项目根只留代码/构建、README、`产品档案.md`/`产品/`（如启用产品包）、`项目档案.md`、`activeContext.md`、`开发规范/`、`{文档事实源目录}/`、`测试/`、`.gitignore`。  
- 标准树：`开发计划.md / 文档索引.md / 资料/（项目文档 + 原始素材 + 资料索引） / 00-项目治理 / 01-需求基线 / 02-设计基线 / 03-计划与状态 / 04-测试与验收 / 05-发布与交付 / 06-复盘与改进 / _归档`；根索引为 `{文档事实源目录}/文档索引.md`。新项目建议文档根直接用 `开发/`。  
- 方案/清单/提测/发布/UAT/复盘各归其位；L2+ 开发计划在文档根，变更/待决/决策在 `00-项目治理/`，需求台账在 `01-需求基线/`；新文件先放 `资料/原始素材/_收件箱/`；发布说明一版一档；旧版/迭代快照移 `_归档/{yyyyMMdd}-{版本}/`（旧项目可用 `历史/`）。  
- **资料 vs 工作文档**：`资料/项目文档/` 放外部 PRD/方案/设计稿；`资料/原始素材/` 放收件箱/截图/附件；其余 00～06 都是工作文档。  
- 细则与命名/根目录白名单见 `规则/工作流.md` §5。
