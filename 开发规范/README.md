# 开发规范 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（开发轨）**：声明式 `workflows/*.yaml` + 角色 `agents/*.yaml` + 红线 `规则/` + 内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）+ 文档治理（需求/方案/清单/提测/发布/UAT/复盘统一落位、索引、归档；根 `CHANGELOG.md` 长期版本记录）。  
执行宿主（任意支持 AGENTS 的 AI 编码工具，要求见本文「宿主适配」节）按 YAML 步骤执行；步内实现路径交 AI（框架固定 · 局部自主）。  
**产品文档解析**：输入含 PRD/迭代方案/文档/页面原型/截图时，先按 `技能/product-doc-analysis/SKILL.md` 产出带引用、冲突、GAP、假设与置信度的需求理解包；再按 `规则/核心/澄清.md` 先分析、只问意图/范围/验收/风险，技术细节给建议，首轮 0～1 问、总≤3，确认后才进需求基线/方案/实施。
**完整链路**：开发计划（L2+）→ 产品文档解析/需求理解（PRD/迭代方案/原型，可选）→ 开发需求基线/技术差距 → 方案/ADR（前端需要补设计时才另出前端设计说明；产品方案完整则直接实现）→ 任务清单 → 实现/自测 → 评审 → 提测 → 测试报告（可选）→ UAT/验收（已有则引用，无则本包补）→ 工程发布审批 → 部署/验证/回滚 → 发布后观察 → 复盘；按变更分级（L0～L3）裁剪。  
**独立落地**：本包可单独使用；不要求安装产品/测试包。若同项目已有 PRD/测试报告/UAT 等资料，可按需复用；缺输入时一句话说明，由用户提供或选择只用已有资料。多包同项目时自动探测并共享 `项目资料/` 与 `activeContext.md`；不需要额外协作目录或合同文件，本包仍独立执行自己的 workflow。  
**产品缺陷流转**：开发判定产品缺陷 → 出评估单（`00-项目治理/缺陷评估/`）→ 平台附件/备注 + 指派产品 → 产品确认后回流开发；产品给新文档后先对齐开发资料/计划再实施。三包独立，交接只认平台。

## 2. 目录

| 路径 | 作用 |
| --- | --- |
| `workflows/` | 流程定义：`intake`（变更吸收）/ `change` / `defect-fix` / `iterate` / `handoff`（交接包/回执/变更通知）/ `onboard` / `release` / `retro` / `control`（开发计划） |
| `agents/` | 角色契约：implementer / defect-fixer / iterate-lead / reviewer-agent / **verifier-agent** / onboard-agent / delivery-lead / worker-agent |
| `能力/` | 可选能力注册表（技能/工具装配建议；`能力/00-能力注册表.md`） |
| `技能/` | 内置专业技能 20 个（00～08 + `engineering-quality` + `product-doc-analysis`；结构 `技能/<name>/SKILL.md`；编号→路径映射见 `技能/README.md`） |
| `AGENTS.md` | AI 入口（口令 → workflow；分级；接入标记；版本单点） |
| `规则/读取索引.md` | 唯一读取入口：step → 必读文件/节 → 预算 |
| `规则/门.md` | 门/gate/`when` 语义、门档位；含 `completion-gate` |
| `规则/工作流.md` | 护栏、提交门、文档落位摘要（只读当前节） |
| `规则/文档治理.md` | 资料收取/分类/覆盖对照/失效/归档 + 工作文档生命周期/归档/清理 + 根 CHANGELOG |
| `规则/核心/` | `澄清.md`、`验证规则.md`、`规则治理.md`、`维护.md` |
| `规则/协作/` | `协作与交接.md`、`子代理编排.md` |
| `规则/缺陷/` | `缺陷修复协作.md`、`缺陷平台适配.md` |
| `规则/专项/` | `迭代交付.md`（迭代/任务清单/DoR/DoD 参考） |
| `规则/playbooks/` | 重阶段步骤卡：迭代/缺陷/发布 |
| `规则/模板/` | 按生命周期分 7 组：`00-接入与治理` / `10-规划与需求` / `20-设计与技术` / `30-计划与任务` / `40-交付与发布` / `60-复盘与改进` / `90-交接与收尾`；先看 `规则/模板/模板索引.md` |
| `规则/tools/` | 包自检 `Test-Template.ps1`、YAML 校验、任务清单校验、文档树初始化 `Initialize-Docs.ps1`、交接包校验 `validate_handoff.py` |
| `验证/` | 完成门 `验证/Invoke-Gate.ps1`、检查矩阵、前端 15 项清单/Playwright 模板、报告 `验证/Test-Report.ps1`（包内只读）；运行态落项目根 `.gate/` |

实例在项目根：`项目档案.md`（§7 项目规范、§8 交付治理、§9 文档归档）、`activeContext.md`、`CHANGELOG.md`、`{文档事实源目录}/`（新项目建议 `开发/`，旧项目可用 `docs/`；含 `{文档事实源目录}/文档索引.md`、`交接/` 与 `资料/交接/`）。文档分类落位见 `规则/工作流.md` §5。跨角色交接按 `规则/协作/协作与交接.md` 生成 `{文档事实源目录}/交接/{HO-ID}/`，台账 `交接台账.md`；用户整包复制给对应角色。

### 2.1 文档分层（按需读）

| 层 | 位置 | 读法 |
| --- | --- | --- |
| 入口 | `AGENTS.md` | 每任务读 §0～§3；先路由再读当前 step |
| 路由 | `workflows/*.yaml` | 只读命中 workflow 的当前 step |
| 常驻规则 | `规则/门.md`、`规则/核心/验证规则.md`、`规则/核心/澄清.md`、`规则/读取索引.md`、`规则/文档治理.md` | 只读当前相关节 |
| 参考手册 | `规则/工作流.md`、`规则/缺陷/缺陷修复协作.md`、`规则/协作/协作与交接.md`（标 `读取级别：参考`） | 只读当前 step/阶段节，禁止通读 |
| 技能 | `技能/<name>/SKILL.md` | 命中步才读；不命中不读 |
| 模板 | `规则/模板/模板索引.md` → 当前组 | 只读当前要填的一份 |
| 验证 | `验证/` | 收尾/过门时读；运行态写 `.gate/开发规范/` |

> 单步读取 ≤5 个来源/≤8k tokens；先读当前 step、当前 agent、当前技能节、当前产物，再按需补规则节。规则不是越多越稳，读全本会稀释当前 step 约束。

## 3. 上手（快速开始）

1. 复制整个 `开发规范/` 到项目根下一层；**排除** `.state/`、`.gate/`、`__pycache__/`（这些是运行态/缓存，不是规范）。推荐 `git archive` 或 `robocopy /XD .state .gate __pycache__`。  
2. 挂载：按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 把引导语句补入项目根 `AGENTS.md`（追加不覆盖）。  
3. 对 AI 说「接入开发规范」→ `workflows/onboard.yaml`：建档 → 文档树/索引/归档 → 根 `CHANGELOG.md` → 入库策略 → 打标。  
4. 之后任务**不再**例行落地自检，直接路由执行。  
5. 新文档/变化/确认项：直接把文件发给 AI，或说「这是新一期方案/这个未决项定了/新增需求…」→ `workflows/intake.yaml`：收件→分类→覆盖对照→影响分析→局部更新→变更吸收报告；你只确认实质变更与资料归档。整理现有资料说「资料收取 / 资料整理 / 资料归档 / 资料巡检」；检查工作文档/临时文件说「文档巡检 / 清理临时文件」。  
6. 新项目/新产品：说「开发计划」→ `workflows/control.yaml` init，按 `规则/模板/10-规划与需求/开发计划模板.md` 建 `{文档事实源目录}/开发计划.md`（新项目建议 `开发/开发计划.md`；旧项目可保留 `00-项目治理/开发计划.md`）；首次计划经 `confirm_plan` 后从 S0 输入检查开始按阶段/门执行。S3 叫「任务与排期」，不要与开发计划混称。  
6.1 日常推进：说 **「按开发计划执行 / 下一步 / 当前状态」** → `control` 的 run/next；读计划 §0，按当前阶段路由到 change/iterate/release/retro，执行到下一个门停止；每步回写计划与执行日志。  
7. 新功能/迭代：说「按方案实施」或「只出任务清单」→ 任务清单按 `规则/模板/30-计划与任务/任务清单模板.md` 落 `03-计划与状态/`；确认后实施。  
8. 发布：说「发布/上线」→ `workflows/release.yaml`；发布前必须过上线检查单与审批。  
9. 复盘：说「复盘/事故复盘」→ `workflows/retro.yaml`。
10. 交接：说「生成交接包/提测交接包/交接给测试/发布交接包」→ `workflows/handoff.yaml` send；说「接收交接包/接收产品文档/接收测试报告」→ receive（核对+回执+更新计划）；说「交接状态/待回执」→ status；说「发变更通知/同步变更」→ change_send/change_receive。用户只需把 `{HO-ID}` 整包复制给对应角色。

落地通常只装本包。意图→包映射见根 README；若同项目装多个包，三包自动探测并共享资料/上下文，不需要额外协作目录；一次会话只执行一个包的 workflow。

## 4. 自检

```text
开发规范/规则/tools/Test-Template.ps1
开发规范/规则/tools/Test-DocHygiene.ps1
开发规范/验证/Invoke-Gate.ps1 -ProjectRoot "."
```

自检内容：引用可解析、章节锚点、workflows→agents、步标记词表、能力名声明、版本单点、**YAML 语法/基本 schema、开发计划模板 schema**；文档卫生检查 AGENTS 行数、规则超长、孤立模板、读取索引/工作流挂载。  
自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。  
任务清单/开发计划可单独校验：

```text
python 开发规范/规则/tools/validate_tasklist.py <任务清单路径>
python 开发规范/规则/tools/validate_dev_plan.py <开发计划路径>
```

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`项目档案.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；子代理（分片/独立核验，按 `规则/协作/子代理编排.md` 阈值取档）、MCP（如缺陷平台）按需。  
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/00-接入与治理/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。  
- **MCP 配置落点**：只写宿主本地/用户级配置（如 Cursor：`%USERPROFILE%\.cursor\mcp.json`；路径以宿主官方文档为准）；禁项目内配置作规范入口。  
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `项目档案.md` §6（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。  
- **技能格式**：`技能/*.md` 含 `name/description` frontmatter，兼容 Agent Skills 发现机制；随包加载不依赖安装。

## 6. 文档与归档

- 项目根只留代码/构建、README、`CHANGELOG.md`、`产品档案.md`/`产品/`（如启用产品包）、`项目档案.md`、`activeContext.md`、`开发规范/`、`{文档事实源目录}/`、`测试/`、`.gitignore`。  
- 标准树：`开发计划.md / 文档索引.md / 资料/（扁平：PRD/需求/迭代/专项/原型/设计/接口/技术/测试/验收/反馈/调研/竞品/会议/数据/原始/其他 + 资料/资料索引.md） / 00-项目治理 / 01-需求基线 / 02-设计基线 / 03-计划与状态 / 04-测试与验收 / 05-发布与交付 / 06-复盘与改进 / _归档`；根索引为 `{文档事实源目录}/文档索引.md`。新项目建议文档根直接用 `开发/`。  
- 方案/清单/提测/发布/UAT/复盘各归其位；L2+ 开发计划在文档根，变更/待决/决策在 `00-项目治理/`，需求台账在 `01-需求基线/`；新文件直接落 `资料/`，先按 `规则/文档治理.md` 收取/对照；发布说明一版一档；旧版/迭代快照移 `_归档/{yyyyMMdd}-{版本}/`（旧项目可用 `历史/`）。  
- **资料 vs 工作文档**：`资料/` 只放外部输入（扁平，按类型前缀命名）；需求基线/方案/ADR/任务清单/提测/发布/UAT/复盘是工作文档；分类/覆盖对照/归档见 `规则/文档治理.md`。新项目强制扁平；旧项目已有子目录可保留，说「重新接入」再迁移。多包模式共享外部资料优先 `项目资料/`，本包 `资料/` 只放专属/历史资料。  
- **版本记录与归档**：根 `CHANGELOG.md` 记录本项目版本/迭代/变化；版本关闭/发布更新；归档后现行文档保持正确，旧版/迭代快照按 `规则/文档治理.md` §6 归档。  
- 细则与命名/根目录白名单见 `规则/工作流.md` §5。
