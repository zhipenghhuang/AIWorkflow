# 安全与威胁建模（技能 · 随包生效）

> 用于：S2 技术方案的安全部分，或权限/资金/敏感数据/上传/外部集成/公共 API/AI 能力变更。  
> 产出：资产/入口/信任边界、威胁与缓解、安全测试清单；高风险项进 ADR/风险表。  
> 原则：**先画信任边界，再列威胁，再定缓解与验证**；不把“有登录”当安全。  
> 冲突：`AGENTS.md`/`规则/` 的红线与门优先；项目已有安全基线优先于本技能默认值。

## 1. 资产、入口与信任边界

- **资产**：账号/权限、资金、订单、个人信息、密钥、配置、审计日志、模型/提示词/知识库。
- **入口**：页面/API/文件上传/回调/消息/定时任务/第三方/Agent 工具调用。
- **信任边界**：浏览器/网关/服务/数据库/第三方/模型供应商；跨边界的数据与身份。
- **角色与数据域**：谁能看/改什么；本人/部门/租户/全部；越权面。
- **数据流**：从哪里来、经过谁、存哪里、谁能读、保留多久、如何删除。
- **滥用场景**：正常用户/内部人员/攻击者/恶意租户/被污染的数据源分别能做什么。

## 2. 威胁清单（STRIDE + OWASP + 供应链 + AI）

### 2.1 通用

- 伪造/篡改/抵赖/信息泄露/拒绝服务/提权（STRIDE）。
- 注入（SQL/命令/模板/LDAP）、XSS、CSRF、SSRF、越权/IDOR、反序列化、路径穿越。
- 认证/会话/令牌/刷新；密码/验证码/锁定/MFA；会话固定/登出失效。
- 密钥硬编码、日志泄露、错误回显、调试接口、配置暴露、默认口令。
- 速率限制/防刷/防重放；敏感操作二次确认；审计缺失。
- 文件上传：扩展名/MIME/内容/大小/存储路径/直链/病毒；图片重编码。
- 第三方回调：验签、时间戳、重放、来源 IP、幂等。

### 2.2 供应链

- 依赖漏洞/许可证/维护状态；锁文件与可复现构建。
- SBOM（CycloneDX/SPDX）、制品签名/来源证明（SLSA）、构建平台可信度。
- CI/CD 密钥、缓存投毒、依赖混淆、内部包命名空间。
- 参考：OWASP ASVS 5.0、OWASP WSTG、SLSA v1.2、OpenSSF Scorecard；按适用性裁剪。

### 2.3 AI / LLM / Agent

- 提示注入（直接/间接）、越狱、角色绕过、系统提示泄露。
- 检索越权/数据外泄、知识库投毒、引用伪造、无依据编造。
- 过度代理：未授权工具调用、批量删除/发送/支付、循环消耗。
- 输出处理：XSS/Markdown 注入、危险链接、代码执行、SQL/命令拼接。
- 模型/数据集/插件供应链；供应商数据使用与保留；PII 进 prompt/日志。
- 参考：OWASP Top 10 for LLM 2025、NIST AI RMF / Generative AI Profile、ISO/IEC 42001（按适用）。

## 3. 缓解与验证（每条威胁都要有验证）

- 每条威胁：**缓解措施 + 验证方式 + 责任人/状态**；不能验证的写“接受风险 + 批准人”。
- 服务端校验为准；资源级授权；最小权限；默认拒绝。
- 加密/脱敏/审计；密钥走环境变量/密钥库；日志禁 token/PII。
- 安全测试：越权（横向/纵向）、注入、上传、重放、限流、错误信息、会话、CSRF/SSRF。
- AI 安全测试：直接/间接注入、越权检索、系统提示套取、工具越权、无限消耗、输出处理。
- 安全验收标准写成可判定用例（输入/动作/预期拒绝/证据），不写“注意安全”。
- 高危项未缓解 → 不进入开发/发布；例外需用户批准并记录风险与补偿措施。

## 4. 高风险场景速查

| 场景 | 必查 |
| --- | --- |
| 登录/会话 |  credential stuffing、锁定、MFA、会话固定、登出失效、找回密码 |
| 权限/租户 | 资源级授权、横向/纵向越权、IDOR、批量接口、导出 |
| 资金/支付 | 金额/币种/精度、重复支付、回调验签、对账、退款权限 |
| 文件上传 | 类型/内容/大小/路径、直链、病毒、图片重编码、存储权限 |
| 公共 API | 认证、限流、幂等、版本、错误信息、CORS、OpenAPI 暴露 |
| 外部集成 | 验签、重放、超时、降级、密钥轮换、供应商权限 |
| AI/Agent | 注入、越权检索、工具白名单、人工确认、预算、审计 |

## 5. 输出（威胁模型表）

```text
资产/入口/边界：{图或表}
威胁：{ID｜资产｜入口｜STRIDE/OWASP 分类｜影响｜可能性}
缓解：{措施｜验证方式｜状态｜责任人}
安全测试：{用例/工具/预期拒绝/证据}
残余风险：{未缓解项｜接受人｜补偿措施｜复审时间}
```

## 6. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “有登录就安全了” | 认证≠授权；资源级越权是最常见漏洞之一。 |
| “前端隐藏了按钮” | 攻击者直接调接口；服务端必须校验。 |
| “内部系统不用管” | 内部账号被盗/横向移动影响更大；至少做最小权限与审计。 |
| “用了框架/ORM 就没注入” | 原生 SQL/排序/模板/命令拼接仍可能注入。 |
| “AI 只是聊天，不涉及安全” | 提示注入、越权检索、工具调用、数据外泄都是真实风险。 |
| “先上线再补安全” | 权限/资金/隐私问题上线后修复成本最高；高危阻断。 |

## 7. 红旗

- 只画架构图，不列信任边界与数据流。
- 威胁表只有“加强校验/注意安全”，没有验证方式。
- 只做登录，不做资源级授权/租户隔离。
- 上传只校验扩展名；回调不验签；日志打印 token/PII。
- 依赖不扫描、无 SBOM、构建来源不可追溯。
- AI 功能无提示注入/越权/工具权限测试。
- 高危项靠“用户没发现”维持。

## 8. DoD

- 资产/入口/边界/数据流清楚；高风险场景全覆盖。
- 每条威胁有缓解、验证、状态、责任人；残余风险有接受人。
- 安全测试用例可执行、可判定；负面路径优先。
- 供应链与 AI 风险按适用性覆盖。
- 高危未缓解不进入开发/发布；例外有批准与补偿措施。
