# 安全与威胁建模（技能 · 随包生效）

> 用于：S2 技术方案的安全部分，或权限/资金/敏感数据/上传/外部集成/公共 API 变更。  
> 产出：资产/入口/信任边界、威胁与缓解、安全测试清单；高风险项进 ADR/风险表。  
> 原则：**先画信任边界，再列威胁，再定缓解与验证**；不把“有登录”当安全。

## 1. 资产与入口

- 资产：账号/权限、资金、订单、个人信息、密钥、配置、审计日志。
- 入口：页面/API/文件上传/回调/消息/定时任务/第三方。
- 信任边界：浏览器/网关/服务/数据库/第三方；跨边界的数据与身份。
- 角色与数据域：谁能看/改什么；越权面。

## 2. 威胁清单（STRIDE + OWASP）

- 伪造/篡改/抵赖/信息泄露/拒绝服务/提权。
- 注入、XSS、CSRF、SSRF、越权、IDOR、反序列化、文件上传、路径穿越。
- 认证/会话/令牌/刷新；密码/验证码/锁定。
- 密钥硬编码、日志泄露、错误回显、依赖漏洞/许可证。
- 速率限制/防刷/防重放；敏感操作二次确认。

## 3. 缓解与验证

- 每条威胁：缓解措施 + 验证方式（测试用例/扫描/评审）。
- 服务端校验为准；资源级授权；最小权限。
- 加密/脱敏/审计；密钥走环境变量/密钥库。
- 安全测试：越权、注入、上传、重放、限流、错误信息。
- 高危项未缓解 → 不进入开发/发布；例外需用户批准并记录。

## 4. 输出与常见坑

- 输出：信任边界图、威胁表（资产/入口/威胁/影响/缓解/验证/状态）、安全测试清单。
- 坑：只做登录不做资源级授权；前端隐藏当授权；日志打印 token/PII；上传只校验扩展名；第三方回调不验签；依赖不扫描。
