# 需求与规格（技能 · 随包生效）

> 用于：clarify 步（需求/验收不明时）、design 步前段。目标：把模糊需求变成**可验收点**，一次问清、不返工。

## 1. 一次一问访谈法

- 每轮只问**一个**问题，附 2～3 个候选选项与推荐项（降低回答成本）。
- 问题优先级：目标与用户 → 主链路径 → 边界与非目标 → 验收与数据口径。
- 连续追问至 **≥95%**：能复述出「谁 / 在什么场景 / 做什么 / 系统怎么响应 / 怎么算对」即达标（纪律见 `AGENTS.md` §0.2）。
- 禁答题式盘问；禁把设计细节（怎么实现）当需求问题。

## 2. 必问清单（缺一即追问）

| 维度 | 要问出 |
| --- | --- |
| 目标与用户 | 谁用、解决什么问题、成功标准 |
| 主路径 | 入口 → 操作 → 结果的完整故事 |
| 输入与规则 | 关键字段/枚举/阈值/来源；非法与空值怎么算 |
| 状态与权限 | 有哪些状态流转、哪些角色不能用 |
| 数据与口径 | 数字怎么算、时间口径、精度；跨端一致性 |
| 异常与限制 | 失败提示、重复提交、并发、数据量级 |
| 非目标 | 本次明确不做（写进范围排除） |
| 验收 | 每条可验收点=条件+动作+可观测量 |

## 3. 可验收点写法

- 好：`已登录管理员在X页点[提交]后，列表出现新记录，状态=待处理`
- 坏：`提交功能正常`（无对象、无观测值）
- 每条附来源（原文/现网/口头确认）；未确认项显式标「**假设**」。

## 4. 输出（并入复述/方案，不另立文档）

- 1～2 句目标复述；验收点清单；明确非目标；未决与假设（供 design 与后续回问）。

## 5. 需求基线落盘（L2+）

- 需求稳定后，按 `规则/模板/需求基线模板.md` 落 `01-需求基线/`；小改用轻量需求卡（背景/目标/AC/非目标）。
- 用户故事：`作为{角色}，我希望{能力}，以便{价值}`；每个故事至少一条 AC。
- NFR 必过：性能/可用性/安全/隐私/兼容/可观测；不适用写「不适用」。
- 范围必须含「明确不做」；未确认项标「假设」并写验证方式。
- 签收：产品/业务/技术/测试至少相关方确认；未签收不得进入设计/排期（用户豁免须记录）。

## 6. 常见坑

- 「我问过」≠「问清了」：回答含糊（“大概/应该”）→ 换成候选选项继续定。
- 用户改口：以最新为准，旧验收点标作废（不留双真值）。
- 只写功能不写 NFR：上线后性能/权限/兼容问题返工。
- AC 不可观测：无法验收，也无法生成测试。
