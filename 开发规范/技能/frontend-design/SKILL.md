# 前端设计（技能 · 随包生效）

> 用于：`change.design` / S2 的前端部分；产品原型/设计稿交接后的工程化设计；涉及页面/路由/组件/状态/表单/交互的变更。  
> 产出：按 `规则/模板/20-设计与技术/前端设计说明模板.md` 落 `开发/02-方案设计/`；重大取舍进 ADR。  
> 原则：**先需求与情境，再信息架构与状态，再视觉与组件；先复用，再扩展，最后才自造。**  
> 质量条：`技能/engineering-quality/SKILL.md`（性能/安全/可运维/测试证据的单一出处）。  
> **本技能不是固定视觉模板**：同一套方法，不同项目必须输出不同密度、导航、组件系统与视觉方向；套模板即失败。

## 0. 开工条件与输入

必读（按存在取用）：

- PRD/需求基线/AC、产品计划、UAT/验收；如项目启用产品包，读其原型、IA、设计评审、开发交接。
- 现有系统截图/代码、设计系统/tokens、品牌/术语、埋点/反馈/客服问题。
- `项目档案.md` §7.1（前端栈/请求封装/设计系统/浏览器矩阵/性能预算/无障碍目标）与 §8（发布/验收）。
- 现有页面/路由/组件与请求封装；不要凭想象造入口。

缺失处理：缺 PRD/原型 → 用现有资料 + 项目档案 + 代码事实补“设计假设”，标注待确认；缺设计系统 → 按 §2 选一个主系统；缺品牌 → 先做中性可用方案，不冒充品牌级设计。

**与产品方案的边界**：产品设计/方案完整时，开发直接按 `frontend-implementation` 实现，本技能**不强制加载**。需要补前端设计或调整 UI 时再用；已有设计稿/原型不重画，改动写“保留/优化/偏离”。

### 0.1 使用判断（开发自选）

- 产品设计完整、无技术冲突 → 不读本技能，直接按产品方案实现。
- 需要补前端设计（无原型/不完整/仅参考）、实现需要 UI 调整、或需要落地设计系统 → 用本技能，先读产品交接/PRD。
- 只是实现细节/组件拆分 → `frontend-implementation`；工程质量 → `engineering-quality`。

任何补充/调整都要在 `前端设计说明` 写“保留/优化/偏离 + 理由”；重大偏离回产品确认。

先写 5 行设计 brief（进模板 §1）：

1. 用户/角色与 top 3 任务；2. 环境/设备/数据量/权限；3. 成功度量；4. 明确不做；5. 最大约束（品牌/合规/性能/交付期）。

## 1. 需求分析与项目适配（先回答，再画）

### 1.1 必答

- 谁在用：角色、权限、数据域、使用频率、熟练度。
- 在哪用：桌面/移动/弱网/离线/大屏/打印；浏览器与分辨率矩阵。
- 数据多大：列表量级、字段宽度、长文本、并发/实时、导入导出。
- 怎么算对：每个 AC 对应哪个页面/路由/状态/组件；缺口=阻断。
- 不能做什么：本期非目标、兼容边界、合规/隐私限制。
- 怎么衡量：任务完成率/时长/错误率、性能预算、客服/埋点基线。

### 1.2 项目类型 → 设计优先级（按项目裁剪，不照搬）

| 项目情境 | 优先 | 常用系统/模式 | 易踩坑 |
| --- | --- | --- | --- |
| B 端后台/运营 | 效率、密度、批量操作、权限 | Ant Design / Carbon / Polaris / Primer | 卡片堆砌、主操作不唯一、权限态缺失 |
| C 端/增长 | 首屏价值、情绪、移动优先 | Material 3 / Fluent 2 / shadcn/ui / 自定义 | 只做 happy path、过度动效、弱网空白 |
| 数据/分析 | 对比、筛选、图表、导出 | Carbon / Ant Design / 图表库 | 颜色误导、无空态、表格不可读 |
| 移动/现场 | 触控、扫码/拍照、弱网/离线 | Material 3 / 平台原生规范 | 桌面页缩小、目标 <44px、无离线提示 |
| 单据/打印 | A4、核对、审计、打印门槛 | 企业表单/表格模式 | 屏幕好看但打印错位、无核对 |
| 公共/民生 | 清晰、低带宽、无障碍 | GOV.UK / USWDS 模式 | 术语晦涩、对比度不足、键盘不可用 |
| 开发者工具 | 密度、键盘、深色、可复制 | Primer / Fluent 2 | 只靠图标、无快捷键、错误不可定位 |

### 1.3 覆盖矩阵（阻断）

`需求/AC → 页面/路由 → 状态 → 组件 → 证据`。每行必须有落点；没有落点的 AC 先补设计，不进入实现。

## 2. 设计系统与视觉方向

### 2.1 选型顺序

1. 已有设计系统/tokens → **复用**，只补缺口。
2. 平台有强制 UI 库 → **扩展**；禁止混搭第二套组件库。
3. 无系统且以效率为主 → 选一个成熟企业系统 + 自定义 tokens。
4. 品牌/体验需要辨识度 → 自定义视觉，但交互行为复用成熟模式。
5. 任何例外 → 写入模板 §2 / ADR：范围、原因、代价、退出条件。

| 系统 | 更适合 | 注意 |
| --- | --- | --- |
| Ant Design | 中后台、表单/表格密集、React | 风格辨识度高；避免全站默认模板感 |
| Material 3 | 跨端/Android/Google 生态 | 动态色与组件语义要统一 |
| IBM Carbon | 企业数据密集、可访问性要求高 | 组件与栅格体系较重 |
| Shopify Polaris | 电商后台/运营 | 面向 Shopify 场景，别硬套通用后台 |
| GitHub Primer | 开发者工具/协作 | 信息密度高，移动端需另设计 |
| Atlassian Design System | 协作/工单/知识库 | 组件多，先定用哪些 |
| GOV.UK Design System | 公共服务/强无障碍 | 视觉朴素，品牌表达有限 |
| Microsoft Fluent 2 | Microsoft 365/企业协作 | 平台感强，跨端需验证 |
| shadcn/ui | React/Tailwind、想拥有组件代码 | 不是完整设计系统；一致性/无障碍要自己兜底 |

> 许可、版本与维护状态以官方仓库为准；只选一个主系统，例外集中登记。

### 2.2 视觉方向（2～3 选 1）

- 每个方向写：气质/关键词、配色、字体、布局、适用理由、代价。
- 方向必须来自项目主题/用户/品牌，不是“紫蓝渐变+大圆角卡片”的默认 AI 风。
- 只花一次大胆：一个记忆点（字体/图形/布局/动效），其余克制。
- 用真实内容/真实数据做版式；禁止 lorem ipsum 式假内容掩盖问题。
- 产出 tokens：颜色（主/辅/中性/语义）、字体与字号阶、间距、圆角、边框、阴影、动效时长/缓动。
- tokens 是设计到实现的契约：页面禁止散落硬编码颜色/间距/圆角。

### 2.3 组件策略

- 组件清单：按钮、输入/选择/日期、表格、卡片、标签、Tabs、弹窗/抽屉、Toast、面包屑、步骤条、空态、错误页、分页。
- 每个组件定义：尺寸、变体、状态（default/hover/focus/active/disabled/loading/error）、文案、tokens、无障碍语义。
- 先复用再扩展； fork 组件必须写原因与维护人，禁止“复制一份改改”。
- 同类页面同一交互；不要因页面不同改组件行为。

## 3. 信息架构、路由与页面规格

- 站点地图/导航层级；一屏一个主任务，主操作唯一且醒目。
- 每页写：目标、入口、出口、主操作、次操作、角色/权限、数据来源、空态、深链。
- 路由：URL 可分享/刷新/前进后退；筛选/分页/Tab/展开面板尽量进 URL。
- 权限：路由/菜单/按钮/字段级控制；前端隐藏不等于后端授权。
- 导航：无死路；返回栈/未保存提醒/离开确认；移动端主任务可完成。
- 响应式：断点、栅格、最大宽度、密度切换；窄屏表格有替代（卡片/横向滚动/列显隐）。

## 4. 状态矩阵（每页必填）

| 状态 | 表现 | 文案 | 操作 |
| --- | --- | --- | --- |
| 空/首次 | 说明 + 引导 | 为什么空、下一步 | 主操作 |
| 加载 | 骨架/进度，避免闪烁 | 不闪跳 | 长任务可取消 |
| 失败/超时 | 原因 + 重试 | 说清怎么解决 | 重试/返回 |
| 部分失败 | 成功项 + 失败项 | 哪些没成功 | 重试失败项 |
| 成功 | 结果可见 + 下一步 | 结果是什么 | 继续/查看 |
| 禁用 | 灰显 + 原因 | 为什么不能点 | 解锁条件 |
| 无权限 | 申请/切换账号 | 缺什么权限 | 申请/联系 |
| 离线/弱网 | 本地/缓存/重试 | 当前可用范围 | 重试/稍后 |
| 冲突/并发 | 版本/覆盖提示 | 谁改了、怎么合并 | 刷新/覆盖/合并 |
| 边界 | 超长/重复/大量/限额 | 具体限制 | 截断/去重/分批 |

表单额外：校验时机、字段级错误、首个错误聚焦、提交中、重复提交、草稿/恢复、未保存提醒。  
列表额外：分页/排序/筛选、空结果、深翻、批量选择、全选边界。

## 5. 交互与文案

- 按钮=动词；同一动作全站同一词；破坏性操作二次确认或可撤销。
- 错误=发生了什么 + 为什么 + 怎么改；禁止“系统错误，请联系管理员”兜底。
- 加载按钮保留原标签 + loading；异步结果用 `aria-live` 播报。
- 乐观更新必须可回滚；失败给出重试/撤销。
- 危险/批量操作显示影响范围与数量；不可逆操作明确写“不可恢复”。
- 空态是行动邀请，不是空白；无数据/无权限/无结果分开写。
- 文案跟品牌语气一致；术语表进项目档案 §7.1，禁止同义词漂移。

### 5.1 减法优先（先删后设计）

- 删除：无决策价值的标语/口号、重复说明、副标题/眉题、装饰性标签、说明书式段落、重复的状态/字段说明。
- 保留：操作动词、状态/结果、风险/不可逆、金额/单位/权限/合规、错误原因/恢复路径、空态下一步。
- 删后用户仍不知道「这是什么/该做什么/下一步」→ 改布局/层级/分组/渐进披露/默认值/就地提示/组件选择；不得把删掉的说明加回来。
- 判定：首屏 3 秒能说出主任务与主操作；每个标签/说明能指向决策/风险/数据含义；同一信息只出现一次。
- 例外：合规/安全/破坏性/金额/权限文案保留，但用最短可理解表达；不删到无法操作。

## 6. 无障碍（默认 WCAG 2.2 AA）

- 语义 HTML 优先；标题层级、landmark、表格表头、表单 label。
- 键盘全覆盖：Tab 顺序、焦点可见、焦点不被 sticky/弹层遮挡、无键盘陷阱。
- 目标尺寸：至少 24×24 CSS px；移动端主操作 ≥44×44。
- 对比度：正文 ≥4.5:1，大文本 ≥3:1，非文本控件/图形 ≥3:1；不只靠颜色传达状态。
- 表单：label、必填/错误关联、错误摘要、自动填充、粘贴不禁用。
- 动效：尊重 `prefers-reduced-motion`；自动播放 >5 秒可暂停/停止/隐藏。
- 缩放/回流：200% 缩放不丢内容；320px 宽可完成主任务，不出现双向滚动。
- 证据：键盘走查记录、焦点截图、对比度检查、axe/Lighthouse/辅助技术抽查（可用时）。

## 7. 性能与容量

- 目标（p75，移动/桌面分开）：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；项目有更严预算则从项目。
- 首屏：关键 CSS/字体、图片尺寸与懒加载、路由级代码分割；禁止首屏加载大图表/大表格全量数据。
- 交互：长任务拆 Worker；大列表虚拟化/分页；避免无意义重渲染与布局抖动。
- 网络：请求合并/取消/竞态处理；超时/重试/降级；骨架与真实布局一致。
- 测量：实验室（Lighthouse/Performance 面板）+ 真实用户（web-vitals/RUM）；只报实验室不冒充实测。
- 预算写进模板 §10；超预算必须说明取舍与后续项。

## 8. 响应式、兼容与打印

- 断点与设备矩阵来自项目档案 §7.1；至少验证手机、笔记本、超宽屏。
- 移动端：主任务可完成；输入字号 ≥16px 防 iOS 缩放；触控目标与安全区。
- 浏览器：项目支持矩阵内验证；Safari/iOS 低电量模式、Windows 高对比度如适用。
- 打印/导出：A4 分页、表头重复、页脚页码、黑白可读、打印门槛（未核对不得正式打印）。

## 9. 交付与设计 QA

交付物（进模板）：

- 设计 brief、覆盖矩阵、IA/路由、页面规格、状态矩阵、组件/tokens、交互/文案、a11y/性能/兼容/打印、验收对照。
- 设计决策/例外/未决项；原型 ≠ 生产代码，开发按项目框架重写。
- 变更记录：版本、日期、影响页面、tokens/组件变更、迁移动作。

设计 QA（12 项，0～2 分；阻断项必须 2 分，总分 ≥20/24）：

| # | 维度 | 阻断 |
| ---: | --- | --- |
| 1 | 项目情境贴合（用户/任务/环境/约束） | 是 |
| 2 | 需求/AC 覆盖矩阵无断链 | 是 |
| 3 | IA/导航/路由/权限 | 是 |
| 4 | 状态完整（空/加载/错/权限/边界） | 是 |
| 5 | 交互/反馈/文案（含减法） | 是 |
| 6 | 设计系统/tokens/组件一致性 | 重要 |
| 7 | 无障碍（键盘/焦点/对比度/语义） | 是 |
| 8 | 性能预算与加载策略 | 重要 |
| 9 | 响应式/移动主任务 | 是 |
| 10 | 兼容/打印导出（如适用） | 是 |
| 11 | 交付物完整/可交接 | 是 |
| 12 | 证据（截图/走查/测量）可复核 | 重要 |

> 三维体验为横向门：UX（任务/文案减法/状态）、DX（可维护/可测/命令）、AX（入口/单一出处/可验证）任一净退化 → 需修。

## 10. 反模式

- 只画 happy path；空/错/权限/弱网/冲突态缺失。
- 全站同一张卡片/大圆角/渐变，换项目只换主色。
- 两套组件库混用；页面硬编码颜色/间距；组件 fork 无维护人。
- 只靠颜色表示状态；自定义 div 按钮；焦点不可见；键盘不可达。
- 首屏塞大图/大表/大图表；骨架与真实布局不一致；只看 Lighthouse 不看真实用户。
- 桌面页直接缩小当移动端；打印靠截图；导出无门槛。
- 用大段说明文字弥补布局/层级问题；保留无决策价值的标语/副标题/装饰标签。
- 把原型 HTML 直接当生产代码；设计说明没有验收对照。
