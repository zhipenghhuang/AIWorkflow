# 任务拆解（技能 · 随包生效）

> 用于：`iterate` 的 `plan` 步、`change` 的条件 `plan` 步。先读本技能，再拆单。  
> 产出：`开发/04-计划与任务/任务清单-{版本或主题}.md`，骨架见 `规则/模板/30-计划与任务/任务清单模板.md`。  
> 原则：**先垂直切片，再按文件分组派工**；任务不是“一行状态”，而是“可独立验收的交付单元”。

## 1. 输入（缺一先补）

- 已确认需求基线 / PRD / 验收标准（`01-需求基线/`）。
- 已确认方案 / 接口 / 数据 / 迁移 / 回滚（`02-方案设计/`）。
- `项目档案.md` §2 代码地图、§7 项目规范、§8 交付与治理。
- 现有代码与测试入口（只读侦察；本步不改代码/配置）。

## 2. 拆解流程

1. **只读侦察**：读需求、方案、代码地图、现有测试与构建命令；标出未知项与待验证假设。  
2. **提取要求点（RP）**：每个需求点编号 `R-01`，写来源与验收标准（AC）；一条 AC 必须是“条件 + 动作 + 可观测结果”。  
3. **建依赖图**：数据/契约 → 服务 → 接口 → 前端 → 集成 → 发布；标外部依赖（他团队、环境、审批、数据）。  
4. **垂直切片**：每个任务尽量交付一条可演示、可测试的完整路径；禁止“所有 DB / 所有 API / 所有 UI”横向切。  
5. **写任务卡**：目标、AC、精确文件/接口、测试先行、验证命令、回滚/开关、DoD、依赖、规模。  
6. **定检查点**：每 2～3 个任务或每个阶段一个 checkpoint；高风险任务前置（fail fast）。  
7. **自检**：每个 RP 有任务；每个任务有 AC/验证/文件；依赖无环；无孤儿任务；`[P]` 不冲突；L 任务已拆。  
8. **确认与冻结**：`confirm_backlog` 展示清单 + 节奏；确认后冻结基线；后续变更走“变更记录”，**禁止覆盖未完成任务清单**。

## 3. 任务卡字段（最小集）

| 字段 | 要求 |
| --- | --- |
| ID | `T-01`，全局唯一；任务卡与总表一致 |
| 阶段 | 基础 / 主链路 / 集成 / 发布 / 收尾 |
| 任务 | 动词开头，一句话；含“和”通常说明该拆 |
| 要求点（RP） | `R-01` 等；无来源的任务不建 |
| 验收标准（AC） | `AC-01` 起；可观测、可判定；禁止“正常/正确” |
| 改动范围 | 精确文件/目录/接口；不写“相关模块” |
| 接口/契约 | 消费什么、产出什么；跨任务签名/字段 |
| 测试先行 | 先写哪个失败测试/探针；无测点写理由 |
| 验证命令与证据 | 命令 + 预期结果 + 证据落点 |
| 回滚/开关 | 高风险任务必填；无则写“不适用” |
| 依赖/并行 | 依赖任务号；可并行标 `[P]`；同文件不并行 |
| 规模 | XS/S/M/L；L 必须继续拆（>5 文件或 >1 个专注时段） |
| DoD | 项目级完成定义 + 本任务附加项 |
| 状态 | 未开始 / 进行中 / 阻塞 / 待验收 / 完成 / 取消 |

## 4. DoR 与 DoD

- **DoR（开工条件）**：需求/AC 明确；依赖就绪；环境/数据可用；方案/接口已确认；任务可独立验证。  
- **DoD（完成定义）**：AC 满足；测试通过；评审通过（如触发）；文档同步；证据留存；可回滚；任务清单已回写。  
- 项目级 DoD 写入 `项目档案.md` §8；任务级附加项写入任务卡。

## 5. 并行与子代理

- `[P]` 只给“不同文件、无未完成依赖、可独立验证”的任务。  
- 默认串行；一组一子代理；同文件/同函数集归一组；提示词含任务号/路径/RP/AC/验证/禁止事项。  
- 子代理返回：任务号、文件、RP 覆盖、验证命令+结果、未决项；编排核验后再回写完成。  
- 高风险/大改/破坏性变更：核验者≠实施者；核验不替代机器门禁。

## 6. 计划自检（确认前逐项过）

- [ ] 每个 RP 至少一个任务；每个任务至少一个 RP。  
- [ ] 每个任务有 AC、精确文件/接口、验证命令、DoD。  
- [ ] 依赖无环；顺序符合“契约/数据 → 服务 → 接口 → 前端 → 集成”。  
- [ ] 每个任务可独立验收；L 任务已拆；高风险任务已前置。  
- [ ] `[P]` 任务不同文件、无未完成依赖。  
- [ ] 有检查点；每个检查点有可执行验证。  
- [ ] 任务清单有变更记录；未覆盖旧清单前先问用户。  
- [ ] 运行 `python 规则/tools/validate_tasklist.py <清单路径>` 通过（如可用）。

## 7. 常见坑

- 按文件横向切：看似整齐，但无法端到端验收。  
- 任务过大：一个任务跨多个子系统、超过 5 个文件、或标题含“和”。  
- 只有“实现”没有“验证”：完成标准变成主观判断。  
- 把方案原样抄进任务：任务应说“改哪里、怎么验”，不是重复设计。  
- 覆盖旧清单：不同工作先问用户；同一工作就地更新并记变更。  
- 先实现后补测：任务卡必须写测试先行；无测点要写理由。

## 8. 输出

- 任务清单（总表 + 任务卡 + 覆盖矩阵 + 检查点 + 变更记录）。  
- 拆单摘要：任务数、RP 覆盖、关键依赖、风险、建议节奏。  
- 未决项/假设清单（需用户确认的放最前）。
