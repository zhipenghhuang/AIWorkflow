# 可观测与埋点（技能 · 随包生效）

> 用于：S2 方案、S4 实施、S8 发布；任何会影响生产可诊断性的变更。  
> 定位：可观测不是“上线后加日志”，而是**设计时就定义怎么知道它坏了、坏在哪、影响谁**。  
> 边界：产品业务埋点/指标口径见 `能力/00-能力契约.md` 的 `analytics` 与产品侧技能；本技能聚焦运行时可观测性。  
> 不适用：纯静态文案/无运行时行为的库；仍按项目要求保留最小日志与错误信息。

## 1. 先定义问题，再埋点

- 三个问题：**用户是否受影响？哪一段失败？为什么失败？**
- 每个关键路径至少能回答：请求量、成功率、延迟、错误类型、依赖状态、受影响租户/版本。
- 没有明确消费场景的日志/指标不加；禁止“先全埋，以后再分析”。

## 2. 三支柱 + 事件

| 支柱 | 最低要求 | 禁止 |
| --- | --- | --- |
| 日志 | 结构化（JSON/键值）、时间/级别/服务/版本/trace id、错误含类型与上下文 | 自由文本大段拼接；打印 token/密码/PII |
| 指标 | RED（请求率/错误率/时长）+ USE（利用率/饱和度/错误）+ 关键业务量 | 高基数标签（用户 id/原始 URL）；无单位/无窗口 |
| 追踪 | 入口生成/透传 trace id；跨服务/DB/队列/第三方建 span；记录关键属性 | 断链；把大对象写进 span |
| 事件/审计 | 发布、配置变更、权限/资金/不可逆操作留审计 | 只记“操作成功”，不记谁/什么/结果 |

## 3. SLI / SLO / 错误预算

- **SLI 从用户视角定义**：成功率、p95/p99 延迟、 freshness、可用性；写清统计窗口与排除项。
- **SLO 是目标不是口号**：例如“30 天内 99.9% 的登录请求在 2s 内成功”；必须有数据源与 owner。
- **错误预算**：预算消耗速率决定发布节奏；燃尽告警按多窗口（如 1h/6h/3d）设置，避免单点抖动。
- 没有 SLO 的项目：先为 1～2 条主链路建基线，不一次铺满。

## 4. 埋点实施规则

- 命名统一：`{domain}.{object}.{action}` / `{service}.{resource}.{measure}`；单位、类型、枚举值写进字典。
- 日志级别：ERROR=需人处理/影响用户；WARN=可恢复/降级；INFO=关键状态变化；DEBUG=排障开关，生产默认关。
- 错误分类：用户错误/依赖错误/系统错误/超时/限流/未知；同类错误聚合，不刷屏。
- 采样：高流量链路按比例/尾部采样；错误与慢请求优先保留；采样率可配置。
- 关联：trace id、request id、tenant/version、发布批次至少有一个能串起来。
- 成本：日志保留分级、指标基数预算、span 属性白名单；可观测成本进容量评估。
- AI/LLM 链路：记录模型/提示词版本、token 用量、首 token/总延迟、检索命中、工具调用、护栏触发、评测分；**不记录完整敏感 prompt/用户数据**。

## 5. 仪表盘与告警

- 每个服务/关键路径一张“黄金信号”面板：流量、错误、延迟、饱和度、依赖、发布标记。
- 告警必须**可行动**：症状而非原因、阈值有依据、附 runbook/负责人/升级路径；无行动项的告警删除。
- 发布看板叠加版本/提交标记；能对比发布前后。
- 告警演练：至少验证一次“触发→通知→处置”；禁止只写配置不验证。

## 6. 发布前后验证

- 发布前：在预发/灰度确认日志字段、指标、trace、告警规则真实产生；截图/查询链接留证。
- 发布后：对照基线看错误率、延迟、吞吐、业务量；观察窗口内不做无关变更。
- 故障时：先看影响面与最近变更，再用 trace/日志定位；保留现场，不先重启掩盖。
- 复盘：把“本可更早发现”的信号补进监控/告警。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “先上线，出问题再看日志” | 没有字段/关联 id，出事只能猜；补埋点本身也是变更风险。 |
| “日志越多越好” | 噪音抬高成本、淹没首错；按消费场景与级别取舍。 |
| “有告警就行” | 不可行动/无 owner 的告警会被忽略；必须能触发处置。 |
| “指标有了就等于可观测” | 没有 trace/日志上下文，指标只能告诉你“坏了”，不能告诉你“哪坏了”。 |
| “记录完整 prompt 方便排查” | 可能泄露 PII/密钥/商业数据；记录版本/哈希/摘要即可。 |

## 8. 红旗

- 关键路径无错误率/延迟指标，或指标无单位/窗口。
- 日志打印 token、密码、身份证、银行卡、完整请求体。
- trace id 不跨服务/队列，断在第一个异步边界。
- 告警无 runbook、无 owner、长期忽略。
- 发布记录没有版本标记，无法对比前后。
- 可观测成本无人负责，日志/指标无限增长。

## 9. 输出与 DoD

- 方案：SLI/SLO、关键路径信号、日志字段、指标/标签、trace 边界、告警与 runbook、成本预算。
- 实施：代码/配置 + 仪表盘/告警 + 验证证据（查询链接/截图/触发记录）。
- DoD：关键路径可回答“是否受影响/哪段失败/为什么”；无敏感信息泄露；告警可行动；发布前后可对比；成本有上限。
