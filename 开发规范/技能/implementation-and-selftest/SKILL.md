# 实现与自测（技能 · 随包生效）

> 用于：implement / verify 步；本技能=通用工程方法与自测标准。  
> **按端加载子技能**：页面/路由/组件/表单/交互 → `技能/frontend-implementation/SKILL.md`；API/服务/数据/任务/集成 → `技能/backend-implementation/SKILL.md`；全栈两端都读。  
> **工程质量条**：所有 implement 步同时加载 `技能/engineering-quality/SKILL.md` §1/§2/§3/§4；本技能只写实现方法，不重复质量条。  
> 子技能不替代本技能：小步、最小改动、调试、自测、证据仍按本技能执行。

## 0. 实现前确认

- 读任务卡：AC、精确文件/接口、测试先行、回滚/开关、DoD。
- 读对应设计：02（+02B/02C/02D/02E/02F 如涉及）。
- 明确“怎么证明它对”：失败测试/探针/验收命令；无测点写理由。

## 1. 小步红绿（自带验证的实现法）

- 每完成一个可验证单元：先想「我怎么证明它对」（失败用例/边界探针）→ 实现 → 证明通过 → 再进下一个。
- 缺陷轨的「修前红证」是同一方法的强制版（`规则/缺陷/缺陷修复协作.md`）。
- 禁攒大招：一个改动大到无法快速验证时，拆。

## 2. 最小改动 · 手术式修改

- 只动与目标相关的行；不顺手重排/重命名/升级无关依赖。
- 开发阶段优先删旧结构/旧数据/死代码，不保留兼容层；上线/真实数据/外部契约除外（`技能/engineering-quality/SKILL.md` §1.2）。
- 动手前说明拟改文件（`AGENTS.md` §0.5）；改动面超出预期先停下说明。

## 3. 调试方法论（先析因后动手）

1. **复现**：拿到稳定复现（最小步骤+数据）。
2. **假设**：列出 2～3 个候选根因（不是猜一个就改）。
3. **二分**：日志/断点/替换/注释把范围对半切，直到锁定。
4. **修因**：修根因不修表象；禁「加个 try 先绕过」。
5. **回归**：按修复路径+影响面验证；留证据。
- 方案无效 **2** 次：换假设或换手段，禁同命令空重跑（`AGENTS.md` §0.3-7）。

## 4. 自测标准（提交前过）

- 每条验收点有对应验证动作与结果（命令+输出）。
- 边界与错误路径至少各试 1 条（空值/非法/重复/越权其一）。
- 未验证路径显式写「未验证」（`规则/工作流.md` §3.1）。
- 收尾写三维影响：UX/DX/AX 各一句；无证据的维度标「未验证」（`技能/engineering-quality/SKILL.md` §1.1）。
- 可测逻辑同步补测；装配 unit-test-gen 时按覆盖缺口驱动（`能力/00-能力注册表.md`）。

## 5. 测试层次与工程动作

- **单测**：纯逻辑/边界/异常；红→绿→重构；禁无断言凑覆盖率。  
- **集成/契约**：跨服务/接口字段/错误码；契约先行，改约先确认。  
- **E2E/冒烟**：主链路 + 关键分支；发布前跑最小充分集。  
- **迁移/配置**：幂等、可回滚/前滚；先小环境验证；大表看锁与时长；开发阶段允许重建 schema/数据/夹具，不写旧字段/旧记录兼容。  
- **开关/降级**：高风险变更用特性开关；默认值安全；回滚路径可执行。  
- **文档**：行为/接口/配置变化与实现同变更；只写现行有效。

## 6. 提交卫生

- 一类改动一提交；提交信息按 `规则/工作流.md` §2；无文件变更不硬造提交。
- 提交前确认：改动范围、验证证据、未验证项、文档同步、敏感信息零入库。
