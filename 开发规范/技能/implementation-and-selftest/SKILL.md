# 实现与自测（技能 · 随包生效）

> 用于：implement / verify 步；本技能=通用工程方法与自测标准。  
> **按端加载子技能**：页面/路由/组件/表单/交互 → `技能/frontend-implementation/SKILL.md`；API/服务/数据/任务/集成 → `技能/backend-implementation/SKILL.md`；全栈两端都读。  
> **工程质量条**：所有 implement 步同时加载 `技能/engineering-quality/SKILL.md` §1/§2/§3/§4；本技能只写实现方法，不重复质量条。  
> 子技能不替代本技能：小步、最小改动、调试、自测、证据仍按本技能执行。

## 0. 实现前确认

- 读任务卡：AC、精确文件/接口、测试先行、回滚/开关、DoD、**实施预检**行（无则本步补）。
- 读对应设计：02（+02B/02C/02D/02E/02F 如涉及）；命中权限/状态/数据基数/多表面时加读 `技能/cross-layer-consistency/SKILL.md`。
- **实施质量门**：`规则/核心/实施质量门.md` DEV-IQ-01～04、**09～10**（SC 先于代码；预检先于代码；重要面硬补；冲突 OPEN）。
- **先抽方案条款**：把方案/PRD/技术设计中的「必须/应/允许/不得/可/仅/同一/不因/Then/状态/权限/重复/补传/并发/边界/异常」逐条抽成 `SC-xx`，写入任务卡（覆盖矩阵 §4.1 追溯 + 任务卡 SC 表）；没有条款清单不开工。固定覆盖见实施质量门 §4。
- 明确“怎么证明它对”：失败测试/探针/验收命令；**预期只认 SC/AC**，不认现网实现；无测点写理由。
- 先找同仓库既有正确写法（另一写入口/另一消费方/既有回归用例）；不复用就说明差异。
- 文档冲突或「表 vs 注」打架 → 停，登记 OPEN，不静默选边（DEV-IQ-04）。

## 0.5 实施预检（自主 · 强制 · DEV-IQ-09/10）

> **写任何业务代码之前**完成本节。细则与扫描表只认 `规则/核心/实施质量门.md` §3；此处只写执行顺序。

1. **自主扫描**：按实施质量门 §3.1 逐面判定命中/不适用（不等用户点名安全、性能、失败路径）。
2. **出示预检**：输出【实施预检】一行（形状见实施质量门 §3.2）；写入任务卡「实施预检」或对话首条实施回执。L0 无行为 → `na` + 理由后可跳过下面 3～4。
3. **命中则加载**：只读该面指向技能的**当前节**（禁通读）；把硬补项扩进 SC 表。
4. **先红后绿**：重要面硬补对应的失败用例/探针先写（或先定命令预期）→ 再实现 → 证明通过。禁止先只做主路径。
5. **砍验**：只能 DEV-IQ-05 债项化；禁止口头「以后再补」。

反合理化见实施质量门 §3.3；与 `engineering-quality` §7.1 一致。

## 1. 小步红绿（自带验证的实现法）

- 每完成一个可验证单元：先想「我怎么证明它对」（失败用例/边界探针）→ 实现 → 证明通过 → 再进下一个；**预检命中面优先**做对应单元。
- 缺陷轨的「修前红证」是同一方法的强制版（`规则/缺陷/缺陷修复协作.md`）。
- 禁攒大招：一个改动大到无法快速验证时，拆。

## 2. 最小改动 · 手术式修改

- 只动与目标相关的行；不顺手重排/重命名/升级无关依赖。
- 开发阶段优先删旧结构/旧数据/死代码，不保留兼容层；上线/真实数据/外部契约除外（`技能/engineering-quality/SKILL.md` §1.2）。
- 动手前说明拟改文件（`AGENTS.md` §0.5）；改动面超出预期先停下说明。

## 3. 调试方法论（先析因后动手）

1. **复现**：拿到稳定复现（最小步骤+数据）。
2. **假设**：列出 2～3 个候选根因（不是猜一个就改）。
3. **二分**：日志/断点/替换/注释把范围对半切，直到锁定。
4. **修因**：修根因不修表象；禁「加个 try 先绕过」。
5. **回归**：按修复路径+影响面验证；留证据。
- 方案无效 **2** 次：换假设或换手段，禁同命令空重跑（`AGENTS.md` §0.3-7）。

## 4. 自测标准（提交前过）

- 每条验收点有对应验证动作与结果（命令+输出）。
- **逐条 SC 自测**：方案条款清单每条至少一条验证；有否定/边界/重复/权限/状态则补对应项；不把 QA 当第一道覆盖。
- **预期诚信（DEV-IQ-02）**：断言/探针必须能指回 SC/AC/Then；与方案冲突 → 停工，禁止改断言迁就代码（禁刷绿）。
- 边界与错误路径至少各试 1 条（空值/非法/重复/越权其一）。
- 命中权限/状态/多值对象时：角色正反、第二次写、并发/重试、既有行但缓存空，至少各 1 条；同类路径扫描结果一并记录。
- **预检命中面**：实施质量门 §3.1 该面「命中后必须」每条有自测/证据；缺一项不得标任务完成。
- 新增动作码/审计/异步任务：中文标签与提交+终态同批（DEV-IQ-07）；否则债项化，不得静默用技术码冒充完成。
- 未验证路径显式写「未验证」（`规则/工作流.md` §3.1）。
- 收尾写三维影响：UX/DX/AX 各一句；无证据的维度标「未验证」（`技能/engineering-quality/SKILL.md` §1.1）。
- 可测逻辑同步补测；装配 unit-test-gen 时按覆盖缺口驱动（`能力/00-能力注册表.md`）。

## 5. 测试层次与工程动作

- **单测**：纯逻辑/边界/异常；红→绿→重构；禁无断言凑覆盖率。  
- **集成/契约**：跨服务/接口字段/错误码；契约先行，改约先确认。  
- **E2E/冒烟**：主链路 + 关键分支；发布前跑最小充分集。  
- **迁移/配置**：幂等、可回滚/前滚；先小环境验证；大表看锁与时长；开发阶段允许重建 schema/数据/夹具，不写旧字段/旧记录兼容。  
- **开关/降级**：高风险变更用特性开关；默认值安全；回滚路径可执行。  
- **文档**：行为/接口/配置变化与实现同变更；只写现行有效。

## 6. 提交卫生

- 一类改动一提交；提交信息按 `规则/工作流.md` §2；无文件变更不硬造提交。
- 提交前确认：改动范围、验证证据、未验证项、文档同步、敏感信息零入库。
