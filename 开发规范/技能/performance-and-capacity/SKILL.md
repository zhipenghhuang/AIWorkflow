# 性能与容量（技能 · 随包生效）

> 用于：S2 技术方案的性能/容量部分；高并发、大数据量、批处理、报表、导出、实时链路、发布前容量评估。  
> 产出：工作量模型、性能目标、瓶颈与方案、压测计划、容量/扩容触发条件、观测与降级。  
> 原则：**先量化，再优化；先找瓶颈，再扩容；没有基线的“优化”不算优化。**

## 1. 工作量模型

- 用户/并发：DAU、峰值在线、并发请求、突发倍数。
- 请求：QPS/TPS、读写比、平均/峰值 payload、批量大小。
- 数据：存量、日增、热数据比例、保留周期。
- 任务：定时/批处理/导出/报表的窗口与并发。
- 外部依赖：第三方限流、超时、配额。

## 2. 目标与 SLO

- 延迟：p50/p95/p99；接口/页面/批任务分别定。
- 吞吐：目标 QPS/TPS；错误率；超时率。
- 资源：CPU/内存/连接池/磁盘/网络利用率上限。
- 可用性/降级：故障时保什么、降什么。
- 成本：单位请求/单位数据成本上限（如适用）。

## 3. 瓶颈假设与设计

- 应用：同步阻塞、N+1、无界集合、锁竞争、线程/连接池。
- 数据库：慢查询、缺索引、大事务、锁等待、连接数、分页深翻。
- 缓存：命中率、穿透/雪崩、一致性、容量。
- 队列/异步：积压、重复消费、顺序、死信。
- 网络/第三方：超时、重试风暴、带宽、DNS/TLS。
- 前端：包体、首屏、图片、长列表、频繁重渲染。

## 4. 方案手段

- 水平/垂直扩展、读写分离、分片、分区、冷热分离。
- 缓存（本地/分布式）、批量、异步、预计算、限流、降级。
- 连接池/线程池/队列容量；背压与超时预算。
- 数据库索引/查询重写/归档；避免大事务。
- 前端懒加载/虚拟列表/图片优化/缓存策略。

## 5. 压测与验证

- 类型：基准/负载/压力/尖峰/浸泡；按风险选择。
- 环境：尽量接近生产；数据量/分布/网络/依赖要说明。
- 工具：k6 / JMeter / Locust / Gatling / 浏览器性能面板（按项目）。
- 成功标准：目标延迟/吞吐/错误率/资源上限；失败即记录瓶颈。
- 观测：RED/USE 指标、慢查询、GC、连接池、队列积压、前端 Core Web Vitals。

## 6. 容量与发布

- 容量=目标峰值 × 安全系数（如 1.5～2）；写清扩容触发阈值。
- 扩容/缩容步骤、成本、回滚；云资源配额/冷启动。
- 发布前容量检查；发布后观察期与告警阈值。
- 大促/活动/批量任务提前演练。

## 7. 常见坑

- 没有基线就优化；只测平均不测 p95/p99。
- 压测数据量太小、依赖全 mock，结论不可用。
- 只扩应用不查数据库/第三方瓶颈。
- 重试无预算导致雪崩；缓存无降级。
- 容量只算 CPU 不算连接/磁盘/带宽/配额。
