# API 设计（技能 · 随包生效）

> 用于：S2 技术方案的接口/契约部分，或任何新增/修改对外/对内 API。  
> 产出：OpenAPI/契约 + 示例 + 错误码 + 兼容/弃用说明；重大变更进 ADR。  
> 原则：**契约先行、服务端校验为准、错误可程序化处理、兼容优先**。

## 1. 资源与操作

- 资源命名用名词；动作用 HTTP 方法/明确 RPC。
- URL/版本/租户/环境边界；避免动词化资源。
- 批量/导入/导出/长任务：同步/异步/分页/回调。
- 幂等：创建用幂等键；终态操作重入拒绝；重复提交可识别。

## 2. 请求与响应

- 必填/类型/范围/枚举/长度/格式；服务端校验为准。
- 分页/过滤/排序：参数名、默认值、上限、稳定排序。
- 时间/金额/精度/时区/枚举：统一格式。
- 错误：稳定错误码、HTTP 状态、用户消息、字段级错误、traceId。
- 不泄露堆栈/密钥/内部地址。

## 3. 版本与兼容

> 开发阶段（`项目档案` §1 `项目阶段=开发`）且非外部公开契约：可直接改字段/枚举/路径，不写旧客户端兼容分支；上线/外部契约按本节。
- 版本策略（URL/Header/媒体类型）；弃用周期与通知。
- 加字段不破坏老客户端；删改走版本/宽限期。
- 契约测试；消费者驱动契约（如适用）。
- 文档与代码同变更；OpenAPI/示例可导入 Apifox/Postman。

## 4. 安全

- 认证/授权/作用域/资源级权限；不假设调用方已鉴权。
- 输入校验、注入、SSRF、文件上传、反序列化。
- 速率限制/配额/防重放；敏感字段脱敏。
- 审计日志：谁、何时、对什么、结果。

### 4.1 权限矩阵与 UI 契约

- 按 `技能/cross-layer-consistency/SKILL.md` 写角色 × 能力 × 数据范围 × 端点；每个角色至少一条允许 + 一条拒绝。
- UI 可见的菜单/按钮/字段必须有同权限 API；只隐藏不校验 = 越权风险。
- 服务端做资源级授权；403/404 语义明确；业务冲突（唯一约束/重复写/状态冲突）用 409/稳定业务码，不把数据库异常漏成 500。
- 权限策略只允许一个实现层；禁止各视图各写一套判断。
- 契约测试覆盖：角色正反、状态正反、第二次写、空缓存+既有行。

## 5. 可靠性

- 超时/重试/退避/熔断；重试只对幂等操作。
- 限流/降级/排队；失败语义与补偿。
- 可观测：RED 指标、结构化日志、trace、错误率/延迟告警。
- 依赖故障时的降级行为。

## 6. 输出与常见坑

- 输出：端点/方法/路径、请求/响应 schema、错误码、鉴权、分页、幂等、限流、示例、兼容说明。
- 坑：只写成功响应；错误码随意；分页无上限；无幂等；破坏性改字段；文档与实现不一致；无超时/重试预算。

## 7. DoD

- 资源/操作/路径/方法清楚；请求/响应 schema 与示例一致。
- 错误码/错误体/失败语义可判定；分页/排序/过滤有上限。
- 鉴权/资源级授权/限流/配额明确；写操作幂等。
- 版本/兼容/弃用策略明确；破坏性变更已确认。
- 超时/重试/降级/可观测齐；契约测试与负面用例通过。
- 文档与实现一致；未决项有 owner/截止。
