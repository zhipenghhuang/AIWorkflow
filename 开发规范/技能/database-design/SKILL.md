# 数据库设计（技能 · 随包生效）

> 用于：S2 技术方案的数据/存储部分，或任何涉及表结构、索引、事务、迁移、分库分表的变更。  
> 产出：ER/表结构/索引/事务边界/迁移与回滚/容量与备份说明；重大决策进 ADR。  
> 原则：**按查询与事务设计，不按“看起来整齐”设计**；先保证正确性与可恢复，再谈性能。

## 1. 概念与逻辑模型

- 实体、关系、基数（1:1/1:N/N:N）、聚合边界。
- 主键策略：自增/雪花/UUID/业务键；全局唯一与可读性。
- 外键/唯一/检查约束；软删除与唯一索引冲突。
- 多租户：租户字段、隔离级别、越权面。
- 数据生命周期：创建/更新/归档/删除/留存/合规。

## 2. 规范化与反规范化

- 默认 3NF；为高频查询/报表做受控反规范化。
- 冗余字段必须有同步机制与一致性校验。
- 大字段/JSON：何时用、如何索引、如何校验/演进。
- 金额/精度/时间/时区/枚举：类型与口径写死。

## 3. 索引

- 按查询模式建索引：等值/范围/排序/覆盖/联合列顺序。
- 避免过度索引（写放大、空间、优化器负担）。
- 唯一索引与业务幂等键；分页/排序的索引支持。
- 用执行计划/慢查询验证，不凭感觉。

## 4. 事务、并发与一致性

- 事务边界：一个业务动作一个事务；避免长事务/大事务。
- 隔离级别与锁：脏读/幻读/死锁；重试策略。
- 并发更新：乐观锁/悲观锁/版本号；幂等键。
- 跨服务一致性：本地事务/Outbox/Saga/补偿；不要假设分布式事务。
- 缓存一致性：失效/双写/延迟双删；先写库还是先写缓存。

### 4.1 复用既有模型/唯一约束（强制）

- 复用现有表/模型前，先列出它的唯一约束、唯一索引、外键与软删除语义；逐条写「它代表什么业务槽位」。
- 写清基数 0/1/N：谁创建、谁分配下一个槽位、重复/并发/重试怎么处理、冲突返回什么业务码。
- 同一业务对象的多个写入口（如单据附件 vs 盖章附件）必须逐一核对；不能假设「另一个入口已经处理」。
- 关系行与 JSON 旁路并存 → 明确主源和对账/重建机制；必须测「关系行已存在、JSON 列表为空」。
- 唯一约束不是 DBA 细节，是业务规则；破坏它前先改业务语义并确认。

## 5. 迁移与回滚

> 开发阶段（`项目档案` §1 `项目阶段=开发`）可直接重建表/索引/数据，不写双写/影子表/回填；上线/真实数据才按本节。
- 迁移脚本幂等、可重复执行；版本化。
- 大表变更：锁、时长、在线 DDL、分批回填、双写/影子表。
- 回滚/前滚：数据兼容、老代码/新代码共存。
- 备份/恢复演练；迁移前快照；失败停止条件。

## 6. 性能与容量

- 数据量/增长/峰值 QPS；单表/单库容量上限。
- 分区/分表/分库/读写分离的触发条件与代价。
- 索引命中、慢查询、连接池、批量写入。
- 归档/冷热分离；备份窗口与恢复目标（RPO/RTO）。

## 7. 安全与审计

- 最小权限账号；应用账号不做 DDL。
- 敏感字段加密/脱敏/审计；SQL 注入防护（参数化）。
- 生产数据不外带；测试数据脱敏。

## 8. 输出与常见坑

- 输出：ER 图、表/字段/索引清单、事务与并发说明、迁移/回滚、容量/备份。
- 坑：只画 ER 不写查询；索引拍脑袋；长事务；迁移不可回滚；软删除破坏唯一约束；分库分表过早；忽略备份恢复。
