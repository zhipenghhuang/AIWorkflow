# 轻量测试设计与执行（技能 · 随包生效）

> 用于：`solo.test`；`change.verify` / `iterate.gates` 在无 QA、且触及用户路径/业务规则/接口行为时**必用**（见 `轻量交付.md` §4.1）。
> 目标：用**最小充分集**做**开发自验**——回答「这次改动能不能用」，不是堆用例数量，也不是版本准出。
> 边界：不替代完整测试包的测试计划/用例库/覆盖三闸/准出门；结论用语写「开发自验 / 可交付」，禁写「已准出」。
> 口径：`规则/核心/轻量交付.md` §4～§4.1；门禁与证据见 `验证/README.md`；P0 未过不得判整体通过。
> 不确定「是否要正式测 / 是否够自验」→ 推荐路径 + 一问确认，不静默跳过用户路径。

## 0. AC 走查（硬）

对照方案卡/需求基线/任务卡验收表：每条 AC → 通过 / 失败 / 未测+理由；未走查不得写 PASS。走查可与测试点表合并，但 AC ID 必须可对账。

## 1. 先建测试卡（5～10 行）

在方案卡的「测试策略」或测试报告开头写清：

| 项 | 内容 |
| --- | --- |
| 变更点 | 改了什么（文件/接口/页面/规则） |
| 影响面 | 直接受影响 + 邻接（谁调用、谁展示、谁依赖） |
| 风险 | 主链路阻断 / 数据 / 权限 / 资金 / 兼容 / 性能 / 安全 |
| P0 | 不过就不能交付的 1～5 条 |
| P1 | 重要但可带缺口交付的 |
| 测试类型 | 功能 / 边界 / 权限 / 异常 / 回归 / 兼容 / 探索式（按风险选） |
| 环境/数据 | 构建、URL、账号、测试数据、清理方式 |
| 不测 | 明确不测项 + 理由 + 接受人 |

**P0 判定**

- 主业务链走不通、数据错/丢、越权、资金错、核心页面打不开 → P0。
- 拿不准向上一档；P0 不因「实现简单」降级。

## 2. 设计最小充分集

按顺序展开，不跳：

1. **主路径**：用户从入口到结果的完整故事，至少 1 条成功。
2. **规则/状态**：合法状态迁移抽样；有状态对象至少 1 条非法跃迁。
3. **边界**：数字/长度/时间/金额/分页取 `min-1 / min / max / max+1` 的代表值。
4. **权限/数据域**：跨角色/租户至少 1 条；文档未声明时做角色冒烟，不假装已覆盖。
5. **异常/失败**：空值、重复提交、网络失败、超时、脏数据、依赖不可用。
6. **写操作**：失败或写后回查 + 清理（可并入主条）。
7. **UI/体验**：布局、遮挡、截断、空态/加载/错误提示、按钮状态、文案减法；截图同帧检查。
8. **回归**：原失败用例 + 冒烟子集 + 影响面组；稳定主链路优先脚本。

**技法速用**

- 等价类：有效/无效各取代表，不穷举同类。
- 边界值：数字、长度、时间、金额、分页都适用。
- 判定表：条件组合互斥时一格一用例。
- 状态迁移：状态 × 事件矩阵；每个非法跃迁一条负向。
- 场景法：入口 → 动作 → 观测点；主路径 + 分支变体。
- 错误推测：按历史缺陷/常见漏测补，不替代前五类。

**最小覆盖（与变更类型匹配）**

| 变更 | 至少覆盖 |
| --- | --- |
| 纯文案/样式 | 受影响页面 + console 无 error |
| 前端行为 | 主路径 + 1 边界 + 1 异常 + 受影响回归 |
| 后端/接口 | 主路径 + 1 边界 + 1 错误码/权限 + 受影响回归 |
| 数据/迁移 | 上述 + 迁移前后核对 + 回滚路径 |
| 高风险 | 停，升级完整档按 L2/L3 检查矩阵 |

## 3. 执行

**前置**

- 构建/环境可访问；账号/数据就绪；知道本次构建对应的提交。
- 先读方案卡 AC 与测试点；预期来自需求/AC/契约/用户裁决，不按现网实现改预期。
- 记录开始时间；截图/证据必须晚于任务开始。

**顺序**

1. 先冒烟：主链路能不能通；不通先停下报 P0，不继续铺量。
2. 再功能：主路径 → 状态/规则 → 边界 → 权限 → 异常。
3. UI 变更先看页面，再看 Network；不猜未见 API，不拿别的接口替代。
4. 写操作查回显/列表/详情/状态；结束后清理测试数据。
5. 前端看 console error、失败请求、关键响应、桌面/移动视口、空态/错误态。
6. 发现用例之外的问题（布局/console/network/文案）记录位置/现象/证据/影响，不静默忽略。

**证据**

- 失败：截图钉住断言面 + 最小复现步骤 + 环境/账号/时间；能取日志/响应就取。
- 通过：至少一条可复核证据（命令输出/响应/截图路径）；不写「已验证」了事。
- 证据路径必须存在；聊天里说「测过了」不算。
- 真实 PII/密钥不入证据；测试数据用合成数据并清理。

## 4. 失败分类

| 分类 | 判定 | 处置 |
| --- | --- | --- |
| 实现缺陷 | 需求清楚，代码行为不符 | 修代码；修后回归 |
| 产品问题 | 需求冲突/缺失/不可行 | 停下问用户；不按现网实现改预期 |
| 环境/数据 | 环境不可用、数据错、依赖缺失 | 修复环境/换数据；记录阻塞 |
| 测试问题 | 步骤/断言/数据写错 | 修正用例后重跑；不计产品缺陷 |
| 待定 | 证据不足/偶发 | 有界复现 2 次；仍不确定记频率与缺口，不硬判 |

**严重度**

- S1 阻断/数据错/越权/资金错；S2 主功能受损但有绕过；S3 一般；S4 文案/体验。
- 拿不准一问；不把 S1 写成「小问题」。

## 5. 修复与回归

- 每个失败修复后立即跑：原失败用例 + 冒烟子集 + 影响面组；不等批末。
- 同一方案无效 2 次 → 换路径或升级，不继续重试刷绿。
- 回归结果就地覆盖，只留最新；报告写轮次与遗留。
- 已脚本化的稳定回归优先脚本；脚本失败先分诊（产品/环境/数据/脚本），不直接判产品缺陷。
- 不手改结果表、不跳测试、不禁告警凑绿；豁免须用户批准并记录。

## 6. 报告

按 `规则/模板/40-交付与发布/轻量测试报告模板.md` 写；最少：

- 范围/环境/构建/测试时间；
- 测试点与结果表（ID/类型/场景/预期/实际/结果/证据）；
- P0/P1 汇总；失败项分类/处置/回归；
- 未测项/缺口/风险接受；
- `verdict: PASS | CONDITIONAL | FAIL`。

**判定（开发自验）**

- `PASS`：P0 全过，AC 走查齐，P1 无阻断，证据可打开，缺口已列。
- `CONDITIONAL`：P0 全过，剩余缺口非 P0，用户明确接受并记录接受人/期限。
- `FAIL`：任一 P0 未过、AC 未走查、证据缺失、关键路径未测且无法说明。
- 非 PASS 禁用「全部通过/可发布/没问题/已准出」；只能写「开发自验未通过/有条件可交付/阻塞」。
- 同项目已有测试包正式报告/准出 → 引用对方结论，本技能不冒充准出。

## 7. 反合理化

| 常见说法 | 现实 |
| --- | --- |
| 「build 过了就算测过」 | 构建只证明能编译，不证明用户路径能用。 |
| 「主路径没问题，边界不用测」 | 小项目的返工常来自空值/重复提交/权限/超长。 |
| 「这个 API 肯定存在」 | 未见/未调用的接口不能当已验证；先看 Network/文档/代码。 |
| 「重跑一次过了就算过」 | 偶发要看频率与分诊；一次通过可能是偶然。 |
| 「失败不重要，先交付」 | 要记录缺口/风险接受；P0 不得带病通过。 |
| 「AI 说通过了」 | 结论要有证据路径；自述不算证据。 |
| 「测试报告太麻烦，写收尾里」 | 至少写 verdict/P0/缺口；否则无法对账。 |
| 「无 QA / 个人项目不用测」 | 跳过提测单 ≠ 跳过自验；L1+ 用户路径仍须最小充分集。 |
| 「build 绿 + 自验 PASS = 已准出」 | 自验只证本轮可用；版本准出归测试包/测试负责人。 |

## 8. 红旗

- 只跑 build/lint，没有用户路径。
- 测试没有环境/构建/账号信息，无法复现。
- 失败没有截图/响应/日志，只有「有问题」。
- 把产品冲突当实现缺陷直接改代码。
- P0 未过仍写「基本可用/有条件通过」。
- 测试数据含真实 PII/密钥，或写操作后不清理。
- 报告数字与证据/结果表不一致。

## 9. 验证 / DoD

- [ ] 测试卡有变更点/影响面/P0/P1/类型/环境/不测项。
- [ ] AC 走查齐；主路径、边界、异常、权限（适用时）、回归至少各一条。
- [ ] 失败有证据与分类；修复后已回归。
- [ ] P0 全过；非 P0 缺口已列并有人接受。
- [ ] 报告 verdict 与结果表一致；证据路径存在；用语为开发自验。
- [ ] 未测项显式列出，没有「应该没问题」。
- [ ] 需要正式测试计划/用例库/准出时，已提示转测试包，不在本技能内冒充。
