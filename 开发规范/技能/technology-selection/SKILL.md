# 技术选型（技能 · 随包生效）

> 用于：S2 技术方案中涉及技术栈/框架/数据库/中间件/云服务/关键依赖选型时。  
> 产出：选型矩阵 + POC/验证证据 + ADR（模板 `规则/模板/20-设计与技术/ADR模板.md`）。  
> 原则：**先约束，再候选，再证据，最后决策**；禁止“最新/最火/我会”式拍脑袋。

## 1. 先写约束

- 业务规模/增长预期、峰值/数据量、延迟/吞吐目标。
- 团队技能与维护成本、交付周期。
- 部署环境（云/私有化/离线/信创）、合规与数据驻留。
- 预算/许可证/采购流程、供应商支持。
- 现有系统兼容/迁移成本/退出成本。

## 2. 候选与硬门槛

- 每类至少 2 个候选（除非事实标准）。
- 硬门槛先过滤：许可证、合规、平台支持、社区活跃度、安全记录、长期维护。
- 不把“星数”当唯一依据；看 release 节奏、issue 响应、CVE、文档质量。

## 3. 评价矩阵（示例权重）

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 功能匹配 | 25% | 核心场景是否直接支持；缺口要二次开发多少 |
| 非功能 | 20% | 性能/可用性/扩展性/一致性 |
| 团队与维护 | 15% | 学习曲线、招聘、排障、升级 |
| 生态与集成 | 10% | 现有系统/工具/云服务集成 |
| 安全与合规 | 10% | CVE、审计、权限、数据合规 |
| 成本/TCO | 10% | 许可、云资源、人力、迁移/退出 |
| 供应商/锁定 | 5% | 锁定风险、替代方案、社区治理 |
| 成熟度 | 5% | 生产案例、版本稳定性、LTS |

- 每项 1～5 分，写证据来源（官方文档/压测/POC/案例）。
- 加权总分只作参考；硬门槛/一票否决优先。

## 4. POC / Spike

- 只验证**最危险的假设**：性能、兼容、迁移、关键 API、许可。
- 写成功标准、时间盒、环境、数据量；结果留证据。
- POC 不追求完整功能；验证不了就写“待验证 + 风险”。

## 5. 决策与 ADR

- 选了什么、放弃什么、为什么、代价、什么条件下改回。
- 迁移/回滚/退出方案；供应商锁定的缓解。
- 版本/许可/支持周期；升级策略。
- 架构级选型必须 ADR；方案里只放结论与链接。

## 6. 常见坑

- 用简历/喜好选型；只看 demo 不看生产约束。
- 忽略许可证（AGPL/GPL/商业条款）与 TCO。
- 不做 POC 就承诺性能/兼容。
- 没有退出方案；被单一供应商/版本锁死。
- 选型与团队能力不匹配，交付后无人维护。
