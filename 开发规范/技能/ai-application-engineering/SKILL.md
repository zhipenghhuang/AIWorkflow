# AI 应用工程（技能 · 随包生效）

> 用于：新增/修改 LLM、RAG、Agent、分类/生成/抽取、embedding、提示词、模型或工具调用。  
> 定位：AI 功能首先是**软件功能**；先满足需求、安全、可观测、可回滚，再谈模型效果。  
> 不替代：普通过程仍按 `技能/solution-design/SKILL.md`、`技能/engineering-quality/SKILL.md`、`技能/threat-modeling/SKILL.md` 执行。  
> 不适用：无模型/无生成行为的确定性功能；走普通工程技能，不硬套评测/护栏。

## 1. 需求与失败成本（先定边界）

- 任务定义：输入、输出、成功标准、不可接受输出、谁使用、使用频率。
- **失败成本分级**：建议/草稿（可人工改）｜辅助决策（需人确认）｜自动执行（不可逆/对外/资金/权限）。级别决定人工确认、护栏与回滚要求。
- 非目标：不把“模型更聪明”当需求；不把开放问答塞进确定性流程。
- 数据边界：哪些数据可进模型/可出模型、保留多久、是否跨境、供应商条款；PII/密钥/商业机密默认不进 prompt。
- 产品需求（模型行为、评测、兜底、人工接管）应与 PRD/验收标准对齐；缺失时列出假设与待确认。

## 2. 参考架构（按需，不默认堆组件）

```text
入口/权限 → 上下文组装（指令/数据/检索） → 模型网关（路由/限流/缓存）
→ 输出校验（schema/规则/安全） → 业务动作/人工确认 → 观测与评测
```

- **模型网关**：统一供应商/模型、超时/重试/降级、配额与成本、密钥管理；禁止业务代码散落供应商 SDK。
- **提示词版本化**：提示词与代码同仓/同版本；变更可追溯、可回滚；禁止线上手改无记录。
- **结构化输出**：优先 JSON Schema/函数调用；服务端再校验，不信任模型输出。
- **上下文**：指令与数据分隔（明确边界/定界符）；控制长度；只放必要信息；检索结果标注来源。
- **兜底**：超时/限流/模型不可用/低置信 → 明确降级（模板/人工/稍后重试），不静默失败。
- **人工接管**：高风险/低置信/越权请求必须可转人工，且保留上下文。

## 3. RAG / 知识库

- 切分：按语义/标题/段落，保留元数据（来源、版本、权限、时间）；避免固定长度切断语义。
- 检索：关键词 + 向量混合优先；必要时 rerank；返回 top-k 与分数供排障。
-  grounding：回答必须能引用检索片段；无依据时明确“不知道/需确认”，不编造。
- 权限：检索前做数据域过滤；禁止“先检索全部再让模型保密”。
- 新鲜度：文档版本/更新时间进索引；过期内容降权或下线；重建索引可重复。
- 评测：检索召回/精度、引用正确率、无依据回答率、答案忠实度；不要只评“像不像”。

## 4. Agent / 工具调用

- 工具白名单 + 最小权限；参数服务端校验；禁止模型直接拼 SQL/命令/URL。
- 不可逆动作（支付、删除、发布、对外发送）必须人工确认或二次授权；默认只读/草稿。
- 循环上限、步数上限、超时、预算上限；失败可中止并回报，不无限重试。
- 幂等键/去重；工具结果结构化回传；审计谁在何时让 Agent 做了什么。
- 沙箱/隔离：代码执行、文件、浏览器、网络访问按最小权限；输出不当指令执行。
- 提示注入：把网页/文档/工具返回视为不可信数据；不因其中“指令”扩大权限或泄露系统提示。

## 5. 评测（Evals）

- **黄金集**：代表性 + 边界 + 对抗 + 历史缺陷；每条有输入、期望/评分规则、难度、来源。
- 评分：精确匹配/规则断言优先；开放输出用 rubric + 人工抽样；LLM-as-judge 需校准并记录偏差。
- 回归：提示词/模型/检索/参数变更必须跑同一套评测；记录版本、数据集哈希、通过率。
- 线上：抽样人工评审、用户反馈、失败聚类；离线分与线上指标同时看。
- 阈值：按失败成本定通过线；允许方差要写明（如 N 次中 ≥M 次通过）。
- 红队：提示注入、越狱、数据外泄、系统提示泄露、过度代理、无限消耗；高风险场景上线前做。

## 6. 安全、隐私与合规

- 输入：注入/越狱/超长/多语言/编码绕过；输出：XSS/ Markdown 注入/恶意链接/代码执行。
- 数据：最小化、脱敏、保留期限、删除路径、供应商数据使用条款；日志不落完整敏感 prompt。
- 权限：模型不拥有比调用者更大的权限；工具调用按用户身份鉴权。
- 内容安全：按业务/地区要求做分类/过滤/申诉；高风险输出有人工复核。
- 供应链：模型/权重/数据集/插件来源与许可；版本固定；变更评审。
- 合规参考：OWASP Top 10 for LLM 2025、NIST AI RMF / Generative AI Profile、ISO/IEC 42001、EU AI Act（按适用性）。

## 7. 成本与延迟

- 预算：每请求 token/费用上限、日/租户配额；超限降级或拒绝，不无限消耗。
- 优化顺序：缩短上下文 → 缓存（精确/语义，注意失效与隔离）→ 小模型/路由 → 流式 → 批处理。
- 延迟：首 token 与总时长分开测；设置超时与取消；避免串行多次模型调用。
- 成本可观测：按功能/租户/模型统计 token 与费用；异常用量告警。

## 8. 可观测与发布

- 记录：模型/提示词版本、token、延迟、检索命中、工具调用、护栏触发、评测分、错误类型；不记录敏感原文。
- trace：一次用户请求串起检索/模型/工具/校验；失败可定位到环节。
- 发布：提示词/模型/索引变更走灰度/开关；可回滚到上一版本；观察质量、成本、延迟、安全告警。
- 评测门：高风险 AI 功能上线前必须有评测报告与红队结果；未达标只能灰度为实验/内部。

## 9. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “模型很强，不用评测” | 强模型也会在边界/对抗/业务口径上错；没有评测就没有回归。 |
| “先上线再收集反馈” | 高风险/不可逆场景必须先有护栏与人工接管。 |
| “加个系统提示就安全了” | 提示注入/越权/输出处理是系统问题，不是一句 prompt。 |
| “RAG 接上就准确了” | 切分、检索、权限、引用、新鲜度任一环都能让答案错。 |
| “成本以后再说” | 无限消耗是 OWASP LLM10；上线前设预算与降级。 |
| “评测用 LLM 打分就行” | judge 有偏差，需校准/抽样/人工兜底。 |

## 10. 红旗

- 提示词只存在某人电脑/平台后台，无版本、无评审、无回滚。
- 模型输出直接拼 SQL/HTML/命令，或直接触发支付/删除/发布。
- 检索不做权限过滤，靠 prompt 要求“不要泄露”。
- 没有黄金集/回归，模型或提示词变更靠“感觉”。
- 日志记录完整 prompt/用户数据/密钥。
- 无 token/费用上限，无超时/降级。
- 高风险功能无人工确认、无审计、无红队。

## 11. 输出与 DoD

- 方案：任务/失败成本、数据边界、架构、提示词/模型版本、检索/工具、护栏、评测、成本/延迟、回滚。
- 实施：代码/配置 + 提示词 + 评测集 + 护栏 + 观测 + 降级/人工接管。
- DoD：验收标准可判定；评测达标且可复跑；安全/隐私检查通过；成本/延迟有预算；可灰度/回滚；日志无敏感信息。
