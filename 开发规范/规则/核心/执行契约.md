# 执行契约（开发轨）

> **定位**：把「按规则执行」变成「按目标 + 事实 + 证据判断」。规则是下限，不是百科全书；未覆盖时允许合理自主，但必须留痕。
> **冲突与覆盖**：默认按规则/红线；冲突时先说明风险与替代，用户再次明确选择按原指令 → 以用户选择为准。无冲突：用户明确指令 > 项目根 `AGENTS.md` > 本包 `AGENTS.md` > 本文件 > 当前 agent 契约 > 项目规范要点。细则见本包 `AGENTS.md` §0 第 5 条。
> **读取时机**：开工判定模式时读 §1～§2；写/改 workflow 时读 §3；收尾前读 §4/§6。不要每步通读。

## 1. 判断模式（先判后做）

| 模式 | 条件 | 行为 |
| --- | --- | --- |
| `execute` | 目标/范围/AC/风险清楚，事实可查 | 直接做到产出/门；不再问 |
| `analyze` | 信息不足但可查（代码/文档/数据/命令） | 先查 1～3 个来源，给「理解 + 建议 + 0～1 问」 |
| `stop` | 影响范围/AC/风险/不可逆/权限/资金/合规，且查不到 | 停下问 1 个关键问题；同时给默认建议与影响 |

- **禁止为流程而流程**：低价值步骤可合并/省略；`output`/`gate`/证据/红线默认不可省（用户按冲突与覆盖选择除外）；跳过要写理由。
- **禁止为自主而自主**：不得自行改范围/AC/优先级/风险接受/发布结论（用户按冲突与覆盖明确选择除外）。
- **规则缺口**：按「最近规则 + 项目事实 + 最小可验证路径」处理；收尾 `deviation=` 按实际情况如实记录取舍。
- **失败纪律**：同一方案无效 2 次换路径；连续 3 轮无新信息收敛范围或给推荐方案，不继续盘问。

## 2. 自主边界

**可自主**：探查顺序、实现路径、工具选择、拆分粒度、措辞、是否派子代理、验证命令、文档结构（模板是下限）。

**必须停（首轮）**：范围/AC/优先级变化；跨系统契约/数据迁移/权限资金/破坏性变更；发布/回滚/提交/推送/回写；风险接受；用户指令与规则冲突（先说明再等选择）；规则与事实冲突且无法判定。用户按冲突与覆盖再次明确选择后，按用户选择继续。

**必须记录**：自主取舍、跳过步骤及理由、假设与验证方式、未验证项、影响面。

## 3. 步骤契约

产出型/决策型 step 至少具备：

| 字段 | 含义 | 缺失处理 |
| --- | --- | --- |
| `agent` | 唯一执行角色 | 必填 |
| `input`（notes 首段或 `reads`） | 读什么 | 必填（可写「无」） |
| `skills`（notes 中路径） | 方法：技能/规则/模板 | 产出型必填 |
| `output` | 落盘路径/形态 | 产出型必填；内部步用 `internal: true` + `reason` |
| `verify` / `gate` | 门/检查/证据 | 产出型必填；无机器门用 `gate_type: checklist` |
| `on_fail` | 失败回退/阻塞 | 必填（可写「回上一步/停下问」） |
| `escalate_to` | 升级对象 | 影响范围/风险时必填 |

- `gate_type: machine` 才可声称「机器过门」；`checklist` 必须给检查方法/证据，不得假装自动。
- `chain: full` 终点必须有 `output` + `verify`；否则不得标 full。
- `next` 只用于有意短链（如 report→handoff），不得用来绕过门。
- 禁止新增「只写 gate、无检查方法」的空门；新增门必须同时写 `gate_type` 与证据来源。

## 4. 计划同步（同轮）

| 事件 | 最小同步集 |
| --- | --- |
| 任务开始/状态变化/阻塞/收尾 | `activeContext.md` 本包 `### 进行中`（任务 ID/状态/最后动作/未提交文件/下一步口令/待确认） |
| 新需求/变更 | 开发计划 §0/§8/§10 + 变更记录 + 文档索引 + `activeContext.md` |
| 范围/AC/里程碑 | §1/§3/§4/§13 + 任务清单 + 测试计划（如启用）+ 交接台账 |
| 进度/阻塞 | §0/§12 + 工作日志（里程碑）+ 交接台账 |
| 缺陷 | 缺陷台账 + §7 + 测试报告（如启用） |
| 交接 | 交接台账 + §0/§12 + 文档索引 + `activeContext.md` |
| 发布 | §0/§10 + 发布说明 + 根 `CHANGELOG.md`（仅开发）+ 工作日志 |
| 回滚/事故 | §9/§10 + 复盘 + 发布记录 |

**规则**：

1. 先列「受影响文档清单」，改完逐项标 `已更新/不适用/待补`；未标不得收尾。
2. 计划是控制面：任何「下一步」必须能从 §0 读出；读不出先修计划。
3. **单包**只改本包；**多包**只改本包分节 + 跨包同步一行；共用原始资料根（推荐 `docs/`）；不自动跑他包。
4. 变更 C2/C3：先重基线再实施；禁止拆成 C0/C1 绕过。
5. 收尾对比「计划下一步 vs 实际下一步」，不一致先修。
6. **进行中=跨会话快照**：任务开始、状态变化、阻塞、收尾前必须更新本包 `### 进行中`；不能只在收尾写。收尾时状态=已完成/待确认/阻塞，未提交文件写实际，下一步口令写下一条。

## 5. 时间 / Token 纪律

- 单步默认核心 ≤3～4 个来源（命中才读）、≤8k tokens；复杂可至 5；先读标题/当前节，够用即停。
- 同一文件不重读；后续 delta-only；大文件只读当前节。
- 不预防性通读规则/技能/模板；不复制正文；用路径引用。
- 超预算：只读当前节 + 收尾说明，**不得**为省预算跳过门/证据/红线。

## 6. 遵守自检（收尾必写）

```text
【遵守自检】route=workflow:step | mode=execute/analyze/stop | reads=... | gates=... | sync=... | skip=... | deviation=...
```

- `route` 必须是实际执行入口；`reads` 列实际读过的文件；`gates` 列门 id/结果；`sync` 列更新的计划/索引/台账；`skip` 列跳过步骤 + 理由；`deviation` 按实际情况如实记录取舍（无则写无）。
- 缺此项 = 未完成收尾；不得只写「已完成」。
