# 项目 README（根目录给人看的入口）

> **定位**：项目根 `README.md` 是人类与任意工具的第一眼简介。  
> **偏好优先（硬）**：写什么、多长、什么语气、要不要徽章/截图/多语言，**以用户偏好为准**；本包模板与市面做法只作参考，**不定死结构与章节**。  
> **与工作流文档分界**：跨会话执行真源仍是项目档案 / 他包档案或基线 / `activeContext`；README **不替代**它们。细节命令与代码地图写档案。  
> **模板**：`规则/模板/00-接入与治理/项目README模板.md`（可选素材库，非强制大纲）。

## 1. 何时读写

| 时机 | 做法 |
| --- | --- |
| 资料不足升级（入口判定 §5） | 有 README → 按**其实际结构**择要；不够或没有 → 探仓库实情；结论**先回写工作流文档** |
| 接入 / 点名生成·更新·整理 | 走 §2 偏好择优；大改一问确认 |
| 任务中核实了对外可见事实 | 可轻量同步已有 README 中对应句；结构大动须确认 |

## 2. 偏好择优（新建 / 大改时）

动手前用**一问**给出推荐 + 备选（已知偏好写在档案/总览「洞见」则可免问、直接按偏好）：

| 档 | 适合 | 大致取向 |
| --- | --- | --- |
| A 极简 | 小仓、内网、只求跑起来 | 一句话 + 怎么跑 + 文档链；短 |
| B 标准协作 | 团队开发默认推荐 | 定位 + 快速开始 + 结构/命令 + 文档入口 |
| C 对外开源/产品 | 公开仓、要招贡献者或对外说明 | 价值主张清晰、快速开始可靠、可选徽章/截图/贡献/许可；仍忌堆砌 |
| D 保持现状 | 已有满意 README | 只补事实缺口或文档链，不改版式 |

用户选定或二次明确坚持后执行；记入 `activeContext` 洞见（如「README 偏好=B」）供后续会话沿用。

## 3. 市面高标准参照（完善时用，非照抄）

整理/升级前，对照**现行高标准 README 常识**做缺口分析（可检索同类优质 README / 文档指南；无网用下列清单），再给用户**可选补强项**，不擅自全盘重写。共识取向：README 是**门面导航**不是手册；细节链到 docs/档案。

1. **开篇能定去留**：名称 + 一句话价值（做什么、给谁）靠前；档 C 宜尽快落到可跑路径。  
2. **快速开始可验证**：从干净环境可复制；写清前置版本；写成功长什么样（URL/输出）；命令须本轮可核实，禁编造。  
3. **渐进披露**：首屏/短文只放「第一次读者要跑起来」的内容；完整参考、架构、全量配置放 docs 或档案。  
4. **结构可扫**：短段、表优于长散文；可选目录示意、常用命令/配置表、截图（有则用，无则不强加）。  
5. **入口与信任**：链到档案/`activeContext`/工作流包（若已装）；档 C 可补贡献/许可/维护状态；无密钥、无空话与过时命令。  
6. **受众匹配**：篇幅与语气跟 §2 档位一致；内网极简不必套开源全套。

输出建议时写清：相对现状缺什么、建议补哪几项、推荐档；**由用户选**后再改。

## 4. 写入优先级（硬）

1. **先**回写工作流实例：项目档案 + `activeContext`（多包时他包由对应包维护）。  
2. **再**按用户偏好更新根 README；不得只改 README 不回写档案/总览。  
3. 冲突以本轮核实的仓库/现网为准，先改档案再改 README。  
4. 已有 README：**禁止整文件套模板覆盖**；合并或重写须符合所选档 + 用户确认。

## 5. 反模式

- 不经询问套死某一模板章节或「必须首屏/某节」。  
- 静默按「标准开源范」重写用户已满意的短 README。  
- 用通读 README 代替档案身份短读。  
- 把密钥、内网敏感路径、未确认推断写进 README。  
- 把市面范文整段抄入当本项目事实。
