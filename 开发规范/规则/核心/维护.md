# 维护本包（开发轨）

> 只在改包/自检/维护时读；业务任务不读本节。`AGENTS.md` 只留维护指针。  
> **能力/技能体检**（推荐口令「体检能力」）走 `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`，不替代本节自检。

## 1. 改哪里

- 不变量/路由/读取协议 → `AGENTS.md`
- 步骤顺序 → `workflows/`
- 角色契约 → `agents/`
- 红线/输出/门 → `规则/`（门：`规则/门.md`）
- 澄清协议 → `规则/核心/澄清.md`
- 协作/交接/变更分级 → `规则/协作/协作与交接.md`；交接步骤 → `workflows/handoff.yaml`；回执/台账模板 → `规则/模板/`
- 模板 → `规则/模板/`
- 文档质量标准/类型矩阵 → `规则/核心/文档质量标准.md`
- 母版/实例边界：母版只维护通用高标准；实例默认不改，AI 提议+用户确认后可本地适配（模板/技能/规则）；本地适配留痕，整包更新前备份/比对；项目特化改产出文档，通用改进回母版升版本
- 技能 → `技能/`（**可在落地包就地改**；通用最优用口令「通用优化技能/母版技能更新」）
- 能力 → `能力/`
- 能力/技能体检流程 → `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`
- 文档树/归档 → `规则/文档治理.md`
- 子代理编排 → `规则/协作/子代理编排.md`（单一出处），workflow/agent 只留指针
- 读取索引 → `规则/读取索引.md`（改 step/reads 后同步）
- 轻量档（solo）→ `规则/核心/轻量交付.md`；步骤 → `workflows/solo.yaml`

## 1.1 体检 vs 装配 vs 维护

| 口令 | 用途 |
| --- | --- |
| 装配能力 | 只盘点/安装外部能力 |
| 体检能力（及同义） | 外部能力 + 随包技能检查/适配建议；确认后可就地改本包 |
| 通用优化技能 / 母版技能更新 | 同上 workflow，mode=generic（不绑具体项目） |
| 维护/查询 | 改规则/路由/跑自检；技能能力深度分析转体检口令 |

## 2. 自检

```powershell
powershell -ExecutionPolicy Bypass -File "开发规范/规则/tools/Test-Template.ps1"
python 开发规范/规则/tools/validate_tasklist.py <清单路径>
python 开发规范/规则/tools/validate_dev_plan.py <开发计划路径>
```

自检覆盖：引用可解析 + 章节锚点 + workflows→agents + 步标记词表 + 能力名声明 + 版本单点 + YAML 语法；另跑文档卫生检查（见 `规则/tools/README.md`）。

## 3. 质量度量

开发计划 §14（DORA/交付质量）；架构评审评分卡见 `技能/solution-design/SKILL.md` §8（`confirm_spec` 用）。

## 4. 规则撰写标准

新增或保留规则/步骤的标准＝**有用、不冗余（单一出处，其余指针）、不误导、高性价比**；强调集中在不可让项；凡「须确认/询问/固定骨架」处，YAML 步上必须有对应 `hitl`。

## 5. 文档粒度

常驻最小、按需加载：被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。

## 6. 宿主无关

本包文本与 YAML 只写能力名（清单见 `能力/00-能力注册表.md`）；禁写具体宿主名与宿主本地路径——宿主要求、挂载与配置示例见 README「宿主适配」节。
