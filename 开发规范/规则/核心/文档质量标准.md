# 文档质量标准（开发轨）

> **定位**：开发轨所有文档的**通用合格线**。模板只提供结构；本文件判断“这份文档能不能用、能不能交接”。
> **适用**：产品定义卡、方案卡、轻量测试报告、需求基线、方案/ADR、前端设计说明、任务清单、开发计划、提测单、发布说明/上线检查/发布记录、UAT、交接包、缺陷评估/文案、复盘、工作日志、CHANGELOG。
> **原则**：按文档位置定内容；完整 PRD/测试计划/用例库不塞进开发文档，也不让开发文档替代测试/产品结论。轻量档的产品定义卡/方案卡/轻量测试报告按 §2 边界使用，不是完整 PRD/测试包。

## 0. 冲突优先级

安全/合规/硬红线 > 用户明确指令 > 项目根 AGENTS > 包 AGENTS > 本文件 > 模板结构 > 历史文档。

模板与本文件冲突：**先修母版模板并升版本 → 自检 → 整包分发**；不按旧模板产出，也不在实例里各自改。

## 0.1 母版 / 实例 / 模板的使用方式

- **母版只维护通用高标准**：不写具体项目环境、端口、账号、组织、版本等实例事实。
- **实例默认不改，但可本地适配**：项目里的 `开发规范/产品规范/测试规范` 默认按母版使用；AI 发现模板/规则/技能不匹配或有更好做法，先输出「拟改内容/原因/影响」，用户确认后只改当前实例，不影响母版。
- **本地适配要留痕**：确认后在项目档案或本地适配记录登记（文件/原因/日期/确认人）；母版整包更新前先备份/比对，避免覆盖；本地适配不自动回灌母版。
- **模板是骨架、标准是底线**：按当前项目实际和文档位置裁剪/补充，不要求逐条机械填写；不适用项写「不适用 + 理由」，不为凑模板写空话。
- **不匹配时先改产出**：模板/标准与项目实际不匹配，优先修改当前项目生成的文档（需求/方案/提测/报告等），使其贴合实际并可验收。
- **适配建议回母版需确认**：AI 可向用户说明差异/影响/建议；只有用户确认且属于通用改进时，才回母版修改并升版本；项目特化不回灌母版。

## 1. 通用硬门槛（任一不满足 = 不合格）

1. **目的与读者明确**：开头能看出“给谁、解决什么、用来做什么决定”。
2. **事实有来源**：环境 URL/端口/IP、构建/提交、账号、日期、数据量、测试结果、缺陷号、审批/准出结论等，来自配置/命令/权威文档/用户确认；未确认写「待确认」并停下问。禁止开发默认、示例、历史值、猜测。
3. **范围有边界**：in/out 分开；out 标来源/理由/确认人；产品不做、测试限制、回归取舍不能混写。
4. **可执行/可验收**：步骤、预期、判定标准可被他人复现；禁“完善/正常/应该没问题”等空话。
5. **证据可核对**：命令+结果摘要/截图/日志/报告路径；结论必须能回到证据；内部路径不能替代正文。
6. **一致与追溯**：ID/版本/AC/任务/缺陷/交接包互相一致；同一事实多处引用不冲突。
7. **状态与变更**：版本、日期、负责人、状态、变更记录齐；旧版归档，不堆“最终版”。
8. **安全与合规**：无密钥/凭据/真实 PII；敏感数据脱敏；权限/数据域写清。
9. **当前有效状态（硬）**：正式文档以当前最终状态为唯一事实来源。
   1. 只描述当前存在的功能、流程、规则和约束。
   2. 删除后直接移除相关表述；不追加「已删除 / 已废弃 / 不要再用xxx / 禁止xxx（因旧物）」等说明。现行仍生效的约束可写（如「密钥不得入库」），那是现行规则，不是删后留痕。
   3. 不记录历史修改过程、原因、旧方案和已取消内容。
   4. 不为防误解而引入当前不存在的概念或对照物。
   5. 改完以最终状态落笔，保持简洁准确。
   6. 对用户的文档/结论输出写现行结论，不复述用户需求原文，不写「本次改了什么」。
   7. 禁止在正式正文记录变更原因与废弃史；留痕仅限变更单 / 工作日志 / 复盘 / CHANGELOG 等允许载体，且不回流正式正文。
   8. 不把未采纳的修改方案、对比草案写入正式文档。
10. **语言克制**：禁辩解式/对比式/冗余括注（如解释“不是某个环境/端口”）、未经确认的“应该/可能”。
11. **评审/确认匹配风险**：L2+、高风险、跨角色文档按规则评审/确认；不自行替产品/测试下结论。

## 2. 开发文档类型矩阵

| 文档 | 位置/作用 | 必须具备 | 不应包含 | 合格判据 |
| --- | --- | --- | --- | --- |
| 产品定义卡（轻量） | 想法→产品判断 | 问题/用户/价值/MVP/非目标/成功标准/风险/假设 | 完整 PRD、技术方案、市场调研全文 | 能判断做不做、范围清 |
| 需求基线 | 需求→开发合同 | 范围/AC/NFR/非目标/来源/追溯 | 实现方案、测试用例 | AC 可验收，out 有依据 |
| 方案/ADR | 技术决策与影响 | 上下文/选项/决策/后果/兼容/回滚/测试策略 | PRD 业务口径复述 | 决策可执行、风险/回滚清楚 |
| 方案卡（轻量） | 小项目实施依据 | 产品行为/技术/任务/验收表/测试策略/风险 | 完整 PRD/用例库/长篇架构 | 一页可执行、AC 可验收 |
| 前端设计说明 | 前端实现与验收依据 | 页面/状态/交互/tokens/a11y/性能/证据 | 后端规则、代码清单 | 状态/视口/异常可验 |
| 任务清单 | 执行控制 | RP/AC/DoR/DoD/依赖/负责人/证据 | 长篇方案 | 每任务可验收、可追溯 |
| 开发计划 | 阶段/门/控制面 | 阶段/门/证据/风险/下一动作/变更 | 代码细节、测试报告 | 状态与证据一致 |
| 版本策略 | 项目版本口径 | 格式/升级矩阵/候选→正式/环境边界/tag/版本查看/审批 | 具体发布步骤、测试用例 | 版本动作可判定、无歧义 |
| 提测单 | 开发→测试转测件 | 构建/环境/范围/改动/验收点/主链路/边界/自测/已知问题/准入退回 | 测试计划/用例/报告 | 测试只拿本单可开测 |
| 轻量测试报告 | 轻量验证结论 | 范围/环境/测试点/结果/证据/缺陷/缺口/verdict | 完整测试计划/用例库 | P0 有结论、证据可打开 |
| 发布说明 | 发布执行依据 | 版本/窗口/审批/回滚/监控/发布后验证 | 营销文案、未证实指标 | 可执行、可回滚 |
| 上线检查单 | Go/No-Go | 硬项/责任人/证据/NO-GO 条件 | 泛泛“检查完毕” | 每项可判定 |
| 发布记录 | 实际发布事实 | 步骤/时间/结果/异常/证据 | 计划复述 | 实际与证据一致 |
| UAT 验收 | 业务验收 | AC/角色/数据/结果/证据/签收 | 开发自测替代 UAT | 逐条 AC 有结论/证据 |
| 交接包 | 跨角色快照 | 00/01/必带快照/回执可选/版本/缺口 | 密钥、未过门草稿 | 接收方可独立核对 |
| 缺陷评估/文案 | 缺陷处置 | 依据/现象/影响/选项/AC/建议/证据 | 未确认就写实现方案 | 产品可决策、测试可复现 |
| 复盘 | 改进闭环 | 事实/根因/行动项/负责人/截止/验证 | 追责、空泛口号 | 行动项可验收 |
| 工作日志/CHANGELOG | 里程碑/发版史 | 版本/日期/变更/迁移/影响 | 过程流水账 | 可追溯、不过期 |

## 3. 评审清单（交付前逐项过）

- [ ] 目的/读者/范围一句话能说清
- [ ] 所有事实字段有来源；无“待确认”被当成事实
- [ ] out 有来源/理由/确认人
- [ ] 每条 AC/改动有可观察验收点
- [ ] 主链路 + ≥1 边界/反向
- [ ] 自测证据含命令/结果/时间；未覆盖显式列出
- [ ] 已知问题含影响/是否阻塞/规避/计划
- [ ] 状态/版本/负责人/变更记录齐
- [ ] 无密钥/PII；链接/路径可打开
- [ ] 当前有效状态：无「已删除/已废弃/不要再用」留痕；无历史过程/旧方案/未采纳草案；结论只写现行
- [ ] 轻量档：方案卡验收表可被完成门读取；测试报告有 verdict/P0/证据
- [ ] 不替测试/产品下结论

## 5. 版本与构建标识（所有文档）

> 细则见 `规则/核心/版本策略.md`；项目可在 `开发/06-发布与交付/版本策略.md` 按模板裁剪。以下为合格线。

- **四个标识分开**：产品/测试版本、构建/制品（tag/commit/构建号/镜像 digest）、部署版本（build-manifest/`.deploy-rev`）、文档版本（提测单 rev）。测试只认实际部署版本；代码 commit 是追溯。
- **模式与节奏**：项目先选 A 发布候选（`rc.N`→正式）或 B 连续迭代（迭代基线→QA 批次 patch）；A 候选期修复只加 `rc.N`，B 每次新构建/QA 批次升 patch；新增功能升 minor，不兼容升 major。
- **收敛与发布**：测试/验收通过、无阻塞缺陷后转正式/交付基线；不允许无限 rc/测试批次；正式版不等于已部署，无 prod 可发交付基线并写 S8 不适用；test/staging 不触发 S8，生产才走 `confirm_deploy`。
- **项目内可查**：页脚/`/version`/构建清单至少一种；页脚/接口/部署标识可互相对齐，不能靠文档 HEAD。
- **tag/Release/部署**：tag 是 commit 书签，Release 是平台说明页，部署是环境变更；tag 只在候选/正式边界打，annotated、不可变；一次构建、同一制品晋级。
- **文档与证据**：文档 commit 不改变构建；提测单交接后改动出下一个 `rc.N`/版本，不覆盖；测试报告记录版本/构建/环境/查看证据，版本不一致阻断测试/发布。

## 6. 维护

- 新增/修改模板时，同步更新本文件 §2 类型矩阵与模板索引。
- 发现“模板有结构但产出不可用” → 先修模板/标准，再修单份文档。
- 版本随包 `template_version` 更新；本文件不单独设版本号。
