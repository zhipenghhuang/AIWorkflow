# 提测单模板

> 用途：开发→测试交接件（企业「转测 / 提测」对齐）；`change`/`iterate` 的 `deliver` 步产出，落 **文档事实源目录 `05-发布与交付/`**（或档案所记映射）。  
> 命名：单点滚动 `提测单-{版本}.md`；多版本并行必须含版本；旧版移 `_归档/{yyyyMMdd}-{版本}/`（旧项目可用 `历史/`）。  
> 纪律：自测结论必须附**本任务内**证据（命令+结果 / 证据指针）；禁「应该没问题」；已知问题不瞒报；改动点与影响面写清（供测试计划取舍与回归范围）。

## 1. 基本信息

| 项 | 值 |
| --- | --- |
| 版本 / 构建 | `{版本号 · 构建号/提交 hash}` |
| 提测时间 | `{yyyy-MM-dd HH:mm}` |
| 分支 / 提交 | `{分支名 / 提交 hash}` |
| 环境 / 入口 | `{环境地址；或指针}` |
| 提交人 | `{姓名/账号}` |
| QA 接收人 | `{姓名/账号}` |
| 关联需求/方案 | `{需求基线/方案路径}` |
| 变更单/任务清单 | `{编号/路径}` |

## 2. 改动点与影响面

- **改动点**：{新/改/删/转版；逐条；关联 AC}
- **影响面**：{直接受影响模块/接口/数据/权限；邻接点；回归建议范围}
- **明确不受影响**：{可选；帮助测试聚焦}
- **外部依赖/环境变化**：{配置/数据/证书/白名单；无则「无」}

## 3. 自测结论（必填）

- 自测方式：{命令 / 用例路径 / 手工步骤}
- 结果：{通过项 + 失败清单；证据指针（日志/截图/报告路径）}
- 覆盖：{AC 覆盖矩阵；未覆盖项}
- 未覆盖：{本任务未验证路径；无则写「无」}
- 门禁：{命令 + 结果；失败基线对账}

## 4. 已知问题与限制

- {问题/限制 + 影响 + 是否阻塞测试；无则写「无」}
- 风险与规避：{…}

## 5. 回归指引（供测试）

- 主链路：{步骤 → 预期}
- 边界/反向：{≥1 或无额外边界}
- 关联缺陷单：{平台单号列表；无则写「无」}
- 测试数据/账号：{前置三件套；敏感信息脱敏}
- 建议轮次：{R0 冒烟 / R1 正式 / R2 回归}

## 6. QA 接收（由 QA 填写）

| 项 | 值 |
| --- | --- |
| 接收结论 | {准入 / 退回 / 有条件准入} |
| 退回原因 | {缺构建/缺证据/环境不可用/范围不清；无则「无」} |
| 接收时间 | {yyyy-MM-dd HH:mm} |
| 测试计划 | {path} |
| 备注 | {…} |

## 7. 关联

- 测试计划/报告：{path}
- 上线检查单/发布说明：{path}
