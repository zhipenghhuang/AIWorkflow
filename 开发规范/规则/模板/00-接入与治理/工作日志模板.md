# 开发工作日志

> **落点**：`开发/工作日志.md`（开发包维护）。  
> **用途**：岗位**里程碑侧记**，人类可扫、可复查；最新在前。  
> **不是**：项目根 `CHANGELOG.md`（给人看的项目发版史，本包在发版时另写）、`发布说明-{版本}.md`（单版叙事）、开发计划执行日志（细粒度过程追加）。  
> **禁止**：把本文件内容当作根 CHANGELOG；把用户可见功能清单只写在这里却不更新根 CHANGELOG（发版时根与发布说明仍必更新）；密钥/PII。  
> **只记里程碑级事件**（见下方事件类型）；日常琐碎进计划执行日志。  
> **年归档**：过长（约 >200 行）或跨年 → 列候选并**用户确认**后移入 `开发/_归档/工作日志/工作日志-{year}.md`，本文件留索引；**不随业务版本整文件搬迁**。

## 事件类型（选型）

| 类型 | 何时写一条 |
| --- | --- |
| 需求理解确认 | 理解包确认 / 澄清收敛 |
| 方案落地 | 方案/ADR 确认并落盘 |
| 提测 | QA 交接包生成 / 提测单就绪 |
| 修复闭环 | 缺陷修复完成并提回归 |
| 发版 | 发布完成（**同时**更新根 `CHANGELOG.md` + 发布说明） |
| 复盘 | 迭代/事故复盘结论 |
