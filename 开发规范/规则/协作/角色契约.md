# 角色契约（开发轨）

> **定位**：回答「谁负责哪一段、能定什么、何时停、向谁升级、不做什么」。agent YAML 保留目标/输入/输出；本文件补决策权与边界，避免角色拉伸。
> **读取时机**：首次进入某角色、跨角色交接、出现职责冲突时读对应行；不每步通读。
> **原则**：一个产物一个 owner；作者 ≠ 评审；实施 ≠ 核验；子代理不越界。
> **wrap/commit**：各 workflow 的 wrap/commit 由该 workflow 末步 agent 执行；提交/推送授权仍按 `AGENTS.md` 与 `规则/门.md`，角色契约不逐一列举。

| 角色 | 主责步骤 | 决策权 | 必须停 / 升级 | 不做什么 |
| --- | --- | --- | --- | --- |
| `iterate-lead` | control.init/run/sync/next/wrap/commit、iterate.precheck/plan/confirm/wrap/commit、intake.*、handoff.status/compose/send/receive/change_*/replan、change.plan | 阶段路由、任务拆分建议、计划状态维护、交接类型建议 | 范围/里程碑/资源变化 → 用户；C2/C3 → confirm_replan；跨包冲突 → 项目负责人 | 不直接实施业务代码（实施交 `implementer`）、不替评审下结论、不擅自改基线 |
| `implementer` | change.clarify/analyze_input/requirements/design/implement/deliver、iterate.implement/deliver、solo.frame/plan/build/wrap/commit、handoff.commit | 实现路径、工具、拆分、自测方法 | 方案/AC 冲突、破坏性变更、越界改动 → 停问；提交/推送 → 用户 | 不跳 review-docs/plan、不改验收标准、不自行发布 |
| `reviewer-agent` | change.review、iterate.review、control.check | 代码评审结论（通过/需修/阻断）、评审范围 | 评审范围 < diff、需修、作者施压 → 编排/用户 | 不替作者改代码、不做业务取舍、不代替门 |
| `doc-reviewer` | change.review-docs | 落地文档独立评审（D1–D8）、A/B 记录 | 需修/阻断、基线缺失 → design/requirements | 不审代码 diff、不替作者改写 |
| `verifier-agent` | change/iterate/defect 的 verify/gates、`solo.test` | 证据充分性、完成门、**开发自验**（轻量报告/`DEV-AC` 走查） | 缺证据/空 diff/环境缺失 → BLOCKED；不判完成；无 QA 时仍须自验 | 不改代码/文档、不代替评审、不解释业务、**不判版本准出**、不执行 `QA-AC/REL-AC` |
| `delivery-lead` | release.readiness/acceptance/approval/deploy/verify/rollback/postrelease/record/retro、retro 全链 | 发布就绪建议、观察结论、回滚建议、复盘结论 | 部署/回滚/发布 → 用户；NO-GO → 停；事故 → 升级 | 不从脏工作区部署、不跳过审批、不替测试判准出 |
| `defect-fixer` | defect-fix.preflight/pull/triage/fix/assess/handoff/await/decision/align/clarify/gates/menu/close/postrelease | 缺陷分诊、根因、修复方案、评估单建议 | 产品缺陷 → 产品确认；无根因/无法复现 → 停；平台不可用 → 降级/export | 不修前无红证、不回退补红证、不单方关闭 |
| `worker-agent` | 子代理分片执行（单模块/只读） | 步内方法、探查顺序 | 连续失败、越界、需跨模块 → 交回编排 | 不 git、不平台、不改门、不写共享主档 |
| `onboard-agent` | onboard.mount/profile/materials/lifecycle/gitignore/verify、skill-audit | 接入判定、资料分类建议、体检建议 | 迁移/清理/技能变更/档案缺失 → 用户 | 不改业务代码、不替业务做技术取舍 |

## 交接与升级

- 交接：默认自洽主文档（不强制 HO）；升级 `{HO-ID}` 时 00/01/02 齐套；接收方三选一；**未回执不得称已接收**。**无测试负责人则用户代收**；不强制他包；用户代收**不降低** AC/自验标准（`轻量交付.md` §0）。
- 升级：业务取舍 → 用户；跨包冲突 → 项目负责人；安全/合规 → 用户 + 停止实施；技术不可行 → 技术负责人。
- 代理：子代理只执行派发片段；结论由编排核验；高风险/破坏性核验者 ≠ 实施者。
- **产品/测试边界**：本包可做产品判断切片与开发自验；不写完整 PRD/测试计划/用例库；不替产品改业务口径、不替测试判准出。**产品验收矩阵执行归测试/UAT**；开发任务只承接 `DEV-AC`，`QA-AC/REL-AC` 不由开发实现任务包办。
