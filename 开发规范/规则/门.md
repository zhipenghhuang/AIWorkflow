# 门（开发轨）

> 单一出处：`hitl` / `gate` / `when` 语义与词表。步骤顺序以 `../workflows/*.yaml` 为准；**只认步上 `hitl`/`hitl_when`/`gate_when`**，专规不另造门。
> 读取时机：当前步有门时只读对应行；写/改 YAML 时才读全表。

## 1. 门与 gate

| 标记 | 含义 | 必须行为 |
| --- | --- | --- |
| `hitl:` | 确认门声明 | 标量（单门）或列表（多门；各项 `name` + 可选 `when`）；未写 `when` 视为无条件 |
| `hitl_when:` | 标量门条件 | 条件不满足 → 跳过该门，不算违例 |
| `gate_when:` | 门禁条件 | 条件不满足 → 跳过该 gate（步骤不跳过） |
| `confirm_change` | 变更吸收/影响 | 出示变更类型/影响矩阵/待更新文档/待确认项；实质变更确认后才更新基线 |
| `confirm_understanding` | 需求理解 | 出示来源/需求理解包/缺口清单/范围/AC/非目标/冲突/GAP/置信度；确认后才进需求基线/设计/实施 |
| `confirm_requirements` | 需求基线/范围 | 出示范围/AC/NFR/非目标/未决；未签收不进设计/排期 |
| `select_review_mode` | 落地文档评审方式 | **STOP 二选一**：A 自行评审通过（HUMAN_APPROVED）｜B AI 独立评审（`doc-reviewer`）；同产物只问一次；未选不得进实施。适用需求基线/方案/ADR/前端设计说明等（见 `技能/design-doc-review`） |
| `confirm_spec` | 方案评审 | 出示范围/接口/兼容与回滚/验收；批准后才实施（可在选模式 + 可选 AI 审之后） |
| `confirm_plan` | 开发计划/版本范围 | 首次创建或范围·版本·里程碑实质变更；确认后计划状态=已确认 |
| `confirm_backlog` | 迭代清单与节奏 | 出示任务数/RP 覆盖/依赖/风险 + 节奏三选；确认后才实施 |
| `confirm_commit` | 拟提交/推送 | 【拟提交】块（文件/分支/推送目标/PR·合并意图）；确认后才执行 |
| `confirm_handoff` | 交接包发送 | 出示 HO-ID/类型/接收方/必带清单/阻断项/回执截止；确认后才生成/发送；未收回执不得称“已交接” |
| `confirm_deploy` | 工程部署审批 | 出示版本/窗口/影响面/回滚决策人；未批准不部署 |
| `confirm_rollback` | 回滚 | 出示触发信号/步骤/数据影响/预计时长；确认后执行 |
| `confirm_acceptance` | UAT/业务验收 | 出示 AC 覆盖/失败项/遗留风险/发布建议；确认后进审批 |
| `confirm_actions` | 复盘行动项 | 出示行动项/负责人/截止/验收；确认后落盘 |
| `confirm_remark` | 回写前备注 | 出示 §6 备注全文；确认后回写 |
| `confirm_gitignore` | 入库策略 | 四选一确认并写档案、改 `.gitignore` |
| `confirm_docs_migration` | 资料/工作文档归档、搬迁或临时清理 | 出示分类/覆盖对照/拟归档或清理清单与目标；确认后执行 |
| `select_menu` | 缺陷批末菜单 | 输出总结+【用户选择菜单】，精确执行选项 |
| `gate: completion-gate` | 完成门（开发轨） | 任务开始 `-StartTask`；运行 `验证/Invoke-Gate.ps1 -Acceptance ...`；读验收清单/diff/证据/process/project-profile，写 `.gate/开发规范/completion.json`；只有本轮 `COMPLETE` 可称完成；空 diff=`NOT_VERIFIED`、dry-run=`DRY_RUN`、缺环境/证据/检查失败 → `BLOCKED` |
| `gate: dev-plan` | 开发计划检查 | L2+ 开发计划存在，阶段表/门/证据/下一步完整；缺项不过 |
| `gate: release-readiness` | 发布就绪 | 按上线检查单逐项核；硬项不过 → NO-GO |

## 2. 步骤条件 `when` 词表

`release_failed_or_direct_rollback`（入口=回滚 或 发布失败/触发回滚条件）｜`new_feature_or_scope_change_or_requested`｜`new_feature_or_architecture_or_breaking_change_or_requested`｜`new_feature_or_architecture_or_breaking_change_or_high_risk_or_requested`｜`architecture_or_breaking_change_or_requested`｜`multi_file_or_new_feature_or_requested`｜`multi_file_or_new_feature_or_high_risk_or_requested`｜`high_risk_or_requested`｜`has_qa_or_deploy_or_requested`｜`has_deploy`｜`has_uat`｜`release_verification_failed`｜`release_failed`｜`release_ready`｜`release_ready_and_acceptance_passed`｜`release_approved`｜`has_deployed`｜`iteration_done_or_incident`｜`recurring_defect_or_incident`｜`incident_or_major_release`｜`docs_migration_needed`｜`requirements_need_confirm`｜`understanding_needs_confirm`｜`has_product_docs_or_prototypes`｜`change_is_substantive`｜`backlog_or_pace_changed`｜`backlog_approval_required`｜`plan_needs_confirm`｜`has_pending_commit`｜`code_changed_or_requested`｜`implementation_required`｜`landing_doc_review_needed`（L2+ 新产出需求基线/方案/ADR/前端设计说明，或点名文档评审，且本会话尚未选定 A/B；L0 无新文档=false）｜`review_required`（有实施且多文件/新功能/高风险/大改/点名代码评审；只出清单或 L0 单文件=false）｜`product_defect`｜`product_decision_received`｜`product_decision_requires_alignment`｜`need_clarification`｜`menu_includes_commit`｜`menu_includes_writeback`｜`menu_includes_deploy`｜`not_awaiting_product`（本轮 await_product 或 product_decision 输出 AWAIT_PRODUCT 时为假，否则为真）｜`handoff_send_required`（显式生成交接包且接收方/范围/必带文档尚未在上一门确认；已由 `confirm_spec`/`confirm_backlog`/`confirm_deploy` 等确认同一发送时为假）｜`handoff_change_substantive`（交接包内变更达到 C2/C3 或改动已定稿基线）。

同一会话同一确认点只问一次；资料/迁移/清理清单确认后本轮不再重复。条件不满足 → 跳过该步（及其 hitl）；不确定按触发处理。`release_failed` = 部署失败或发布验证失败/触发回滚条件；`release_ready` = 上线检查单结论 GO；`release_ready_and_acceptance_passed` = 上线检查单 GO 且 UAT/验收通过或不需要；`release_approved` = `confirm_deploy` 已批准；`implementation_required` = 非「只出任务清单」且清单已确认；`backlog_approval_required` = L2+，或清单/范围/节奏实质变化；L1 小批只通知不审批。`has_product_docs_or_prototypes` = 输入含外部 PRD/迭代方案/需求文档/页面原型/截图/接口或技术文档；`understanding_needs_confirm` = 有外部文档/原型、存在 2 个以上实质歧义或冲突、L2+，或用户要求方案/排期/估算；已有**当前任务**理解确认记录则假，纯信息查询/机械低风险操作不触发。

## 3. 门档位（防过度审批）

| 档 | 适用 | 行为 |
| --- | --- | --- |
| autonomous | 只读、L0 微改、可逆 | 直接做，收尾记录假设；仅保留证据/提交/密钥红线 |
| notify | L1 常规、清单/节奏未实质变化 | 展示清单/计划后继续，用户可打断 |
| approve | L2+ 范围/方案/清单实质变化、L3、部署/回滚/回写/提交 | 停：需求基线、**评审方式选择**、方案、清单/节奏、部署、回滚、回写、提交、交接包发送 |

低风险动作不要升级为 approve；高风险动作不得降为 notify。红线不被“少问/直跑”覆盖。
