# 文档治理（资料 + 工作文档）

> 单一出处：入站意图分析、资料/工作区分流、覆盖对照、受影响同步、归档与清理；含根 `CHANGELOG.md` 与 `开发/工作日志.md`。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/清理**；未确认前只读。
> **单包优先**：仅本包即可闭环；缺产品/测试包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。多包时共用根级**原始资料根**与交接直读，放入≠分发。
> **反堆积**：确认采纳且 S1/S2/S3 → **同批**失效归档（仅包内 `资料/_归档/` 与工作区归档）；正式档就地覆盖；禁止「只落位、等关版本再清」。根级原始资料根**不归档、不迁出主副本**。
> 安全：**现行**证据（当前 `task.json` 任务、本轮门回执所需）、当前计划/方案/任务清单、源文件、用户文件、密钥、`.git` 永不自动删除；**过期运行态**（非当前任务截图、早于本轮 `started_at` 的图、`.gate/开发规范/` 下非 JSON 媒体等）视为临时/过程，可进清理候选；拿不准 → 待确认或移 `开发/_归档/_待清理/`。
> **`.gate` 落点**：截图与前端 QA（由 `验证/frontend/design-qa.md` 拷入）只写 `.gate/frontend/`；`.gate/开发规范/` 只写 JSON 回执。新任务 `-StartTask` 清空 `.gate/frontend/` 下旧媒体。

## 1. 三个区

| 区 | 放什么 | 不放什么 |
| --- | --- | --- |
| **原始资料根**（推荐 `docs/`） | 项目外部/用户投放的**原始输入主副本**（永久保留） | 本包活文档、包内归档 |
| `开发/资料/` | 本包所需原始输入的**副本**与只读证据 | 本包需求基线/方案/任务/提测/发布/UAT/复盘 |
| `开发/00～08` 与主档 | 本包工作文档 | 外部原件主副本（在原始资料根） |

- **工作文档根（硬）**：本包必须有 `开发/`；新产物只落此处。
- **原始资料根（硬）**：项目根级，单包与多包**同一语义、共用一份**。推荐名 `docs/`；若已有其它名 → 登记实际路径并引用，不强制改名。无现成目录 → 接入时默认建 `docs/`。
- **主副本规则**：原始资料根内文件**一律视为项目原始资料**——**禁止迁出**；只做索引、按需复制、按需吸收（含引用）。新文档入库须先在此留主副本。跨包只引用；放入 ≠ 自动跑他包。
- **资料模式**（只约束原始资料根内部结构；**不**禁止复制/吸收）：

| 模式 | 对原始资料根 | 仍允许 |
| --- | --- | --- |
| `keep` | **结构保持不动** | 建/更新索引；按需复制；按需吸收/引用 |
| `mix`（默认） | **只添加整理** | 同上 |
| `replace` | **完全重整**（方案确认后执行；须修引用） | 同上 |

  均须可查可引。不强制对齐包内 `资料/` 树。
- **认根**：用户指定优先；否则按 §2.1 判定表；**不确定必须问用户**。
- **版本记录**：根 `CHANGELOG.md`＝开发维护的发版史；`开发/工作日志.md`＝岗位里程碑（禁写入/补链根 CHANGELOG）。他包各自维护本包工作日志。

## 2. 原始资料根与包内资料

### 2.1 原始资料根（无归档 · 不迁出）

```text
docs/                            # 或档案登记的其它原始资料根路径
├─ 资料索引.md                   # 必有：全量可查可引
└─ …                             # 子目录由实况决定
```

**认根判定表**（用户未指定时；冲突/多候选 → 问用户）：

| 优先 | 线索 | 倾向 |
| --- | --- | --- |
| 1 | 用户点名 | 采用该路径 |
| 2 | 根下 `docs/` 且主要为文档 | `docs/` |
| 3 | 唯一明显大文档夹（根级 `文档/`、`项目文档/`、`资料/` 等，非包内） | 该夹 |
| 4 | 多候选或以代码/配置为主 | **停问** |

- **禁止**：原始资料根建 `_归档/`；禁止把其中文件**迁移**到 `开发/` 工作区；禁止为对齐包内树强制改结构。
- **中途存量（硬）**：**索引全登记**；**不**默认全量复制/吸收；按任务/版本需要分批复制或吸收；可长期仅索引。
- **三档处置**：

| 档 | 做什么 | 何时 |
| --- | --- | --- |
| **索引** | 写入 `{原始资料根}/资料索引.md` | 默认；存量必做 |
| **复制** | 复制进 `开发/资料/`（本包树）；原件不动 | 本包常读/证据/离线需要 |
| **吸收** | 见 §2.3；原件不动 | 需要工作区 SSOT 或稳定引用 |

- **入站通道**：① 直接放；② 根散落 → 先收入原始资料根；③ 对话/附件 → 先落盘。确认前只读分析（落盘保原件除外）。

### 2.2 包内 `开发/资料/`（按需副本 · 可归档）

```text
开发/资料/
├─ 资料索引.md
├─ _通用/
├─ {版本或主题}/
├─ 交接/{HO-ID}/
└─ _归档/{yyyyMMdd}-{版本或批次}/
```

- **禁止**：新建 `项目文档/`/`原始素材/`/`_收件箱/`；禁止新资料长期平铺 `资料/` 根；禁止强制类型前缀改名。
- 仅**按需复制**的副本；非原始资料根全量镜像。
- 失效副本 → `资料/_归档/`；不影响原始资料根。

### 2.3 吸收深度（实用）

> **吸收 ≠ 迁移**。原件永远留在原始资料根。

| 深度 | 工作区动作 | 适用 |
| --- | --- | --- |
| **R0 引用** | 计划/索引/台账写来源路径 + 用途一句 | 查阅、非本轮范围 |
| **R1 要点吸收** | 相关范围/AC/约束写入待决/变更/任务卡；挂原件链接 | 澄清、排期、小改 |
| **R2 结构吸收** | 按模板写入/更新 `01`/`02` 等 SSOT；`来源=` 原始路径 | 正式基线、提测入口、定稿 |

- **默认**：存量→索引；任务命中→至少 R0；改基线/实施入口→R1 或 R2（不确定取低档并问一次）。
- **禁止**：整文件挪进 `01/` 冒充吸收；禁止搬空原始资料根。
- **SSOT**：工作区正式结论为准；原件溯源。冲突→T8。

## 3. 入站意图分析

输出：`类型 | 落点 | 同步 | 归档/覆盖`。

**先判替代关系**：T1 才归档旧基线；T2/T4 保留未被覆盖的基础设计/流程图/原型，只归档被替代的增量与工作文档。

| 类型 | 线索 | 落点 | 本包同步 | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 整份新 PRD/需求废止旧版 | 主副本留/落入原始资料根；按需复制；R1/R2→`01-需求基线/` | 台账、计划、文档索引 | 旧工作区基线可归档；原始资料根不动 |
| T2 方案/设计变更 | 方案 diff、技术结论 | 同上；正文吸收→`02`/`03` | 变更记录、任务清单、计划、索引 | 失去实施入口的工作区旧方案可归档；局部就地覆盖 |
| T3 未决确认 | 拍板、澄清答复 | 结论→`00-待决项`；原件留根 | 关闭待决、冻结范围 | 过程件不堆现行区 |
| T4 迭代专项/局部 | 修改方案、单模块补丁 | 原件留根；增量→方案/任务 | 影响面任务、计划 | 禁两份「最终方案」并排现行 |
| T5 范围/优先级 | 砍需求、重排期 | 计划/台账 | 状态与范围节 | 旧通知工作区侧可归档 |
| T6 缺陷/回流 | 产品回复、修复说明 | 原件留根；结论→`00` | 对齐 01～06 | 旧评估可归档 |
| T7 仅参考 | 无强制采纳 | 索引=`参考`；默认可不复制 | 一般不改 SSOT | 不进现行工作区 |
| T8 冲突 | 未裁决矛盾 | `待确认` | 停下问 | 不覆盖现行 |
| T9 交接包 | HO-ID | 多包直读；仓外按接收 | 计划/台账回写 | 发出包不可改 |

C0～C3 同协作规则。**SSOT=工作区**（R1/R2）或工作区挂引用（R0）；吸收不是把外件挪进 `01/`。

## 4. 资料收取步骤

1. 识别变化（原始资料根优先全量索引；`开发/资料/`；根散落先拟收入原始资料根）→ T1～T9 + 建议档位（索引/复制/R0～R2）。
2. 输出候选；确认前不改文件（新件落盘除外）。
3. **确认后同批**：主副本留/落入原始资料根并登记 → 仅对需要的文件复制进 `开发/资料/` → 按深度吸收 → S1/S2/S3 只动包内副本/工作区旧稿 → 更新索引/计划/activeContext。原始资料根不迁不删。
4. 中途存量：先全索引；未点名复制/吸收的保持仅索引。部分/参考保留；冲突→T8。

**覆盖关系**（本包枚举）：全量替代｜全量覆盖｜部分覆盖｜增量补充｜仅新增｜重复｜冲突。  
**失效依据**：S1 全量替代；S2 全量覆盖；S3 重复；S4 需求删除/版本取消；S5 用户明确失效。多包时若存在产品包可对齐其覆盖关系；**单包仅用本节 T1～T9 与上列 S1～S5，不强制读产品包**。禁按年龄归档。失效只作用于包内副本与工作区，不删除原始资料根主副本。

## 5. 工作文档四类

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `项目档案.md`、`activeContext.md`（含 `### 进行中` 快照）、`开发/文档索引.md` | 长期 | 就地更新；本包只改 `## 开发` |
| 根 `CHANGELOG.md` | 长期 | 只增不改；过长确认后移块到 `开发/_归档/changelog/`，禁版本关闭整文件搬迁 |
| `开发/工作日志.md` | 长期 | 过长确认后移块到 `开发/_归档/工作日志/` |
| `开发/开发计划.md` | 长期主档 | 关闭时快照到 `_归档/{yyyyMMdd}-{版本}/`，主档不移动 |
| `00-项目治理/` | 长期 | 变更/待决/决策/缺陷评估；就地更新 |
| `01-需求基线/` | 绑定 | 正文按实施入口归档；`需求台账.md` 常青 |
| `02-方案设计/` | 绑定 | 关闭或非实施入口 → 归档；但被后续迭代引用的基础设计/流程图保留原位或资料，不整夹归档 |
| `03-技术设计/` | 长期 | SSOT 就地更新；不随迭代整夹归档 |
| `04-计划与任务/` | 绑定 | 同实施入口规则 |
| `05-测试与验收/` | 绑定 | 工程侧 UAT 等；关闭归档。多包时业务 UAT SSOT 在产品，此处可引用 |
| `06-发布与交付/` | 绑定 | 一版一档；关闭归档 |
| `07-运维与协作/` | 长期 | 就地更新 |
| `08-复盘与改进/` | 绑定 | 关闭归档 |
| `开发/交接/{HO-ID}/` | 快照 | 不可改；`-v2`；台账常青 |
| `**/.draft/` 等 | 临时 | 清理候选 |

**实施入口**（方案/任务清单）：

| 留现行 | 进归档 |
| --- | --- |
| 仍有未完成功能要改代码；草案/评审中/已确认/实施中 | 主体已落地，不再作下一期入口；已实施/已执行/已归档 |

尾巴写在状态括号，不占现行入口。

## 6. 更新还是归档

主档/局部 → 就地更新。T1/失去实施入口 → 确认后归档。T4 → 增量就地或专项件，禁并排双最终方案。版本关闭 → 绑定文档归档；`00`/`03`/`07`/台账/计划主档保留。正式文档只写现行有效。

归档前做**引用检查**：被当前计划、技术设计、测试/验收引用的文档不得标记失效；先修引用或保留原位。归档清单写明“替代关系/仍被谁引用”。

## 7. 版本/迭代关闭（换迭代 = 关当前版进入下一版）

> **迭代即版本主题**：换下一期方案/新版本目录 = 结束当前迭代并开下一迭代。与「正式发布上线」**不是两套清理标准**——分类、绑定归档、失效资料、临时清理、索引/链接同一套完整分析；差别只在是否做**发版对外项**。

### 7.1 关账清单（按实际裁剪，不是少做）

> **关账前置**：先按 §3 判 T1/T2/T4。T1 全量替代才归档旧基线；T2/T4 增量/局部，保留仍被后续迭代引用的基础设计、流程图、原型，只归档被替代的增量与工作文档。

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分析分类：长期/版本绑定/失效替代/过程临时 | 必做 | 必做 |
| 更新计划/台账/索引/activeContext | 必做（指向下一迭代） | 必做 |
| 当前迭代绑定的增量方案/清单/提测/UAT/复盘等 → `_归档/{yyyyMMdd}-{版本或迭代}/`（基础设计/流程图按前置判定保留） | 必做（已确认结束的） | 必做 |
| 失效资料 → `资料/_归档/` + 清单 | 必做 | 必做 |
| 临时/过程/失败/重复清理 | 必做 | 必做 |
| 修断链 | 必做 | 必做 |
| 根 CHANGELOG 发版史 / 发布说明对外 | **跳过**（除非用户点名发版） | 必做 |
| 部署/上线检查/对外公告 | 跳过 | 按 release 门 |

### 7.2 确认结束当前迭代（不确定必问）

出现下一期方案/换主题/版本号升级，但当前迭代是否算结束不明确（例如仍在缺陷回归、提测未结）→ **STOP** `confirm_iteration_close`：出示「当前迭代标识、未完成项、拟归档摘要、下一迭代标识」→ 用户确认「结束当前并进入下一」后才执行 §7.1；用户说「并行不关」→ 只落新资料、不归档现行绑定主档，收尾记假设。

用户已明确「下一期 / 换版本 / 关这期」→ 按已确认执行，不重复空问。

### 7.3 触发（自动探测 · 同会话）

1. 新迭代/版本文档确认采纳（intake / materials / change）且判定换代，或用户确认结束当前
2. 换主题目录 / 版本号升级 / 计划范围换代
3. 正式发版/结项口令
4. 点名整理/巡检/清理（可只做清理子集，仍先分析分类）

未确认零移动；现行证据/现行主档/密钥永不自动删。

## 8. 过程/临时清理

范围 `开发/` + 项目根顶层（含 `.gate/`）；不确定 → `开发/_归档/_待清理/`。候选：已完结 `.draft/`、tmp/bak/log、副本、未引用导出；过期运行态（`.gate/frontend` 旧截图、`.gate/开发规范/` 非 JSON 媒体、`.gate/logs`）；进行中 draft、现行证据/主档、根 CHANGELOG/工作日志永不自动删。

**何时扫清理**：点名整理/巡检/清理（lifecycle）；或换迭代/关版本并入 §7.1。日常任务收尾不主动列清理、不追问。不另立「轻量卫生」标准。新任务 `-StartTask` 可自动清空 `.gate/frontend/` 旧媒体（不等同关账全清 `.gate`）。

## 10. 触发

| 时点 | 动作 |
| --- | --- |
| 接入/重新接入 | 认根并登记；确保 `开发/`+标准树；原始资料根全索引；按需复制/R0～R2；按资料模式整理原树 |
| 新文档/intake/方案变更/未决/专项 | §3～§4；确认后同步+归档同批；若换代→§7（不确定则先 `confirm_iteration_close`） |

| 点名整理/巡检/清理 | §7.1 清理子集或 lifecycle；仍先分析分类 |
| 季度可选 | 只出候选 |
