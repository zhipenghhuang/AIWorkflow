# 能力与技能体检（开发轨）

> **读取级别：参考**。仅 `workflows/skill-audit.yaml` 或点名体检时读；业务任务不读。  
> **定位**：盘点外部能力 + 检查/优化随包技能；可按项目适配，也可按通用最优（不绑具体项目）。  
> **包可独立落地**：本包目录内的 `技能/`、`能力/` **允许在用户确认后就地修改**（开源使用者、单包、多项目副本皆可）。若当前工作区要按通用最优维护，用 **通用模式** 即可。

## 1. 模式

| 模式 | 触发口令（例） | 对照基准 | 改什么 |
| --- | --- | --- | --- |
| **project** | 体检能力 / 能力优化 / 技能优化 / 优化技能 / 优化能力 …（且存在项目对照物） | 本项目档案、栈、平台、近期失败/降级、用户目标 | 本包 `技能/`、`能力/`、档案可用性；可装配外部能力 |
| **generic** | 含「通用」「不按项目」「通用优化」；**或**探测为无项目对照物（见下） | 行业/开源实践、能力表主选备选、技能完整性与冗余、映射覆盖；**禁止**写死某客户/某仓库特例 | 同上（改当前这份包文件）；保持可复用 |

**模式判定（必守）**：
1. 口令含「通用」「不按项目」「通用优化」→ **generic**。  
2. 否则若**无项目对照物** → **强制 generic**（未接入落地/无项目对照常见）：无 `项目档案.md`（或仅有模板占位未填实）、且无可用 activeContext 业务焦点可对照。报告首行写 `mode=generic（无项目对照自动）`。  
3. 有填实档案/可对照栈 → **project**（除非用户点名通用）。  
4. 禁在无对照物时硬猜某项目需求；也禁空跑「缺档案故无建议」——改做通用完整性/冗余/映射/能力表主备选分析。

## 2. 流程（与 YAML 步对齐）

1. **scope**：确认模式 + 范围（全量｜仅外部能力｜仅随包技能｜按域：前端/后端/安全/发布/缺陷…）。  
2. **inventory**：读 `能力/00-能力注册表.md` + 档案 §6（或等价）；读 `技能/README.md` 映射表；抽查映射命中的 SKILL frontmatter（name/description）；**禁止**无范围通读全部 SKILL 正文。  
3. **fit**：对照基准列「够用 / 过重 / 缺口 / 冲突 / 重复」。  
4. **propose**：输出【能力技能体检报告】（模板见下）；每条建议含证据与动作。  
5. **apply**（`confirm_skill_changes`）：用户确认后才改文件/给安装步骤；未确认 = 零改动。  
6. **wrap**：收尾骨架；待确认表列未执行项。

## 3. 建议卡（每条必填）

```text
ID / 对象（能力名 | 技能/<name>）
现象：与基准的差（证据：档案§ / 门失败 / 用户目标 / 映射缺口）
判定：缺装 | 达不到要求 | 过重 | 过时 | 重复 | 映射断裂 | 可维持
动作：装配能力 | 改能力表主选/备选 | 就地改 SKILL.md | 改技能 README 映射 | 维持+降级可接受
优先级：P0 阻断质量 / P1 明显增益 / P2 可选
成本：安装 · token · 维护
```

## 4. 可执行动作（确认后）

- **外部能力**：按能力表与 README「宿主适配」给安装/绑定步骤；可提示用户再说「装配能力」做向导式盘点。  
- **随包技能**：直接编辑本包 `技能/<name>/SKILL.md` 与 `技能/README.md`（增删映射、收窄/增补方法、修正触发描述）。  
- **能力注册表**：更新本包 `能力/00-能力注册表.md`（主选/备选/降级说明）；表外新源须先登记再引用。  
- **档案**：回写 `项目档案.md` §6 可用性。  
- **自检**：改了引用/映射后建议跑 `规则/tools/Test-Template.ps1`（点名或本轮改包时）。

## 5. 纪律

- 未 HITL 不改 `技能/`、`能力/`、不装工具。  
- 业务会话轻量建议（见 `AGENTS.md` 技能节）≠ 本体检；深度对照只在本 workflow。  
- 与「装配能力」分工：装配=安装向导；体检=诊断+优化提案（可含装配候选）。  
- generic 模式禁止把单一项目约定写进通用技能正文；project 模式允许项目向裁剪。  
- 一次会话只体检本包；多包他包请用户在对应包会话执行。
