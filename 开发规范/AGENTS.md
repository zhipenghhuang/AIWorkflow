# AGENTS.md

> **用途**：开发协作 AI 入口。新会话读 §0；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。已路由同会话中段只靠 `规则/核心/规则重锚.md` 心跳，不重读本节全文。
> **位置**：`开发规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；与用户指令冲突时见 §0 第 5 条（可覆盖）。
> **template_version**：`2026.11.01.3`（单点：包内版本以本文为准；与产品/测试交接口径对齐）。
> **架构**：Workflow + Agent + 规则/门/读取索引 + 技能/能力 + 验证层 + 开发计划控制面；落地文档 `review-docs` + `select_review_mode`（自行｜AI，仅完整档），代码审仍走 `review`。
> **分层**：本包=通用开发规则；`项目档案.md`=项目事实；根 `AGENTS.md`=挂载 + 项目自写额外要求（母版不规定偏好正文）。

## 0. 开工（每任务）

1. **中文**：对话与结论用中文；写现行结论。
2. **activeContext + 项目身份 + 开发计划（硬短读）**：任务前读 `activeContext.md` **总览（必填）** + `## 开发` 的 `### 进行中`（含 `rule_card`）+ 跨包同步；先按 `进行中` 报备（2～3 句），无则补建本包节。**同轮项目身份（每新会话一次）**：有 `项目档案.md` → 只读 §1 + §2 表；无或资料不足 → `规则/核心/入口判定.md` §5 升级补强并先回写。空壳/占位/命令不可用必须升级。总览须含一句话定位（已接入禁长期「无」）。任务开始/状态变化/阻塞/收尾更新本包进行中（只读分析除外，见执行契约 §1.2）。**三处同拍**：阶段/门/焦点/下一动作语义变化时对齐开发计划 §0 + `文档索引` §1（细则执行契约 §4 规则 7）；语义未变可只改进行中。收尾只改本包分节；多包禁改他包。L2+ 读 `开发/开发计划.md` 报备阶段/门/下一步。
3. **接入状态（一次判定）**：运行时有 `开发规范接入：已完成` → 跳过落地检查；无标记 → 按 `agents/onboard-agent.yaml` 判定一次，具备则静默打标，不具备则走 `workflows/onboard.yaml`。`Test-Template.ps1` 只在改包/点名时跑。
4. **独立判断**：不迎合；先查错误前提/逻辑跳跃/信息缺失；数字/结论尽量核实来源；用户有误直接指出；主动提醒忽略的变量、成本与偏差。**方案择优（硬）**：不适配/高风险/明显更差 → 依据+主推（可 1 备选）供确认，禁静默照做。用户按第 5 条二次坚持 → 以用户为准并记 `deviation=`。
5. **冲突与覆盖**：默认按本包规则与红线。用户指令冲突时：①不执行冲突项；②说明风险与替代；③用户再次明确选择 → 以用户为准。收尾 `deviation=` 如实。无冲突：用户明确指令 > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约 > 项目档案技术要点（若有）。**拟改与现行代码或 CI 稳定口径冲突 → 先指出再改，禁静默覆盖。** 红线默认可被用户二次明确覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 新会话首轮已路由 | 本文 **§0 硬节**（本轮一次）→ workflow 当前 step 块 → 读取索引当前行 → 当前 agent/产物；写/更新 `rule_card` |
| 同会话已路由中段 | **不重读 §0 全文**；按 `规则/核心/规则重锚.md` 做【规则心跳】→ 必要时只重读 step 块 + 读取索引当前行 + agent/产物 |
| 路由未定/首条 | 本文 §3 口令表或 `规则/核心/入口判定.md` → 再按上行走已路由；多包歧义先查根 README **意图→包** |
| 有门/写 YAML | `规则/门.md` 当前行；不通读全表 |
| 验证/收尾 | `验证/README.md` + `规则/核心/验证规则.md` + 检查矩阵 + 验收清单/证据 |
| 交接/变更 | `规则/协作/协作与交接.md` 当前节 + **默认**`通用交接单文档模板.md`（升包才读交接包说明）+ `交接台账.md`；变更按 C0～C3 |
| 前后端/交付 | `项目档案.md` §7/§8/§9；技能按步读 |
| 维护/查询 | 本文 + `规则/核心/维护.md` + 点名 |

同一会话文件未变不重读；后续 delta-only；探查限定目录/关键词。**workflow 文件只读当前 step 块（当前 `- name:` 至下一个），不整文件通读。** **规则阅读不是越多越稳**：读全本会稀释当前步约束。**读取预算（目标，非硬上限）：核心 ≤3～4 个来源（命中才读）+ ≤8k tokens；复杂可至 5；确需更多时只读当前节并在收尾说明，不得为省预算跳过门/证据/红线。** 标 `读取级别：参考` 的大文件只读当前节。宿主整文件注入本文时：中段仍只认心跳 + `rule_card`，禁止每步当全文必读。

7. **执行契约**：判断模式（execute/analyze/stop）、自主边界、步骤契约、计划同步见 `规则/核心/执行契约.md`。规则是下限不是百科全书；低价值步骤可合并/省略；输出/门/证据/红线默认不可省（用户按第 5 条选择覆盖除外）；跳过与取舍写收尾【遵守自检】，不静默偏离。只读解释/对比/诊断按 `规则/核心/执行契约.md` §1.2，不强行进入交付链；用户要详细时用分析说明，不受只读简报 2～3 行限制。
8. **规则心跳（硬）**：触发与一行格式只认 `规则/核心/规则重锚.md`；切步 / 过门前后 / 约每 5～8 轮用户消息须输出【规则心跳】并按需 `rule_card=refresh`。心跳≠收尾自检。

### 0.0 事实与文档（硬规则）

- 事实字段须来自配置/命令/权威文档/用户确认；未核实写「待确认」。同一事实单一来源；正式资产只写现行有效（细则 `规则/核心/文档质量标准.md` §1 第9条）。
- 模板/规则/技能可适配：先拟改/原因/影响，确认后改本包；能靠产出解决的优先改产出。
- **版本标识分离**：产品/测试/构建/部署/文档版本分开；测试只认实际部署版；项目须暴露版本查看方式。矩阵见 `规则/核心/版本策略.md`。

### 0.1 任务分级（防过度/不足）

| 级别 | 典型 | 必走 | 可跳过 |
| --- | --- | --- | --- |
| L0 微改 | 单文件/文案/配置；无行为/契约/权限/数据变化 | clarify → implement → verify → commit | requirements/design/review-docs/plan/review/deliver/release |
| L1 常规 | 多文件、范围收敛、无跨系统契约 | clarify →（轻量卡）→ implement →（代码 review 按风险）→ verify →（有 QA）deliver → commit | 全量 PRD/ADR；有新方案则问 A/B |
| L2 功能/迭代 | 新功能、跨模块、接口/数据变更、多任务 | requirements → design（条件）→ **review-docs（A/B）** → plan → implement → review → verify → deliver → release_handoff（条件）→ retro（条件）→ wrap → commit | 无 |
| L3 高风险 | 权限/资金/迁移/公共 API/安全/破坏性 | L2 + 文档/代码独立审 + 安全/隐私 + 回滚演练 + 发布审批 + 观察 + 复盘 | 无 |
| 缺陷 | 平台缺陷/指派/修复#/产品评估/产品回复 | defect-fix：preflight → pull → triage →（fix/assess→handoff→await→decision→align/clarify）→ gates → menu → close → postrelease | 无平台→change |

分级在 clarify 写入首条路由；不确定先最小充分，高风险/不可逆/跨包再高一档。L0：证据/提交确认/密钥/理解回执不可省（纯机械除外）。L2+ 默认 `开发/开发计划.md`。轻量档默认 `solo`（`规则/核心/轻量交付.md`）；拿不准高一档+一问。**评审**：L0 与 L1 低风险单点可免独立审；L2+/L3/权限·资金·迁移·公共 API·破坏性不可免；免审不免自检。

### 0.2 确认门 · 澄清 · 直跑

- 门只认 YAML `hitl`/`hitl_when`/`gate_when` + `规则/门.md`；不另造门。
- 意图/澄清/P·D·S：**只认** `规则/核心/澄清.md`；含糊口令禁直接写交接单。
- 产品资料 → `技能/product-doc-analysis`；理解包 §0 Brief+差量表必填，无 §0 不拆单/实施。
- 直跑只到任务完成（不含提交/推送/部署/回写）；他包产物可选不阻塞，AC/完成门/自验不可省；档位/准出不确定 → 推荐+一问。自主边界见 `规则/核心/执行契约.md`。

### 0.3 硬红线（易疏忽）

1. 证据先于结论；未验证不称完成。
2. 缺陷：修前红证；禁回退补红证；无根因不修；未验证不回写；产品缺陷先评估/确认。
3. 最小改动；密钥零入库；文档只写现行；新输入按 `规则/文档治理.md` §3 分流。
4. 禁刷绿；git 前拟提交确认；分支/推送/PR 见 `规则/工作流.md` §2。
5. 子代理禁 git/平台/改门；高风险核验者≠实施者。
6. 文档不落根；发布不跳门；失败按回滚预案。
7. 需求理解先于方案；UX/DX/AX 不净退化。
8. **跨层**：L2+/L3 或权限/状态/数据基数/多表面 → `技能/cross-layer-consistency`；同判定单服务端谓词；UI 可见须同权 API。
9. **实施质量**：只认 `规则/核心/实施质量门.md`（SC 先于代码；DEV-IQ-09 预检；DEV-IQ-10 重要面硬补；自测只认方案/AC）。

### 0.4 验证与汇报（硬约束）

1. **完成只认门**：`-StartTask` → `验证/Invoke-Gate.ps1` → `.gate/开发规范/completion.json` 本轮 `COMPLETE`；空窗口/`DRY_RUN` 不算。
2. 证据先于结论；子代理自述不算；前端须浏览器验证。
3. 程序 SSOT：`规则/核心/验证规则.md` + `验证/README.md`；质量门对账见 `实施质量门.md` §8。

### 0.5 工程与执行

- 质量条：`技能/engineering-quality` + `规则/工作流.md` §3.4。方案落地/预检：`实施质量门.md`。
- 执行：多解先权衡；失败同方案 2 次换路径；最小改动；先工具后子代理；改动面超预期先停。优先直接编辑文件。
- 框架固定（口令→workflow、hitl、证据/密钥/子代理/git/文档落位）默认可被第 5 条覆盖；路径/工具/拆分可自主。

### 0.6 协作与交接（硬约束）

> 细则只认 `规则/协作/协作与交接.md` 当前节。硬句：内容优先、默认择优单文档；HO 仅触发命中；正式签收/C2·C3/发布须回执；C2/C3 重基线过门。

### 0.7 提交、推送、部署（硬约束）

> 提交｜推送｜部署分开；默认只提交。git/拟提交/分账只认 `规则/工作流.md` §2；发布/环境只认 `规则/核心/版本策略.md`。`COMPLETE`+`confirm_deploy` 才部署；直跑不含自动提交/推送/部署。  
> **尽早提交**：重要改动确认后尽早本地提交，勿长期只停在工作区。**多 remote / 异形 tip**：禁对本工作树 `checkout`/`reset` 到非日常工作 tip；对该 tip 的同步/历史改写只走临时目录或独立 worktree（§2 分支纪律第 6 条）。

## 1. 接入

实例：`项目档案.md`（§1/§7/§8/§9）+ `activeContext.md`；工作根必须有 `开发/`；原始资料根推荐 `docs/`（其它名可）；占位符未换=未接入。交接：`开发/交接/出站|入站/{类别}/` + `交接台账.md`（唯一登记；`资料/交接` 不作主入口）；多包同仓直读对方出站，仓外经 docs→入站分析吸收。
口令「接入/重新接入/档案/文档树」→ `onboard.yaml`；必须建索引+标准树+原始资料根+本包 `资料/`+根 `CHANGELOG.md`+`开发/工作日志.md`；L2+ 另建开发计划/变更记录/待决项/决策记录/需求台账。

## 2. 收尾

触发：工作流末步、计划结束、点名「收尾/总结」。**对照** `规则/模板/90-交接与收尾/收尾骨架.md` §2。**必须含【遵守自检】与「运行态：」行**，缺项=未收尾。提交/推送/部署/回写门按 YAML `hitl` 独立确认；完整【拟提交】在 commit 只展示一次（第 2 点仅「待提交摘要」）；默认仅提交，推送单独确认；未提交默认不得开始下一任务（例外=基线检查选项 C/D 且用户确认）。

## 3. 口令 → Workflow（命中即停）

> **描述**：表内是常见口令示例（非穷尽），同义表述按五元组路由，不要求逐字匹配；命中优先执行。未命中或任意描述句 → 必读 `规则/核心/入口判定.md`：抽五元组（动作/对象/结果/连续/体量）→ 意图类 A～L → 项目状态修正；首条必写 `reason=`（可附 `intent=`）。不抠固定措辞；路由后按步加载技能，不另造 workflow。

**部署歧义（硬规则）**：裸说「部署/推服务器」先判环境，不默认 S8：test/staging/UAT → S7 环境部署（版本按项目模式，只记录+冒烟，不触发 `confirm_deploy`）；prod/生产/正式 → `release`/S8；无法判断只问一次目标。提交/推送 ≠ 部署。
**复合口令**：「提交推送部署更新服务器」= commit→push→环境更新；唯一 test 环境按 S7，多环境问一次；不得默认 S8。

**入口直达**：单步口令（代码评审/提测/下一步/回滚/澄清）只执行该 step 到产出完成即停；`change`/`iterate`/`release` 按各自链路继续到下一个门或收尾；「只出任务清单」到 wrap + commit 确认即止。`workflow.chain: full`（如 onboard）例外，必须走到 verify/打标。单步入口仍按 `规则/模板/90-交接与收尾/收尾骨架.md` 输出。
**互斥**：「落地…#编号…优化方案」=缺陷；「落地迭代方案」=迭代；无 `#` 又无「迭代」→ 一问。未命中 1～5 的改代码/改配置实施类 → `change`；发布/回滚/复盘各自独立。有开发计划且续跑语义（下一步/继续开发计划/当前状态）→ 优先 `control`。
**无口令**：口语未命中上表 → `规则/核心/入口判定.md`（通用意图类，非口令同义词表）。
**首条**：`route=workflow:<id> | step=<id> | level=<L0-L3> | mode=... | reason=... | reads=<读取索引行> | next_action=…`；有输入加 `input=<diff/路径>`。纯只读分析可写 `route=readonly:analysis | step=explain | mode=analyze | reason=… | next_action=…`。

## 4. 维护

## 7. 多包（自动探测）

- **口令表节号**：本包与产品 §3；测试 §2（勿跨包按节号直译）。
- **单包独立为默认**；多包联动**可选、非必须**；不要求装齐三包、不强制同时启用、**不因缺他包阻塞本包**；跨包同步只登记状态，不等于自动联动。**联动=交付物字段+同仓直读，≠共安装、≠自动跑对方、≠强制引用他包路径。**
- ≥2 个包目录=多包；共用原始资料根（推荐 `docs/`）、根 `activeContext.md`（总览→各包分节→跨包同步→运行时）。
- 各包只改本分节/本包接入行/相关跨包同步一行；禁整文件覆盖或改他包分节；一次会话只跑一个包 workflow；跨包默认自洽交付物/同仓直读对方 `交接/出站/`，**仅升包时**用 `出站/{类别}/{HO-ID}/`；不复制正文、不自动跑对方。
- **歧义定包**：缺陷/发布/下一步等先查根 README **意图→包**；无法唯一则一问。
