# AGENTS.md

> **用途**：开发协作 AI 入口。常驻最小集；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。
> **位置**：`开发规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；红线不被覆盖。
> **template_version**：`2026.10.28.12`（单点：包内版本以本文为准；与产品/测试交接口径对齐）。
> **架构**：Workflow + Agent + 规则/门/读取索引 + 技能/能力 + 验证层 + 开发计划控制面；落地文档 `review-docs` + `select_review_mode`（自行｜AI），代码审仍走 `review`。

## 0. 开工（每任务）

1. **中文**：对话与结论用中文；写现行结论。
2. **activeContext + 开发计划**：任务前读 `activeContext.md` 总览 + `## 开发` + 跨包同步，2～3 句报备焦点/下一步；无则按模板创建（只建本包节）。有实质进展收尾只更新本包分节。多包时禁止改他包分节/他包接入行。L2+ 同时读 `开发/开发计划.md`，报备阶段/门/下一步。
3. **接入状态（一次判定）**：`activeContext.md` 运行时有 `开发规范接入：已完成` → 跳过落地检查；无标记 → 按 `agents/onboard-agent.yaml` 判定一次，具备则静默打标，不具备则走 `workflows/onboard.yaml`。`Test-Template.ps1` 只在改包/点名时跑。
4. **独立判断**：不迎合；先查错误前提/逻辑跳跃/信息缺失；数字/结论尽量核实来源；用户有误直接指出依据与风险。
5. **冲突优先级**：安全/合规/硬红线（§0.3） > 用户明确指令 > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约 > 项目规范要点。红线不被覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 任意已路由 | 本文 §0～§3（含口令表）→ workflow 当前 step 块 → 读取索引当前行 → 当前 agent/产物 |
| 有门/写 YAML | `规则/门.md` 当前行；不通读全表 |
| 验证/收尾 | `验证/README.md` + `规则/核心/验证规则.md` + 检查矩阵 + 验收清单/证据 |
| 交接/变更 | `规则/协作/协作与交接.md` 当前节 + `规则/模板/90-交接与收尾/交接包说明模板.md` + `交接台账.md`；变更按 C0～C3 |
| 前后端/交付 | `项目档案.md` §7/§8/§9；技能按步读 |
| 维护/查询 | 本文 + `规则/核心/维护.md` + 点名 |

同一会话文件未变不重读；后续 delta-only；探查限定目录/关键词。**workflow 文件只读当前 step 块（当前 `- name:` 至下一个），不整文件通读。** **规则阅读不是越多越稳**：读全本会稀释当前步约束。**读取预算（目标，非硬上限）：常规单步 ≤3 个来源/≤8k tokens；确需更多时只读当前节并在收尾说明，不得为省预算跳过门/证据/红线。** 标 `读取级别：参考` 的大文件只读当前节。

7. **执行契约**：判断模式（execute/analyze/stop）、自主边界、步骤契约、计划同步见 `规则/核心/执行契约.md`。规则是下限不是百科全书；低价值步骤可合并/省略，但输出/门/证据/红线不可省；跳过与自主取舍写收尾【遵守自检】，不静默偏离。

### 0.0 事实与文档（硬规则）

- 环境/构建/账号/日期/结果/缺陷号/发布窗口/审批结论等事实字段，必须来自配置、命令输出、权威文档或用户确认；未核实写「待确认」并问，禁止用默认/示例/历史值补。
- 生成后回查关键字段；同一事实只保留一个来源；文档只写现行事实，禁辩解/对比/猜测式结论；结构完整≠合格，按 `规则/核心/文档质量标准.md` 判。
- 母版只维护通用高标准；项目实例默认不改，但不锁死：发现模板/规则/技能不匹配 → 先出「拟改/原因/影响」，用户确认后只改当前实例并登记；不自动回灌母版。
- 模板是骨架、标准是底线：按项目实际裁剪，不适用写「不适用 + 理由」；产出层能解决的不改母版。

### 0.1 任务分级（防过度/不足）

| 级别 | 典型 | 必走 | 可跳过 |
| --- | --- | --- | --- |
| L0 微改 | 单文件/文案/配置；无行为/契约/权限/数据变化 | clarify → implement → verify → commit | requirements/design/review-docs/plan/review/deliver/release |
| L1 常规 | 多文件、范围收敛、无跨系统契约 | clarify →（轻量卡）→ implement →（代码 review 按风险）→ verify →（有 QA）deliver → commit | 全量 PRD/ADR；有新方案则问 A/B |
| L2 功能/迭代 | 新功能、跨模块、接口/数据变更、多任务 | requirements → design（条件）→ **review-docs（A/B）** → plan → implement → review → verify → deliver → release_handoff（条件）→ retro（条件）→ wrap → commit | 无 |
| L3 高风险 | 权限/资金/迁移/公共 API/安全/破坏性 | L2 + 文档/代码独立审 + 安全/隐私 + 回滚演练 + 发布审批 + 观察 + 复盘 | 无 |
| 缺陷 | 平台缺陷/指派/修复#/产品评估/产品回复 | defect-fix：preflight → pull → triage →（fix/assess→handoff→await→decision→align/clarify）→ gates → menu → close → postrelease | 无平台→change |

分级在 clarify 判断并写入首条路由；不确定按高一档。L0 不强制文档，但证据/提交确认/密钥红线不可省；L0 也不得跳过理解回执（纯机械操作除外）。L2+ 默认启用《开发计划》；路径 `开发/开发计划.md`。

**评审分级**：独立代码评审不是每阶段一律强制。L0、以及 L1 中确实低风险/单点的改动可免独立评审；**L2+、L3、权限/资金/迁移/公共 API/破坏性变更不可免**。免审必须在计划/任务清单记录理由与风险接受人；**免审不免自检**——测试/冒烟/证据仍按级别执行（有 `*_scoped` 则定向，否则全仓）。不得把 L2+ 说成“阶段简单”绕过评审；若确实简单，先重定级并记录。

### 0.2 确认门 · 澄清 · 直跑

- **只认 YAML 步上 `hitl`/`hitl_when`/`gate_when`**；语义见 `规则/门.md`。条件不满足则跳过；专规不另造门。
- **门档位**：autonomous（L0/只读/可逆，直接做）｜notify（L1、清单/节奏未实质变化，展示后继续）｜approve（L2+ 范围/方案/清单实质变化、L3、部署/回滚/回写/提交）。
- **澄清**：按 `规则/核心/澄清.md`；先读规则/技能/代码/文档做分析，再给「我的理解 + 已分析建议 + 需要你拍板（0～1 个）」；只问影响意图/范围/验收/风险的问题；总提问 ≤3（阻塞/安全/合规/高风险问题不受 3 问限制，但仍一次一问）；不确定项按澄清§2.1分流。
- **产品资料先解析**：输入含 PRD/迭代方案/需求文档/页面原型/截图/接口或技术文档 → 先按 `技能/product-doc-analysis/SKILL.md` 产出带引用的理解包；原型只作 UI/交互依据，冲突列出来问，不反推后端规则。
- **直跑/预授权**：口令命中 → 首条 `route=...`；「一次性/直接跑完」默认只到任务完成，不含提交/推送/部署/回写。只免等待，不免输出。
- **可选输入不阻塞**：缺 PRD/方案/提测单/测试报告/UAT/缺陷单 → 一句话说明缺口，由用户提供/选择已有资料/本包模板补；禁因缺其它包阻塞。

**澄清停止条件**：理解已复述、关键高影响问题已确认、技术细节已有建议/方案；剩余只是低影响假设或待用户确认的建议。95% 仅参考；连续 3 轮无新信息 → 收敛范围或给推荐方案，不继续盘问。澄清记录按 `规则/核心/澄清.md` §7 落盘。

### 0.3 硬红线（易疏忽）

1. 证据先于结论；未验证不称完成。
2. 缺陷：修前红证；禁回退补红证；无根因不修；未验证不回写；产品缺陷先评估单/产品确认。
3. 最小改动；密钥零入库；文档只写现行；旧版确认后同批归档；新输入先按 `规则/文档治理.md` §3 分流。
4. 禁刷绿（改断言/跳测试/关告警）；git 前拟提交确认；分支/推送/PR 按 `规则/工作流.md` §2。
5. 子代理禁 git/平台/改门；核验后再结论；高风险/破坏性核验者≠实施者。
6. 文档不落根；发布不跳门；失败按回滚预案。
7. 需求理解先于方案；全局体验（界面减法/UX-DX-AX 不净退化）。

### 0.4 验证与汇报（硬约束）

1. **落地文档先选 A/B**（`select_review_mode`，方法 `技能/design-doc-review`）；代码评审按 L0～L3 定 `review_required`。L2+/L3/高风险不可免；免审记录理由/接受人；多波次在计划里二选一（每波审/只 S5 全量），不混用。
2. **完成只认门**：任务开始 `-StartTask`（冻结 `base_commit`）；改动跑 `验证/Invoke-Gate.ps1`，读 `.gate/开发规范/completion.json`。无本轮 `COMPLETE`（task/diff 匹配）只能报未验证/部分/阻塞；空窗口/`DRY_RUN` 不算完成。
3. **证据先于结论**：结论引本轮检查/退出码/证据路径；子代理自述不算证据；失败/缺环境=`BLOCKED`。
4. **前端必须浏览器验证**（状态/视口/console/network/截图/设计 QA）；报告先写【验证回执】；非 `COMPLETE` 禁用“完成/通过/已修复”。
5. **门不替代授权**；成本纪律（`*_scoped` 定向/全量留发布/截图 1 张每页/不通读规则）见 `验证/README.md`、`规则/核心/验证规则.md`。

### 0.5 工程与执行

- **质量条**：`技能/engineering-quality/SKILL.md` + `规则/工作流.md` §3.4；不可省：可测逻辑补测、密钥零入库、外部输入校验、破坏性变更先确认、回滚/降级路径。
- **执行**：多解先权衡；先工具后子代理；不预防性通读；改动面超预期先停。
- **框架固定/局部自主**：口令→workflow、步上 hitl、输出骨架、证据/红绿、密钥、子代理边界、git 纪律、文档落位不可让；实现路径/顺序/工具/拆分/措辞可自主。低价值步骤可合并/省略，但输出/门/证据/红线不可省；规则未覆盖时按目标+事实+最小可验证路径，收尾记录取舍。

### 0.6 协作与交接（硬约束）

1. 交接内容优先、包按需、正文通用；提测默认自洽提测单，HO 包先问后发；有平台不重复 BUG/FIX 整包；多包同仓直读；未回执不得称「已接收」。
2. 三件套 `00/01/快照` 缺一不发；提测包须 `COMPLETE`，发布包须 `confirm_deploy`；接收三选一（接受/有条件/退回），同轮回写计划/索引/台账。
3. 变更 C0～C3：C2/C3 必须重基线过门，禁止拆小绕过；交接/变更后更新 `交接台账` → 开发计划 §0/§1/§12 → 索引 → `activeContext`。

### 0.7 提交、推送、部署（硬约束）

> 本地提交（可逆）｜推送（远程可见）｜部署（环境变更）三件事分开；默认只提交。

- 任务前有前序未提交 → 【基线检查】；完成自测/评审后 → 【提交检查】+【拟提交】；会话结束 → 【提交提醒】；>20 文件或 >500 行先拆分/说明。
- 发布只从干净工作区、已提交/已打 tag 的版本构建；`COMPLETE` + `confirm_deploy` 才部署；回滚单独 `confirm_rollback`。
- 一任务/一逻辑一次提交；禁 `git add -A` 混前序；无关文件/生成物/密钥不入库；用户说「直接跑完」也不自动提交/推送/部署。

## 1. 接入

实例：`项目档案.md`（§1/§7/§8/§9）+ `activeContext.md`；占位符未换=未接入。交接 `开发/交接/{HO-ID}/` + `交接台账.md`（唯一登记）；多包同仓直读，仓外包在用户放置处读。
口令「接入/重新接入/档案/文档树」→ `onboard.yaml`；必须建索引+标准树+`资料/`+根 `CHANGELOG.md`+`开发/工作日志.md`；L2+ 另建开发计划/变更记录/待决项/决策记录/需求台账。

## 2. 收尾

触发：工作流末步、计划结束、点名「收尾/总结」。按 `规则/模板/90-交接与收尾/收尾骨架.md`：中文回执 → 第1点纯汇报 → 第4点待确认表（无则「待你确认：无」）→ 第6点进度/下一步；**必须附【遵守自检】**（route/mode/reads/gates/sync/skip/deviation），缺项=未收尾。提交/推送/部署/回写门按 YAML `hitl` 独立确认；`wrap` 只报未提交数，完整【拟提交】在 commit 只展示一次；默认仅提交，推送单独确认；未提交不得开始下一任务。

**入口直达**：单步口令（代码评审/提测/下一步/回滚/澄清）只执行该 step 到产出完成即停；`change`/`iterate`/`release` 按各自链路继续到下一个门或收尾；「只出任务清单」到 wrap + commit 确认即止。`workflow.chain: full`（如 onboard）例外，必须走到 verify/打标。单步入口仍按 `规则/模板/90-交接与收尾/收尾骨架.md` 输出。
**互斥**：「落地…#编号…优化方案」=缺陷；「落地迭代方案」=迭代；无 `#` 又无「迭代」→ 一问。未命中 1～5 的改代码/改配置实施类 → `change`；发布/回滚/复盘各自独立。
**首条**：`route=workflow:<id> | step=<id> | level=<L0-L3> | mode=execute/analyze/stop | reads=<读取索引行> | next_action=…`；有输入加 `input=<diff/路径>`。

## 4. 维护

改不变量/路由/读取协议 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/门 → `规则/`；改澄清 → `规则/核心/澄清.md`；改协作/交接/变更分级 → `规则/协作/协作与交接.md` + `workflows/handoff.yaml`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`；改文档树/归档 → `规则/文档治理.md`；改子代理 → `规则/协作/子代理编排.md`；改读取索引 → `规则/读取索引.md`。自检见 `规则/核心/维护.md` §2。

## 5. 文档治理（摘要）

- 工作文档根 `产品/` · `开发/` · `测试/`；旧 docs/ 用 keep/mix/replace，映射记档案。根白名单：代码/构建、README、根 `CHANGELOG.md`、`项目档案.md`、`activeContext.md`、三包目录、`项目资料/`、`.gitignore`。
- 资料区 `开发/资料/{版本或主题}/` + `_通用/` + `资料/_归档/`；入站 T1～T9；确认采纳且 S1/S2/S3 → 同批归档；工作产物不回写资料；单包不自动跑他包。
- **换迭代=关版本**：新迭代/换代/换主题（可不发版）→ 同会话按文档治理 §7；不确定 → `confirm_iteration_close`；确认后 §7.1 完整归档清理。根 `CHANGELOG.md`=发版史；`开发/工作日志.md`=岗位里程碑；发布说明按版本。

## 6. 技能与能力（按步加载）

- **角色边界**：谁负责/能定/何时停/向谁升级见 `规则/协作/角色契约.md`；冲突先查表。
- **技能**：`技能/<name>/SKILL.md` 命中步必用；阶段→技能见 `技能/README.md`；新增/大改按末节质量标准（description 含中文触发词、≤500 行、超长拆 references）。
- **能力**：`能力/00-能力注册表.md` 已装即用、未装降级；「装配能力」=安装，「体检能力」=诊断+优化（`skill-audit.yaml`）。业务会话最多 1 条有证据的建议，禁推销。

## 7. 多包（自动探测）

- ≥2 个包目录=多包；共享 `项目资料/`、根 `activeContext.md`（总览→各包分节→跨包同步→运行时）。
- 各包只改本分节/本包接入行/相关跨包同步一行；禁整文件覆盖或改他包分节；一次会话只跑一个包 workflow；跨包用 `{HO-ID}` 整包，不复制正文、不自动跑对方。
