# AGENTS.md

> **用途**：开发协作 AI 入口。本文只放常驻最小集；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。
> **位置**：`开发规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；红线不被覆盖。
> **template_version**：`2026.10.23.5`（单点：包内版本以本文为准）。
> **架构**：Workflow YAML + Agent 契约 + 规则/门/读取索引 + 内置技能 + 可选能力 + 开发计划控制面（L2+）。

## 0. 开工（每任务）

1. **中文**：对话与结论使用中文；输出写现行结论。
2. **activeContext + 开发计划**：任务前读 `activeContext.md`，2～3 句报备焦点/下一步；L2+ 同时读 `{文档事实源目录}/开发计划.md`，报备阶段/门/下一步。无 activeContext 按模板初始化；无计划且 L2+ → 按 `技能/development-plan/SKILL.md` + 模板创建（或走 `control init`）。
3. **接入状态（一次判定 · 禁止每任务自检）**：读 `activeContext.md`；已有 `开发规范接入：已完成` → 跳过落地检查。无标记 → 按 `agents/onboard-agent.yaml` 接入清单判定一次：已具备 → 静默打标；不具备 → 走 `workflows/onboard.yaml`，核验后打标再继续。`Test-Template.ps1` 只在改包/点名自检时跑。
4. **独立判断**：不迎合；先查错误前提、逻辑跳跃与信息缺失；数字/结论/人物尽量核实来源；用户有误直接指出依据与风险；主动提示被忽略的变量、成本、偏差与依赖。
5. **冲突优先级**：用户明确指令 > 安全/合规/硬红线（§0.3/§0.5） > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约 > 项目规范要点（`项目档案.md` §7）。红线不被 agent 契约或输出偏好覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 任意已路由 | 本文 §0～§2 → `workflows/{workflow}.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 agent/产物 |
| 有门/要写 YAML | `规则/门.md` 当前行；不要通读全表 |
| 重阶段（缺陷/迭代/发布） | `规则/playbooks/` 对应卡；细节按卡指针读节 |
| 前后端/交付细节 | `项目档案.md` §7/§8/§9 |
| 文档治理 | `规则/文档治理.md` 当前节；旧 `资料治理.md`/`文档生命周期.md` 仅指针 |
| 分片/长任务 | 达 `规则/子代理编排.md` §2 阈值才拆；不预防性通读 |
| 维护/查询 | 本文 + `规则/维护.md` + 点名 |

同一会话文件未变不重读；后续步骤 delta-only；探查限定目录/关键词。**规则阅读不是越多越稳**：读全本会稀释当前步约束。

**资料收取（仅当有新文件/变化）**：按 `规则/文档治理.md` §3 输出【资料收取与归档候选】；确认前只读，不改名/不移动/不标记失效。无新文件不扫描。
**多包（自动）**：同项目根存在两个及以上包目录时自动启用，详见 §7；单包不启用。
**文档生命周期**：版本关闭/点名「文档整理/巡检/清理」时，按 `规则/文档治理.md` §4～§9 输出【文档治理检查】；确认后才执行。禁止中途顺手删除。

### 0.1 任务分级与最小流程（防过度/不足）

| 级别 | 典型 | 必走 | 可跳过 | 主要产物 |
| --- | --- | --- | --- | --- |
| **L0 微改** | 单文件、无契约/数据/权限/安全影响、≤约 30 分钟 | clarify → implement → verify →（有变更）commit | requirements/design/plan/review/deliver/release | 收尾六段；必要时轻量需求卡 |
| **L1 常规** | 多文件但范围收敛、无跨系统契约 | clarify →（轻量需求卡）→ implement →（review 按风险）→ verify →（有 QA）deliver → commit | 全量 PRD/ADR/单独计划 | 需求卡/提测单（如交接） |
| **L2 功能/迭代** | 新功能、跨模块、接口/数据变更、多任务 | requirements → design（条件）→ plan → implement → review（按风险）→ verify → deliver → commit → release_handoff（含部署） | 无 | 需求基线/方案/任务清单/提测单/发布说明 |
| **L3 高风险** | 权限/资金/数据迁移/公共 API/安全合规/破坏性 | L2 全链 + 独立评审 + 安全/隐私检查 + 回滚演练 + 发布审批 + 发布后观察 + 复盘 | 无 | L2 + 上线检查单/发布记录/复盘 |
| **缺陷** | 平台缺陷/指派/修复#/产品缺陷评估/产品回复 | `defect-fix`：preflight → pull → triage →（fix / assess_product → handoff_product → await_product → product_decision → align / clarify）→ gates → menu → close → postrelease | 无平台→change | 总结菜单/备注/评估单/发布记录 |

分级由 AI 在 clarify 判断并写入首条路由；不确定按高一档。L0 不强制文档，但证据/提交确认/密钥红线不可省；**L0 也不得跳过理解回执**（纯机械操作除外）。
**L2+ 默认启用《开发计划》**；L0/L1 可写「不适用」或轻量开发卡。计划路径 `{文档事实源目录}/开发计划.md`；阶段表/门/证据/下一步随进展更新。S3 叫**任务与排期**，不单独叫“开发计划”。
术语：RP=Requirement Point（`R-xx`）；AC=验收标准；DoR=开工条件；DoD=完成定义；波次=同一迭代内可重复走 S2～S5 的切片（`W1`/`W2`…）。

### 0.2 确认门 · 澄清 · 直跑

- **只认 YAML 步上 `hitl`/`hitl_when`**；门/gate/`when` 语义见 `规则/门.md`。条件不满足则跳过；专规不另造门。
- **门档位**：autonomous（L0/只读/可逆，直接做）｜notify（L1、清单/节奏未实质变化，展示后继续）｜approve（L2+ 范围/方案/清单实质变化、L3、部署/回滚/回写/提交）。
- **防重复**：同一确认点只问一次；同批信息只展示一次；固定骨架/菜单/拟提交不得省略；禁长文复述规则代替开跑。
- **澄清追问环（强制）**：按 `规则/澄清.md` 执行；任何任务先给「理解回执」（一句话目标 + 置信度 + 缺口），**一次只问一个问题**并附建议；按回答更新理解与置信度，直到 ≥95% 且能复述「谁/场景/做什么/系统怎么响应/怎么算对/明确不做什么」，用户明确确认后才产出最终方案/基线/清单/代码。非机械任务至少问 1 个高影响问题（复述确认也算）；低风险也先复述；仅纯信息查询/机械操作可免（免问也留一行回执）。禁一次多问、禁自问自答、禁把假设当结论、禁把确认门当澄清。
- **产品资料先解析**：输入含 PRD/迭代方案/需求文档/页面原型/截图/接口或技术文档 → 先按 `技能/product-doc-analysis/SKILL.md` 产出带引用的理解包；原型只作 UI/交互依据，冲突列出来问，不反推后端规则。
- **澄清与门**：确认门是授权，不是澄清；澄清回答不自动授权执行。门可一次展示多个授权选项，但不得夹带澄清问题。
- **直跑**：口令命中 → 立即 `route=workflow:<id> | step=… | level=… | reads=… | next_action=…`；步内条件 hitl 仍执行。
- **预授权**：「一次性/直接跑完」默认只到任务完成，不含提交/推送/部署/回写；收到后声明默认界并直接执行。只免等待，不免输出。
- **可选输入不阻塞**：缺 PRD/方案/提测单/测试报告/UAT/缺陷单 → 一句话说明缺口，由用户提供/选择已有资料/本包模板补；禁因缺其它包阻塞。

**澄清停止条件**：能预测用户对下 3 个问题的反应 + 能按 `规则/澄清.md` §4 复述（谁/场景/做什么/系统怎么响应/怎么算对/不做什么）+ 用户明确说「对/是/按这个来」；「随便/你决定/看着办/沉默」不算确认。连续 3 轮置信度不升 → 换问法或回退重问。澄清记录按 `规则/澄清.md` §7 落盘。

### 0.3 硬红线（易疏忽 · 准确度）

1. 证据先于结论；未验证不声称完成。
2. 缺陷：修前红证；禁修复后回退补红证；无根因不修；未验证不回写；产品缺陷先评估单、产品确认后才实施；评估单≠完整技术方案。
3. 最小改动；密钥零入库；正式文档只写现行有效；旧版归档不堆“最终版”。
4. 禁刷绿跳过门禁；禁先实现后补测冒充验收；禁改断言/跳过测试/禁用告警凑绿（豁免须用户批准）；git 前拟提交确认；分支/推送/PR/合并按 `规则/工作流.md` §2 与档案 §1。
5. 子代理禁 commit/push/开 PR/合并/改平台/改确认门；核验后再结论；高风险/大改/破坏性变更核验者≠实施者。
6. 平台备注按专规写全（行间 `<br>`；禁每行 `<p>`/行间空行）；备注与状态同轮；面向测试/产品只写中文结论与业务事实。
7. 遇错先析因；同方案无效 2 次换路径；缺陷闭环 3 次回根因。
8. 文档不落根；方案/清单/报告/截图/临时文件进标准目录；根目录只留白名单（`规则/文档治理.md` + 本文 §5）。
9. 发布不跳门：未过上线检查单/审批不得部署；验证失败按回滚预案，不恋战。
10. 子代理不越界：按 `规则/子代理编排.md` 取档；不达阈值不拆；同一文件/清单/单据不并行写；返回 ≤30 行。
11. 需求理解先于方案：未完成理解回执/确认，不得凭 PRD 标题、聊天记忆或截图写基线/方案/清单/代码；不得把原型/截图当后端规则；冲突/缺口必须显式列出。

### 0.4 执行中（效率）

1. 多解需拍板 → 一句权衡再建议；路径唯一则直接做。
2. 跑命令前确认环境与依赖。
3. 动手前说明拟改文件；优先直接编辑；仅批量/重复性操作才生成脚本；最小改动。
4. 增强能力首缺提示（每能力一次）；已安装/已提示 → 静默。
5. 文档/开发计划同步：产出在收尾前落位并更新 `{文档事实源目录}/文档索引.md`；L2+ 更新开发计划 §0/§1/§12；版本/里程碑变更同步根 `CHANGELOG.md`。
6. 资料先确认（`规则/文档治理.md` §3）；文档生命周期先确认（§4～§9）。
7. 先工具后子代理：能脚本/校验器/单上下文完成的不派；连续 2 批无净收益回直做。

### 0.5 工程红线

1. 可测逻辑同步补测（无测点除外）。
2. 不引入未声明依赖；新增依赖看版本/许可证/维护状态。
3. 外部输入校验；防注入/越权；接口鉴权按接口自校；外部调用设超时与错误处理；错误不回传敏感信息。
4. 不改已评审契约；破坏性变更先文档+确认（含回退思路）。
5. 不动生产数据；破坏性操作先确认；迁移脚本幂等、可回滚/前滚。
6. 个人信息最小化/脱敏；证据不夹带真实 PII/密钥。
7. 高风险变更用开关/降级/可回滚路径；发布前有回滚预案。

### 0.6 框架固定 · 局部自主

- **不可让**：口令→workflow、`hitl`/`hitl_when`、专规输出骨架、预授权界、证据/红绿、密钥、子代理阈值与边界、git 分支/推送/PR/合并纪律、接入标记语义、能力取用与降级、文档落位/根目录白名单、文档现行有效。
- **应交 AI**：步内实现路径、探查顺序、是否派子代理、验证命令、文档措辞、任务拆分粒度；禁另造确认门或预防性通读。
- **规则未覆盖/冲突**：以用户目标、代码事实与既有门禁为先，选最小成本可验证路径；收尾记录取舍，不新增门、不跳红线。
- **成本**：择优在推理中完成，不另开规划回合；计划/评审/发布等条件步只在触发时执行。

### 0.7 文档现行有效

只描述当前存在的功能/流程/规则；删除即移除；不记录历史过程；不引入不存在概念；结论不复述过程或方案草稿。例外：变更记录/CR/待决项/DEC/执行日志/复盘可留痕，但不回流需求基线/方案/任务清单/发布说明。

## 1. 接入

实例在项目根：`项目档案.md`（§7 项目规范、§8 交付治理、§9 文档归档）、`activeContext.md`；文档分类/索引/归档见 `规则/文档治理.md`。占位符未换=未接入。
口令「接入开发规范/重新接入/生成项目档案/文档树」→ `workflows/onboard.yaml` + `agents/onboard-agent.yaml`。接入必须建 `{文档事实源目录}/文档索引.md` + 标准树 + `资料/`（扁平）+ `资料/资料索引.md` + 根 `CHANGELOG.md`；L2+ 另建开发计划/变更记录/待决项/决策记录/需求台账。

## 2. 收尾

触发：工作流末步、计划全部阶段结束、点名「收尾/总结」。输出按 `规则/模板/收尾骨架.md`；专规只填第 1 点。提交/部署/回写门按 YAML `hitl` 独立确认；`wrap` 只写「有 N 个文件待提交」，完整【拟提交】在 commit 步只展示一次。

| 14 | 维护/查询 | 本文 + `规则/维护.md` + 点名 | — |

**入口直达**：单步口令（代码评审/提测/下一步/回滚/澄清）只执行该 step 到产出完成即停；`change`/`iterate`/`release` 按各自链路继续到下一个门或收尾；「只出任务清单」到 wrap 即止。单步入口仍按 `规则/模板/收尾骨架.md` 输出六段。
互斥：「落地…#编号…优化方案」=缺陷；「落地迭代方案」=迭代；无 `#` 又无「迭代」→ 一问。未命中 1～5 的改代码/改配置实施类 → `change`；发布/回滚/复盘各自独立。
首条：`route=workflow:<id> | step=<id> | level=<L0-L3> | reads=<读取索引行> | next_action=…`；有输入加 `input=<diff/路径>`。

## 4. 维护

改不变量/路由/读取协议 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/门 → `规则/`；改澄清 → `规则/澄清.md`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`；改文档树/归档 → `规则/文档治理.md`；改子代理 → `规则/子代理编排.md`；改读取索引 → `规则/读取索引.md`。自检见 `规则/维护.md` §2。

## 5. 文档治理（摘要）

- 根目录白名单：代码/构建文件、README、`CHANGELOG.md`、`项目档案.md`、`activeContext.md`、`开发规范/`、`{文档事实源目录}/`、`产品/`（如启用）、`测试/`（如启用）、`项目资料/`（多包）、`.gitignore`。
- 标准树：开发计划/文档索引/资料（扁平）/00-项目治理/01-需求基线/02-设计基线/03-计划与状态/04-测试与验收/05-发布与交付/06-复盘与改进/_归档；无内容不建空目录。
- 资料 vs 工作文档：`资料/` 只放外部输入；工作文档在 00～06 与根；分类/对照/归档见 `规则/文档治理.md`。
- 命名：`{类别}-{主题}-{版本或yyyyMMdd}.md`；发布说明一版一档；任务清单确认后冻结；旧版移 `_归档/{yyyyMMdd}-{版本}/`。
- 长期记录：根 `CHANGELOG.md` 记录版本/迭代/迁移；版本关闭/发布更新（`规则/文档治理.md` §6）。
- 归档正确：归档后现行文档保持现行正确，不把历史说明回流正式产物；旧版/迭代快照按 §6 归档，不堆「最终版」。

## 6. 技能与能力（按步加载）

- **技能层（必用）**：`技能/<name>/SKILL.md`，随包复制、无需安装；step notes 直接按路径读；每份含 `name/description`。含 `development-plan`、`change-intake`、`product-doc-analysis`、`requirements-and-spec`、`solution-design`（+ 子技能）、`engineering-quality`、`implementation-and-selftest`（+ 前后端）、`code-review`、`qa-handoff-and-release`、`task-breakdown`、`acceptance-and-launch`、`retrospective-and-improvement`。
- **阶段 → 技能**：见 `技能/README.md`「开发计划阶段 → 技能」；每阶段至少一个；S2 按变更面加载子技能，不全读。
- **能力层（可选）**：`能力/00-能力注册表.md`；已安装即用，未安装降级，首次缺失提示一次。
- **能力不替代技能**：没有工具也要按技能/清单完成并留证据。

## 7. 多包（自动探测）

项目根同时存在两个及以上包目录（`产品规范/`、`开发规范/`、`测试规范/`，以各自 `AGENTS.md` 为标志）= 多包模式；只有一个包 = 单包模式。自动生效，无需额外目录或合同文件。

- 共享外部资料根：`项目资料/`（首次需要共享资料时创建；不预建、不强制）。共享索引 `项目资料/资料索引.md`；本包 `资料/` 只放本包专属/历史资料。一份资料一个主副本，跨包只写引用。
- 根 `activeContext.md` 共用：按 `产品 / 开发 / 测试` 分节，各包只更新本节与 `跨包同步`，不覆盖其他节。
- 一次会话只执行一个包的 workflow；跨包交接只写“路径 + 状态”，不复制正文、不自动执行对方 workflow。
- 单包模式以上全部不启用，按本文默认执行。
