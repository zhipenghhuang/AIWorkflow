# AGENTS.md

> **用途**：开发协作 AI 入口。常驻最小集；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。
> **位置**：`开发规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；红线不被覆盖。
> **template_version**：`2026.10.27.5`（单点：包内版本以本文为准）。
> **架构**：Workflow + Agent + 规则/门/读取索引 + 技能/能力 + 验证层 + 开发计划控制面；落地文档 `review-docs` + `select_review_mode`（自行｜AI），代码审仍走 `review`。

## 0. 开工（每任务）

1. **中文**：对话与结论用中文；写现行结论。
2. **activeContext + 开发计划**：任务前读 `activeContext.md` 总览 + `## 开发` + 跨包同步，2～3 句报备焦点/下一步；无则按模板创建（只建本包节）。有实质进展收尾只更新本包分节。多包时禁止改他包分节/他包接入行。L2+ 同时读 `开发/开发计划.md`，报备阶段/门/下一步。
3. **接入状态（一次判定）**：`activeContext.md` 运行时有 `开发规范接入：已完成` → 跳过落地检查；无标记 → 按 `agents/onboard-agent.yaml` 判定一次，具备则静默打标，不具备则走 `workflows/onboard.yaml`。`Test-Template.ps1` 只在改包/点名时跑。
4. **独立判断**：不迎合；先查错误前提/逻辑跳跃/信息缺失；数字/结论尽量核实来源；用户有误直接指出依据与风险。
5. **冲突优先级**：用户明确指令 > 安全/合规/硬红线（§0.3） > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约 > 项目规范要点。红线不被覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 任意已路由 | 本文 §0～§2 → workflow 当前 step → 读取索引当前行 → 当前 agent/产物 |
| 有门/写 YAML | `规则/门.md` 当前行；不通读全表 |
| 验证/收尾 | `验证/README.md` + `规则/核心/验证规则.md` + 检查矩阵 + 验收清单/证据；报告 `验证/Test-Report.ps1` |
| 交接/变更 | `规则/协作/协作与交接.md` 当前节 + `规则/模板/90-交接与收尾/交接包说明模板.md` + `交接台账.md`；变更按 C0～C3 |
| 前后端/交付 | `项目档案.md` §7/§8/§9；技能按步读 |
| 维护/查询 | 本文 + `规则/核心/维护.md` + 点名 |

同一会话文件未变不重读；后续 delta-only；探查限定目录/关键词。**规则阅读不是越多越稳**：读全本会稀释当前步约束。**单步读取 ≤5 个来源/≤8k tokens；标 `读取级别：参考` 的大文件只读当前节；不为预防而读。**

### 0.1 任务分级（防过度/不足）

| 级别 | 典型 | 必走 | 可跳过 |
| --- | --- | --- | --- |
| L0 微改 | 单文件/文案/配置；无行为/契约/权限/数据变化 | clarify → implement → verify → commit | requirements/design/review-docs/plan/review/deliver/release |
| L1 常规 | 多文件、范围收敛、无跨系统契约 | clarify →（轻量卡）→ implement →（代码 review 按风险）→ verify →（有 QA）deliver → commit | 全量 PRD/ADR；有新方案则问 A/B |
| L2 功能/迭代 | 新功能、跨模块、接口/数据变更、多任务 | requirements → design（条件）→ **review-docs（A/B）** → plan → implement → review → verify → deliver → commit → release_handoff | 无 |
| L3 高风险 | 权限/资金/迁移/公共 API/安全/破坏性 | L2 + 文档/代码独立审 + 安全/隐私 + 回滚演练 + 发布审批 + 观察 + 复盘 | 无 |
| 缺陷 | 平台缺陷/指派/修复#/产品评估/产品回复 | defect-fix：preflight → pull → triage →（fix/assess→handoff→await→decision→align/clarify）→ gates → menu → close → postrelease | 无平台→change |

分级在 clarify 判断并写入首条路由；不确定按高一档。L0 不强制文档，但证据/提交确认/密钥红线不可省；L0 也不得跳过理解回执（纯机械操作除外）。L2+ 默认启用《开发计划》；路径 `开发/开发计划.md`。

### 0.2 确认门 · 澄清 · 直跑

- **只认 YAML 步上 `hitl`/`hitl_when`/`gate_when`**；语义见 `规则/门.md`。条件不满足则跳过；专规不另造门。
- **门档位**：autonomous（L0/只读/可逆，直接做）｜notify（L1、清单/节奏未实质变化，展示后继续）｜approve（L2+ 范围/方案/清单实质变化、L3、部署/回滚/回写/提交）。
- **澄清**：按 `规则/核心/澄清.md`；先读规则/技能/代码/文档做分析，再给「我的理解 + 已分析建议 + 需要你拍板（0～1 个）」；只问影响意图/范围/验收/风险的问题；不确定项按澄清§2.1分流。
- **产品资料先解析**：输入含 PRD/迭代方案/需求文档/页面原型/截图/接口或技术文档 → 先按 `技能/product-doc-analysis/SKILL.md` 产出带引用的理解包；原型只作 UI/交互依据，冲突列出来问，不反推后端规则。
- **直跑/预授权**：口令命中 → 首条 `route=...`；「一次性/直接跑完」默认只到任务完成，不含提交/推送/部署/回写。只免等待，不免输出。
- **可选输入不阻塞**：缺 PRD/方案/提测单/测试报告/UAT/缺陷单 → 一句话说明缺口，由用户提供/选择已有资料/本包模板补；禁因缺其它包阻塞。

**澄清停止条件**：理解已复述、关键高影响问题已确认、技术细节已有建议/方案；剩余只是低影响假设或待用户确认的建议。95% 仅参考；连续 3 轮无新信息 → 收敛范围或给推荐方案，不继续盘问。澄清记录按 `规则/核心/澄清.md` §7 落盘。

### 0.3 硬红线（易疏忽）

1. 证据先于结论；未验证不声称完成。
2. 缺陷：修前红证；禁修复后回退补红证；无根因不修；未验证不回写；产品缺陷先评估单、产品确认后才实施。
3. 最小改动；密钥零入库；正式文档只写现行有效；旧版确认后同批归档（`资料/_归档/` 或实施入口归档），不堆“最终版”；新输入先按 `规则/文档治理.md` §3 意图分析再分流。
4. 禁刷绿：禁改断言/跳测试/禁用告警凑绿（豁免须用户批准）；git 前拟提交确认；分支/推送/PR/合并按 `规则/工作流.md` §2 与档案 §1。
5. 子代理禁 commit/push/开 PR/合并/改平台/改确认门；核验后再结论；高风险/大改/破坏性变更核验者≠实施者。
6. 平台备注按专规写全（行间 `<br>`；禁每行 `<p>`/行间空行）；备注与状态同轮；面向测试/产品只写中文结论与业务事实。
7. 遇错先析因；同方案无效 2 次换路径；缺陷闭环 3 次回根因。
8. 文档不落根；方案/清单/报告/截图/临时文件进标准目录；发布不跳门：未过上线检查单/审批不得部署；失败按回滚预案。
9. 需求理解先于方案：未完成理解包/确认，不得凭 PRD 标题、聊天记忆或截图写基线/方案/清单/代码；冲突/缺口显式列出。
10. **全局体验**：界面减法（删冗余文案/标签，不清楚改布局）；UX/DX/AX 不净退化；开发阶段不背旧数据。见 `engineering-quality` §1.1～1.2、`frontend-design` §5。

### 0.4 验证与汇报（硬约束）

1. **落地文档先选评审方式**：需求基线/方案/ADR/前端设计说明等实施前 STOP `select_review_mode`——A 自行通过｜B AI（`doc-reviewer`）；未选不得实施。方法：`技能/design-doc-review`。与代码 `review` 分轨。
2. **完成只认门**：任务开始 `Invoke-Gate.ps1 -StartTask -TaskId ...`；代码/配置改动运行 `验证/Invoke-Gate.ps1`，读 `.gate/开发规范/completion.json`。没有本轮 `COMPLETE`（task_id/diff_hash 匹配），只能报“未验证/部分完成/阻塞”；空 diff = `NOT_VERIFIED`，dry-run = `DRY_RUN`，都不是完成。
3. **证据先于结论**：结论引用本轮检查、退出码、证据路径；路径必须存在；聊天文本/子代理自述不算证据；失败/环境缺失 → `BLOCKED`。
4. **前端必须浏览器验证**：状态/视口/console/network/截图/设计 QA；L1 至少七项+桌面/移动截图，L2+ 十五项；纯文案可 L0-light，但仍要受影响页面截图 + console 无 error。
5. **报告先写回执**：`【验证回执】verdict=...` 在完成内容之前；非 `COMPLETE` 禁用“完成/通过/已修复/正常”（“未完成/未通过/未修复”允许）；`验证/Test-Report.ps1` 对账。
6. **门不替代授权**：提交/部署/回写仍按 YAML `hitl` 单独确认；门只证明“做到没有”，不证明“可以发”。
7. **成本纪律**：只跑受影响范围；全量回归只留给发布/L3；L0/L1 不新增文档；截图桌面+移动各 1 张/页，JPEG/WebP 优先；不默认 HTML report/trace/video；不每个任务通读规则/技能。详细规则：`验证/README.md`、`规则/核心/验证规则.md`、`验证/检查矩阵.yaml`；维护读 `规则/核心/规则治理.md`。

### 0.5 工程与执行（摘要）

- **质量条**：`技能/engineering-quality/SKILL.md` + `规则/工作流.md` §3.4；不可省：可测逻辑补测、密钥零入库、外部输入校验、破坏性变更先确认、回滚/降级路径。
- **执行**：多解拍板先给权衡；先工具后子代理；不预防性通读；改动面超出预期先停下说明。
- **框架固定/局部自主**：不可让——口令→workflow、步上 hitl、输出骨架、预授权界、证据/红绿、密钥、子代理边界、git 纪律、文档落位；应交 AI——步内实现路径、探查顺序、是否派子代理、验证命令、措辞、拆分粒度。规则未覆盖/冲突时以用户目标、代码事实与既有门禁为先，收尾记录取舍。

### 0.6 协作与交接（硬约束）

1. **交接包是跨角色唯一载体**：需求/设计/提测/缺陷/修复/变更/发布按 `规则/协作/协作与交接.md` 生成完整包 `开发/交接/{HO-ID}/`（00～04）。**多包同仓**对方直读，禁止转到对方 `资料/交接/`；**仓外/单包**发文件夹或可选 ZIP。包内保留 `04-回执/` 模板；回执默认可选。**未收回执不得称「已接收」**；日常以 `已发送` 继续本侧，仅正式签收或发布/C2/C3 才要求回执后标已接收。
2. **合同三件套**：`00-交接说明.md` + `01-交接清单.md` + 必带文档快照；缺一不发。提测包必须过完成门 `COMPLETE`，发布包必须过 `confirm_deploy`。
3. **接收三选一**：接受/有条件接受/退回；阻断缺口退回，非阻断写条件/责任人/截止；接收后同轮更新开发计划/任务清单/索引/台账。正式签收时才填回执。
4. **变更分级**：C0 澄清/纠错 → C1 同范围增量 → C2 范围/里程碑/资源 → C3 战略/架构/合规/破坏性；C2/C3 必须重基线并过门，禁止拆成 C0/C1 绕过。变更通知发 `CHG` 包；正式签收时接收方回执并更新计划。
5. **计划同轮回写**：发送/接收/回执/变更后更新 `交接台账.md` → 开发计划 §0/§1/§12 → 文档索引 → `activeContext.md`；计划只写摘要，台账是交接真值。`已发送 ≠ 已接收`。

## 1. 接入

实例在项目根：`项目档案.md`（§1 项目阶段、§7/§8/§9）、`activeContext.md`；文档分类/索引/归档见 `规则/文档治理.md`。占位符未换=未接入。交接：`开发/交接/{HO-ID}/`（发出包）+ `开发/交接/交接台账.md`（唯一登记）；多包同仓直读对方发送路径，仓外包在用户放置处读，归档有用时可选落 `开发/资料/交接/{HO-ID}/`。
口令「接入开发规范/重新接入/生成项目档案/文档树」→ `workflows/onboard.yaml` + `agents/onboard-agent.yaml`；接入必须建文档索引 + 标准树 + `资料/` + 根 `CHANGELOG.md` + `开发/工作日志.md`；L2+ 另建开发计划/变更记录/待决项/决策记录/需求台账。

## 2. 收尾

触发：工作流末步、计划全部阶段结束、点名「收尾/总结」。按 `规则/模板/90-交接与收尾/收尾骨架.md`；按收尾骨架：中文回执 → 第1点纯汇报 → 第4点待确认表（无则「待你确认：无」）→ 第6点进度与下一步。提交/部署/回写门按 YAML `hitl` 独立确认；`wrap` 只写「有 N 个文件待提交」，完整【拟提交】在 commit 步只展示一次。交接回执按协作规则；未回执不得称已接收。

**入口直达**：单步口令（代码评审/提测/下一步/回滚/澄清）只执行该 step 到产出完成即停；`change`/`iterate`/`release` 按各自链路继续到下一个门或收尾；「只出任务清单」到 wrap 即止。`workflow.chain: full`（如 onboard）例外，必须走到 verify/打标。单步入口仍按 `规则/模板/90-交接与收尾/收尾骨架.md` 输出。
**互斥**：「落地…#编号…优化方案」=缺陷；「落地迭代方案」=迭代；无 `#` 又无「迭代」→ 一问。未命中 1～5 的改代码/改配置实施类 → `change`；发布/回滚/复盘各自独立。
**首条**：`route=workflow:<id> | step=<id> | level=<L0-L3> | reads=<读取索引行> | next_action=…`；有输入加 `input=<diff/路径>`。

## 4. 维护

改不变量/路由/读取协议 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/门 → `规则/`；改澄清 → `规则/核心/澄清.md`；改协作/交接/变更分级 → `规则/协作/协作与交接.md` + `workflows/handoff.yaml`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`；改文档树/归档 → `规则/文档治理.md`；改子代理 → `规则/协作/子代理编排.md`；改读取索引 → `规则/读取索引.md`。自检见 `规则/核心/维护.md` §2。

## 5. 文档治理（摘要）

- 工作文档根默认 `产品/` · `开发/` · `测试/`；已有 docs/ 等用 keep/mix/replace 兼容，映射记档案。
- 根目录白名单：代码/构建文件、README、根 `CHANGELOG.md`、`项目档案.md`、`activeContext.md`、`开发规范/`、`开发/`、`产品/`（如启用）、`测试/`（如启用）、`项目资料/`（多包）、`.gitignore`。
- 资料区：`开发/资料/{版本或主题}/` + `_通用/` + `资料/_归档/`（禁 `项目文档/`、禁强制类型前缀）；入站 T1～T9；确认采纳且 S1/S2/S3 → 同批进 `资料/_归档/`；工作产物不回写资料；单包优先不自动跑他包。
- 版本记录：根 `CHANGELOG.md`＝发版史；`开发/工作日志.md`＝岗位里程碑（产品/测试同理各维护本包工作日志，不写根）；发布说明按版本。细则：`规则/文档治理.md` + `规则/工作流.md` §5；无内容不建空目录；版本关闭归档见文档治理 §7；不堆“最终版”。

## 6. 技能与能力（按步加载）

- **技能（必用）**：`技能/<name>/SKILL.md`，随包复制、命中步必用；阶段→技能见 `技能/README.md`；每阶段至少一个；S2 按变更面加载子技能，不全读。
- **能力（可选）**：`能力/00-能力注册表.md`；已安装即用，未安装降级，首次缺失提示一次；能力不替代技能。

## 7. 多包（自动探测）

项目根同时存在两个及以上包目录（`产品规范/`、`开发规范/`、`测试规范/`，以各自 `AGENTS.md` 为标志）= 多包模式；否则单包。
- 共享 `项目资料/`（首次需要时创建）、根 `activeContext.md`（固定骨架：总览 → 已启用包分节 → 跨包同步 → 运行时；单包只建本包节）。
- 各包只更新本分节、跨包同步中与本包相关的一行、运行时本包接入行（本包为 `开发规范接入：已完成`）；禁止整文件套模板覆盖、禁止改他包分节/他包接入行。
- 一次会话只执行一个包 workflow；跨包交接优先用 `开发/交接/{HO-ID}/` 整包（路径+状态+回执），对方未装包时按普通文档/回执处理；不复制正文、不自动执行对方 workflow。
- 单包模式以上不启用，按本文默认执行（仍用同分节骨架，仅含本包节）。
