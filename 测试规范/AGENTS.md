# AGENTS.md

> **用途**：测试规范 AI 入口。先读本文 → 命中口令打开对应 `workflows/*.yaml` → 当前步只加载 `agents/*.yaml`。  
> **位置**：`测试规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准。  
> **template_version**：`2026.10.21.4`（单点：包内版本以本文为准）。  
> **架构**：Workflow 定义（YAML）+ Agent 契约 + 规则红线 + 内置专业技能（`技能/`：随包生效、命中步必用）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级；外部工具安装见 README「宿主适配」节）；执行宿主（任意支持 AGENTS 入口与所需能力的 AI 编码工具；要求见 README「宿主适配」节）为执行器。主链见 `workflows/testing.yaml`（分析→计划→用例→执行→报告）。正式轨：功能全量/专项、探索式、接口、发布前、缺陷——并列；计划驱动模式按测试计划编排多轨。  
> **执行通道**：AI-MCP 通道（默认）+ **脚本档**（可脚本化用例确定性回归，0 token；见 `规则/脚本执行.md`）。

## 0. 开工（每任务）

1. **中文**：对话与结论使用中文；输出写现行结论。  
2. **activeContext**（跨会话工作记忆）：任务前读项目根 `activeContext.md`，**2～3 句**报备当前焦点与下一步；无则按模板初始化。用以理解项目当下与用户需求，不凭聊天记忆。有实质进展则收尾更新（焦点/最近变化/下一步/仍生效决策与洞见；过期删除）。稳定真值仍在 `环境基线.md` 与 `测试/资料/项目文档/`。  
3. **落地 / 自动接入**（一次判定 · 打标后免检）：  
   - 读 `activeContext.md`：已有 `landing=ok` → **禁止**再做接入预检，直跑命中 workflow。  
   - **无标记**且命中生成/执行/缺陷类口令（§2）→ **仅此一次**按 `agents/onboard-agent.yaml` 接入清单核验：  
     - 通过 → 写入 `landing=ok`，静默直跑原任务；  
     - 未接入或缺关键节 → `workflows/onboard.yaml` 补齐后写 `landing=ok`，**resume 原口令**（不要求用户重述）。  
   - 清标记仅当：用户点名「接入 / 重新接入」或明确要求重检；其余任务见标记直跑；维护/查询不强制。  
4. **独立判断**：不迎合；先查错误前提、逻辑跳跃与信息缺失；数字/结论与台账/报告同口径并尽量核实来源；用户有误直接指出依据与风险；主动提示被忽略的变量、成本、偏差与依赖。  
5. **冲突优先级**：用户明确指令 > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约 > 命中专规红线。  
6. **精读预算**：

| 口令类 | 默读 |
| --- | --- |
| 任意已路由 | 本文 → 命中 `workflows/*.yaml` → **当前步** `agents/*.yaml` → 按该 agent `reads` **读对、读够**（宁可读全本轨专规，勿漏关键节）；按步注加载 `技能/` 对应专业技能（随包生效、必用） |
| 生成细节 | 需要时 `规则/工作流.md` §2.1.0（三闸·缺口三分类·分析短表）、§2.5（用例评审口令）、§2.6（期中变更）/ `规则/模板/`；探索式/接口/发布前加读对应 `规则/轨契约/*.md`；**不跨轨通读**缺陷协作/多Agent（指针明确的单节点读除外） |
| 执行细节 | 需要时 `规则/工作流.md` §3.0/§3.6/§5 + `规则/多Agent与输出.md`（§1～§2.1、§3、**计划驱动 §4**；§2.2 **稳态**含全链终局退程；**异常点读**仅红点/无工具/端口/并行冲突时）；失败分类 `规则/缺陷分类.md`；派子代理时带 worker/reviewer 契约；分轨加读轨契约 |
| 脚本执行 | 纯脚本档执行（**仅限一切顺利的纯回归**）：`规则/脚本执行.md` + `多Agent与输出.md` §3（合并六态）+ 基线脚本执行节即可，执行专规其余节免读；出现失败/阻塞/STALE/任何不确定 → **立即**按「执行细节」行读够再处理，**禁**以已省读为由跳纪律（读成本 ≪ 误判返工成本）；执行器字段见 `规则/tools/playwright/README.md` |
| 缺陷协作 | `workflows/defect.yaml` → bug-agent → `规则/缺陷协作.md`（本轨读够；**不跨轨通读**多Agent——指针明确的单节点读除外，如 §2.2 浏览器纪律/退程） |
| 维护 / 查询 | 本文 + 点名 |

同一会话内文件未变不重读；后续步骤 **delta-only**（禁重贴已读稳定规则全文）；同方案无效 **2** 次换手段（**禁同命令空重跑**）；探查限定目录/关键词，大范围调查派子代理。  
**读纪律**：优先保证不读错轨、不漏本轨关键节；规则默读相对整轮执行成本很小——**禁止**为省读而砍专规导致漏约束。

### 0.1 计划门与三门 · 澄清（与 workflow `hitl` / `hitl_when` 对齐）

| 门 | 步上声明（条件见 YAML） | 动作 |
| --- | --- | --- |
| 门1 | `select_mainread`（when: mainread_unspecified） | 主读未点名 → STOP 一问；已选定 → **跳过**（不得重问） |
| 计划门 | `confirm_plan`（when: `plan_needs_confirm`） | 版本级首版/换代或范围·准出·缺陷提交策略实质变更 → STOP 一行摘要（范围/测试类型/轨道顺序/缺陷提交策略/探索章程数/准出）确认；同会话同载体只一次；专项轻量不设门 |
| 门2 | `confirm_scope`（when: `scope_needs_confirm`） | 开跑前一行：主读/计划范围/环境 → 确认；同会话同载体只一次（「继续」沿用）；**计划驱动已确认 → 跳过并附【已预授权执行：按计划】** |
| 门3 | `confirm_commit`（generate / handoff 条件） | 有拟入库或须问交平台 → STOP；否则跳过 |
| 迁移门 | `confirm_docs_migration`（when: `docs_migration_needed`） | 旧结构迁移前列清单/目标，确认后执行；不擅自删 |

**期中变更（不新开计划）**：用户给变化/新文档 → 建 `测试/变更/CR-*.md` + 影响分析；A 澄清/B 同范围增量 → 就地更新计划 + 用例/脚本，不重开计划门；C 实质变更（范围/准出/排期/缺陷策略）→ 计划状态=变更中 + 计划门；D 缺陷驱动 → 缺陷轨。**执行时机默认等计划模块/阶段位；提前仅限 P0/高风险、阻塞后续、独立且数据/入口就绪、有专门含变更构建；P0 冒烟可在构建/阶段边界先跑；执行前核构建含变更**；执行 P0 冒烟 + 变更用例 + 影响面，不默认全量。  

1. **澄清追问**：目标/范围/验收不明或多解 → **一次只问一个问题**，按回答继续追问至 **≥95%** 再给方案；判据＝能复述「谁 / 什么场景 / 做什么 / 系统怎么响应 / 怎么算对」。三要素已唯一 → 1～2 句复述即可；确认门是执行授权，不是澄清，不重复问。  
2. 口令命中且范围唯一 → 直跑；**仅当步上 hitl 条件满足（未写 when 视为满足）时不可跳过**。确认门只认步上 `hitl`，专规不另造门。  
3. 分轨关键字须与动作共现（如「执行」+「探索式/探索测试」）；歧义一问。  
4. **防重复**：同一确认点只问一次；同批信息只展示一次；固定骨架/菜单/拟提交清单不得以「简洁/直跑」省略或改字段；禁长文复述规则代替开跑或确认提问。
5. **预授权界**：「一次性 / 直接跑完 / 中途不停」＝预授权，默认**只到任务本身完成**（执行＋核验＋固定输出骨架）；**不含**提交/推送/部署/回交平台等后续流程。收到后**声明默认界并直接执行**；**仅当口令同时提到后续动作且范围不明**时一问；只免**等待**、不免**输出**——已覆盖的确认门附【已预授权执行：<组合>】，未覆盖的门仍按步上 `hitl` 执行。**计划 §0 状态=已确认/执行中/待关闭的计划内缺陷提交**（计划 §11「发现即提交」）视为预授权；**口令「按计划执行 / 按测试计划执行 / 执行测试计划」**＝计划状态=已确认/执行中/待关闭的计划内执行预授权（`confirm_scope` 条件不满足 → 跳过并附【已预授权执行：按计划】直接开跑）；均不含 git/部署/计划外提交。**少问**：只问会改变范围/验收/风险的问题；可由计划/基线/主读推断的先按现行值推进并记「假设」，不把确认门当澄清。

> hitl 形态与 `gate: coverage-map` / `confirm_plan` / `confirm_remark` / `confirm_gitignore` 以 `workflows/*.yaml` 为准（条件不满足则跳过该门）。`when` 词表：`mainread_unspecified`｜`mainread_unspecified_for_generate`｜`exploratory_mainread_missing`｜`plan_needs_confirm`｜`scope_needs_confirm`｜`standalone_generate_with_pending`｜`has_pending_commit_or_platform_ask`｜`has_pending_commit`｜`remark_writeback`｜`docs_migration_needed`；`gate_when` 词表：`functional_coverage_required`。**`gate_when` 不满足 → 跳过该 gate（步骤不跳过）**。`scope_needs_confirm`：非计划驱动、计划状态非「已确认/执行中/待关闭」或范围/环境实质变化时为真；计划驱动且 §0 为已确认/执行中/待关闭时为假（跳过门2，附预授权）；**期中变更 A/B 并入后保持已确认→假；C 变更中→真（计划门）**。门1 形式挂 `generate` 步，仅**新生成**且主读未点名时触发（用例评审不触发）；analyze 先跑时代行提问（同一确认点，只问一次）。计划门挂 `plan` 步；无计划直执行不另设门（随门2 并列确认）。

**缺陷分流（本包）**：提交/查重/「指派给我」+回归·验证·复测 → `workflows/defect.yaml`（拉单以指派为准，**不**要求已解决；分拣见 `规则/缺陷协作.md` §7）；只描述现象、无平台编号 → 本包执行失败/change。  
**与开发流程分工（可选联动 · 不强制）**：修 Bug 代码 / 修复# / 仅 `#数字` 不在本包执行；如项目已启用开发工作流，可提示用户到该流程处理；未启用则本会话不执行，也不要求安装/引用开发包。

### 0.2 硬红线（易疏忽 · 准确度）

1. 禁臆造路由/接口/按钮；正式资产只写现行有效状态（§0.6）。  
2. 密钥与凭据不入库、不进提交摘要；基线密码明文仅限测试环境且经用户授权（见基线 §1/§2.2）。  
3. 子代理边界（`多Agent与输出.md` §1.4）：不 git/不交平台/**不改他模块文件**；模块档只写本模块台账与证据；拆分档 Worker 仅写 DraftPath；编排核验后再结论。  
4. **先 UI 再 Network**（功能/探索式轨）；禁猜未见 API 判失败。  
5. **阻塞从严**：缺数据/缺样本须先造数或换样（≠阻塞）；可打通不写阻塞；产品问题记失败；单案互异手段≥2 且总尝试≤3，仍不可用才 blocked 并写已尝试（细则 `多Agent与输出.md` §1.3-4）。**blocked 四问**（任一未过不写 blocked）：① 能否造数/换样？② 能否换入口/角色/账号？③ 是否被测对象自身缺陷（→fail）？④ 互异手段≥2 且总尝试≤3 了吗？  
6. 过程文件只落工作流 §1.2 各通道 `.draft/`。  
7. 对话收尾用总结骨架；平台备注写全（与状态同轮；版式：行间 `<br>`、禁每行 `<p>`，见 `规则/缺陷协作.md` §4）。  
8. **禁抬高通过率**：不手改结果表刷绿；失败须实拍进 `测试/功能测试/证据/{模块}/`。  
9. 遇错先析因；同方案无效 **2** 次换路径（换假设或手段，**禁同命令空重跑**）。  
10. 发布前/探索式轨：母版只定目录与边界，**方法与场景库项目自备**；工具选装见 `能力/00-能力注册表.md`（装配≠菜谱），禁假装母版有完整菜谱。  
11. **能脚本不 AI**：清单=已脚本化的用例回归/重跑必须走脚本档（`规则/脚本执行.md` §3），禁用 MCP 逐条重跑；脚本判失败按**有界复核**（同节：一次为限、同批同因合并、可定性即停）后方可定性，**禁**脚本失败直接交平台。  
12. **计划驱动不跳轨**：按计划 §9.2 阶段执行，每阶段仍按对应轨契约；不跨轨通读、不静默降范围；计划实质变更回计划门。  
13. **缺陷提交按计划授权**：计划 §11 已授权「发现即提交」→ 查重后直接提交；未授权仍门3；禁计划外提交。  
14. **额外发现不静默**：执行中用例之外的 UI/布局/显示/文案/console/network/UX 异常 → 记录位置/现象/证据/影响；能复现进缺陷/观察项，不能复现记频率；不替代用例结果。  

### 0.3 执行中（效率）

1. 多解需拍板 → 先说权衡再给建议；路径唯一则直接做。  
2. 跑命令前确认环境与依赖；系统操作优先简单稳定方案；失败先析因（§0.2-9）。  
3. 动手前说明拟改文件；文件修改优先直接编辑，仅批量/重复性操作才生成脚本；**最小改动**。  
4. **工具点名优先**：本包点名的脚本（`规则/tools/`）与浏览器 MCP（基线 §8 绑定）必须按点名调用；不受宿主「少用 Shell / 换工具」类全局偏好覆盖。  
5. **成本分配**：token/时间大头在**执行循环与返工**（快照/工具往返/重跑，且上下文随用例数累积）——省它优先「能脚本不 AI、同页少重复全量快照（DOM 变更后再刷新）、批次结果一次汇总」；**规则阅读是低成本项**，禁为省读砍关键节（漏约束的返工成本远高于读规则）。  
6. **增强能力首缺提示（每能力一次）**：命中步骤/轨要用增强能力（清单见 `能力/00-能力注册表.md` §3）而本机缺失 → 附一句提示（例：未装 X，已按降级执行；启用说「装配能力」）并记入 `环境基线.md` §17（状态记「未安装（已提示）」）；已安装/已提示 → 静默。

### 0.4 工程红线

1. 不在生产/未授权环境执行；造数仅在授权测试环境。  
2. 真实 PII 不入证据/平台；需要时脱敏。  
3. 严重程度按业务影响（S1–S4）；拿不准一问。  
4. P0 未通过不得判整体通过（「有条件通过」仅限 P0 全通过、缺口非 P0 且用户接受）；准出评估对照计划准出标准（`测试/测试计划.md`；无计划按模板默认），未测项显式列缺口。

### 0.5 框架固定 · 局部自主

- **不可让**：口令→workflow、步上 hitl/`hitl_when`、专规输出骨架、预授权界（一次性仅到任务完成）、密钥、角色边界、`.draft/` 落点、覆盖三闸（功能全量/专项）、缺口三分类与能测尽测、主读已点名仍须轻量分析短表、执行口径探查与 pending 红线、失败分类与相符证明（`规则/缺陷分类.md`）、脚本档失败升级与脚本/用例同步（`规则/脚本执行.md`）、冒烟前置与阻断面分流（`规则/多Agent与输出.md` §1.1.1）、计划门与准出评估、**计划驱动阶段编排/回归闭环/缺陷提交授权**、`landing=ok` 免检纪律、能力注册表取用与降级（**已安装即启用**；未安装=降级路径，禁阻塞或硬编）、文档现行有效（§0.6）。  
- **应交 AI**：怎么拆用例/划批/取档/探查/是否派子代理——推理中择优；不另开长文规划（分析短表与测试计划除外）；不预防性通读。  
- **规则未覆盖或冲突**：以用户目标、台账事实与既有门禁为先，选最小成本可验证路径；在收尾「假设与未决项」记录取舍，不新增门、不跳红线。  
- **轨互斥与计划编排**：默认轨互斥——单轨口令命中即停，不跨轨默读；**计划驱动模式**按计划 §9.2 编排多轨（阶段内仍按对应轨契约），可并行但须账号/数据/环境隔离；不并行开跑未计划轨道。  
- **计划驱动独立实施**：本包可单独启用，不要求开发/产品包同时安装或默认联动；跨包输入（PRD/提测单/自测证据等）可选，缺失时按现有主读/基线执行并最多一句提示，不反复追问。  

### 0.6 文档现行有效（正式产物 · 不可让）

1. 只描述当前存在的功能、流程、规则与约束；以当前最终状态为唯一事实源，保持简洁准确。  
2. 删除内容后直接移除，不增加「禁止 / 不要 / 已废弃 / 旧方案」等说明。  
3. 不记录历史修改过程、变更原因、取消内容与废弃概念。  
4. 不引入不存在的概念；不确定的写「待确认」，不猜造。  
5. 结论性输出不复述用户原话、修改过程或方案草稿；不把修改方案写入正式产物，正式产物按各自模板写业务内容。

## 5. 收尾

**触发**：工作流末步、计划驱动全部阶段（P0～P9）结束、或用户点名「收尾 / 总结」时，必须输出本骨架。阶段中途只出 ≤3 行简报，不替代最终收尾；极短只读任务可压缩为 2～3 行，但 6 个字段标签保留。

**唯一骨架**：生成 / 执行 / 缺陷 / 报告等专规收尾只填第 1 点，不得另起编号或省略第 2～6 点。第 1 点的「可直接复制汇报」给业务 / 上级看：业务语言、量化、结论先行，禁过程词、工具名、轮次编号与内部路径；四要素参考执行台账「结论说明」——覆盖与总体、主链路点名、问题逐项影响、交付 / 数据风险判断。

```text
【任务收尾】
1. 完成了什么：{一句话结论}
   可直接复制汇报（整段复制）：
   {对象}已完成{交付内容}。覆盖{范围}共{N}项（完成/通过 {n} 项，{P%}）；{核心链路/关键能力}已{通过/达成}；{失败/阻塞/待实现 n 项及业务影响}；{对交付/数据/上线的影响判断}。结论：{通过/有条件通过/不通过/已交付/待确认}。
2. 改了哪些文件：{路径；无改动写「无」}；拟提交：{短列表或「无」}；.gitignore：{一句}
3. 如何验证：{命令+结果 / 台账计数与证据核对 / 报告准出对照；未验证须明示}
4. 假设与未决项：{列表或「无」}
5. 还存在什么问题或风险：{列表或「无」}
6. 下一步值得做什么：{建议或「无」}
```

- **第 1 点**：数字须与台账 / 结果表 / 报告一致；无问题写「未发现阻断问题」；不写「先…后…」、脚本名、轮次编号。按任务类型取数：执行=用例数/通过率；生成=映射点/用例数；评审=审阅用例数/缺口数；计划=范围项/轨道数；缺陷=提交/回归单数。  
- **第 2 点**：列实际新增 / 修改 / 删除的文件或产物；拟提交与 `.gitignore` 同点；未提交须说明。  
- **第 3 点**：验证＝可复跑的命令 / 检查＋结果，或「台账 N 条与结果表一致、证据 N 张可打开」；未验证不得写通过。  
- **第 4 / 5 点**：假设与风险分开；无则写「无」，不留空。  
- **第 6 点**：给可执行下一步（执行 / 回归 / 交平台 / 补资产），不写空泛建议。  
- 门3（提交 / 交平台）在骨架后单独一行只问一次，不并入 6 点。  
- **收尾自检（输出前逐项过）**：① 标题【任务收尾】（生成/执行可用【生成收尾】/【执行收尾】，但骨架相同）；② 1～6 字段标签齐；③ 第 1 点含可复制汇报且数字与台账/报告一致；④ 未验证/阻塞/待实现明示；⑤ 提交/交平台门在骨架后单独确认。

## 6. 维护本包

改不变量 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/输出 → `规则/`；改轨边界 → `规则/轨契约/`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`（注册表）；**改计划编排 → 测试计划模板 + `规则/工作流.md` §3.6 + `规则/多Agent与输出.md` §4（三处同步）**。  
改后跑 `规则/tools/Invoke-TestWorkflow.ps1 -Action ValidateTemplateRefs`（引用可解析 + 章节锚点 + workflows→agents + 步标记词表 + 能力名声明 + 版本单点；含 workflows/agents YAML）。  
**用例文档校验**：`python 规则/tools/validate_testcase.py <模块用例.md>`（模块总览/结构化详情/步骤定位/预期判定/追溯/评分卡）。  
**无障碍/UX**：`规则/模板/无障碍与UX检查清单.md`；结果并入测试报告 §11。
**重排维护**：改口令表/门表/清单编号后，检索全包「行 N」「优先 N」「§x.y」等编号引用并同步（自检不查编号引用）。  
宿主无关：本包文本与 YAML 只写能力名；宿主具体值与本地路径只写实例基线（§8/§13）；宿主要求与挂载见 README「宿主适配」节；能力名清单见 `能力/00-能力注册表.md`。  
规则撰写：新增或保留规则/步骤的标准＝**有用、不冗余（单一出处，其余指针）、不误导、高性价比**——满足即可加或留，不满足不加；默认可完成的动作不写；强调（加粗）集中在不可让项；凡**阻塞式确认门**处，YAML 步上必须有对应 `hitl`（确认门冷启对齐）；澄清类一问（§0.1-1）不入 hitl，不另立门。  
文档粒度（常驻最小 · 按需加载）：拆分与合并判据＝被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。
