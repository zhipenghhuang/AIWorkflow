# AGENTS.md

> **用途**：测试规范 AI 入口。本文只放常驻最小集；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。
> **位置**：`测试规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；红线不被覆盖。
> **template_version**：`2026.10.23.5`（单点：包内版本以本文为准）。
> **架构**：Workflow YAML + Agent 契约 + 规则/门/读取索引 + 内置技能 + 可选能力。主链：分析→计划→生成→执行→报告；正式轨：功能全量/专项、探索式、接口、发布前、缺陷。
> **执行通道**：AI-MCP（默认）+ 脚本档（可脚本化用例确定性回归，0 token）。

## 0. 开工（每任务）

1. **中文**：对话与结论使用中文；输出写现行结论。
2. **activeContext**：任务前读 `activeContext.md`，2～3 句报备焦点/下一步；无则按模板初始化。有实质进展收尾更新（焦点/最近变化/下一步/决策与洞见；过期删除）。稳定真值在 `环境基线.md` 与 `测试/资料/`。
3. **落地/自动接入（一次判定 · 打标后免检）**：读 `activeContext.md`；已有 `landing=ok` → 禁止再预检，直跑命中 workflow。无标记且命中生成/执行/缺陷类口令 → 仅此一次按 `agents/onboard-agent.yaml` 接入清单核验：通过→写 `landing=ok` 静默直跑；未接入→`onboard.yaml` 补齐后打标并 resume 原口令。清标记仅当点名「接入/重新接入」或明确要求重检。
4. **独立判断**：不迎合；先查错误前提、逻辑跳跃与信息缺失；数字/结论与台账/报告同口径并尽量核实来源；用户有误直接指出依据与风险。
5. **冲突优先级**：用户明确指令 > 安全/合规/硬红线（§0.2/§0.4） > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约。红线不被 agent 契约或输出偏好覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 任意已路由 | 本文 §0～§2 → `workflows/{workflow}.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 agent/产物 |
| 有门/要写 YAML | `规则/门.md` 当前行；不要通读全表 |
| 生成细节 | `规则/playbooks/generate.md` + `工作流.md` §2.1.0/§2.5 + 用例模板 + 当前轨契约 |
| 执行细节 | `规则/playbooks/execute.md` + `工作流.md` §3.0/§3.1 + 当前轨契约；**不跨轨通读** |
| 脚本档 | `脚本执行.md` §3/§4 + executor README；失败/阻塞再按 `playbooks/execute.md` 升级 |
| 缺陷协作 | `规则/playbooks/defect.md` + `缺陷协作.md` 当前节 + `缺陷分类.md`（判类型时） |
| 分片/长任务 | 达 `多Agent与输出.md` §1.5 阈值才拆；不预防性通读 |
| 维护/查询 | 本文 + `规则/维护.md` + 点名 |

同一会话文件未变不重读；后续步骤 delta-only；同方案无效 2 次换手段；探查限定目录/关键词。**规则阅读不是越多越稳**：读错轨/读全本会稀释当前 step 约束；只读当前 step 卡。
**资料收取（仅当有新文件/变化）**：按 `规则/文档治理.md` §3 输出【资料收取与归档候选】；确认前只读，不改名/不移动/不标记失效。无新文件不扫描。
**多包（自动）**：同项目根存在两个及以上包目录时自动启用，详见 §7；单包不启用。
**文档生命周期**：版本关闭/点名「文档整理/巡检/清理」时，按 `规则/文档治理.md` §4～§9 输出【文档治理检查】；确认后才执行。禁止中途顺手删除。

### 0.1 计划门与三门 · 澄清

- **只认 YAML 步上 `hitl`**；门/`when`/`gate_when` 语义见 `规则/门.md`。条件不满足则跳过；专规不另造门。
- **门档位**：autonomous（只读/列表/巡检/已脚本化回归，直接做）｜notify（同范围生成/执行、A/B 期中变更，展示后继续）｜approve（计划实质变更、首次执行未确认范围、平台建单/回写、提交、资料搬迁/清理）。
- **计划门**：版本级首版/换代或范围·准出·缺陷提交策略实质变更才停；同会话同载体只一次；专项轻量不设门。
- **门1/门2**：主读未点名一问；执行范围/环境未确认才停；计划驱动已确认→跳过并附【已预授权执行：按计划】。
- **门3**：有拟入库/须交平台/拟新建缺陷单→停；否则跳过。
- **澄清追问环（强制）**：按 `规则/澄清.md` 执行；任何任务先给「理解回执」（一句话目标 + 置信度 + 缺口），**一次只问一个问题**并附建议；按回答更新理解与置信度，直到 ≥95% 且能复述「谁/场景/做什么/系统怎么响应/怎么算对/明确不做什么」，用户明确确认后才写计划/用例/断言。非机械任务至少问 1 个高影响问题（复述确认也算）；低风险也先复述；仅纯信息查询/机械操作可免（免问也留一行回执）。禁一次多问、禁自问自答、禁把假设当结论、禁把确认门当澄清。
- **测试依据先建模**：PRD/迭代方案/原型/接口或技术文档 → 先按 `技能/test-basis-analysis/SKILL.md` 建需求模型、冲突/九类歧义清单与 oracle；预期无来源不写断言；不按现网实现反推需求。
- **澄清与门**：确认门是授权，不是澄清；澄清回答不自动授权执行。门可一次展示多个授权选项，但不得夹带澄清问题。
- **预授权**：「一次性/直接跑完」默认只到任务完成（执行+核验+固定骨架），不含提交/推送/部署/交平台。计划 §0=已确认/执行中/待关闭的计划内执行与「发现即提交」视为预授权；计划外提交仍门3。
- **防重复**：同一确认点只问一次；同批信息只展示一次；固定骨架/菜单/拟提交不得省略。

**澄清停止条件**：能预测用户对下 3 个问题的反应 + 能按 `规则/澄清.md` §4 复述（谁/场景/做什么/系统怎么响应/怎么算对/不做什么）+ 用户明确说「对/是/按这个来」；「随便/你决定/看着办/沉默」不算确认。连续 3 轮置信度不升 → 换问法或回退重问。澄清记录按 `规则/澄清.md` §7 落盘。

**期中变更（不新开计划）**：用户给变化/新文档，或产品在平台确认并给新说明/附件 → 建 `测试/变更/CR-*.md` + 影响分析；A 澄清/B 同范围增量 → 就地更新计划+用例/脚本，不重开计划门；C 实质变更 → 计划状态=变更中 + 计划门；D 缺陷驱动 → 缺陷轨；产品确认带新 AC → D+B/D+C。执行时机默认等计划模块/阶段位；提前仅限 P0/高风险/阻塞后续/独立且数据入口就绪/专门含变更构建；执行 P0 冒烟 + 变更用例 + 影响面，不默认全量。

**缺陷分流**：提交/查重/「指派给我」+回归·验证·复测/巡检/补充澄清 → `workflows/defect.yaml`；产品确认/新文档 → `testing.yaml` plan（`工作流.md` §2.6）；只描述现象、无平台编号 → 本包执行失败/change。
**产品缺陷直提**：分类=产品缺陷 → 提交后直接指派产品负责人，不经开发；产品判定回流见 `缺陷协作.md` §7.4/§8.8。
**与开发流程分工**：修 Bug 代码/修复#/仅 `#数字` 不在本包执行；可提示到开发流程；未启用则本会话不执行，不要求安装。

### 0.2 硬红线（易疏忽 · 准确度）

1. 禁臆造路由/接口/按钮；正式资产只写现行有效状态（§0.6）。
2. 密钥与凭据不入库、不进提交摘要；基线密码明文仅限测试环境且经用户授权。
3. 子代理边界：不 git/不交平台/不改他模块文件；模块档只写本模块台账与证据；拆分档 Worker 仅写 DraftPath；编排核验后再结论。
4. **先 UI 再 Network**（功能/探索式轨）；禁猜未见 API 判失败。
5. **阻塞从严**：缺数据/缺样本先造数或换样（≠阻塞）；可打通不写阻塞；产品问题记失败；单案互异手段≥2 且总尝试≤3，仍不可用才 blocked 并写已尝试。blocked 四问任一未过不写 blocked。
6. 过程文件只落各通道 `.draft/`。
7. 对话收尾用总结骨架；平台备注写全（与状态同轮；版式按 `缺陷协作.md` §4.0/基线 §13）；读者=开发/产品，不写测试内部资产/过程信息。
8. **禁抬高通过率**：不手改结果表刷绿；失败须实拍进 `测试/功能测试/证据/{模块}/`。
9. 遇错先析因；同方案无效 2 次换路径；禁同命令空重跑。
10. 发布前/探索式轨：母版只定目录与边界，方法与场景库项目自备；禁假装母版有完整菜谱。
11. **能脚本不 AI**：已脚本化用例回归/重跑必须走脚本档；脚本失败按有界复核（一次为限、同批同因合并、可定性即停）后方可定性；禁脚本失败直接交平台。
12. **计划驱动不跳轨**：按计划 §9.2 阶段执行，每阶段仍按对应轨契约；不跨轨通读、不静默降范围；实质变更回计划门。
13. **缺陷提交按计划授权**：计划 §11 已授权「发现即提交」→ 查重后直接提交；未授权仍门3；禁计划外提交。
14. **额外发现不静默**：用例之外的 UI/布局/显示/文案/console/network/UX 异常 → 记录位置/现象/证据/影响；能复现进缺陷/观察项，不能复现记频率；不替代用例结果。
15. **资料先确认**：新资料先分类 + 覆盖对照，输出候选；确认后才改名/登记/标记失效/归档。只有全量替代/全量覆盖/重复可归档；部分覆盖/增量保留；禁止删除、禁止按时间年龄归档。
16. **文档生命周期先确认**：工作文档按长期/版本绑定/失效/过程分类；版本关闭才归档版本绑定文档；临时/失败/重复文件列清理候选，确认后才删除或移 `_待清理/`；证据、当前计划/报告、源文件、用户文件永不自动删除。
17. **依据可追溯**：每个用例/断言必须能指到需求/AC/规则/原型/接口文档；无来源先问或标“文档未声明”，不得臆造；文档与实现冲突记失败/待确认，不按实现改预期。

### 0.3 执行中（效率）

1. 多解需拍板 → 先说权衡再给建议；路径唯一则直接做。
2. 跑命令前确认环境与依赖；失败先析因（§0.2-9）。
3. 动手前说明拟改文件；优先直接编辑；仅批量/重复性操作才生成脚本；最小改动。
4. **工具点名优先**：本包点名的脚本与浏览器 MCP 必须按点名调用；不受宿主「少用 Shell/换工具」类全局偏好覆盖。
5. **成本分配**：token/时间大头在执行循环与返工（快照/工具往返/重跑）——省它优先「能脚本不 AI、同页少重复全量快照（DOM 变更后再刷新）、批次结果一次汇总」。规则阅读按当前 step 卡，不读全本；**读错轨/读全本会稀释约束，不是省**。
6. **增强能力首缺提示（每能力一次）**：命中步骤/轨要用增强能力而本机缺失 → 附一句提示并记入基线 §17；已安装/已提示 → 静默。

### 0.4 工程红线

1. 不在生产/未授权环境执行；造数仅在授权测试环境。
2. 真实 PII 不入证据/平台；需要时脱敏。
3. 严重程度按业务影响（S1–S4）；拿不准一问。
4. P0 未通过不得判整体通过（「有条件通过」仅限 P0 全通过、缺口非 P0 且用户接受）；准出评估对照计划准出标准；未测项显式列缺口。

### 0.5 框架固定 · 局部自主

- **不可让**：口令→workflow、`hitl`/`hitl_when`、专规输出骨架、预授权界、密钥、角色边界、`.draft/` 落点、需求模型与 oracle 可追溯、覆盖三闸（功能全量/专项）、缺口三分类与能测尽测、主读已点名仍须轻量分析短表、执行口径探查与 pending 红线、失败分类与相符证明、脚本档失败升级与脚本/用例同步、冒烟前置与阻断面分流、计划门与准出评估、计划驱动阶段编排/回归闭环/缺陷提交授权、`landing=ok` 免检、能力取用与降级、文档现行有效。
- **应交 AI**：怎么拆用例/划批/取档/探查/是否派子代理——推理中择优；不另开长文规划（分析短表与测试计划除外）；不预防性通读。
- **规则未覆盖/冲突**：以用户目标、台账事实与既有门禁为先，选最小成本可验证路径；收尾记录取舍，不新增门、不跳红线。
- **轨互斥与计划编排**：默认轨互斥——单轨口令命中即停，不跨轨默读；计划驱动按计划 §9.2 编排多轨（阶段内仍按对应轨契约），可并行但须账号/数据/环境隔离；不并行开跑未计划轨道。
- **计划驱动独立实施**：本包可单独启用，不要求开发/产品包同时安装或默认联动；跨包输入可选，缺失按现有主读/基线执行并最多一句提示。

### 0.6 文档现行有效

只描述当前存在的功能/流程/规则；删除即移除；不记录历史过程；不引入不存在概念；结论不复述过程或方案草稿；不把修改方案写入正式产物。例外：变更记录/CR/复盘/执行日志可留痕，但不回流正式资产。

## 1. 接入

实例在项目根：`环境基线.md`、`activeContext.md`、设计输入目录（默认 `测试/资料/`，扁平）。占位符未换或无基线=未接入。接入流程与核验清单：`workflows/onboard.yaml` + `agents/onboard-agent.yaml`（业务口令触发时自动走一次并打标）。

**测试分级（防过度/不足）**：

| 级别 | 典型 | 计划 | 执行 |
| --- | --- | --- | --- |
| T0 补丁/热修 | 小改、单模块 | 轻量计划（≤1 页） | P0 冒烟 + 影响面 + 已脚本化回归 |
| T1 模块 | 功能/模块 | 轻量计划 | 模块功能 + 接口（如适用） |
| T2 版本 | 发布级 | 完整计划 | P0～P9 按计划 |
| T3 高风险 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 全量 + 性能/安全/兼容 |

T0/T1 不强行填完整 17 节；范围、类型、轨道、执行矩阵、准出、风险必须写清。发布列车/大版本 ≥1 次功能全量；补丁不强制全量。

## 4. git

提交/推送前：拟提交清单 + `.gitignore` 现状 + 当前分支 → 用户确认后执行；禁擅自切主干、force push、开/合并 PR（除非点名）。完整任务收尾检查仓库状态与 `.gitignore`，写入收尾第 2 点。

## 5. 收尾

触发：工作流末步、计划全部阶段结束、点名「收尾/总结」。输出按 `规则/模板/收尾骨架.md`；生成/执行可用【生成收尾】/【执行收尾】；专规只填第 1 点。门3（提交/交平台）在骨架后单独确认；`report` 只写「有 N 个文件待提交」，完整【拟提交】在 handoff 步只展示一次。

## 6. 维护

改不变量/路由/读取协议 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/门 → `规则/`；改澄清 → `规则/澄清.md`；改轨边界 → `规则/轨契约/`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`；改计划编排 → 测试计划模板 + `工作流.md` §3.6 + `多Agent与输出.md` §4（三处同步）；改读取索引 → `规则/读取索引.md`。自检见 `规则/维护.md` §2。

## 7. 多包（自动探测）

项目根同时存在两个及以上包目录（`产品规范/`、`开发规范/`、`测试规范/`，以各自 `AGENTS.md` 为标志）= 多包模式；只有一个包 = 单包模式。自动生效，无需额外目录或合同文件。

- 共享外部资料根：`项目资料/`（首次需要共享资料时创建；不预建、不强制）。共享索引 `项目资料/资料索引.md`；本包 `资料/` 只放本包专属/历史资料。一份资料一个主副本，跨包只写引用。
- 根 `activeContext.md` 共用：按 `产品 / 开发 / 测试` 分节，各包只更新本节与 `跨包同步`，不覆盖其他节。
- 一次会话只执行一个包的 workflow；跨包交接只写“路径 + 状态”，不复制正文、不自动执行对方 workflow。
- 单包模式以上全部不启用，按本文默认执行。
