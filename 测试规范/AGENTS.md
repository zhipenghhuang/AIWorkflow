# AGENTS.md

> **用途**：测试规范 AI 入口。常驻最小集；命中口令 → `workflows/*.yaml` 当前 step → `规则/读取索引.md` 当前行 → 当前 `agents/*.yaml`。
> **位置**：`测试规范/`。与项目根 `AGENTS.md` 冲突时，以项目根为准；红线不被覆盖。
> **template_version**：`2026.10.24.3`（单点：包内版本以本文为准）。
> **架构**：Workflow + Agent + 规则/门/读取索引 + 技能/能力 + 验证层（台账/报告/覆盖/回写）；主链分析→计划→生成→执行→报告。

## 0. 开工（每任务）

1. **中文**：对话与结论用中文；写现行结论。
2. **activeContext**：任务前读 `activeContext.md`，2～3 句报备焦点/下一步；无则按模板初始化。有实质进展收尾更新。
3. **接入状态（一次判定）**：`activeContext.md` 有 `landing=ok` → 禁止再预检，直跑命中 workflow；无标记且命中生成/执行/缺陷类口令 → 仅此一次按 `agents/onboard-agent.yaml` 核验，通过则写 `landing=ok` 静默直跑，未接入则走 `onboard.yaml` 后 resume。
4. **独立判断**：不迎合；先查错误前提/逻辑跳跃/信息缺失；数字/结论与台账/报告同口径并尽量核实来源；用户有误直接指出依据与风险。
5. **冲突优先级**：用户明确指令 > 安全/合规/硬红线（§0.2/§0.4） > 项目根 `AGENTS.md` > 本文 > 当前 agent 契约。红线不被覆盖。
6. **读取协议**：

| 场景 | 读什么 |
| --- | --- |
| 任意已路由 | 本文 §0～§2 → workflow 当前 step → 读取索引当前行 → 当前 agent/产物 |
| 有门/写 YAML | `规则/门.md` 当前行；不通读全表 |
| 生成/执行 | `规则/playbooks/generate.md` 或 `execute.md` + `工作流.md` 当前节 + 当前轨契约；不跨轨通读 |
| 验证/收尾 | `验证/README.md` + `规则/核心/验证规则.md` + 计划/台账/报告；报告门 |
| 交接/变更 | `规则/协作/协作与交接.md` 当前节 + `规则/模板/90-交接与收尾/交接包说明模板.md` + `交接台账.md`；变更按 C0～C3 |
| 脚本档 | `规则/专项/脚本执行.md` §3/§4 + executor README；失败/阻塞再按 `playbooks/execute.md` 升级 |
| 维护/查询 | 本文 + `规则/核心/维护.md` + 点名 |

同一会话文件未变不重读；后续 delta-only；同方案无效 2 次换手段；探查限定目录/关键词。**规则阅读不是越多越稳**：读错轨/读全本会稀释约束。**单步读取 ≤5 个来源/≤8k tokens；标 `读取级别：参考` 的大文件只读当前节；不为预防而读。**

### 0.1 计划门与三门 · 澄清

- **只认 YAML 步上 `hitl`**；门/`when`/`gate_when` 语义见 `规则/门.md`。条件不满足则跳过；专规不另造门。
- **门档位**：autonomous（只读/列表/巡检/已脚本化回归，直接做）｜notify（同范围生成/执行、A/B 期中变更，展示后继续）｜approve（计划实质变更、首次执行未确认范围、平台建单/回写、提交、资料搬迁/清理）。
- **计划门**：版本级首版/换代或范围·准出·缺陷提交策略实质变更才停；同会话同载体只一次；专项轻量不设门。
- **门1/门2/门3**：主读未点名一问；执行范围/环境未确认才停；计划驱动已确认→跳过并附【已预授权执行：按计划】；有拟入库/须交平台/拟新建缺陷单→停。
- **澄清**：按 `规则/核心/澄清.md`；先读规则/技能/主读/代码/现网做分析，再给「我的理解 + 已分析建议 + 需要你拍板（0～1 个）」；只问影响意图/范围/验收/风险的问题，接口/字段/测试技术等细节自行分析；总提问不超过 3 个；确认后才写计划/用例/断言。禁把技术细节逐条问用户、禁自问自答、禁把假设当结论/把确认门当澄清。
- **测试依据先建模**：PRD/迭代方案/原型/接口或技术文档 → 先按 `技能/test-basis-analysis/SKILL.md` 建需求模型、冲突/九类歧义清单与 oracle；预期无来源不写断言；不按现网实现反推需求。
- **预授权**：「一次性/直接跑完」默认只到任务完成（执行+核验+骨架），不含提交/推送/部署/交平台。计划 §0=已确认/执行中/待关闭的计划内执行与「发现即提交」视为预授权；计划外提交仍门3。

**澄清停止条件**：理解已复述、关键高影响问题已确认、测试策略/oracle 已有建议；剩余只是低影响假设或待用户确认的建议。95% 仅参考；连续 3 轮无新信息 → 收敛范围或给推荐方案，不继续盘问。

**期中变更/缺陷分流**：用户给变化/新文档或产品平台确认 → 建 `测试/变更/CR-*.md` + 影响分析；A 澄清/B 同范围增量就地更新；C 实质变更回计划门；D 缺陷驱动→缺陷轨。提交/查重/指派给我+回归/巡检→`workflows/defect.yaml`；只描述现象无平台编号→本包执行失败/change。修 Bug 代码不在本包执行。

### 0.2 硬红线（易疏忽）

1. 禁臆造路由/接口/按钮；正式资产只写现行有效状态（§0.6）。
2. 密钥/凭据不入库、不进提交摘要；基线密码明文仅限测试环境且经用户授权；真实 PII 不入证据/平台。
3. 子代理边界：不 git/不交平台/不改他模块文件；模块档只写本模块台账与证据；拆分档 Worker 仅写 DraftPath；编排核验后再结论。
4. **先 UI 再 Network**（功能/探索式轨）；禁猜未见 API 判失败。
5. **阻塞从严**：缺数据/缺样本先造数或换样（≠阻塞）；可打通不写阻塞；产品问题记失败；单案互异手段≥2 且总尝试≤3，仍不可用才 blocked 并写已尝试；blocked 四问任一未过不写 blocked。
6. **禁抬高通过率**：不手改结果表刷绿；失败须实拍进 `测试/功能测试/证据/{模块}/`；P0 未通过不得判整体通过。
7. **能脚本不 AI**：已脚本化用例回归/重跑必须走脚本档；脚本失败按有界复核（一次为限、同批同因合并、可定性即停）后方可定性；禁脚本失败直接交平台。
8. **计划驱动不跳轨**：按计划 §9.2 阶段执行，每阶段仍按对应轨契约；不跨轨通读、不静默降范围；实质变更回计划门。
9. **依据可追溯**：每个用例/断言必须能指到需求/AC/规则/原型/接口文档；无来源先问或标“文档未声明”，不得臆造；文档与实现冲突记失败/待确认，不按实现改预期。
10. **资料/文档/回写**：新资料先分类+覆盖对照，确认后才改名/登记/归档；版本关闭才归档版本绑定文档；交平台/回写必须有回执，无权限走 export，不得声称已回写。

### 0.3 执行中（效率）

- 多解先权衡；路径唯一直接做；动手前说明拟改文件；最小改动；过程只落 `.draft/`。
- 工具点名优先：本包点名的脚本/浏览器 MCP 按点名调用；成本分配见 `规则/专项/多Agent与输出.md` §1.3/§3（能脚本不 AI、少全量快照、按 step 读规则）。

### 0.4 工程红线

1. 不在生产/未授权环境执行；造数仅在授权测试环境。
2. 严重程度按业务影响（S1–S4）；拿不准一问。
3. P0 未通过不得判整体通过（「有条件通过」仅限 P0 全通过、缺口非 P0 且用户接受）；准出对照计划标准；未测项显式列缺口。
4. 子代理/并行：账号/数据/浏览器 profile/写域隔离；同条用例禁并行。

### 0.5 框架固定 · 局部自主

- **不可让**：口令→workflow、`hitl`/`hitl_when`、专规输出骨架、预授权界、密钥、角色边界、`.draft/` 落点、需求模型与 oracle 可追溯、覆盖三闸、缺口三分类、执行口径探查与 pending 红线、失败分类与相符证明、脚本档失败升级、冒烟前置、计划门与准出、计划驱动阶段编排/回归闭环/缺陷提交授权、`landing=ok` 免检、能力取用与降级、文档现行有效。
- **应交 AI**：怎么拆用例/划批/取档/探查/是否派子代理——推理中择优；不另开长文规划（分析短表与测试计划除外）；不预防性通读。
- **规则未覆盖/冲突**：以用户目标、台账事实与既有门禁为先，选最小成本可验证路径；收尾记录取舍，不新增门、不跳红线。
- **轨互斥/独立实施**：单轨口令命中即停，不跨轨默读；计划驱动按 §9.2 编排多轨；本包可单独启用，不要求开发/产品包同时安装。

### 0.6 文档现行有效

只描述当前存在的功能/流程/规则；删除即移除；不记录历史过程；不引入不存在概念；结论不复述过程或方案草稿；不把修改方案写入正式产物。例外：变更记录/CR/复盘/执行日志可留痕，但不回流正式资产。

### 0.7 验证与汇报（硬约束）

1. **报告只认门**：出报告/准出前运行 `验证/Invoke-Gate.ps1 -Mode report`；读 `.gate/测试规范/report.json`。没有 PASS/CONDITIONAL，只能报“不通过/阻塞/未验证”。`writeback` 只写 `writeback.json`，不得覆盖 report。
2. **数字/P0 对账**：报告 §4 与台账 §1/§2 逐项一致；计划/稳定冒烟清单的 P0 必须在台账中存在且为终态，P0 缺失/未过不得写“整体通过/可准出”；有条件通过仅限 P0 全过、缺口非 P0 且用户接受；数字不一致先修，不得手改通过率。
3. **证据可打开**：失败/阻塞/待实现必须有证据或已尝试/恢复条件；路径不存在 = FAIL/BLOCKED。
4. **报告先写回执**：`【验证回执】verdict=...` 在结论之前；非 PASS 禁用“全部通过/可发布”。
5. **回写有回执**：交平台/回写前跑 `-Mode writeback`；无回执不得声称已回写；无权限走 export。
6. **成本/规则**：单模块小批跑 execute 门；版本级/全量跑 report 门；不全量回归每个补丁；不新增测试文档。详细规则：`验证/README.md`、`规则/核心/验证规则.md`；维护读 `规则/核心/规则治理.md`。

### 0.8 协作与交接（硬约束）

- **唯一载体**：提测/报告/缺陷/变更/发布按 `规则/协作/协作与交接.md` 生成 `测试/交接/{HO-ID}/`；接收方回执到 `04-回执/接收回执.md`。**未收回执不得称“已交接/已接收”**。
- **三件套 + 三选一**：`00-交接说明` + `01-交接清单` + 必带快照；接收=接受/有条件/退回。C2/C3 必须重基线并过计划门，禁止降级绕过。
- **同轮回写**：`交接台账.md` → 测试计划 §0/§16.1 → 文档索引 → `activeContext.md`；计划只写摘要，台账是交接真值。

首条：`route=workflow:<id> | step=<id> | role=<agent> | reads=<读取索引行> | next_action=…`；仅无标记预检时加 `preflight=onboard`；有主读/输入时加 `input=<路径>`。

## 3. 实例路径（相对项目根）

根只留 `环境基线.md`、`activeContext.md`；测试产物统一 `测试/`（计划/报告/功能/接口/探索式/发布前/脚本/资料/交接/归档）。路径、旧项目兼容、可选输入见 `规则/工作流.md` §1.3 与 `规则/读取索引.md`；禁止在项目根堆测试产物。

## 4. git

提交/推送前：拟提交清单 + `.gitignore` 现状 + 当前分支 → 用户确认后执行；禁擅自切主干、force push、开/合并 PR（除非点名）。完整任务收尾检查仓库状态与 `.gitignore`，写入收尾第 2 点。

## 5. 收尾

触发：工作流末步、计划全部阶段结束、点名「收尾/总结」。按 `规则/模板/90-交接与收尾/收尾骨架.md`；先写 `【验证回执】`，再写结论；生成/执行可用【生成收尾】/【执行收尾】；专规只填第 1 点。门3（提交/交平台）在骨架后单独确认；`report` 只写「有 N 个文件待提交」，完整【拟提交】在 handoff 步只展示一次。收尾必须列「未回执/退回/阻断执行」的 HO-ID；有未回执的必需交接，不得把阶段标为完成。

## 6. 维护

改不变量/路由/读取协议 → 本文；改步骤 → `workflows/`；改角色 → `agents/`；改红线/门 → `规则/`；改澄清 → `规则/核心/澄清.md`；改协作/交接/变更分级 → `规则/协作/协作与交接.md` + `workflows/handoff.yaml`；改轨边界 → `规则/轨契约/`；改模板 → `规则/模板/`；改技能 → `技能/`；改能力 → `能力/`；改计划编排 → 测试计划模板 + `工作流.md` §3.6 + `规则/专项/多Agent与输出.md` §4（三处同步）；改读取索引 → `规则/读取索引.md`。自检见 `规则/核心/维护.md` §2。

## 7. 多包（自动探测）

项目根同时存在两个及以上包目录（`产品规范/`、`开发规范/`、`测试规范/`，以各自 `AGENTS.md` 为标志）= 多包模式；否则单包。
- 共享 `项目资料/`（首次需要时创建）、根 `activeContext.md`（按产品/开发/测试分节，各包只更新本节与跨包同步）。
- 一次会话只执行一个包 workflow；跨包交接优先用 `测试/交接/{HO-ID}/` 整包（路径+状态+回执），对方未装包时按普通文档/回执处理；不复制正文、不自动执行对方 workflow。
- 单包模式以上不启用，按本文默认执行。

## 8. 技能与能力（按步加载）

- **技能（必用）**：`技能/<name>/SKILL.md`，随包复制、命中步必用；方法见 `技能/README.md`。
- **能力（可选）**：`能力/00-能力注册表.md`；已安装即用，未安装降级；能力不替代技能。
