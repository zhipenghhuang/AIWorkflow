# AI 测试资产体系 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（测试轨）**：主链见 `workflows/testing.yaml`——分析 → **测试计划（唯一编排载体）** → 生成 → 按计划执行 → 报告（口令可切入任一步）；内置专业技能（`技能/`：随包生效、按步自动加载）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）。版本级单点：`测试/测试计划.md`（范围/类型/轨道/编排/回归/缺陷/探索式/准入准出）、`测试/测试报告.md`（计划对照/准出评估/遗留风险）。  
正式并列轨：功能全量/专项、探索式、接口、发布前、缺陷；**计划驱动模式**按测试计划把各轨串成一条执行链（功能→接口→探索式→非功能→回归→缺陷闭环→报告）。  
口令映射 workflow；条件 `hitl`/`hitl_when`、覆盖三闸、冒烟前置与阻断面、证据红线不可让；执行形态四档与取档由 AI 择优（已脚本化→脚本档 0 token；多模块→模块子代理逐模块；单模块小批→直跑；较大/高风险→Worker+Reviewer 拆分）。  
首次无 `landing=ok` 时自动按接入清单核验并打标一次；之后直跑。  
**独立实施**：本包可单独落地，不要求开发/产品包同时安装或默认联动；跨包输入是可选的——有则按用户指定路径读入，无则按现有主读/基线执行，最多一句提示，不阻塞、不反复追问。  
**成本策略**：功能 P0 冒烟 + 接口确定性用例 + 回归 P0 冒烟优先脚本化（0 token）；发布前用工具测量，AI 只做设计/探查/失败复核/探索；P0 冒烟脚本与接口脚本跨版本复用；**不搞全量资产库**。**分配门槛**：P0-Smoke/每次构建发布才脚本；新功能/复杂判断给 AI；一次性不脚本；禁止“AI 跑一遍→再生成→再跑”。  
**新版本入口**：计划 §3.7 逐模块/流程标「P0 冒烟/P0 待脚本/迭代功能/接口确定性/一次性/淘汰」；P0 冒烟脚本登记 `测试/00-稳定冒烟清单.md`，再按矩阵执行。  
**额外发现**：AI 执行中同时记录用例之外的 UI/布局/显示/文案/console/network/UX 异常，进报告 §5.4；不静默忽略。  
**执行引擎**：UI 稳定主链路/E2E 与 API/契约默认 Playwright 脚本；AI 用于设计、探查、失败复核、探索式与报告；性能/安全/兼容/迁移用专项工具，AI 只解读与判定。  
方法参考：ISO/IEC/IEEE 29119-3 测试计划要素、ISTQB 风险驱动/测试金字塔、SBTM 探索式测试；可选 `qa-skills`/`exploratory-skill` 见 `能力/00-能力注册表.md`（未安装按内置技能执行）。  

## 2. 目录

| 路径 | 作用 |
| --- | --- |
| `workflows/` | `testing` / `defect` / `onboard` |
| `agents/` | analyzer / planner / testcase / orchestrator / worker / reviewer / bug / report / onboard |
| `能力/` | 可选能力注册表（技能/工具装配建议；`能力/00-能力注册表.md`） |
| `技能/` | 内置专业技能（每步方法/手艺，随包生效、按步自动加载；含 `name/description` frontmatter；`技能/README.md`） |
| `AGENTS.md` | AI 入口（接入 + 口令 → workflow；版本单点） |
| `规则/工作流.md` | 产物路径、覆盖三闸、收尾骨架 |
| `规则/轨契约/` | 探索式 / 接口 / 发布前边界（按口令点读） |
| `规则/多Agent与输出.md` | 执行形态四档、jsonl↔台账、执行红线 |
| `规则/脚本执行.md` | 脚本档：可脚本化判定、资产与脚本格式、执行纪律、合并提速 |
| `规则/缺陷协作.md` | 平台提交/回归/备注 |
| `规则/缺陷分类.md` | 失败分类（实现缺陷/产品缺陷）与相符证明 |
| `规则/模板/` | 基线、**企业级测试计划（唯一编排）**、报告（计划对照）、功能用例、探索式用例、台账、**稳定冒烟清单、测试变更记录**、activeContext、00 索引、根 AGENTS 引导样例 |
| `规则/tools/` | 包自检（`Invoke-TestWorkflow -Action ValidateTemplateRefs`；含 YAML 引用/锚点与步标记词表）+ 脚本档工具（`playwright/` 执行器与配置模板、`merge-ledger.mjs` 台账合并） |

> 实例在项目根：`环境基线.md`、`activeContext.md`；测试产物统一在 **`测试/`**。  
> 顶层只保留：`测试/测试计划.md`、`测试/测试报告.md`、`测试/00-稳定冒烟清单.md`、`测试/变更/`、`测试/功能测试/`、`测试/接口测试/`、`测试/探索式测试/`、`测试/发布前测试/`、`测试/脚本/`、`测试/资料/`、`测试/_归档/`。  
> **不再分 `测试用例/` 和 `执行台账/`**：功能测试的用例、台账、评审、证据、分析短表全部放 `测试/功能测试/`。  
> **不再单独建“计划执行看板”**：状态统一放 `测试/测试计划.md` §0，过程明细放 §16 执行日志/执行台账。

### 2.1 实例目录分类（扁平化 · 禁止根目录堆测试产物）

| 位置 | 放什么 | 禁止 |
| --- | --- | --- |
| 项目根 | `环境基线.md`、`activeContext.md` | 测试计划/报告/用例/台账/脚本/证据/项目资料 |
| `测试/` | `测试/测试计划.md`、`测试/测试报告.md`、`测试/00-稳定冒烟清单.md`（版本级单点） | 长期堆各轨临时文件 |
| `测试/资料/` | **项目文档/ + 测试数据/** + `测试/资料/资料索引.md`（固定资料区） | 正式计划/报告/用例 |
| `测试/变更/` | 期中变更 CR（影响分析/计划调整/文档更新/回归） | 新版本整期方案（归计划/资料） |
| `测试/功能测试/` | 功能全量/专项**用例、执行台账、评审记录、分析短表、证据、`.draft/` 过程件**，全部同级 | 接口/探索式/发布前用例 |
| `测试/接口测试/` | 契约表、接口用例、接口台账、证据、`脚本/` | 功能 UI 用例 |
| `测试/探索式测试/` | 探索式用例、台账、证据、session 记录 | 功能全量用例 |
| `测试/发布前测试/` | `性能/`、`安全/`、`兼容/` 三个独立专项，各自方案/报告/证据/脚本 | 三项混在一个方案里 |
| `测试/脚本/` | 共享执行器、配置、功能脚本 | 业务数据/证据 |
| `测试/_归档/` | 换代/结项/版本快照 | 现行版本资产 |

> 规则：**项目根只保留 2 项**（`环境基线.md`、`activeContext.md`）；所有测试产物和项目资料都在 `测试/` 下。  
> `测试/资料/项目文档/` 是**输入**：PRD/方案/设计稿/外部文档放这里；`测试/资料/测试数据/` 放样本/造数说明；测试执行资产不要回写 `资料/`。  

```text
测试/资料/
├─ 项目文档/      # PRD/需求/方案/设计稿/外部文档
├─ 测试数据/      # 样本/造数说明/账号配方
└─ 资料索引.md    # 来源/日期/版本/关联需求/状态
```
> **旧项目兼容**：已有 `测试/测试用例/`、`测试/执行台账/`、`测试/测试脚本/`、`测试/发布前测试/{专项}` 可继续使用；在 `环境基线.md` §2.1 记录实际路径。说「重新接入」时按最新布局一次性迁移并更新索引/链接；不迁移则按实际路径执行。


## 3. 上手（快速开始）

1. 复制整个 `测试规范/`；在项目根 `AGENTS.md` 补入引导语句（样例见 `规则/模板/根AGENTS薄指针.md`）  
2. 设计文档放入设计输入目录（默认 `测试/资料/项目文档/`）  
3. 主流程：「生成测试计划」→ 计划门确认 →「按测试计划执行」→ 报告/准出；日常用「当前状态 / 下一步」只读计划 §0；也可用「生成测试资产」/「执行××专题」单轨切入  
4. 收尾确认拟提交；需要时交缺陷  

```text
方案文档 → 分析 → 测试计划（类型/轨道/编排/回归/缺陷/探索式）
→ 生成资产 → 按计划执行（功能→接口→探索式→非功能→回归→缺陷闭环）
→ 测试报告（计划对照/准出/遗留风险）
```

示例口令：

```text
生成测试计划，主读 测试/资料/项目文档/BI-2026Q4迭代方案.md
（计划门确认：范围/类型/轨道/缺陷策略/探索章程/准出）
按测试计划执行
```

**新版本迭代执行 6 步**：

1. 读方案/变更点，查 `测试/00-稳定冒烟清单.md`（只看 P0-Smoke 脚本，不查全量资产）。
2. 计划 §3.7 填「本轮执行矩阵」：P0 冒烟 / P0 待脚本 / 迭代功能 / 接口确定性 / 一次性 / 淘汰。
3. P0 冒烟 → 脚本回归；P0 待脚本 → 本轮补脚本；迭代功能 → AI 执行。
4. 接口确定性 → API 脚本；新功能/未定型 → AI 探路一次，稳定且成为 P0 后再固化；一次性不脚本。
5. 冒烟 → 功能/接口 → 探索式 → 非功能 → 连续回归；缺陷按计划提交/修复/回归。
6. 报告计划 vs 实际 + 额外发现；只更新 P0 冒烟清单，不做全量索引。

**期中变更（不新开计划）**：给 AI 新变化/新文档 → `测试/变更/CR-*.md` 影响分析 → 更新计划 §0/§2/§3.1/§3.2/§3.7/§14.3/§15 → 只改受影响用例/脚本 → P0 冒烟 + 变更用例 + 影响面 → 报告/验收。A 澄清/B 同范围增量不重开计划门；C 实质变更回计划门；D 缺陷走缺陷轨。**执行时机默认等计划模块/阶段位；提前仅限 P0/高风险、阻塞后续、独立且数据/入口就绪、有专门含变更构建；P0 冒烟可在构建/阶段边界先跑；执行前核构建含变更。**  

计划驱动执行覆盖本包可执行轨道；单元/静态、UAT、灰度/生产验证由对应团队执行或协调，计划登记责任人与证据，不冒充已测。  


## 4. 自检

```text
测试规范/规则/tools/Invoke-TestWorkflow.ps1 -Action ValidateTemplateRefs
```

自检时机：改包后、用户点名；接入核验由 onboarding 接入清单执行。自检含 YAML 语法/schema（`规则/tools/validate_workflow.py`，需 Python + PyYAML）。  
可选输入：见 §1「独立实施」；有则按用户指定路径读入，无则按现有资料执行，最多一句提示，不阻塞；回写由用户点名。

## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`环境基线.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；浏览器自动化按需（功能/探索式轨必需）、子代理推荐。
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。
- **MCP 配置落点**：只写宿主本地/用户级配置（如 Cursor：`%USERPROFILE%\.cursor\mcp.json`；路径以宿主官方文档为准）；实例绑定值填 `环境基线.md` §8.1；禁项目内配置作规范入口。
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `环境基线.md` §17（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。
