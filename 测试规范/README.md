# AI 测试资产体系 — 使用说明

> 供人阅读；AI 入口为同目录 `AGENTS.md`。  
> **template_version**：以 `AGENTS.md` 为准（单点）。

## 1. 是什么

**AI Workflow 包（测试轨）**：主链见 `workflows/testing.yaml`——需求/测试依据分析（需求模型/oracle/追溯）→ **测试计划（唯一编排载体）** → 生成 → **用例评审（独立量规/机器门）** → 按计划执行 → 报告（口令可切入任一步）；内置专业技能（`技能/`：随包生效、按步自动加载，含 `testcase-review`）+ 可选能力层（`能力/` 注册表：本机可用即自动使用、不可用降级）。版本级单点：`测试/测试计划.md`（范围/类型/轨道/编排/回归/缺陷/探索式/准入准出）、`测试/测试报告.md`（计划对照/准出评估/遗留风险）。  
**依据建模**：PRD/迭代方案/原型/接口/代码 diff 先按 `技能/test-basis-analysis/SKILL.md` 建需求模型/冲突/九类歧义/oracle/TP 追溯，再按 `规则/核心/澄清.md` 先分析、只问意图/范围/验收/风险，技术细节给建议，首轮 0～1 问、总≤3，确认后才写计划/用例；预期无来源不写断言。
正式并列轨：功能全量/专项、探索式、接口、发布前、缺陷；**计划驱动模式**按测试计划把各轨串成一条执行链（功能→接口→探索式→非功能→回归→缺陷闭环→报告）。  
口令映射 workflow；条件 `hitl`/`hitl_when`、覆盖三闸、冒烟前置与阻断面、证据红线不可让；执行形态四档与取档由 AI 择优（已脚本化→脚本档 0 token；多模块→模块子代理逐模块；单模块小批→直跑；较大/高风险→Worker+Reviewer 拆分）。  
首次无 `测试规范接入：已完成`（兼容旧 `landing=ok`）时自动按接入清单核验并打标一次；之后直跑。  
**独立实施**：本包可单独落地，不要求开发/产品包同时安装或默认联动；跨包输入是可选的——有则按用户指定路径读入，无则按现有主读/基线执行，最多一句提示，不阻塞、不反复追问。多包同项目时自动探测并共享 `项目资料/` 与 `activeContext.md`；不需要额外协作目录或合同文件，本包仍独立执行。  
**成本策略**：**域常青分层库**（L0 Core 冒烟清单 ≤12｜L1 域主档｜L2 本版增量）+ **变更装填执行**（suite=`core|module|full`）；禁日常通读全库当回归索引。功能 P0 / 接口高风险维优先脚本化；发布前用工具测量；AI 做增量设计/探查/失败复核/探索。**完整覆盖**=库映射齐；**完整执行**=按装填/发版加宽，非每迭代全库重跑。**分配门槛**：P0-Smoke 才脚本；命中域增量保 caseId；冷启动无域才首生；禁无分析全仓重生；禁「继续」隐式 generate；禁止“AI 跑一遍→再生成→再跑”。  
**新版本入口**：计划 §3.7 逐模块/流程标「P0 冒烟/P0 待脚本/迭代功能/接口确定性/一次性/淘汰」；P0 冒烟脚本登记 `测试/00-稳定冒烟清单.md`，再按矩阵执行。  
**额外发现**：AI 执行中同时记录用例之外的 UI/布局/显示/文案/冗余标签/console/network/UX 异常，进报告 §5.4；不静默忽略。  
**体验纪律**：验收 UI 减法（冗余文案/标签、删后仍可理解）与 UX/DX/AX 三维；测试资产同样不得净退化；详见 `AGENTS.md` §0.2-11、`规则/模板/20-测试用例/无障碍与UX检查清单.md` §2.1。  
**执行引擎**：UI 稳定主链路/E2E 与 API/契约默认 Playwright 脚本；AI 用于设计、探查、失败复核、探索式与报告；性能/安全/兼容/迁移用专项工具，AI 只解读与判定。  
方法参考：ISO/IEC/IEEE 29119-3 测试计划要素、ISTQB 风险驱动/测试金字塔、SBTM 探索式测试；需求分析与澄清参考 fishzjp/qa-skills `requirement-analysis`/`clarify-pattern`、GitHub Spec Kit `clarify`/`analyze`、addyosmani/agent-skills `interview-me`；可选 `qa-skills`/`exploratory-skill` 见 `能力/00-能力注册表.md`（未安装按内置技能执行）。

> **归档落点**：计划/报告/CR/交接进 `测试/_归档/`；**功能/接口域主档常青留下**；轨内 `_归档/` 仅下线域/重生快照/旧探索轮；失效资料进 `测试/资料/_归档/`。细则见 `规则/文档治理.md` §7。  
> **交接**：**内容优先、包按需**——默认交自洽计划/报告/平台缺陷；HO 包仅多文件/签收/仓外/点名时先问后发。禁静默发包与「报告完成必须发包」。有平台已交不重复 BUG 包。多包同仓直读，禁转发。
> **不再分 `测试用例/` 和 `执行台账/`**：功能测试的用例、台账、评审、证据、分析短表全部放 `测试/功能测试/`。  
> **不再单独建“计划执行看板”**：状态统一放 `测试/测试计划.md` §0，过程明细放 §16 执行日志/执行台账。

### 2.1 实例目录分类（禁止根目录堆测试产物）

| 位置 | 放什么 | 禁止 |
| --- | --- | --- |
| 项目根 | `环境基线.md`、`activeContext.md` | 测试计划/报告/用例/台账/脚本/证据/项目资料 |
| `测试/` | `测试/测试计划.md`、`测试/测试报告.md`、`测试/00-稳定冒烟清单.md`（L0 Core） | 长期堆临时文件；关账搬走仍有效域主档 |
| `测试/资料/` | **版本/主题子目录**：`{V1.5,V2.0,APS-…}/` + `_通用/` + `资料索引.md` + `测试数据/` + `_归档/`（失效资料；禁 `项目文档/` 层） | 正式计划/报告/用例；勿用类型前缀扁平落盘 |
| `测试/变更/` | 期中变更 CR（影响分析/计划调整/文档更新/回归） | 新版本整期方案（归计划/资料） |
| `测试/功能测试/` | **域常青**用例/台账/评审/分析/证据/`.draft/`；`_归档/` 仅下线域/重生快照 | 接口/探索式/发布前用例 |
| `测试/接口测试/` | **域常青**契约/用例/台账/证据/`脚本/`；`_归档/` 仅下线/旧轮/重生快照 | 功能 UI 用例 |
| `测试/探索式测试/` | 用例、台账、证据、session；点名旧轮 → `_归档/{yyyyMMdd}/` | 功能全量用例 |
| `测试/发布前测试/` | 方案/矩阵常青；停用包 → `{专项}/_归档/{yyyyMMdd}-{版本}/` | 多项混在一个方案里 |
| `测试/脚本/` | 共享执行器、配置、功能脚本 | 业务数据/证据 |
| `测试/_归档/` | **仅**计划/报告/CR/交接跨轨快照 + `_待清理/` | 仍有效的功能/接口域主档；失效资料 |

> 规则：**项目根只保留 2 项**（`环境基线.md`、`activeContext.md`）；所有测试产物和项目资料都在 `测试/` 下。多包模式例外：根 `项目资料/` 是共享资料根，不属测试产物；单包不建。  
> `测试/资料/` 是**输入区**：设计文档落 `{版本或主题}/` 或 `_通用/`；本包用例/报告/脚本/证据不要回写 `资料/`。入站先意图分析（T1～T9）；确认采纳且 S1/S2/S3 → 同批进 `资料/_归档/`。分类、覆盖对照、失效与归档以 `规则/文档治理.md` 为准。单包优先；放入≠自动跑他包。

```text
测试/资料/
├─ 资料索引.md
├─ _通用/                             # 跨版本稳定输入
├─ V1.5/
├─ V2.0/
├─ APS-2.2.0/ … APS-2.5.0/
```

> **兼容**：已有 `测试/测试用例/`、`测试/执行台账/`、`测试/测试脚本/` 等旧轨路径可继续使用并记入基线 §2.1；「重新接入」时迁到现行轨目录。旧 `资料/项目文档/{ver}/` → `资料/{ver}/`；残留类型前缀平铺可登记保留，新资料进 `{版本或主题}/` 或 `_通用/`。

## 3. 上手（快速开始）

1. 复制整个 `测试规范/`；在项目根 `AGENTS.md` 补入引导语句（样例见 `规则/模板/00-接入与基线/根AGENTS薄指针.md`）  
2. 设计文档放入设计输入目录（默认 `测试/资料/{版本或主题}/` 或 `_通用/`；新文件先按 `规则/文档治理.md` 收取/对照）  
3. 主流程：「生成测试计划」→ 计划门确认 →「生成测试资产」→「用例评审」放行 →「按测试计划执行」→ 报告/准出；日常用「当前状态 / 下一步」只读计划 §0；也可用「生成测试资产」/「执行××专题」单轨切入  
3.1 **不用口令**：任意自然语言描述要测什么/怎么测/跑测/准出即可；AI 按 `规则/核心/入口判定.md` 抽五元组→意图类→计划状态修正，不抠固定措辞；首条 `route`/`reason`。有计划优先按 §0 续跑；未建模不得直接写用例；判断错可一句纠正。  
4. 缺陷按计划 §11 提交；有平台→交平台为主不发 BUG 包；无平台/点名缺陷交接→**先问后发**详单包（§3.1.1）。
5. 交接：**内容优先、包按需、先问后发**。默认交报告/计划/平台缺陷；说「生成交接包…」或命中多文件/签收/仓外时才问并发包。接收类口令走 `receive`。

```text
方案文档 → 分析 → 计划 → 资产 → 执行 → 报告/准出
→（可选，经你确认）交接包 TEST/PLAN/BUG/… 
```

示例口令：

```text
生成测试计划，主读 测试/资料/V2.7.0/IBIPS_V2.7.0_….md
（计划门确认：范围/类型/轨道/缺陷策略/探索章程/准出）
按测试计划执行

资料收取 测试/资料/V2.0/…
（AI 输出入站分析 T1～T9 + 覆盖对照 + 归档候选；确认后同批落位/归档）

文档巡检
（AI 输出工作文档更新/归档 + 临时文件清理候选；确认后执行）
```

**新版本迭代执行 6 步**：

1. 读方案/提测影响面/变更点；打开 **Core 冒烟清单 + 命中域现行用例**（禁通读全库；禁跳过命中域）。
2. 计划 §3.7 装填：命中域 + **邻接影响面（宁多勿漏）**；迭代 suite=module；发版/完整项目=full。
3. 生成：命中域增量保 caseId（无域才首生）；映射/用例宁多勿漏；覆盖三闸过关 → 评审。
4. 执行：core 冒烟全绿 → 跑装填域（module/full）；接口默认可执行高风险维，发版 depth=full。
5. 缺陷即回归；连续回归不默认全库；探索式/发布前按计划穿插。
6. 报告声明 suite + 计划 vs 实际；**迭代≥module、发版=full 才可准出**；更新 Core 与 §3.7。

**期中变更（不新开计划）**：给 AI 新变化/新文档，或产品在平台确认并给新说明/附件 → `测试/变更/CR-*.md` 影响分析 → 按 CR §5 更新资料/计划/用例/脚本/报告/索引 → P0 冒烟 + 变更用例 + 影响面 → 报告/验收。A 澄清/B 同范围增量不重开计划门；C 实质变更回计划门；D 缺陷走缺陷轨；产品确认带新 AC → D+B/D+C。**执行时机默认等计划模块/阶段位；提前仅限 P0/高风险、阻塞后续、独立且数据/入口就绪、有专门含变更构建；P0 冒烟可在构建/阶段边界先跑；执行前核构建含变更；产品确认新 AC 按新 AC 回归。**  

计划驱动执行覆盖本包可执行轨道；单元/静态、UAT、灰度/生产验证由对应团队执行或协调，计划登记责任人与证据，不冒充已测。  


## 4. 自检


## 5. 宿主适配（宿主无关）

本包不写死任何宿主（Cursor / opencode / Claude Code 等均可）；换宿主只改实例侧（`环境基线.md`），包零改动。

- **最低能力**：入口自动装载（AGENTS.md 或等价）、文件读写、shell、对话式确认门（hitl）；浏览器自动化按需（功能/探索式轨必需）、子代理（分片/核验，按 `规则/专项/多Agent与输出.md` §1.5 阈值取档）。  
- **入口挂载**：AGENTS.md 系宿主按 `规则/模板/00-接入与基线/根AGENTS薄指针.md` 挂载；CLAUDE.md 系可用 @ 引用指向本包 AGENTS.md。
- **MCP 配置落点**：只写宿主本地/用户级配置（如 Cursor：`%USERPROFILE%\.cursor\mcp.json`；路径以宿主官方文档为准）；实例绑定值填 `环境基线.md` §8.1；禁项目内配置作规范入口。
- **能力（可选）**：外部技能/工具按 `能力/00-能力注册表.md` 选装（技能类走宿主技能目录/插件市场——通用 skills CLI 可跨宿主；MCP 类写宿主本地/用户级配置）；**已安装即启用**、未安装=降级不阻塞；可用性自动记录于 `环境基线.md` §17（无需人工填写）；增强能力**首次缺失提示一次**（记档后静默）；点名「装配能力」可展开完整清单与安装建议。  
- **体检能力**：口令「体检能力」等 → `workflows/skill-audit.yaml`：对照项目（或「通用优化技能」）检查能力 + 随包技能；确认后可就地改本包（无需母版仓）。
