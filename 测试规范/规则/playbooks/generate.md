## 2. 分级

| 级别 | 典型 | 计划 | 生成 |
| --- | --- | --- | --- |
| T0 补丁/热修 | 小改、单模块 | 轻量计划（≤1 页） | **打开命中域增量**；无域则按域首生 |
| T1 模块 | 功能/模块 | 轻量计划 | 命中域增量 + 接口（如适用） |
| T2 版本 | 发布级 | 完整计划 + §3.7 装填 | 命中域增量；发版可 depth/suite=full |
| T3 高风险 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 命中+邻接增量；安全维不可静默剔除 |

T0/T1 不强行填完整模板；但范围、类型、轨道、**装填矩阵**、准出、风险必须写清。

## 3. 流程卡

1. **analyze**：主读判定（点名路径 > 唯一正式版 > 计划已登记 > 否则一问）；多份须主读+对照；冲突不静默选边（可用户声明冲突SSOT）。仍出 **测试分析表**（`测试/测试分析表.md`，模板见 `10-计划/测试分析表模板`）。影响源：提测单若有→CR→主读 diff→用户点名。禁整步空过；关键歧义未裁决先问。
2. **plan**：双读「主读原文 + 测试分析表」；填 §3.7 装填；有前序/GATE 写依赖版 P0-Smoke；理解未确认不得计划已确认。
3. **generate**：**双读原文 + 测试分析表**（以分析表覆盖单元/影响面/oracle 为生成清单，原文核证据）→ 只处理命中域增量（保 caseId）；无域首生；缺分析表先回 analyze。**禁**无分析表整版重生；**禁**「继续」触发 generate。同域无效合并≥2 → 有界重生。
4. **覆盖三闸**（功能命中域/专项）：对本期命中域+邻接影响面『一遍过·宁多勿漏』（宁可多、不要缺；≠全仓重生）。① 可测承诺；② 映射无空行 + 深度档；③ 缺口三分类。拿不准多生成，禁瘦映射凑齐。细则 `工作流.md` §2.1.0。跑 `-Mode coverage`。
5. **用例质量（生成自检）**：
   - **功能**：独立可执行、前置三件套、步骤四列；§1 总览可导航；评分卡 ≥18/20；`validate_testcase.py`。
   - **接口**：契约表+对照禁空+请求要点+判定三要素；评分卡 ≥18/20；`validate_api_testcase.py`；禁套功能模板。
   - **探索式/随机**：对照各自模板；步骤四列+判定面；探索须章程映射（计划驱动）；随机须占比自检。
   - **自检不替代独立评审**。
6. **脚本判定**：P0-Smoke/核心闭环 → 同轮脚本；接口按 depth（迭代 `standard`=适用维全可脚本；发版 `full`；补丁才 `core` 仅高风险维）→ 同轮 API 脚本；其余默认 AI；一次性不脚本。
7. **review-cases**：T1+ 功能强制；接口 T1+ 或进准出强制（量规见 `testcase-review` §3.1）；探索计划纳入且 T2+ 强制。放行后才进 execute/P2。需修 → 回 generate → 重审≤1。T0 可 SELF_CHECKED。
8. **收尾**：生成收尾写增改删表 + 映射/条数；独立生成有拟入库 → 门3；同会话续执行 → 先评审再执行，门3 留 report。

## 4. 红线

- 禁臆造路由/接口/按钮；禁空泛「已全覆盖」；禁无深度档自检宣称覆盖闸通过。
- 禁无分析整版/全仓重生；禁把「一遍过」做成全库重写；禁并行写同一正式域文件（分片只写 `.draft`）。
- 方案/GEN/TP 已写「前置与操作」→ 用例入口/步骤须落该动作原文；步骤详细度按 `testcase-design` §5 基线。
- 每条用例可追溯到 RQ/AC/F/R/TP/`GATE/REL/§` 或页面/接口来源；预期不按现网反推；P0/GATE 无对应用例=覆盖缺口。
- 主读已点名不免除测试分析表；小任务不豁免覆盖闸（功能命中域/专项）；禁只读原文跳过分析表。
- 探索式/随机业务流程/接口/发布前按各自契约，不套功能三闸；随机业务流程禁止写入测试计划。
- 大规模生成：≥3 模块且（预估≥40 条或用户点名）→ 分片写 `.draft`（不相交可并行≤3）；编排合并；超时/空产物→降级直做（多Agent §1.5.4）；**禁**并行写同一正式域文件；开跑声明 `mode=`。
- 生成写手不得自审自放行；T1+ 功能未过评审闸不得进 P2。
- 旧 `{NN}` 包视为 L1，不强制重编号。

## 5. 资产文档形态（AI 实操 · 与市面 change-scoped / project-wide 对齐）

| 阶段 | 测什么 | 文档怎么长 |
| --- | --- | --- |
| **首版/冷启动**（PRD/方案/原型首次） | project-wide：范围内模块全抽覆盖单元 | 每业务模块 **1 份**用例 + **1 份**台账；计划 1；**测试分析表** 1；冒烟清单 1；有接口则接口域文件；探索/发布前按计划选「是」才建 |
| **新迭代**（主读变更） | change-scoped：命中+邻接宁多勿漏 | **默认打开已有模块文件增量**（增/改/淘汰/rerun）；新模块才**新增** `{NN}-{模块}测试用例.md`；大改可有界重生该域；禁每版平行新开整套 |
| **执行选例** | 读计划 §0 suite + §3.7 装填域 | 只跑装填行列出的域/条；Core 无条件；有文件≠本轮跑 |

**分类（写入用例/矩阵）**：按优先级 P0-Smoke / P0-HighRisk / P1-Core / P2-Low；按类型 功能/接口/探索/发布前；按层 L0 Core / L1 域常青 / L2 本版增量。  
**必用技能链**：`test-basis-analysis`（建模）→ `test-analysis-and-plan`（计划/装填）→ `testcase-design`（技法+深度）→ `testcase-review`（放行）→ 执行选 `test-execution-and-exploration`（+ 接口/性能等按轨）。  
**充分性底线**：每 P0/GATE ≥1 主路径+≥1 失败/阻断；有状态≥1 非法跃迁；有输入≥1 边界；跨角色≥1 越权或接受不测；影响面逐邻接点落映射——对齐市面「claim×hypothesis 覆盖矩阵 / blast radius」思路，落在本仓 GATE/AC 映射上。
