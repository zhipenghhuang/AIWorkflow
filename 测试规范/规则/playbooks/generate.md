## 2. 分级

| 级别 | 典型 | 计划 | 生成 |
| --- | --- | --- | --- |
| T0 补丁/热修 | 小改、单模块 | 轻量计划（≤1 页） | **打开命中域增量**；无域则按域首生 |
| T1 模块 | 功能/模块 | 轻量计划 | 命中域增量 + 接口（如适用） |
| T2 版本 | 发布级 | 完整计划 + §3.7 装填 | 命中域增量；发版可 depth/suite=full |
| T3 高风险 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 命中+邻接增量；安全维不可静默剔除 |

T0/T1 不强行填完整模板；但范围、类型、轨道、**装填矩阵**、准出、风险必须写清。

## 3. 流程卡

1. **analyze**：主读未点名 → 列候选+建议，一问选定；已点名 → 仍出需求模型/轻量分析短表。影响源优先级：提测单（若有）→ CR → 主读 diff → 用户点名。禁整步空过；关键歧义未裁决先问，不猜。
2. **plan**：版本级/首版 → 完整计划；小任务 → 轻量计划；填 §3.7 装填（suite + 命中域 + 增改删/rerun）；有前序/GATE 依赖时写入依赖版 P0-Smoke；计划门仅实质变更时停。
3. **generate**：按 §3.2 + §3.7 **只处理命中域**；有域文件 → 锚点增量改（保 caseId）+ 产出增改删表；无域 → 按域首生（冷启动）；缺计划先轻量补；缺主读先门1。**禁**无分析整版重生；**禁**「继续」触发 generate。同域无效合并≥2 次 → 有界重生（快照归档后整域重生）。
4. **覆盖三闸**（功能命中域/专项）：对本期命中域+邻接影响面『一遍过·宁多勿漏』（宁可多、不要缺；≠全仓重生）。① 可测承诺；② 映射无空行 + 深度档；③ 缺口三分类。拿不准多生成，禁瘦映射凑齐。细则 `工作流.md` §2.1.0。跑 `-Mode coverage`。
5. **用例质量（生成自检）**：每条独立可执行、前置三件套齐、步骤四列齐全；模块头 §1 总览索引可导航；评分卡 ≥18/20。**自检不替代独立评审**。
6. **脚本判定**：P0-Smoke/核心闭环 → 同轮脚本；接口确定性高风险维 → 同轮 API 脚本；full 维懒生成或发版补；其余默认 AI；一次性不脚本。
7. **review-cases（主链强制 · T1+ 功能）**：独立角色按 `技能/testcase-review`；放行后才进 execute/P2。需修 → 回 generate → 重审≤1。T0 可 SELF_CHECKED。
8. **收尾**：生成收尾写增改删表 + 映射/条数；独立生成有拟入库 → 门3；同会话续执行 → 先评审再执行，门3 留 report。

## 4. 红线

- 禁臆造路由/接口/按钮；禁空泛「已全覆盖」；禁无深度档自检宣称覆盖闸通过。
- 禁无分析整版/全仓重生；禁把「一遍过」做成全库重写；禁并行写同一正式域文件（分片只写 `.draft`）。
- 方案/GEN/TP 已写「前置与操作」→ 用例入口/步骤须落该动作原文；步骤详细度按 `testcase-design` §5 基线。
- 每条用例可追溯到 RQ/AC/F/R/TP/`GATE/REL/§` 或页面/接口来源；预期不按现网反推；P0/GATE 无对应用例=覆盖缺口。
- 主读已点名不免除轻量分析短表；小任务不豁免覆盖闸（功能命中域/专项）。
- 探索式/随机业务流程/接口/发布前按各自契约，不套功能三闸；随机业务流程禁止写入测试计划。
- 大规模生成 ≥3 模块且 ≥40 条才分片；单模块直做；不并行写同一文件。
- 生成写手不得自审自放行；T1+ 功能未过评审闸不得进 P2。
- 旧 `{NN}` 包视为 L1，不强制重编号。
