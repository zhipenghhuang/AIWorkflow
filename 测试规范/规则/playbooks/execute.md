## 2. 执行卡

1. **门2/预授权**：计划已确认且「按计划执行」→ 跳过门2 +【已预授权执行：按计划】；否则一行确认。
2. **装填行**：出示 **runId/构建** + suite/depth + 命中域 + next + **`mode=`**（脚本|直跑|模块子代理|拆分，对照多Agent §1.5.1）。「继续」只续装填；单域继续→直跑合法。
3. **开跑新鲜度**：装填内→`未执行`；装填外→`未本轮验证`。台账路径：`…/{NN}-{短名}/*-功能台账.md` 或 `*-接口台账.md`。
4. **数据一次造齐** → **core 冒烟（脚本优先）** → 全绿进 module/full；冒烟红按多Agent §1.1.1 分流。
5. **装填域逐条跑**；按 mode 取档（≥2 域同轮→模块子代理；隔离套可并行≤3，见 §1.5.3）；超时/空返回→降级直做（§1.5.4）；一条一写台账（写 `验证构建`）；截图即视觉检。
6. **异常**：走 `技能/test-execution-and-exploration` §0 现场处置表（取证→归因→处置→继续）；脚本 fail 有界复核 1 次；blocked 四问。
7. **回归**：原单+冒烟+影响面组（默认纳入）；缺陷策略见缺陷协作 §6.1；结果就地覆盖本轮行。
8. **收尾**：`execute -Scope {域}`；汇报只用 §1.1 本轮计数；准出：迭代≥module、发版=full；报告声明 suite + 本轮实测。

**高效要点**：能脚本不 MCP；同页一次侦察多次操作；同方案无效 2 次换手段；可自主（造数/换样/修脚本漂移/绕过独立面）先做完再问；不可让（密钥/改预期藏 bug/换载体/静默降范围）必停。

## 3. 红线

- 先 UI 再 Network；禁猜未见 API 判失败；仅 list 探活不得判 fail。
- **禁换验收载体**：按用例/方案已点名动作走 UI→同源 Network；难测不得改打「同类」其它批量/写接口；载体入口缺失→待实现/fail，不猜替代 API。
- 台账「执行通道」以**登记取值**为准（常见：`AI-MCP`｜`脚本档`｜`混合`，非穷尽）。未知通道 → **就近映射**到登记取值并写 `deviation=`（手段/差异一句）；**禁止**因标签未列出拒执行。有 UI 入口却冒充纯 API 终态仍违规（与禁换验收载体一致）。
- 口径待探查=钉本载体字段/实现值，≠换功能点。
- UI 文案减法与视觉六项见工作流 §2.1.0；禁「先功能后视觉、截图不看界面」。
- 缺数据/缺样本先造/换样，≠blocked；方案/AC 范围内未实现→`待实现（实现缺陷）`；blocked 四问任一未过不写 blocked。
- 本批未终态齐（停轮/用户中断除外）禁【执行收尾】与拟提交清单。
- 禁抬高通过率；禁改断言/跳测试凑绿；失败必须留证。
- 已脚本化用例回归必须走脚本档；脚本通过不采信退出码。
- 不跨轨通读；不静默降范围；**不把 `未本轮验证`/库内旧通过算进本轮通过率**；计划实质变更回计划门。
- 安全/P0 不可因「精准选测」静默剔除；装填内 P0 不得留在 `未本轮验证`。
