## 2. 流程卡

1. **classify**：识别子类（提交/回归/修改/查重/列表/巡检/澄清/产品回流）；未点子类先 LIST 再一问。回归默认指派给我·未关闭（含打开/已解决）；巡检=我提交/关注，只读变化，不默认回归。
2. **search**：提交前查重；回归/巡检拉单读 status/resolution/assignedTo/resolvedBuild/actions/files/lastEditedDate，按 §7.3 快照 diff；api 读不全 → browser → 请用户补；禁只看标题。
3. **submit**：
   - 新建单：提交策略以 `规则/缺陷/缺陷协作.md` §6.1 为准（计划 §11）；批末/阶段末/收尾确认类走 `confirm_commit`（platform_submit）。
   - 回写/关闭/激活/标重复/补充澄清：`confirm_remark` 先出 id+备注全文。
   - 建单十段齐；标题 `[V版本?][测试类型]`+正文；证据 ≥1 张钉断言点；产品缺陷带相符证明+证据，直接指派产品，不经开发。
   - 备注与状态同轮；写后 §8.7 回查；附件回查挂载；失败重试 ≤1；无权限走 export。
   - **通道互斥**（`协作与交接.md` §3.1.1）：已交平台 → **不**发包，只回写单号；无平台/`export`/点名「缺陷交接包」→ **先问后发**，确认后再 `handoff.send`。任何 HO 包禁静默生成。
4. **wrap**：输出提交/回归结果块 + 收尾（对照 `收尾骨架` §2）；`confirm_remark` 包末必有【拟写回·底部摘要】（无类省略）；写回后「完成了什么」含动作+单号，禁空话；有拟入库才 `confirm_commit`；本轮用浏览器 MCP → 按多Agent §2.2 全链终局退程。回归后若建议 `FIX` 包 → 先问，确认才发。

## 3. 红线

- 禁臆造步骤/路由/接口；提交 steps 同源台账十段，禁三段式空壳。
- 禁只看标题分析；禁未查重建单；禁无证据提交。
- 拟提交前对照 oracle 原文：空成功无状态变化、契约未对齐、或测到前置缺口却写成另一断言 → 弱证据/改题，**默认不进清单**。
- 产品缺陷无相符证明不得标产品缺陷；非问题/重复/信息不足给排除依据。
- 禁删缺陷；禁把测试内部资产/路径/脚本/内部分类写进平台备注。
- 禁抬高通过率；禁脚本失败未经复核直接交平台。

## 4. 输出

平台单号/备注全文/提交汇总块/回归结论；收尾按 `规则/模板/90-交接与收尾/收尾骨架.md`。
