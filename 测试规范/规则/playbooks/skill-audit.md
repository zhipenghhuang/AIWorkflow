# 能力与技能体检（测试轨）

> **读取级别：参考**。仅 `workflows/skill-audit.yaml` 或点名体检时读；业务任务不读。  
> **定位**：盘点**实例能力** + 检查/优化随包技能。  
> **改哪里**：能力 → 只改 `测试/能力/`；技能 → 确认后可改本包 `技能/`。点名「通用优化技能」时技能按通用最优（不绑项目）。

## 1. 模式

| 模式 | 触发口令（例） | 对照基准 | 改什么 |
| --- | --- | --- | --- |
| **project** | 体检能力 / 能力优化 / …（且有项目对照物） | `测试/能力/`、环境基线索引、T0～T3、轨道、近期门失败/降级、用户目标 | `测试/能力/`；本包 `技能/`；基线 §8/§17 仅刷索引 |
| **generic** | 含「通用」「不按项目」「通用最优」；或无填实基线/清单 | 契约+参考目录、技能完整性/映射；**禁止**写死环境特例 | 可改包内技能；**不**把某项目选型写进包契约当真源 |

**模式判定**：口令含「通用/不按项目/通用最优」→ generic；否则无填实基线且无 `测试/能力/00-能力清单.md` → **强制 generic**；有填实清单或基线 → project。

## 2. 流程

1. **scope** → 2. **inventory**（`测试/能力/00-能力清单.md` + 契约/参考目录 + `技能/README` 映射；抽查 frontmatter；禁通读全部 SKILL）→ 3. **fit** → 4. **propose** → 5. **apply**（`confirm_skill_changes`）→ 6. **wrap**。

## 3. 建议卡

```text
ID / 对象（能力名 | 技能/<name>）
现象：与基准的差（证据：清单行 / 门失败 / 计划缺口 / 用户目标）
判定：缺装 | 达不到要求 | 过重 | 过时 | 重复 | 映射断裂 | 可维持
动作：装配能力 | 改测试/能力/ | 就地改 SKILL.md | 改技能 README 映射 | 维持+降级可接受
优先级：P0 / P1 / P2
成本：安装 · token · 维护
```

## 4. 可执行动作（确认后）

- **外部能力**：安装/绑定步骤；写入 `测试/能力/`（清单/槽位/绑定/装配笔记）；刷基线 §8/§17 索引。可续「装配能力」。  
- **随包技能**：就地改 `技能/<name>/SKILL.md` 与 `技能/README.md`。  
- **包契约/参考目录**：仅当通用缺口且用户确认回灌母版时改 `测试规范/能力/`；默认改实例。  
- 改包后跑 `规则/tools/Invoke-TestWorkflow.ps1 -Action ValidateTemplateRefs`。

## 5. 纪律

- 未 HITL 零改动。装配=安装向导；本流程=诊断+优化。  
- 能力正文 SSOT=`测试/能力/`；他处只索引。  
- generic 禁止环境硬编码；一次会话只体检本包。
