# 能力与技能体检（测试轨）

> **读取级别：参考**。仅 `workflows/skill-audit.yaml` 或点名体检时读；业务任务不读。  
> **定位**：盘点外部能力 + 检查/优化随包技能；可按项目适配，也可按通用最优（不绑具体项目）。  
> **包可独立落地**：本包目录内的 `技能/`、`能力/` **允许在用户确认后就地修改**；点名「通用优化技能」时按通用最优（不绑具体项目）。

## 1. 模式

| 模式 | 触发口令（例） | 对照基准 | 改什么 |
| --- | --- | --- | --- |
| **project** | 体检能力 / 能力优化 / 技能优化 / 优化技能 …（且存在项目对照物） | 环境基线、T0～T3、轨道、近期门失败/降级、用户目标 | 本包 `技能/`、`能力/`、基线可用性节；可装配外部能力 |
| **generic** | 含「通用」「不按项目」「通用最优」；**或**无项目对照物 | 行业/开源 QA 实践、能力表主选备选、技能完整性与冗余、映射覆盖；**禁止**写死某环境特例 | 同上；保持可复用 |

**模式判定（必守）**：口令含「通用/不按项目/通用最优」→ generic；否则无填实 `环境基线.md`（占位未换=无）→ **强制 generic**，报告写 `mode=generic（无项目对照自动）`；有填实基线 → project。禁无对照时空喊「缺基线无建议」——改做通用完整性/映射/能力表分析。

## 2. 流程（与 YAML 步对齐）

1. **scope** → 2. **inventory**（能力表 + 基线 §17 + `技能/README` 映射；抽查 frontmatter；禁通读全部 SKILL）→ 3. **fit** → 4. **propose**（体检报告）→ 5. **apply**（`confirm_skill_changes`）→ 6. **wrap**。

## 3. 建议卡（每条必填）

```text
ID / 对象（能力名 | 技能/<name>）
现象：与基准的差（证据：基线§ / 门失败 / 计划缺口 / 用户目标）
判定：缺装 | 达不到要求 | 过重 | 过时 | 重复 | 映射断裂 | 可维持
动作：装配能力 | 改能力表 | 就地改 SKILL.md | 改技能 README 映射 | 维持+降级可接受
优先级：P0 / P1 / P2
成本：安装 · token · 维护
```

## 4. 可执行动作（确认后）

- 外部能力：安装/绑定步骤；可续「装配能力」。  
- 随包技能：就地改 `技能/<name>/SKILL.md` 与 `技能/README.md`。  
- 能力表：更新本包 `能力/00-能力注册表.md`；表外新源先登记。  
- 基线：回写 `环境基线.md` §17。  
- 改引用后建议跑 `规则/tools/Invoke-TestWorkflow.ps1 -Action ValidateTemplateRefs`（或包内等价自检）。

## 5. 纪律

- 未 HITL 零改动。装配能力=安装向导；本流程=诊断+优化。  
- 业务轻量建议见 `AGENTS.md` 技能节；深度只在本 workflow。  
- generic 禁止环境硬编码；project 允许裁剪。一次会话只体检本包。
