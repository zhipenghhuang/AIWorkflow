# 文档治理（资料 + 工作文档）

> 单一出处：入站意图分析、资料/工作区分流、覆盖对照、受影响同步、归档与清理。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/清理**；未确认前只读。
> **单包优先**：仅本包即可闭环；缺产品/开发包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。多包时共用根级**原始资料根**与交接直读，放入≠分发。
> **反堆积**：确认采纳且 S1/S2/S3 → **同批**失效归档（仅包内 `资料/_归档/` 与工作区归档）；用例/台账/报告就地覆盖只留最新；禁止「只落位、等关版本再清」。根级原始资料根**不归档、不迁出主副本**。
> 安全：**现行**证据（本轮门回执/仍被报告引用的失败实拍）、当前计划/报告、源文件、用户文件、密钥、`.git` 永不自动删除；**过期运行态**（`.gate/测试规范/` 下非 JSON 媒体、过期 logs 等）视为临时/过程，可进清理候选；拿不准 → 待确认或移 `测试/_归档/_待清理/`（仅跨轨临时，不含各轨资产与资料）。
> **`.gate` 落点**：`.gate/测试规范/` 只写 JSON 回执；失败实拍按轨契约进 `测试/**/证据/`，不堆进 `.gate/{包名}/`。

## 1. 三个区

| 区 | 放什么 | 不放什么 |
| --- | --- | --- |
| **原始资料根**（推荐 `docs/`） | 项目外部/用户投放的**原始输入主副本**（永久保留） | 本包活文档、包内归档 |
| `测试/资料/` | 本包所需原始输入的**副本**、只读证据、测试数据 | 计划/用例/台账/报告/脚本/证据等**工作产物** |
| `测试/` 各轨 | 本包工作产物 | 外部原件主副本（在原始资料根） |

- **工作文档根（硬）**：本包必须有 `测试/`；新产物只落此处。
- **原始资料根（硬）**：项目根级，单包与多包**同一语义、共用一份**。推荐名 `docs/`；若已有其它名 → 登记实际路径并引用，不强制改名。无现成目录 → 接入时默认建 `docs/`。
- **主副本规则**：原始资料根内文件**一律视为项目原始资料**——**禁止迁出**；只做索引、按需复制、按需吸收（含引用）。新文档入库须先在此留主副本。跨包只引用；放入 ≠ 自动跑他包。
- **资料模式**（只约束原始资料根内部结构；**不**禁止复制/吸收）：

| 模式 | 对原始资料根 | 仍允许 |
| --- | --- | --- |
| `keep` | **结构保持不动** | 建/更新索引；按需复制；按需吸收/引用 |
| `mix`（默认） | **只添加整理** | 同上 |
| `replace` | **完全重整**（方案确认后执行；须修引用） | 同上 |

  均须可查可引。不强制对齐包内 `资料/` 树。
- **认根**：用户指定优先；否则按 §2.1 判定表；**不确定必须问用户**。
- **工作产物不回写资料**。
- **版本记录**：根 CHANGELOG 仅开发维护；本包只写 `测试/工作日志.md`。

## 2. 原始资料根与包内资料

### 2.1 原始资料根（无归档 · 不迁出）

```text
docs/                            # 或档案登记的其它原始资料根路径
├─ 资料索引.md                   # 必有：全量可查可引
└─ …                             # 子目录由实况决定
```

**认根判定表**（用户未指定时；冲突/多候选 → 问用户）：

| 优先 | 线索 | 倾向 |
| --- | --- | --- |
| 1 | 用户点名 | 采用该路径 |
| 2 | 根下 `docs/` 且主要为文档 | `docs/` |
| 3 | 唯一明显大文档夹（根级 `文档/`、`项目文档/`、`资料/` 等，非包内） | 该夹 |
| 4 | 多候选或以代码/配置为主 | **停问** |

- **禁止**：原始资料根建 `_归档/`；禁止把其中文件**迁移**到 `测试/` 工作产物区；禁止为对齐包内树强制改结构。
- **中途存量（硬）**：**索引全登记**；**不**默认全量复制/吸收；按任务/版本需要分批；可长期仅索引。
- **三档处置**：

| 档 | 做什么 | 何时 |
| --- | --- | --- |
| **索引** | 写入 `{原始资料根}/资料索引.md` | 默认；存量必做 |
| **复制** | 复制进 `测试/资料/`（本包树）；原件不动 | 本包常读/证据/测试数据需要 |
| **吸收** | 见 §2.3；原件不动 | 计划/分析表/用例需要 SSOT 或稳定引用 |

- **入站通道**：① 直接放；② 根散落 → 先收入；③ 对话/附件 → 先落盘。确认前只读分析（落盘保原件除外）。

### 2.2 包内 `测试/资料/`（按需副本 · 可归档）

```text
测试/资料/
├─ 资料索引.md
├─ _通用/
├─ {版本或主题}/
├─ 测试数据/
├─ 交接/{HO-ID}/
└─ _归档/{yyyyMMdd}-{版本或批次}/
```

- **禁止**：新建 `项目文档/`；禁止强制类型前缀扁平；禁止新资料长期平铺 `资料/` 根。
- 设计输入（环境基线 §2.1）= 原始资料根 + 按需的 `测试/资料` 副本/测试数据。
- 失效副本 → `资料/_归档/`；不影响原始资料根。

### 2.3 吸收深度（实用）

> **吸收 ≠ 迁移**。原件永远留在原始资料根。

| 深度 | 工作区动作 | 适用 |
| --- | --- | --- |
| **R0 引用** | 计划/分析表/索引写来源路径 + 用途一句 | 查阅、非本轮装填 |
| **R1 要点吸收** | 相关范围/AC/风险写入分析表或 CR；挂原件链接 | 计划门前、专项增量 |
| **R2 结构吸收** | 更新计划范围/准出/矩阵或分析表结构化节；`来源=` 原始路径 | 版本级计划、准出入口 |

- **默认**：存量→索引；任务命中→至少 R0；改计划/生成用例依据→R1 或 R2（不确定取低档并问一次）。
- **禁止**：整文件挪进 `测试/` 冒充吸收；禁止搬空原始资料根。
- **SSOT**：计划/用例/报告为准；原件溯源。冲突→T8。

## 3. 入站意图分析

输出：`类型 | 落点 | 同步 | 归档/覆盖`。

**先判替代关系**：T1 才归档旧基线；T2/T4 保留未被覆盖的设计输入/测试数据/稳定冒烟清单，只归档被替代的用例轮次与报告。

| 类型 | 线索 | 落点 | 本包同步 | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 整版新 PRD/计划废止 | 主副本留/落入原始资料根；按需复制；R1/R2→计划现行 | 计划指针、索引、用例影响面 | 包内副本可 `_归档`；计划快照；原始资料根不动 |
| T2 方案/设计变更 | 方案/原型变更 | 原件留根；建/更 `变更/CR-*` | CR §5 指针 | 就地覆盖受影响用例结论 |
| T3 未决确认 | 口径拍板 | 结论→CR/计划/断言；原件留根 | 分析表假设清除 | 过程件不进现行 SSOT |
| T4 迭代专项 | 修改方案、S-NN | 原件留根；专项包 + 台账 | 专项索引、计划追加节 | 停用专项标停用 |
| T5 范围/优先级 | 砍测、调准出 | 计划范围/准出节 | §0/矩阵 | 旧范围通知工作区侧可归档 |
| T6 缺陷/回流 | 平台结论、修复说明 | 原件可留根；缺陷轨 | 回归范围、台账 | 不把用例整包误丢根 `_归档` |
| T7 仅参考 | 无强制 | 索引=`参考`；默认可不复制 | 一般不改用例 | — |
| T8 冲突 | 未裁决 | `待确认` | 停下问 | 不改现行断言 |
| T9 交接包 | HO-ID | 多包直读；仓外按接收 | 计划/台账 | 发出包不可改 |

C0～C3 同协作。SSOT=计划/用例/报告（R1/R2）或挂引用（R0）；不是把原件挪进 `测试/`。

## 4. 资料收取步骤

1. 识别变化（原始资料根优先全量索引；`测试/资料/`；根散落先拟收入）→ T1～T9 + 建议档位。
2. 输出候选；确认前不改文件（新件落盘除外）。
3. **确认后同批**：主副本留/落入原始资料根并登记 → 仅对需要的文件复制进 `测试/资料/` → 按深度吸收 → S1/S2/S3 只动包内副本 → 更新索引/计划/报告/activeContext。原始资料根不迁不删。
4. 中途存量：先全索引；未点名复制/吸收的保持仅索引。部分/参考保留；冲突→T8。

覆盖关系与 S1～S5 同他包。禁按年龄归档。失效只作用于包内副本与工作区，不删除原始资料根主副本。

## 5. 工作文档四类

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `环境基线.md`、`activeContext.md`（含 `### 进行中` 快照）、`测试/测试计划.md`、`测试/测试报告.md` | 长期/当前 | 就地更新；关闭时计划/报告**快照**到 `测试/_归档/{yyyyMMdd}-{版本}/`，当前档不移动 |
| `测试/工作日志.md` | 长期 | 过长确认后移块到 `测试/_归档/工作日志/` |
| `测试/00-稳定冒烟清单.md`、可复用脚本 | 长期 | 保留/更新 |
| `测试/功能测试/` | **域常青** | 主档跨版本保留/增量更新；关闭时**不**整轨搬走。轨内 `_归档/` 仅：下线域、有界重生快照、代谢淘汰的僵尸 L2 |
| `测试/接口测试/` | **域常青** | 现行就地增量；轨内 `_归档/` 仅点名旧轮/重生快照/下线域 |
| `测试/探索式测试/` | 绑定轮次 | 点名旧轮 → 轨内 `_归档/`（探索轮本就按戳成对） |
| `测试/随机业务流程测试/` | 绑定（计划外） | 点名旧轮 → 轨内 `_归档/`；不进计划/报告准出归档链 |
| `测试/发布前测试/{专项}/` | 矩阵常青 + 轮次 | 专项矩阵/方案常青就地更新；停用包/旧轮 → `{专项}/_归档/` |
| `测试/变更/CR-*` | 绑定 | 关闭 → `测试/_归档/.../变更/` |
| `测试/交接/{HO-ID}/` | 快照 | 不可改；关闭 → `测试/_归档/.../交接/`；台账常青 |
| `**/.draft/` 等 | 临时 | 清理候选（确认后删或 `_待清理/`） |

**执行入口**：是否仍在当前计划 **装填范围**（§3.7 / suite）内执行。库内有文件 ≠ 本轮必跑。用例/台账/报告：**就地覆盖，只留最新结论**。

> **禁**：把功能/接口/探索式/随机业务流程/发布前**仍有效主档**整包丢进 `测试/_归档/` 根或轨内归档。根 `_归档` 只收计划/报告/CR/交接快照与 `_待清理`。  
> **既有实例**：旧 `{NN}-*` 包视为 L1 现行，关账后仍留原位；不强制重编号。

## 6. 更新还是归档

局部 → 就地覆盖（保 caseId）。T1 资料失效归档 + 计划快照。T4 专项增量，停用/沉淀后归档专项文件（沉淀进域主档的条不归档）。版本关闭 → §7（**计划/报告快照；用例主档留下**）。正式资产只写现行有效。

归档前做**引用检查**：被当前计划/用例/脚本/报告引用的设计输入、测试数据、稳定冒烟清单、**域主档**不得标记失效；先修引用或保留原位。归档清单写明“替代关系/仍被谁引用”。定期代谢：无引用且连续 ≥2 版未装填的纯 L2 僵尸 → 候选淘汰（确认后轨内归档）。

## 7. 版本/迭代关闭（换迭代 = 关当前版进入下一版）

> **迭代即版本主题**：换下一期方案/新版本目录 = 结束当前迭代并开下一迭代。与「正式发布上线」**不是两套清理标准**——分类、计划快照、失效资料、临时清理、索引/链接同一套；差别只在是否做**发版对外项**。**用例域主档常青，不随换代整轨归档。**

### 7.1 关账清单（按实际裁剪，不是少做）

> **关账前置**：先按 §3 判 T1/T2/T4。T1 全量替代才归档旧基线资料；T2/T4 增量/局部，保留仍被引用的设计输入、测试数据、稳定冒烟、**功能/接口域主档**；只快照计划/报告与已关闭 CR，并对下线域/淘汰条做轨内归档。

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分析分类：长期/版本绑定/失效替代/过程临时 | 必做 | 必做 |
| 更新计划/台账/索引/activeContext（含下一迭代装填指针） | 必做 | 必做 |
| 计划/报告/已关闭 CR/交接 → 根 `_归档/{yyyyMMdd}-{版本或迭代}/`；**功能/接口域主档留下**；仅下线域/重生快照/淘汰 L2 → 轨内 `_归档/` | 必做（已确认结束的） | 必做 |
| 失效资料 → `资料/_归档/` + 清单 | 必做 | 必做 |
| 临时/过程/失败/重复清理 | 必做 | 必做 |
| 修断链 | 必做 | 必做 |
| 测试报告准出对外 / 根 CHANGELOG | **跳过**（除非点名关报告发版） | 按报告/准出门 |
| 平台回写收尾 | 按缺陷策略 | 按缺陷策略 |
| 沉淀审计：本版 L2 择优并入 L1；僵尸 L2 候选淘汰 | 建议 | 必做（发版） |

### 7.2 确认结束当前迭代（不确定必问）

出现下一期方案/换主题/版本号升级，但当前迭代是否算结束不明确（例如仍在缺陷回归、提测未结）→ **STOP** `confirm_iteration_close`：出示「当前迭代标识、未完成项、拟归档摘要、下一迭代标识」→ 用户确认「结束当前并进入下一」后才执行 §7.1；用户说「并行不关」→ 只落新资料、不归档现行绑定主档，收尾记假设。

用户已明确「下一期 / 换版本 / 关这期」→ 按已确认执行，不重复空问。

### 7.3 触发（自动探测 · 同会话）

1. 新迭代/版本文档确认采纳（materials / testing.plan 期中变更）且判定换代，或用户确认结束当前
2. 换主题目录 / 版本号升级 / 计划范围换代
3. 正式发版/结项口令
4. 点名整理/巡检/清理（可只做清理子集，仍先分析分类）

未确认零移动；现行证据/现行主档/密钥永不自动删。

## 8. 过程/临时清理

扫描 `测试/` 与项目根顶层（含 `.gate/`）；不确定 → `测试/_归档/_待清理/`。候选：已完结 `.draft/`、tmp/bak/log、副本、未引用导出；过期运行态（`.gate/测试规范/` 非 JSON 媒体、`.gate/logs`）；进行中 draft、现行证据/计划/报告禁动。细则与点名清理口令见 `规则/工作流.md` §1.3。

**何时扫清理**：点名整理/巡检/清理（lifecycle）；或换迭代/关版本并入 §7.1。日常任务收尾不主动列清理、不追问。不另立「轻量卫生」标准。
