# 文档治理（资料 + 工作文档）

> 单一出处：入站意图分析、资料/工作区分流、覆盖对照、受影响同步、归档与清理。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/清理**；未确认前只读。
> **单包优先**：仅本包即可闭环；缺产品/开发包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。多包时可用 `项目资料/` 与交接直读，放入≠分发。
> **反堆积**：确认采纳且 S1/S2/S3 → **同批**失效归档；用例/台账/报告就地覆盖只留最新；禁止「只落位、等关版本再清」。
> 安全：证据、当前计划/报告、源文件、用户文件、密钥、`.git` 永不自动删除；拿不准 → 待确认或移 `测试/_归档/_待清理/`（仅跨轨临时，不含各轨资产与资料）。

## 1. 两个区

| 区 | 放什么 | 不放什么 |
| --- | --- | --- |
| `测试/资料/` | 外部设计输入、只读证据、测试数据 | 计划/用例/台账/报告/脚本/证据等**工作产物** |
| `测试/功能测试/` 等轨 | 本包工作产物 | 外部原件（放 `资料/`） |

- **单包资料根**：`测试/资料/`。多包 `项目资料/`：确认后只吸收进本包。
- **工作产物不回写资料**。
- **单一主副本**：跨包只引用。
- **版本记录**：根 CHANGELOG 仅开发维护；本包只写 `测试/工作日志.md`。

## 2. 资料目录（版本/主题子目录）

```text
测试/资料/
├─ 资料索引.md
├─ _通用/                         # 跨版本稳定输入（原「项目文档根」通用件）
├─ {版本或主题}/                  # 如 V2.7.0、APS-2.2.0；文件名保持原名
├─ 测试数据/                      # 样本/造数/账号配方
├─ 交接/{HO-ID}/
└─ _归档/{yyyyMMdd}-{版本或批次}/
```

- **禁止**：新建 `项目文档/`；禁止强制类型前缀扁平；禁止新资料平铺 `资料/` 根。
- **兼容**：旧 `资料/项目文档/{ver}/` → 迁到 `资料/{ver}/`（重新接入列候选）；旧扁平 `PRD-*` 可保留登记，新件进版本目录。
- 设计输入目录（环境基线 §2.1）默认：`测试/资料`（含 `_通用/` 与版本子目录）。

## 3. 入站意图分析

输出：`类型 | 落点 | 同步 | 归档/覆盖`。

| 类型 | 线索 | 落点 | 本包同步 | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 整版新 PRD/计划废止 | 外件→`资料/{ver}/`；计划就地为现行 | 计划指针、索引、用例影响面 | 旧资料同批 `资料/_归档`；计划旧口径快照到 `测试/_归档`（主档不移动） |
| T2 方案/设计变更 | 方案/原型变更 | 外件→资料；建/更 `变更/CR-*` | CR §5：计划/用例/脚本/报告指针 | 就地覆盖受影响用例结论 |
| T3 未决确认 | 口径拍板 | 结论→CR/计划「待探查」关闭/用例断言 | 分析短表假设清除 | 过程件不进现行 SSOT |
| T4 迭代专项 | 修改方案、S-NN | 外件→资料；`功能测试/S-{NN}-*-专项` + 台账 | 专项索引、计划追加节（非 C2/C3 不重开计划门） | 停用专项标停用；模块被替换 → 轨内归档 |
| T5 范围/优先级 | 砍测、调准出 | 计划范围/准出节 | §0/矩阵 | 旧范围通知被替代 → 归档 |
| T6 缺陷/回流 | 平台结论、修复说明 | 外件可进资料；缺陷轨流程 | 回归范围、台账 | 按缺陷流程，不把用例整包误丢根 `_归档` |
| T7 仅参考 | 无强制 | 资料=`参考` | 一般不改用例 | — |
| T8 冲突 | 未裁决 | `待确认` | 停下问 | 不改现行断言 |
| T9 交接包 | HO-ID | 多包直读；仓外按接收 | 计划/台账 | 发出包不可改 |

C0～C3 同协作。双落点时 SSOT=本包工作产物（计划/用例/报告），不是资料原件。

## 4. 资料收取步骤

1. 识别变化 → 判 T1～T9 + 覆盖。
2. 输出候选；确认前不改文件。
3. **确认采纳后同批**：落位 `资料/{ver}/` 或 `_通用/` → 同步 CR/计划/用例等 → S1/S2/S3 资料进 `测试/资料/_归档/{批次}/` → 清单 → 更新索引/计划/报告/activeContext。
4. 部分/增量/参考保留；冲突→T8。

覆盖关系与 S1～S5 同他包。禁按年龄归档。

## 5. 工作文档四类

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `环境基线.md`、`activeContext.md`（含 `### 进行中` 快照）、`测试/测试计划.md`、`测试/测试报告.md` | 长期/当前 | 就地更新；关闭时计划/报告**快照**到 `测试/_归档/{yyyyMMdd}-{版本}/`，当前档不移动 |
| `测试/工作日志.md` | 长期 | 过长确认后移块到 `测试/_归档/工作日志/` |
| `测试/00-稳定冒烟清单.md`、可复用脚本 | 长期 | 保留/更新 |
| `测试/功能测试/` | 绑定 | 关闭 → `功能测试/_归档/{yyyyMMdd}-{版本}/`；专项增量见工作流 |
| `测试/接口测试/` | 绑定 | 关闭或点名旧轮 → 轨内 `_归档/`；现行就地更新 |
| `测试/探索式测试/` | 绑定 | 点名旧轮 → 轨内 `_归档/` |
| `测试/随机业务流程测试/` | 绑定（计划外） | 点名旧轮 → 轨内 `_归档/`；不进计划/报告准出归档链 |
| `测试/发布前测试/{专项}/` | 绑定 | 关闭 → `{专项}/_归档/` |
| `测试/变更/CR-*` | 绑定 | 关闭 → `测试/_归档/.../变更/` |
| `测试/交接/{HO-ID}/` | 快照 | 不可改；关闭 → `测试/_归档/.../交接/`；台账常青 |
| `**/.draft/` 等 | 临时 | 清理候选（确认后删或 `_待清理/`） |

**执行入口**：是否仍在当前计划确认范围内执行。否 → 旧轮可轨内归档。用例/台账/报告：**就地覆盖，只留最新结论**。

> **禁**：把功能/接口/探索式/随机业务流程/发布前资产整包丢进 `测试/_归档/` 根。根 `_归档` 只收计划/报告/CR/交接快照与 `_待清理`。

## 6. 更新还是归档

局部 → 就地覆盖。T1 资料失效归档 + 计划快照。T4 专项增量，停用才归档。版本关闭 → §7 分轨。正式资产只写现行有效。

## 7. 版本/迭代关闭（换迭代 = 关当前版进入下一版）

> **迭代即版本主题**：换下一期方案/新版本目录 = 结束当前迭代并开下一迭代。与「正式发布上线」**不是两套清理标准**——分类、绑定归档、失效资料、临时清理、索引/链接同一套完整分析；差别只在是否做**发版对外项**。

### 7.1 关账清单（按实际裁剪，不是少做）

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分析分类：长期/版本绑定/失效替代/过程临时 | 必做 | 必做 |
| 更新计划/台账/索引/activeContext | 必做（指向下一迭代） | 必做 |
| 当前迭代绑定计划快照/用例轮次/报告/CR 等 → 分轨或根 `_归档/{yyyyMMdd}-{版本或迭代}/` | 必做（已确认结束的） | 必做 |
| 失效资料 → `资料/_归档/` + 清单 | 必做 | 必做 |
| 临时/过程/失败/重复清理 | 必做 | 必做 |
| 修断链 | 必做 | 必做 |
| 测试报告准出对外 / 根 CHANGELOG | **跳过**（除非点名关报告发版） | 按报告/准出门 |
| 平台回写收尾 | 按缺陷策略 | 按缺陷策略 |

### 7.2 确认结束当前迭代（不确定必问）

出现下一期方案/换主题/版本号升级，但当前迭代是否算结束不明确（例如仍在缺陷回归、提测未结）→ **STOP** `confirm_iteration_close`：出示「当前迭代标识、未完成项、拟归档摘要、下一迭代标识」→ 用户确认「结束当前并进入下一」后才执行 §7.1；用户说「并行不关」→ 只落新资料、不归档现行绑定主档，收尾记假设。

用户已明确「下一期 / 换版本 / 关这期」→ 按已确认执行，不重复空问。

### 7.3 触发（自动探测 · 同会话）

1. 新迭代/版本文档确认采纳（materials / testing.plan 期中变更）且判定换代，或用户确认结束当前
2. 换主题目录 / 版本号升级 / 计划范围换代
3. 正式发版/结项口令
4. 点名整理/巡检/清理（可只做清理子集，仍先分析分类）

未确认零移动；证据/现行主档/密钥永不自动删。

## 8. 过程/临时清理

扫描 `测试/` 与项目根顶层；不确定 → `测试/_归档/_待清理/`。候选：已完结 `.draft/`、tmp/bak/log、副本、未引用导出；进行中 draft、现行证据/计划/报告禁动。细则与点名清理口令见 `规则/工作流.md` §1.3。

**何时扫清理**：点名整理/巡检/清理（lifecycle）；或换迭代/关版本并入 §7.1。日常任务收尾不主动列清理、不追问。不另立「轻量卫生」标准。

## 10. 触发

| 时点 | 动作 |
| --- | --- |
