# 门（测试轨）

> 单一出处：计划门、门1～3、迁移/资料门、`when`/`gate_when` 词表。步骤顺序以 `../workflows/*.yaml` 为准；**只认步上 `hitl`**，专规不另造门。
> 读取时机：当前步有门时只读对应行；写/改 YAML 时才读全表。

## 1. 门

| 门 | 步上声明 | 动作 |
| --- | --- | --- |
| 门1 | `select_mainread`（when: `mainread_unspecified_for_generate` / `exploratory_mainread_missing`） | 主读未点名 → STOP 一问；已选定 → 跳过，不得重问 |
| 理解门 | `confirm_understanding`（when: `understanding_needs_confirm`） | 出示需求模型摘要/oracle/冲突/九类歧义/GAP/缺口清单/置信度；确认后才写计划/用例/断言 |
| 计划门 | `confirm_plan`（when: `plan_needs_confirm`） | 版本级首版/换代或范围·准出·缺陷提交策略实质变更 → STOP 一行摘要确认；同会话同载体只一次；专项轻量不设门 |
| 门2 | `confirm_scope`（when: `scope_needs_confirm`） | 开跑前一行：主读/计划范围/环境 → 确认；同会话同载体只一次；计划驱动已确认 → 跳过并附【已预授权执行：按计划】 |
| 门3 | `confirm_commit`（when: `standalone_generate_with_pending` / `has_pending_commit_or_platform_ask` / `platform_submit`） | 有拟入库、须问交平台或拟新建缺陷单 → STOP；否则跳过 |
| 迁移/资料门 | `confirm_docs_migration`（when: `docs_migration_needed`） | 资料收取/分类/改名/归档、或旧结构迁移前列清单与目标；确认后执行 |
| 备注门 | `confirm_remark`（when: `remark_writeback`） | 拟关/激/解决/标重复/补充澄清/回归写回 → 先列 id+结论+备注全文；确认后执行 |
| 入库门 | `confirm_gitignore` | 四选一确认资产入库范围并写 `.gitignore`；接入时一次 |
| 交接门 | `confirm_handoff`（when: `handoff_send_required`） | 出示 HO-ID/类型/接收方/必带清单/阻断项/回执截止；确认后才生成/发送；未收回执不得称“已交接” |
| 覆盖闸 | `gate: coverage-map`（when: `functional_coverage_required`） | 功能全量/专项新生成/补生成：运行 `验证/Invoke-Gate.ps1 -Mode coverage`；设计点→用例映射无空行且映射到真实用例；不适用于其它轨 |
| 用例评审闸 | `gate: case-review`（when: `case_review_required`） | 功能全量/专项 T1+（或点名评审）：运行 `验证/Invoke-Gate.ps1 -Mode review`；评审记录存在、结论可解析、独立性声明、阻断未清不得放行；回执 `.gate/测试规范/review.json`；未 PASS 不得写「放行执行/评审通过」 |
| 评审方式门 | `select_review_mode`（when: `landing_doc_review_needed`） | **STOP 二选一**：A 自行｜B AI（testcase-reviewer）；可附自定义焦点。适用：**测试计划**（T1+ 实质）、**分析短表**（T2/T3 或歧义≥2）、**功能/专项用例**、**接口**（进准出）、探索/发布前（建议/T3）。同产物只问一次；未选不得宣称评审通过/计划可驱动/进 P2 |
| 评审确认门 | `confirm_review`（when: `review_needs_confirm`） | 结论=需修后放行、有条件放行须接受人、或与计划 P2 入口冲突 → STOP；已放行且无未接受重要项 → 跳过 |
| 报告闸 | `gate: report-consistency` | 出报告/准出前运行 `验证/Invoke-Gate.ps1 -Mode report`；台账/报告计数一致、P0 计划覆盖、证据、覆盖缺口；未 PASS/CONDITIONAL 不得写整体通过；回执在 `.gate/测试规范/report.json` |
| 回写模式 | `验证/Invoke-Gate.ps1 -Mode writeback` | 交平台/回写前运行；无回执/备注状态不同轮/附件未回查 → BLOCKED；只写 `writeback.json`，不覆盖 report |

## 2. `when` / `gate_when` 词表

`mainread_unspecified`｜`mainread_unspecified_for_generate`｜`exploratory_mainread_missing`｜`understanding_needs_confirm`｜`plan_needs_confirm`｜`scope_needs_confirm`｜`standalone_generate_with_pending`｜`has_pending_commit_or_platform_ask`｜`has_pending_commit`｜`remark_writeback`｜`platform_submit`｜`docs_migration_needed`｜`handoff_send_required`（显式生成交接包且接收方/范围/必带文档尚未在上一门确认；已由计划门/门2/门3/报告门确认同一发送时为假）｜`handoff_change_substantive`（交接包内变更达到 C2/C3 或改动已定稿基线）｜`landing_doc_review_needed`｜`review_needs_confirm`。

`gate_when`：`functional_coverage_required`｜`case_review_required`（不满足 → 跳过该 gate，步骤不跳过）。

`landing_doc_review_needed`：下列任一待审且本会话该产物尚未选定 A/B → 真：**计划**（T1+ 首版/换代/范围·准出·缺陷策略实质变）、**分析短表**（T2/T3 或歧义≥2）、**功能/专项用例**（T1+）、**接口资产**（计划驱动或进准出）、探索/发布前（T3 或计划纳入且点名/建议触发）。用户点名「自行通过/我审」→ A 后置假；「AI 评审」→ B 后置假；T0/专项轻量追加可提示一次或默认 A。

`case_review_required`：功能全量/专项且 T1/T2/T3 **且用户选 B**，或点名机检 → 真；选 A、T0、接口/探索/发布前（软留痕）→ 假（仍须 HUMAN_APPROVED 或评审记录）。

`review_needs_confirm`：评审结论为需修后放行、有条件放行（重要遗留需接受人）、或计划 §9.2 P2 要求评审通过但记录未放行时为真；结论=放行执行且无未接受重要项时为假。

`scope_needs_confirm`：非计划驱动、计划状态非「已确认/执行中/待关闭」或范围/环境实质变化时为真；计划驱动且 §0 为已确认/执行中/待关闭时为假。期中变更 A/B 并入后保持已确认→假；C 变更中→真（计划门）。

`understanding_needs_confirm`：输入含 PRD/迭代方案/原型/接口或技术文档、存在 2 个以上实质歧义/冲突、T2/T3，或用户要求计划/用例/准出时真；已有**本轮当前范围**确认的需求理解包/分析短表或纯信息查询/机械低风险操作时假。

同一会话同一确认点只问一次；资料/迁移/清理清单确认后本轮不再重复（`docs_migration_needed` 置假）。

## 3. 门档位（防过度审批）

| 档 | 适用 | 行为 |
| --- | --- | --- |
| autonomous | 只读、列表/巡检、已脚本化回归 | 直接做，收尾记录变化/假设 |
| notify | 同范围生成/执行、A/B 期中变更 | 展示范围/计划/环境后继续，用户可打断 |
| approve | 计划实质变更、首次执行未确认范围、**评审方式选择**、用例需修/有条件放行确认、平台建单/回写、提交、资料搬迁/清理、交接包发送 | 停：计划门、门2/门3、评审方式门、评审确认门、备注门、迁移门、交接门 |

低风险动作不要升级为 approve；高风险动作不得降为 notify。红线不被“少问/直跑”覆盖。
