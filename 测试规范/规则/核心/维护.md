- 不变量/路由/读取协议 → `AGENTS.md`

- 角色 → `agents/`
- 红线/输出/门 → `规则/`（门：`规则/门.md`）
- 澄清协议 → `规则/核心/澄清.md`
- 协作/交接/变更分级 → `规则/协作/协作与交接.md`；交接步骤 → `workflows/handoff.yaml`；回执/台账模板 → `规则/模板/`

- 模板 → `规则/模板/`
- 技能 → `技能/`（**可在落地包就地改**；通用最优：「通用优化技能/母版技能更新」）
- 能力 → `能力/`
- 能力/技能体检 → `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`
- 计划编排 → 测试计划模板 + `规则/工作流.md` §3.6 + `规则/专项/多Agent与输出.md` §4（三处同步）

## 1.1 体检 vs 装配 vs 维护

| 口令 | 用途 |
| --- | --- |
| 装配能力 | 只盘点/安装外部能力 |
| 体检能力（及同义） | 外部能力 + 随包技能检查/适配；确认后可就地改本包 |
| 通用优化技能 / 母版技能更新 | 同上，mode=generic |
| 维护/查询 | 改规则/自检；深度技能能力分析转体检口令 |

## 4. 重排维护

改口令表/门表/清单编号后，检索全包「行 N」「优先 N」「§x.y」等编号引用并同步（自检不查编号引用）。

## 5. 规则撰写标准

新增或保留规则/步骤的标准＝**有用、不冗余（单一出处，其余指针）、不误导、高性价比**；默认可完成的动作不写；强调集中在不可让项；凡阻塞式确认门处，YAML 步上必须有对应 `hitl`；澄清类一问不入 hitl。

## 6. 文档粒度

常驻最小、按需加载：被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。

## 7. 宿主无关

本包文本与 YAML 只写能力名；宿主具体值与本地路径只写实例基线（§8/§13）；宿主要求与挂载见 README「宿主适配」节；能力名清单见 `能力/00-能力注册表.md`。
