> 只在改包/自检/维护时读；业务任务不读本节。`AGENTS.md` 只留维护指针。  
> **能力/技能体检**走 `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`。

- 不变量/路由/读取协议 → `AGENTS.md`

- 步骤 → `workflows/`（含 `skill-audit.yaml`）
- 角色 → `agents/`
- 红线/输出/门 → `规则/`（门：`规则/门.md`）
- 澄清协议 → `规则/核心/澄清.md`
- 协作/交接/变更分级 → `规则/协作/协作与交接.md`；交接步骤 → `workflows/handoff.yaml`；回执/台账模板 → `规则/模板/`
- 轨边界 → `规则/轨契约/`
- 模板 → `规则/模板/`
- 文档质量标准/类型矩阵 → `规则/核心/文档质量标准.md`
- 适配：模板/规则/技能可按项目实际适配；AI 先出拟改/原因/影响，用户确认后改本包并登记；能靠产出文档解决的优先改产出
- 技能 → `技能/`（**可就地改**；通用最优：「通用优化技能」）
- 能力 → `能力/`
- 能力/技能体检 → `workflows/skill-audit.yaml` + `规则/playbooks/skill-audit.md`
- 计划编排 → 测试计划模板 + `规则/工作流.md` §3.6 + `规则/专项/多Agent与输出.md` §4（三处同步）
- 读取索引 → `规则/读取索引.md`（改 step/reads 后同步）

## 1.1 体检 vs 装配 vs 维护

| 口令 | 用途 |
| --- | --- |
| 装配能力 | 只盘点/安装外部能力 |
| 体检能力（及同义） | 外部能力 + 随包技能检查/适配；确认后可就地改本包 |
| 通用优化技能 / 通用最优技能 | 同上，mode=generic |
| 维护/查询 | 改规则/自检；深度技能能力分析转体检口令 |

## 2. 自检

```powershell
powershell -ExecutionPolicy Bypass -File "测试规范/规则/tools/Invoke-TestWorkflow.ps1" -Action ValidateTemplateRefs
powershell -ExecutionPolicy Bypass -File "测试规范/规则/tools/Test-DocHygiene.ps1"
python 测试规范/规则/tools/check_skills.py 测试规范 --strict
python 测试规范/规则/tools/validate_testcase.py <模块用例.md>
```

> **`check_skills.py` 必须带包根**（上例 `测试规范` 或包内 `.`）；裸跑 `--strict` 会假报 `SKILL_DIR_MISSING`。

自检覆盖：引用/锚点/workflows→agents/步标记/能力名/版本单点/YAML/技能；另跑文档卫生检查（见 `规则/tools/README.md`）。

`规则/模板/20-测试用例/无障碍与UX检查清单.md`；结果并入测试报告 §11。

## 4. 重排维护

改口令表/门表/清单编号后，检索全包「行 N」「优先 N」「§x.y」等编号引用并同步（自检不查编号引用）。

## 5. 规则撰写标准

新增或保留规则/步骤的标准＝**有用、不冗余（单一出处，其余指针）、不误导、高性价比**；默认可完成的动作不写；强调集中在不可让项；凡阻塞式确认门处，YAML 步上必须有对应 `hitl`；澄清类一问不入 hitl。

## 6. 文档粒度

常驻最小、按需加载：被 ≥2 角色/场景引用或按口令分时机点读 → 独立成文；单角色且不足 20 行 → 并入其契约/所属文档；单文件超 200 行且分时段消费再拆；引用不复制。

## 7. 宿主无关

本包文本与 YAML 只写能力名；宿主具体值与本地路径只写实例基线（§8/§13）；宿主要求与挂载见 README「宿主适配」节；能力名清单见 `能力/00-能力注册表.md`。
