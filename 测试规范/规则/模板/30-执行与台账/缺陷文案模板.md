# 缺陷文案模板（十段/HTML/备注骨架）

<!-- longform: 按节读取；不要通读 -->

> 只在拟提交/拟回写时读；`规则/缺陷/缺陷协作.md` 的 `§5.0.1～5.0.3`、`§8.x` 指针指向本文件。

## 5. 提交骨架（模板）

### 5.0.1 十段结构（缺段不得提交）

首行 `<b>{caseId} {caseName}</b>`，其后各块以 `<b>【…】</b>` 起；块间仅一个空段（HTML 用单个 `<p></p>`）；块内行间用 `<br>` 相连，**禁**段内每行外包 `<p>`（`'<p>'+l+'</p>'` 式→每行一空段）、禁连续多个空段；拼装与写入前自检见 §4.0。

| # | 块 | 必填要点 |
| ---: | --- | --- |
| 1 | **【提交摘要】** | 四行齐：执行结果；缺陷类型（实现缺陷\|产品缺陷，见 `规则/缺陷/缺陷分类.md`）；问题标题（=**平台标题**，含 `[V…][类型]` 前缀）；`严重程度：…；优先级：…`。**S1/S2 另加两行**：`一句话影响：{谁/什么业务受影响}`；`最小复现：{≤3 步或最短路径}`。可附模块·路由一行 |
| 2 | **【环境】** | `环境URL=`；账号**角色**（**禁密码**）；版本·构建（可知则写） |
| 3 | **【测试数据/业务主键】** | 页面原样**完整业务码**/关键主键竖排（`列名=全码`）；足以换环境打开同一对象；禁短 Id 假号、禁「未抄全码」套话 |
| 4 | **【问题】** | 页面/菜单锚点 + 对象全码 + 动作 + 偏差与业务影响（≥2 句；禁无主语「操作后/查询后」起句） |
| 5 | **【复现】** | 编号步骤一般 ≥3；按**实际导航**写可跟做路径（侧栏/顶栏/直链/搜索定位等，勿硬套侧栏层级）；**一步一事**；每步写**页面/区域/控件/行定位 + 数据值**；含复现频率与前置；禁「打开系统/按场景数据」空话 |
| 6 | **【实际】** | 前端编号 ≥2 条肉眼观测（与复现同序可对读）；写页面原文/数值/状态/字段=值；截图叶名独立成行且钉断言面；接口细节进第 8 块，此处可写「见【接口判定】」 |
| 7 | **【预期】** | 前端编号 ≥2；可验收行为+业务含义；与【实际】/复现同序对应；禁空「应正常」 |
| 8 | **【接口判定】** | 有相关接口则必填：方法+路径、关键参数实际值、码/消息、回查字段=值、判定句；本轮无接口写「本轮无相关接口」 |
| 9 | **【设计对照】** | 有设计文档：资料 `{设计输入目录}《{文件名}》§{章节}「{节点}」`；`原文：`（逐字片段≥8 字，取自被引文档）；`设计应然：`；`现网/本轮：`；`差别：`；`方案理解核对：{本缺陷针对的明确要求；哪些未冻结/待确认项没有被误判为缺陷}`；`本条以…为准`。要素间硬空行/`<br>`，禁分号粘连；文件/章节/要点**真实可回查**（编造/越章节=先改引）。禁仅 `…用例.md`、禁空泛。**产品缺陷**另加 `相符证明：`（见 `规则/缺陷/缺陷分类.md`）与 `证据：{截图叶名/接口字段=值}`；`实现缺陷` 禁写相符证明。**无设计文档**：`无设计文档·现网依据：`{本轮 UI/接口要点}，禁编造引用后反复改 |
| 10 | **【技术附记】** | `route=`、`落点=` 各行；有接口可摘要 `code=`/`响应：字段=值`；`依据=`、`判定=`（须有据）；UI≠Network 时加 `对账=`；**无密钥/无绝对路径/无用例路径** |

### 5.0.3 禁止（提交内容）

| # | 禁止 | 正确 |
| ---: | --- | --- |
| 1 | steps 用简陋「步骤/结果/期望」三段式或缺十段任一段 | 按 §5.0.1 十段齐（待实现须有缺失证据，可非截图；其余同构） |
| 2 | 不查重即建单；失败无截图；附件未按 §13/§4.1 上传或不回查 | 先查重 → 建单 → 按适配上传 → 回查挂载 |
| 3 | 标题只写 caseId / 空话；缺测试类型前缀；已确认版本却无 `[V…]`；猜造未确认版本；严重度/优先级塞中文枚举或未映射字段 | 平台标题=`[V版本?][类型]`+正文；正文≤56 字；取值经 §13 映射 |
| 4 | 【复现】无可达路径/无业务主键；同一步混多路径 | 按实际导航写清路径+主键；一步一事 |
| 5 | 【实际】/【预期】空形容词（「异常」「不正确」「应正常」）或与复现脱节 | 可见原文/数值；编号同序对读 |
| 6 | 【设计对照】分号粘连 / 仅用例.md / 编造章节原文 | 硬空行+真实可回查指针；无文档走「无设计文档·现网依据」 |
| 7 | 密码、Token、绝对路径、用例/台账路径写入 steps | 环境只写 URL+角色；路径类不进平台 |
| 8 | 有接口证据却无【接口判定】，或 UI 段堆 API 术语 | 接口进第 8 块；UI 段写产品可观测现象 |
| 9 | 把用例 ID/台账/计划/报告路径、测试脚本、内部分类/评级理由写入平台 | 只写开发/产品需要的事实；内部信息留在台账 |
| 10 | 产品缺陷只写相符证明结论、不附证据 | 相符证明 + `证据：{截图叶名/接口字段=值}` |
| 11 | 把「待实现」当非缺陷/不交/阻塞 | 待实现=实现缺陷，按批次/阶段/收尾清单提交；明确范围外→不适用 |
| 12 | 只附设计文档/需求文件当失败证据 | 设计文档只进【设计对照】；失败必须有断言点截图或 `字段=值`+请求响应 |

### 5.0.4 人类可查 60 秒检查（提交前）

> 开发/产品通常先看标题和第一屏；他们不读测试内部台账。

- **标题**：列表页只看标题，能否区分“哪个对象、什么动作、什么偏差、什么后果”？
- **第一屏**：【提交摘要】是否有一句话影响 + 最小复现；S1/S2 没有 → 不合格。
- **复现**：非作者按步骤能否走到同一状态；有没有“打开系统/相关按钮/按场景数据”这类空话？
- **观测**：【实际】是否是页面原文/数值/状态/字段=值；【预期】是否写清“怎样算修好”。
- **证据**：截图是否含地址栏/页面标题/关键字段/断言点；设计文档是否被误当失败证据？
- **定位**：业务主键是否能打开同一对象；环境/构建/账号角色是否齐全。
- **追查**：本地草稿是否有关联用例 + 查重结论；平台正文是否误带内部路径/凭据？

**详细度基线（差 → 好；领域示意，禁照抄字段/码）**

| 差（不可复现） | 好（模式：菜单/入口 → 对象全码 → 字段=值 → 操作 → 可观测断言） |
| --- | --- |
| 打开某页 → 点击 → 失败 | `{入口路径} → 对象 {业务全码} → {字段}={值} → 「{按钮}」→ 核对 {字段/状态} → 断言点` |
| 同业务详情/列表 | `{列表} → 按「{列名}」定位 {全码} → 详情/Tab → 核对 {关键字段}` |
| 提交后没生效 | 同操作两次 → 记录两次 `{业务单号}` → 回查 `{指标/列表} → 预期 vs 实际` |
| 查询结果不对 | 换 `{时间/筛选条件}` 各查一次 → 记录关键字段 → 再变更数据后复测 |

> 判断：**非作者只拿本单，能否不猜页面/不猜字段/不猜数据地复现并判定**；不能 → 步骤还不够细。

## 8. 备注骨架

确认前展示全文；书写版式按 §4.0（与提交 steps 同规）。备注**一次性写入**（与状态写回同轮）；写错修正=编辑原备注，禁追加第二条补丁备注（多数平台普通角色无删评论权限）。

**读者=开发/产品**：只写事实、证据、请求；禁写入用例 ID/路径、台账/计划/报告路径、测试脚本、密钥、指派账号、内部分类/评级理由、内部过程、无关测试数据、未标注猜测、PII。测试内部信息留在台账/CR。  
**备注正文用中文结论**；`fixed/notrepro/bydesign` 等解决码只填平台字段，不写进备注。

### 8.1 激活（未通过/部分修复）

```text
【回归未通过·请继续修复】Bug#{id} · {标题}
【模块/入口】{模块}；页面 {…}；接口 {方法 路径}（无可省）
【验证构建】{resolvedBuild/commit}；构建含修复={是/否/未知}
【本轮数据】{主键与关键字段}
【环境】URL={…}；角色={…}
【复现频率】{每次/间歇 n/m/一次}
【复现】
1. …
2. …
3. …（≥3 步）
【实际】
1. 前端：{…}
2. 接口：{方法 路径；参数；码/消息}（或本轮无）
【预期】
1. 前端：{…}
2. 接口：{…}
【与原单对照】{原单步骤/数据/环境一致/差异}
【差异】{一句}
【对照】{额外对照（参数组合/换参/延时回查等关键结果）；无则写「无额外对照」}
【我已排除】{换账号/换数据/清缓存/换浏览器/换构建/直连接口等结果}
【证据】{截图叶名/录屏/HAR/console/日志/请求ID}
【判断】{原问题未修复 / 部分修复（已修复…仍失败…）}
【根因倾向】{有依据写；否则写「需开发确认」；标注「推测」}
【请开发】{继续修复 / 确认构建 / 联调}
```

> 新问题 → 走 §8.5，不套本骨架；部分修复 → 【判断】写清“已修复/仍失败”，不写“还是不行”。

### 8.2 关闭（通过）

```text
【回归通过·关闭】Bug#{id} · {结论}
【模块/入口】{模块}；页面 {…}；接口 {…}（无可省）
【验证构建】{resolvedBuild/commit}；构建含修复={是/否}
【本轮数据】{主键}
【环境】URL={…}；角色={…}
【复测步骤】
1. …
2. …（≥2，覆盖原问题路径）
【复测结论】{已消除；对比修复前 / 按新口径验证通过}
【关键实测】
1. 前端：{…}
2. 接口：{…}（或本轮无）
【影响面回归】{受影响模块/相邻功能/结果}
【边界抽查】{≥1 或与本缺陷无关未另抽}
【口径依据】{原设计 / 产品确认的新文档/AC 版本}
【证据】{截图/录屏/日志/附件名}
```

> 产品确认新 AC → 【复测结论】写“按新口径验证通过”；【口径依据】写文档/章节/版本。

### 8.4 补充澄清说明（开发无法复现/无法定位）

```text
【补充澄清说明】Bug#{id} · {标题}
【开发反馈】{摘录开发说无法复现/卡在哪一步/已尝试什么}
【结论先行】{测试侧本轮仍可复现；频率 n/m；关键触发条件是…}
【问题定位】{页面/菜单/字段/接口/按钮；哪个值/状态不对；影响哪条业务}
【复现前置】{环境URL/构建/账号角色/权限/数据状态/功能开关/租户/浏览器/设备/网络/时区}
【复现步骤】1...2...3...（每步“操作 + 页面/字段 + 观测值”）
【关键观测】{页面原文/数值/状态；接口方法+路径+参数+响应码/字段；console/network；日志/请求ID}
【复现频率】{每次/间歇 n/m/一次；触发条件}
【与开发环境差异】{构建/配置/数据/角色/浏览器/网络/缓存/时区…}
【我已排除】{换账号/换数据/清缓存/换浏览器/换构建/直连接口等结果}
【最小复现】{能复现的最短步骤/最小数据；不能缩减则写“暂无”}
【证据】{录屏（关键 10 秒）/截图（圈出断言点）/HAR/console/日志/请求ID/时间戳}
【请开发确认】{请按以上步骤复现；若仍无法复现，请告知卡在哪一步/哪个观测值不同，我再补/可联调}
```

- 读者=开发；只写开发复现所需事实；不写用例/台账/内部分类/测试过程。
- 开发反馈是“看不懂问题/不知道在哪”而非“无法复现” → 先用业务语言重述场景、页面/字段/接口、预期 vs 实际，再给短视频；不堆步骤。
- 澄清轮次：同一缺陷补充说明 ≤2 轮；第 2 轮仍无法复现 → 约联调/在开发环境复现/加日志；仍不行 → 升级测试负责人/开发负责人/产品，决定保留观察或双方同意按无法复现关闭。

### 8.5 新问题/回归缺陷

【回归发现新问题】Bug#{id} · {标题}
【原单】Bug#{id}（原缺陷）
【新问题】Bug#{newId}（新建）或 {待提交}

【复现频率】{每次/间歇 n/m/一次}
【复现】1...2...3...
【实际】1. 前端：{…} 2. 接口：{…}
【预期】1. 前端：{…} 2. 接口：{…}
【证据】{截图/录屏/HAR/console/日志/请求ID}

### 8.6 非修复处置（设计如此/重复/外部/延期/不修/转需求）

```text
【处置结论】Bug#{id} · {标题}
【分诊】{设计如此 / 重复 / 外部原因 / 延期 / 不修 / 转需求}
【依据】{设计文档/产品确认/主单/外部证据/需求单}
【影响】{用户/范围/版本/风险}
【接受人/截止】{…}
【测试侧动作】{关闭 / 保持 / 转需求 / 纳入遗留风险}
【证据】{…}
```

写平台时的处置取值经 §13 映射（禅道示例见 §4.1）。语义处置：

- 设计如此：设计文档/产品确认；同意关闭，不同意转产品。  
- 重复：写主单号；跟随主单回归；关闭并链接。  
- 外部原因：外部证据；关闭/转外部责任；报告风险。  
- 延期：写目标版本/复审日期；报告 known issue；不标已修复。  
- 不修：写理由/接受人；报告风险。  
- 转需求：写需求单号；关闭并链接；测试计划纳入需求变更。

### 8.7 回写回查

1. 写入前若最后编辑时间已变 → 重读合并，不覆盖别人刚写的内容。  
2. 写后按 §13「详情」端点核对状态/处置/指派/最后编辑时间与最新备注等**本轮写入字段**（禅道内置：`GET /api.php/v1/bugs/{id}`）；HTTP 成功码不替代回查。  
3. 有附件时按 §13「附件回查」断言挂载到本单（禅道内置：`GET /api.php/v2/files/{fileId}`）。  
4. 记录 `noteId/time` 到台账/CR。  
5. 不一致 → 编辑原备注修正一次；平台不支持编辑 → 追加【更正】并注明“更正上条备注第 X 段”，保留原记录；仍失败 → `export` 包标「待回写」；不声称成功。  
6. 备注与状态同轮；正常不追加第二条补丁备注。

### 8.8 产品判定回流（测试处理）

> 适用：产品判定“非问题/设计如此/重复/信息不足”后指派回测试；或产品确认产品缺陷但测试需要记录新口径。读者=产品/开发，只写事实与处理结论。

```text
【产品判定·测试处理】Bug#{id} · {标题}
一、产品结论：{产品缺陷 / 实现缺陷 / 非问题 / 设计如此 / 重复 / 信息不足}
二、依据：{产品备注/附件名/文档 §章节；无则「无」}
三、测试处理：{接受关闭 / 补充后复测 / 等待开发修复 / 转需求 / 纳入遗留}
四、影响与风险：{范围/版本/用户影响；接受人；无则「无」}
五、下一步：{关闭 / 回派产品 / 等新构建 / 补材料}
六、证据：{截图/附件名；无则「无」}
```

- 产品结论为“产品缺陷” → 按 §7.4 等含修复构建后回归；产品确认不等于已修复，不在此提前关闭。  
- 产品结论为“实现缺陷” → 等开发修复；测试按 §7 回归，不要求产品改 PRD。  
- 产品结论为“非问题/设计如此” → 测试同意才关闭；不同意按 §7.4 转产品复核。  
- 产品结论为“重复” → 关闭并链接主单；后续跟随主单回归。  
- 产品结论为“信息不足” → 补齐材料后回派产品，不默认关闭。  
- 备注用中文结论，不写平台英文解决码；解决码只填平台字段。
