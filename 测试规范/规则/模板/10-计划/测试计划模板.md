> **纪律**：范围含**明确排除**；测试类型选择有依据；执行顺序/并行/依赖可执行；回归/缺陷/探索式可落地；准出可判定（清单/阈值），禁空泛「测试完成即通过」。

> **独立运行**：本计划是测试轨总控，不是项目总控；PRD/提测单/UAT 为可选输入，有则引用，无则按主读/基线继续，不阻塞。

### 3.6 执行分配与自动化策略（按实际价值，不搞全量资产库）

- **默认分配**：重复验证/确定性 → 脚本；复杂判断/新变化/探索 → AI；性能/安全/兼容/迁移 → 专业工具；一次性 → AI/人工，**不脚本**。  
- **只维护 P0-Smoke 脚本清单**：`测试/00-稳定冒烟清单.md`（建议 ≤12 条）；**不登记全量用例/脚本**，全量资产仍在用例/台账。  
- **功能**：只脚本 P0-Smoke/核心闭环；其余迭代功能由 AI 执行；新功能不强制复用旧用例，按变更新增/更新。  
- **接口**：确定性接口用例默认 API 脚本；跨版本只更新受影响 endpoint；**不做全量重生成**。  
- **脚本晋升**：某用例成为 P0-Smoke、每次构建/发布都跑、连续 1～2 版稳定 → 才补脚本；**不用“复用 ≥3 次”拍脑袋**。  
- **已知稳定流程**：脚本先行（AI 生成 → CLI/CI）；**未知流程**：AI 探路一次，稳定后 codegen/trace 固化；禁止“AI 跑一遍→再生成→再跑”双耗。  
- **额外发现**：AI 执行中记录用例之外的 UI/布局/显示/文案/console/network/UX 异常，进台账/报告；不静默忽略。

- **当期验收通过，且常青/前序约定项未崩**（§2.2 所列依赖版 Smoke / 常青冒烟 / 约定 HighRisk 已实测通过或有用户接受的缺口）。禁止默认成「仅本期新功能通过」；常青/前序失败不得静默判有条件通过。
- §3.1 选「是」的测试类型均执行完成，或有用户接受的缺口/不测理由。
- `S1/S2` 缺陷清零；`S3/S4` 已定性并有处置结论（修复/接受/遗留）。
- 产品缺陷判「下版/不修」须有产品负责人书面接受风险（写明接受人）；未接受不得判通过/有条件通过。
- 回归通过：原单复测 + 冒烟子集 + 影响面组；高风险修复按升级口径完成；产品确认新 AC 按新 AC 回归。
- 探索章程完成并产出覆盖/缺口句；无空泛「探索通过」。
- `测试/测试报告.md` 已更新，计划执行对照与遗留风险成立。
- **不含**计划外「随机业务流程」轮次结论（该轨不参与准出对照）。

> **P0 未通过 → 不通过**；「有条件通过」仅限 P0 全通过、缺口非 P0 且用户接受。

## 6. 暂停 / 恢复准则

- 环境级不可用（登录/站点/网关/基础数据且穷尽自打通）→ 停轮报告；修复后先复跑冒烟再续。
- 主链路产品缺陷 → 阻断面：无法换样/绕过时下游记阻塞点名上游，独立面照跑；可换样/可独立执行的面不记阻塞。
- 数据/隐私/合规风险 → 立即暂停，脱敏或换样后再续。
- 计划范围/准出/排期实质变更 → 回到计划门；禁静默降范围。
- 恢复：口令「继续」（沿用范围/轮次；不重跑已终态）；恢复前先复跑冒烟未过项。

## 10. 回归策略

- **版本级依赖回归（开跑即做）**：§2.2 所列依赖版 **P0-Smoke** 须实测通过后再铺开本期全量；禁有界对照替代；默认不重跑依赖版归档全量（升全量须用户点名）。  
- **P0 冒烟脚本复用（默认）**：稳定冒烟清单只保留 P0-Smoke 脚本；迭代功能用例按本轮新增/更新，不强制复用旧用例；旧模块替换才单项归档，**禁整包重生成**。  
- **连续回归（默认）**：每个缺陷修复后立即回归，不等批末；范围 = 原单复测 + 冒烟子集 + 影响面组；修复落在依赖供给面时加跑对应依赖 Smoke。  
- **影响面组**：由开发回写【改动范围/影响面】+ 分析短表变更点生成（3～8 条建议）；用户点头才扩。  
- **升级口径**：高风险修复（跨模块/契约/数据/权限/资金/并发）或同模块短窗口 ≥2 单 → 提示升级（受影响模块局部全量/扩大回归至邻接与历史高发区）。  
- **准出回归**：报告前跑一次计划范围内的回归；已脚本化优先脚本档（0 token）。  
- **记录**：结果就地覆盖台账与证据，只留最新确认结论；报告 §5.2 汇总回归轮次/通过率/遗留。  
- 与缺陷轨「平台单回归」分轨：平台单回归走 `规则/缺陷/缺陷协作.md` §7；本计划回归走本轨台账。  

## 11. 缺陷管理

### 11.1 分级

| 级别 | 判定 | 处置 |
| --- | --- | --- |
| S1 致命 | 主链路阻断/数据不可恢复/资金安全 | 立即停轮/上报；修复后全量回归 |
| S2 严重 | 核心功能不可用/明显数据错误/越权 | 当轮修复；原单+影响面回归 |
| S3 一般 | 非核心功能异常/有绕过 | 排期修复；回归原单 |
| S4 轻微 | 文案/样式/体验 | 可接受/排期；回归原单 |

> 产品缺陷判「下版/不修」时，须产品负责人书面接受风险；S1/S2 不得静默降级。

### 11.2 提交策略（计划门确认或同范围沿用上次确认即授权）

| 策略 | 本计划选择 | 说明 |
| --- | --- | --- |
| 发现即提交 | `{是/否}` | 查重后立即提交；十段齐+证据；不再逐条问；收尾列清单 |
| 按模块批末提交 | `{是/否}` | 功能按模块、接口按域、非功能按专项、探索按章程/会话分批（P0/P1 冒烟缺陷并入当天批次）；批内先落台账，批末出拟提交清单→用户确认→只提交确认项；不跨批累积 |
| 阶段末提交 | `{是/否}` | 每阶段（P2/P3/P4/P5/P6）末汇总提交；阶段内先落台账 |
| 收尾确认 | `{是/否}` | 按门3 一次确认后提交 |
| 仅导出提交包 | `{是/否}` | 平台不可写/未适配；AI 出包，用户提交后回填编号 |

- 未配置平台或未授权 → 默认 `export`，禁猜接口。  
- **五选一**：仅一项为「是」；未配置平台 → 选「仅导出提交包」。  
- **按模块批末提交不得变成整期一次提交**：一批=一个模块/域/专项/章程/修复批次；批末一次确认，批内不逐条问。  
- 提交前查重（平台同标题/同路径/同现象）；证据钉断言点；真实 PII 脱敏。  
- 阻塞默认不交；**待实现=实现缺陷（方案/AC/计划范围内应实现未实现）→ 进入批次提交**，不得以“未实现”免交；明确范围外/后续池 → `不适用`，不标待实现。

### 11.3 修复-回归闭环

```text
失败/待实现（实现缺陷） → 查重 → 归入当前批次 → 按 §11.2 策略提交（发现即提/按模块批末/阶段末/收尾/导出）
→ 分类（实现缺陷/产品缺陷；待实现固定实现缺陷）
→ 实现缺陷：开发修复 → 回归（§10）→ 通过关闭/未通过激活
→ 产品缺陷：产品决策
   ├─ 立即修：CR（D+B/C）→ 更新资料/计划/用例/脚本 → 开发修复 → 按新 AC 回归
   ├─ 下版/不修：计划 §2.3 排除 + 报告 §7 遗留风险 + 台账状态；不标已修复
   ├─ 退回开发：重分类为实现缺陷 → 开发修复 → 回归
   └─ 补充信息：保持打开；列缺什么/谁补/截止
→ 台账与报告更新
```

- 缺陷状态与备注同轮写回；备注全文按 `规则/缺陷/缺陷协作.md` §8。  
- 产品确认/新文档 → 按 `规则/工作流.md` §2.6 建 CR；不在缺陷轨直接改用例。  
- 未修复前不重复提交同因单；同批修复可合并一次回归。

## 18. 计划自适应（变更/重规划）

| 触发 | 级别 | 动作 | 审批 | 更新 |
| --- | --- | --- | --- | --- |
| 文案/口径/笔误 | `C0` | 就地更新，不重基线 | 测试负责人 | 计划/用例/索引 |
| 同范围补 AC/用例/回归 | `C1` | 更新计划/用例/脚本；通知受影响角色 | 测试负责人 | 计划 §0/§2/§3/§15、台账 |
| 范围/准出/排期/缺陷策略变化 | `C2` | 重基线、重排、回计划门；发 `CHG` | 计划门 | 计划 §5/§9/§10/§11、报告 |
| 高风险/合规/迁移/破坏性 | `C3` | 重跑专项/全量/回归；更新准出 | 计划门 + 专项评审 | 全部受影响资产 + 风险 |
| P0 冒烟失败/环境不可用 | — | 停轮/排查/升级 | 测试 + 开发 | 计划 §6/§16.1 |
| S1/S2 缺陷或准出失败 | `C2` | 停轮/回归/重评准出 | 测试 + 产品 | 报告/准出/计划 |
| 数据/账号不可用 >4h | — | 造数/换样/暂停 | 测试 | 计划 §7/§16.1 |
| 产能变化 >20% | `C2` | 降范围/拆轮次/延期 | 测试 + 产品 | 计划 §2/§9 |

- **动作**：保持+加缓冲｜重排轮次｜降范围/抽样｜拆轮次｜暂停升级｜重新基线；写理由与影响。
- **同轮回写**：计划 §0/§1.1/§2/§3/§5/§9/§14.3/§15/§16.1 + 交接台账 + 索引 + `activeContext.md`。
- 禁止把 C2/C3 拆成 A/B 绕过计划门；禁止口头变更/先测后补单。
