> **文档结构（本接口域内）**：§1 总览 → §2 契约表 → §3 覆盖对照（接口×维度）→ §4 用例详情 → §5 脚本清单 → §6 覆盖摘要 → §7 评审。  
> **域常青**：跨版本保留；增量改条保 `{API前缀}-{NN}`；**不**因换迭代整文件归档。  
> **落盘**：`测试/接口测试/{NN}-{模块名}接口用例.md`；台账 `测试/接口测试/{NN}-{模块名}接口台账.md`；脚本 `测试/接口测试/脚本/{NN}-{模块}.script.mjs`。小项目可单文件落在同目录（文件名含「接口用例」即可），字段同本模板。  
> **计划驱动**：属计划 §3.2；本轮是否执行看 §3.7 + depth（有文件≠本轮跑）。  
> **单一出处**：维度定义与 depth 见 `规则/轨契约/接口.md` + `规则/专项/多轨质量标准.md` §2.2。

**写法红线（生成即检）**：

1. **禁猜 path/字段**：方法+path+关键参数须来自主读原文或本轮 Network/基线 §3；冲突须标明以何为准。  
2. **契约表齐**：每个必测接口一行；来源=基线已登记或本轮实测。  
3. **覆盖对照禁空**：每个必测接口 × 每个适用维 → 用例 ID 或「不适用+依据」；depth=`standard|full` 时适用维须可执行（或书面不适用）。  
4. **单条可跟做**：前置（账号域/鉴权/数据）｜请求要点（method path + 关键 body/query）｜期望（状态码 + 业务码/信号 + ≥1 关键字段）｜失败判定｜写后回查（写操作）｜清理。  
5. **判定三要素**：仅 2xx ≠ 通过；假成功/200 空壳 = 失败。  
6. **脚本默认**：可脚本化=是 → 同轮产出脚本；=否须理由（语义判定/一次性/依赖未定）。禁只出用例无脚本无理由。  
7. **人类可查**：非作者可按请求要点复现；禁「调用接口成功」类空话。  
8. **ID**：`{前缀}-{NN}`（如 `API-01`）；增量保 ID；排序 成功契约/冒烟 → 鉴权越权 → 边界负向 → 幂等并发。
