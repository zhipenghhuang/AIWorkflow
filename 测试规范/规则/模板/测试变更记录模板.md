# 测试变更记录（CR-{yyyyMMdd-HHmm}-{主题}）

> **定位**：期中变更的**唯一变更单**；用户只提供变化/新文档，或产品在平台确认并给新说明/附件时，AI 负责影响分析、资料/计划/用例/脚本/报告更新与回归安排。  
> **落盘**：`测试/变更/CR-{yyyyMMdd-HHmm}-{主题}.md`；计划 §15 登记一行并链接本文件。  
> **纪律**：先分析影响，再改文档；不重复建用例、不整包重生成、不默认全量重跑；§5 未闭合不得标完成。  
> **三包独立**：产品/开发产物是可选输入；无产品包时用平台备注/附件或用户文档，不阻塞。

### 5.1 执行时机规则

- **默认计划位**：按计划模块/阶段顺序执行；未到该模块不提前跑功能变更。  
- **提前例外**：P0/高风险、阻塞后续模块、不依赖未跑模块且数据/入口就绪、有专门含变更的构建；须在 CR 写原因。  
- **P0 冒烟**：可在下一个构建/阶段边界先跑，不等功能模块位。  
- **禁止**：一条用例中途切换；旧构建跑新变更；多个变更反复打断（按阶段边界合并）。

### 6.1 产品结论分流

| 产品结论 | 测试侧动作 |
| --- | --- |
| 澄清/补充说明（不改 AC） | 更新资料/索引/用例表述/计划依据；不重开计划门 |
| 立即修（含新 AC/文档） | 按本 CR 更新资料/计划/用例/脚本/追溯；开发修复后按新 AC 回归 |
| 下版 | 本期不改；计划 §2.3 排除 + 报告 §7 遗留风险 + 台账状态；不标已修复 |
| 不修 | 同下版 + 理由/接受人 |
| 退回开发 | 重分类为实现缺陷；更新台账/报告统计；走实现缺陷修复+回归 |
| 补充信息 | 保持打开；CR=待补充；列缺什么/谁补/截止；资产暂不改 |

> “立即修”但没有新 AC/文档 → 先确认是否实现缺陷；按现有设计修实现偏差的，归实现缺陷，不建产品变更 CR。
