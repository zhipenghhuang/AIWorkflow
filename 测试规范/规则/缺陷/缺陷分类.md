# 缺陷分类（实现缺陷 / 产品缺陷 · 相符证明）

> 适用：失败行的**分类**（台账 §3「分类」、提交【提交摘要】）。  
> 阻塞/不适用**不是**缺陷类型（环境/样本与「—」）；`待实现` 固定 `实现缺陷`，并计入缺陷批次提交。  
> 单一出处：判定树与相符证明以本文为准；`规则/模板/30-执行与台账/执行台账模板.md`、`规则/缺陷/缺陷协作.md` 按本文执行。

## 1. 判定树（AI 按证据落账，无人工拍板）

1. 有设计文档可引（文件/章节/节点真实可回查）：  
   - **现网 ≠ 资料**（未做 / 做错 / 缺段）→ `实现缺陷`（默认）。  
   - **现网 = 资料**（已按设计做）但仍挡主路径或有风险 → `产品缺陷`（必附相符证明）。  
2. 无设计文档可引：写「无设计文档·现网依据：…」，按 `实现缺陷` 落。  
3. 对照写不清 / 引不到设计 → 默认 `实现缺陷`；差别注明「对照不足，按默认实现缺陷」。

## 2. 相符证明（仅产品缺陷必填）

- 写清现网哪一步/状态/接口与「资料写法」一致（点名业务主键或字段值；≥12 字、禁空话）。  
- 差别句须含「**资料与现网一致，但该口径导致…**」。  
- **必须绑定证据**：`证据：{截图叶名 / 接口字段=值}`，与【实际】/【接口判定】同源；只写结论无证据 = 不合格。  
- 台账「分类」与提交备注（`规则/缺陷/缺陷协作.md` §5）两处同源、口径一致。

**合格示例**：现网订单详情「优惠金额」=0，与《促销规则》§3.2「满减后应付=原价-优惠」一致；但该口径导致已取消订单仍显示优惠 0，用户误以为未享优惠。证据：`order-detail-0.png`；接口 `GET /orders/123` 返回 `discount=0`。  
**不合格示例**：「资料与现网一致，但体验不好」——未点名字段/证据，未说明业务风险。

## 3. 禁则（防误标）

- `实现缺陷` 禁写相符证明；`待实现` 禁标 `产品缺陷`；阻塞/不适用不填缺陷类型。  
- 无相符证明/无证据 → 不得标 `产品缺陷`；按 `实现缺陷` 或补充信息处理。  
- 接口 500/404、与资料不符、缺段 → 属 `实现缺陷`，禁标 `产品缺陷`。  
- 禁「资料有、现网无」用缺口冒充相符；不挡主路径的体验类不落失败、勿硬塞 `产品缺陷`。

## 4. 混合成因（实现偏差 + 设计口径）

- 先按 `实现缺陷` 修实现偏差；修复后复测仍挡主路径/有风险 → 再按 `产品缺陷` 走产品决策。  
- 台账可记「主分类=实现缺陷；关联产品问题=…」，但不得用「混合」跳过实现修复，也不得用实现偏差掩盖产品口径问题。  
- 同一缺陷只落一个主分类；关联问题写入【设计对照】/备注，不另造第三类。

## 5. 流转对象（三包独立）

| 分类 | 提交后指派 | 说明 |
| --- | --- | --- |
| 实现缺陷 | 开发负责人 | 测试等待修复；按 `规则/缺陷/缺陷协作.md` §7 回归 |
| 待实现（方案/AC/计划范围内未交付） | 开发负责人 | **实现缺陷**；必须进入批次/阶段/收尾提交，不得以“未实现”免交；范围外→`不适用` |
| 产品缺陷 | **产品负责人** | **不经开发**；产品判定后按 `规则/缺陷/缺陷协作.md` §7.4 回流 |
| 阻塞/不适用 | 不建缺陷单 | 按台账缺口/阻塞处理，不占缺陷 |

- 产品缺陷提交时必须带 `相符证明 + 证据`；产品判定为“非问题/重复/信息不足”时，产品指派回测试，测试按 `规则/模板/30-执行与台账/缺陷文案模板.md` §8.8 处理。  
- 产品判定为实现缺陷时，产品说明依据并指派开发；测试按实现缺陷回归，不要求产品改 PRD。
