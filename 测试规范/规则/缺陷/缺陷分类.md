# 缺陷分类（实现缺陷 / 产品缺陷 · 相符证明 · 卡点分流）

> 适用：失败行的**分类**（台账 §3「分类」、提交【提交摘要】）；卡点升级时的**通道与责任**判定。  
> 阻塞/不适用**不是**缺陷类型（台账结果可为 `blocked`）；`待实现` 固定 `实现缺陷`，并计入缺陷批次提交。  
> 单一出处：判定树与相符证明以本文为准；卡点升级与平台字段匹配见本文 §0 + `规则/缺陷/缺陷协作.md` §6.0 / `规则/缺陷/缺陷平台适配.md`。  
> **定位**：规范引导 AI 自主分析与用户门禁确认，**提升正确性与效率**；禁止把本文件当成写死「只能测做 / 必须开任务 / 一律 codeerror」的教条。

## 0. 卡点分流（本地消化 / 平台盯办 / 缺陷）

> 与「不轻易阻塞」同向：先打通，再升级；升级时比的是**谁做更合适、平台真实字段怎么填**，不是岗位口号。

### 0.1 决策序（AI 自主；门禁只拦「瞎默认」）

1. **本地优先**：缺数据/样本/账号 → 先造数/换样/换角（有界，见 `多Agent与输出.md`）；短路径能打通 → **继续测，不开平台单**（禁止「指派给测试自己」的空转单）。  
2. **成本比较**：本地很重或不划算时，AI 评估测/开/实施/产品谁更方便（例：造数极繁但开发有种子脚本 → 可拟指开发）。  
3. **成因归类**（语义，平台无关）：  
   - **实现偏差**：现网 ≠ 硬 AC/方案句，或范围内未交付 → 走 **缺陷通道**（实现缺陷 / 待实现）。  
   - **门禁正确仅验收未就绪**：现网 = 资料门禁（邻接用例可佐证），只是缺种子/算例跑不通 → **禁止**开成「改门禁」类实现缺陷；优先继续本地准备；需外力时走 **平台盯办**（类型/指派按 §0.2 探查匹配）。  
   - **可测性/环境/配置外责**：测试无法独立完成（无注入面、环境挂、缺权限且无法自助）→ **平台盯办**，拟责任方与平台类型后确认。  
   - **口径未钉**：无硬 AC、审计落点/契约风格等未写死 → **勿默认实现缺陷**；问产品或用户；确认后再建单。  
4. **不确定就问**：责任人、是否建单、平台类型/优先级选哪个 → 给主推 + 0～1 问（澄清规则）；**禁瞎猜指派与类型**。  
5. **用户确认适配**：本项目平台字段用法（类型枚举、推荐映射）写入实例基线/适配表前须用户确认；已确认则复用，过期或对不上再探再问。

### 0.2 平台匹配（探查 → 匹配 → 确认）

- 先读 `环境基线` 缺陷协作节 + `缺陷平台适配.md`；不足则 **探查实机建单页/API**（单据形态、类型、严重度、优先级、紧急度等以**该项目实际枚举**为准）。  
- 将 §0.1 成因映射到**实机字段**（例：某禅道 Bug 类型含代码错误/配置相关/安装部署/安全相关/设计缺陷/测试脚本/其他……——**仅示例，禁抄成全球唯一表**）。  
- 无独立「任务」模块时，可用 Bug/Issue 等单据盯办，但须选**匹配的类型与指派**，禁止把配置/设计/脚本问题默认成「代码错误」。  
- 匹配不成或字段含义不清 → 问用户；适配结果经确认后落实例，不写进本母版正文枚举全集。

### 0.3 通道与责任（灵活，不写死账号）

| 通道 | 何时 | 平台 | 责任方怎么定 |
| --- | --- | --- | --- |
| 本地消化 | 测试短路径可打通或继续准备更优 | 不开单 | 测试执行准备 |
| 平台盯办 | 需外力解决卡点（数据种子、环境、可测性、配置等） | 按 §0.2 实机单据+类型 | 基线有策略则用；否则 **问用户**（可测/可开/可产品） |
| 缺陷（实现/待实现） | 现网≠硬依据或范围内未交付 | 缺陷/Bug 通道；类型偏实现类 | 默认开发负责人（基线）；产品缺陷见 §5 |
| 口径确认 | 无硬 AC / 落点未钉 | 问清后再建；或设计/产品类类型 | 问用户或产品 |

- **待实现**仍须进缺陷批次（实现缺陷），不得用「阻塞/盯办」逃避。  
- 平台盯办项关闭后 → **必须重跑**原用例；通过才清卡点；仍失败再按实现偏差开/转缺陷。

## 1. 判定树（失败行分类 · AI 按证据落账）

1. 有设计文档可引（文件/章节/节点真实可回查）：  
   - **现网 ≠ 资料**（未做 / 做错 / 缺段）→ `实现缺陷`（默认）。  
   - **现网 = 资料**（已按设计做）但仍挡主路径或有风险 → `产品缺陷`（必附相符证明）。  
   - **现网 = 资料门禁**且问题仅为验收数据/种子未就绪 → **不**落实现缺陷催改门禁；回 §0 本地消化或平台盯办。  
2. 无设计文档可引：写「无设计文档·现网依据：…」。  
   - 默认可按 `实现缺陷` 落（三包对齐：测试不擅自标产品缺陷）。  
   - **例外面**（安全增强习惯、HTTP/业务码风格、审计落点等**无硬句**）→ 先走 §0「口径未钉」（问用户/产品），**禁止**用「行业惯例」唯一支撑就交实现缺陷。  
   > 开发若复核为需求缺口/设计口径不明，由开发出评估单交**产品终审**改判；产品确认后按 `缺陷协作.md` §7.4 回流。  
3. 对照写不清 / 引不到设计 → 默认 `实现缺陷`；差别注明「对照不足，按默认实现缺陷」；若实为口径争议 → 升级问用户，勿硬交。

## 2. 相符证明（仅产品缺陷必填）

- 写清现网哪一步/状态/接口与「资料写法」一致（点名业务主键或字段值；≥12 字、禁空话）。  
- 差别句须含「**资料与现网一致，但该口径导致…**」。  
- **必须绑定证据**：`证据：{截图叶名 / 接口字段=值}`，与【实际】/【接口判定】同源；只写结论无证据 = 不合格。  
- 台账「分类」与提交备注（`规则/缺陷/缺陷协作.md` §5）两处同源、口径一致。

**合格示例**：现网订单详情「优惠金额」=0，与《促销规则》§3.2「满减后应付=原价-优惠」一致；但该口径导致已取消订单仍显示优惠 0，用户误以为未享优惠。证据：`order-detail-0.png`；接口 `GET /orders/123` 返回 `discount=0`。  
**不合格示例**：「资料与现网一致，但体验不好」——未点名字段/证据，未说明业务风险。

## 3. 禁则（防误标）

- `实现缺陷` 禁写相符证明；`待实现` 禁标 `产品缺陷`；阻塞/不适用不填缺陷类型（实现/产品）。  
- 无相符证明/无证据 → 不得标 `产品缺陷`；按 `实现缺陷` 或补充信息处理。  
- 接口 500/404、与资料不符、缺段 → 属 `实现缺陷`，禁标 `产品缺陷`。  
- 禁「资料有、现网无」用缺口冒充相符。  
- **体验类边界**：不挡主路径、且无合规/资金/数据安全风险的体验/文案/观感问题 → **不落失败、不建缺陷单、勿硬塞 `产品缺陷`**。若用户/产品主动要求改口径或排期优化 → 转产品侧 `change`/需求池受理（对话或文档即可），**不占用缺陷通道冒充产品缺陷**；台账可记「建议产品受理：…」但不改本行分类为产品缺陷。  
- **禁**未探查平台枚举就套默认「代码错误」类取值；**禁**把门禁正确/口径未钉/测未准备伪装成实现缺陷；**禁**为进平台把本当 `blocked`/本地准备的项改标 `fail`。

## 4. 混合成因（实现偏差 + 设计口径）

- 先按 `实现缺陷` 修实现偏差；修复后复测仍挡主路径/有风险 → 再按 `产品缺陷` 走产品决策。  
- 台账可记「主分类=实现缺陷；关联产品问题=…」，但不得用「混合」跳过实现修复，也不得用实现偏差掩盖产品口径问题。  
- 同一缺陷只落一个主分类；关联问题写入【设计对照】/备注，不另造第三类。

## 5. 流转对象（三包独立 · 指派取基线或问用户）

| 分类/通道 | 提交后指派 | 说明 |
| --- | --- | --- |
| 实现缺陷 | 开发负责人（基线；不明则问） | 测试等待修复；按 `缺陷协作.md` §7 回归 |
| 待实现（方案/AC/计划范围内未交付） | 开发负责人（基线；不明则问） | **实现缺陷**；必须进入批次提交；范围外→`不适用` |
| 产品缺陷 | **产品负责人**（基线；不明则问） | **不经开发**；按 `缺陷协作.md` §7.4 回流 |
| 平台盯办（非实现偏差） | **问用户或基线策略**（可开/可实施/可产品） | 类型/单据按 §0.2 实机匹配；关闭后重跑 |
| 本地消化 / 不适用 | 不建单 | 测试继续准备或台账缺口说明 |

- 产品缺陷提交时必须带 `相符证明 + 证据`；产品判定为“非问题/重复/信息不足”时，产品指派回测试，测试按 `规则/模板/30-执行与台账/缺陷文案模板.md` §8.8 处理。  
- 产品判定为实现缺陷时，产品说明依据并指派开发；测试按实现缺陷回归，不要求产品改 PRD。  
- 无缺陷平台 / `export` / 仅文档交接：分类与相符证明规则不变；提交包或交接正文写清类型与指派对象，禁因无平台改口令或跳过分类。
