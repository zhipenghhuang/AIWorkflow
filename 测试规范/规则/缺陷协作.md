# 缺陷协作（口令 · 确认 · 提交/回归）

> **步骤顺序**以 `../workflows/defect.yaml` 为准；角色见 `../agents/bug-agent.yaml`。不跨轨**通读** `多Agent与输出.md`（指针明确的单节点读除外，如 §2.2 浏览器纪律/退程）。  
> 真值：`环境基线.md` §13。本文定确认门与备注骨架；平台差异经 §13 适配，内置 zentao 见 §4。  
> 本轨专规**读够再用**（可按子类先看 §7/§5 等，但勿因省读漏确认门/骨架）；提交 steps **十段齐**（§5）且过转开发自问；对话收口写总结；备注全文放确认包。close/activate/resolve 取值按 §13 映射。

## 0. 启动

```text
route=workflow:defect | step=… | role=bug-agent | next_action=LOGIN|LIST|SUBMIT|DEDUP|REGRESS|AWAIT_CONFIRM|…
```

收口须带总结性结论说明；禁只回「已提交/已关闭」。

## 1. 前置

读 §13（provider、凭据、默认项目、提交方式、适配定义），按「提交方式」执行：

| 提交方式 | 适用 | 要点 |
| --- | --- | --- |
| `api`（默认） | 平台开放接口 | 按 §13「适配定义」端点/字段执行；内置 zentao 见 §4 |
| `browser` | 仅 Web 界面 | 用基线 §8 浏览器 MCP 操作（端口未开 → 按 §8.1「拉起命令」自行拉起，见 §8 生命周期）；查重→建单→传证仍按 §5 |
| `export` | 不允许代提交，或平台不可读写 | 仅提交：AI 出提交包（标题＋steps＋证据清单）交用户；用户提交后回填编号 |

未适配或方式未填：一问补齐 §13；补不齐默认 `export`（不直连、禁猜接口）。  
provider 生态（可选）：Jira → mcp-atlassian / 官方远程 MCP；GitLab/GitHub Issue → 对应 MCP；TAPD 无成熟适配 → 按 §13 自适配 + `export`；清单见 `能力/00-能力注册表.md`。

| 子类 | 识别 | 动作 |
| --- | --- | --- |
| 回归 | 「回归」+（指派给我\|已解决\|平台）+Bug/缺陷；或「禅道/平台」+指派给我+（回归\|验证\|复测） | LIST→**读内容/备注分拣**（§7）→按类复测或澄清→拟写回→一次确认 |

## 3. 确认门（只认 YAML）

`hitl: confirm_remark` + `hitl_when: remark_writeback`：拟关/激/解决/标重复或回归写回 → 先列 id + 结论 + **备注全文**，确认后执行。条件不满足则跳过。执行收尾交缺陷见 §6。

## 4. 平台适配与 API（内置 zentao）

其它 provider：按 §13「适配定义」补端点/字段/取值后按同骨架执行；未适配先补 §13。

- 通用：状态变更与 comment **同轮**；禁删缺陷对象；禁密码/绝对路径/用例路径入备注或 steps。  
- 写平台文本版式（steps/备注均适用；脚本拼装同规）：块内行间用 `<br>` 相连（拼装=`lines.join('<br>')`），块间单个 `<p></p>`；**禁**每行外包 `<p>`（`'<p>'+l+'</p>'` 式→渲染成每行一空段）、`<br><br>`、`\n\n` 与连续空段；文本/markdown 同构（行间单换行、块间至多一空行）。写入前按 payload 自检，违者改正再写。  
- zentao 内置：Token `POST /api.php/v1/tokens`；禁浏览器登录页；建单 REST v1（`openedBuild=trunk`；severity/pri 为 `"1"`…`"4"`）。  
- zentao 附件：`POST /api.php/v2/files`，字段名 **`file`** + `objectType=bug` + `objectID`（禁 v1）；**非 ASCII 文件名须按 UTF-8 原字节写入 multipart `filename`**（防 .NET 自动转 MIME 编码致乱码）；**回查用 `GET /api.php/v2/files/{fileId}` 核对 `objectType/objectID`**（实测：v1 缺陷详情 `files` 字段可为空数组，**不得**据此判未挂载；挂载断言以 v2 元数据或缺陷页附件区为准）；失败重试 ≤1，禁反复重传。

## 5. 提交骨架（详细 · 十段齐）

> **同源**：`steps` 正文 = 台账 §3 问题详情（失败/待实现）按本节改写成平台备注格式；**禁**另造第二套空壳话术、禁往 steps 塞未在台账/本轮实测出现的套话。  
> 备注格式按 §13「备注格式」（html / markdown / text）；下列以 HTML（zentao 默认）为准，其它格式同构。  
> 质量目标：开发只看平台单即可**定位对象、跟做复现、看见观测值、知道怎样算修好**（§5.1 自问）。

### 5.0 字段与枚举（建单）

| 项 | 要求 |
| --- | --- |
| `title` | = 台账「问题标题」；格式 `{页面/模块}：{动作，偏差，后果}`；**≤56 字**；禁只写 caseId /「有问题」 |
| `severity` / `pri` | API 传字符串 `"1"`…`"4"`（禁中文枚举如 `3-中等`）；与台账严重程度/优先级两档一致（`1-致命`…`4-轻微` / `1-紧急`…`4-低` → 取首位数字） |
| `openedBuild` | zentao 固定 `trunk`（禁 `0`/空） |
| `type` | 默认 `codeerror`（站点另有约定从其） |
| 附件 | 失败须 ≥1 张钉断言点截图；流程见 §4（v2 + 回查） |

### 5.0.1 十段结构（缺段不得提交）

首行 `<b>{caseId} {caseName}</b>`，其后各块以 `<b>【…】</b>` 起；块间仅一个空段（HTML 用单个 `<p></p>`）；块内行间用 `<br>` 相连，**禁**段内每行外包 `<p>`（`'<p>'+l+'</p>'` 式→每行一空段）、禁连续多个空段；拼装与写入前自检见 §4。

| # | 块 | 必填要点 |
| ---: | --- | --- |
| 1 | **【提交摘要】** | 四行齐：执行结果；缺陷类型（实现缺陷\|产品缺陷，见 `缺陷分类.md`）；问题标题；`严重程度：…；优先级：…`。可附模块·路由一行 |
| 2 | **【环境】** | `环境URL=`；账号**角色**（**禁密码**）；版本·构建（可知则写） |
| 3 | **【测试数据/业务主键】** | 页面原样**完整业务码**/关键主键竖排（`列名=全码`）；足以换环境打开同一对象；禁短 Id 假号、禁「未抄全码」套话 |
| 4 | **【问题】** | 页面/菜单锚点 + 对象全码 + 动作 + 偏差与业务影响（≥2 句；禁无主语「操作后/查询后」起句） |
| 5 | **【复现】** | 编号步骤一般 ≥3；含侧栏「一级」→「二级」→打开「全码」→按钮；**一步一事**（禁同一步「；另试/并且」混第二路径） |
| 6 | **【实际】** | 前端编号 ≥2 条肉眼观测（与复现同序可对读）；截图叶名独立成行且钉断言面；接口细节进第 8 块，此处可写「见【接口判定】」 |
| 7 | **【预期】** | 前端编号 ≥2；可验收行为+业务含义；与【实际】/复现同序对应；禁空「应正常」 |
| 8 | **【接口判定】** | 有相关接口则必填：方法+路径、关键参数实际值、码/消息、回查字段=值、判定句；本轮无接口写「本轮无相关接口」 |
| 9 | **【设计对照】** | 有设计文档：资料 `{设计输入目录}《{文件名}》§{章节}「{节点}」`；`原文：`（逐字片段≥8 字，取自被引文档）；`设计应然：`；`现网/本轮：`；`差别：`；`本条以…为准`。要素间硬空行/`<br>`，禁分号粘连；文件/章节/要点**真实可回查**（编造/越章节=先改引）。禁仅 `…用例.md`、禁空泛。**产品缺陷**另加 `相符证明：`（见 `缺陷分类.md`）；`实现缺陷` 禁写相符证明。**无设计文档**：`无设计文档·现网依据：`{本轮 UI/接口要点}，禁编造引用后反复改 |
| 10 | **【技术附记】** | `route=`、`落点=` 各行；有接口可摘要 `code=`/`响应：字段=值`；`依据=`、`判定=`（须有据）；UI≠Network 时加 `对账=`；**无密钥/无绝对路径/无用例路径** |

### 5.0.3 禁止（提交内容）

| # | 禁止 | 正确 |
| ---: | --- | --- |
| 1 | steps 用简陋「步骤/结果/期望」三段式或缺十段任一段 | 按 §5.0.1 十段齐（待实现不强制截图，其余同构） |
| 2 | 不查重即建单；失败无截图；v1 传附件 | 先查重 → 建单 → v2 传证 → 回查挂载 |
| 3 | 标题只写 caseId / 空话；severity/pri 用中文枚举 | 问题标题格式+≤56 字；API 用 `"1"`…`"4"` |
| 4 | 【复现】无菜单路径/无全码；同一步混多路径 | 侧栏一级→二级→全码→按钮；一步一事 |
| 5 | 【实际】/【预期】空形容词（「异常」「不正确」「应正常」）或与复现脱节 | 可见原文/数值；编号同序对读 |
| 6 | 【设计对照】分号粘连 / 仅用例.md / 编造章节原文 | 硬空行+真实可回查指针；无文档走「无设计文档·现网依据」 |
| 7 | 密码、Token、绝对路径、用例/台账路径写入 steps | 环境只写 URL+角色；路径类不进平台 |
| 8 | 有接口证据却无【接口判定】，或 UI 段堆 API 术语 | 接口进第 8 块；UI 段写产品可观测现象 |

### 5.1 转开发自问（提交前 · 非另造 hitl）

答不上则先补测/补写，**禁**用固定口号凑详细：

| # | 自问 |
| ---: | --- |
| Q1 | 凭【测试数据/业务主键】能否在本环境打开同一对象？ |
| Q2 | 他人只靠【复现】能否走到同一界面状态？ |
| Q3 | 【实际】是否为本轮页面/弹窗上的值或文案原文？ |
| Q4 | 【预期】是否写清怎样算修好（可验收行为）？ |
| Q5 | 结论若依赖接口，【接口判定】是否已有 `字段=值`？ |
| Q6 | 设计指针的 §/节点/`原文：` 是否已打开被引文档逐字命中？ |

失败须上传≥1 张对准断言点截图并**按 §4 方式回查挂载（v2 元数据）**。

```text
【缺陷协作·提交结果】

   - #{id} {标题}

   - {caseId} 提交失败：{原因}；排除：{原因}
```

无成功条目 → 不输出第 2 块，改为一行说明。本块置入【任务收尾】第 1 点；第 2～6 点按 AGENTS §5。

## 6. 执行收尾衔接

入口：**计划 §11 预授权** 或 工作流 §4 用户确认交平台。范围：失败及用户指定待实现；阻塞默认不交。  
流程：查重→§5（十段齐+§5.1 自问）→§5.2。询问句式（在入口步只问一次，本轨不重问）：「本轮拟提交 N 条缺陷（失败 X + 待实现 Y），是否确认提交？（可排除条目 / 取消）」

### 6.1 计划驱动提交策略

- 计划 §11 选择「发现即提交」且计划 §0 状态=已确认/执行中/待关闭 → 执行中查重后**直接提交**，不再逐条问；仍须十段齐+证据+回写台账；收尾列提交清单。**建单不触发 `confirm_remark`；关闭/激活/解决等平台状态回写仍按 §3 确认**。  
- 「批末提交」→ 阶段末汇总一次；「收尾确认」→ 按门3；「仅导出」→ AI 出提交包，用户提交后回填编号。  
- 未配置平台/未授权 → 默认 `export`，禁猜接口；计划外提交仍按门3。  
- 同因不重复提交；同批修复可合并一次回归。  


## 7. 回归（平台写回一次确认）

复测范围与升级：按 `工作流.md` §3.1「修复后回归（默认口径）」——默认=原单复测+冒烟子集；影响面组建议制（用户点头才跑）；高风险/连环缺陷提示升级。

### 7.0 计划驱动连续回归

- 优先 P0-Smoke 脚本 + 受影响模块用例；每次修复后立即回归，不等批末；范围=原单+冒烟子集+影响面组（计划 §10）。  
- 结果就地覆盖台账/证据，只留最新；报告 §5.2 汇总轮次/通过率/遗留。  
- 高风险/连环缺陷提示升级（模块局部全量/扩大邻接回归），用户确认后执行；同批修复合并一次回归。  
- 平台单回归（本轨）与计划内功能回归分轨：本轨写回平台状态，计划回归写台账/报告，不混用结论。  

### 7.1 拉单范围（先指派，不先过滤已解决）

| 口令 | LIST 默认范围 |
| --- | --- |
| 「指派给我 / 我的 / assigntome」+（回归\|验证\|复测）或仅「回归」+平台未收窄 | **指派给当前账号的未关闭单**（含 active / resolved）；**禁止**仅因 `status≠resolved` 整批丢弃 |
| 点名「回归已解决」 | 收窄为 `status=resolved`（可再叠加指派给我） |
| 点名单号 | 仅这些单 |

每条拉单后**先读再动手**：标题、steps、severity/pri、status/resolution、附件、**近期备注/讨论**（`solutionChannel=manual` 时备注读不全 → 先请用户补关键备注再分拣）。

### 7.2 分拣（大部分走正常回归；未解决看内容）

| 信号（状态 ∪ 备注/指派意图） | 处置 |
| --- | --- |
| `resolved`（多数） | **正常回归**：复测 → 拟 close / activate（§8.1/§8.2） |
| `active`，但备注/讨论像「已修请验 / 请回归 / 复测一下」，或步骤表明待验证、疑似忘点解决 | **按回归复测**。通过：确认包拟 `resolve(fixed)`+`close`（或「请补点解决后再关」若 API/权限不许代 resolve），备注用 §8.2 并写明「本轮平台仍为激活」。未通过：拟 activate 或保持 active + §8.1 |
| `active`，备注像「对测试有疑问 / 请澄清步骤或数据 / 请换样再测」 | **按备注意图**：补充复测、回备注澄清（§8.4），或一问用户；**不默认 close** |
| `active`，无验证/疑问意图（纯开发待修误指派等） | LIST 标「非回归候选」+一句依据；一问排除或转开发待修；禁当已解决硬关 |
| 读完仍无法判定 | 列入无法判定，一问后再测 |

