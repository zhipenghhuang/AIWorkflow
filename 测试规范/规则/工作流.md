## 1. 总则

### 1.1 计划门与三门 · 落盘

见 `../AGENTS.md` §0.1（计划门＋门1～3；条件门：`hitl_when` 不满足则跳过）。正式资产只写现行有效状态（AGENTS §0.6）；落盘按 `规则/模板/`。

### 1.2 测试分级（T0～T3 · 防过度/不足）

| 级别 | 典型 | 计划 | 执行 |
| --- | --- | --- | --- |
| T0 补丁/热修 | 小改、单模块 | 轻量计划（≤1 页） | P0 冒烟 + 影响面 + 已脚本化回归 |
| T1 模块 | 功能/模块 | 轻量计划 | 模块功能 + 接口（如适用） |
| T2 版本 | 发布级 | 完整计划 | P0～P9 按计划 |
| T3 高风险 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 全量 + 性能/安全/兼容 |

T0/T1 不强行填完整 17 节；范围/类型/轨道/执行矩阵/准出/风险必须写清。发布列车/大版本 ≥1 次功能全量；补丁不强制全量。

### 1.3 产物与过程（相对项目根 · 正式并列轨）

> **产物根：唯一 `测试/`**——项目根仅 `环境基线.md`、`activeContext.md`；项目文档进 `测试/资料/项目文档/{版本或主题}/`，样本/测试数据进 `测试/资料/测试数据/`；跨角色交接包放 `测试/交接/{HO-ID}/`（台账 `测试/交接/交接台账.md`），收到的包放 `测试/资料/交接/{HO-ID}/`；**禁止在项目根新建测试计划/用例/台账/脚本/证据/项目资料**；下表路径均相对项目根。  
> **资料收取/对照/归档**：以 `规则/文档治理.md` 为准；新资料先分析分类 + 与同主题/同版本旧文件做覆盖对照，输出候选，**用户确认后**才改名/登记/标记失效/归档。  
> **归档（分轨）**：换代/结项/版本关闭（用户确认后）→ 功能/接口/探索式/发布前资产分别进**各自轨** `_归档/`；失效资料进 `测试/资料/_归档/`；计划/报告/CR/交接进 `测试/_归档/{yyyyMMdd}-{版本}/`；当前 `测试/测试计划.md` 不移动；**禁**把各轨用例整包丢进根 `_归档/`。多版本并行（罕见）→ `测试/{版本}/` 另起一套、单点随其目录。  
> 探索式 / 接口 / 发布前：边界见 `规则/轨契约/`。  
> **功能测试模块规模阈值**：模块数 ≤3 且文件 ≤20 时保持 `测试/功能测试/` 全部同级；超过时按模块建子目录（`{模块}/用例-…`、`台账-…`、`评审-…`、`分析-…`），证据仍集中 `测试/功能测试/证据/{模块}/`。阈值写入计划 §3.7/环境基线 §2.1，不改变现有轨契约。

## 2. 生成

> **资产生命周期（轻量 · 不搞全量资产库）**：**P0-Smoke 脚本**跨版本保留/更新；**迭代功能用例**按本轮新增/更新，不强制复用旧用例；接口确定性脚本只更新受影响 endpoint；**一次性不脚本**；旧模块替换才单项归档。**不维护全量回归资产索引**；稳定冒烟只登记 `测试/00-稳定冒烟清单.md`（≤12 条）。日常小修 → §2.1.1 专项增量；执行结果更新 → §3.1 续跑/回归。

### 2.1 功能测试资产

- **口令**：生成用例 / 生成测试资产 / 阶段一 等  
- **输入**：已点名主读或门1 选定 + 设计输入 + 可探查现网 + **需求模型/轻量分析短表**（需求理解/变更点/影响面/口径待探查/oracle/歧义；见 analyze，主读已点名也不省）+ **现行测试计划**（范围/测试类型/轨道/编排；缺或超范围 → 先按 plan 步轻量补）+ `测试/00-稳定冒烟清单.md`（有则读；只看 P0-Smoke 脚本）  
- **动作**：轻量分析（可与生成同轮）→ 按计划范围与模板产出基线/用例/台账骨架（**计划驱动按 §3.2 资产清单逐项生成/登记**；结果=未执行；**写法红线见用例模板头**）→ **逐条判可脚本化并落 §1.2 清单**（`规则/专项/脚本执行.md` §1）→【生成收尾】  
- **大规模生成**：≥3 模块且 ≥40 条 → 按 `规则/专项/多Agent与输出.md` §1.5 分片（一模块一子代理只写草稿；编排统一 ID/模板/排序并合并，跑覆盖三闸）；单模块/小批直做。  
- **能测尽测**：方案未写死数值/细则时，**仍须生成行为与流程用例**；预期可写「以本构建现网实现值为准」。禁止因「文档待冻结 / 交给开发定」而整段不生成或不测。  
- **框架闸**：  
  1. **完稿自检**：按生成代理（testcase-agent）清单逐项过——独立可执行/前置三件套/编号对齐/判定面/负向边界/影响面逐点/视觉基础/映射无空行/引用可回查/冒烟集齐/排序/清理与提示/七维自查/章节回执/引用抽验；缺项先补，禁带缺口落盘。  
  2. 有依据写清；设计来源可回查或标明现网依据。  
  3. 生成期结果列为「未执行」（「待实现」仅作执行终态，且仅限能力未交付——见 §3.0）。  
  4. **覆盖（准确度前置 · 三闸）**：落盘前须完成；缺任一项不得称「已覆盖」。细则如下。

#### 2.1.0 覆盖三闸（功能全量 / 功能专项 · 不可让）

> **定位（不可让）**：功能全量是迭代准出主轨——本期全量**只生成一次**，按『**一遍过 · 宁多勿漏**』生成；**影响面（逐邻接点）与视觉/UI 基础必须覆盖**；接口/探索式/发布前为补充轨。  
> **强制范围**：§2.1 功能全量与 §2.1.1 专项。探索式/接口/发布前（§2.2～§2.4）为软要求：须写覆盖/缺口句，不强制完整映射表。

| 闸 | 要求 |
| --- | --- |
| **① 可测承诺抽取** | 从主读（+有界对照）及**轻量分析短表**抽点。文档出现则须入清单：**验收/GATE**、**主成功路径**、**状态与关键非法跃迁**、**权限/数据域**、**明确异常与阻断**；并**须纳入（一遍过目标，宁多勿漏）**：**相对上版/相对范围的变更点**、**供给邻接与回归影响面（逐邻接点）**、方案明确不做的负向边界（可轻量）。某类文档未写 → 映射表说明列写「文档未声明」，**不得当作免测**（权限至少角色冒烟或用户接受不测，见下）。**章节回执**：主读逐章核对——每章「设计点→映射」或「无设计点」；**缺章不得称已覆盖**。 |
| **② 设计点→用例映射** | 落盘用例文件 `## 3. 设计点覆盖映射`（见用例模板）：每点一行 → 用例 ID（可多对多）或「不适用」+依据；**禁止空映射**。阻断主链 / 验收 GATE 标 **P0-Smoke**（冒烟闸判定行，见 `规则/专项/多Agent与输出.md` §1.1.1）；高风险点标 **P0-HighRisk**——均须有对应用例；P0（两档）**覆盖缺口**先问用户是否接受不测。影响面/变更点行须能指到用例或「不测+理由」。 |
| **③ 缺口显式（三分类）** | 收尾「缺口」必须按类写清，**禁**把「方案未写死数字」写成「不测」：① **覆盖缺口**=未映射或用户接受不测；② **口径待探查**=方案留白、开发已/将落地，**已有用例**，执行时先读现网实现值再断言；③ **环境/交付缺口**=入口不可达或能力未交付（执行期 blocked/pending）。「覆盖」句须可对照映射表（如「映射 N 点，P0 全覆盖，影响面 i 点全落，视觉基础已含，覆盖缺口 k，口径待探查 m」），**禁**空泛「已全覆盖」。 |

**视觉/UI 基础**（每受影响页面 ≥1 条或并入相邻用例预期）：布局无错位/遮挡；文案与数值无截断/缺失；按钮/图标状态正确；空态、加载、错误提示齐备；样式与既有页面一致（不追求像素级——像素级归项目视觉回归）。装配 visual-reg（含免装配的 Playwright 截图断言）时，可对受影响页作截图抽查（对比基线图；以「有疑点才深挖」为度）。

**权限未声明**：说明列可写「文档未声明」，但须 **≥1 条可用角色冒烟（建议 P1-Core）**，或收尾写明用户接受本轮不测权限——二选一，禁止静默跳过。

设计技法（按需选用，不必照本宣科）：等价类 / 边界值 / 判定表 / 状态迁移 / 错误推测；写操作与字段级必含负面与边界。

**轻量分析短表**（功能全量/专项生成前必有；可与 generate 同轮；禁长文）：落 `测试/功能测试/分析短表.md`（过程位；生成期消费，收尾报路径）。至少含：需求理解（来源/目标/角色/范围/非目标/关键规则/状态/权限/oracle）｜理解确认（已确认/待确认+日期/人）｜变更点（增/改/删/转版）｜影响面（直接/邻接/回归）｜口径待探查（阈值/容差/维度/权限等）｜风险｜建议测试类型｜歧义/冲突/GAP/假设｜TP→用例或处置｜置信度。主读已点名**不免除**本表；仅免除「再问主读」。需求/测试依据建模细则见 `技能/test-basis-analysis/SKILL.md`。

**【生成收尾】与 AGENTS §5【任务收尾】同骨架（6 点）；第 1 点「汇报」= 结论说明体一整段（禁子 bullet）。** 主读/计划/落盘/覆盖/自检/缺口等工程明细写入第 2～5 点或汇报段正文，不另起汇报子项。

### 2.1.1 修改方案专项

增量 `测试/功能测试/S-{NN}-…-专项.md` + `测试/功能测试/S-{NN}-…-执行台账.md`；按 `规则/模板/30-执行与台账/专项索引模板.md` 在 `测试/功能测试/00-专项索引.md` 登记一行（状态列供人工追踪：草稿/启用/停用，不影响执行）。覆盖三闸（§2.1.0）只对**增量章节**设计点；映射表只含本专项点。计划/报告以**追加节**登记（增量范围/准出；不重开计划门）。汇报用【生成收尾】，写清 `S-*`、方案名、增量条数与映射点数。

### 2.2 探索式用例

### 2.6 期中变更（计划增量 · 用户只给变化）

口令：「本期变更 / 计划变更 / 增量变更 / 新文档更新测试计划 / 产品缺陷已确认 / 产品给新说明或文档 / 同步产品变更」。**不新开整期计划**；在当前 `测试/测试计划.md` 上增量更新。三包独立：产品/开发产物是可选输入；无产品包时用平台备注/附件或用户文档。

1. **建 CR**：`测试/变更/CR-{yyyyMMdd-HHmm}-{主题}.md`（模板 `规则/模板/30-执行与台账/测试变更记录模板.md`）；CR 是唯一变更单，计划 §15 只登记摘要。  
2. **分类**：A 澄清/无范围变化｜B 功能增量/修改（同范围）｜C 实质变更（范围/准出/排期/缺陷策略）｜D 缺陷驱动。产品确认带新 AC/文档 → **D+B**（同范围）或 **D+C**（实质变更）；纯澄清不改 AC → A；不得只算 D 而跳过用例/计划更新。  
3. **影响分析**：按 CR §3 写全：模块/页面、接口、用例、脚本、数据/环境、回归范围、覆盖点、资料/文档、计划/报告、追溯/评审、接口/探索式/发布前资产。  
4. **资料收取/对照**：新文档放入 `测试/资料/项目文档/{版本或主题}/`（通用文档可平铺 `项目文档/` 根），按 `规则/文档治理.md` §3 分类 + 覆盖对照；输出候选，**用户确认后**才改名/登记/标记旧文件失效；只有全量替代/全量覆盖/重复才列归档候选（落 `测试/资料/_归档/`），部分覆盖/增量补充保留旧文件；更新 `测试/资料/资料索引.md`；用例/台账/报告的设计指针同步替换。  
5. **更新计划**：按 CR §4 更新 §0/§1/§2/§3.1/§3.2/§3.7/§5/§7/§8/§9.2/§10/§11/§12/§14.3/§15/§16.1；只改受影响项。  
6. **更新资产**：只改受影响用例/脚本/数据/接口/探索式/发布前资产；保留 ID/路径；P0-Smoke 变化才更新稳定冒烟清单；不重复建、不整包重生成。  
7. **门禁**：C 类 → 计划状态=变更中 + 计划门；A/B 类 → 就地更新，不重开计划门；D 类 → 缺陷轨，范围变化才回计划；D+B/C 按 B/C 门禁。**不新增确认门**。  
8. **执行时机**：默认等计划模块/阶段位；提前仅限 P0/高风险、阻塞后续、独立且数据/入口就绪、有专门含变更构建；P0 冒烟可在构建/阶段边界先跑；执行前核构建含变更；禁一条用例中途切换/旧构建跑新变更/多个变更反复打断。  
9. **执行**：P0 冒烟脚本 → 变更用例 → 影响面组（3～8）；高风险/连环才升级局部全量；不默认全量重跑。产品确认新 AC → **按新 AC 回归**，禁用旧预期判通过。  
10. **收尾**：按 CR §5 逐项标「已更新/不适用/待补+责任人+截止」；未闭合不得标 CR 完成；更新计划 §0/§16.1、报告 §2/§3/§5/§6/§7/§9/§10、activeContext；用户按计划验收。  

### 2.7 协作交接（提测/报告/缺陷/变更）

- **接收**：提测/需求/报告/变更包先走 `workflows/handoff.yaml` receive：核对清单/版本/构建/阻断缺口 → 接受/有条件/退回 → 填写回执 → 更新计划 §0/§1.1/§16.1 与台账；未签收不得开跑或把结果判为通过。

- **变更**：C0 就地更新；C1 更新计划/用例/脚本并发 `CHG`；C2/C3 回计划门并重基线；禁止把 C2/C3 拆成 A/B 绕过；变更后同步 `交接台账.md`、计划 §0/§15/§16.1、索引、`activeContext.md`。

## 3. 执行

门2 确认后：功能/探索式读 `规则/专项/多Agent与输出.md`（执行形态四档取档，含脚本档）；接口轨单 Agent（见轨契约）。**计划驱动多轨 → §3.6**（计划 §9.2 编排；阶段内仍按轨契约）。**功能全量/专项按计划轮次执行**（`测试/测试计划.md`；缺则轻量补）：先过「数据准备 → 冒烟」前置（`规则/专项/多Agent与输出.md` §1.1.1）——先集中备数据（⓪）再跑 P0-Smoke 冒烟行，未全绿按环境/产品分流（停轮或阻断面）后再进全量。执行中不向用户刷用例级明细（终稿 §4 除外）。

### 3.0 口径探查与结果态（功能全量/专项 · 不可让）

1. **实施后必测**：方案将数值/细则交给项目落地时，执行以**本构建现网实现**（页面说明、配置、接口、计算版本）为断言尺子；与方案意图冲突 → 失败或拉产品确认，**不得**因「方案未写死」跳过。  
2. **口径待探查**：开跑该条前先读出实现值，写入台账摘要或基线增量，再判定通过/失败。  
3. **`待实现`（pending）**：仅当能力未交付或入口/功能不存在。**禁止**「系统已有规则/阈值，仅文档未写」→ pending。  
4. **`阻塞`**：外部依赖穷尽自打通仍不可达（互异手段≥2 且总尝试≤3；缺数据须先造/换，细则见 `规则/专项/多Agent与输出.md` §1.3-4）。与 pending 勿混用。**blocked 四问**：能造数/换样？能换入口/角色？是否被测缺陷（→fail）？互异手段≥2 且总尝试≤3？**终态对照**：缺数据/样本→造/换；菜单无入口且无接口→pending；菜单有入口但页面/接口 404/500→fail；登录/网关/环境级不可用且穷尽→blocked。  

### 3.1 功能专题 / 专项

口令：执行/跑/专题/阶段二；或执行专项 `S-{数字}…`。

> 「回归」三义：**功能轨回归**（本轨「回归/重跑」＝重测既有用例）｜**平台单回归**（缺陷轨 §7，指派给我/已解决）｜**轮次回归**（R2+ 轮——修复后按轮次复跑，范围见下条默认口径）。

- **续跑（「继续」）**：沿用 `DraftPath` 与门2 上次确认，接未完成；不重跑已有终态；缺终态先对账再补写/定点重测（**禁未对账重复写操作**，见多Agent §2.1）。  
- **回归执行（「回归 / 重跑 {全量|模块|条目}」）**：按点名范围**重测既有用例**；结果**就地覆盖**台账与证据（执行时间更新为最近一轮）；**只保留最新确认结论，不写过程**；细则见 `规则/专项/多Agent与输出.md` §2.1。  
- **修复后回归（默认口径 · 成本自适应）**：**优先 P0-Smoke 脚本 + 受影响模块用例**；**默认只跑「原单复测 + 受影响模块冒烟子集」**（两件最廉价：多为已脚本化 → Playwright 0 token）；**影响面组（3~8 条）= AI 依开发回写的【改动范围/影响面】给出建议，用户点头才跑**；**高风险修复**（跨模块/契约/数据/权限/资金/并发）或**连环缺陷**（同模块短窗口 ≥2 单）→ AI **提示升级**（受影响模块局部全量 / 扩大回归至邻接与历史高发区），用户确认后执行。同批修复可**合并一次回归**（重叠模块去重）。**计划驱动：每次修复后立即回归，不等批末（计划 §10）；回归结果并入报告 §5.2**。平台单入口同口径（见 `规则/缺陷/缺陷协作.md` §7）。  
- 与缺陷轨「平台单回归」（指派给我/已解决等，见 `规则/缺陷/缺陷协作.md` §7）不同轨——平台单回归走 `规则/缺陷/缺陷协作.md`。
