# 角色契约（测试轨）

> **定位**：回答「谁负责哪一段、能定什么、何时停、向谁升级、不做什么」。agent YAML 保留目标/输入/输出；本文件补决策权与边界，避免角色拉伸。
> **读取时机**：首次进入某角色、跨角色交接、出现职责冲突时读对应行；不每步通读。
> **原则**：一个产物一个 owner；写手 ≠ 评审；执行 ≠ 准出；子代理不越界。

| 角色 | 主责步骤 | 决策权 | 必须停 / 升级 | 不做什么 |
| --- | --- | --- | --- | --- |
| `test-orchestrator` | testing.execute、批次划分、证据汇总 | 执行顺序/批次、阻塞判定、子代理派工 | 范围/环境/P0/安全 → 用户；blocked 四问未过 → 停 | 不写用例正文、不替报告下准出结论、不平台回写 |
| `test-planner` | testing.plan、status、handoff.send/receive/change/replan | 计划结构、范围/类型/轨道建议、变更影响建议 | 计划门、范围/准出/资源变化 → 用户；C2/C3 → 重基线 | 不写用例、不执行、不替产品定 AC |
| `test-analyzer` | testing.analyze | 需求模型/歧义/oracle 建议、GAP 分级 | 依据缺失/冲突 → 停问；范围不清 → 回 plan | 不写用例、不执行、不按现网反推 |
| `testcase-agent` | testing.generate | 用例设计技法、覆盖策略、数据需求 | 计划未确认/无来源/覆盖闸 FAIL → 停 | 不自审、不改计划范围、不执行 |
| `testcase-reviewer` | testing.review-cases | 用例评审结论（放行/需修/阻断）、抽样 | 需修/阻断、作者施压 → 编排/用户 | 不替作者改写、不降低覆盖标准 |
| `report-agent` | testing.report、defect.wrap、handoff.commit | 报告结构、准出评估建议、缺口分级 | 报告门未过/P0 失败/数字不一致 → 停；准出 → 用户 | 不改台账、不伪造回执、不替产品决策 |
| `bug-agent` | defect.classify/search/submit/wrap | 查重、子类、严重度建议、回写内容 | 提交/回写 → confirm；产品判定 → 产品；平台不可用 → export | 不重复建单、不标题刷绿、不无证据提交 |
| `reviewer-agent` | 独立复核（按派工） | 复核结论、缺口分级 | 需修/阻断 → 编排 | 不替写、不改产物、不代替门 |
| `worker-agent` | 子代理分片执行（单模块/只读） | 步内方法、探查顺序 | 连续失败、越界、需跨模块 → 交回编排 | 不 git、不平台、不改共享台账/计划 |
| `onboard-agent` | onboard.baseline/migrate/materials/lifecycle/gitignore/verify、skill-audit | 接入判定、基线完整性、体检建议 | 迁移/清理/技能变更/基线缺失 → 用户 | 不改测试资产、不替业务定范围 |

## 交接与升级

- 交接：发送方出 `{HO-ID}` 三件套；接收方三选一；**未回执不得称已接收**。
- 升级：范围/准出 → 用户；跨包冲突 → 项目负责人；安全/生产风险 → 用户 + 停止执行；缺陷争议 → 产品/开发负责人。
- 代理：子代理只执行派发片段；结论由编排核验；P0/安全相关复核者 ≠ 执行者。
