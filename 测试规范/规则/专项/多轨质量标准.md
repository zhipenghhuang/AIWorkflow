# 多轨质量标准（测试轨 · 高质量门槛）

> **单一出处**：功能 / 接口 / 发布前 / 探索式（及计划外随机）的**共用高质量门槛**与**准出组合条件**。各 `轨契约/` 只写本轨细节，不得低于本文。  
> **读取**：生成/执行/报告/准出前读本文当前相关节；勿通读他包。  
> **原则**：宁多勿漏（命中+邻接）· 证据先于结论 · 无来源不写断言 · 禁静默降档 · 缺口必须显式。  
> **轨清单非穷尽**：功能/接口/发布前/探索/随机为常用轨；新专项按同质量门槛挂载，禁把本文轨名当成唯一合法路径。

## 1. 共用硬门槛（所有正式轨）

| # | 门槛 | 不满足则 |
| --- | --- | --- |
| Q0 | 已有 `测试/测试分析表.md` 且 **§0 Brief+差量表** 已确认（或本轮明示不适用+依据） | 禁宣称「本期已对齐/可准出」；生成前先 analyze |
| Q1 | 用例/方案/断言可追溯到主读或分析表（RQ/AC/F/R/TP/章/接口） | 禁臆造预期；无来源标 GAP 或问清 |
| Q2 | P0 / GATE / 阻断项未过 → 不得整体通过 | 报告门 FAIL |
| Q3 | 覆盖映射无空行：有点必有用例 ID 或「不适用+依据」 | 禁称已覆盖 |
| Q4 | 可脚本化确定性用例：**同轮产出脚本**或书面不可脚本化理由 | 接口/功能 P0 默认未完成 |
| Q5 | 评审：T1+ 落地产物须选 A/B；进准出的接口/纳入计划的发布前·探索式不得跳过 | 禁「未审即准出」 |
| Q6 | 报告声明本轮 `runId/构建` + `suite` + 各轨 `depth`/风险级 + 装填域 + 本轮实测计数 + 缺口清单 | 缺声明不得准出 |
| Q7 | 准出只认本轮装填；`未本轮验证` 不计通过率；目录按 §1.3.0（`*-功能|接口用例/台账`，发布前带专项前缀） | 光秃用例.md / 旧通过冒充本构建 → 不得称已对齐 |

## 2. 分轨执行深度

### 2.1 功能 / 专项

| 档 | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅补丁/热修且报告标明「补丁口径」 | P0-Smoke + 窄影响面 |
| `module` | **迭代/提测默认** | 命中域 + **逐邻接影响面**（宁多勿漏）+ 视觉/UI 基础 + 覆盖三闸 |
| `full` | 发版/完整项目/大版本 | 范围内 Module 全跑（含邻接策略按计划） |

### 2.2 接口（depth）

| depth | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅 T0/补丁口径 | 命中写/关键读的**高风险维**可执行+脚本（或 不适用+依据） |
| `standard` | **迭代/提测默认**（有接口在范围时） | 命中接口 × **全部适用维**均有可执行用例+脚本（或 不适用+依据）；覆盖对照禁空 |
| `full` | 发版/完整项目/点名 | 范围内全部必测接口 × 全部适用维可执行+脚本 |

> 对照表可先列全维；**迭代执行默认 standard**。仅补丁口径才允许停在 depth=`core`。

### 2.3 发布前

| 风险级 | 何时 | 最低 |
| --- | --- | --- |
| 基础级 | 小改/低风险且计划选用 | 契约最小集全做完 + **硬覆盖映射**无空 |
| 标准级 | **版本级默认**（不确定上靠） | 标准级最小集全做完 + 硬映射 + 指标有目标值与来源 |
| 高风险级 | 资金/权限/数据/公共 API/大促 | 高风险级最小集 + 硬映射 |

- **硬覆盖映射**：每条必测面 → `方案章节 | 工具/跑次 | 结果(达标/未达标/缺口)`；空行=未完成。 
- 裁剪须写入报告并由用户书面接受；禁静默不做。  
- 安全 critical/high 未闭环 → 不得发布通过。

### 2.4 探索式

| 档 | 何时 | 最低 |
| --- | --- | --- |
| 建议 | 计划 §12 未纳入 | 可独立跑；用例对照模板（步骤四列+判定面）；收尾写覆盖/缺口 |
| **纳入计划（T2+）** | 计划已列探索章程 | 每条章程目标 → 用例/会话证据或「不测+理由」（模板 §3 映射）；§0 高影响差量主题至少 1 条相关章程或显式跳过理由 |
| T3 / 准出引用 | 报告引用探索结论 | 须评审放行（A/B）后才可写入准出依据 |

> 字段底线：前置三件套齐；禁空话步骤；oracle 有来源。不要求功能轨深度档全表。

### 2.5 随机业务流程

计划外；**不参与准出**。质量底线：对照随机模板（去重窗=最近 N 轮+新增轴；旅程可判定；发现分流）；禁臆造现网/主读不存在的能力；证据可打开；收尾含分流与账本写回（相对窗无新增且非刻意复测=未收尾）。不得用随机结果替代功能/接口/发布前/计划准出结论；不以补计划缺口为目的。

## 3. 准出组合条件（报告门对齐）

| 准出口径 | 功能 suite | 接口 depth（范围含接口时） | 发布前 | 探索式 | 分析表 |
| --- | --- | --- | --- | --- | --- |
| **迭代/提测可准出** | ≥`module` | ≥`standard` | 计划未列可不跑；已列则映射完成或缺口已接受 | 计划未列可不跑；已列则章程目标闭环 | §0 已确认 |
| **发版/完整项目可发布** | `full` | `full` | 按风险级最小集完成 + 硬映射无未接受空行 | 若报告引用则须已评审 | §0 已确认 |
| **补丁口径** | `core`+窄面 | `core` 可 | 按计划；未跑须标明 | 不强制 | §0 或补丁说明 |
| **仅 core / 仅接口高风险维未声明补丁** | — | — | — | — | **不得**称迭代/版本可准出 |

有条件通过：仅限 P0-Smoke/P0-HighRisk 全过 + 非 P0-Smoke/P0-HighRisk 缺口用户书面接受 + 报告列遗留/接受人。

## 4. 生成与评审强制面

| 产物 | 生成后 | 进准出前 |
| --- | --- | --- |
| 功能/专项 | 覆盖三闸 + T1+ A/B 评审 | 本轮装填对应评审已放行（合卷或分卷） |
| 接口 | 按 `接口测试用例模板` + 对照禁空 + depth 可执行/脚本 + `validate_api_testcase.py` | T1+ 或进准出 → A/B 评审（I1–I6） |
| 发布前方案/报告 | 硬映射表齐 | T2+ 或发版准出 → A/B 评审 |
| 探索式（计划纳入） | 模板字段齐 + 章程目标可对账 | T2+ → A/B 评审 |

**评审批次**（细则 `工作流` §2.5）：默认按本轮装填成卷；同轨同主读可多域合卷；跨轨不合卷；未放行域禁入执行装填。

## 5. 反模式（禁止）

- 用「软覆盖」空话代替映射表空行。  
- 迭代准出仍按接口「只跑高风险维」且不声明 depth=`core`/补丁。  
- 发布前无指标目标值却写「达标」。  
- 无分析表 §0 却称多轨已对齐本期。  
- 随机/探索结论冒充功能或发版准出。  
- 静默降 suite/depth/风险级。  
- 非装填行仍显示「通过」并计入报告通过率。  
- 新资产不用域夹、或用光秃 `用例.md`/`方案.md`；功能/接口文件名不带「功能/接口」区分。  
- 每个域夹机械强制单独一整套 A/B（同轮同主读应合卷）；跨轨硬合卷；未审域混进执行装填。
