# 脚本执行（脚本档 · Playwright · 执行提速）

> **读取级别：参考**（按节读取；按 `读取索引` 只读当前 step 节，禁止通读全本）。

> **定位**：功能/探索式轨内**第四种执行形态**「脚本档」——可脚本化用例的确定性执行通道；与模块档/直跑档/拆分档并列，取档见 `规则/专项/多Agent与输出.md` §1.1。
> **为何有它**：AI-MCP 逐条执行在回归场景重复消耗时间与 token；已定稿、断言明确的主链路应固化为脚本，0 token 复跑，AI 只处理不可脚本化与失败复核。
> **默读时机**：生成时判定可脚本化（testcase-agent）、执行时取脚本档（test-orchestrator）、脚本档相关口令时读够本文。工具细节（安装/命令/字段）见 `规则/tools/playwright/README.md`（首次落地或变更时读）。

## 1. 适用判定（生成时逐条判定 · 不可让）

| 判定 | 特征 | 例 |
| --- | --- | --- |
| **可脚本化 = 是** | 主链路稳定；断言可写成文本/选择器/接口字段；无临场判断；入口与数据前置已探明 | 功能 P0-Smoke/核心主链路、列表筛选与字段核对、写后回查、URL/文案断言、接口确定性用例 |
| **可脚本化 = 否** | 需要临场决策/口径探查/跨系统人判；断言是语义复算且一次性；UI 未定型；环境探查类 | 「汇总—明细对账」类判定、待探查口径、探索式测试、发布前测量类（性能/容量） |

> **功能默认**：功能 **P0-Smoke/核心闭环** 默认判「是」并固化脚本；其余迭代功能（新/改/规则/状态/异常）默认 AI 执行，不强行脚本化。未知流程 AI 探路一次，稳定且成为 P0 后再固化。

### 1.1 脚本化 ROI 门槛（防一次性脚本 · 防“AI 跑一遍再生成”双耗）

| 条件 | 选择 | 理由 |
| --- | --- | --- |
| P0-Smoke/P0-HighRisk，或每次构建/发布都跑 | **脚本优先** | 高频复用，回归 0 token |
| 新功能/变化功能/复杂规则/状态组合/需要判断 | **AI 执行** | 变化大、脚本维护不划算；AI 更适合探索/判断 |
| 一次性/低频/迁移/兼容抽查/环境探查 | **不脚本**；AI/人工执行一次 | 复用低，脚本成本 > 收益 |
| UI 未定型、流程仍在变 | **先 AI 探路一次**；稳定后用 Playwright `codegen`/trace 生成脚本 | 探路是发现，不是重复执行 |
| 已知稳定流程 | **脚本先行**：AI 生成 Playwright 脚本 → CLI/CI 执行；**不要** AI 手工跑一遍再生成 | 避免双重执行成本 |
| 已知稳定接口 | **API 脚本先行**：契约/断言可写死，直接 `--mode=api` | 无浏览器、快、稳 |

- **不看“复用 ≥3 次”**：只看是否 **P0-Smoke / 每次构建发布都跑 / 接口确定性**；其他默认 AI。  
- **功能只脚本 P0-Smoke/核心闭环**；其余 60～90 条迭代用例由 AI 执行，不强行脚本化。  
- **脚本必须进入日常**：PR API smoke/contract、构建冒烟、夜间回归、发布回归；**只用于偶尔缺陷回归的脚本 ROI 很低**。  
- **未知流程**：AI-MCP 只探路；不要“AI 全量跑一遍 → 再生成脚本 → 再跑一遍”。探路后直接 codegen/trace 固化，最多跑一次脚本验证。  
- **失败复核**：脚本失败才回 AI 看 trace/Network/日志；AI 不重跑整条稳定流程。

1. 判定在**生成用例时**做，落 `测试/功能测试/` 的**§1.2 脚本化清单**（模板见 `规则/模板/20-测试用例/测试用例模板.md` §1.2）；**禁**事后口头判定。
2. 判「否」须**一句理由**（判定型/探查型/动态链路/UI 未定型…）；不得因「暂时没空」判否。
3. 判定为「是」但本轮未编写脚本的，清单状态记 `待脚本化`——不影响正常 AI 执行；**回归/复跑轮优先补齐（先 P0-Smoke 与首轮稳定项）**。**接口轨例外**：确定性接口用例必须同轮产出脚本，不得标 `待脚本化`（见 `轨契约/接口.md`）。
4. **P0-Smoke 冒烟行优先脚本化**（全量轮冒烟前置闸 0 token 复跑；收益最大）。
5. **执行后回评（脚本化候选）**：首轮 AI 执行顺利、断言无需临场探查的用例 → 该轮收尾列「脚本化候选」（下次生成/维护轮回填判定=是并写脚本）；优先 P0-Smoke/P0-HighRisk/高频失败项。**稳态目标：回归轮的已脚本化覆盖逐轮上升**（日常回归大头由脚本档吃掉，AI-MCP 只留探查/判定/探索）。

## 2. 资产与脚本格式

| 资产 | 位置 | 说明 |
| --- | --- | --- |
| 执行器 | `测试/脚本/executor.mjs` | 自 `规则/tools/playwright/` 复制；业务无关引擎，**勿改逻辑**（同 RDM 手册「复制而非重写」纪律） |
| 适配配置 | `测试/脚本/case-executor.config.mjs` | 登录钩子（唯一承接点）/前后置/超时；自 `config.template.mjs` 实例化 |
| 用例脚本 | `测试/功能测试/{NN}-{短名}/脚本/{NN}-{短名}.script.mjs` | `doc` 指向同夹 `*-功能用例.md`；执行器在 `测试/脚本/` |
| 接口脚本（`--mode=api`） | `测试/接口测试/{NN}-{短名}/脚本/{NN}-{短名}.script.mjs` | 无浏览器；`apiLogin`；动作限 `api`/`note` |
| 产出 jsonl | `测试/功能测试/.draft/script-{模块}-{runStamp}.jsonl`（默认落点；接口/发布前轨用 `--draftDir=`/`--evidenceDir=` 指到本轨，见各轨契约） | **与拆分档 Worker jsonl 同格式**（`规则/专项/多Agent与输出.md` §3），合并规则沿用 |
| 证据 | `测试/功能测试/证据/{模块}/` | UI 失败自动全屏截图；API 失败落现场 json；叶名含 caseId |

**脚本最小结构**（`export default`）：

```js
export default {
  module: '01-单方案真实评价指标',
  doc: '测试/功能测试/01-单方案真实评价指标测试用例.md',   // 供需同步检查
  suites: { smoke: ['APS230-KPI-01'], regression: ['APS230-KPI-01', 'APS230-KPI-04'] },
  cases: [
    { id: 'APS230-KPI-01', title: '…', tags: ['smoke', 'regression'], steps: [
        { action: 'goto',   target: '/resource/planning/aps/plans' },
        { action: 'click',  target: 'APS 排程方案' },
        { action: 'assert', target: '排程覆盖率' },
        { action: 'api',    method: 'GET', path: '/api/…', expectStatus: 200, expectFields: ['data.total'] },
    ] },
    { id: 'APS230-KPI-04', title: '…', tags: ['regression'], run: async (ctx) => { /* 复杂复算逃逸口 */ } },
  ],
}
```

> **标签/套件（跨版本复用）**：`tags` 与 `suites` 固定写在脚本内；回归按 `--tag=smoke|regression` 或 `--suite=core|module|full`（或脚本内命名套件）选型，**与计划 §3.7 suite 对齐**——core≈冒烟/稳定冒烟，module≈装填命中域，full=发版/点名；**不要求也不默认全库脚本化/全库跑**。新增/淘汰只改对应 case 与 suites，**不随版本改脚本列表**。  

**动作速查**（完整字段见 `规则/tools/playwright/README.md`）：

| action | target | value | 说明 |
| --- | --- | --- | --- |
| `goto` | 路由或完整 URL | — | 导航并等载入 |
| `click` | 文本/`data-testid`/选择器 | — | 弹层内优先；antd 两字空格自动兼容 |
| `fill` | label/placeholder/name/testid/选择器 | 输入值 | 先清空后输入；DatePicker 自动回车 |
| `select` | 下拉 label/选择器 | 选项文本 | 兼容 antd / 原生；带选中验证与重试 |
| `press` | 同 fill | 键名 | 键盘事件 |
| `wait` | 选择器 | 毫秒（二选一） | 等待元素可见或固定时长 |
| `assert` | 文本/`url:片段`/选择器 | — | 可见性断言 |
| `assertNot` | 文本/选择器 | — | 断言不存在 |
| `api` | — | — | 走会话上下文请求；`expectStatus`/`expectMessage`/`expectFields`/`save` 断言；`--mode=api` 时动作限 `api`/`note` |
| `eval` | 页面 JS 表达式 | 期望值（`~` 前缀=包含） | 口径探查/复算 |
| `screenshot` | 叶名后缀 | — | 手动留证（失败自动留证无需写） |

**占位符**：target/value/path 中 `:key` 自动替换；`:runStamp` 每轮注入（数据戳，与 `REG-` 前缀配合保证幂等）。
**合并提速（可选）**：`node 测试规范/规则/tools/merge-ledger.mjs --ledger=… --jsonl=…` 机械合并——功能台账（§1 计数 + §2 结果/摘要/证据）与接口台账（判定/计数/空列补摘要，人工已填不覆盖）；结论说明仍由 AI 按专规补写。

## 3. 执行纪律（不可让）

1. **脚本优先**：已脚本化用例（清单状态=已脚本化）的**回归/重跑必须走脚本档**，禁止再用 MCP 逐条重跑；只有脚本失败复核、口径探查或清单=否的用例走 AI 通道。
2. **失败升级（有界复核 · 防过度验证）**：脚本判 `fail` 的用例需经 AI 复核后方可定性（浏览器 MCP 或等价通道）；**复核一次为限、同批同因合并一次**——目标是「可定性即可」，不是全量复现：能判为 ① 产品/实现缺陷（落 fail）② 脚本漂移/执行器问题（修脚本重跑）③ 环境/数据问题（按环境处理）之一即停；偶发问题记录观察频率即可，**禁**为凑 100% 复现率反复抓取。明显环境/数据缺失直接按环境处理，不触发复核。**禁**脚本失败未经复核直接交平台。  
3. **口径单一**：脚本预期必须与用例文档同源；**禁**在脚本引入文档之外的新口径或放宽断言。文档改口径 → 同轮改脚本（见 §4）。
4. **核验同标准**：脚本通过不采信退出码——合并前须文件在、jsonl 行数与范围一致、`result` 合法（编排回收核验）；通过可不截图，失败必须留证。
5. **隔离**：脚本档与 AI 通道**同轮不得对同条用例并行执行**（防脏数据互扰）；脚本档内用例按脚本声明顺序执行（脚本内自带依赖序）。
6. **数据卫生**：沿用 `REG-`/runStamp 纪律与基线 §14/§15；脚本内造数优先走 `api` 动作（快、可核对），UI 操作仅保留业务主路径。
7. **`ctx.blocked()` 纪律**（与 AI 通道同口径）：仅当前置造数/换样已写进脚本且仍因**外部不可用**才可 `blocked`；**禁**因缺样本/未造数直接 `blocked`（应先 `api`/步骤构造）；复核见脚本误用 → 改脚本重跑或按环境处理，**禁**原样交平台。细则指针 `规则/专项/多Agent与输出.md` §1.3-4。
8. **登录一次/轮**：登录钩子每轮执行一次（登录态跨用例复用）；**禁**用例内重复登录（除登录专测）。
9. **复核经济性（脚本档的目的是省时省 token）**：复核与抓证一律**批处理/合并**；禁为单条失败起多轮深挖（可定性即停）；缺陷提交按 `规则/缺陷/缺陷协作.md` 骨架一次成稿，不反复改写。任何「为脚本而加」的流程若不能换来回归轮的净节省，应删。

## 4. 同步与漂移（用例 ↔ 脚本）

1. **同步义务**：用例文档（步骤/预期/口径）变更 → **同轮**更新对应脚本；`--check` 模式校验脚本 caseId 与文档一致性（文档缺 ID 报 STALE）。
2. **漂移诊断**（复核时用）：脚本失败先跑 `--case=` 单条复现；再以 MCP 打开同页对照——页面与脚本预期不一致且用例文档支持脚本 → 缺陷；页面与文档一致且脚本不符 → 脚本漂移。
3. **脚本变更须过口径单一闸**（§3.3）；修订记录不写过程，只留最新（结论卫生同 `规则/专项/多Agent与输出.md` §2.1）。

## 5. 安全

- 凭据（账号/密码/token）**只走环境变量**（如 `E2E_USERNAME`/`E2E_PASSWORD`）；config 与脚本**禁**出现明文凭据；基线「脚本执行」节（模板 §16；实例以实际编号为准）只记环境变量名。
- 截图证据落 `测试/功能测试/证据/`，随内容遵守 PII 脱敏红线（`AGENTS.md` §0.2-2）。

## 6. 与 AI-MCP 通道的分工（默认策略）

| 场景 | 首选通道 |
| --- | --- |
| 已脚本化用例回归 / 冒烟复跑 | **脚本档**（0 token） |
| 同批混合（部分已脚本化） | 先脚本档跑已脚本化子集 → 再 AI 跑其余（同条禁并行） |
| 接口确定性用例（默认） | 脚本档 `--mode=api`（契约明确、断言可写死） |
| 生成期探查、口径探查、清单=否用例 | AI-MCP |
| 脚本失败复核、缺陷定性 | AI-MCP（必须） |
| 探索式轨 | 探索性测试，不脚本化；按轨契约执行 |
| 随机业务流程轨 | 计划外随机体检，不脚本化；按 `轨契约/随机业务流程.md` |
| 发布前轨 · 可脚本化子集（安全负向/兼容断言） | 脚本档（见 `轨契约/发布前.md` 脚本化通道） |
| 发布前轨 · 测量类（性能/容量） | 项目自备工具（不硬塞脚本档） |

### 6.1 默认执行引擎（Playwright-first · 按层选型）

| 测试层/场景 | 默认引擎 | 说明 |
| --- | --- | --- |
| UI 稳定主链路 / E2E | **Playwright 脚本** | 跨浏览器、trace、并行、CI 友好；稳定后固化，回归 0 token |
| API / 契约 | **Playwright APIRequestContext**（`executor --mode=api`）或项目 API 客户端 | 与 UI 同框架同报告；确定性接口默认脚本 |
| UI 探索 / 未定型 / 一次性 | AI-MCP（browser-mcp） | 只用于探查、口径、失败复核、探索；不反复全量快照 |
| 单元 / 静态 | 项目测试框架 / CI | Jest/Vitest/pytest/ESLint/Semgrep 等 |
| 性能 | k6 / JMeter / Locust（`perf-test`） | AI 不替代压测工具 |
| 安全 | SAST/SCA/DAST（`sec-scan`） | AI 做负向设计与复核 |
| 兼容 / 视觉 / a11y | Playwright projects / `visual-reg` / `a11y` | 代表矩阵，不做全排列 |
| 契约验证 | Pact / Schemathesis（`contract-test`/`api-fuzz`） | 候选人工复核后落账 |

### 6.2 AI 补强边界（不做主执行器）

- **AI 做**：需求/风险分析、用例设计、脚本草稿、选择器修复建议、失败复核、探索式会话、报告归纳。
- **脚本/工具做**：确定性重复执行、回归、压测、扫描、截图比对、CI 门禁。
- **反模式**：AI 逐步点击 API；已脚本化用例用 MCP 重跑；每版本重写脚本；把 AI 当压测器/扫描器。
- **固化闭环**：AI 首查/探查 → 稳定路径脚本化 → 回归 0 token → 失败再回 AI 复核。

## 7. CI / 定时复跑（可选 · 企业 BVT 自动化形态）

> 定位：脚本档不止人手跑——**每次构建/定时触发**跑已脚本化冒烟与稳定回归，等价企业 BVT（Build Verification Test）。本包不绑定任何 CI 平台；编排写在各项目 CI 配置。

| 项 | 约定 |
| --- | --- |
| 命令 | `node 测试/脚本/executor.mjs --plan=测试/{功能|接口}测试/{NN}-{短名}/脚本/{NN}-{短名}.script.mjs --tag=smoke`（接口加 `--mode=api`） |
| 环境 | `npm ci && npx playwright install --with-deps chromium`（UI 模式）；凭据走 CI secrets 环境变量（同 §5，禁明文入库） |
| 退出码 | **0=全过；1=有非通过；2=配置/环境硬错**——CI 直接按退出码判红绿，不解析日志 |
| 制品 | jsonl（`测试/功能测试/.draft/`）+ 证据（截图 / net json）留存为构建制品；**CI 不改台账/基线/平台**（合并与结论仍按本包流程由 AI/人执行） |
| 范围 | 仅已脚本化的 **P0-Smoke 冒烟行与稳定回归**（对照 §1 判定=是）；探查/口径/判定型不上 CI |
| 失败处置 | CI 红 ≠ 直接交平台：仍按 §3 有界复核定性；可先通知人，由 AI 通道走复核与分流（冒烟未过按 `规则/专项/多Agent与输出.md` §1.1.1） |
| 并发 | 与本地/AI 通道互斥同一 profile 与 runStamp（对照 §3-5；多套并行见基线 §8.2） |

**CI 能力（可选）**：本机可用 `ci`（见 `能力/00-能力注册表.md`）时由 AI 读取构建状态/触发复跑；不可用=流水线按本表配置执行。  
**报告渲染（可选）**：装配 `report-render` 时可把 jsonl/执行器输出渲染为明细报告；准出仍以 `测试/测试报告.md` 为准。
