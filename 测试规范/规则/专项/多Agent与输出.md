## 1. 执行形态与角色（功能/探索式轨）

### 1.1 执行形态四档

| 档 | 适用（按 §1.5 决策树；用户可点名强制） | 形态 | 落盘 |
| --- | --- | --- | --- |
| **脚本档** | 清单=已脚本化 + **功能稳定主链路/回归** + 接口确定性用例（`规则/专项/脚本执行.md` §1） | `node 测试/脚本/executor.mjs --plan=… [--tag=smoke|regression] [--suite=…]` 确定性回放；失败项升级 AI 复核 | 执行器 jsonl ＋ 证据（同拆分档格式） |
| **直跑档** | 「继续」单模块装填；单模块小批（≈≤20 条）；探索小章程；宿主无子代理 | 编排本会话直接执行＋批末自查；不派子代理 | **直写本模块台账**（逐条）＋证据；无 jsonl |
| **模块子代理档** | 同轮开跑 **≥2 装填模块**（或计划明示多模块装填） | **一模块一子代理**（独占上下文）；模块内执行＋批末自查；编排核验后下一模块。主收益=**上下文卸载**（减长会话漂移），墙钟其次 | 同上（各子代理只写本模块） |
| **拆分档** | 单模块 ≈>20 条 / 多批 / 高风险（长链、写密集）/ 需隔离核验 / 用户点名 | Worker（jsonl → DraftPath）→ 同回合 Reviewer → 编排合并（批流见 §2） | jsonl ＋ 台账 |

- **取档**：严格按 §1.5 决策树；**禁**用「派工前 3 问」把已达阈值的多模块开跑压成直跑。**禁**对已脚本化用例用 MCP 逐条重跑（`AGENTS.md` §0.2-7）。
- **开跑声明（不可省）**：execute / 大规模 generate 出示 suite 时多一行：`mode=脚本|直跑|模块子代理|拆分` + 对照决策树条款一句；收尾【遵守自检】可复述。
- 探索式：小批（≈≤10 条或单章程）直跑；多章程同轮或单章程大步骤 → 拆分/分章程子代理。接口轨 **单 Agent**（见轨契约）。**计划驱动跨轨**按计划 §9.2 取轨，阶段内仍按本表（§4）。
- **自查清单**（模块档/直跑档共用，＝ Reviewer 核心项）：`result` 合法 ｜ 失败人可复现 ｜ 证据钉断言点 ｜ 计数与台账对账 ｜ 写操作 Network 核对 ｜ **截图已同帧视觉检**（工作流 §2.1.0）｜ UI 文案减法已记。  
- **模块档派发**：模块、用例文档路径、基线 §8 与相关节摘录（不附整本）、证据目录、返回格式（模块小结素材）；子代理只写本模块台账与证据；**子代理自带浏览器 MCP**（基线 §8 登记套），编排**不**代点浏览器。  
- **编排核验（模块档）**：文件在、逐条落盘、计数一致、抽查失败证据；通过后进入下一模块（或并行批下一批）。  
- **并行（适当提效）**：见 §1.5「并行与隔离」——只读/生成 draft/隔离执行套可并行（≤3）；**共享** browser profile / 账号 / 写域 → **必须串行**。

### 1.1.1 冒烟前置闸（功能装填/专项轮 · 开跑纪律）

> 等价企业「提测冒烟 / 冒烟准入」：装填轮开跑前先做**数据准备（⓪）**再跑冒烟行（suite=core），判定是否值得展开——防「主链路已断仍跑装填域」的白跑（见本文件与 `规则/playbooks/execute.md` §2）。
> 冒烟判定行 = 各模块用例 §1.1「P0/P1 核心冒烟集」中标 **P0-Smoke** 的行（每模块 ≥1；跨模块 E2E 含 1 条；无标法时取每模块主链路首条）；已脚本化优先**脚本档**。  
> 适用：功能装填/专项（**≠** 每迭代 suite=full）。探索式/接口/发布前按各轨契约。  
> 轮次：R0 冒烟(core) → R1 装填域(module；发版/完整项目 full) → R2+ 回归；准出对照计划 §5。  

| 段 | 纪律 |
| --- | --- |
| ⓪ 数据准备 | 门2 后扫**本批装填域**前置三件套；缺者集中造齐；**未齐不进冒烟**；小批≤≈20 或已齐可跳过。 |
| ① 冒烟轮 | suite=core：先跑 P0-Smoke（脚本优先）；落账顺序 P0-Smoke → P0-HighRisk → … |
| ② 判定 | **全绿** → 转计划 §3.7 **装填域续跑**（suite=module；发版/完整项目/点名才 full；冒烟已终态不重跑）；**有失败** → §1.3 有界复核后按根因分流 ↓ |
| ②a 环境级 | 登录/站点/网关/基础数据不可得且穷尽 → **停轮**；修复后「继续」先复跑冒烟未过行 |
| ②b 产品级主链路 | 评估阻断面；被阻断下游记 `阻塞`；独立面照常跑装填域；修复后回归＝冒烟行＋被阻断组 |
| ②c 脚本漂移 | 修脚本重跑冒烟 |
| ③ 报告 | 冒烟写入【执行收尾】汇报段；此后回归按 `工作流.md` §3.1（原单+冒烟子集+影响面；禁默认全库重跑） |

- **条件放行**：用户点名「跳过冒烟 / 带病续跑」→ 放行，收尾须记「冒烟未跑/未过＋影响面」。  
- 冒烟行与装填域同标准落账留证；续跑不重跑已终态冒烟行。

### 1.3 准确度红线（易疏忽）

1. **真失败**：拟落失败须本轮走完 UI 主路径并见可见偏差；禁仅 list 探活即判失败。  
2. **写操作**通过/失败须本轮 Network 见过对应 METHOD+path；**UI 看似成功但主业务请求非预期异常 → 记失败并附【接口判定】**；禁纯 API 冒充页面结论。点名菜单/页面的用例：未走浏览器 MCP/脚本 UI 主路径不得以纯 API 写通过/失败终态（接口轨或入口本就纯 API 除外）。  
3. 失败摘要/截图**钉断言点**；通过可不强制截图；**凡已截目标页 → 同帧视觉检**（工作流 §2.1.0），禁截完只当留证不看界面。  
4. **阻塞判定**（单一真值）：`blocked` 仅限**非产品缺陷**的外部不可用。判定前先**自行打通**（造数/建号/赋权/换角色/换入口/重置等；缺上游按基线 §11 或构造）。**缺数据/缺样本 ≠ 阻塞**——须构造或换样后再判；构造过程暴露的被测缺陷记 `fail`。**方案/AC 范围内未实现（菜单无入口且无接口）→`待实现（实现缺陷）`；入口存在但 404/500/空壳→`fail`；两者都不是阻塞**，且待实现计入缺陷。禁单次猜深链 404 即判未交付。单案打通有界：**互异手段 ≥2** 且 **总尝试 ≤3**（含换样/配方；禁同手段空重跑）；仍不可用方可 `blocked`，摘要写已尝试与证据；**被测对象自身缺陷 → 记 `fail`**；失败分类与相符证明见 `规则/缺陷/缺陷分类.md`。  
   **blocked 四问（逐项过，任一未过不写 blocked）**：① 能否造数/换样？② 能否换入口/角色/账号？③ 是否被测对象自身缺陷（→`fail`）？④ 互异手段≥2 且总尝试≤3 了吗？  
   **终态对照**：缺数据/样本 → 造/换样，不记 blocked｜菜单无入口且无接口 → `待实现（实现缺陷，计入缺陷）`｜菜单有入口但页面/接口 404/500/空壳 → `fail`（实现缺陷）｜登录/网关/环境级不可用且穷尽手段 → `blocked`。  
5. **链式阻断**：上游缺陷致链路不可建且**无法换样/绕过** → 下游记 `blocked` 且摘要点名上游用例与根因（禁重复记 `fail`）；可换样/可独立执行的面照跑，禁套 blocked。上游数据已落库或另有可换样本 → 换样执行。全量轮冒烟未过的阻断面按 §1.1.1②b 处置。  
6. 已在目标页且未漂则续测，勿无故重登。  
7. **一条一写（全档通则）**：逐条落盘、禁攒批；失败证据落约定目录且叶名含 caseId。  
8. **选样与冲突**：造数/换样/改权前——①查基线 §14（命中 → list 核对 ENABLED；无 → 构造）②查 §15 ③筛选全净；写 400/唯一性先查 §15；有新可复用信息收尾回写 §12，无则禁改基线。  
9. **状态先后**：同一样本上既有负向阻断探测又有正向写操作 → **先负向**（写后状态已变，负向结论不可再得）；被写操作改变状态的实例不得跨条按变更前口径断言——后续用例须换样或新建实例，禁沿用旧断言面落终态。  
10. 同方案无效 2 次换路径：**换根因假设或验证手段，禁同命令空重跑**。  
11. **审查范围**：只报影响正确性/需求覆盖的缺口；不追风格偏好、不为假想场景要求加防御（防过度设计）。  
12. **脚本失败升级**（脚本档）：`fail` 先按**有界复核**（`规则/专项/脚本执行.md` §3：一次为限、同批同因合并、可定性即停）复核再定性；结论=产品/实现缺陷→落 fail；脚本漂移/执行器问题→修脚本重跑；环境问题→按环境处理。**禁**脚本失败直接交平台，**禁**为凑复现率反复深挖。  
13. **用例即口径**：严格按本批用例（前置三件套/步骤/预期/清理/执行提示）操作与判定、步骤↔预期**同号核对**；逐条先核前置可达（账号/数据/入口）再进步骤，不可达先按 §1.3-4 打通/换样；禁跳步、禁合并步、禁自创步骤或私改断言；预期留白按 工作流 §3.0（先读现网实现值再断言）。发现用例缺陷（步骤不可行/预期与现网不符）→ 不静默改判：按现网口径落结论、摘要注「**用例待修**」，收尾列修订建议；笔误级修订可同轮，须同步脚本（`规则/专项/脚本执行.md` §4）。  
14. **额外发现 / 视觉**：用例外 UI/UX/console/network → 记位置/现象/证据/影响；截图顺带视觉检见 §1.1 自查与工作流 §2.1.0；能复现进缺陷，不静默忽略，不替代用例结果。  

### 1.4 子代理边界（全档）

- 不 git / 不交平台 / **不改他模块文件**；模块档与直跑档只写本模块台账与证据；拆分档 Worker 仅写 DraftPath。  
- 派发提示必含：对应契约 must 要点、模块、批次、caseId、路径、`DraftPath`（拆分档）、基线 §8 及本批相关节摘录（**不附整本**）。  
- 编排回收核验：文件在、落盘完整（模块/直跑档＝台账逐条；拆分档＝jsonl 齐全后合并）、计数一致、`result` 合法；失败则同回合补跑；不采信口头完成。

### 1.5 子代理编排（决策树 · 阈值 · 并行 · 降级 · 派工）

> 目的：高收益处隔离上下文并**适当并行**提效；**不盲目拆**。净收益＝上下文卸载＋墙钟加速＋质量增益−（重复读取＋合并核验＋漂移风险）。  
> 原则：**先脚本/工具 → 再决策树取档**；宿主无子代理能力 → 全程直做并收尾注明。

#### 1.5.1 取档决策树（自上而下，命中即停）

1. 已脚本化且非复核 → **脚本档**  
2. 用户点名强制档 → 从其点名  
3. 接口轨 / 入口本就纯 API → **单 Agent**（轨契约）  
4. 宿主无 Task/子代理 → **直跑档**（`subagent=unavailable`）  
5. 口令「继续」且本批装填域 = **1 个模块** → **直跑档**（合法；不强制为拆而拆）  
6. 同轮开跑装填域 **≥2 个模块**（或计划 §3.7/§9 明示多模块同阶段装填）→ **模块子代理档**  
7. 单模块 ≈>20 条，或高风险写密集/长链，或需独立核验，或用户点名 → **拆分档**  
8. 其余单模块小批 / 探索小章程 → **直跑档**

**派工前 3 问**（仅用于**未达**上表阈值时的可选拆分；**不得**用来否决已命中的第 6/7 步）：① 脚本/校验器能否完成？② 单元独立且写入不相交（或只读）？③ 合并核验机械且返回 ≤30 行？三问皆否 → 维持直跑。

#### 1.5.2 触发阈值（不达不拆；达则应拆或声明偏差）

| 场景 | 阈值 | 取档 |
| --- | --- | --- |
| 生成用例（命中域功能/专项） | **≥3 模块且**（预估合计 **≥40 条** 或用户点名分片） | **分片**：一模块一子代理，只写 `.draft/generate/{模块}.md`；**draft 文件不相交可并行≤3**；编排合并/统一 ID/覆盖三闸 |
| 缺陷批处理 | **≥5 单且读单成本高**或合计 ≥20k token | **逐单只读侦察**（可并行≤3）；分类/处置/回写集中 |
| 执行 | 见决策树 §1.5.1 | 模块子代理 / 直跑 / 拆分 |
| 报告对账 | 台账/证据计数、可打开性 | **脚本优先**；仅语义归因派核验子代理 |
| 大范围调查 / 分析扇出 | ≥20k token 或 ≥5 文件/来源 | **只读扇出**（可并行≤3）；主上下文只收摘要 |
| 同一文件/同一条用例/同一单据/共享写域 | — | **禁并行写** |

达阈值却直做 → 收尾必须 `deviation=subagent_skipped:<理由>`（宿主不可用/用户点名直做除外可写 `unavailable`/`user`）。

#### 1.5.3 并行与隔离

| 类型 | 可否并行 | 条件 |
| --- | --- | --- |
| 只读侦察/文档抽取/证据核对 | **可** | 并发 ≤3；返回各 ≤30 行 |
| 生成分片（各写不同 `.draft/{域}`） | **可** | 并发 ≤3；**禁**并行写同一正式域文件 |
| 模块子代理执行（UI） | **默认串行** | 共享同一 debugPort/profile/账号/写域时必须串行 |
| 模块子代理执行（隔离套） | **可** | 基线 §8 已登记**互斥隔离套**（不同 port/profile）+ 计划 §3.4 可并行 + 账号/写域不交叉；并发 ≤ 隔离套数且 ≤3 |
| 脚本档多标签/多 plan（无 UI） | **可** | 写域/库表不冲突；冲突则串行 |
| 拆分档 Worker∥Reviewer | **否** | 同回合串行：Worker 完 → Reviewer |

并行冲突/污染 → 立即改串行，记录偏差；不把并行失败当产品失败。

#### 1.5.4 失败降级（不可让）

出现任一项 → **同回合降级直做/串行补齐**，禁空转重派同一方案：

- 超时 / deadline / 无产物 / 返回空  
- `rules=violation` 或 `scope=over` 且无法当场收敛  
- 连续 2 批负收益（返回 >30 行、合并冲突、返工、主上下文回读原始证据、超范围）

收尾：`deviation=subagent_degraded:<timeout|empty|violation|neg_roi>`；产物以编排直做结果为准。不为「多 Agent」而拆；不把确定性校验交给 LLM。

#### 1.5.5 扇出读 · 汇聚写 · 派工 · 回收

- 读可扇出；写须单写手或文件集不相交；同一用例文件/模块台账/报告/计划/单据禁并行写。  
- 判断、终态、门禁、平台回写、合并结论留在编排；子代理不得过 `hitl`/`gate`、不得 git/交平台/改他模块。  
- 分片生成只写 draft；编排合并后跑一次覆盖三闸；子代理不改主用例文件。  

**派工包（7 项，缺一不派）**：①任务与验收 ②边界（允许路径）③输入节选（**不附整本**）④规则摘录 3～5 条＋契约路径 ⑤输出契约 ⑥返回 ≤30 行固定字段 ⑦禁止事项（git/平台/门/超范围/同命令空重跑）。

**回收**：文件在、逐条落盘、计数一致、`result` 合法、证据可打开；规则回执 `rules`/`scope`/`evidence`；不采信口头完成；批末核验通过再下一批。

**上下文卫生**：主上下文只留派工/返回/核验摘要；子代理不通读整本；delta-only；Reviewer 不收 Worker 推理（防锚定）；失败同回合重测 ≤1，同方案无效 2 次换路径。

**成本批末一行**：`batch | mode | units | parallel | returns≤30 | conflicts | rework | verdict=keep|direct|degraded`。

## 2. 批流（拆分档）

```text
门2 → Draft → Worker 一批 → 同回合 Reviewer
→ 格式问题当场改 → 不可信则同回合重测≤1
→ 合并台账 → 下一批或失败汇总 → 工作流 §4
```

禁止 Worker↔Reviewer 多轮乒乓。仍不通 → 失败/阻塞落账后下一条。无对应 case 的额外发现执行中可 ≤4 行，其余进台账/§4。

**修正边界**：只可当场修正笔误与编排侧文案；终态判定与证据问题须回修（重测/重拍），不得以改文案替代；误报嫌疑或证据缺失且无法闭环 → 停止并报告。

### 2.1 续跑 · 回归 · 结论卫生

- **续跑（「继续」）**：额度/中断后接未完成；沿用本会话 `DraftPath`、门2 与本轮 runId；不重跑已有**本轮**终态行；已读稳定规则不重贴（delta-only）。  
- **新 run / 换构建开跑**：装填内→重置 `未执行`（或仅修改/rerun）；装填外旧通过/失败→`未本轮验证`；准出只计 §1.1。路径 `测试/{轨}/{NN}-{短名}/*-功能台账.md` 或 `*-接口台账.md`。  
- **回归执行（「回归 / 重跑 {全量|域|条目}」）**：按点名范围**重测既有用例**；结果**就地覆盖**本轮台账行与证据（验证构建=本轮）；**只保留最新确认结论，不写过程**；旧轮留档仅用户点名（轨内 `_归档/`）。与缺陷轨「平台单回归」不同轨。  
- **计划驱动连续回归**：每个缺陷修复后立即回归，不等批末；范围＝原单复测＋冒烟子集＋影响面组（计划 §10）；高风险/连环缺陷提示升级；结果就地覆盖本轮行，报告 §5.2 汇总。  
- 缺终态（拆分档 jsonl / 模块·直跑档台账行）时先对账页面/Network：已成功 → 补写结果；未成功 → 定点重测——**禁未对账直接重复写操作**。未出 §4 先补 §4；不自动开其它模块；全量 draft 与 `S-*` 互不接力。  
- 续跑中途不退程、不关调试 Chrome。

### 2.2 MCP（纪律）

绑定与选型 SSOT：`测试/能力/00-能力清单.md` 槽 `browser-automation`（别名 `browser-mcp`）及按需 `测试/能力/绑定/browser-automation.md`；`环境基线.md` §8 **仅索引**。接口轨可不启用。纪律总则见 `规则/能力/实例纪律.md`。

**稳态（执行默读）**：

- 执行前读清单：`启用=是` 且按 `kind`/`绑定` 确认已挂载；**未挂载** → 请用户重载/装配后继续，勿自行换实现。  
- **`kind=mcp` 且端口未开（工具在、仅连不上浏览器）≠ 未挂载**：按绑定文件「拉起命令」自行拉起调试 Chrome（只替换绑定内端口/profile），轮询 `{browserUrl}/json/version` 至就绪（≤15s）→ **原会话直接重试**。仍连不上 → 只 Restart 本行 MCP 一次再试；再失败 → 停止并报告。  
- **`kind=skill-cli`**：按绑定/实现手册操作；不适用 CDP 套件则勿套用拉起 Chrome 句。  
- **自愈边界（不可让）**：自修只限「按绑定拉起浏览器」「Restart 本行 MCP」；**禁**换端口/profile/server/impl/宿主、禁杀占用进程、禁改宿主配置与清单选型（未挂载属配置层 → 停止并给出应补条目）。  
- **中断与续跑不关浏览器、不退程**；宿主重启后先恢复页上下文再 snapshot，禁默认整页重开。  
- 跨模块：复用浏览器进程 ≠ 复用页面上下文；须重新 snapshot、核对模块/路由/登录域与 Network。  
- **禁止**自动回退未在 `测试/能力/` 登记的其它浏览器实现；其它不可用 → 停止并询问用户。  
- **禁**反复 `new_page`、禁关他模块页、禁执行中为救红点关浏览器。  
- **全链终局退程（不可让）**：本轮若已拉起/使用调试浏览器，须在**本任务链全部结束后**退程关闭（关 tab 不够）。「全部结束」＝执行结论已确认，且缺陷协作、入库提交、点名部署等后续均已做完或明确不做。由最后一步收尾角色退程（通常 `report-agent`）；若仍进 defect / 门3 待确认 → **延后不退**。下次按绑定再拉起。本轮未用浏览器 → 不操作。

**异常点读**（仅红点/无工具/端口失效/多套并行冲突时再读；**禁**顺跑预防性通读）：

- **红点**：Settings 本行 MCP 红点/报错 → 只 Restart 该 MCP，**禁止**因此关调试浏览器；同端口占用同样禁关浏览器/换端口。  
- **同会话排障**：Restart 后先在本会话核对工具列表与端口；仍无工具 → **停止并请用户** Restart/重载后说「继续」；**禁止**规则驱动的无差别「新开对话」空转。  
- **端口**：失效有限等待，禁无限等待与静默切换。  
- **多套并行**：同一端口/server 同时仅一个操作会话；绑定内互斥字段自检不过 → 停止报告。终局只退**本套**，禁动他套。

## 3. 过程输出

**启动**：`route=workflow:testing | step=execute | role=test-orchestrator | next_action=… | DraftPath=… | 模块=…`；计划驱动加 `plan=测试/测试计划.md | phase=P0～P9 | track=功能/接口/探索式/发布前/回归`。

**Worker jsonl（拆分档 · 每行）**（脚本档同格式：由 `测试/脚本/executor.mjs` 产出，附 `source=script`；合并规则同下表）：

```json
{"caseId":"…","result":"pass|fail|blocked|na|pending","summary":"…","evidencePaths":[]}
```

fail：`summary` 写清现象+关键路径/主键；禁密钥。  
`pending`=**方案/AC/计划范围内应实现而未实现（菜单无入口且无接口）**（实现缺陷，计入缺陷并进入批次提交；非外部阻塞）。入口存在但 404/500/空壳/假成功→`fail`。明确范围外/后续池→`na`，不标 pending。**禁止**「方案未写死数值但系统已有实现规则」→ pending；此类须先探查现网口径再判 pass/fail（工作流 §3.0）。

**jsonl `result` → 台账结果（拆分档合并必用）**

| jsonl | 台账结果 |
| --- | --- |
| `pass` | 通过 |
| `fail` | 失败 |
| `blocked` | 阻塞 |
| `na` | 不适用 |
| `pending` | 待实现 |
| 缺行 / 无合法 `result` / `todo`（同义容忍） | **未执行**（先对账补写或定点重测，禁止默认为通过） |

合并时按上表写结果列；计数六态与工作流 §4 一致；**`pending`=待实现（实现缺陷），计入缺陷合计，必须进入批次提交**。**可选机械合并**：`规则/tools/merge-ledger.mjs`（更新 §1 计数与 §2 行；模块结论/结论说明仍由 AI 按专规补写）。模块结论含「待实现」时：任一条 `pending` 且无 `fail`/`blocked` 主导风险 → 模块结论可用「待实现（实现缺陷）」；有失败则「失败」优先。

**模块档/直跑档自查**：执行者按 §1.1 自查清单逐项过，输出一句自检结论（并入模块小结/失败汇总）。

**Reviewer（拆分档）**：模块/batch/verdict；计数；当场修改；当场重测（≤1）；核对失败是否人可复现、证据是否钉断言点。

**合并一句**：`已合并 → 台账=… | 本批计数 | 累计通过率=P%（通过/总数）| next_action=…`

**失败/阻塞/待实现行 §3 成稿**：模块档/直跑档在落盘当时、拆分档/脚本档在复核或合并时，即按 `规则/模板/30-执行与台账/执行台账模板.md` §3 为对应行成稿（分类/问题标题/两档/复现/实际/预期/接口判定/设计对照/证据）；素材=本轮实测与用例、证据，缺则当场补采；**禁空壳、禁留到缺陷轨回补**。

**失败汇总**（并入 report·§3）：条数 + 一句摘要 + 交平台建议；是否交平台只在 report 问一次；不拉平台、不改状态。

终稿：工作流 §4。

## 4. 计划驱动编排（跨轨 · 唯一编排口径）

> 适用：口令「按计划执行 / 执行测试计划」，或计划已确认的多轨执行。计划 §9.2 是编排真值；单轨口令仍按 §1～§3。  
> 原则：**计划定阶段/轨道/依赖/门禁；阶段内仍按对应轨契约与四档执行；不跨轨通读**。

### 4.1 角色与真值

- 编排（`test-orchestrator`）逐阶段推进；每阶段只读当前轨契约（功能/探索式、接口、发布前），不预读其它轨。
- 计划 §10 回归、§11 缺陷、§12 探索；台账/证据/缺陷记录为执行真值。
- 过程状态落 `测试/测试计划.md` §0/§16.1（阶段/状态/偏差/阻塞）；正式对照落报告 §2，不把过程写成正式结论。

### 4.2 阶段执行与门禁

> **SSOT**：阶段表/入口/出口/门禁只认 `规则/模板/10-计划/测试计划模板.md` §9.2（与 `规则/工作流.md` §3.6 同步）。本文不重复大表；改编排先改计划模板，再对工作流/本节指针。

- **不跳阶段**；计划标注并行的阶段可按 §4.3 并行；未标注默认串行。  
- 未列/不适用的阶段由计划写明（如无接口/无 UAT），不默认全做；跳过须有依据。  
- P2 功能 = **装填域**（suite=module；发版/完整项目才 full）；≠库内全文件必跑；冒烟分流见 §1.1.1。  
- P7 UAT/P8 发布前/灰度若由业务/Ops 执行，编排只协调与收证，不冒充执行。  
- 阶段出口未过 → 停在该阶段或按阻断面分流；不得静默降范围/跳下游。  

### 4.3 并行与隔离

- 阶段/轨道并行：仅计划 §3.4/§9.2 标注「可并行」；细则与子代理并发见 **§1.5.3**。  
- **同一条用例禁并行**；共享写数据/同一业务主键 / 共享 browser profile → 串行。  
- 接口/非功能可与功能并行（不共享写域、构建稳定）；探索可在对应面稳定后穿插；回归随修复触发。  
- 有隔离套时模块子代理可并行（§1.5.3）；冲突/污染 → 立即串行，记录偏差。  

### 4.4 缺陷-回归闭环

`fail → 定性/查重 → 提交（计划 §11 策略）→ 开发修复 → 回归（原单+冒烟子集+影响面组）→ 关闭/激活 → 台账/报告更新`

- 优先 P0-Smoke 脚本 + 受影响模块用例；未受影响用例不重跑；新功能/变更按迭代用例执行。  
- 提交策略见 `规则/缺陷/缺陷协作.md` §6.1（计划 §11）。  
- 高风险/连环缺陷 → 提示升级（模块局部全量/扩大邻接回归），用户确认后执行。  
- 同因不重复提交；同批修复合并一次回归；结果就地覆盖只留最新。  

### 4.5 探索式穿插

- 按计划 §12 章程：mission/范围/时间盒/数据/oracle；session 记录→debrief→triage。  
- 分流：产品缺陷→缺陷+回归；覆盖缺口→补用例/补章程；误报→记录。  
- 探索式不脚本化；证据按会话留；收尾写章程完成/覆盖/缺口；不替代功能装填/准出范围。  

### 4.6 停止/恢复/变更

- 停止：P0-Smoke 未过、环境不可用、数据/合规风险、计划实质偏差 → 按计划 §6 暂停或回计划门。  
- 恢复：先复跑冒烟未过项，再续未完成阶段；不重跑已终态。  
- 计划变更：范围/准出/排期/缺陷策略变更 → 更新计划并回计划门；小改就地记录在报告偏差。  
- 未授权提交/计划外提交 → 仍按门3；禁以「计划驱动」为由绕过确认。
