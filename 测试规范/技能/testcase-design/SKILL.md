# 用例设计（技能 · 随包生效）

> 字段/红线以 `规则/模板/20-测试用例/测试用例模板.md` 为准；本技能=技法与手感。  
> 计划驱动：按 `测试/测试计划.md` §3 类型/轨道与 §12 探索章程设计；功能用例与探索章程分开，不混用覆盖口径。

## 1. 技法速用手册

- **等价类**：有效/无效各取代表；同类代表不重复测。
- **边界值**：取点口诀 `min-1 / min / min+1 / 典型 / max-1 / max / max+1`——数字、长度、时间、分页、金额都适用。
- **判定表**：条件组合互斥时列规则表，一格一用例（同结果列可合并）。
- **状态迁移**：画状态 × 事件矩阵；每个**非法跃迁**一条负向。
- **场景法**：用户故事串「入口 → 动作 → 观测点」；主路径 + 每条分支变体。
- **组合/配对**：多输入选项用 pairwise 思路裁剪（不做全排列）。
- **错误推测**：按历史缺陷谱系补（见 §4）。

## 2. 设计顺序（顺手套七维）

主路径 → 状态与规则 → 负向与非法跃迁 → 边界 → 权限/数据域 → 异常与脏数据 → **视觉/体验**（布局/遮挡/截断/文案/空态/加载/错误提示/按钮状态；七维自查见 testcase-agent 完稿自检）。

### 2.1 覆盖全面性（不能只看主流程）

- 每个受影响模块至少覆盖：主路径、状态/规则、负向/边界、权限/数据域、异常/恢复、UI/体验。
- 复杂配置/筛选用组合/配对；状态对象画状态 × 事件；写操作必含失败/回查/清理。
- 文档未写死数值 → 仍出行为用例，执行先读现网口径；禁整段不测。
- 用例之外发现（UI/布局/显示/console/network）在执行期记录，不替代用例覆盖。

## 3. 断言写法

- 每条预期必须**可观测**：值/文案/状态列/字段=值（杜绝「正常/正确」）。
- 灰盒判定优先写业务信号（列表刷新/状态列/接口字段）。

## 4. 常见漏测谱系（生成时对照补）

金额与精度｜时间与时区｜分页边界与排序｜重复提交/幂等｜空态与首屏｜超长与 Emoji｜导入导出（模板/编码）｜权限域与越权｜并发同键｜缓存刷新｜浏览器返回/刷新态｜网络慢与失败重试｜**UI 布局/遮挡/截断/文案**｜按钮/禁用/加载态｜错误提示与恢复。

## 5. 与文档的关系

- **用例文档结构（模块内索引 + 结构化，不改目录）**：§1 模块总览表（ID/标题/场景/优先级/类型/关联需求AC/设计点/前置摘要/步骤数/脚本/最近结果/缺陷）→ §2 结构化详情；总览与详情同文件，不拆文件夹、不建全局索引。
- **单条结构**：元数据 → 一句话场景/业务价值 → 前置（账号/数据/入口/环境/构建/依赖）→ 测试数据表 → 步骤表（#/位置/操作/数据/中间预期）→ 预期表（判定面/失败判定）→ 清理 → 证据要求 → 执行提示 → 追溯 → 变更记录。
- **步骤定位**：每一步都写清页面/区域/Tab/弹层/控件/行定位；列表→详情写「按 {列名} 定位行」；按钮用界面可见文案；禁「相关/适当按钮」。
- 口径变更 = 改断言 + 同轮同步脚本（`规则/专项/脚本执行.md` §4）；口径待探查先写「以本构建实现值」。
- **章节回执**：完稿前对主读逐章过一遍——每章要么「设计点→映射」，要么明确「无设计点」；缺章禁落盘。
- **评审留痕**：口令「用例评审」默认产出 `测试/功能测试/评审-{范围}-{yyyyMMdd-HHmm}.md`（结论与【任务收尾】第 1 点同源；「只审不录」可跳过；需修项在记录 §5 补记）。
- **引用抽验**：收尾前抽 2～3 条『设计来源』打开被引文件核对（不实即改）——错误拦在生成期，不留给评审。
- **质量评分卡**：场景/前置/步骤/预期/负面边界/独立清理/追溯/可读/数据/版本十项，0～2 分；缺入口/步骤/预期/追溯为阻断；≥18/20 且无阻断方可评审通过。

## 6. 行业参考（按需对齐 · 不落空话）

- **用例文档字段**：ISO/IEC/IEEE 29119-3（标识/目标/前置/输入/预期/环境/实际等）、ISTQB 基础级用例模板、TestRail/Qase/Zephyr 常用字段（优先级/类型/前置/步骤/预期/自动化/关联需求）。
- **验收表达**：Gherkin/BDD 的 Given/When/Then 可用于验收型用例；手工功能用例仍以步骤表 + 判定面为主。
- **GitHub 可选增强**（方法内化，不强制安装）：`fishzjp/qa-skills`（证据驱动/可执行用例，MIT）、`saleem-daqa/qa-test-case-generation`（非重复手工用例，MIT）、`JohnWayneeee/casely-qa-skill`（需求→TestRail-ready，MIT）、`gneder/qa-test-plan-skill`（需求→计划/Gherkin，MIT）。
- **安全面**：OWASP 常见清单（注入/越权/认证与会话/敏感数据暴露/文件上传/配置暴露）——安全相关用例按此对齐。
- **设计技法**：ISTQB 基本技法（等价类/边界值/判定表/状态迁移/场景法——即上文手册）；国内评审制项目可对齐 GB/T 15532。
- **引用写法**：写「对齐 {OWASP/ISTQB/ISO 29119} ×」即可，**禁**空写「已符合标准」。
