# 分析与计划（技能 · 随包生效）

> 用于：analyze / plan。**测试计划是执行编排的唯一载体**——计划不完整，后续执行一定失控。  
> **分析前置**：analyze 先按 `技能/test-basis-analysis/SKILL.md` 建需求模型、冲突/九类歧义清单与 oracle；本技能负责把“可测点/风险”转成计划与编排。计划必须引用需求模型/AC/TP；歧义未裁决不得写成确定范围。

## 1. 分析：从方案文档到可测点

- **先建模**：按 `test-basis-analysis` 十要素（目标/范围/角色/输入/输出/状态/规则/异常/依赖/待确认）+ 证据；再拆可测点。
- **四步拆解**：名词（对象/字段）→ 动词（状态变化/动作）→ 规则（约束/阈值/来源）→ 异常（失败/边界/权限）。
- **变更点三问**：变了什么、影响谁（邻接）、回归边界在哪。
- **可测承诺清单**：验收/GATE、主成功路径、状态与关键非法跃迁、权限/数据域、明确异常与阻断、变更点、影响面（逐邻接点）、负向边界。
- **风险分级**：主链路阻断/资金与安全/数据不可恢复/跨系统契约 → P0；影响 × 概率定优先级，拿不准向上一档。
- **测试类型建议**：按变更风险选功能/接口/回归/探索式/性能/安全/兼容/迁移/UAT；不适用写理由，禁默认「只测功能」。
- **输出**：轻量分析短表（变更点｜影响面｜口径待探查｜风险｜建议测试类型｜行→用例或处置），落 `测试/功能测试/分析短表.md`。

## 2. 计划：企业级测试计划 17 节（§0～§16）

按 `规则/模板/测试计划模板.md` 填，不跳节：

0. 一页状态（计划状态/当前阶段/当前门/下一动作/需人工/健康度/阻塞）
1. 测试对象与构建（版本/主读/环境/计划版本/负责人）
2. 目标与范围（范围内 + **明确排除** + 假设/约束）
3. 测试策略、类型与轨道（类型选择矩阵、轨道/资产、轮次、并行/依赖、设计技法、本轮执行矩阵）
4. 准入标准（计划/资产/环境/数据/冒烟）
5. 准出标准（P0、类型完成、缺陷清零、回归、探索式、报告）
6. 暂停/恢复（环境/主链路/数据合规/计划变更）
7. 环境、数据、账号与工具（环境矩阵/数据策略/角色/能力）
8. 风险与应对（产品/项目风险、概率、责任人）
9. 里程碑与执行编排（P0～P9 阶段表：范围/依赖/并行/入口/出口/产出）
10. 回归策略（连续回归、原单+冒烟+影响面、升级口径）
11. 缺陷管理（分级、提交策略、查重、修复-回归闭环）
12. 探索式测试（3～6 条章程：主题/风险/范围/时间盒/数据/排期）
13. 角色与职责（QA/开发/产品/Ops/UAT）
14. 交付物、度量与变更控制（含版本历史）
15. 变更批次（期中变更 CR 登记）
16. 执行日志与归档（§16.1 日志、§16.2 版本关闭/归档）

## 3. 测试类型选择法

| 变更特征 | 必选/建议 |
| --- | --- |
| 主链路、验收/GATE、资金/权限/数据 | 功能全量/专项 + 回归 + 安全冒烟 |
| 新增/变更接口、跨系统契约 | 接口/契约 + 功能联动 |
| 复杂状态、组合配置、时序并发 | 功能 + 探索章程（状态/数据/干扰漫游） |
| 性能敏感、大数据量、长稳 | 性能/容量/稳定性 |
| 权限/敏感数据/上传/注入面 | 安全（SAST/DAST/负向 smoke） |
| 浏览器/设备/OS/辅助功能 | 兼容/可访问性 |
| 存量数据、版本升级、可回退 | 数据迁移/升级/回滚演练 |
| 业务验收/客户签字 | UAT |
| 上线风险/监控/回滚 | 灰度/生产验证 |

- **选「否」必须写理由**；文档未声明 ≠ 免测（权限至少角色冒烟）。
- 本包执行功能/接口/探索式/发布前；单元/静态、UAT、灰度/生产验证登记责任人，不冒充已测。

## 4. 执行编排法

- **依赖图**：构建 → 冒烟 → 功能 → 接口/非功能/探索式（可并行）→ 回归（连续）→ UAT → 发布前/灰度 → 报告。
- **并行条件**：账号/数据/浏览器 profile/写域隔离；同一条用例禁并行；写冲突串行。
- **回归插入**：缺陷修复后立即回归，不等批末；范围=原单+冒烟子集+影响面组；高风险/连环缺陷提示升级。
- **探索式穿插**：对应业务面稳定后按章程执行；session → debrief → 缺陷/补用例/补章程。
- **门禁**：每阶段入口/出口写清；未过不进入下游（或按阻断面分流）；计划偏差回计划门或记报告。
- **估算与排期**：按用例数/模块/风险给粗略人日与里程碑；计划 §9.1 里程碑、§14.2 工作量偏差；不追求精确，但要有可对照的数。

## 5. 计划质量自检（落盘前逐项过）

- 范围/排除/假设/约束齐，无「全部/适当」空词。
- 范围/类型/编排/章程引用需求模型/AC/TP；未裁决歧义、GAP、假设已显式列出，未写成确定结论。
- 测试类型逐项选「是/否」+ 依据；不适用有理由。
- 轨道与资产路径可回查；生成状态明确（待生成/已生成）。
- 执行编排阶段可执行：依赖/并行/入口/出口/产出/负责人齐。
- 回归、缺陷提交、探索章程可落地；缺陷策略与计划门授权一致。
- 准入/准出可判定；P0/缺口/风险接受规则明确。
- 环境/数据/账号/工具齐；外部责任项标注「协调/不冒充」。
- 计划门摘要能一行说清：范围/类型/轨道顺序/缺陷策略/探索章程数/准出。
