# 分析与计划（技能 · 随包生效）

> 用于：analyze / plan。**测试计划是执行编排的唯一载体**——计划不完整，后续执行一定失控。  
> **分析前置（不可跳）**：analyze 先按 `技能/test-basis-analysis/SKILL.md` 建需求模型、冲突/九类歧义、不变量、显式/隐式、章节回执与 oracle，并过 `confirm_understanding`；本技能只把「已确认的可测点/风险」转成计划与编排。计划必须引用**测试分析表**/AC/TP；**理解未确认或关键歧义未裁决 → 不得「计划已确认」/不得宣称迭代功能准出。**

**提测影响面 → 装填**：把提测单影响面/回归范围映射进计划 **§3.7**（命中域 + `suite=core|module|full`）；L0/L1/L2、suite、装填为测试内部词，不要求开发会写。有提测单优先消费其字段；无则自填命中域，不阻塞。

## 1. 分析输入（不重复建模）

> **建模流程 SSOT** = `技能/test-basis-analysis/SKILL.md`。本技能**禁止**再写十要素/九类歧义/章节回执全流程；只**消费**已确认的测试分析表。

- **输入**：`测试/测试分析表.md`（覆盖单元+影响面+歧义+oracle）；无表或理解未确认 → 先回 analyze / `confirm_understanding`，不在此重建模。
- **变更点三问**（计划用）：变了什么、影响谁（邻接）、回归边界（本期增量 / 依赖上游 P0-Smoke / 无关跨域默认排除）。
- **覆盖与依赖**：P0/GATE 须落资产行；依赖版只强制 P0-Smoke 实测（禁假设已过；升全量须点名）。
- **风险/类型**：主链路阻断等 → P0；按风险选功能/接口/回归/探索/性能/安全等，不适用写理由。
- **输出**：计划 §3.7 装填域来自分析表；无表不得宣称计划已完整。

## 2. 计划：企业级测试计划（§0～§18；核心 §1～§16）

按 `规则/模板/10-计划/测试计划模板.md` 填，不跳节：

0. 一页状态（计划状态/当前阶段/当前门/下一动作/需人工/健康度/阻塞）
1. 测试对象与构建（版本/主读/环境/计划版本/负责人）
2. 目标与范围（范围内 + **明确排除** + 假设/约束）
3. 测试策略、类型与轨道（类型选择矩阵、轨道/资产、轮次、并行/依赖、设计技法、本轮执行矩阵）
4. 准入标准（计划/资产/环境/数据/冒烟）
5. 准出标准（P0、类型完成、缺陷清零、回归、探索式、报告）
6. 暂停/恢复（环境/主链路/数据合规/计划变更）
7. 环境、数据、账号与工具（环境矩阵/数据策略/角色/能力）
8. 风险与应对（产品/项目风险、概率、责任人）
9. 里程碑与执行编排（P0～P9 阶段表：范围/依赖/并行/入口/出口/产出）
10. 回归策略（连续回归、跨版本失败/待实现/已修复、原单+冒烟+影响面、升级口径）
11. 缺陷管理（分级、提交策略、查重、修复-回归闭环）
12. 探索式测试（3～6 条章程：主题/风险/范围/时间盒/数据/排期）
13. 角色与职责（QA/开发/产品/Ops/UAT）
14. 交付物、度量与变更控制（含版本历史）
15. 变更批次（期中变更 CR 登记）
16. 执行日志与归档（§16.1 日志、§16.2 版本关闭/归档）

## 3. 测试类型选择法

| 变更特征 | 必选/建议 |
| --- | --- |
| 主链路、验收/GATE、资金/权限/数据 | 功能全量/专项 + 回归 + 安全冒烟 |
| 新增/变更接口、跨系统契约 | 接口/契约 + 功能联动 |
| 复杂状态、组合配置、时序并发 | 功能 + 探索章程（状态/数据/干扰漫游） |
| 性能敏感、大数据量、长稳 | 性能/容量/稳定性 |
| 权限/敏感数据/上传/注入面 | 安全（SAST/DAST/负向 smoke） |
| AI/LLM/RAG/Agent | AI 评测（oracle/重复阈值）+ 功能 + 提示注入/越权/红队 |
| 浏览器/设备/OS/辅助功能 | 兼容/可访问性 |
| 多语言/多地区 | 本地化（文案/日期/金额/RTL） |
| 测试数据/环境/依赖变更 | 数据与环境核验、依赖回归 |
| 存量数据、版本升级、可回退 | 数据迁移/升级/回滚演练 |
| 业务验收/客户签字 | UAT |
| 上线风险/监控/回滚 | 灰度/生产验证 |

- **选「否」必须写理由**；文档未声明 ≠ 免测（权限至少角色冒烟）。
- 本包执行功能/接口/探索式/发布前；单元/静态、UAT、灰度/生产验证登记责任人，不冒充已测。

## 4. 执行编排法

- **依赖图**：构建 → 冒烟（有前序依赖则含依赖版 P0-Smoke）→ 本期功能 → 接口/非功能/探索式（可并行）→ 回归（连续）→ UAT → 发布前/灰度 → 报告。
- **并行条件**：账号/数据/浏览器 profile/写域隔离；同一条用例禁并行；写冲突串行。
- **回归插入**：缺陷修复后立即回归，不等批末；范围=原单+冒烟子集+影响面组；高风险/连环缺陷提示升级。
- **探索式穿插**：对应业务面稳定后按章程执行；session → debrief → 缺陷/补用例/补章程。
- **门禁**：每阶段入口/出口写清；未过不进入下游（或按阻断面分流）；计划偏差回计划门或记报告。
- **估算与排期**：按用例数/模块/风险给粗略人日与里程碑；计划 §9.1 里程碑、§14.2 工作量偏差；不追求精确，但要有可对照的数。

### 4.1 自动化分层与 CI 门

- **分层**：接口/契约/单测优先于 UI；稳定的主链路/回归脚本化，探索/一次性/视觉判断保留人工或半自动。
- **选择**：高频、稳定、可断言、数据可造、跨版本重复执行 → 脚本；频繁变/强视觉/难断言 → 人工/AI 辅助，不硬脚本化。
- **CI 门**：提交级 smoke；合并/夜间全量或模块回归；发布前最小充分集；失败阻断规则写清，不静默跳过。
- **flake 治理**：失败先分诊（产品/环境/数据/脚本/随机）；有界重试并记录；长期 flaky 隔离并修，不靠重跑刷绿。
- **维护**：脚本 owner、选择器/数据/环境依赖、执行时长、清理；定期删失效脚本，避免负资产。
- **AI 生成脚本**：只作候选；必须人工评审断言/数据/清理，禁直接进回归门。
- 方法见 `技能/test-data-and-environment/SKILL.md`、`规则/专项/脚本执行.md`；本表只定策略与门。

## 5. 计划质量自检（落盘前逐项过）

- 范围/排除/假设/约束齐，无「全部/适当」空词。
- 范围/类型/编排/章程引用需求模型/AC/TP；未裁决歧义、GAP、假设已显式列出，未写成确定结论。
- 主读有前序/GATE 依赖时：§2.2/§9.2/§10 已写依赖版 P0-Smoke 路径与条数；无「有界对照即回归」。
- 测试类型逐项选「是/否」+ 依据；不适用有理由。
- 轨道与资产路径可回查；生成状态明确（待生成/已生成）。
- 执行编排阶段可执行：依赖/并行/入口/出口/产出/负责人齐。
- 回归、缺陷提交、探索章程可落地；缺陷策略与计划门授权一致。
- 准入/准出可判定；P0/缺口/风险接受规则明确。
- 环境/数据/账号/工具齐；外部责任项标注「协调/不冒充」。
- 数据与环境：版本/隔离/造数/清理/依赖 mock 已定；无生产 PII。
- AI 功能：oracle/评测集/重复阈值/红队/成本延迟已定；无 oracle 不写“通过”。
- 自动化：分层/CI 门/flake 治理/维护 owner 已定；AI 生成脚本不直接进回归门。
- 计划门摘要能一行说清：范围/类型/轨道顺序/缺陷策略/探索章程数/准出。
