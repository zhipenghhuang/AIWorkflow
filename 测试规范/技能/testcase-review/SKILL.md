# 用例评审（技能 · 随包生效）

> 字段/门禁以 `规则/工作流.md` §2.5、`规则/模板/40-报告与评审/评审记录模板.md`、`agents/testcase-reviewer.yaml` 为准；本技能=**用例细轴**量规。  
> **范围总览 / 计划·分析·多轨 / 选 B【自主分析】** → 先读 `技能/test-artifact-review/SKILL.md`。  
> **定位**：生成之后、执行之前的**独立静态评审**；不重生成、不改口径。

> **增量诚实 · 一遍过范围**：审「命中域是否增量到位、增改删表是否诚实」，不要求全仓重生才算一遍过；一遍过=命中范围宁多勿漏≠全库重写。未命中域缺改≠覆盖失败。

## 1. A/B 停问与独立性（SSOT）

**不在此复述 A/B 文案与级别表** → 一律按 `技能/test-artifact-review/SKILL.md`（选 B【自主分析】、独立性、级别强制）。本技能只提供用例细轴量规；未先完成总览停问不得直接打分放行。

## 2. 评审流程（高标准 · 一遍过）

1. **定批次**（`工作流` §2.5）：读计划 §3.7 / 本轮装填；同轨同主读 → 默认可合卷；跨轨拆开；T0/≤3 条可 SELF_CHECKED。同批只问一次 A/B。  
2. **定范围**：本批用例路径列表、条数、计划 §3.2 资产行、覆盖闸回执。合卷 §1 列全路径。  
3. **抽基线**：打开分析表/AC/TP；抽 3～5 条追溯链实开核对。  
4. **单条量规**（P0 全审，P1≥50%，P2 抽 20% 且 ≥5）：见 §3；合卷按域抽样。  
5. **套件量规**（整批一次；某域独有空洞在说明列点名）：见 §4。  
6. **缺口分级** → A/B：  
   - **选 A**：评审记录 + HUMAN_APPROVED；**不跑** `-Mode review`。  
   - **选 B**：评审记录 → `-Mode review` → 据门 JSON。  
7. **结论**：整批 +（合卷时）分域；未放行域禁入执行装填。需修回 generate；同回合重审 ≤1。  
8. **落盘**：单域 `{NN}-{短名}-评审-{戳}.md` 或合卷 `测试/{轨}/评审-{摘要}-{戳}.md`。

## 3. 单条量规（A1–A6 · 任一条 FAIL=阻断）

> 对齐 ISO/IEC/IEEE 29119-3 字段意图 + ISTQB CTFL 静态测试/追溯；阈值参考行业 test-case-review-rubric。

| ID | 轴 | PASS | FAIL（阻断） |
| --- | --- | --- | --- |
| A1 | 目标具体 | 标题点名可观测行为与单一验证点 | 「测试登录/功能正常」或一条绑两个无关验证 |
| A2 | 前置可执行 | 账号/数据/入口/环境可被第二人复现；入口对齐 GEN/TP 已点名动作；写到菜单/路由/行定位 | 「系统就绪」「有数据」；入口空泛或与场景载体不符 |
| A3 | 步骤原子 | 一步一交互；步骤↔预期同号；每步位置/操作/数据/中间预期齐全 | 一步多动作；步骤动词是「验证/检查」而非操作；「执行批量」「同业务详情/列表/弹层」「按场景数据」「本步结果可在页面核对」等空话 |
| A4 | 抽象层级匹配 | 业务规则用例用业务语言；UI 机制用例点名控件/区域 | 业务用例写死 DOM；UI 用例空到看不出测什么 |
| A5 | 预期可观测 | 值/状态/文案/字段=值；可失败；预期来自方案/AC/契约 | 「正常/正确/好看」；「本步结果可在页面核对」；无判定面；**因现网只显示“—”就把“待补配置”改成通过**（oracle 被实现弱化） |
| A6 | 追溯有效 | 指向现存 RQ/AC/F/R/TP/页面/接口；有场景表则落到场景不只原则 | 空追溯；指向已删需求；用现网实现当 oracle；只挂 G-xx 未落 GEN/TP 动作 |

另：**负面/边界**（写操作与字段级）缺失 → 重要或阻断（P0/资金/权限面=阻断）；**清理/证据**缺失 → 重要。

### 3.1 接口用例量规（I1–I6 · 审接口域时用；与 A 轴并列，任一条 FAIL=阻断）

> 骨架 SSOT=`接口测试用例模板.md`；机检=`validate_api_testcase.py`。

| ID | 轴 | PASS | FAIL（阻断） |
| --- | --- | --- | --- |
| I1 | 契约可核对 | path/方法/关键字段有主读或 Network/基线来源 | 猜 path；无来源；未验证导入当通过 |
| I2 | 对照禁空 | 每 EP×适用维有用例 ID 或「不适用+依据」；depth 声明一致 | 空单元格；用「软覆盖」顶替 |
| I3 | 请求可复现 | 前置鉴权/数据 + Headers/Query/Body 关键字段齐 | 「调用接口」无要点；密钥写进用例正文 |
| I4 | 判定三要素 | 状态码 + 业务码/信号 + 关键字段；有失败判定 | 仅 2xx；「返回正常」；无业务信号 |
| I5 | 写后回查/隔离 | 写条有回查；无 token/越权用隔离上下文 | 写后不查；越权条带着管理员会话测 |
| I6 | 脚本默认 | 确定性=是且脚本路径有效，或否+理由 | 可脚本化无脚本无理由 |

探索式/随机：至少核对「步骤四列 + 判定面 +（探索）章程映射 /（随机）占比自检」；空话步骤=重要或阻断（P0 面）。

## 4. 套件量规（S1–S6）

| ID | 轴 | PASS | FAIL |
| --- | --- | --- | --- |
| S1 | 分区覆盖 | 有效/无效等价类有代表 | 只有快乐路径 |
| S2 | 边界覆盖 | 关键数值/长度/分页有 min±1 等 | 文档有边界却无对应用例 |
| S3 | 去重 | 无实质重复步骤集 | 多条同前置同步骤同预期 |
| S4 | 无孤儿/无空洞 | 映射表每点有用例或「不适用+依据」；无幽灵 ID | 空映射；映射 ID 不存在 |
| S5 | 优先级形态 | P0-Smoke/HighRisk/P1/P2 分层合理；冒烟可脚本化已判 | 无 P0；或全部标 P0 |
| S6 | ID/模板一致 | ID 唯一、模板节齐全、排序稳定 | ID 冲突；缺节；乱序阻碍执行 |
| S7 | 方案/设计覆盖 | `GATE/AC/TP/F/R/§` 每个 P0 项有用例或「不适用+依据+接受人」；设计文档章节回执无缺章 | 只映射 DP/模块名；P0/GATE 无对应用例；范围外静默消失 |
| S8 | 数据链路/可观测性 | 幂等键落库/重放、统计窗口守恒、联动关键字段、点位级诊断、最新值来源/时间/质量、审计按对象检索、基线对象存在、受控场景包完整、`待实现` 交付后已复测 | 只测“页面能点/能返回”，未验证数据落库、窗口守恒、关联字段、诊断粒度、审计/加密、基线/场景包；`待实现` 长期不复测 |

**覆盖三闸复核**：细则 SSOT=`规则/工作流.md` §2.1.0；本步只复核三闸是否过（章节回执 / 映射无空+深度档 / 缺口三分类），对照 `testcase-design` §2.2。深度/视觉未达标 → 默认**重要**；P0 主链无失败分支或有状态无非法跃迁 → **阻断**；S7/S8 关键空洞 → **阻断**。

## 5. 评分卡与体验门（与生成同源，评审重打）

十项 0～2 分（场景/前置/步骤/预期/负面边界/独立清理/追溯/可读/数据/版本）；缺入口/步骤/预期/追溯=阻断；**≥18/20 且无阻断**才可放行。  
横向门：UX（照做）、DX（可维护/可脚本）、AX（结构化可追溯）任一净退化 → 需修。

## 6. 缺口分级与结论

| 级 | 含义 | 对放行 |
| --- | --- | --- |
| 阻断 | A 轴 FAIL、P0 覆盖空洞、P0 深度档缺主失败分支/有状态无非法跃迁、oracle 臆造、追溯断裂 | 禁止放行 |
| 重要 | 负面不足、深度/视觉摘要空或偏薄、影响面未落、评分卡 &lt;18、清理/证据弱 | 默认需修；用户书面接受可有条件放行（记接受人） |
| 建议 | 可读性、命名、非关键重复 | 可放行并记改进 |

结论仅二选一：`放行执行` ｜ `需修后放行`（有条件放行须写接受人+遗留）。

## 7. 输出纪律（Bugbot 风格 · 可扫描）

评审记录 + 收尾第 1 点必须含**按严重度排序**的缺口表：

| 严重度 | 位置（用例ID / 节） | 发现 |
| --- | --- | --- |
| 阻断/重要/建议 | `{ID} §步骤n` | `{一句话}` |

返回编排摘要 ≤30 行；禁贴全文用例。

## 9. 与执行 Reviewer 的边界

| | testcase-reviewer（本技能） | reviewer-agent（执行拆分档） |
| --- | --- | --- |
| 时机 | 生成后 / 执行前 | 执行批内 |
| 对象 | 用例设计质量 | jsonl↔证据↔预期 |

## 10. 门与退出

- 功能全量/专项 **选 B**：`验证/Invoke-Gate.ps1 -Mode review` → `.gate/测试规范/review.json`；未 PASS/CONDITIONAL 不得「放行执行」。  
- 功能全量/专项 **选 A**：评审记录 + HUMAN_APPROVED 即可放行；不跑机检。T0 可 SELF_CHECKED。  
- 退出准则：无未接受阻断；评分卡达标；覆盖三闸复核通过；评审记录与收尾结论同源。
