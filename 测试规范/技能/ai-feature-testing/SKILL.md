# AI 功能测试（技能 · 随包生效）

> 用于：LLM/RAG/Agent/分类/生成/抽取类功能的 analyze / plan / generate / execute / report。  
> 定位：AI 输出没有唯一答案，但**验收必须有可判定的 oracle、通过阈值和可复跑证据**。  
> 不替代：确定性功能仍按 `技能/test-basis-analysis/SKILL.md`、`技能/testcase-design/SKILL.md` 执行；安全面同时加载 `技能/test-performance-security-compatibility/SKILL.md`。  
> 不适用：无模型/无生成行为的确定性功能；走常规用例设计，不硬套评测集。

## 1. 先定义“什么算对”

- 任务：输入、输出、使用场景、失败后果、谁可接受/拒绝。
- Oracle 类型：精确值/规则断言｜字段/格式校验｜引用/来源一致性｜rubric 评分｜人工评审｜对比基线。
- 不可接受输出：编造事实、越权、泄露系统提示/隐私、危险建议、格式破坏、无限消耗。
- 允许方差：同一输入多次运行的合理差异；写清“N 次中 ≥M 次通过”或分档阈值。
- 没有 oracle 的功能不得宣称“测试通过”；只能报“探索/观察”。

## 2. 评测集（Eval Set）

- 组成：代表性主路径 + 边界/长尾 + 对抗/注入 + 历史缺陷 + 多语言/口音/错别字（按场景）。
- 每条：输入、上下文/检索、期望/评分规则、难度、来源、隐私级别、owner。
- 规模：先 30～100 条可用集，再按风险扩；质量优先于数量。
- 版本：数据集版本/哈希、标注人、变更记录；模型/提示词/检索变更跑同一套。
- 防止污染：评测集不进入训练/提示词；线上样本进集前先脱敏。

## 3. 测试维度

| 维度 | 检查 |
| --- | --- |
| 正确性/忠实度 | 事实正确、与检索/输入一致、不编造；引用可核 |
| 相关性/完整性 | 回答了问题、覆盖必要信息、不答非所问 |
| 格式/契约 | JSON/schema、字段、长度、语言、单位 |
| 安全 | 提示注入、越狱、数据外泄、系统提示泄露、危险内容 |
| 权限 | 检索/工具/数据域不越权；按调用者身份授权 |
| 鲁棒性 | 改写/错别字/多语言/超长/空输入/矛盾输入 |
| 工具/Agent | 工具选择、参数、循环/步数、失败恢复、人工确认 |
| 性能/成本 | 首 token/总延迟、token/费用、超时/限流/降级 |
| 体验 | 不确定性表达、引用展示、可编辑/可撤销、人工接管 |

## 4. 非确定性与 flaky 处理

- 重复运行：关键用例至少 3 次（高风险 5 次）；记录每次输出与判定。
- 通过标准：按风险定“全过/≥M/N/分档”；不得用一次通过代表稳定。
- 控制变量：固定模型版本、温度/采样、提示词、检索索引、工具版本；变更一项就重跑。
- 失败分类：模型随机性｜提示词/上下文｜检索｜工具/依赖｜数据｜环境｜真正缺陷。
- flaky 用例：先证明是随机性还是缺陷；不得直接标记“偶发忽略”。

## 5. RAG / 知识库专项

- 检索：召回率/精度、top-k、排序、无结果处理；按问题类型分群。
- 忠实度：回答是否有检索依据；引用是否指向正确片段；无依据时是否拒答。
- 新鲜度：旧文档/冲突文档/删除文档是否仍被引用。
- 权限：不同租户/角色问同一问题，不能看到越权内容。
- 切分/索引：改切分/embedding/索引后必须回归同一评测集。

## 6. Agent / 工具专项

- 工具选择与参数：该用不用、不该用乱用、参数错误、注入参数。
- 权限边界：只读/写/不可逆动作分级；不可逆动作必须人工确认。
- 循环/预算：步数、超时、token/费用上限；失败可中止。
- 提示注入：网页/文档/工具返回中的恶意指令不得改变系统目标或扩权。
- 审计：能还原谁在何时让 Agent 做了什么；敏感操作有记录。

## 7. 红队（高风险必做）

- 直接/间接提示注入、越狱、角色扮演、编码绕过、多语言绕过。
- 系统提示/密钥/其他用户数据套取；RAG 越权检索。
- 过度代理：未授权工具调用、批量删除/发送/支付。
- 无限消耗：超长输入/循环工具/重复请求导致费用或资源耗尽。
- 内容安全：仇恨/暴力/自伤/未成年人/医疗金融建议（按业务）。
- 记录：攻击输入、预期防线、实际结果、修复、复测；未修复的高危阻断发布。

## 8. 证据与报告

- 每次运行记录：模型/提示词/检索/工具版本、数据集版本/哈希、参数、时间、环境。
- 结果：逐条输入/输出/判定/评分/理由；失败样本可复现。
- 汇总：通过率、分维度、失败聚类、方差、成本/延迟、未覆盖项。
- 人工评审：抽样比例、评审人、分歧处理；LLM-as-judge 需校准与人工复核。
- 结论：通过/有条件/不通过；不得用“整体感觉不错”替代阈值。

## 9. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “输出挺像，应该没问题” | 像不等于对；要有 oracle/引用/规则/人工评审。 |
| “跑一次过了” | 非确定性功能一次通过不代表稳定；按 N 次/分档。 |
| “模型升级会更好” | 升级可能回归；必须跑同一评测集并对比。 |
| “提示注入是模型厂商的事” | 应用层要隔离指令/数据、限权、校验输出、做红队。 |
| “评测集太小没关系” | 小集只能做冒烟；高风险要覆盖边界/对抗/历史缺陷。 |
| “LLM 打分最方便” | judge 有偏差/漂移；需校准、抽样、人工兜底。 |

## 10. 红旗

- 没有 oracle/阈值，只说“看起来合理”。
- 只测 happy path，不测拒答/无依据/越权/注入。
- 模型/提示词/索引变更不做回归。
- 用一次运行结果代表稳定性。
- 评测集含生产 PII 或进入训练/提示词。
- 高风险 Agent 可无确认执行不可逆动作。
- 报告不记录模型/提示词/数据集版本，无法复跑。

## 11. 输出与 DoD

- 计划：oracle、评测集、维度、重复次数/阈值、红队、环境/数据、证据。
- 执行：逐条结果、失败分类、复现材料、成本/延迟。
- DoD：验收标准可判定；评测可复跑；非确定性有阈值；安全/权限/注入覆盖；高风险红队完成；未覆盖项与风险写清。
