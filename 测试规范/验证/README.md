# 验证（测试轨）

> 目的：让“测试通过/准出”有可对账的证据。门读现有测试计划/台账/报告，不新增测试文档。
> 读取时机：`review-cases`、`execute` 批末、`report`、`handoff`/交平台前。维护读 `规则/核心/规则治理.md`。

## 1. 什么时候跑

| 场景 | 命令 | 输出 |
| --- | --- | --- |
| 生成覆盖 | `Invoke-Gate.ps1 -Mode coverage` | §3 映射/ID + §4 深度档自检/视觉基础行 |
| 用例评审 | `Invoke-Gate.ps1 -Mode review` | 评审记录结构/独立性/放行结论（`.gate/测试规范/review.json`） |
| 执行批末 | `Invoke-Gate.ps1 -Mode execute` | 台账/证据/阻塞检查 |
| 出报告/准出 | `Invoke-Gate.ps1 -Mode report` | 报告↔台账↔P0 计划覆盖对账 |
| 交平台/回写 | `Invoke-Gate.ps1 -Mode writeback` | 平台回执检查（不覆盖 report） |

```powershell
powershell -ExecutionPolicy Bypass -File "测试规范/验证/Invoke-Gate.ps1" -Mode report -ProjectRoot "."
```

## 2. 检查什么

- **计划**：`测试/测试计划.md` 存在；§0 状态、§5 准出、§9.2 编排、§11 缺陷策略、§12 探索章程可读；§3.7/§9.2 与 `00-稳定冒烟清单` 的 P0 用例必须进台账。
- **台账**：§1 汇总与 §2 结果表计数一致；状态合法；失败/待实现（实现缺陷）/阻塞有证据；待实现计入缺陷；阻塞写已尝试/恢复条件；`用例优先级` 列用于 P0，`缺陷优先级` 单独记录。
- **P0**：P0-Smoke / P0-HighRisk 未通过、未执行或计划有但台账缺失时，报告不得写 PASS/整体通过。
- **报告**：§4 数字与台账一致；§1 准出评估必须唯一（PASS/CONDITIONAL/FAIL/BLOCKED）且与 P0/未执行/缺口一致；回执若已填，必须与门 verdict 一致。
- **覆盖**：功能全量/专项 §3 映射无空行且映射到真实用例 ID；§4 含「深度档自检」「视觉基础」行（缺则 FAIL）；报告/coverage 模式功能资产必须有映射；P0 点有用例或“不适用+依据”。语义是否达标见评审量规，门不臆造深度分数。
- **用例评审**：存在现行 `评审-*.md`；可解析结论（放行执行/有条件放行/需修后放行）；含独立性与量规/严重度痕迹；放行时不得残留未消化阻断；有条件放行须有接受人；语义量规（A1–A6/S1–S6）由 AI 按技能执行，机器只核结构与放行态。
- **回写**：交平台时存在回执（单号/备注/状态/附件）；`writeback` 只写 `.gate/测试规范/writeback.json`，不要求计划/台账，不覆盖 report。
- **口径**：只统计当前台账，`_归档`/`.draft`/`资料`/`证据` 不参与对账。

## 3. 完成状态

> `PASS/CONDITIONAL/FAIL/BLOCKED` 条件与报告措辞见 `规则/核心/验证规则.md` §2；本文件不重复状态表。回执中文：可准出/有条件准出/不准出/阻塞；机器仍读 PASS/CONDITIONAL/FAIL/BLOCKED。

## 4. 成本纪律

- 门只读现有计划/台账/报告，不要求新增文档。
- 只对版本级/全量/计划驱动跑 report 门；单模块小批跑 execute 门即可。
- 证据抽样打开，不逐张人工看；失败/阻塞必看。
- 全量回归只留给发布/大版本；补丁按计划 P0 冒烟 + 影响面。
