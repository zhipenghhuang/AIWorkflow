# 验证（测试轨）

> 目的：让“测试通过/准出”有可对账的证据。门读现有测试计划/台账/报告，不新增测试文档。
> 读取时机：`execute` 批末、`report`、`handoff`/交平台前。维护读 `规则/30-规则治理.md`。

## 1. 什么时候跑

| 场景 | 命令 | 输出 |
| --- | --- | --- |
| 执行批末 | `Invoke-Gate.ps1 -Mode execute` | 台账/证据/阻塞检查 |
| 出报告/准出 | `Invoke-Gate.ps1 -Mode report` | 报告↔台账↔P0 对账 |
| 交平台/回写 | `Invoke-Gate.ps1 -Mode writeback` | 平台回执检查 |

```powershell
powershell -ExecutionPolicy Bypass -File "测试规范/验证/Invoke-Gate.ps1" -Mode report -ProjectRoot "."
```

## 2. 检查什么

- **计划**：`测试/测试计划.md` 存在；§0 状态、§5 准出、§9.2 编排、§11 缺陷策略、§12 探索章程可读。
- **台账**：§1 汇总与 §2 结果表计数一致；状态合法；失败/阻塞有证据；阻塞写已尝试/恢复条件。
- **P0**：P0-Smoke / P0-HighRisk 未通过时，报告不得写 PASS/整体通过。
- **报告**：§4 数字与台账一致；§1 准出评估必须唯一（PASS/CONDITIONAL/FAIL/BLOCKED）且与 P0/未执行/缺口一致。
- **覆盖**：功能全量/专项 §3 映射无空行；报告模式下功能测试资产必须有映射；P0 点有用例或“不适用+依据”。
- **回写**：交平台时存在回执（单号/备注/状态/附件）；`writeback` 模式只核回执，不要求计划/台账。
- **口径**：只统计当前台账，`_归档`/`.draft`/`资料` 不参与对账。

## 3. 完成状态

| 状态 | 条件 | 报告措辞 |
| --- | --- | --- |
| `PASS` | P0 全过；未执行=0；台账/报告数字一致；准出评估=PASS；证据可打开；无未接受缺口 | 通过/可准出 |
| `CONDITIONAL` | P0 全过；缺口非 P0；准出评估=CONDITIONAL 且用户书面接受 | 有条件通过；列遗留 |
| `FAIL` | 任一 P0 失败；准出评估=PASS 但有失败/未执行；关键证据缺失；数字不一致 | 不通过；列失败 |
| `BLOCKED` | 环境/输入/回执缺失；无法对账 | 阻塞/未验证 |

## 4. 成本纪律

- 门只读现有计划/台账/报告，不要求新增文档。
- 只对版本级/全量/计划驱动跑 report 门；单模块小批跑 execute 门即可。
- 证据抽样打开，不逐张人工看；失败/阻塞必看。
- 全量回归只留给发布/大版本；补丁按计划 P0 冒烟 + 影响面。
