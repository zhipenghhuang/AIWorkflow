# 测试数据与环境（技能 · 随包生效）

> 用于：plan / execute 中涉及环境、账号、数据、依赖的准备与核验。  
> 定位：**数据与环境是测试的一部分，不是开跑前的杂事**；不可复现的数据会让结论不可信。  
> 边界：环境搭建/运维归开发/Ops；本技能定义测试侧准备、隔离、清理与证据。  
> 不适用：纯静态检查/无需环境数据的评审；仍要记录依据与版本。

## 1. 环境基线（先核验再开跑）

> 先读 `env-baseline.md` **命中节**（按标题，不整本通读）：项目身份、登录、账号、浏览器；本批再加接口/造数/样本/冲突/平台/脚本等相关节。计划 §2.2 只写命中节/差异/核验。缺基线或占位未换 → 先接入/补基线，不猜 URL/账号/字段。

- 记录：环境名/URL、版本/构建/提交、配置差异、依赖版本、证书/域名、特性开关、数据版本。
- 可比性：与目标环境（预发/生产）的差异逐项列出；不可比项写限制，不冒充生产结论。
- 可用性：入口、账号、权限、网络、第三方沙箱、文件存储、消息/任务是否就绪。
- 重置：能否一键重置数据/配置；谁负责；重置耗时；重置后如何验证。
- 变更：测试期间环境/构建变更必须记录时间点，受影响用例重跑或标失效。
- **回写（硬）**：本轮打通的新可复用造数/API/样本/冲突（**含脚本或命令入口与参数**）→ 同轮按基线「同步规则」增补；批末有则补齐、无则禁改。映射以实例同步节为准（模板常为 §12）。

## 2. 数据策略（最小充分）

> **执行卡点（硬）**：缺数据/样本不对 → **先查基线造数/样本节**，再本策略造数或换样；未穷尽自助手段 **禁止** 把场景标成 `阻塞`（终态见 `classification.md` §0.4）。能界面/API/脚本造通却空等外力 = 违规。

| 策略 | 适用 | 注意 |
| --- | --- | --- |
| 复用现有 | 只读/稳定主数据 | 先核对状态与版本；防脏数据；**基线造数/样本节优先**（节号以实例为准） |
| 界面/API 造数 | 业务闭环、状态流转 | 走真实校验；记录步骤与 id；**缺数默认走这条**；打通后回写基线 |
| 脚本/夹具 | 批量、边界、回归 | 固定 seed；可重复；清理 |
| 数据脱敏 | 需要真实分布 | 不可逆/不可重识别；不留原值 |
| 合成数据 | 隐私敏感、极端组合 | 保持分布/约束，不伪造业务规则 |

- 覆盖：主路径 + 边界/极端 + 非法/缺失 + 权限/租户 + 状态迁移；不为每条用例造全量数据。
- **负向绑定**：`testcase-design` §3 命中的专用负向（同键异体、冲正/更正、前提缺失、历史改写、经营隔离等）须有**可复现造数/换样**（基线配方或本批步骤）；无配方不得将该负向标通过。
- 确定性：固定 seed/时间/时区/随机源；避免“今天能过明天不能过”。
- 幂等：写操作用唯一键/`REG-`/runStamp；重复执行不叠加副作用；隔离前缀对象勿混入正式经营样本窗（方案有隔离要求时）。
- 清理：用例后清理或标注；失败也清理；清理失败要记录并隔离，不留给下一位。

## 3. 隔离与并行

- 隔离维度：账号、租户、数据域、浏览器 profile、写域、消息队列、文件目录。
- **隔离套登记**：并发前在计划 §4.3/§5.2 登记 `profileDir/debugPort/browserUrl/账号/写域/downloadDir`；同一隔离套只一个 writer；同一 MCP 内部并行需支持独立会话/请求级路由或每 worker 独占实例；只读可同上下文/账号，写需独立 profile/context、账号/数据/写域隔离，否则串行；隔离套数决定并行上限（默认 ≤3，UI 默认 ≤2，按资源调整）。
- **浏览器资源**：性能/压测窗口不并行 UI；下载/截图写本批目录；同账号/同 profile/同 port/同写域任一交叉 → 串行。
- 同一条用例禁并行；共享写资源串行；冲突登记（谁在用什么数据/账号）。
- **共用数据归属**：跨批次/跨版本复用的数据须登记 owner、版本范围与失效条件；复用前核对 owner 未变、状态未漂移，否则重造或换样（不靠「上次是好的」）。
- 并行前验证：两个 worker 同时跑不互踩；失败可定位到 worker。
- 只读共享数据可复用；写数据默认私有。

## 4. 账号与权限

- 角色矩阵：匿名/普通/管理员/跨租户/无权限；每类至少一个可用账号。
- 账号来源、有效期、锁定/验证码/二次认证处理；禁止把真实用户账号当测试账号。
- 密码/令牌按基线管理，不入库、不进截图、不进报告。
- 权限用例必须验证“拒绝”而不是只验证“能进”。

## 5. 依赖与模拟

- 第三方：优先沙箱/测试租户；无沙箱则 mock/stub，并记录与真实的差异。
- 时间/时钟：可注入/可回拨；跨时区/夏令时单独验证。
- 网络：慢网/断网/超时/重试/乱序；用工具模拟，不靠“感觉”。
- 文件/消息/任务：准备输入文件、队列消息、定时任务触发方式；验证消费/补偿。
- mock 纪律：mock 行为要与契约一致；契约变更同步 mock；禁止 mock 掉要测的核心逻辑。

## 6. 数据质量与证据

- 开跑前抽查：关键字段、状态、关联关系、数量级；异常先修数据再测。
- 证据：环境快照、构建号、账号角色、数据集 id/seed、造数摘要（对象+关键 ID）；造数回执（响应体/ID 清单）进 `.draft`，不进正式证据；清理结果。
- 失败复现：记录数据 id/请求 id/时间窗；能导出最小数据集就导出。
- 报告：数据/环境限制、缺口、不可比项；不把环境问题算产品通过/失败。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “先用手头数据跑，跑不通再说” | 脏数据会把实现问题伪装成数据问题；先核验/换样。 |
| “缺数据就标阻塞等别人” | 违规；能造数/换样必须先做；穷尽外力后才阻塞。 |
| “负向场景没数据，主路径过了就算测到” | 否；专用负向无配方=未测；先造/换样再判。 |
| “用生产数据最真实” | PII/合规风险；必须脱敏/授权/最小化。 |
| “清理太麻烦，留着吧” | 残留数据污染后续用例，且可能泄露；必须清理或隔离。 |
| “ mock 一下就行” | mock 掉核心逻辑=没测；只 mock 外部依赖并记录差异。 |
| “环境不一样但应该没事” | 差异就是风险；写限制或换环境，不静默假设。 |

## 8. 红旗

- 不知道当前构建/配置/数据版本就开跑。
- 多用例共用同一写账号/同一数据，互相污染。
- 测试数据含真实手机号/身份证/银行卡/地址。
- 失败无法复现，因为没有记录数据 id/seed/时间。
- 环境变更后不重跑受影响用例。
- 清理失败静默放过。

## 9. 输出与 DoD

- 计划：环境矩阵、数据策略、账号矩阵、依赖/mock、隔离与并行、清理、风险。
- 执行：环境/数据快照、造数记录、隔离登记、清理结果。
- DoD：环境/构建/数据版本可追溯；数据可复现；无生产 PII；并行不互踩；失败可复现；清理完成或有隔离记录。
