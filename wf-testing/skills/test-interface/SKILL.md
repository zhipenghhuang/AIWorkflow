# 接口测试（技能 · 随包生效）

> 产物/维度/脚本以 `rules/tracks/api.md` 为准；文档骨架 `rules/templates/20-test-cases/api-test-case-template.md`（执行记录）。  
> 原则：**脚本优先、契约先行、判定三要素、写后回查**；不预写全量接口用例，执行时按意图/契约生成场景并记录。

## 0. 必做

1. 读主读/OpenAPI/Network/前端契约 + 计划 §2 接口意图；禁猜 path/字段（禁按模块名对称拼 path）。
2. 建契约清单：EP、方法+path、鉴权、关键参数、成功码/关键字段、错误码、来源。
3. **先填 §2.1 维表**（每 EP：适用维 → `SC-*` 或 `不适用+依据`；depth 底线见 `tracks/api`），再按表生成场景；禁先探活后补空表。
4. 执行时写 `{workroot}/{ver}/api/{NN}-{短名}-执行记录.md`；确定性同轮脚本；探活只进 `.draft`。
5. 跑 `python rules/tools/validate_api_testcase.py <域文件>`；ERROR 未清=未完成。
6. 声明 depth：迭代 standard、发版 full、补丁 core；不得用“只跑高风险”冒充 standard。

## 1. 契约阅读

- 必填/类型/格式/枚举/范围/长度/默认/错误码；未声明=风险点，标试/问/不适用。
- 契约版本；breaking change（删字段/改类型/改语义/新必填）单独标记并更新场景/脚本。
- path/方法/字段以原文或本轮实测为准；冲突标明以何为准。

## 2. 脚本优先

- 确定性接口 → 同轮脚本（`executor --mode=api`）；回归 0 token。
- AI 只做契约探查、语义判定、脚本生成/维护、失败复核；不逐步点 UI 替代接口。
- 脚本放域内 `scripts/`；P0 接口冒烟登记 `smoke-checklist.md`；失败有界复核 1 次再定性。

## 3. 判定与证据

- 三要素：HTTP 状态码 + 业务码/信号 + **点名关键字段=值**；仅 2xx 不算通过；假成功/200 空壳=失败；「message 非空/有 data」≠通过。
- 写条写后回查（列表/详情/**状态字段=期望值**）；配置/账号类写口同此；方案要求的版本/来源/幂等键等追溯字段在命中响应中断言；同义多字段冲突=失败。
- 无 token/越权用隔离上下文；请求摘要不含密钥；证据含响应码/字段/脚本 jsonl。失败/待实现留 `入口指纹`；空列表/404/未交付须先排除测侧误用。
- 错误语义对齐：预期业务阻断时实际须同类门禁/阻断码；入口错配/指纹过期/参数门禁错类不算“符合预期”；失败原因须业务可读，SQL/堆栈原文可作缺陷证、不得当合格错误契约。

## 4. 缺陷谱系

参数校验缺口｜越权/IDOR｜幂等缺失/重放｜终态重入｜超长/Emoji 截断｜分页/排序注入｜错误码语义错/假成功｜精度/时区｜大字段/响应膨胀｜METHOD/Content-Type 误用。

## 5. 资产与复用

- 按域/契约维护执行记录 + 脚本；新版本只更新受影响 EP；旧轮归档 `api/_archive/`，不整包装进根 `_archive/`。
- 失败分诊：产品/契约漂移/脚本漂移/环境数据；脚本漂移修脚本，契约漂移更新记录与脚本。
- 未覆盖维度/限制写清；mock 结论不得冒充真实链路。

## 6. DoD

- 契约清单有来源；§2.1 维表无空白；depth 已声明；机检无 ERROR。
- 判定三要素 + 写后回查 + 脚本/理由；证据可打开。
- 失败分类；未覆盖/限制写清；报告与记录一致。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “UI 过了接口就不用测” | 迭代必须纳入接口轨（§0，整轨否仅白名单+用户确认）；须按 depth；契约/错误码/幂等独立覆盖；UI 探针≠接口轨。 |
| “先手点再补脚本” | 能脚本不 AI；稳定契约优先自动化。 |
| “现网响应当预期” | Oracle 来自契约/需求，不按实现改预期。 |
| “2xx 就算通过” | 状态码+业务信号+关键字段=值；假成功=失败。 |
| “有 message/failReason 就算错误契约过” | 须业务可读且与门禁同类；异常原文当合格错误=失败。 |
| “对称猜 path 404 就未交付” | path 须契约/Network；未钉指纹禁交「入口不存在」。 |
| “覆盖对照做成全维矩阵才完整” | 按适用维；不适用写依据；不要求全维空表。 |
| “功能执行记录里已有 API 证据” | 那是探针；接口轨完成仍要本域 `api/` 记录+契约清单+§2.1 维表。 |
| “depth=full 太重，先只跑关键写口” | 须改计划声明更低 depth 并经确认；禁静默缩 full。 |
| “探活全绿 / 通过率高就能关批” | 否；认正文+维表+机检；探活不顶替。 |
| “路由 404 就算不存在资源维过了” | 否；路由未挂≠业务对象不存在（`tracks/api` 404 分型）。 |
| “越权返回非 500 就算过” | 否；须拒绝或空域可观测。 |
