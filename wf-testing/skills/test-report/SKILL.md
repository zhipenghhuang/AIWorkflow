# 测试报告与准出结论（技能 · 随包生效）

> 用于：`testing.report`。  
> 目标：把本轮执行事实收敛成**唯一结论**，让读者能复核“为什么是这个结论”。  
> 边界：不新增测试、不改执行记录；不替产品/业务做发布决策；不把“未执行”写成“通过”。

## 0. 必做

1. 读本轮 `test-analysis.md` §2.1 台账、`test-plan.md` §3/§4、全部执行记录与证据，再写结论。  
2. 先对账计数，再写 verdict；计数不一致 → 先修数据或标 GAP，不写结论。  
3. 结论唯一：`PASS | CONDITIONAL | FAIL | BLOCKED`；同一报告不得并列两个主结论。  
4. 每个 P0 有终态与证据；每个 `处置=测` 意图有终态；失败/阻塞/待实现有缺陷号或明确处置。  
5. CONDITIONAL 必须写接受人、接受范围、复审点；无接受人 → FAIL。  
6. 报告落 `{workroot}/{ver}/test-report.md`；完成前跑 `-Mode report` 与 `-Claim -Mode report`。

## 1. 输入与对账

| 输入 | 取什么 | 对账点 |
| --- | --- | --- |
| `test-analysis.md` | §2.1 意图台账、P0/P1/P2、Oracle、覆盖矩阵 | 意图总数、处置=测数、P0 数 |
| `test-plan.md` | §0 状态/准出、§3 批次/轮次、§4 准出条件 | 计划范围 = 报告范围 |
| 执行记录 | 场景表、§3 意图结论、证据路径、缺陷号 | 场景数、通过/失败/阻塞/待实现、证据可打开 |
| 平台/缺陷 | 单号、状态、备注 | 失败是否有归属、回写是否完成 |

- 计数以**记录中的实际行**为准，不以计划声明为准；差异写 GAP 并说明影响。  
- 原文对账未关数 >0 → 不得 PASS；只能 CONDITIONAL（有接受人）或 FAIL/BLOCKED。  
- 计划纳入的功能/接口/探索/发布前轨道，每轨都要有可复核记录；空壳记录按未执行处理。

## 2. 结论判定（按顺序，不跳级）

| 结论 | 判定条件 | 允许动作 |
| --- | --- | --- |
| **PASS** | P0 全过且有证伪/负向；全部处置=测意图终态；原文对账未关=0；无阻断失败；四轨记录齐 | 可写“准出通过”；进入 closeout |
| **CONDITIONAL** | 过程完整，仅剩已登记的产品/业务红；§4 有接受人+复审点；无未解释的测试缺口 | 可进 closeout；报告须标“有条件通过” |
| **FAIL** | 存在测试失败、P0 未过、意图未终态、原文对账未关且无接受人 | 先修/补测/回开发；不得写通过 |
| **BLOCKED** | 环境/数据/入口/权限不可用，且已按有界自助仍无法恢复 | 写卡点+已尝试+恢复条件；不得判通过 |

- 失败与阻塞并存 → 优先 FAIL（阻塞是原因，不是结论）。  
- 只有 P0 通过、P1/P2 未测 → 不得 PASS；P1/P2 也是覆盖义务。  
- `未执行`/`未本轮验证` 仍在 → 批未关，不得 PASS。  
- 报告结论必须与 `-Mode report` 机检一致；机检 FAIL 时先修报告，不辩解。

## 3. 报告写法

1. **§0 摘要**：版本/范围/计划状态/准出口径/结论/一句话理由。  
2. **§2 结果**：按意图或轨道列通过/失败/阻塞/待实现；数字与执行记录逐项对齐。  
3. **§2.3 覆盖**：P0/P1/P2 覆盖、原文对账、四轨记录、细节维；缺项写 GAP+影响。  
4. **§3 缺陷**：失败/阻塞逐条给单号或拟提交处置；不得只写“已知问题”。  
5. **§4 缺口与条件**：缺口、接受人、复审点、遗留风险；CONDITIONAL 必填。  
6. **§5 结论**：唯一 verdict + 依据 + 后续动作。

- 数字只从本轮日志/记录取；不凭记忆、不引用旧报告。  
- 失败场景写“现象+期望+实际+证据”，不写“疑似/可能”。  
- 长表可进附录；主报告先给结论与阻断项。

## 4. 反模式（出现即停）

- 用“大部分通过/基本可用”替代唯一结论。  
- 把 P0 失败写成 CONDITIONAL，靠接受人换通过。  
- 计划写了 10 个意图，报告只写 8 个，差额不解释。  
- 用旧轮次证据/截图充当本轮证据。  
- 把“未执行”写成“不适用”，或把阻塞写成失败/通过。  
- 报告数字与执行记录不一致，靠改报告凑一致。  
- 没有复审点的 CONDITIONAL，或接受人只写“产品”。

## 5. 红旗

- 报告 §2 计数与执行记录行数不一致。  
- P0 有失败但结论仍 PASS。  
- 证据路径打不开、时间早于本轮、哈希重复。  
- 四轨中有一轨只有目录/空文件。  
- 缺口表为空但存在 `未执行` 或未关原文对账。  
- 结论与 `-Claim -Mode report` 输出矛盾。

## 6. DoD

- [ ] 唯一结论，且与机检/证据一致。  
- [ ] P0 全过且有证伪；全部处置=测意图终态。  
- [ ] 计数与执行记录逐项对齐；差异有 GAP。  
- [ ] 失败/阻塞有归属；证据可打开且为本轮。  
- [ ] CONDITIONAL 有接受人/范围/复审点。  
- [ ] 报告结构齐 §0～§5；结论可复核。  
- [ ] `-Mode report` 通过，`-Claim -Mode report` 为 `CLAIM: ALLOWED`。
