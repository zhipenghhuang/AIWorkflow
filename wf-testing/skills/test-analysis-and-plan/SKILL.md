# 测试计划（技能 · 随包生效）

> 用于：`testing.plan`。**分析必做，计划是总排**；分析未确认不写计划，计划未确认不执行。
> 分析真源：`{workroot}/{ver}/test-analysis.md`（来源/AC 设计点/意图/风险/覆盖）。本技能只把已确认分析转成执行安排。

## 0. 必做

1. **读分析**：来源盘点、章节回执、依据覆盖、AC/设计点账本、意图 P0/P1/P2、覆盖矩阵、方法矩阵、D01–D13 + S6/S7/S11、风险、影响面、核心链路；任一矩阵有空格/缺口 → 停，先补分析。
1.1 **读基线**：`env-baseline.md` 项目身份/§1 登录/§4 账号/§8 浏览器/§13 平台/§16 脚本命中节；计划 §2.2 写命中节/差异/核验，不能只写待确认。
1.2 **双读**：分析是原文索引，不是替代；后续执行须逐场景打开原文对应段 + ≥1 互补源，禁只读分析；计划只引用分析结论。
2. **范围**：范围内/明确排除/假设/约束；排除有接受人；引用分析路径；范围必须含直接+邻接+上游+下游+共享数据+回归。
3. **策略**：功能/接口/回归/探索/发布前/UAT 逐项选；不适用写理由；声明 suite/depth/发布前风险级；T1+ 必须纳入探索或 N/A+依据+接受人。
4. **轮次/批次**：R0 冒烟 → R1 功能/接口 → 探索/发布前 → R2 回归；写批次/并行/隔离/合并点；同一意图禁并行。
5. **准入准出**：意图终态 100%；P0/P1/P2 全部终态；S6/S7/S11 有落点；覆盖矩阵/影响面/核心链路无缺口；有条件通过规则明确。
6. **缺陷/变更**：提交策略、修复回归、CR 分级。
7. **自主边界**：可调整场景/工具/顺序；范围/准出变化必须停；决策/偏差记计划 §6。

## 1. 计划结构（对应模板）

- §0 一页状态：版本/构建/环境/轮次/风险档/分析计数/意图终态/下一动作/阻塞/准出预判。
- §1 范围与依据：分析路径、范围内/排除、假设/决策、CR、**影响面/核心链路摘要**。
- §2 策略与轨道：功能/接口/回归/探索/发布前/UAT；suite/depth；自动化/环境/数据；AI 自主边界。
- §3 轮次与顺序：R0/R1/R2；**批次/并行/隔离/合并点**；**探索章程或 N/A**。
- §4 准入/准出/发布门槛：P0/P1/P2 全终态、S6/S7/S11、覆盖矩阵/影响面/核心链路、有条件通过。
- §5 缺陷/回归/变更。
- §6 执行日志/决策。
- §7 附件。

> 计划**不重复**分析中的意图表/风险表/覆盖矩阵/方法矩阵/AC 账本；只引用路径与计数。

## 2. 测试类型选择（按风险，不堆类型）

| 变更特征 | 必选/建议 |
| --- | --- |
| 主链路、验收、资金/权限/数据 | 功能 + 回归 + 安全冒烟 |
| 新增/变更接口、跨系统契约 | 接口/契约 + 功能联动 |
| 复杂状态、组合配置、时序并发 | 功能 + P0 深度 + 探索 |
| 性能敏感、大数据量、长稳 | 发布前性能/容量 |
| 权限/敏感数据/上传/注入 | 安全负向 + 越权 |
| AI/LLM/RAG/Agent | AI 评测（Oracle/rubric/重复阈值）+ 注入/越权 |
| 浏览器/设备/OS/辅助功能 | 兼容/可访问性 |
| 存量数据、升级、回退 | 迁移/回滚演练 |
| 业务验收/客户签字 | UAT |
| 上线风险/监控/回滚 | 灰度/生产验证 |

选「否」必须写理由；文档未声明 ≠ 免测。

## 3. 轨道编排

- **功能**：按分析命中意图 + 邻接影响面排 R1；P0 冒烟进 R0。
- **接口**：契约清单 → 适用维 → 脚本；迭代 depth=standard、发版 full、补丁 core。
- **探索**：未知/复杂体验/历史缺陷簇才纳入；一场一句章程；不替代功能/接口。
- **发布前**：性能/安全/兼容/迁移按风险级选最小集；指标/门槛/证据进 §4；缺口书面接受。
- **回归**：R2 = 原单 + 冒烟子集 + 影响面 + 锚点；修复后立即回归。
- **UAT/灰度**：登记责任人/证据，不冒充已测。

## 4. 准出设计

- **意图级**：范围内意图全终态；P0/负向/计算类结论 100%；一个意图一个结论。
- **P0**：全过；未过不得整体通过。
- **证据**：失败/阻塞/待实现有证据或明确原因；P0 通过有可打开证据。
- **缺口**：未覆盖/N/A/阻塞/待实现/发布前缺口显式列接受人/复审点。
- **组合**：迭代 ≥module + 接口 ≥standard；发版 full + 接口 full + 发布前硬映射；补丁标“补丁口径”。
- **有条件通过**：仅 P0 全过 + 非 P0 缺口 + 用户书面接受 + 报告列遗留。

## 5. 自主分析与择优

- **可自主**：场景顺序/工具/数据构造、低风险场景合并、发现更优验证方式。
- **必须记录**：计划 §6 写决策/偏差（为什么改、影响哪些意图、是否需人确认）。
- **必须停**：范围/准出/缺陷策略实质变化；关键 Oracle 无来源；P0 未覆盖；不可逆/合规/资金/权限。
- **禁止**：静默降范围/改预期/把失败写成通过；用“方案未写死”跳过行为验证。

## 6. 计划门自检

- 分析：来源盘点/章节回执/依据覆盖/AC 设计点账本无缺口；意图都有处置与接受人；覆盖矩阵/方法矩阵/细节维/风险/影响面/核心链路无未接受缺口。
- 计划：范围/轨道/轮次/批次/准入准出/缺陷策略可执行；引用分析路径；suite/depth 已声明；T1+ 探索章程或 N/A 有接受人；S6/S7/S11 有落点。
- 不要求全量用例；不要求固定分卷；不要求逐用例多轮评审。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “先写计划，分析以后补” | 分析未确认不得写计划。 |
| “计划里塞全部细节更完整” | 分析是细节真源；计划只做总排。 |
| “按计划只跑当前模块” | 计划范围内的全部意图与轨道都要到终态。 |
| “主路径绿=迭代完整” | P0 深度/负向/状态/权限/幂等未覆盖=缺口。 |
| “方案没写就不用测” | 未写≠免测；标 GAP/问，行为仍要验证。 |
