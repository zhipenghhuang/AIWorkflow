# 测试计划（技能 · 随包生效）

> 用于：`testing.plan`。**分析必做，计划是总排**；分析未确认不写计划；**覆盖闸未 PASS 不得称可执行**；计划未确认不执行。  
> **先后（硬）**：先完整覆盖方案每一个应测细节入分析账，再写计划；执行期自主（造数/择优/加场景）不替代本步入账，也不回补空账。  
> 分析真源：`{workroot}/{ver}/test-analysis.md`（**§2.1 意图台账为链接 SSOT**）。准出/轨道真源：`rules/special/multi-track-quality.md` **§0** + 文首 + §3。  
> 模板：`test-analysis-template.md` + `test-plan-template.md` 两份都填。

## 0. 必做

1. **读分析**：§2.1 意图台账（具体 INT+**字段级** Oracle+处置；主题句 Oracle 先退回分析）→ 来源盘点/章节回执/依据覆盖 → §2.1.1 设计点（只映射台账 ID）→ 覆盖矩阵/方法矩阵/D01–D13+S6/S7/S11/风险/影响面/核心链路；任一空格/缺口或缺台账 → 停，先补分析。
1.1 **覆盖闸**：本轮新建/更新分析或计划后跑 `-Mode coverage`；未 PASS 不得写「计划可执行/开跑」。
1.2 **读基线**：`env-baseline.md` 命中节；计划 §2.2 写命中节/差异/核验。
1.3 **执行预告**：后续执行须方案原文 → 结合本分析理解 → 现场择优；禁只读分析、禁先看分析再找原文。
2. **范围**：范围内/明确排除/假设/约束；排除有接受人；含直接+邻接+上游+下游+共享数据+回归。
3. **策略**：功能/接口/回归/探索/发布前/UAT 按 `multi-track-quality` **§0** 裁定（默认硬纳入；整轨否仅白名单+接受人）；声明 suite/depth/发布前风险级（分级见 `tracks/pre-release`）。
4. **轮次/批次**：R0 冒烟 → R1 功能/接口 → 探索/发布前 → R2 回归；§3.1 按计划模板该节填表。
5. **准入准出**：见 `multi-track-quality` §3；有条件通过规则明确。
6. **缺陷/变更**：提交策略、修复回归、CR 分级。
7. **自主边界**：可调场景/工具/顺序；范围/准出变化必须停；偏差记计划 §6。

## 1. 计划结构（对应模板）

- §0 一页状态 · §1 范围与依据 · §2 策略与轨道 · §3 轮次/批次/探索 · §4 准入准出 · §5 缺陷/变更 · §6 日志 · §7 附件。
- 计划不重复分析大表；只引用路径与计数。

## 2. 轨道裁定（摘要 · 真源 `multi-track-quality` §0）

| 轨道 | 迭代默认 | 整轨否 | 弹性 |
| --- | --- | --- | --- |
| 功能 | **必须** | 无 | suite≥`module` |
| 接口 | **必须** | 仅无服务端/HTTP/RPC/WS/契约面 + **用户确认** | depth≥`standard` |
| 回归 | **必须** | 仅零变更+零邻接 + **用户确认** | R2 范围 |
| 探索 | **T1+ 必须** | 仅 T0/补丁或无运行时交付 + **用户确认** | 章程数；有面对须章程（Q19） |
| 发布前 | **必须** | 仅永不部署且无运行时面 + **用户确认** | 须建方案+硬映射；表内未跑仅 Q19③ |
| 迁移 | 有升级/存量 | 无则 N/A+依据 | 可并入发布前 |
| UAT/灰度 | 有上线签字则登记 | 无流程则登记不适用 | 本包不冒充已测 |

**禁软否**：「无接口文档 / UI 已测 / 小改 / 无 NFR / 功能测完 / 无可探索面」。文档未写 NFR ≠ 免测。UI 内嵌 API ≠ 接口轨。

## 3. 轨道编排

- **功能**：命中意图 + 邻接影响面排 R1；P0 冒烟进 R0；矩阵空格先补再排期。
- **接口**：必须纳入（整轨否仅 §0 白名单+用户确认）→ 契约清单 → 适用维 → 脚本；迭代 standard、发版 full、补丁 core。
- **探索**：T1+ 强制纳入；一场一句章程；不替代也不被功能替代。
- **发布前**：强制纳入；小改用基础级；硬映射；指标/门槛进 §4。
- **回归**：R2 = 原单 + 冒烟子集 + 影响面 + 锚点。
- **UAT/灰度**：登记责任人/证据。

## 4. 准出设计

见 `multi-track-quality` §3 / §4。有条件通过：仅 P0 全过 + 非 P0 缺口 + 用户书面接受 + 报告列遗留。

## 5. 计划编排自主（非覆盖豁免）

- **可自主**：轮次内场景顺序建议、工具/数据策略、低风险合并批次、更优验证方式写入计划。
- **不可自主**：跳过应测细节入账、空着覆盖/方法矩阵写计划、用「执行时再分析」代替本步完整分析；**不可自填接受人跳轨/降档**（Q19）。
- **必须记录**：计划 §6 决策/偏差。
- **必须停**：范围/准出/缺陷策略实质变化；关键 Oracle 无来源；P0 未覆盖；不可逆/合规/资金/权限；拟写 N/A/整轨否/不测 → **先问用户**。
- **禁止**：静默降范围/改预期/把失败写成通过；用“方案未写死”跳过行为验证；用接受人顶替建方案/章程/记录。

## 6. 计划门自检

- 分析：台账/来源/设计点/矩阵/细节维/风险/影响面/核心链路无未接受缺口；`-Mode coverage` PASS。
- 计划：可执行；suite/depth/发布前风险级已声明；迭代正式轨按 §0 纳入或白名单否+接受人；T1+ 探索章程闭环；S6/S7/S11 有落点；§3.1 形态合规。
- 不要求全量用例预写；要求方案可验收单元与方法技法在台账/矩阵有落点。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “先写计划，分析以后补” | 分析未确认不得写计划；覆盖闸未过不得开跑。 |
| “计划里塞全部细节更完整” | 分析是细节真源；计划只做总排。 |
| “按计划只跑当前模块” | 计划范围内全部意图与轨道都要到终态。 |
| “主路径绿=迭代完整” | 细节/方法矩阵/发布前未闭环=缺口。 |
| “台账有意图就算可执行” | P0 Oracle 须字段可复核；专用负向与造数配方要进计划/造数批，否则执行必浅。 |
| “没有接口文档=无接口轨” | 必须纳入；否仅 §0 白名单（无服务端/HTTP 等）；UI 探针≠接口轨。 |
| “小改不做发布前” | 仍纳入；风险级用基础级；整轨否仅永不部署/无运行时面。 |
| “功能测完就不用探索” | T1+ 强制探索；功能不替代探索。 |
| “未纳入发布前仍可准出” | 迭代须发布前纳入或 §0 白名单+**用户确认**。 |
| “计划里写接受人=QA 就能裁轨/裁项” | 否；接受人须用户当轮确认，且不能顶替必建产物（Q19）。 |
| “必选轴写不测省事” | 有对应面必须章程；无面对才 N/A+事实句+用户确认。 |
| “少写负向通过率好看” | 发现问题优先；砍负向=禁止。 |
| “方案没写就不用测” | 未写≠免测；标 GAP/问，行为仍要验证。 |
| “多模块也写直跑/空 PG 更快” | 同并行组≥2 模块默认模块子代理；无隔离禁 PG。 |
| “写了 PG 就是并行能力” | PG 必须带互斥隔离指针；否则改串行。 |
| “设计点齐了就能开跑” | 须 §2.1 台账 + coverage PASS。 |
