# 性能 / 安全 / 兼容（技能 · 随包生效）

> 边界/字段/阻断项以 `rules/tracks/pre-release.md` 为准；工具选装见 `capabilities/00-contract.md`。  
> 原则：**工具测量，AI 解读**；不把 AI 当压测器/扫描器，不拿测试机结论冒充生产。

## 1. 风险分级（先定最小集）

> 级别定义与最小集以 `tracks/pre-release.md` 为准；本节只钉执行要点。

- **基础级**：小改/低风险 → 依赖与密钥扫描 + 关键接口 smoke + 1 条核心性能基线 + 1 个代表浏览器/分辨率。
- **标准级**：版本级/多模块 → 基础级 + **短时并发性能**（≥2 VU 阶梯；禁空闲串行×3 关账）+ SAST/SCA（缺工具→降级+关账确认）+ 纵/横越权 + DAST/对外负向 + 兼容代表矩阵（有面对才扩维）+ 迁移回滚短演练。
- **高风险级 / P0级**：资金/权限/数据/公共 API/大促 → 标准级 + 全链路压测/长稳（短代须用户确认）+ 全量安全 + 兼容矩阵 + 混沌/故障注入 + 回滚实战。
- 裁剪必须写入报告缺口，禁静默不做。

## 2. 性能

- **目标先定**：RT/吞吐/错误率/资源 + 达标线 + 来源（SLA/历史基线）——一句话可判定。
- **场景建模**：读/写/混合、峰值/均值、数据量级与分布（冷热）；关键交易优先。
- **测量纪律**：预热后计；标准级按轨契约跑并发阶梯并留 VU/时长/p95/错误率摘要；记录资源指标（可得则记）；环境不可比须标限制。
- **基线/容量**：对照上版本/生产/目标值；容量拐点/水位；长稳按风险级；空闲基线与并发结论分列。
- **报告**：目标 vs 实测 vs 结论逐行；瓶颈线索必留。
- **前端性能**：Core Web Vitals（LCP/INP/CLS）+ 资源体积/请求数/缓存；用 Lighthouse/真实用户指标，不只看实验室分数；移动网络/低端设备单列。
- 工具：`perf-test`（k6/JMeter/Locust）或项目自备并发工具；AI 只解读数据/给瓶颈假设。

## 3. 安全（最小负向集）

- **扫描**：SAST（代码）、SCA（依赖/许可证）、secrets（密钥）、DAST（对外运行面）；SBOM 产出并核对依赖处置（critical/high 修复或豁免+接受人）。缺 `sec-scan`：负向可跑，扫描映射行未跑+关账确认，禁写「已扫描」。
- **威胁建模**：关键资产/入口/信任边界/数据流；STRIDE 简表即可，不追求全套。
- **业务负向**：越权/IDOR（横向/纵向各至少落点）、注入、认证会话、敏感回显/导出、上传与路径、配置暴露。
- **隐私合规**：PII 采集/存储/导出/日志脱敏；个保法/GDPR 适用项写结论。
- **AI/LLM 安全**：直接/间接提示注入、越权检索、系统提示泄露、工具越权/过度代理、无限消耗、输出处理（XSS/命令/SQL）。
- **方法对齐**：OWASP WSTG（Web）、OWASP ASVS 5.0（验证项）、OWASP Top 10 for LLM 2025（AI）；按适用性裁剪并写版本。
- **阻断**：critical/high 未闭环不得判发布通过；工具产物须人工复核，禁直接当结论。
- 工具：`sec-scan`（semgrep/ZAP/Trivy/gitleaks 等）或项目安全团队；AI 只做负向设计与复核。

## 4. 兼容 / 可访问性

- **矩阵法**：浏览器/OS/设备/分辨率/网络/缩放各取代表值，不做全排列；重点端与退化端各 1；**弱网/断网/切换**、输入法/字体、低端设备性能单列。
- **a11y**：对外页面至少自动扫描一次（axe-core），关键流程键盘/焦点/对比度/语义/屏幕阅读器抽查；目标 WCAG 2.2 AA（适用时 EN 301 549）；覆盖缩放 200%、减少动态、错误提示可读。
- **i18n/本地化**：文案长度/换行、日期/时间/时区、金额/币种/小数、复数/性别、RTL（如适用）；不把中文硬编码进通用组件。
- **视觉**：`visual-reg` 截图比对关键页；动态内容遮罩，阈值按项目。
- 移动端点名时用 `mobile-automation`（注册表）。

## 5. 迁移 / 升级 / 回滚

- dry-run 先跑；核对行数/校验和/关键字段/状态；记录停机窗口/迁移耗时；回滚演练记录耗时与数据影响。
- 灰度分批时核对每批数据与开关状态；回滚触发条件写清（错误率/延迟/业务指标/数据异常）。
- 不可回滚或数据不可恢复 → 必须显式风险接受；否则不得发布。

### 5.1 韧性 / 混沌（高风险必做）

- 故障注入：依赖超时/错误、实例宕机、网络分区、磁盘/队列满、时钟漂移；按爆炸半径从小到大。
- 验证：降级/熔断/重试/限流是否按设计生效；错误是否可恢复；数据是否一致。
- 不在生产直接注入未批准的故障；先预发/演练环境，生产需审批与回滚预案。
- 记录：注入条件、观察指标、实际行为、恢复时间、defects/改进项。

### 5.2 发布后验证（最小闭环）

- 生产冒烟：发布后按 `smoke-checklist.md` P0 主链跑一遍；失败给回滚建议。
- 监控观察期：错误率/延迟/关键业务指标/告警；记录窗口与阈值。
- 灰度/开关：灰度比例、feature flag 默认值、回滚开关可验证。
- 回滚触发：条件与责任人写清；结论=通过/观察中/回滚建议。

## 6. 结论纪律

- 达标/通过 = 绑定可复核产物（报告/原始数据/日志）；未测面显式列缺口。
- 环境/数据不可比、工具不可用、样本不足 → 写限制/缺口，禁假称已测。

## 7. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “扫描没报就是安全” | 扫描覆盖有限；越权/业务逻辑/注入需人工负向设计。 |
| “压测机跑得动就行” | 环境/数据/流量模型不可比；结论要写限制。 |
| “串行打 3 次 / 空闲 RT 绿就算标准级性能” | 否；标准级须短时并发阶梯证据；空闲基线不能冒充容量通过。 |
| “sec-scan 没有，无 token 拒一下就算安全过” | 否；须纵/横越权等业务负向；扫描类未跑须关账确认，禁写已扫描。 |
| “兼容性测主流浏览器就够” | 按用户分布选代表端，退化端也要 1 个；写矩阵。 |
| “a11y 是前端的事” | 验收要覆盖键盘/对比度/语义；自动扫描只是一部分。 |
| “混沌测试太高级” | 高风险系统至少验证降级/超时/回滚，不一定要全套平台。 |
| “发布前过了就不用发布后验证” | 生产数据/流量/开关不同；至少生产冒烟 + 观察期 + 回滚触发。 |
| “扫描没报就不用威胁建模” | 扫描覆盖不到业务逻辑/越权链；威胁建模定攻击面后再测。 |
