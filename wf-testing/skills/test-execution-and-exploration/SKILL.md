# 执行与记录（技能 · 随包生效）

> 用于：`testing.execute`（功能/接口/探索/回归）。  
> **执行口径**：AI **逐场景对照原始方案/原型/接口/AC 原文 + 至少一个互补源**（原型/接口/代码/现网/历史缺陷）执行；分析只是索引，不替代多源对照；场景执行时生成，不依赖预写用例。  
> **记录口径**：边执行边写 `*-执行记录.md`：场景 + 原文/依据（多源）+ 3～7 步 + 数据 + Oracle + 结果 + 证据 + 缺陷；另写意图结论表，P0/P1/P2 全部终态。  
> **环境口径**：开跑前读 `env-baseline.md` 命中节（项目身份/§1 登录/§4 账号/§8 浏览器/§16 脚本）；环境/构建/账号/数据与计划 §2.2 一致；变更记入计划 §6 与执行记录。  
> **计划驱动**：计划 §3 轮次/§4 准出是编排真值；P0 优先；回归按 §5.2；S6/S7/S11 是功能收口必看探针。

## 0. 必做

1. **开跑声明**：轮次、范围（意图 ID/模块）、构建/环境、`exec_mode=`/`pg=`。先读计划 §3.1；缺行/冲突才打开 `rules/collaboration/subagents.md` **仅 §1**（档位/决策树摘要）补取档→回技能；有隔离才写 `pg=PG-*`，否则 `pg=na`。
2. **读来源 + 分析 + 基线（经济读，覆盖不降）**：开跑读计划 §0/§3/§4 + `env-baseline.md` 命中节；**每个场景**打开该意图的原文对应段 + ≥1 互补源 + 分析中该意图/风险/影响面命中行。禁止只看分析摘要或单一源；禁止为省事跳过原文。不预防性通读分析全文矩阵定义（定义已在计划门确认；空格/漏项发现时再回读并回写）。  
3. **逐点对照**：每个场景执行前重读原文对应段与互补源，执行记录 `原文/依据` 写多源；发现分析漏项/原文理解偏差/源间冲突 → 立即回写分析/计划或记 GAP/问，再继续。  
4. **生成当前场景**：按 `testcase-design` 由意图展开；P0 按深度；覆盖矩阵/方法矩阵/细节维的空格先补；不预生成全量。  
5. **执行**：脚本优先；同页簇/动作连做；失败现场留证；不把步骤当脚本机械点击；S6/S7/S11 在功能收口前逐项看。  
6. **边执行边记录**：每场景写执行记录行；失败/阻塞/待实现另起详情；写意图结论表；更新计划 §0/§6。  
7. **批末**：所有在范围意图终态；失败/阻塞证据可开；跑 `-Mode execute -Scope`；再进下一批/阶段。

## 1. 执行记录（唯一落档）

- 功能：`{workroot}/{ver}/functional/{NN}-{短名}-执行记录.md`
- 接口：`{workroot}/{ver}/api/{NN}-{短名}-执行记录.md`
- 探索：`{workroot}/{ver}/exploratory/{主题}-{戳}-探索记录.md`
- 发布前：`{workroot}/{ver}/pre-release/{专项}-test-report.md`
- 一行一场景；默认不写逐步表格；失败/P0/锚点才展开 3～7 步详情。
- 结果：未执行/通过/失败/阻塞/待实现/不适用/未本轮验证；一个意图按最差态合并。
- §3 意图结论表一行一个 INT，P0/P1/P2 都有终态；未测意图必须列接受人。

## 2. 现场处置

| 情况 | 自主做什么 | 禁止 |
| --- | --- | --- |
| 缺数据/样本 | 造数/换样再跑 | 直接 blocked |
| 被测入口已定位且 404/空壳 | 记 fail+证据；可绕过跑独立面 | 标 blocked；猜 API 冒充该条 pass |
| 无菜单无接口（范围内） | 待实现（实现缺陷）进缺陷 | 当 blocked/仅观察；API 旁路刷绿 |
| 前置/依赖/环境不可达（穷尽） | blocked+已试/恢复条件；盯办或挂上游 | 写成实现缺陷；空重试同手段 |
| 点名 UI 仅 API/E0 | 未走 E1 → 不得 pass；旁路另记 | E0 冒充 UI 终态 |
| 弱通过/空扫/假成功 | 按工作流 §3.0 定性 fail 或造数再判 | 观察后宣称达标；无样本标 pass |
| 同路径旁证问题 | 记 fail/额外发现+证据 | 静默忽略 |
| 脚本 fail | 有界复核 1 次：产品/脚本/环境分诊 | 脚本红直接交平台；反复深挖 |
| Flake | 同方案无效 2 次换手段；记频率 | 一次绿即稳；静默跳过 |

**落账前四问**：① 被测入口本轮已定位（菜单/Tab/路由/写口）？② 证据可开且钉断言点？③ 结果态按 `classification.md` §0.4（失败/阻塞/待实现不混标）？④ 写操作 Network 见 METHOD+path 且回查？四问未过不落账。

## 2.5 自主与不确定

- **可自主**：场景顺序、工具、数据构造、同页簇/动作连做、发现更优路径后新增场景；按实际风险调整，不机械照旧用例/旧边界。
- **必须回写**：新增意图/边界写分析 §2.1/§2.4 或执行记录；范围/准出/环境变化记计划 §6；不能只口头改。
- **原文冲突**：原文/AC/契约优先；现网差异记 fail/待确认，不按现网改预期；原文未写死才探查现网口径并记录。
- **多源冲突**：原文、原型、接口、代码/现网不一致时不要静默选一个；按优先级（用户裁决/AC/PRD/契约 > 设计/原型/接口 > 代码/现网事实）落结论，并记证据/GAP；原型与原文冲突通常按原文，必要时问。
- **项目实际择优**：按当前项目已有源、工具、风险选场景与深度；缺源不臆造，降级/补源/问，记录影响。
- **必须停/问**：影响 Oracle、范围、准出、不可逆/合规/资金/权限，一次一问；低风险可假设并记录，不逐细节问。
- **不得做**：删 P0/负向、私改断言凑通过、把旧通过当本轮、用 API 旁路冒充点名 UI。

## 3. 结果语义（不可让）

- 终态表 / 404 分界 / 有界打通：`rules/defects/classification.md` §0.4；四问：`multi-agent-output.md`。
- **判定对账（落通过/失败前）**：打开该意图**原文对应段** + 分析 §2.1 该 INT 行（Oracle/不可接受失败）+ ≥1 互补源；结果只认可观测断言是否成立。分析是索引，禁只凭分析摘要或现网“看起来对”判通过；Oracle 须写可复核点（状态/字段/码/提示），禁填「通过/正常/无报错」。
- `不适用`：范围外/业务不适用 + 依据 + 接受人。
- 失败/阻塞/待实现必须有证据或原因；通过不得只凭“没报错”。
- 无有效样本不得报通过；期望拒绝却弱成功/授权未拦却先撞业务规则 = fail。
- 新 INT 先回写分析再记入执行记录；P0 通过须含证伪/负向场景（或 N/A+接受人）。

## 4. 接口执行

- 契约/请求要点/判定三要素/写后回查；仅 2xx 不算通过；假成功=失败。
- 无 token/越权用隔离上下文；写条写后回查；证据含请求摘要（无密钥）+ 响应码/业务码/关键字段。
- 确定性场景同轮脚本；回归优先脚本；失败有界复核后再定性。

## 5. 探索式（T1+ 纳入）

- T1+ / 版本级计划必须纳入 ≥3 条章程（T2/T3 ≥4，≤6）或 N/A+依据+接受人；T0/补丁可 N/A。必选轴 S6/S7/S11/状态误读至少各 1 条或书面不测。
- 一场一句章程 + 时间盒 + 3～6 风险点；覆盖/没碰到/发现/疑问/下一句；发现才写复现。
- Debrief：缺陷→缺陷+回归；缺口→补意图/锚点或下一场；收尾写「拟补锚点」；禁空泛“探索通过”；不替代功能/接口覆盖。

## 6. 随机业务流程（计划外）

- 仅独立口令；不进计划、不参与准出；现网口径；模仿真人办结主业务；不脚本化。
- 结论只落 `random-flows/`；缺陷类型=`随机`；收尾写分流与账本；不替代覆盖。

## 7. 回归与证据

- 修复即回归：原单 + 冒烟子集 + 影响面 3～8 条 + 相关锚点；P0升级。
- 结果就地覆盖执行记录；只留最新；旧轮归档。
- 失败截图钉断言点；同帧做视觉检查；不拿旧图/他人图充数；密钥/PII 不入证据。
- 报告数字与执行记录一致；未测/未本轮验证显式列。

## 8. 执行 DoD

- 意图范围清楚；场景有来源/Oracle；P0/P1/P2 全部有终态；P0 深度齐。
- 记录/证据/失败分类/重试有界；未测/阻塞显式；S6/S7/S11 有落点。
- P0 未过不整体通过；计划 §0/§6 已同步。
- 锚点通过或有缺口接受人。
- 经济回执：`exec_mode=`/`pg=`（或 `na`）；已脚本化走脚本；同页簇/造数按判断执行。

## 9. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “重跑一次过了就算过” | 非确定性/flake 看多次与分诊；一次通过可能是偶然。 |
| “失败不重要，先跳过” | 跳过要记录缺口/风险接受；不能静默。 |
| “截图差不多就行” | 证据要钉断言面与时间；旧图/糊图不算。 |
| “先交平台，后面补证据” | 弱证据/错题不交平台；回写要有回执。 |
| “已脚本化再 MCP 点一遍更放心” | 双耗；回归只跑脚本，失败才有界复核。 |
| “步骤就是脚本，照着点” | 步骤供复核；AI 执行对照来源/意图，不机械点。 |
| “多模块也直跑更快” | ≥2 装填模块默认模块子代理（可串行）；无 Task 再降级并记 `subagent=unavailable`。 |
| “写了 pg= 就算并行” | 无互斥隔离必须 `pg=na`；冲突串行并记 `plan_batch_conflict`。 |
| “计划没写批次就自己并行” | 未列批次默认串行；先补 §3.1 或记 `no_batch_plan`，禁静默并行。 |
| “看到 404 就标阻塞” | 先定位被测入口；入口自身 404/空壳→失败；仅前置/依赖不可达→阻塞（§0.4）。 |
| “缺数据直接 blocked” | 先造/换样；有界穷尽后才阻塞；禁空手段重试。 |
| “有阻塞就写准出 BLOCKED” | 失败/待实现与阻塞并存 → 准出优先 FAIL；仅前置阻塞主导才 BLOCKED。 |
| “分析写了就算对照过原文” | 分析是索引；落账前仍须打开原文对应段 + 互补源。 |
| “Oracle 写通过/正常” | 无效；须可观测断言，并能与分析 Oracle/原文对上。 |
