# 执行与记录（技能 · 随包生效）

> 用于：`testing.execute`（功能/接口/探索/回归）。  
> **执行口径（三步序硬）**：① **方案原文**按目录/可验收单元逐项对照 → ② **结合分析理解**（`test-analysis.md` 命中行作索引；非入口/非 Oracle/非互补源）→ ③ **现场执行择优**（有互补源则对照；按规则/技能高质量实施；实现≠方案走偏差择优）。禁先看分析再找原文；禁只读分析；场景执行时生成，不依赖预写用例。  
> **记录口径**：边执行边写 `*-执行记录.md`：场景 + 原文/依据（多源）+ 3～7 步 + 数据 + Oracle + 结果 + 证据 + 缺陷；另写意图结论表，P0/P1/P2 全部终态。  
> **环境口径**：开跑前读 `env-baseline.md` 命中节（登录/账号/浏览器 + 本批造数·样本·接口相关节）；环境/构建/账号/数据与计划 §2.2 一致；变更记计划 §6 与执行记录；新可复用路径同轮回写基线（见 `test-data-and-environment` / 基线同步节）。  
> **计划驱动**：计划 §3 轮次/§4 准出是编排真值；P0 优先；回归按 §5.2；S6/S7/S11 是功能收口必看探针。

## 0. 必做

1. **开跑声明**：轮次、范围（意图 ID/模块）、构建/环境、`exec_mode=`/`pg=`；**同轮对话亮出**（见 `global-rules` §8）。先读计划 §3.1；缺行/冲突才打开 `rules/collaboration/subagents.md` **仅 §1**（档位/决策树摘要）补取档→回技能；有隔离才写 `pg=PG-*`，否则 `pg=na`。开跑读计划 §0/§3/§4 + `env-baseline.md` 命中节。
2. **三步序（硬）**：① **方案原文**：直接打开原文，按目录/可验收单元逐项对照（不做清单代理）。② **结合分析理解**：读分析中该意图/风险/影响面/UI·文案命中行，弄清要测什么与 Oracle；漏来源/漏章/漏细节 → 先回写分析再继续；不预防性通读分析全文矩阵（空格/漏项发现时再回读并回写）。③ **现场执行择优**：有互补源再对照（原型/接口/代码/现网/历史缺陷；无则单源+理由+接受人）；按规则/技能高质量实施；实现≠方案按 §3 偏差择优下结论。
3. **逐点对照**：每个场景执行前重走三步序短径——重读原文对应段 → 结合分析该行理解 → 现场对照/实施/择优；`原文/依据` 写方案锚点（有互补源则写互补源；分析不作互补源）。发现分析漏项/原文理解偏差/源间冲突 → 立即回写分析/计划或记 GAP/问，再继续。  
4. **生成当前场景**：按 `testcase-design` 由意图展开；P0 按深度；覆盖矩阵/方法矩阵/细节维的空格先补；不预生成全量。  
5. **执行**：脚本优先；同页簇/动作连做；失败现场留证；不把步骤当脚本机械点击；S6/S7/S11 在功能收口前逐项看。  
5.1 **先打通再阻塞（硬）**：遇缺数据/样本不对/账号角色不对/入口一时找不到/临时权限不足 → **先查基线造数/样本节**，再自助造数/换样/建号/换角/赋权/换入口（有界 ≥2 互异手段）；未穷尽 **禁止** 落 `阻塞`、**禁止**据此问用户。仅前置外力穷尽后才可阻塞，摘要须卡点+已尝试+恢复条件（`classification.md` §0.4）；对人进度见 `global-rules` §8。  
5.2 **同域自洽探针（硬）**：结果页/写操作页落 `通过` 前，对**本屏已打开且与断言相关**的载体做最小互证（有则扫；无对应载体写 N/A，禁编造）：① 头/概览/汇总 ↔ 同页明细/邻区/来源；② UI 提交量·枚举 ↔ 同行需求量或列表/Network 已见合法值；③ 办结门禁——状态/工序已齐仍只能强制·绕过，或阻断文案不可定位到剩余规则 → `失败`；④ 列表·筛选标签·徽标·KPI ↔ 同对象详情/契约关键字段（有 ≥2 载体则对账，见 multi-track S11）；⑤ **生产↔消费**（适用时）——主数据/上游已启用关联对象存在时，本屏检查/展开/计数不得「通过且空读入」无定位。无明文方案句仍可写「无设计文档·现网依据」；分型真源 `classification.md` §0.5（同域矛盾禁选型）。  
6. **边执行边记录**：每场景写执行记录行；失败/阻塞/待实现另起详情；写意图结论表；更新计划 §0/§6。  
7. **批末关账**：① 本批意图终态齐；失败/阻塞证据可开；② INT 均在 §2.1 台账；本批触及的 §2.1.1 设计点已映射到这些 INT 的终态或 N/A+接受人；③ **基线回写自检**（新可复用 API/配方/样本/冲突已按同步节回写，或确认无新增）；④ 跑 `-Mode execute -Scope`：过程完整且仅产品红 → **CONDITIONAL** 可下批（缺陷须入库）；分析/计划/链接/证据任一不过 → **FAIL/BLOCKED**，先补齐再推进；⑤ 批末对人关账按 `global-rules` §8。

## 1. 执行记录（唯一落档）

- 功能：`{workroot}/{ver}/functional/{NN}-{短名}-执行记录.md`
- 接口：`{workroot}/{ver}/api/{NN}-{短名}-执行记录.md`
- 探索：`{workroot}/{ver}/exploratory/{主题}-{戳}-探索记录.md`
- 发布前：`{workroot}/{ver}/pre-release/{专项}-test-report.md`
- 一行一场景；§1 的 `步骤` 列始终写 3～7 个短动作（带核对点）；失败/P0/锚点才在 §2 另展开 3～7 步详情。
- §0 写「原文/对照」+ 原文对账计数；§1.1 正向/负向/状态/权限/幂等/UI 六类各有 SC 或 N/A+依据。
- 结果：未执行/通过/失败/阻塞/待实现/不适用/未本轮验证；一个意图按最差态合并。
- §3 意图结论表一行一个 INT，P0/P1/P2 都有终态；未测意图必须列接受人。

## 2. 现场处置

| 情况 | 自主做什么 | 禁止 |
| --- | --- | --- |
| 缺数据/样本/账号/角色 | **先**造数/换样/建号/换角再跑；写已尝试 | 一遇缺数就 blocked；等别人造数 |
| 被测入口已定位且 404/空壳 | 记 fail+证据；可绕过跑独立面 | 标 blocked 推责；猜 API 冒充该条 pass |
| 无菜单无接口（范围内） | 待实现（实现缺陷）进缺陷 | 当 blocked/仅观察逃避缺陷；API 旁路刷绿 |
| 前置/依赖/环境不可达（**自助穷尽后**） | blocked+卡点/已试手段/恢复条件；盯办或挂上游 | 未穷尽就 blocked；写成实现缺陷；同手段空重试 |
| 点名 UI 仅 API/E0 | 未走 E1 → 不得 pass；旁路另记 | E0 冒充 UI 终态 |
| 弱通过/空扫/假成功 | 按工作流 §3.0 定性 fail 或造数再判 | 观察后宣称达标；无样本标 pass |
| 同域自洽矛盾（同屏冲突/读写分裂/旁路假可过） | `失败`+现网依据+证据；按 `classification.md` §0.5 禁选型 | 标选型/优化通过；「有强制开关」当过；静默 |
| 同路径旁证问题 | 记 fail/额外发现+证据 | 静默忽略 |
| 脚本 fail | 有界复核 1 次：产品/脚本/环境分诊 | 脚本红直接交平台；反复深挖 |
| Flake | 同方案无效 2 次换手段；记频率 | 一次绿即稳；静默跳过 |

**落账前四问**：① 被测入口本轮已定位（`入口指纹`：ui/network/contract 三选一有证，见 `classification.md` §0.4）？② 证据可开且钉断言点（失败含页面→截图；接口可另附终态 json，**不**用 json 顶替 UI 断言面）？失败块含 `surface=ui|api|ui+api`；有 UI 面须 UI 路径+截图，纯 API 才可请求链？③ 结果态按 §0.4（失败/阻塞/待实现不混标；未定位禁写「入口不存在」）？④ 写操作 Network 见 METHOD+path 且**回查字段=值**（禁只认 200）？四问未过不落账。

## 2.5 自主与不确定

- **覆盖底线（硬）**：分析阶段已入账的细节/矩阵/意图不得因「现场自主」删减或顺延无接受人；自主只加场景、换手段、造数打通、偏差择优，**不降覆盖**。分析空账不得靠执行口头补。
- **可自主（执行现场）**：场景顺序、工具、数据构造、同页簇/动作连做、发现更优路径后新增场景；按实际风险调整，不机械照旧用例/旧边界。
- **必须回写**：新增意图/边界写分析 §2.1/§2.4 或执行记录；范围/准出/环境变化记计划 §6；不能只口头改。
- **原文冲突**：原文/AC/契约优先作对照基准；**不按现网改写预期**；出现差异走下方「方案偏差择优」，禁止静默当通过，也禁止凡差必开缺陷。
- **多源冲突**：原文、原型、接口、代码/现网不一致时不要静默选一个；按优先级（用户裁决/AC/PRD/契约 > 设计/原型/接口 > 代码/现网事实）落结论，并记证据/GAP；原型与原文冲突通常按原文，必要时问。
- **项目实际择优**：按当前项目已有源、工具、风险选场景与深度；缺源不臆造，降级/补源/问，记录影响。
- **必须停/问**：影响 Oracle、范围、准出、不可逆/合规/资金/权限，或偏差分型说不清，一次一问；低风险可假设并记录，不逐细节问。
- **不得做**：删 P0/负向、私改断言凑通过、把旧通过当本轮、用 API 旁路冒充点名 UI、用「优化」掩盖阻断级偏差。

## 3. 结果语义（不可让）

- 终态表 / 404 分界 / 有界打通 / 偏差分型：`rules/defects/classification.md` §0.4/§0.5；四问：`multi-agent-output.md`。
- **判定对账（落通过/失败前）**：重走三步序——原文对应段 → 分析 §2.1 该 INT 行（仅理解索引）→ 现场（有互补源则对照）；结果只认可观测断言是否成立。禁只凭分析摘要或现网“看起来对”判通过；Oracle 须写可复核点（状态/字段/码/提示/文案/布局），禁填「通过/正常/无报错」。
- **Oracle 精度（落通过前）**：按 `testcase-design` §3.1——主题句（「有原因/已联动/状态对」）不得单独支撑 P0 通过；同义多字段/多载体须对账；方案要求的追溯字段在命中路径上非空（或条件 N/A）；失败原因用户可读，SQL/堆栈/驱动原文作「已有原因」=失败。§3 命中的专用负向未跑且无 N/A+依据 → 该意图不得标通过。命中「关联/绑定」时：配置面 SC 与门禁/读入 SC 都要跑；**生产者已有生效数据而消费端成功且计数=0、问题=0** → 失败（假绿），禁只测检查 API 收工。
- **方案偏差择优（实现 ≠ 方案时，必做 · 属三步序第③步）**：先对照原文，再分型写入「实际/差异」——
  1. **缺陷**：明确要求未达成，或挡正常功能/主路径，或安全/合规/资金/数据错，或假成功/空壳/未交付，或 **同域自洽矛盾**（§0.5 三类）→ `失败`/`待实现` + 缺陷。
  2. **选型/优化实施**：方案意图已达成；实现路径或交互/文案/布局不同但等价可用；**不挡正常功能**；无合规/资金/安全风险；**且无同域自洽矛盾** → 可 `通过`；写 `偏差=选型|优化` + 依据；可记 §4 建议，**不建缺陷**。
  3. **待确认**：影响说不清或方案含糊 → 一次一问或 GAP；未确认禁硬通过、也禁硬凑缺陷。
- `不适用`：范围外/业务不适用 + 依据 + 接受人。
- 失败/阻塞/待实现必须有证据或原因；通过不得只凭“没报错”。拟交平台的失败/待实现：须打通重跑后仍成立，通道按 `classification.md` §0（交前复判 `collaboration.md` §5.1 Q15）；真偏差该交、外力盯办、测侧可通不开单。
- 无有效样本不得报通过；期望拒绝却弱成功/授权未拦却先撞业务规则 = fail。
- 新 INT 先回写 §2.1（具体 ID + Oracle + 优先级）再记入执行记录；禁簇名；禁只写设计点不建台账。**优先级取分析 §2.1，不在记录里改判**；§3 意图结论必须指向实际场景。
- P0 通过须含证伪/负向场景（或 N/A+接受人）；闸认「阻断/门禁/冲突/假通过」等为证伪信号，禁空刷词。
- 批末 CONDITIONAL ≠ 准出通过：仅表示过程完整、可继续测其他批找缺陷；整体准出仍看 report 闸。

## 4. 接口执行

- 契约/请求要点/判定三要素/写后回查；仅 2xx 不算通过；假成功=失败。
- 无 token/越权用隔离上下文；写条写后回查；证据含请求摘要（无密钥）+ 响应码/业务码/关键字段。
- 确定性场景同轮脚本；回归优先脚本；失败有界复核后再定性。

## 5. 探索式（T1+ 纳入）

- T1+ / 版本级计划必须纳入 ≥3 条章程（T2/T3 ≥4，≤6）并闭环；整轨 N/A 仅 §0 + **用户确认**。必选轴有对应面须各 ≥1 章程（无面对才 N/A+事实句，Q19）。
- 一场一句章程 + 时间盒 + 3～6 风险点（收尾逐点结论）+ 会话四记；发现才写复现；**非空记录落盘后才可写计划已跑**（Q18）。
- 未关高簇未盖住 → **优先 ≤6 加场**；无法加场须用户确认（Q19）；禁只填四轴标签。
- Debrief：缺陷→缺陷+回归；缺口→补意图/锚点或下一场；收尾写「拟补锚点」；禁空泛“探索通过”；不替代也不被功能/接口替代。

## 6. 随机业务流程（计划外）

- 仅独立口令；不进计划、不参与准出；现网口径；模仿真人办结主业务；不脚本化。
- 结论只落 `random-flows/`；缺陷类型=`随机`；收尾写分流与账本；不替代覆盖。

## 7. 回归与证据

- 修复即回归：原单 + 冒烟子集 + 影响面 3～8 条 + 相关锚点；P0升级。
- 结果就地覆盖执行记录；只留最新；旧轮归档。
- 失败截图钉断言点；同帧做视觉检查；不拿旧图/他人图充数；密钥/PII 不入证据。
- 报告数字与执行记录一致；未测/未本轮验证显式列。

## 8. 执行 DoD

- 意图范围清楚；场景有来源/Oracle；P0/P1/P2 全部有终态；P0 深度齐（`testcase-design` §3；禁浅打勾）。
- 本批触及的设计点/适用维已落场景；不适用须事实句（无该维）；顺延无**用户确认**=缺口（Q19）。
- 计划含接口轨：`api/` **非空**记录+契约清单+场景表+depth；脚本不顶替；点名域必须有记录（Q18/Q19）。
- 发布前已纳入：须先落专项方案+硬映射再跑；未跑只写在**已建映射行**且用户当轮确认；**禁**接受顶替建方案/开批；禁空壳关账（Q18/Q19）。
- 记录/证据/失败分类/重试有界；未测/阻塞显式；S6/S7/S11 有落点；结果/写操作页同域探针已做或无对应载体 N/A。
- P0 未过不整体通过；计划 §0/§6 已同步；状态/总览须分轨报进度（功能/接口/探索/发布前），禁只报功能条数。
- 锚点须通过；暂缓仅用户确认并记复审点（Q19）。
- 经济回执：`exec_mode=`/`pg=`（或 `na`）；已脚本化走脚本；同页簇/造数按判断执行。

## 9. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “重跑一次过了就算过” | 非确定性/flake 看多次与分诊；一次通过可能是偶然。 |
| “失败不重要，先跳过” | 禁。`处置=测` 必须终态；接受人不能顶替（Q19）。 |
| “截图差不多就行” | 证据要钉断言面与时间；旧图/糊图不算。 |
| “先交平台，后面补证据” | 弱证据/错题不交平台；回写要有回执。 |
| “已脚本化再 MCP 点一遍更放心” | 双耗；回归只跑脚本，失败才有界复核。 |
