# 场景设计（技能 · 随包生效）

> 用于：`testing.execute`。  
> **执行口径**：与执行技能同三步序——方案原文 → 结合分析理解 → 现场执行择优；场景是执行时生成的验证方式。  
> **步骤口径**：执行记录保留 3～7 步紧凑步骤，供第二人复核；步骤服务于可读性，不要求逐步截图或逐步 DOM 定位。
> 字段/结构以 `rules/templates/20-test-cases/test-case-template.md`（功能）与 `api-test-case-template.md`（接口）为准。

## 1. 从意图到场景

- 一个意图至少一个场景；P0意图必须有能**证伪**它的场景，不是只走主路径。
- 场景写：谁/什么条件 → 做什么 → 期望什么可观察结果；不要写“验证功能正常”。
- **Oracle 须可复核到字段/码/文案**（见 §3.1）；「状态正确/有原因/已联动」等主题句不算 P0 可判 Oracle。
- **配置面与门禁面**：台账已拆的「关联/绑定」与「缺失阻断」须**各有 SC**（可同批）；禁只跑检查/计算 API 顶替配置入口断言。
- 一个场景可覆盖多个意图，但每个意图分别记结论；一个意图只出一个结论（最差态合并）。
- 先找失败面，再补成功面：失败/拒绝/边界/状态/权限/幂等/恢复往往比主路径更能发现问题；**主路径通过不得顶替专用负向**（§3 命中行）。

## 1.1 自主判断与边界

- **三步序**：方案原文逐项 → 结合分析理解 → 现场执行择优；场景覆盖功能与 UI/文案等已分析细节；不按现网改写预期。
- **多源对照**：场景回指原文对应段；现场步有互补源则对照（原型/接口/代码/现网/历史缺陷），无则单源+理由+接受人；不能只看分析；分析不作互补源。
- **源冲突**：原文/AC/契约 > 设计/原型/接口 > 代码/现网事实；冲突不静默选一个。
- **方案偏差择优**：属现场步；实现≠方案时按执行技能分型——缺陷 / 选型或优化实施 / 待确认；禁凡差必开缺陷，也禁用「优化」掩盖阻断。
- **边界重新推导**：边界值、状态组合、路径、UI/文案核对按本轮原文 + 数据 + 构建重新算；旧用例/旧边界只是线索，不机械复跑。
- **可以新增**：执行中发现更优验证、未覆盖边界、异常路径、方案漏盘细节，可加场景并回写分析；不删 P0/负向、不静默降范围。
- **回写**：新增意图/边界写分析 §2.1/§2.4 或执行记录；偏差记计划 §6。
- **不确定**：影响 Oracle/范围/准出/不可逆/合规/偏差分型 → 一次一问；低风险可假设并记录，不逐细节问。

## 2. 技法（方法矩阵已列须有落点；禁止全排列堆砌）

- **等价类**：有效/无效各取代表；同类代表不重复。
- **边界值**：`min-1/min/min+1/典型/max-1/max/max+1`；数字、长度、时间、分页、金额。
- **判定表**：多条件互斥时列规则；同结果列可合并。
- **状态迁移**：状态×事件矩阵；每个非法跃迁至少一条负向。
- **场景法**：入口→动作→观测点；主路径 + 分支变体。
- **组合/配对**：多参数用 pairwise，不做全排列。
- **算例法**：统计/评分/占量/能力指数：公式、输入、精度、最小分母集、期望值；分母 0/缺维单列。
- **错误推测**：按历史缺陷/谱系补（金额/时间/分页/空态/超长/导入导出/缓存/网络/权限/并发/迁移/UI）。

## 2.5 覆盖来源（不得绕过）

- 场景必须能回指分析 §2.1 意图和**原文对应段**（章/AC/原型/接口）；分析只是索引，执行前逐场景重读原文。
- 先扫覆盖矩阵空格：模块×面、方法×规则、D01–D13、S6/S7/S11；空格先补意图/场景或写 N/A+依据，不能只测主路径。
- 变更点按分析 §5.2 直接/邻接/上游/下游/共享数据/回归逐项落场景；无提测单也要自建影响面。
- 初版覆盖全部主链与上下游；迭代覆盖受影响主链 + 上下游回归，不能只测改动模块。
- **环境基线**：场景前置账号/数据/入口从 `env-baseline.md` 取；基线缺失先补，不猜 URL/账号/字段。

## 3. 深度档（不可让 · 完整≠条数 · 条数少≠可降档）

> 映射无空行只证明「点有人认领」，不证明深度够。P0/关键规则按命中特征行一次写够；缺口必须写「不适用+依据」。  
> **不预生成全量用例**只禁止空转刷用例库，**不豁免**本表深度；用户要全覆盖时按命中特征写够场景，禁止「一条主路径终态」收工。

| 命中特征 | 最低深度（P0/关键项） |
| --- | --- |
| P0 / 阻断主链 / 核心链路 | ≥1 主路径成功 + ≥1 关键失败/阻断（可同条可判定分支） |
| 有状态对象/流程 | 合法迁移抽样 + **≥1 非法跃迁**负向；多步向导失败/未进阶须可见原因 |
| 跨角色 / 租户 / 数据域 | ≥1 **负向拒绝**（明确失败语义，禁弱成功信封）+ 目标身份 ≥1 **正向可达**（禁高权代测） |
| 方案声明横切/口径类规则（幂等/并发/审计/附件/移交/权威复算/固定事实/跨口径对比） | 按声明抽样；同键异体拒、冲突不覆盖、不可比须明示、事实不可否定；多对象适用时载体 ≥2 或「不适用+依据」；**禁只断言汇总文案或原始 JSON 存在**；声明的版本/规则编码/来源对象等追溯字段须点名断言非空或明示 N/A |
| 同一业务量/状态出现在 ≥2 个 UI 载体 **或** ≥2 个字段/码表示同一事实 | ≥1 **交叉断言**（列表/详情/页脚/预览/接口字段：名称+数值+单位或状态文案**语义一致**）或「不适用+依据」；双字段同义并存且冲突=失败 |
| 受影响 UI 页 | 视觉基础：独立条 **或** 并入相邻预期；截图同帧检布局/遮挡/截断/空态/按钮态/文案 |
| 有成对日期/区间 | ≥1 倒置或交叉负向，或「不适用+依据」 |
| 有预检·确认表·预警确认与正式提交 | ≥1 **预检/确认↔提交一致**；≥1 负向：勾选/全选≠处理完成仍可提交 → 必须拦截或「不适用+依据」 |
| 有配置/样本/权限/时限前提（P0 或前提缺失会误判） | ≥1 条 **前提缺失断言**：不显示合格/不计分母/不催办/不自动放行；观测点=页面/状态/计数/通知 |
| 有关联/绑定/挂接配置（对象须指向版本/清单/结构/对方等） | ≥1 **配置面**：入口或 API 可建立/校验绑定键；≥1 **消费对账**：生产者侧已有生效数据时，消费端须读入计数>0 **或** BLOCKED+定位，**禁**成功/通过且计数=0、问题=0 |
| 有多状态轴/多单据关联 | ≥1 条 **交叉断言**：A 完成≠B 完成；发货≠到货；关闭≠验证；审核通过≠覆盖；同对象跨页状态用词冲突按「≥2 载体」行 |
| 写操作 | 失败/回查/清理；成功须交付方案要求的可观测结果；幂等落库/重放 |
| 有计算/统计/评分/占量/能力指数 | 公式/输入/精度/最小分母集/期望值；独立复算；页面取整不得单独判通过 |
| 有异步/回调/任务 | 触发→处理→终态；丢失/重复/延迟；任务入口/进度/失败可查 |
| 有权限/敏感数据/上传/注入面 | 越权/IDOR/危险文件/注入负向；证据脱敏 |
| 有覆盖型操作（改方案/记执行/保存/确认） | 入口命名与分区可区分；保存/确认不覆盖已确认方案；执行记录与方案变更分开；危险操作二次确认 |
| 同对象跨模块术语/编号/权限/路由 | 菜单、列表、详情、编号前缀、权限种子、路由可对应；未定义关系先确认，不把不同对象混成同一对象 |

| 有资产生命周期（资产/模板/数据集/指标/文档） | 未命名/TEST/重复/空壳/占位不得发布或启用；列表/详情有醒目待整改标识；治理清单/改名/归档/停投入口可达；发布/标准化后刷新状态正确；服务端治理态为准，客户端启发式只辅助 |
| 有计算/数据/对象证据/影响面 | 口径/来源/公式/版本/方法适用性可解释；对账对象/数据集/报表可追溯；固定映射未配置时明确阻断；汇总之外有对象级明细/证据/下钻；破坏性操作前有当前生效版本/引用/影响清单；认证撤销后有禁新引用/停投说明；历史/别名类型归一 |
| 有关联输入/候选表/复杂详情 | 空关系说明缺什么；候选表可搜索/筛选/分组；详情分区标题清晰；返回后筛选/滚动/上下文保留；历史补录类型齐全 |
| 有数值/单位/期限/时效 | 整数单位拒绝小数；小数位/截断/四舍五入符合规则；采样/抽检间隔不被静默截断；日期先后、原/当前期限、时效/账龄有边界与拒绝语义；前后端口径一致 |
| 有异步导出/超限/后台任务 | 后端契约与前端提示一致；超限转异步必须给任务入口；按钮 loading/禁用防连点；无入口不得提示“转异步” |
| 有数据链路/可观测性要求（适用时） | 幂等落库、窗口守恒、联动字段、点位级诊断、最新值来源/时间/质量、审计可检索、基线对象可查、`待实现` 交付后复测；失败/降级原因须**用户可读**（禁把 SQL/堆栈/驱动原文当合格 failReason） |
| 有历史/修订/确认留痕 | ≥1 条：**历史展示不被后续同对象操作改写**（或方案明示可改写+依据）；新旧修订可区分 |
| 有冲正/撤销/更正/回滚类写操作 | ≥1 条守恒负向：相关分项不为非法负值、残留分项清零或按方案归并；禁只断言「操作成功」 |
| 有测试/模拟数据与正式经营/生产统计隔离要求 | ≥1 条：正式统计窗/报表**不得**出现声明应排除的测试/无标识对象；禁只断言「对象带了测试前缀」 |

### 3.1 Oracle 精度（P0/关键 · 不可让）

- **点名可观测点**：写字段名/码/文案/计数，不写「正确/正常/已处理/有原因」。
- **同义多表**：方案用两字段、两码或 UI+API 表达同一事实 → 场景须对账一致；只验其一=深度不够。
- **追溯字段**：方案要求规则版本/来源对象/幂等键/计算版本等 → 命中/建议/建单路径上断言出现且非空（或方案允许空时写条件）。
- **失败可观测**：超时/降级/拒绝须有稳定业务信号；原始异常文本可作缺陷证据，**不得**当作「已有原因」通过。
- **专用负向不可替**：上表命中的冲正/历史改写/经营隔离/同键异体/前提缺失/关联挂接等，须独立 SC 或同条可判定分支；主路径绿≠该负向已测；**检查假绿不得顶替「能否配置绑定」**。

- 只测主路径不算完整；负向/边界/状态/权限/前提缺失是默认面，不是“可选加分”。
- 一个意图可有多个场景，但每个意图只出一个结论（最差态合并）；场景通过率不能替代意图结论率。
- 执行记录 §1.1 写场景覆盖说明；§3 写意图结论，**场景 ID 必须指向 §1 的 SC**（只有结论没有场景不算执行）；P0 缺口不得用“低优先级/后续补”跳过。

## 4. 步骤怎么写（可复核）

- 3～7 步，一步一个动作 + 核对点；格式 `1. 打开{入口/路由}（看{区域}）→ 2. 输入{字段=值}→ 3. 点「{按钮}」→ 4. 核对{列表/详情/Network}的{字段/状态/提示}`。
- 每步至少一个可核对对象（字段/状态/码/提示/Network）；不写「打开/点了/看了」这类无判定对象的动作。
- 位置到页面/区域/Tab/弹层/控件；按钮用界面可见文案；列表按列名定位行。
- 写清关键数据（字段=值/样本/账号）；不写“按场景数据/同业务详情/本步结果可在页面核对”。
- 通过/低风险场景在 §1 保留带核对点的紧凑步骤即可；失败/P0/锚点再在 §2 展开详情块（预期/实际/复现/证据/分类）。
- 不要求每条截图；失败/P0截图钉断言点并同帧做视觉检查。

## 5. 接口场景

- 契约先行：method/path/鉴权/关键参数/成功码/关键字段/错误码；禁猜。
- 维度按适用性：成功契约、无 token/失效、越权、参数边界、超长/Emoji、非法状态/假成功、幂等/并发、不存在资源、分页、排序、错误 METHOD；不适用写依据。
- 判定三要素：HTTP 码 + 业务码/信号 + 关键字段；仅 2xx 不算通过；写后回查；假成功=失败。
- 确定性场景同轮脚本；请求摘要不含密钥；证据含响应码/关键字段/脚本 jsonl。

## 6. 执行中自主调整

- 可自主：场景顺序、数据构造、工具选择、低风险抽样；发现更优验证方式可改。
- 必须记录：执行记录 §3/计划 §6 写“为什么改/影响哪些意图/是否需确认”。
- 必须停：Oracle 无来源、范围/准出变化、P0 未覆盖、不可逆/合规/资金/权限风险。
- 禁止：改预期凑通过、删负向/边界、把失败/阻塞写成通过、用 API 旁路冒充点名 UI。

## 7. 自检（执行前/批末）

1. 每个场景有意图/来源/Oracle；P0 Oracle 符合 §3.1（字段级，非主题句）。
2. P0意图有失败/负向/状态/权限/幂等/恢复（适用项）；§3 命中的专用负向有独立落点或 N/A+依据。
3. 同义多表/多载体交叉断言已做或 N/A+依据。
4. 证据可打开、钉断言点；失败/阻塞/待实现有原因。
5. 步骤足够第二人复核，但不假装是逐步脚本。
6. 新风险/新意图已回写计划。
7. 结果状态语义正确；计数与记录一致。

## 8. 常见合理化与反驳

| 合理化 | 现实 |
| --- | --- |
| “方案场景都覆盖了” | 场景 1:1 不等于技法展开；看失败/边界/状态/权限。 |
| “字段太多，全排列” | 等价类 + pairwise；全排列是浪费。 |
| “预期写正常/成功就行” | 不可观测=不可判定；写值/状态/字段。 |
| “有 failReason/有状态字段就算过” | 须语义正确且用户可读；双字段冲突或 SQL/堆栈当原因=失败。 |
| “主路径过了，冲正/历史/经营隔离以后补” | §3 命中即本轮深度；无独立负向或 N/A+依据=缺口。 |
| “AI 输出没法测” | 用 Oracle/rubric/人工+重复阈值；不是不测。 |
| “UI 看看就行” | 截图同帧检；阻断主路径才算 fail，其余记额外发现。 |
| “方案没写负数/边界/权限” | 负向/边界/权限是默认面；文档未写≠免测。 |
| “页面显示百分比就算通过” | 没有分母/公式/复算，不算通过。 |
| “少写负向通过率好看” | 测试为找缺陷；为刷绿砍负向=禁止。 |
| “不预生成用例所以场景少也正常” | 少的是预写库，不是深度；命中特征行未展开=缺漏。 |
| “一个 INT 一条正向就终态” | P0/关键须按 §3 深度档；缺负向/边界/适用面须补测或「不适用+依据」。 |
| “结构/关联检查 API 测了就算绑定能力测了” | 否；配置入口/字段/键与消费端读入或阻断是两面；只测检查=漏配置契约。 |
