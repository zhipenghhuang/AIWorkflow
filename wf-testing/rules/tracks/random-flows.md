# 轨契约 · 随机业务流程测试

> 口令命中「随机业务流程 / 业务随机」生成或执行时默读本文。主链 step 仍用 `testing.yaml`。  
> **定位（主场景）**：无迭代、无测试计划时的**日常**测试——**模仿真实用户操作与体验**，把一类**长业务办完**，发现问题与优化建议，优化项目。  
> **计划外**：**不进** `{workroot}/test-plan.md`、不占 P0～P9、不参与准出；「按计划执行」**不**调度本轨。完整覆盖与准出只认计划内分析→生成→独立评审→装填执行；本轨**不**以「读/补计划缺口」为选路依据。  
> **与探索式**：口令互斥（一次会话只走一轨）。探索式按章程挖风险；本轨是用户旅程模仿 + 体验发现，**不是**无章程探索式，也**不是**全产品冒烟执行器。探索式规则见 `tracks/exploratory.md`，**本文件不修改该轨**。

## 主业务选池（服务「办一类活」）

1. **默认池**：全产品**主业务办结链**（跨模块、可办结的一类活 / 主链路）；主题（若有）只收窄「办哪类活」，不当 oracle、不当选池合同边界。  
2. **候选来源**：用户主题（可选）→ 有则参考 `env-baseline.md`「菜单地图」+ `{workroot}/smoke-checklist.md` **作办结候选**（禁机械跑完冒烟表）→ 现网菜单/入口探查补全。  
3. **门2 必写**：`选池依据`｜`本轮办结目标（用户意图一句话）`｜`为何算主业务`｜去重窗/新增轴｜`刻意复测`。  
4. **禁止**：用某期迭代方案、分析表 §0 差量、计划缺口界定本轮选池或判定；默认不以单模块边角配置页当主旅程。  
5. 多轮靠账本 + 去重窗换轴逐步散开；不追求一轮覆盖度拉满。

## 执行手感

- 从真实入口进，按界面提示与业务习惯往下办，直到一类活办结或明确失败面。  
- 允许合理变体（换角色可见性、换样本、异常后恢复再办完）。  
- 沿途记录：卡点、假成功、脏数据风险、提示不诚实、流程绕、体验摩擦。  
- **禁止**：为「覆盖模块数」东点西点；无办结目标的菜单扫街；用 API 旁路冒充「用户办完」。

## 去重窗（最近 N 轮）

- **账本**：每轮收尾追加旅程指纹（可查）。路径见上表。
- **去重窗**：只取**最近 N 轮**（默认 **N=3**；同主题优先；用户点名可改本轮 N，记 `deviation=`）。窗外历史**不**参与挡跑。
- **指纹字段（宜短）**：`指纹ID`｜`主题`｜`入口→模块链`（3～8 跳）｜`变体轴`｜`轮次戳夹`｜`发现摘要`｜`回流`。
- **门2 必带**：`去重窗=最近N轮` + 窗内摘要（或「窗内无」）；`本轮相对窗的新增轴=…`；`刻意复测=否|是+理由`（仅修后verify/用户点名）。
- **雷同（仅窗内）**：与窗内任一条「入口+模块链+变体轴」重合 ≥2 维且无新轴 → 不得作本轮主内容；可 1 条锚点复测证明环境。与窗外雷同 → 允许。
- **收尾**：指纹追加进账本；相对窗无新增且非刻意复测 → **未收尾**（禁空跑炒冷饭）。

## 发现分流

| 类 | 约定 |
| --- | --- |
| 缺陷（类型=`随机`） | 崩溃、脏写、假成功、权限不自洽、提示不诚实、主路径办不完、明显阻断办结 |
| 体验/流程优化建议 | 不挡办结但手感/流程别扭；不追纯风格偏好 |
| 建议补功能用例 | 旅程暴露的常青缺口；确认后才入库 |
| 仅文档≠现网 | **不**按旧方案/主读开实现缺陷；可记优化或建议补用例 |
| 误报/不适用 | 如实写 |

## 红线

- 旅程/用例 ID：`RND-{NN}`（台账合并按此识别）；禁纯数字/下划线。
- **对照随机模板**：§0 含口径=现网、办结目标、选池依据、去重窗与新增轴；主体为旅程纪要（路线摘要 + 关键观察 + 失败面）；§收尾分流表必填类（无则写「无」）。
- 禁臆造现网不存在的菜单与能力；禁为本轨选/问主读；禁把有界背景升成判定尺子。
- 禁菜单扫街冒充旅程；禁 API 旁路冒充用户办结；禁把冒烟清单机械跑完冒充本轨。
- 禁替代 P0-Smoke / 功能全量 / 计划准出；禁「按计划执行」静默跑本轨；禁宣称本场可发布。
- 不脚本化；先 UI 再 Network；证据落本轨目录；禁抬高通过率。
- 收尾禁空泛「随机通过」；须写：办结目标对照、去重窗对照、新增轴、发现分流、账本已写回。
- 缺陷测试类型用 **`随机`**；修复后回归走计划内策略或用户点名复测，不以本轨轮次冒充回归闭环。
