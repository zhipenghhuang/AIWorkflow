# 轨契约 · 前端（计划阶段批）

> 口令「执行前端测试」或计划 §3.1 **前端批**时读本文。  
> **定位**：对照方案/锁定原型做**页面结构与可用性底线**关账；企业级最低要求＝信息架构可追溯、主任务可完成、空错态诚实。  
> **不是**正式可用性实验室；**不替代**功能批业务 Oracle、探索体验深挖、发布前兼容/性能。

## 边界

| 项 | 约定 |
| --- | --- |
| 纳入 | 有页面/客户端 UI：**迭代默认必须**；整批「否」仅无 UI 面 + 事实句（可并用户确认） |
| 正式产物 | `{workroot}/{ver}/frontend/{NN}-{短名}-执行记录.md` |
| 过程 | `{workroot}/{ver}/frontend/.draft/` |
| 模板 | `rules/templates/20-test-cases/test-case-template.md`；适用时并 `a11y-ux-checklist.md` |
| 依据 | 方案页面/入口节 + 分析钉死的**设计基准**（原型/终稿）；无原型 → 方案 UI 描述 + 现网，记单源+理由 |
| 执行形态 | 浏览器 E1；`track=前端`；宜在相关功能域批后、探索批前 |

## 最低覆盖（有 UI 时）

1. **页面映射表**（记录 §0 或 §1 前置表）：设计基准页/入口 ↔ 现网菜单/路由/Tab；逐行结论＝`符合`｜`等价`（写等价物）｜`偏离`｜`缺失`。
2. **结构断言**：相对设计基准，独立工作台被同页堆叠、关键分区缺失、遮挡/截断导致主操作不可达 → 按 `classification.md` §0.5（**IA 默认缺陷或待确认**，禁闷选型）。
3. **可用性底线**：状态可见、术语与方案一致、空态/错误给下一步、关键动作可达；填 `a11y-ux-checklist` §2 适用行（无面对写 N/A+事实句）。
4. **择优**：独立页改为同级菜单/Tab 等**等价导航**时，须映射表写清且主任务可完成；**等价或更优**可记选型/优化；**IA 偏离或可观测净退化**须批收口对人点名（细则 `classification.md` §0.5）；用户未接受 → 禁标通过。

## 红线

- 禁「页面能打开 / 分区标题在 = 符合方案或原型」。
- 禁用「等价可用」选型吞掉映射表 `偏离/缺失` 且不问用户。
- 禁本批顶替功能/探索/发布前准出义务；禁实验室指标冒充本批完成。
