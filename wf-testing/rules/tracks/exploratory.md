# 轨契约 · 探索式测试

> 口令命中「探索式 / 探索测试」生成或执行时默读本文。主链 step 仍用 `testing.yaml`。  
> **定位**：补功能/接口测不到或不方便固化的点 + 细节/体验深挖（入口下一步、提示/空态诚实、状态误读、门禁假可点等）；**不替代功能/接口覆盖**。  
> **成败**：以可复现发现、覆盖缺口、新风险衡量；禁空「探索通过」或用步骤跑完率当成功。  
> **计划驱动**：按计划 §2 轨道/§3 轮次，意图/风险见分析 §2/§3；T1+/版本级（非补丁）必须纳入 ≥3 条章程（T2/T3 ≥4，≤6）且必选轴有对应面须章程（无面对才 N/A+事实句+用户确认，Q19）；整轨 N/A 仅 `multi-track-quality` §0 + 用户确认；独立口令可即兴。  
> **互斥**：随机业务流程是计划外独立轨（`tracks/random-flows.md`），不塞进本轨。

## 常青边界（硬）

| 常青什么 | 不常青什么 |
| --- | --- |
| 命名纪律、SBTM 节奏、谱系选题方法、发现分流；根 `smoke-checklist` 沉淀 | 单轮探索记录文件（随 `{ver}/` 关账） |
| 历史记录作母题/风险参考 | 把上轮章程原样冻成「探索全量库」复跑 |
| 稳定发现沉淀为 **意图/锚点**（或新章程） | 用探索记录冒充功能/接口主档、进 suite 装填计数 |

- 锚点常青只适用于 P0/高价值场景；探索成功标准是本轮章程目标闭环 + 可复现发现，不是库对齐。  
- 换版本/新提测/缺陷面明显变化 → **必须重选题**写计划 §2/§3 并回指分析 §2/§3（或即兴新戳），禁默认沿用上版章程文件名。

## 章程选题（跟实际风险走）

输入至少 2 类：

| 源 | 怎么用 |
| --- | --- |
| 分析 §2 高影响意图 / §3 风险 | 邻接风险优先入章程；不入须用户确认+事实理由（Q19） |
| 本项目缺陷平台 | 近窗未关/复发/同模块簇 → 谱系码对齐；已稳定进意图/锚点的降优先级 |
| 跨项目实战 | 只经 `defect-findings-spectrum.md`；禁搬他项目用例/戳夹 |
| 本轮执行记录 | 缺口 → 新章程或补意图；勿只记观察 |
| 上轮探索记录 | 仅作母题参考；风险已消或已进意图/锚点 → 换题 |

### 必选轴（T1+）

| 轴 | 章程/不测 |
| --- | --- |
| S6 入口/可见/失败下一步 | `{EXP-…}`（有入口/失败面必填） |
| S7 门禁假可点/禁用原因/全选≠确认 | `{EXP-…}`（有门禁面必填） |
| S11 提示/空态/同源一致 | `{EXP-…}`（有提示/多载体必填） |
| 状态误读/跨载体冲突 | `{EXP-…}`（有跨载体必填） |

> 有对应面 → 必须章程，**禁**「不测+接受」顶替。无对应 UI/门禁/多载体 → N/A+事实句+**用户确认**。四行空或有面却不测 = 计划门/P2 未过。

### 一场一条

- 章程一句：看哪里、用什么、想发现什么（对齐一个谱系码）。
- 计划可留最多 6 条待办，按风险排序；一场只领一条；其余写下场；不测仅 Q19。
- 先领本产品未关、且本轮意图没盖住的最高簇；没有缺陷簇才用谱系静态优先池。
- 页面提示成功后，要核对记录/状态是否真的变了。同键换内容仍能再建、空请求也成功 → 归接口轨；本场不测就写「不覆盖接口幂等」。
- 每场：领一条 → 时间盒 → 记覆盖/没碰到/发现/疑问/下一句 → 分流；**风险点须逐点结论后方可关场**。
- **已跑判定**：计划状态=已跑/本场 ⇔ 同章程非空 `*探索记录`（章程一句+风险点表结论+会话四记）；空文件/只改计划状态字 ≠ 闭环。
- **发现分流**：缺陷 → 缺陷+回归；缺口 → 补意图/锚点（写 INT/SC）或下一句；误报 → 记录；交付缺口禁止只进观察。
- **沉淀清单（硬）**：debrief/收尾必写「拟补锚点/意图：…」或「无稳定可沉淀」。
- **加场**：本产品未关高簇且计划章程未盖住 → **优先在 ≤6 内加场**；确无法加场须用户确认不测+事实理由（Q19）；禁仅填满四轴标签即停。

## 红线

- ID 用 `{前缀}-{NN}`（如 `EXP-01`），禁纯数字/下划线。
- 对照模板：章程一句、为何是本场、3～6 个可判定风险点（逐点结论）、会话四记（覆盖/没碰到/疑问/下一句）。发现才写可跟做的复现、判定依据与严重度。
- 生成前至少读计划 §2/§3；无计划须写不适用+依据。
- 禁「已登录」「验证功能正常」「探索通过」当记录或收尾。
- 禁预写整套逐步用例代替会话。
- 禁空文件/仅戳名关账；禁多轴连扫无各场正文却计多章程。
- 禁把探索记录当常青库做 suite 装填/通过率统计；禁跨版本默认复用未重选题的章程。
- 禁无缺陷/计划依据却宣称「本轮探索已覆盖实战高频面」。
- 探索辅助（可选）：装配 vision-ui 时可用自然语言+截图断言辅助判定；结论仍须可对照主读/现网。
- 执行与落账细则见 `rules/special/multi-agent-output.md`；计划驱动跨轨见 §4。
- 证据落 `{ver}/evidence/`，禁抬高通过率。
- 探索式不脚本化；session/debrief 必做，发现须分流。
- 章程步骤含菜单/页面时同功能轨：浏览器 MCP 先 UI 再 Network；仅无 UI 断言面可 API，记录通道写「混合」。
