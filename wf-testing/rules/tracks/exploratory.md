# 轨契约 · 探索式测试

> 口令命中「探索式 / 探索测试」生成或执行时默读本文。主链 step 仍用 `testing.yaml`。  
> **定位**：补功能/接口测不到或不方便固化的点 + 细节/体验深挖（入口下一步、提示/空态诚实、状态误读、门禁假可点等）；**不替代功能/接口覆盖**。  
> **成败**：以可复现发现、覆盖缺口、新风险衡量；禁空「探索通过」或用步骤跑完率当成功。  
> **计划驱动**：按计划 §2 轨道/§3.2 风险面，风险见分析 §3；T1+/版本级（非补丁）必须纳入，高风险面有对应面须有探索结论（无面对才 N/A+事实句+用户确认，Q19）；**风险面清单 ≥4**（少则事实说明+用户确认），场次按预算（一份记录可覆盖多面）；整轨 N/A 仅 `multi-track-quality` §0 + 用户确认；独立口令可即兴。  
> **互斥**：随机业务流程是计划外独立轨（`tracks/random-flows.md`），不塞进本轨。

## 常青边界（硬）

| 常青什么 | 不常青什么 |
| --- | --- |
| 命名纪律、SBTM 节奏、谱系选题方法、发现分流；根 `smoke-checklist` 沉淀 | 单轮探索记录文件（随 `{ver}/` 关账） |
| 历史记录作母题/风险参考 | 把上轮场次原样冻成「探索全量库」复跑 |
| 稳定发现沉淀为 **意图/锚点**（或新风险面） | 用探索记录冒充功能/接口主档、进 suite 装填计数 |

- 锚点常青只适用于 P0/高价值场景；探索成功标准是本轮风险假设有结论 + 可复现发现，不是库对齐。  
- 换版本/新提测/缺陷面明显变化 → **必须重选题**写计划 §2/§3.2 并回指分析 §3（或即兴新戳），禁默认沿用上版探索记录文件名。

## 风险面选题（跟实际风险走）

输入至少 2 类：

| 源 | 怎么用 |
| --- | --- |
| 分析 §2 高影响意图 / §3 风险 | 邻接风险优先入风险面；不入须用户确认+事实理由（Q19） |
| 本项目缺陷平台 | 近窗未关/复发/同模块簇 → 谱系码对齐；已稳定进意图/锚点的降优先级 |
| 跨项目实战 | 只经 `defect-findings-spectrum.md`；禁搬他项目用例/戳夹 |
| 本轮执行记录 | 缺口 → 新风险面或补意图；勿只记观察 |
| 上轮探索记录 | 仅作母题参考；风险已消或已进意图/锚点 → 换题 |

| 面 | 探索/功能收口落点 |
| --- | --- |
| S6 入口/可见/失败下一步 | `{EXP-…}` 或功能 SC（有入口/失败面） |
| S7 门禁假可点/禁用原因/全选≠确认 | `{EXP-…}` 或功能 SC（有门禁面） |
| S11 提示/空态/同源一致 | `{EXP-…}` 或功能 SC（有提示/多载体） |

### 探索方法（选题与检查点来源）

> 只作选题/检查点提示，不强制全走；一场挑 1～2 个 lens 深挖即可。

- **HTSM 精简**：产品元素（结构/功能/数据/接口/平台/操作）× 质量准则（能力/可靠/易用/性能/安全/兼容）。
- **tours 精简**：地标（主链）、邻居（邻接模块）、超模（数据极值/长文本）、恶邻（异常/断网/脏数据）、反叛（绕过入口/越权）、博物馆（历史/兼容）。
- **谱系**：按 `defect-findings-spectrum.md` 的 S1–S13 选 1 个簇。

### 一场一条

- 风险假设一句：看哪里、为什么现在有风险、想发现什么（对齐一个风险面/谱系）。
- 每场先列 **3～5 个可判定检查点**，再开始探索；检查点须逐点结论后方可关场。
- 先领本产品未关、且本轮意图没盖住的最高簇；没有缺陷簇才用谱系静态优先池。
- 页面提示成功后，要核对记录/状态是否真的变了。同键换内容仍能再建、空请求也成功 → 归接口轨；本场不测就写「不覆盖接口幂等」。
- 每场：领一条 → 按检查点探索 → 记覆盖/没碰到/发现/疑问/下一句 → 分流。
- **已跑判定**：计划状态=已跑/本场 ⇔ 同场非空 `*探索记录`（风险假设+检查点结论+会话四记+结论）；空文件/只改计划状态字 ≠ 闭环。
- **发现分流**：缺陷 → 缺陷+回归；缺口 → 补意图/锚点（写 INT/SC）或下一句；误报 → 记录；交付缺口禁止只进观察。
- **debrief（硬）**：收尾四选一——保留（继续同面）/ 换题（风险已消）/ 补测（检查点未达）/ 沉淀（补锚点/意图）；必写「拟补锚点/意图：…」或「无稳定可沉淀」。
- **加场**：高风险面或未关高簇未盖住 → 加场，不设固定上限；无法加场须用户确认不测+事实理由（Q19）；禁为凑场次或只填风险面标签即停。
- **度量**：有效发现率=发现缺陷场次/总场次；报告 §2.3 记录；只用于选题与复盘，不用于通过率。

## 红线

- ID 用 `{前缀}-{NN}`（如 `EXP-01`），禁纯数字/下划线。
- 对照模板：风险假设一句、为何是本场、3～5 个可判定检查点（逐点结论）、会话四记（覆盖/没碰到/疑问/下一句）、debrief 四选一。发现才写可跟做的复现、判定依据与严重度。
- 生成前至少读计划 §2/§3.2；无计划须写不适用+依据。
- 禁「已登录」「验证功能正常」「探索通过」当记录或收尾。
- 禁预写整套逐步用例代替会话。
- 禁空文件/仅戳名关账；禁只填风险面标签连扫无各场正文。
- 禁把探索记录当常青库做 suite 装填/通过率统计；禁跨版本默认复用未重选题的探索记录。
- 禁无缺陷/计划依据却宣称「本轮探索已覆盖实战高频面」。
- 探索辅助（可选）：装配 vision-ui 时可用自然语言+截图断言辅助判定；结论仍须可对照主读/现网。
- 执行与落账细则见 `rules/special/multi-agent-output.md`；计划驱动跨轨见 §4。
- 证据落 `{ver}/evidence/`，禁抬高通过率。
- 探索式不脚本化；session/debrief 必做，发现须分流；风险面 ≥4，场次按预算，禁凑场次。
- 探索步骤含菜单/页面时同功能轨：浏览器 MCP 先 UI 再 Network；仅无 UI 断言面可 API，记录通道写「混合」。
