# 步骤包 · defect/submit

> **状态 = 本 step**。本文管编排与完成口径；**方法质量在 §6 指向的 skill**（打开→执行→回来）。  
> 不要把 skill 正文嵌进本文；不要跳过必开 skill。

## 1. 元信息

- **包轨**：wf-testing
- **workflow**：`defect`
- **step**：`submit`（提交或回写）
- **packet**：`rules/packets/defect/submit.md`
- **角色**：`bug-agent`（缺陷平台协作）。查重/提交/回归/回写按专规；备注与状态同轮；读者=开发/产品；本步只做该角色职责；越界交回或升级。
- **上游**：`search`（取其产出为本步输入；该步被 `when` 跳过时按缺口停/补齐）
- **后续**：`wrap`
- **失败去向**：不提交/不回写；补证据、补探查或问用户；不得为交平台改标失败
- **条件步** `when=defect_submit_required`：条件不满足则跳过本步（不打开本包）。
- **轻量路径**：纯文档/无行为/未命中时，可将预检标 `na`（一句理由）；**必开技能与 Claim/HITL 不降**。
- **父状态机**：`rules/packets/defect/_chain.md`（进 workflow 一次）。

- **产出**：平台单号（或待确认后的统一导出路径）· 备注与状态同轮 · 可复制汇总块（collaboration.md §5.2）

- 7. **完成只认门**：`-Claim` → `CLAIM: ALLOWED`；无 ALLOWED 禁写完成/通过/可提测。P0 未过不得整体通过；UI 证据 E1 实点+截图/Network。
- 11. **技能闭环**：§6 必开 skill 打开→执行→回包；禁止粘贴代替。

### 本步读链与防丢失

- **编排**：本文 §5 +（若 §7 列出）一个模板。

### 本步禁止

- 禁止读取本清单外的 rules / skills 正文；需要跳转只按 §6/§7 各一次。

## 4. 本步门

- **HITL `confirm_remark`**：拟关/激/解决/标重复/补充澄清/回归写回 → 先列 id+结论+备注全文；确认后执行
- **HITL `confirm_platform`**：有拟入库、须问交平台/新建缺陷单/回写 → STOP（交平台用专用确认句）；**≠** git；否则跳过
- **GATE `writeback-receipt` when=remark_writeback**：运行对应 verify；未过不得宣称完成。
- **推进**：默认本步完成后即停（仍输出收尾骨架），不打开下一步。仅当本会话是按链、继续、按计划执行或全链入口时，才进入阶段表的下一未跳过步。
