# 步骤卡 · defect/submit

> 状态 = 本 step；全局规则见 `rules/core/global-rules.md`（每步必读并逐条过）；方法在 §6 指定节（打开→执行→回包）。不读他步 packet / 大手册。

## 1. 元信息

- **workflow / step**：`defect` / `submit`（提交或回写）
- **packet**：`rules/packets/defect/submit.md`
- **角色**：`bug-agent`（缺陷平台协作）。查重/提交/回归/回写按专规；备注与状态同轮；读者=开发/产品；本步只做该角色职责；越界交回或升级。
- **上游**：`search`（取其产出为本步输入；该步被 `when` 跳过则记 `skip=`，不因缺上游阻塞，除非本步硬依赖其产出）
- **后续**：`closeout`
- **失败去向**：不提交/不回写；补证据、补探查或问用户；不得为交平台改标失败
- **条件判定 `when:defect_submit_required`**：子类为提交/修改/回归写回/补充澄清/产品回流/新建单；满足→真，否则跳过本步（不打开本包）。
- **轻量路径**：纯文档/无行为/未命中时，可将预检标 `na`（一句理由）；**必开技能与 Claim/HITL 不降**。

## 2. 本步目标

- **目标**：提交或回写
- **产出**：平台单号（或待确认后的统一导出路径）· 备注与状态同轮 · 可复制汇总块（collaboration.md §5.2）

> **全局规则**：每步读 `rules/core/global-rules.md` 并逐条过（切步/过门/续跑都重读）；心跳 `global=ok` 表示本步已读；未读不得写 `global=ok`。偏离写 `global=dev:<原因>`。

### 本步边界

- 只读本包 + §6 技能 + §7 模板；不通读他步/大手册。
- 必开技能打开→执行→回包；未过 §4 门不得宣称完成。

## 4. 本步门

- **HITL `confirm_remark`**：拟关/激/解决/标重复/补充澄清/回归写回 → 先列 id+结论+备注全文；确认后执行。
- **条件判定 `hitl:remark_writeback`**：拟关/激/解决/标重复/补充澄清/回归写回；满足→真，否则跳过该门。
- **HITL `confirm_platform`**：有拟交平台/新建缺陷单 → STOP；回写走备注门；≠ git；无平台动作跳过。
- **条件判定 `hitl:platform_submit`**：拟新建缺陷单/交平台；满足→真，否则跳过该门。
- **GATE `writeback-receipt` when=remark_writeback**：运行对应 verify；未过不得宣称完成。
- **条件判定 `gate:remark_writeback`**：拟关/激/解决/标重复/补充澄清/回归写回；满足→真，否则跳过该闸（步骤不跳过）。
- **推进**：默认本步完成后即停（仍输出收尾骨架），不打开下一步。仅当本会话是按链、继续、按计划执行或全链入口时，才进入阶段表的下一未跳过步。

## 5. 本步动作

> **本节 = 本步编排与门槛**（顺序、产出、门、禁做）。
> **方法质量在技能**：§6 列为必开/条件开的 skill 必须按闭环执行，**禁止**把技能正文粘进本包替代实读；**禁止**为省事跳过必开技能。

### 本步动作清单

- remark_writeback＝拟关/激/解决/标重复/补充澄清/回归写回备注。
- 先出 id+备注全文再执行。
- platform_submit＝计划为批末/阶段末/收尾确认且本轮拟新建单时触发。
- 执行批 ID 与计划对齐。
- 修复批可另立 `B-FIX-xx` 并在计划登记。
- 细则见 先红证/根因。
- 不修表象。
- 回写带证据（分流：本地消化/盯办/缺陷；待实现进缺陷清单；测本地消化不开单；外力盯办须实机类型+指派匹配或问用户）。
- 补充澄清 回归未通过 新问题 非修复处置 产品判定回流各按对应写回骨架。
- 写后按 collaboration 回查。
- 产品缺陷：提交后直接指派产品负责人，不经开发。
- 产品判定非问题/重复/信息不足 → 指派回测试按回流处理。
- 建单标题：`[V版本?][测试类型]`+正文（已确认迭代版本才加 `[V…]`；类型必加）。
- 列表/仅查重展示/仅建单（无状态回写）→ 跳过 remark 门。
- 拟新建单仍按 platform_submit 门。
- 列表子类可跳过本步直 closeout。
- 回写内容由编排集中生成。
- 子代理只提供事实素材，不写平台、不改状态。
- **缺陷通道**：`api`/`browser`/「提交禅道|平台」→ **完整交平台即完成**（writeback 回执 + 台账单号）。
- **禁止**同轮导出包、BUG HO、出站实拷详单、一缺陷一目录。
- 无平台/`export`/点名「缺陷交接包|发给开发|仅导出」→ **先问后发**：出示【拟统一导出】（条数/单文件或单 EXPORT 目录）。
- 确认后本批**只落一份**（见 内容优先、包按需；未回执不得称已接收；禁「拟提交」充数；禁逐条文件夹）。
- 基线缺陷平台节不全 → 先问补适配直提 vs 统一导出。
- 确认前零落盘。
- 更新台账/计划平台号。
- 仅导出路径才更新 `handoff-ledger.md`。
- 未回执不得写“开发/产品已接收”。
