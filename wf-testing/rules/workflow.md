## 1. 总则

### 1.1 计划门与三门 · 落盘

见 `../AGENTS.md` §0.1（计划门＋门1～3；条件门：`hitl_when` 不满足则跳过）。正式资产只写现行有效状态（AGENTS §0.0）；落盘按 `rules/templates/`。

### 1.2 测试分级（T0～T3 · 防过度/不足）

| 级别 | 典型 | 计划 | 执行 |
| --- | --- | --- | --- |
| T0 补丁/热修 | 小改、单模块 | 轻量计划（≤1 页） | P0 冒烟 + 影响面 + 已脚本化回归 |
| T1 模块 | 功能/模块 | 轻量计划 | 模块功能 + 接口（如适用） |
| T2 版本 | 发布级 | 完整计划 | P0～P9 按计划 |
| T3 高风险 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 全量 + 性能/安全/兼容 |

T0/T1 不强行填完整模板；范围/类型/轨道/执行矩阵/准出/风险必须写清。发布列车/大版本 ≥1 次功能全量；补丁不强制全量。  
**常青纪律（计划内）**：版本级范围须含本期增量 + 常青/前序足够覆盖（至少依赖版 P0-Smoke 或等价常青冒烟；高风险可升 HighRisk）；准出须**当期通过且常青/前序约定项未崩**，禁止默认「仅新功能通过」。常青靠 Smoke+影响面+必要 HighRisk，不默念归档全量。计划外「随机业务流程」不替代本层、不进计划登记/排期/准出。

### 1.3 产物与过程（相对项目根 · 正式并列轨）

> **产物根：唯一 {workroot}/**——项目根仅 env-baseline.md、activeContext.md；设计输入进 inbound/{ver|topic}/ 或 inbound/_common/（禁 项目文档/ 层），样本/测试数据进 docs/materials/{ver}/05-testing/test-data/；交接：出站实拷/升包在 {workroot}/handoff/outbound/{category}/，入站收件在 {workroot}/handoff/inbound/{category}/（台账 {workroot}/handoff/handoff-ledger.md；handoff/inbound不作主入口）；**禁止在项目根新建测试计划/用例/台账/脚本/证据**（原始输入放入原件根 `inbound/`，推荐 docs/）；下表路径均相对项目根。  
> **资料收取/对照/归档**：以 rules/doc-governance.md 为准；新资料先分析分类 + 与同主题/同版本旧文件做覆盖对照，输出候选，**用户确认后**才改名/登记/标记失效/归档。  
> **归档（分轨 · 域常青）**：换代/结项/版本关闭（用户确认后）→ **主计划/四卷/报告/CR/交接快照**进 {workroot}/_archive/{yyyyMMdd}-{版本}/；**用例主档留下**（功能/接口域常青）。轨内 _archive/ 仅收：下线域、有界重生快照、点名旧轮（探索式/随机）、发布前专项停用包/旧轮报告。失效资料进 inbound/INDEX.md 状态；当前 {workroot}/test-plan.md 不移动；**禁**把各轨用例整包丢进根 _archive/；**禁**关账搬走仍有效的功能/接口主档。多版本并行（罕见）→ {workroot}/{版本}/ 另起一套、单点随其目录。  
> **常见轨框架**（功能 / 探索式 / 随机业务流程 / 接口 / 发布前，非穷尽）：边界见 rules/tracks/（随机业务流程为**计划外**独立轨）。新测试种类不强制新轨名 → **就近归轨**，计划/台账写差异与 deviation=；有独立目录需求时再登记。

## 2. 生成

> **资产生命周期（域常青 · 分层库 · AI 增量）**：功能/接口等**域主档跨版本保留**（`…/{NN}-{短名}/*-功能|接口用例.md`），**不**因换迭代整轨搬走。分层：`L0`=Core（`{workroot}/smoke-checklist.md`，≤12）｜`L1`=域常青主档｜`L2`=本版增量（special/新条，择优沉淀进 L1）。**索引** = 域注册 + Core + 本轮装填表（计划 §3.7）；**禁**日常通读全库当回归清单。  
> **生成默认**：影响源（提测单影响面**若有优先** → CR → 主读 diff/有界对照 → 用户点名）→ **先打开命中域** → 表 `新增|修改|淘汰|rerun` + 保 `caseId` 增量改；**禁**无分析整版重生；**禁**「继续」隐式全仓 generate。  
> **rules/深度档升版后**：对本期命中域对照 `testcase-design` §2.2 **现行深度档做 diff**（缺行补条或「不适用+依据」）；**禁**只升规范版本号、命中域仍旧深度。  
> **影响面（测试包自建 · 不依赖提测单）**：无开发提测单/无 HO 时，**测试分析表**仍须写清 **直接/邻接/回归** 影响面并落入 §3.7 装填；**禁**因「没有提测单」跳过邻接影响面或只测变更点本身。提测单只是加速输入，不是影响面的前提。  
> **冷启动**：命中域文件不存在 → **允许按域首生**（非逃生）；有库后默认增量。  
> **有界重生（逃生）**：口令「重写{域}」／半域失效／同域无效合并≥2 次 → 快照入轨内 `_archive/` 后整域重生；须收尾写明域名与原因。  
> **一遍过**：= **本期命中范围/本域变更面** 宁多勿漏（映射无空、影响面落点），**≠** 全仓重生。  
> **脚本**：P0-Smoke 跨版本保留；接口按 depth（迭代 `standard` / 发版 `full` / 补丁 `core`）可执行维须脚本化；一次性不脚本须理由。日常小修 → §2.1.1；续跑 → §3.1。详见 `rules/special/multi-track-quality.md`。

### 2.1 功能测试资产

- **口令**：生成用例 / 生成测试资产 / 阶段一 等  
- **输入**：已点名主读或门1 选定 + 设计输入 + 可探查现网 + **`{workroot}/test-analysis.md`（必有；模板见 `rules/templates/10-planning/test-analysis-template.md`；主读已点名也不省）** + **现行测试计划**（缺/超范围 → 先轻量补）+ `{workroot}/smoke-checklist.md`（有则读）+ **命中域现行用例**（有则必读；`_archive` 默认不读）。**生成/计划双读：主读原文 + 测试分析表**。  
- **动作**：轻量分析（可与生成同轮）→ 定命中域 → **增量**产出/更新用例与台账（**计划驱动按 §3.2 + §3.7 装填登记**；结果=未执行；**写法红线见用例模板头**；模块头须有 §1 总览索引供锚点改条）→ **逐条判可脚本化并落 §1.2 清单**（`rules/special/script-execution.md` §1）→【生成收尾】写增改删表  
- **大规模生成**：≥3 模块且（预估≥40 条或用户点名）→ 按 `multi-agent-output.md` §1.5 分片（draft 不相交可并行≤3；编排合并+覆盖三闸；超时降级直做）；**禁**并行写同一正式域文件。  
- **能测尽测**：方案未写死数值/细则时，**仍须生成行为与流程用例**；预期可写「以本构建现网实现值为准」。禁止因「文档待冻结 / 交给开发定」而整段不生成或不测。  
- **既有实例**：旧 `{NN}-*.md` 包**视为 L1 现行**；下版起增量；**不强制重编号**。  
- **框架闸**：  
  1. **完稿自检**：按生成代理（testcase-agent）清单逐项过——独立可执行/前置三件套/编号对齐/判定面/负向边界/影响面逐点/视觉基础/映射无空行/引用可回查/冒烟集齐/排序/清理与提示/七维自查/章节回执/引用抽验；缺项先补，禁带缺口落盘。  
  2. 有依据写清；设计来源可回查或标明现网依据。  
  3. 生成期结果列为「未执行」（「待实现」仅作执行终态，且仅限方案/AC/计划范围内未实现——见 §3.0；待实现=实现缺陷，必须计入缺陷并提交）。  
  4. **覆盖（准确度前置 · 三闸）**：落盘前须完成；缺任一项不得称「已覆盖」。细则如下。

#### 2.1.0 覆盖三闸（功能全量 / 功能专项 · 不可让）

> **术语**：覆盖单元=验证点（同一 ID，见分析表 §2）；不再另造 `VP-` 编号。  
> **定位（不可让）**：功能轨是迭代准出主轨——对本期**命中域/变更面**按『**一遍过 · 宁多勿漏**』补齐映射与用例（增量优先）；**影响面（逐邻接点）与视觉/UI 基础必须覆盖**；接口/探索式/发布前为补充轨。**禁**把「一遍过」读成全仓重生。  
> **强制范围**：§2.1 功能全量与 §2.1.1 专项须过覆盖三闸。接口/发布前/探索式（§2.2～§2.4）按 `rules/special/multi-track-quality.md`：**接口对照禁空+depth 可执行**；**发布前硬映射**；**探索章程目标闭环**——禁止「软覆盖」空话。

### 3.0 口径探查与结果态（功能全量/专项 · 不可让）

1. **实施后必测**：方案将数值/细则交给项目落地时，执行以**本构建现网实现**（页面说明、配置、接口、计算版本）为断言尺子；与方案意图冲突 → 失败或拉产品确认，**不得**因「方案未写死」跳过。  
2. **口径待探查**：开跑该条前先读出**本载体**实现值（字段名/提示/配置），写入台账摘要或基线增量再判定；**禁止**因难测改测其它功能点/接口。  
3. **`待实现`（pending）**：方案/AC/计划范围内应实现而未实现（菜单无入口且无接口）→ **实现缺陷**；入口存在但 404/500/空壳/假成功→**失败（实现缺陷）**；两者都必须计入缺陷并进入批次/阶段/收尾提交。明确范围外/后续池 → `不适用`，不标 pending。**禁止**「系统已有rules/阈值，仅文档未写」→ pending。**禁止**把交付缺口写成分析表「依据 GAP」或台账「观察」后继续刷绿；可另开 API/门户深测，但**入口齐套点名用例本身不得因旁路通过而标 pass**。  
4. **`阻塞`**：过渡态——穷尽自打通仍不可达（互异手段≥2 且总尝试≤3；缺数据须先造/换，细则见 `rules/special/multi-agent-output.md` §1.3-4）。**方案/AC 范围内未实现（菜单无入口且无接口）→`待实现（实现缺陷）`；入口存在但页面/接口 404/500/空壳→`fail`；两者都不是阻塞**；与 pending 勿混用。测短路径可通 → 本地消化不开单。需外力 → 按 `classification.md` §0.4 同轮**盯办短证** + 批末盯办清单（建单随 §11/门3），**禁**为交平台改标 fail/待实现。**blocked 四问**：能造数/换样？能换入口/角色？是否被测缺陷（→fail）？互异手段≥2 且总尝试≤3？**终态对照**：缺数据/样本→造/换；菜单无入口且无接口→`待实现（实现缺陷）`；菜单有入口但页面/接口 404/500/空壳→`fail`；环境/可测性外责穷尽→`blocked`（同轮短证）。  
5. **GAP ≠ 交付缺口（对照）**：分析表 **依据 GAP**=oracle/AC 无来源或不可观测 → 澄清/关键未关禁准出；**交付缺口**=范围内应有入口/能力而未交付 → 执行终态 `待实现`/`fail` → 缺陷批次。二者禁混用、禁互相冲掉。  
6. **判定语义（禁弱通过 · 单一段）**：  
   - **不可达 ≠ 实现失败**：断言面接口缺失/造数穷尽 → `blocked`（写已试路径）；面可达且违背方案/AC → `fail`。  
   - **无有效样本不得报通过**：变体/预检一致/入口齐套等，空扫「未见异常」→ 禁 pass（造数 / `blocked` /「不适用+依据」）。  
   - **拒绝与成功须可观测**：期望拒绝却弱成功信封、或授权未拦却先撞业务规则 → fail；声明成功却不交付方案要求结果 → fail；目标身份应有权却不可达 → fail（禁高权代测冒充）。侧信道可另记，**禁**观察后宣称权限/安全达标。  
   - **错误语义对齐**：预期业务阻断时，实际须为**同类**门禁/阻断码；入口错配、指纹过期、参数门禁错类 → 不得记「符合预期阻断」PASS，须先纠入口/口径（接口见 `tracks/api.md`）。  
   - **横切与口径**：方案声明的幂等/并发/审计/附件/移交等适用多对象时 ≥2 载体或 N/A；有权威源则展示须对照；固化事实不可否定须有负向。单载体绿不得宣称横切面通过。  
7. **路径旁证（执行中 · 不扩载体）**：跑本条时同路径已见的产品问题（假成功、空壳、越权、口径矛盾、阻断级视觉等）须记 `fail` 或「额外发现」并留证；**禁**因「非本条原断言」静默忽略。仍遵守「禁换验收载体」：旁证只记所见，不改打其它功能点凑条。
8. **验证点结论（禁重复计）**：同一验证点只在归属阶段/轨记一次结论；跨阶段只引用结论与证据，不重算通过率；用例通过率与验证点结论率分开声明。
