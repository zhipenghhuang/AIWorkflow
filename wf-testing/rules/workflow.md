# 工作流（产物 · 轨道 · 执行 · 收尾）

> **读取级别：参考**（按节读取；当前步只读步骤包 §7 指定的节；禁止通读全本）。
> **主链**：分析 → 计划 → 执行 → 报告。步骤以 `../workflows/testing.yaml` 为准；门只认步上 `hitl*`。
> **分析必做**：`test-analysis.md` 是来源/AC/设计点/意图/风险/覆盖真源；计划只做总排，不重复分析大表。
> **执行**：用户说「按测试计划执行/继续测试计划」即执行计划范围内全部意图与轨道，到本轮终态。
> **运行时**：只认当前步骤卡 + §6 技能（+可选模板）；本文参考，禁通读拼流程。子代理/批流详版仅按技能按需打开短口径；平台协作按缺陷技能/步骤卡。

## 1. 总则

### 1.1 计划门与三门 · 落盘

见 `../AGENTS.md` §0.1（分析/计划路由硬门）与 `gates.md`（计划门、执行门、平台门；条件门不满足则跳过）。正式资产只写现行有效状态；落盘按 `rules/templates/`。

### 1.2 执行路径（默认完整，轻量需条件）

> T0～T3 仅为内部风险标签，按事实判定；只有补丁/单模块、无新增功能面且不承担版本准出才轻量，其余默认完整。

| 路径 | 触发 | 计划 | 执行 |
| --- | --- | --- | --- |
| 轻量 | 补丁/单模块，无新增功能面，不承担版本准出，无跨模块/权限/数据/安全 | 轻量计划（`plan_tier=lite`） | P0 冒烟 + 命中意图 + 影响面 + 已脚本化回归 |
| 完整 | 版本/发布列车/对外发布/版本准出（默认） | 完整计划 | R0～R2 按计划 |
| T3 专项 | 权限/资金/数据/迁移/安全 | 完整计划 + 专项 | 全量命中 + 性能/安全/兼容/迁移 |

**不确定**：事实不足或轻量/完整都能解释 → 先问 1 个关键问题；不得静默用轻量。YAML `when` 不满足可跳过相应步，须在收尾 `when_eval=假:<依据>`；手工跳过须用户同意并记 `skip=user:<理由>`。
**走链**：单步口令按「入口即止」只做该步；完整任务用「按计划/继续」推进到本轮终态。不得无提示断链，也不得越过门自动跑完。
**机器下限**：轻量计划写 `plan_tier=lite` + `版本准出=否`；声明 `版本准出=是` 必须完整计划。

### 1.3 产物与过程（相对项目根）

> **产物根：`{workroot}/`**——项目根仅 `env-baseline.md`、`activeContext.md`；设计输入进 `inbound/{ver|topic}/` 或 `_common/`；交接在 `{workroot}/handoff/`。
> **迭代轴**：本期分析/计划/执行/报告进 **`{workroot}/{ver}/`**（与产品轨版本大夹同构）；根上只留跨迭代常青资产。
> **资料治理**：以 `rules/doc-governance.md` 为准；新资料先分析分类 + 对照，用户确认后才改名/登记/标记失效/归档。
> **归档**：确认关账后将 `{workroot}/{ver}/` **整夹**迁入 `{workroot}/_archive/{yyyyMMdd}-{ver}/`；`smoke-checklist` / `scripts` / `capabilities` / `handoff` 台账留下。

## 2. 分析与计划

### 2.1 分析（必做）

- **来源盘点**：章节/标题、F/R/AC/A/N、字段规则、状态与非法跃迁、权限、关键异常、入口、配置、NFR，以及 **UI 布局/组件、文案/提示/空态**；**已映射/总数须被 §1.2/§1.3/§2.1.1 实际行数支撑**；方案有 UI 时不得整类省略。
- **环境基线**：读 `env-baseline.md` 项目身份/§1 登录/§4 账号/§8 浏览器/§13 平台/§16 脚本命中节；分析只写本轮差异，不复制整本。
- **章节回执 / 依据覆盖**：每章每 AC/F/R/N/设计点/UI/文案条目有落点或 N/A+依据；PRD/方案/原型/接口逐条映射；缺行=缺口。
- **意图台账**：每条可判定承诺一行 `INT-*`；来源/意图/Oracle/优先级 P0/P1/P2/不可接受失败/处置/接受人/方式。P0/P1/P2 都必须执行；P0 未过不得整体通过，P1/P2 未测不得跳过。
- **覆盖矩阵**：模块/流程 × 13 面（主路径/状态/边界/权限/并发/审计/通知/迁移/非功能/视觉/集成/计算/负向）；每格 `INT/场景` 或 `N/A+依据`，空白=缺口；有 UI 时视觉/UI 不得无依据整格 N/A。
- **质量特性**：ISO 25010 八类按风险标适用/方法族/意图或 N/A+依据（见分析模板 §2.2.1）。
- **方法矩阵**：P0/关键规则 × 常用方法（等价/边界/判定/状态/场景/算例）+ 其他方法列；P0 至少两种或单方法依据；只测主路径不算完整。
- **细节维**：D01–D13 + S6/S7/S11 逐维有意图或 N/A+依据；有 UI 时 D05/D08/S6/S7/S11 默认适用；S6/S7/S11 是功能收口探针。
- **风险清单**：逐类扫描（资金/对账、状态、幂等/并发、异步、权限、迁移、依赖、历史、空值、可观测、UX）；AI 提议，人确认“什么失败不可接受”。
- **影响面**：直接/邻接/上游/下游/共享数据/事件/回归逐层有落点或 N/A+依据；无提测单也自建。
- **核心链路**：每条主业务链入口/关键步骤/意图/P0 冒烟；初版全量，迭代覆盖受影响主链+上下游回归。
- **输出**：`{workroot}/{ver}/test-analysis.md`；分析未经确认，不写计划、不执行。

### 2.2 计划（总排）

- **范围**：范围内/明确排除/假设/约束；排除有接受人；含直接+邻接+上游+下游+共享数据+回归。
- **计划**：读 `env-baseline.md` 命中节；写环境/构建/账号/数据/隔离/开跑前核验与差异；缺基线先接入。
- **引用分析**：路径 + 意图 P0/P1/P2 计数 + N/A/缺口 + 覆盖矩阵/影响面/核心链路摘要；不重复分析大表；**§0 计数/版本准出/准出口径/§3.1 意图范围须与分析联动**。
- **策略与轨道**：见 `multi-track-quality` **§0**/文首；suite/depth/发布前风险级声明；整轨否仅白名单+接受人；T1+ 探索强制纳入。
- **轮次/顺序/批次**：R0 冒烟 → R1 功能/接口 → 探索/发布前 → R2 回归；§3.1 批次/并行/隔离按计划模板该节填表；全部在范围意图。
- **准入准出**：意图终态 100%（P0/P1/P2 全部）；S6/S7/S11 有落点；覆盖矩阵/影响面/核心链路无未接受缺口；证据/锚点/报告一致。
- **缺陷/变更**：提交策略、修复回归、CR 分级。
- **输出**：`{workroot}/{ver}/test-plan.md`；计划未确认，不执行。

### 2.3 功能 / 专项

- 分析：AC/规则/字段/状态/权限/异常/入口/UI/文案逐项有意图；P0 有不可接受失败/Oracle。
- 计划：命中模块 + 邻接影响面 + 回归范围；suite 按版本。
- 执行：按意图生成场景；P0 覆盖关键失败/负向、状态/非法跃迁、权限正反、幂等/并发、恢复/对账；其他按风险补深度；实现≠方案按 `classification.md` §0.5 择优分型。
- 视觉/UI：截图同帧检查布局/遮挡/截断/空态/按钮态/文案；不另开纯视觉轮；差异走偏差择优。
- 额外发现：执行中记录 UI/布局/文案/console/Network/UX 异常；范围内入口/能力未交付→待实现/失败+缺陷；选型/优化建议不占缺陷通道。

**权限未声明**：说明列可写「文档未声明」，但须 ≥1 条可用角色冒烟，或用户书面接受本轮不测。
**设计技法**：等价/边界/判定表/状态迁移/场景/算例/错误推测/因果图/组合/属性/模糊/体验；方法矩阵已列（含其他方法）须有落点或 N/A+依据。

### 2.4 探索式

见 `tracks/exploratory.md`。一场一句风险假设 + 会话记录；发现才写复现；一轮一文件（平铺）。
- **T1+ / 版本级（非补丁）**：计划必须纳入；高风险面有对应面须有探索结论（无面对才 N/A+事实句+用户确认，Q19）；风险面 ≥4，场次按预算；未闭环不得准出；禁「功能测完」整轨否。
- **T0/补丁或无运行时交付**：整轨 N/A+依据+**用户确认**（§0/Q19）；独立口令可即兴，不替代功能/接口覆盖。
- 禁空泛「探索通过」。

### 2.5 随机业务流程（计划外）

见 `tracks/random-flows.md`；不进计划、不参与准出；「按计划执行」不调度；固定口径=现网；ID=`RND-NN`；账本 `{workroot}/{ver}/random-flows/_覆盖账本.md`；收尾写办结/窗对照/新增轴/分流。

### 2.6 接口

见 `tracks/api.md`；迭代必须纳入（整轨否仅 `multi-track-quality` §0 白名单+用户确认）。使用 `api-test-case-template.md`（执行记录）。落盘 `{ver}/api/{NN}-{短名}-执行记录.md`；脚本 `{workroot}/scripts/`；契约清单 + §2.1 适用维 + 判定三要素 + 脚本默认；迭代 depth=standard、发版 full、补丁 core；探活/UI 探针 ≠ 本轨完成。

### 2.7 发布前

见 `tracks/pre-release.md`；迭代必须纳入（§0；小改用基础级）。`{ver}/pre-release/{专项}-测试方案.md` + `…-test-report.md`（平铺）。用 charter + 指标/达标线 + 硬映射，不写详细步骤用例；缺口书面接受；计划驱动按轮次/发布门槛。

### 2.8 期中变更

口令「本期变更/计划变更/增量变更/新文档更新测试计划」。**不新开整期计划**；在当前分析/计划上增量更新。

1. **建 CR**：`{workroot}/{ver}/changes/CR-{yyyyMMdd-HHmm}-{主题}.md`；计划 §1.3/§6 登记摘要。
2. **分类**：A 澄清/无范围变化｜B 功能增量/修改（同范围）｜C 实质变更（范围/准出/排期/缺陷策略）｜D 缺陷驱动。产品确认带新 AC/文档 → D+B 或 D+C。
3. **影响分析**：模块/页面、接口、意图/风险、执行记录/脚本、数据/环境、回归、锚点、计划/报告。
4. **资料收取/对照**：新文档入 `inbound/`；按 `doc-governance.md` 对照；确认后登记/归档。
5. **更新分析/计划**：只改受影响项；分析计数与 AC/设计点账本同步。
6. **更新执行记录/脚本/锚点**：只改命中意图；保 ID/路径；禁无分析整版重生。
7. **门禁**：C 类回计划门；A/B 类变更就地更新；D 走缺陷轨，范围变化才回计划。
8. **执行**：默认等计划轮次位；提前仅限 P0、阻塞后续、独立且数据/入口就绪、有含变更构建。
9. **收尾**：CR 逐项标「已更新/不适用/待补」；未闭合不得标完成。

### 2.9 交接

- **接收**：提测/需求/报告/变更包先走 `workflows/handoff.yaml` receive：核对清单/版本/构建/阻断 → 接受/有条件/退回 → 回执 → 更新计划 §0/§1/§6、分析、执行记录；未签收不得开跑或判通过。
- **发出**：内容优先、包按需；报告→`test-report.md`；缺陷有平台→只交平台；无平台才本批统一一份；计划→`test-plan.md`；未回执不得写「已接收」。
- **状态**：有 HO 时 `handoff-ledger.md` 为包状态真值；无包时以主文档+平台为准。

## 3. 执行

`confirm_execution_scope` 确认后：功能/探索式按 **execute 步骤卡**取档；接口单 Agent；发布前按轨契约。**计划驱动 → 按计划 §3 轮次/§4 准出推进**。开跑前读 `env-baseline.md` 命中节。

> **执行口径 / 三步序 / 多源对照**：运行时只认 **execute 步骤卡 + §6 执行技能**（缺行补取档才按技能打开短口径）；本手册仅参考，不拼流程。
> **装填先行**：开跑展示计划 §0/§3：轮次 + 意图范围 + 已终态 + next。未进本轮范围→未本轮验证。
> **准出门槛**（与 `multi-track-quality` 同向；运行时以 report/门禁为准）：
> - 迭代/提测与发版/补丁准出：只认 `multi-track-quality` §3。
> - 补丁/热修：可 core + 接口 depth=core，报告标「补丁口径」；不得冒充版本准出。
> - 意图：**P0/P1/P2 全部有终态**；P0/负向/计算类结论 100%；一个意图一个结论；未结论/未执行不计通过。
> - 覆盖：分析矩阵/影响面/核心链路无未接受缺口；S6/S7/S11 有落点；T1+ 探索高风险面有结论。
> - 批次：计划 §3.1 批次合并通过；未合并批次不计本轮终态。

### 3.0 口径探查与结果态（不可让）

1. **实施后必测 / 偏差择优 / 边界重推**：见 execute 步骤卡与 §6 执行技能；分型真源 `rules/defects/classification.md` §0.5。
2. **口径待探查**：开跑前先读出本载体实现值（字段名/提示/配置/文案），写入执行记录或基线增量再判定；禁换功能点。
3. **结果态（`待实现` / `失败` / `阻塞`）**：`rules/defects/classification.md` §0.4；运行时四问见 `multi-agent-output.md`。待实现与失败进缺陷；选型/优化可过并记依据；阻塞不当交付缺口；缺数据/账号不对须先自助造数换样换角，未穷尽禁阻塞。
4. **GAP ≠ 交付缺口**：依据 GAP=oracle/AC 无来源或不可观测 → 澄清/接受未关禁准出；交付缺口=范围内应有入口/能力未交付 → 待实现/失败+缺陷。
5. **判定语义**：
   - 不可达 ≠ 实现失败（§0.4）；无有效样本不得报通过；空扫「未见异常」→ 禁 pass。
   - 期望拒绝却弱成功/授权未拦却先撞业务规则 → fail；声明成功不交付结果 → fail。
   - 错误语义对齐：预期业务阻断时实际须同类门禁/阻断码；入口错配/指纹过期/参数门禁错类不算符合预期。
   - 横切规则（幂等/并发/审计/附件/移交）多对象适用时 ≥2 载体或 N/A；单载体绿不得宣称通过。
6. **路径旁证 / 同域自洽**：执行中同路径已见问题（假成功、空壳、越权、口径矛盾、阻断级视觉、同屏冲突/读写分裂/旁路假可过）记 fail/额外发现并留证；同域矛盾禁选型（`classification.md` §0.5；探针见执行技能 5.2）。
7. **意图结论**：同一意图只在归属轮次记一次结论；跨阶段引用结论与证据，不重算。

### 3.1 功能 / 专项

- **续跑**：沿用计划轮次与意图状态；只续未终态，不隐式全量重生、不重做分析 unless CR。
- **回归**：按点名范围重测既有场景；结果就地覆盖执行记录与证据；只留最新确认结论。
- **修复后回归**：每次修复后立即回归，不等批末；原单 + 冒烟子集 + 影响面组 + 相关锚点；P0/连环 → 扩大邻接。
- **外源/他测 open**：命中本期范围 → 入回归矩阵/计划覆盖债；禁只在对话消化。

### 3.2 探索式

见 `tracks/exploratory.md`；沿用同戳记录；计划驱动按计划纳入。独立口令可即兴；不替代功能/接口覆盖。Debrief 写覆盖/未碰到/发现/疑问/下一句 + 沉淀清单。

### 3.2.1 随机业务流程

见 `tracks/random-flows.md`；仅独立口令；不进计划/准出；浏览器 MCP；不脚本化；模仿真人办结主业务；结论只落本轨；缺陷类型=`随机`。

### 3.3 接口

见 `tracks/api.md`；过程 `api/.draft/`；单 Agent；脚本优先；判定三要素；写后回查；假成功=失败；depth 按计划声明。

### 3.4 发布前

见 `tracks/pre-release.md`；过程专项 `.draft/`；工具测量 + 指标/门槛；结果写 `*-test-report.md`；缺口/接受人进计划 §4 与报告 §4；安全 critical/high 未闭环不得发布通过。

### 3.6 计划驱动执行

- **轮次**：R0 冒烟 → R1 功能 → R1 接口 → 探索/发布前（按计划）→ R2 回归 → 报告。
- **顺序/并行**：按计划 §3.1 批次/§3；同一意图禁并行；共享账号/数据/写域/浏览器状态 → 串行。
- **全意图**：计划范围内 `处置=测` 的 P0/P1/P2 意图全部到终态；P1/P2 不因低优先级跳过。
- **原文对账**：开跑按原文目录对分析 §1.1/§1.2/§2.1.1；批末本轮来源条目有 INT/场景结论，未关写接受人。
- **收口**：T1+ 功能阶段完成前 S6/S7/S11 有落点；探索高风险面有结论（有面对须覆盖；Q18/Q19）。
- **阶段出口**：按意图结论判定，不按场景条数；未结论/未执行显式缺口。
- **执行门预授权**：计划 §0 已确认/执行中/待关闭且口令为「按计划执行」→ 跳过并附【已预授权执行：按计划】。
- **执行细则**：并行隔离、回归、缺陷提交/闭环、探索穿插、非功能、外部责任、停止/恢复/变更 → 以 execute 步骤卡/技能为准；详版按需读 `rules/special/multi-agent-output.md` §4（禁通读、不替代步骤卡）。

## 4. 执行收尾（`confirm_platform`）

**【执行收尾】**：对照 `rules/templates/90-handoff/closeout-skeleton.md` §1；汇报独立成块（六点前），用执行记录结论说明体一段；报告落 `{workroot}/{ver}/test-report.md`。
> 输出按骨架 §2 六点；第 1 点=完成了什么短段+「影响：」；失败/阻塞/待实现写入第 1/5/6 点；数字与执行记录/报告一致。
> 出本节前：执行记录计数与结果表一致；计划 §0/§6 已更新；结论只留最新确认状态。

### 4.1 仓库拟提交（`confirm_commit`）

> 与收尾第 2 点「待提交摘要」分工：摘要在收尾；本块仅仓库确认一次。门 ID=`confirm_commit`；展示块名可写【拟提交·仓库】。

## 5. 全流程速查

```text
依据/迭代方案
  → 分析：来源盘点 + AC/设计点账本 + 意图台账 + 风险清单 + Oracle
  → 计划：范围/轨道/轮次/准入准出/缺陷策略/状态
  → 执行：按计划全部在范围 P0/P1/P2 意图；AI 对照来源+意图生成场景；边执行边写执行记录
  → 报告：按业务模块/优先级汇总 → 结论/缺陷/风险/建议
  → handoff：提交/交平台/交接
```

- **分析**是测试设计/覆盖索引（不是需求原文；执行仍以原文对应段为准，有互补源则对照）；**计划**是总排；**执行记录**是结果真源；**报告**只做汇总与结论。
- **P0 未过**不得整体通过；失败/阻塞/待实现必须有证据或原因。
- **锚点**只留 P0 + 高价值场景；回归按 §3.1。
