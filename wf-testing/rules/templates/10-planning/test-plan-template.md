# {项目/版本} 测试计划（总排）

> **plan_format**：`schedule-v1`
> **定位**：测试执行的唯一总排。范围、类型/轨道、轮次/顺序、准入准出、缺陷策略、状态/日志收在本文件。
> **分析真源**：`{workroot}/{ver}/test-analysis.md`（来源/AC/设计点/意图/风险/覆盖）。计划只引用其结论与计数，不重复全部意图/风险表。
> **执行口径**：用户说「按测试计划执行」或「继续测试计划」时，按本计划执行**全部在范围 P0/P1/P2 意图与轨道**，直到本轮终态；不要求额外生成步骤。
> **事实字段（硬）**：版本/构建/环境/账号/日期/范围/指标必须实际确认；未确认写「待确认」并停下问。
> **文档现行**：只写当前有效。

- **按计划执行**：一次推进到本轮全部在范围意图终态；「继续」从未终态处续跑。
- **执行自主**：可新增/替换场景、边界、工具；新增意图回写分析 §2.1，偏差记 §6；不删 P0/负向、不静默降范围；原文/AC/契约优先，现网差异不直接当预期。

## 4. 准入与准出

### 4.1 准入

- 分析已确认；计划已确认；范围/轨道/轮次/缺陷策略无歧义。
- 环境/账号/数据/P0 冒烟就绪。
- 执行记录模板/证据目录/脚本通道就绪。

### 4.2 准出

- **意图终态 100%**：范围内每个 `处置=测` 意图有终态（通过/失败/阻塞/待实现）；N/A 有接受人；无「未执行」。
- **P0**：P0 意图全过；未过不得整体通过。
- **P1/P2**：也必须全部有终态；P2 未测不能用「低优先级」跳过，除非 N/A+依据+接受人。
- **覆盖**：分析表来源/章节/AC/设计点/覆盖矩阵/方法矩阵/细节维/影响面/核心链路无未接受缺口；P0 有 Oracle/证据。
- **证据**：失败/阻塞/待实现有证据或明确原因；报告数字与执行记录一致。
- **锚点**：P0 冒烟与高价值锚点本轮通过。
- **报告**：结论唯一，缺口显式列接受人。

### 4.3 功能收口探针（T1+）

## 5. 缺陷与变更

### 5.1 缺陷分级与提交

| 级别 | 判定 | 处置 |
| --- | --- | --- |
| S1 致命 | 主链阻断/数据不可恢复/资金安全 | 立即停轮/上报；修复后全量回归 |
| S2 严重 | 核心不可用/明显数据错误/越权 | 当轮修复；原单+影响面 |
| S3 一般 | 非核心异常/有绕过 | 排期修复；回归原单 |
| S4 轻微 | 文案/样式/体验 | 可接受/排期 |

- 提交策略：`{发现即提交 / 按批末 / 阶段末 / 收尾确认 / 仅导出}`；有平台优先平台，零重复导出；无平台才本批统一一份。
- 查重：同标题/同路径/同现象先查；证据钉断言点；PII 脱敏。
- 待实现=范围内应实现未实现（实现缺陷），不得当未测/阻塞；范围外→不适用。
- 阻塞：穷尽自打通（互异手段≥2、总尝试≤3）后仍不可用；写卡点/已尝试/恢复条件。

### 5.2 修复与回归

- 每个修复后立即回归，不等批末：原单 + 冒烟子集 + 影响面组 + 相关锚点。
- P0/跨模块/契约/数据/权限/资金/并发，或同模块短窗口 ≥2 单 → 升级局部 module/扩大邻接。
- 结果就地更新执行记录，只留最新；缺陷复现补锚点。

### 5.3 变更

- A 澄清 / B 同范围增量：就地更新分析/计划/执行记录，不重开计划门。
- C 范围/准出/排期/缺陷策略实质变化：回计划门，更新 §0/§1/§2/§3/§4/§6。
- D 缺陷驱动：走缺陷轨；范围变化才回计划。
- 禁止口头变更、先测后补单、静默降范围。
