# {项目/版本} 测试计划（总排）

> **必填节**：§0–§6；§7 与「计划门摘要」按需。**读法**：按表定位，表下 `>` 判定口径填表时再读。

> **plan_format**：`schedule-v1`
> **定位**：测试执行的唯一总排。范围、类型/轨道、轮次/顺序、准入准出、缺陷策略、状态/日志收在本文件。
> **分析真源**：`{workroot}/{ver}/test-analysis.md`（来源/AC/设计点/意图/风险/覆盖）。计划只引用其结论与计数，不重复全部意图/风险表。
> **执行口径**：用户说「按测试计划执行」或「继续测试计划」时，按本计划执行**全部在范围 P0/P1/P2 意图与轨道**，直到本轮终态；不要求额外生成步骤。
> **事实字段（硬）**：版本/构建/环境/账号/日期/范围/指标必须实际确认；未确认写「待确认」并停下问。
> **文档现行**：只写当前有效。

- **默认顺序**：R0 → 功能 → 接口 → 探索/发布前（按计划纳入）→ 回归 → 报告。
- **并行**：仅当账号/数据/写域/浏览器隔离成立；同一意图禁并行；未写并行方案默认串行。
- **按计划执行**：一次推进到本轮全部在范围意图终态；「继续」从未终态处续跑。
- **执行自主**：可新增/替换场景、边界、工具；新增意图回写分析 §2.1，偏差记 §6；不删 P0/负向、不静默降范围；原文/AC/契约优先，现网差异不直接当预期。
- **门检**：轮次行的目标/出口不得空；§3.1 批次行的模块/域、执行形态不得空；`意图范围` 必须覆盖全部分析 `处置=测` 意图或写「全部」。

### 3.1 批次与并行

> 大版本/多模块填；单模块可一行「串行」。批次=合并、缺陷提交、证据核验的最小单位；未列批次默认串行并记 `deviation=no_batch_plan`。  
> **本表即计划步填表真源**（读链内；勿另开协作手册）。**子代理 ≠ 并行**。

| 批次 | 模块/域 | 意图范围 | 执行形态 | 并行组 | 隔离套/账号/写域 | 依赖/门 | 合并核验 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `B-R1-01` | `{…}` | `{INT-…}` | `{脚本/直跑/模块子代理/拆分}` | `{PG-01/串行}` | `{profile/账号/写域}` | `{R0 全绿}` | `{执行记录+证据+计数}` |

**怎么填（命中即停）**

| 列 | 口径 |
| --- | --- |
| **执行形态** | 已脚本化稳定主链/回归 → `脚本`；接口确定性 → `脚本` 或 `直跑`；同轮 **≥2 模块（含串行）** → `模块子代理`（一模块一新开；直跑须记 `deviation=subagent_skipped:<理由>`）；单模块 ≈>20 条或 P0 写密集/需独立核验 → `拆分`；补丁/单模块小批/探索小章程 → `直跑`（阈值镜像自 `collaboration/subagents.md` §2，以其为准）。可附 `surface=api\|ui\|ui+api`：含站内信/菜单/账号停用等 UI 可观测点 → 勿只写纯 `api`（执行闸见 `gate: execute-batch`）；失败行按 surface 交单：`ui`/`ui+api` 须 UI 路径+截图，`api` 才可请求链 |
| **批次容量** | 单批 **≤35 意图**；超则拆批（不拆记 `deviation=batch_over_capacity:<理由>`） |
| **并行组** | 默认 `串行`（串行=各批互不等待，**不**触发跨行扇出校验）。写 `PG-*` **仅当**隔离列能指向互斥账号或 profile/port（或无 UI 且写域不交叉） |
| **隔离套** | 有 PG → 必填可核验指针；串行可写 `共享·串行` 或具体账号 |
| **数据准备批** | §2.2 有造数项时必填一行：批次写 `B-R0-DATA`（或 `B-R0-02`），模块/域写「数据准备」，意图范围写「无（数据前置）」+ 造数项编号，执行形态=**造数**（脚本+直跑），出口=造数台账；后续批以它为依赖 |
| **轨道批** | §2 纳入=是 的接口/探索/发布前各须 ≥1 行：模块/域写「接口」「探索」「发布前」（接口批可列 `EP-*`）；缺行=该轨未排期（覆盖闸 FAIL，`multi-track-quality` §0） |
| **轻量** | 单模块/lite：一行 `直跑` + `串行` 即可 |

- 同一意图禁并行；共享账号/数据/写域/浏览器状态 → 串行。
- 并行组内并发 ≤3；UI 默认 ≤2，3 个需独立 profile/port + 资源确认。
- 同并行组（`PG-*`）内 ≥2 装填模块：形态默认 `模块子代理`；并行组=`串行` 的多行不强制子代理。无第二套隔离却写 PG → 改串行后再过计划门。
- 执行记录 §0「轮次/批次」须写本节批次 ID；批末按本节意图范围核对，**缺意图须补测**；仅真范围外经用户确认可 N/A（Q19）；未关不得合并。

## 4. 准入与准出

### 4.1 准入

- 分析已确认；计划已确认；范围/轨道/轮次/缺陷策略无歧义。
- 环境/账号/数据/P0 冒烟就绪。
- 执行记录模板/证据目录/脚本通道就绪。
- 原文对账：按原文目录/可验收单元核对分析 §1.1/§1.2/§2.1.1 漏项；漏项先补分析；未对账不开跑。

### 4.2 准出

- **意图终态 100%**：范围内每个 `处置=测` 意图有终态（通过/失败/阻塞/待实现）；N/A 有接受人；无「未执行」。
- **P0**：P0 意图全过；未过不得整体通过。
- **P1/P2**：也必须全部有终态；P2 未测不能用「低优先级」跳过，除非 N/A+依据+接受人。
- **覆盖**：分析表来源/章节/AC/设计点/覆盖矩阵/方法矩阵/细节维/影响面/核心链路无未接受缺口；P0 有 Oracle/证据。
- **原文关账**：功能/接口执行记录 §0「原文对账」行已填（其他轨在本轨记录写同义对账）；本轮范围每个来源条目有 INT/场景结论或 N/A+接受人；P0 有证伪场景（按轨适用）。
- **证据**：失败/阻塞/待实现有证据或明确原因；报告数字与执行记录一致。
- **锚点**：P0 冒烟与高价值锚点本轮通过。
- **报告**：结论唯一，缺口显式列接受人。

## 5. 缺陷与变更

### 5.1 缺陷分级与提交

| 级别 | 判定 | 处置 |
| --- | --- | --- |
| S1 致命 | 主链阻断/数据不可恢复/资金安全 | 立即停轮/上报；修复后全量回归 |
| S2 严重 | 核心不可用/明显数据错误/越权 | 当轮修复；原单+影响面 |
| S3 一般 | 非核心异常/有绕过 | 排期修复；回归原单 |
| S4 轻微 | 文案/样式/体验 | 可接受/排期 |

- 提交策略：`{发现即提交 / 按批末 / 阶段末 / 收尾确认 / 仅导出}`；有平台优先平台，零重复导出；无平台才本批统一一份。
- 查重：同标题/同路径/同现象先查；证据钉断言点；PII 脱敏。
- 待实现/失败/阻塞终态与有界打通：`rules/defects/classification.md` §0.4；范围外→不适用。

### 5.2 修复与回归

- 每个修复后立即回归，不等批末：原单 + 冒烟子集 + 影响面组 + 相关锚点。
- P0/跨模块/契约/数据/权限/资金/并发，或同模块短窗口 ≥2 单 → 升级局部 module/扩大邻接。
- 结果就地更新执行记录，只留最新；缺陷复现补锚点。

### 5.3 变更

- A 澄清 / B 同范围增量：就地更新分析/计划/执行记录，不重开计划门。
- C 范围/准出/排期/缺陷策略实质变化：回计划门，更新 §0/§1/§2/§3/§4/§6。
- D 缺陷驱动：走缺陷轨；范围变化才回计划。
- 禁止口头变更、先测后补单、静默降范围。
