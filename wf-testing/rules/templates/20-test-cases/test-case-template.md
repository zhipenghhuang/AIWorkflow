# {模块/域} 执行记录（功能）

> **record_format**：`intent-v1` ｜ **类型**：功能/UI
> **定位**：执行时同步生成；用例、步骤、结果、证据、缺陷在同一个文件。
> **执行口径**：AI 以原始方案/原型/AC + `test-analysis.md` 意图/风险为准直接执行；下表步骤写清入口/操作/核对对象（字段/状态/码/提示）与预期，3～7 个短步，供第二人复核。
> **落盘**：`{workroot}/{ver}/functional/{NN}-{短名}-执行记录.md`（平铺）。
> **结果**：只认本轮构建/runId；未执行/未本轮验证不计通过率。

## 1. 场景与结果

> 一行一个场景；场景由意图展开，可正/负/边界/状态/权限/幂等/恢复。`原文/依据` 写多源：主读章节/AC + 至少一个互补源（原型路由/接口/代码/现网/历史缺陷）；写具体章节/AC/路由/接口/契约 ID，只写文档名视为未对照。执行前逐场景对照，分析只是索引。
> `步骤` 写 3～7 个短动作，每步带可核对对象：`1. 打开{入口/路由}（看{区域}）→ 2. 输入{字段=值}→ 3. 点「{按钮}」→ 4. 核对{列表/详情/Network}的{字段/状态/提示}`。通过行也带核对点，不写「打开/点了/看了」这类无判定对象的动作；失败/P0 可另起 §2 展开复现。
> `结果` 只能是：未执行 / 通过 / 失败 / 阻塞 / 待实现 / 不适用 / 未本轮验证（上轮结果不冒充本构建）。
> `证据` 填相对 `{workroot}` 的路径或可打开链接；失败/阻塞/待实现必填。
