# 文档治理（原件 · 工作区 · 权威文档库）

> 单一出处：外部输入、工作文档、权威文档库、入站分析、吸收深度、同步、归档与清理。
> 铁律：**先分析分类 → 输出候选 → 用户确认 → 才改名/移动/标记失效/归档/删除**；确认前只读。
> **三层**：`inbound/` 原件（可乱）｜`{workroot}/` 工作区（过程/草稿/待确认）｜`docs/materials/` 权威文档库（定稿/完整/可发送）。
> **单包优先**：仅本包即可闭环；缺产品/测试包 → 一句缺口，不阻塞、不强制安装、不自动跑他包。
> **工作根**：见 §2.4；非标准工作根必须在环境基线声明，不另建根文件。
> **材料库**：项目级 `docs/materials/`，不按包拆；只放定稿、正确、完整、可独立阅读的文档；可直接整包发送。

## 1. 三层

| 层 | 放什么 | 不放什么 |
| --- | --- | --- |
| **inbound/** | 全部外部/用户投放的原始输入主副本；全量登记 | 工作文档；权威文档库；`_archive/` |
| **{workroot}/** | 本包计划、需求、方案、任务、验证、发布、复盘、交接、能力、过程稿 | 外部原件主副本；已定稿的完整项目文档集 |
| **docs/materials/** | 项目权威文档库：定稿文档 + 精选外部输入 + 版本说明 + 索引 | 草稿、过程、证据、待确认、密钥、PII、inbound 全量镜像 |

- **工作区**：日常写作、评审、实施、验证都在 `{workroot}/`；允许过程稿和待确认。
- **权威文档库**：对外完整、可直接发送；正文从工作区发布，不在库内直接改。
- **原件**：只登记、按需复制、按需吸收；不迁出、不删除、不归档。

## 2. 原件、材料库、工作区

### 2.1 inbound（原件根）

```text
inbound/
├── INDEX.md                 # 全项目外部输入唯一全量登记
├── _common/                 # 跨版本输入
└── {ver|topic|batch}/       # 按版本/主题/批次
```

- 认根：项目根 `inbound/`；用户另行指定时按指定；不定 → 一问，不猜。
- 新外部输入先落 `inbound/`，再分析；不得直接放 `docs/materials/`。
- `INDEX.md` 复用 `inbound/INDEX.md`字段：`ID | 文件 | 类型 | 主题/版本 | 来源 | 关联 | 状态 | 覆盖/替代 | 登记时间`。
- 状态：`current / reference / pending / superseded`；失效只改状态，不建 `_archive/`。
- `inbound_structure=keep|mix|replace` 只约束原件结构；`replace` 只改名/移动并修引用，不删除主副本。
- 大二进制用 Git LFS 或 external 指针（路径+校验和+位置）；不使用“ignore 即主副本”的假象。

### 2.2 docs/materials（项目权威文档库）

```text
docs/materials/
├── INDEX.md                 # 总目录：版本/域/文档/来源/状态
└── {ver}/
    ├── README.md            # 本版说明：范围/包含/不包含/阅读顺序
    ├── 00-overview/
    ├── 01-requirements/
    ├── 02-design/
    ├── 03-technical/
    ├── 04-implementation/
    ├── 05-testing/
    ├── 06-release/
    └── 07-appendix/
```

- **项目级一份**，不按包拆；各包只写自己负责的域。
- **多包共享文件**：`README.md`/`INDEX.md` 由已装开发包统一刷新；无开发包由已装产品包；均无则由当前发布包。非主责包只提交本域文件与索引行，不重建他域；`06-release/` 业务文件归产品、工程文件归开发，不互相覆盖。
- 每个 `{ver}/` **自包含**；不设外挂 `_common/`；只发单版本也不缺文件。
- **不设 `_archive/`**；旧版本保留，`INDEX.md` 标 `current / superseded`。
- `README.md` 写版本、范围、包含/不包含、阅读顺序、来源、缺失/待补。
- `INDEX.md` 登记所有文件；来源列写 `IN-xxxx`、`docs/...` 或 `generated`。
- 只放**可外发**内容：无草稿、证据、密钥、真实 PII、未授权第三方文档。
- 正文不在材料库直接改；定稿后从 `{workroot}/` 发布/同步。
- **默认覆盖最新**：未明确「保留历史 / 不覆盖 / 升 rev / 另存快照」时，对目标 `{ver}/` **就地覆盖**为工作区当前定稿（README/INDEX 按 §2.2 多包主责规则刷新，`last_published_at` 同步）。
- **显式例外**：用户点名保留已外发副本、不覆盖、升 rev、另存 `{ver}-r2`、或正式签收锁定 → 才新建 `{ver}-r2`/升 rev，不覆盖旧目录。
- 材料库不是交接包；发送/交接只是它的用途，回执/台账仍走 `handoff/`。

### 2.3 吸收深度（A0～A2）

> **吸收 ≠ 迁移**。原件永远留在 `inbound/`。

| 深度 | 工作区动作 | 适用 |
| --- | --- | --- |
| **A0 引用** | 计划/索引/台账写来源路径 + 用途一句 | 查阅、非本轮范围 |
| **A1 要点吸收** | 相关范围/AC/约束写入待决/变更/任务卡；挂原件链接 | 澄清、排期、小改 |
| **A2 结构吸收** | 按模板写入/更新 `{workroot}/` 的 SSOT；`来源=IN-xxxx` | 正式基线、提测入口、定稿 |

- 默认：存量 → 仅索引；任务命中 → 至少 A0；改基线/实施入口 → A1 或 A2（不确定取低一档并问一次）。
- 禁止：把原件整文件挪进工作区冒充吸收；禁止搬空 `inbound/`。
- 工作区 SSOT 是吸收后的结论；原件用于溯源；冲突 → T8。

### 2.4 工作区（{workroot}）

- 测试工作区：
  - **常青（根）**：`INDEX.md`、`work-log.md`、`smoke-checklist.md`、`scripts/`、`capabilities/`、`handoff/`、`_archive/`
  - **迭代大夹** `{ver}/`：`test-analysis.md`、`test-plan.md`、`test-report.md`、`写回回执.md`（有写回才建；本轮覆盖）、`changes/`、`evidence/`、轨目录 `functional/` · `api/` · `exploratory/` · `random-flows/` · `pre-release/`（轨内同类记录平铺；勿一记录一空夹）
- 测试材料库写入域：`05-testing`。

- **组织轴**：版本/迭代 = `{ver}/` 大夹；模块与场次默认进文件名。轨名并列、不编号、不表示执行先后；执行顺序只认 `{ver}/test-plan.md` §0/§3。
- **建夹**：一类多份且与父夹其它文件异类 → 专夹 + 夹内平铺；轨内单份执行记录不另套模块夹。
- **工作根**：读环境基线「项目身份」的 `workroot`；未声明按约定：单包 `docs/`，多包 `docs/{owner}/`；非标准必须在基线声明，不另建根文件。`{ver}` 取基线「当前版本/主题」或 INDEX/`activeContext` 指针。
- 工作区可含过程稿、草稿、待确认、证据；正式文档只写现行有效。
- 单包为 `docs/`；多包为 `docs/testing/`。
- **工作区索引**：`{workroot}/INDEX.md`（单包即 `docs/INDEX.md`）；只做导航：当前 `{ver}`、文档清单、材料包、归档、缺失；**不写阶段/门/状态**（状态权威＝`{ver}/test-plan.md` §0）。
- **项目总览**：多包或保留原目录时用 `docs/INDEX.md`；链到各工作区索引、`docs/materials/INDEX.md`、`inbound/INDEX.md`、各包 `handoff/handoff-ledger.md` 与既有目录；不写状态、不替代工作区索引；多包各包只改本包一行。
- **共享/控制路径**：`docs/materials/`、`docs/handoff/`（单包）、`inbound/`。
- 无内容不建空目录；模板是骨架，不是强制空树。

### 2.5 接入级别（I0～I3）

> 只约束工作树；与 `inbound_structure` 分开确认。绿场默认 I3；存量/杂乱必问。

| I | 工作树 | 写入 |
| --- | --- | --- |
| I0 | 复用现场树 | 先档案映射；只写现场树+映射，禁止套标准路径 |
| I1 | 现场骨架+补标准夹 | 确认后归类 |
| I2 | 现场保留+旁挂标准责区 | 新写只进标准树；读冲突一问 |
| I3 | 标准树唯一 SSOT | 方案确认后整理 |

## 3. 入站分析 T1～T9

输出四列：`类型 | 落点 | 同步 | 归档/覆盖`。先判替代关系：T1 才归档旧基线；T2/T4 保留未被覆盖的基础设计/流程图/原型，只归档被替代的增量与旧稿。T1～T9 是处置框架，不是穷尽白名单。

| 类型 | 线索 | 落点 | 本包同步 | 归档/覆盖 |
| --- | --- | --- | --- | --- |
| T1 全量基线替代 | 整份新 PRD/需求废止旧版 | `inbound/` 主副本；A1/A2 → `{workroot}/` | 计划、索引、台账；定稿后发布 materials | 旧工作区基线可归档；inbound 不动 |
| T2 方案/设计变更 | 方案 diff、技术结论 | `inbound/`；正文吸收 → 对应轨或 `{workroot}/{ver}/changes/` | 变更记录、计划、索引 | 失去实施入口的旧方案可归档；局部就地覆盖 |
| T3 未决确认 | 拍板、澄清答复 | 结论 → `{workroot}/{ver}/changes/open-items.md`；原件留 `inbound/` | 关闭待决、冻结范围 | 过程件不堆现行区 |
| T4 迭代专项/局部 | 修改方案、单模块补丁 | `inbound/`；增量 → 方案/任务 | 影响面任务、计划 | 禁两份「最终方案」并排现行 |
| T5 范围/优先级 | 砍需求、重排期 | 计划/需求池 | 状态与范围节 | 旧通知工作区侧可归档 |
| T6 缺陷/回流 | 产品回复、修复说明 | `inbound/`；结论 → 治理/变更/缺陷评估 | 对齐需求、设计、测试 | 旧评估可归档 |
| T7 仅参考 | 无强制采纳 | 只登记 `inbound/INDEX.md` | 一般不改 SSOT | 不进工作区现行 |
| T8 冲突 | 未裁决矛盾 | `inbound/` 状态=`pending` | 停下问 | 不覆盖现行 |
| T9 交接类 | 跨角色交付/提测/签收/对方材料 | 主副本 `inbound/`；工作副本 `{workroot}/handoff/inbound/{category}/` | 打开分析 + A0～A2；台账/计划回写 | 出站快照不可改；入站非 SSOT |

- 交接类别用英文 id（`requirements/design/plan/qa/report/bug/fix/clarification/release/uat/change/retro/decision/unsorted`），口令别名见 `rules/path-aliases.md`。
- 同仓优先直读对方 `handoff/outbound/`；不重复拷贝。

## 4. 资料收取步骤

1. 识别未登记/变化文件（`inbound/INDEX.md` 优先；根散落先拟收入 `inbound/`）。
2. 读标题/目录/变更段 → 判 T1～T9 + 覆盖关系 + 建议档位（索引 / 复制 / A0～A2）。
3. 输出【入站分析】候选；确认前不改文件（新件落盘保原件除外）。
4. **确认后同批**：`inbound/` 登记 → 按需复制到对应域/工作区 → 按深度吸收 → S1/S2/S3 只归档工作区旧稿 → 更新计划/索引/activeContext；定稿内容再发布到 `docs/materials/`。
5. 中途存量：先全索引；未点名复制/吸收的保持仅索引；冲突 → T8。

> **入站硬约束**：任何外部输入（含用户直接放在根目录的 md/xlsx/图片）必须先完成第 4 步的 `inbound/` 登记，再进 `{workroot}/`；禁止先放 `10/20-…` 后补登记。已误放 → 同轮移入 `inbound/`、补索引/变更记录并修正引用，不保留双份现行稿。

**覆盖关系**：全量替代｜全量覆盖｜部分覆盖｜增量补充｜仅新增｜重复｜冲突。
**失效依据**：S1 全量替代；S2 全量覆盖；S3 重复；S4 需求删除/版本取消；S5 用户明确失效。禁按年龄归档；失效只作用于工作区与材料库副本，不删除 `inbound/` 主副本。

## 5. 工作文档与材料库发布

### 5.1 工作文档四类

| 类型 | 动作 |
| --- | --- |
| 长期/固定 | 就地更新，不随迭代整文件搬走 |
| 版本/迭代绑定 | 关闭时归档；期中失去交付入口也可归档 |
| 失效/替代 | 确认后归档；部分覆盖保留未覆盖部分 |
| 过程/临时 | 确认后删/移 `_archive/_pending-cleanup/` |

| 文档/目录 | 类型 | 处理 |
| --- | --- | --- |
| `activeContext.md`、`{workroot}/INDEX.md` | 长期 | 就地更新；本包只改本责；`docs/INDEX.md` 多包时只改本包一行 |
| `{workroot}/work-log.md` | 长期 | 追加里程碑；过长确认后移块到 `_archive/work-log/` |
| `{workroot}/smoke-checklist.md` | 长期 | 跨迭代 P0/高价值锚点；就地更新；不随版夹迁走 |
| `{workroot}/{ver}/`（分析/计划/报告/轨记录/changes/evidence） | 迭代绑定 | 确认关账后**整夹**迁入 `_archive/{yyyyMMdd}-{ver}/`；P0/高价值意图须有执行记录或 N/A+依据 |
| `{workroot}/scripts/` | 长期 | 脚本资产；不随关账删除 |
| `{workroot}/handoff/outbound/{category}/` | 出站快照 | 真源在生命周期目录；报告/计划等按需实拷；**缺陷有平台时禁止**为交单实拷详单（见 `handoff.md` §3.1.1）；关版本同批归档；台账常青 |
| `{workroot}/handoff/inbound/{category}/` | 收件工作副本 | 须分析吸收；非永久主副本；关版本可归档 |
| `{workroot}/**/.draft/` | 临时 | 清理候选 |
| `docs/materials/` | 权威文档库 | 按版本发布；不设 `_archive`；旧版本保留 |

### 5.2 发布到材料库

触发：导出项目文档 / 生成资料库 / 发资料 / 发项目文档 / 交接 / 关版本 / 点名。

1. 选版本、范围、受众；版本取项目/迭代版本，缺则问一次，不硬造。
2. **发布模式**：默认 `overwrite-latest`（就地覆盖目标 `{ver}/`）；仅用户明确「保留历史 / 不覆盖 / 升 rev / 另存快照 / 签收锁定」时用 `rev` 或 `{ver}-r2`。未说明 → 不询问、直接覆盖最新。
3. 从 `{workroot}/` 选**定稿**文档 → 对应域；从 `inbound/` 选**权威正确**外部输入 → 对应域。
4. 每个 `{ver}/` 写/刷新 `README.md`；更新 `docs/materials/INDEX.md`（含 `last_published_at`）。
5. 校验：README/INDEX、来源可解析、无草稿/证据/密钥/PII、链接自包含、单版本可直接发送。
6. 外发前按现有 `confirm_handoff` / `confirm_intent` 确认；材料库本身不设新门。
7. 正式交接：`{workroot}/handoff/` 记台账/回执；材料库作为 payload，不重复整套。

材料库内容规则：

| 域 | 放什么 |
| --- | --- |
| `00-overview` | 项目一句话、版本范围、术语、阅读顺序 |
| `01-requirements` | PRD、迭代方案、需求基线、验收标准、外部需求 |
| `02-design` | 产品设计、原型说明、UX、设计评审 |
| `03-technical` | 技术方案、选型、架构、ADR、接口/数据 |
| `04-implementation` | 实施说明、任务分解、关键配置/部署 |
| `05-testing` | 测试计划、意图/风险、报告、关键执行记录/锚点结论 |
| `06-release` | 发布说明、上线/回滚、运维交接 |
| `07-appendix` | 外部参考、标准、术语、权威附件 |

- 不按来源分 `inputs/`/`deliverables/`；来源写 `INDEX.md`。
- 每个 `{ver}/` 自包含；跨版本通用内容复制进各版本，不做外挂 `_common/`。
- `test-data/` 仅测试包按需放 `05-testing/`，默认不随完整文档集外发。
- 旧版本目录保留，不设 `_archive/`；`INDEX` 标 `current/superseded`。
- **默认覆盖最新**；仅显式要求保留历史时升 `rev` 或 `{ver}-r2`。

## 6. 更新还是归档

主档/局部 → 就地更新（覆盖终态）。T1/失去实施入口 → 确认后归档。T4 → 增量就地或专项件，禁并排双最终方案。版本关闭 → `{workroot}/{ver}/` **整夹**迁入 `_archive/{yyyyMMdd}-{ver}/`；常青仅 `smoke-checklist.md` / `scripts/` / `capabilities/` / `handoff/` 台账与根索引。正式文档只写现行有效；档案/索引等常青格不写接入·迁移·归档事件（过程进工作日志/归档清单）。

归档前做**引用检查**：被当前计划、技术设计、{workroot}/验收引用的文档不得标记失效；先修引用或保留原位。归档清单写明“替代关系/仍被谁引用”。

**材料库不归档**：旧版本目录就是历史；只改 `INDEX` 状态。默认对目标 `{ver}/` **覆盖最新定稿**；仅用户显式要求保留历史时新建 rev/`{ver}-r2`。

## 7. 版本/迭代关闭

> 迭代即版本主题。与正式发布不是两套清理标准；差别只在是否做发版对外项。

### 7.1 关账清单（按实际裁剪）

| 动作 | 换迭代（可不发版） | 正式发版/结项 |
| --- | --- | --- |
| 分析分类：长期/版本绑定/失效替代/过程临时 | 必做 | 必做 |
| 更新计划/台账/索引/activeContext | 必做（指向下一迭代） | 必做 |

### 7.2 确认结束当前迭代
