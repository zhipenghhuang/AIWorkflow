# 门面与对外事实同步（测试）

> **读取级别：参考**（事件触发时读；收尾不再强制 `facade=` 字段）。

> **定位**：根 `README.md` 与基线/档案中**对外可见句**的事件触发同步。  
> **不替代**：状态「三处同拍」（计划 §0 ↔ 导航 INDEX ↔ `activeContext`）只认 `global-rules.md` §8；事件级同步矩阵见 `execution-contract.md` §4（参考）；关账/materials 仍认 `doc-governance.md` §7。  
> **禁每轮全扫**：未命中下表触发 → 不打开、不对账根 README；日常身份短读仍只读档案/基线。  
> **写法**：轻量改已有对应句；结构大动走 `project-readme.md` 偏好确认。实例面禁写工作流包用途/装载/升级（见 `AGENTS.md` 多包·实例面）。  
> **根 CHANGELOG**：本包**不写**。

## 2. 触发矩阵（事件 × 必/可）

| 触发 | 基线/档案/总览 | 根 README | materials README | 根 CHANGELOG | 三处同拍 |

**对外可见事实（判定）**：会出现在根 README 或对外「怎么验」路径上的现行值；内部场景草稿、缺陷讨论、仅 AI 工作流路径不算。

## 2.1 冷层定点核对（矩阵「必」触发时 · 禁全扫）

命中上表对基线/README 为「必」的行时，只核**已存在**命中句（无则该项 `na`）：

1. **被测/对外版本句**（基线或 README 现行版本展示）与本轮核实版本一致。
2. **测试入口/怎么验句**（基线 §1 或 README 已有对应句）与本轮核实入口一致。
3. 其它本轮已核实且已断的对外句 → 只改该句。

预算：≤3 次定点打开。热层已更、冷层仍写旧现行值 → 不得称同步完成。未打开命中句 **不得**写 `冷层:ok`。

## 3. 执行顺序与预算

1. 先改基线/档案命中行与总览，再改根 README 对应句；禁只改 README；禁写根 CHANGELOG。  
2. 只改**本轮已变**相关句；禁止为「保险」通读全文。  
3. 无根 README 或无可改测试句 → README 项 `na`；基线命中行仍按矩阵回写。  
4. 推迟 → 收尾 `冷层:deferred:<原因>`；必触发未做且未 defer → 不得称同步完成。

## 4. 收尾表述

命中矩阵「必」：`sync=` 须含 `冷层:ok|na|deferred:<因>`（`ok`=已打开并对齐）；未命中触发 → 写「无门面变化」。有门面句改动时第 6 点一句说明。**不另造** `facade=` / `triad=` 字段。
