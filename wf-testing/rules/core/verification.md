# 验证与准出（测试轨）

> **读取级别：参考**（核对状态语义时读；门与回执以 `verify/README.md` + `gates.md` 为准）。

> **单一出处**：分析/执行记录/报告/证据/P0 的对账规则、完成状态与报告措辞。`AGENTS.md` 只留指针；`verify/README.md` 是操作入口。
> **读取时机**：计划门、执行批末、报告、handoff/交平台前。

## 2. 完成状态

| 状态 | 条件 | 报告措辞 |
| --- | --- | --- |
| `PASS` | P0 全过；本轮所有 `处置=测` 意图有终态；本轮意图无未执行；分析/执行记录/报告一致；证据可打开；无未接受缺口 | 通过/可准出 |
| `CONDITIONAL` | P0 全过；缺口非 P0；所有 `处置=测` 意图有终态或接受人；准出评估=CONDITIONAL 且用户书面接受 | 有条件通过；列遗留 |
| `FAIL` | 任一 P0 失败；P1/P2 有未测且无接受；关键证据缺失；数字不一致；覆盖矩阵/影响面/核心链路有未接受缺口 | 不通过；列失败 |
| `BLOCKED` | 环境/输入/回执缺失；无法对账 | 阻塞/未验证 |

> 中文回执映射：可准出=PASS｜有条件准出=CONDITIONAL｜不准出=FAIL｜阻塞=BLOCKED｜未验证=NOT_VERIFIED。

## 3. 对账规则

- 分析 §2 意图 ↔ 执行记录场景/意图结论：意图状态按最差态合并（失败>阻塞>待实现>未执行>通过；全 N/A=不适用）；一个意图只记一个结论。
- 场景计数只统计本轮记录；`_archive`/`.draft`/`资料` 不参与对账。
- **全意图对账**：分析中每个 `处置=测` 意图必须在执行记录出现且有终态；P1/P2 未测同样 FAIL；N/A 只认分析中有依据+接受人的行。
- `待实现`=实现缺陷，计入缺陷合计/交平台；不得当未测；范围外→不适用。
- 报告 §2.1 场景统计、§2.2 意图统计 ↔ 各执行记录汇总；不一致先修报告/记录，不得直接写准出。
- `writeback` 模式只核回执（单号/备注/状态/附件），不要求计划/记录存在。

### 3.1 依据覆盖与证据

- 报告 §0 准出评估 ↔ P0/缺口：P0 未过不得写“通过”；有条件通过必须有接受人/遗留项；须声明本轮 runId/构建与 suite/depth。
- 覆盖：分析来源盘点、章节回执、依据覆盖、AC/设计点账本、意图/风险、覆盖矩阵/方法矩阵/细节维/影响面/核心链路；P0 有 Oracle/不可接受失败；N/A 有接受人。
- 缺口：未覆盖、N/A、阻塞、待实现、环境缺口必须列接受人/复审点。
- 阻塞/失败/待实现：摘要与通道按 `classification.md` §0.4；阻塞须已尝试/恢复条件；缺数据先造/换。
- 收口：T1+ 报告须有 S6/S7/S11 着落与探索章程闭环；缺=未完成。
- 回写：单号/备注/状态/附件回执；备注与状态同轮。
- 回执归属：report 读 `.gate/wf-testing/report.json`、execute 读 `execute.json`、writeback 读 `writeback.json`。
- P0 计划覆盖：分析中 P0 意图必须在执行记录中有终态且证据可打开；缺失=FAIL。

## 4. 成本纪律

- **步后门**：域批末 `execute -Scope {域路径片段}`；缺 Scope 且无法推断 → BLOCKED。
- **准出门**：版本级 `report`——聚合各现行执行记录本轮意图/场景；忽略 `未执行`/`未本轮验证`。
- 证据失败/阻塞必看；不要求每条通过截图；不每补丁全量回归。
