# 全局规则（每步必读）

> **读取级别：每步必遵守；重读见 §7。** 心跳 `global=ok` 表示本步已按 §7 复核；偏离写 `global=dev:<原因>`；未按 §7 复核不得写 `global=ok`。
> 本文件只放“所有链、所有步骤都适用”的规则；启动路由、链/步、门、技能、模板、文档治理不在本文件重复。
> **单一出处**：改全局规则只改本文件；步骤卡只写本步边界，不复制本文件正文。

## 1. 开工判定

- **新任务**：复述目标/范围/验收；完整档确认后执行。
- **续跑**：读 `activeContext` 运行状态，从 `packet=` 继续；一行确认。
- **只读**：一句话复述后直接回答；不写、不过门、不对外。
- 未确认（完整档）禁写/改、跑改库/部署/提交、对外发送、下完成结论。
- 批量任务不豁免；逐条按同一规则。
- **开工基线（硬）**：先看工作区是否已有他人未提交改动或并行任务（`git status`、近期 mtime、`activeContext`）；有则记为本轮**基线**，不混入本轮证据、scope 或提交。同一工作区同一时间只允许一个写入批次；并行写入须文件集不相交、归属明确（见 `collaboration/subagents.md`）；发现自己的改动被覆盖/丢失 → 停，先确认来源。
- **既有约束先对账（硬）**：测试分析/计划与需求基线、验收口径、已知缺陷、环境基线冲突 → 在 plan/coverage 前按既有优先级裁决（需求基线/已接受口径优先），偏差写 N/A/接受人，不得执行后才暴露。

| 档 | 触发 | 输出 |
| --- | --- | --- |
| 完整 | 新交付/歧义/外发/高风险/范围变化 | 六段：字面要求/目标/范围/依据/验收/缺口（0～3） |
| 一行 | 计划内续跑/意图已清 | 目标 + 范围 + 下一步 |
| 免 | 纯只读 | 一句复述 |

- 理解→方案双确认只在需求/方案/计划/评审/变更等域门需要；同会话同一对象只确认一次。

## 2. 理解与澄清

- **先自主分析（硬）**：先查文档/代码/数据/页面/现网/基线；能自助打通（造数/换样/换角/换入口/对齐契约）则先做有界尝试，**禁止**一遇不明就问用户或标阻塞。
- **才问用户**：有界手段穷尽（或属 §6 必须停）仍无法裁定、且答案会改变范围/验收/不可逆动作 → 一次只问 1 个关键问题（附候选/推荐 + **已尝试** + **卡点**）；问到能继续即可。
- 不把提问当流程；不迎合；用户有误直接指出依据与风险。
- 数字/人物/结论核实来源（来源+日期）；主动提醒忽略的变量、成本、偏差和不可逆风险；禁臆造数据/反馈/竞品结论。

## 3. 判断深度（最小充分）

- 按 **决策影响 / 不可逆性 / 协调面 / 证据强度** 取最小充分深度，不默认最高档。
- 命中不可逆、对外承诺、定价/合同/合规/隐私、跨包契约、真实 PII、平台回写、发布/回滚 → 取重。
- 低风险/可逆/只读：可合并步骤、少文档、直接给结论；事实来源、未验证声明、红线不可省。
- **深度拿不准**（分析做到多深）：给推荐档 + 一句理由；只有档位改变范围/验收/是否实施时才问 1 问；不问则按推荐档执行。升档/降档写 `reason=`。禁止用「规则没写」当不做的理由。本条不用于选路径、判歧义、或决定质量条是否命中。

## 4. 动作前分析

- **实质动作** = 写/改文件、跑命令/测试、过门、改状态、外发、提交/部署、下结论。
- 可逆本地小改：一行（目标/依据/验证）。
- 写/门/外发/提交/不可逆：六字段（目标/依据/现状/方法/影响/验证）。
- 纯只读免；禁止先做后补。

## 5. 择优与执行

- 方案不适配/明显更差 → 依据 + 主推（可附 1 备选）；用户坚持 → 执行并记 `deviation=`。
- 给方案先说权衡；跑命令前确认环境与依赖；失败先析因。
- 同一方案 2 次无效换路径；连续 3 轮无新信息 → 收敛或给推荐。
- 先工具后子代理；优先直接编辑，批量/重复才写脚本。
- 最小改动；动手前说明拟改文件；改动面超预期先停。

## 6. 决策与停

- **AI 自主**：方法、结构、措辞、证据组织、未列尽产物归类。
- **必须停**：客户需求/范围/优先级/成功指标无依据；改已定稿基线；对外承诺；发布/回滚；真实 PII；平台回写；用户指令与硬门冲突。
- 用户坚持劣解 → 执行并记 `deviation=`；不静默拒绝也不盲从。

## 7. 读法与技能

- 读链：`AGENTS`（路由）→ `cold-start`（启动）→ `activeContext`（状态）→ **本文件** → `workflows/<id>.md`（进链一次）→ 当前步骤卡（每步）→ §6 技能整卡（必做 → 方法/判定 → 反模式/DoD）→ 模板按步骤卡 §7 点名（通常 1 份；成对/多份按卡内顺序读，不预防性通读）。
- **主从（硬）**：步骤卡=本步剧本/验收；技能/模板=方法与壳；本文件=跨步场规则。本步专属门槛以步骤卡为准；技能不得另造平行流程；core/defects/collaboration 等具名索引按步骤卡点名再读当前节。
- **重读（硬）**：新会话 / 换链 / 本文件或当前 packet 变更 → 全文逐条过。同链中段切步/过门/续跑 → 按节复核最小集（§1、§4、§6、§8、§9 + 本包 §12）；`reads=` 写节号；未核节不得写 `global=ok`。全文条款仍须遵守，禁止用「中段免全文」跳过硬门。**禁**把「遵守」理解成每步通读本文件/大手册；中段预防性通读=浪费且易冲突。
- **步骤卡实读（硬）**：本步**第一次实质动作前**须用工具打开 `activeContext` 的 `packet=` 路径；未打开不得写 `global=ok`、不得宣称本步已按包执行。禁凭记忆/摘要代替步骤卡。
- 同时只激活 1 个 packet；不读他步 packet、不读大手册、不跨链拼规则。
- 技能必须打开→**整卡读取**（必做 → 方法/判定 → 反模式/DoD）→回包；`references/` 仅在正文点名时再开；不得用摘要代替实读；条件未命中标 `na` + 理由。
- 无链图/无 packet → 停下按 AGENTS 重建或问用户，不凭记忆跑。
- 参考/技能/模板按命中读当前节；不重复贴长文。
- 未走 workflow 的直接动作（工作总结/维护/查询/只读）：每次进入先按本条重读本文件（只读可 `mode=analyze`）；不得凭上一轮记忆跳过。
- `reads=` 记本步打开的步骤卡路径 + 技能 + 全局规则节号。未按本条复核不得写 `global=ok`。

## 8. 状态、续跑与同步

- **续跑指针**：`activeContext` 的 workflow/state/status/packet/gate/next/updated。切步、过门、续跑只认这里。
- **阶段语义**：`testing` 链且已有 `{workroot}/{ver}/test-plan.md` 时，阶段/门/焦点/下一动作/准出口径的权威是该计划 §0；`activeContext` 是热快照，不得领先 §0。其余链、或尚无测试计划时，阶段语义在 `activeContext`。正式门未签但实质已开测/已提缺陷 → §0 写「进行中（正式门待补）」。
- 切步/过门/长会话每 3～5 轮：更新上述权威 + 一行【心跳】锚 `【锚】workflow=… | state=… | packet=… | global=ok | role=… | next=…`。**心跳≠对人汇报**。
- **对人进度（硬）**：长任务禁止闷声连跑。对人可见硬节点（通用）：①本步开始/续跑声明；②本步可验收单元收口；③卡点升外力或落入 §6 必须停；④凡须用户确认的门。每节点 2～5 行：结论 / 卡点或风险 / 下一步；「继续」不豁免；禁仅改 `activeContext`/落盘代替对人汇报。**本包映射**：可验收单元=功能批/意图批（结论计数 + 红/阻/待实现）；④含拟交缺陷平台。
- 续跑：读 `activeContext` 的 `packet=` → 打开该步继续；不从头重跑；packet 丢失用链图定位。
- 完成/阻塞/取消：`status=done|blocked|cancelled`；阻塞写卡点/已尝试/恢复条件；**升外力时同轮对人报卡点**（与上条③合一，不另造通道）。
- 任务开始/状态变化/阻塞/收尾：同轮更新续跑指针；阶段语义有变化且本链有测试计划时，同轮改计划 §0 与 §6。
- **同拍（硬）**：有计划时，收尾在第 2/6 点核对「§0 与 activeContext 热快照一致」。本轮改被测版本、焦点或下一步 → 同轮改 `activeContext` 总览/焦点/运行时**命中句**与 `### 进行中`（禁只改表、留旧版本/焦点句）。`INDEX` 只在入口文件增删、改名、归档时更新链接，不写阶段/门/状态。不另造 `triad=`/`facade=` 字段。事件级同步矩阵见 `execution-contract.md` §4（参考；不替代本条）。
- **门面冷层（硬·事件）**：命中被测版本 bump / 迭代·版本关闭 / 准出后发布衔接 / 对外可见事实变 → 按 `doc-facade-sync.md` 定点核对（有则核：版本展示句、测试入口/怎么验句）；未命中不扫。热已更、冷仍旧现行值 = 未收尾。

## 9. 证据、完成与收尾

- 证据先于结论；禁刷绿；密钥/PII 零入库。
- **证据终态制（硬）**：执行记录「证据」列与门禁只认**断言终态**叶（通过=关键绿证；失败=`字段=值` 终态 JSON 和/或钉断言点截图）。探查/重试/中间 save·repub·试连、**造数回执（响应体/ID 清单）**等过程产物写入 `{ver}/.draft/` 或 `{轨}/.draft/`，**禁止**堆进 `evidence/` 正式树冒充多证；造数结论只留执行记录「数据准备」摘要（对象+关键 ID）。正式叶宜少而准（通常每场景 1～2 个），不以叶数量代替可复核性。
- **失败当场取证（硬）**：UI/页面失败须在失败当轮钉断言面截图（可含地址栏/关键字段）；禁拖到交平台时再现网补截图/补主键（缺则回执行轨补采后再交）。
- **有完成 Claim 门**的步骤（`report` / `writeback`）：只认 `verify/Invoke-Gate.ps1 -Claim -Mode report|writeback` → `CLAIM: ALLOWED`；无 ALLOWED 不得写整体通过/准出。
- **验证封板（硬）**：执行前冻结被测构建、环境与数据版本并记录 build/runId；执行中换版本/环境/数据须标注并重跑受影响意图；`report`/`writeback` 取 Claim 后不再改执行记录/证据，确需改 → 重跑报告门并重新 Claim。
- **无完成 Claim 门**的步骤（含 `plan`/`execute` 的 coverage/execute 回执）：产出落盘且本步门已过即可，`claim=na`；不得冒用完成态措辞。
- 门失败/未运行 → 未验证/阻塞；不得用聊天结论替代。
- **写回回执落点**：`{ver}/写回回执.md`（本轮覆盖）；禁按日散落、禁另开 `defects/`、禁塞 `functional/`。门亦认存量 `functional|api|evidence` 下含 `回执`/`回写` 的 md。过程稿勿放 `.draft` 充门禁。
- 收尾六点（完成/文件/验证/假设/风险/下一步）+ 拟提交；只读 2～3 行；主动发现 ≤3（问题+依据+建议+是否阻塞）。
- 收尾自检字段：`route/mode/packet/global/skills/reads/gates/confirm/sync/skip/when_eval/deviation`；按共享 closeout 输出。

## 10. 文档纪律

- 只写现行/当前有效；删除即移除；不写历史/旧方案/变更原因/修改方案。
- 单一出处；同一规则不重复正文；模板是下限不是剧本。
- 路径/产物未列尽：按目的就近归位（控制面/主档/过程/归档/`inbound`）；收尾 `deviation=` 一句。
- 不把规则/方案写进正式资产；不描述不存在的文档。

## 11. 冲突与例外

- 用户当轮明确指令 > 根 AGENTS > 本包全局规则 > agent/profile。
- 多文档同题冲突（计划/模板/步骤卡/参考层/报告/基线）：按 `rules/core/conflict-matrix.md` 判；只在起因文件改真值，引用处不复制阈值。
- 包入口、开局卡、执行契约、文档质量里的覆盖顺序只认本节，那些文件只留指针。
- 与硬门冲突先说明风险，由用户二选一；不静默拒绝也不盲从。
- **跳过只认条件求值（硬）**：`when` / `gate_when` 为假才可自动跳过，`when_eval=` 须写可核事实与出处；求值不确定按真。手工跳过步/门须用户当轮明确同意（`skip=user:<理由>`）；`skip` / `na` / `deviation` 不得绕开 hitl、Claim、证据或红线。
- 降档仅在用户明确要求时，记 `deviation=`。

## 12. 本包差异

- 完成门：`verify/Invoke-Gate.ps1 -Claim -Mode report|writeback` → `CLAIM: ALLOWED`。
- 领域红线：P0 未过或任一 `处置=测` 意图未终态，不得整体通过；UI 证据 E1 实点+截图/Network；缺陷平台回写须确认；交「未交付/列表空/入口不存在」前须 `入口指纹`+误用已排除（`classification` §0.4 / `collaboration` §5.0.1c），写口须回查字段（禁只认 200）。
- 覆盖红线：只认 `multi-track-quality` 文首与 Q0–Q19（含 Q18 关账认正文、Q19 接受人纪律）；计划含接口轨时功能内嵌 API ≠ 接口完成（`tracks/api`）；无**用户确认**的顺延/N/A≠已覆盖；AI 自填接受人无效。
- 执行三步序（硬）：① **方案原文** → ② **结合分析理解**（索引；非入口）→ ③ **现场执行择优**（实现≠方案按 `rules/defects/classification.md` §0.5）。细则见当前 execute 步骤卡与 §6 执行技能。
