# 执行契约（测试轨）

> **读取级别：参考**（维护 / 写 workflow / 查事件级同步矩阵时读）。
> **运行时硬规则**：开工、动作前分析、三处同拍、心跳、执行原文对照 → 只认 `global-rules.md`；**禁止**用本文替代每步必读规则。

> **定位**：把「按计划执行」变成「按风险 + 证据 + oracle 判断」。规则是下限，不是百科全书；未覆盖时允许合理自主，但必须留痕。
> **冲突与覆盖**：顺序只认 `global-rules.md` §11。拟改与现行实现、现网或 CI 稳定口径冲突时，先指出依据与影响再改，禁止静默覆盖。
> **读取时机**：写/改 workflow 读 §3；查事件级同步明细读 §4；收尾机读字段细则读 §6；开工/动作前只认 `global-rules.md` §1/§4；本文 §1.0 仅指针。

## 1.0 开工与动作前分析（指针）

> **runtime SSOT**：只认 `global-rules.md` §1（开工档位 / 【需求与意图理解】）与 §4（【动作前分析】）。  
> 本文不复写六段/分级表；维护对照时改 `global-rules.md`，勿在此另立硬条文。  
> 与 `confirm_intent`（`clarification.md` §0）分工：开工门=`confirm_task_intent`；`confirm_intent` 仅歧义细化，不替代开工门。

## 1. 判断模式（先判后做）

| 模式 | 条件 | 行为 |
| --- | --- | --- |
| `execute` | 计划/范围/环境/oracle 清楚，事实可查 | 按 §5/§6 执行到批次/门；不再问 |
| `analyze`/`plan` | 依据不足但可查（PRD/原型/接口/代码/现网） | 先建来源盘点/意图台账/风险清单，给「理解 + 建议 + 0～1 问」 |
| `stop` | 范围/环境/数据/安全/准出结论，且查不到 | 停下问 1 个关键问题；同时给默认建议与影响 |

> `execute` 的前提是 `global-rules.md` §1 已确认（`intent=confirmed`）；未确认不得以“目标清楚”直接执行。

- **禁止为流程而流程**：低价值步骤可合并；`output`/`gate`/证据/红线默认不可省；跳过只认 `global-rules.md` §11（条件求值 / 用户同意）并记 `skip=`/`when_eval=`。
- **模板是下限不是剧本**：收尾/表单按通用占位填**本项目事实**；禁照抄示例；未列尽字段按目标+证据补全并留痕。
- **禁止为自主而自主**：不得自行改范围/准出标准/优先级/P0/缺陷严重度/通过结论（用户按冲突与覆盖明确选择除外）。
- **规则缺口**：按「最近规则 + 计划 + 事实」处理；产物/路径/例外未列尽 → §1.3；收尾 `deviation=` 按实际情况如实记录取舍。
- **失败纪律**：同一方案无效 2 次换手段；blocked 四问未过不写 blocked；连续 3 轮无新信息收敛。
- **方案择优**：发现用户方案不适配项目或明显更差 → 先说明依据与影响 + 主推（可附 1 备选），再确认或按覆盖继续；禁止静默执行劣解。低风险措辞差异不抬杠。

## 1.1 最小充分（自适应深度）

不按“场景清单”选流程，按四个维度判断：

| 维度 | 问什么 | 取轻 | 取重 |
| --- | --- | --- | --- |
| 决策影响 | 结论会影响准出、缺陷处置、发布、多人协作吗？ | 不影响 | 影响 |
| 不可逆性 | 做错后能否低成本回退？ | 可逆 | 不可逆/高代价 |
| 协调面 | 需要几个角色/包/环境/外部确认？ | 单点/单包 | 跨角色/跨包/外部 |
| 证据强度 | 结论用于解释/草稿，还是准出/对外承诺/平台回写/审计？ | 解释/建议/草稿 | 准出/承诺/回写/审计 |

- 默认取“能支撑当前决策的最小深度”，不是默认最高档。
- 命中任一取重：不可逆、准出、生产/未授权环境、真实 PII、跨包契约、平台回写、缺陷严重度争议。
- 低风险/只读/可逆：允许合并步骤、减少文档、直接给结论；事实来源、未验证声明、红线不可省。
- **深度拿不准**：只认 `global-rules.md` §3（推荐档 + 一句理由；改变范围/准出/是否执行才问）。本文件不另立深度标准。

## 1.2 只读分析（解释/对比/诊断/复盘）

触发：用户要理解测试结果、覆盖、缺陷、质量趋势、方案取舍；不要求改意图/执行/交平台/出准出结论。

- 不进入测试链，不写计划/台账/报告；仅允许按 `rules/core/context-memory.md` 记录用户明确偏好/要求与工作记忆（一句话回执），不更新任务状态。
- 先定范围与来源；事实、推断、未知分开；引用台账/证据/文档；不把只读分析说成“已执行/已准出”。
- 输出深度由问题决定：默认 3～5 段；用户要“详细/全面/对比”时展开，不受只读简报 2～3 行限制。
- 发现需要执行/准出/交平台时，停下来给“下一步入口 + 影响”，不擅自转执行。
- 结论只对“本轮读到的材料”负责；未执行/未跑门要明说。

## 1.3 未列尽归类（规则缺口择优）

> 规则不枚举全部产物、路径与例外。**未写明 ≠ 可随意堆放，也 ≠ 停工等新规则**；按目的归类就近落位，禁为补漏加百科条目。

1. **先定角色**（择一主角色）：控制面（计划 / 意图台账 / 锚点清单）｜执行记录/域常青｜轮次·阶段件｜过程（`.draft/`）｜归档。
2. **就近归位**：并入已有 SSOT 或工作流约定目录；能改正文就不新建同题文件；能写进计划/台账行就不另起全局总览。
3. **禁方便堆**：不得因「规则没写路径」把控制面/轮次件塞进轨根或域夹根；不得把仍有效主档丢进 `_archive`；不得另造替代分析/计划 §2/§3 / 域 §1 / `00-专项索引` 的全库索引。
4. **留痕档**：路径非显而易见或与习惯不同 → 收尾 `deviation=` 写「归类=角色→路径」一句；改角色边界/准出/证据形态仍须先说明再确认（§2 必须停）。

## 2. 自主边界

**可自主**：探查顺序、场景设计技法、脚本/浏览器选择、拆分/划批、数据造法、证据组织、是否派子代理、**未列尽产物按 §1.3 归类落盘**（模板是下限）。

**必须停（首轮）**：意图含糊/外发交接未对齐却拟落盘（澄清 §0.1）；范围/准出/环境/账号/数据变化；P0 失败；安全/隐私/生产风险；缺陷提交/回写；产品判定回流；准出结论；用户指令与规则冲突（先说明再等选择）。用户按冲突与覆盖再次明确选择后，按用户选择继续。

**必须记录**：假设与验证方式、oracle 来源、未测/阻塞原因、跳过步骤及理由、影响面。

## 3. 步骤契约

产出型/决策型 step 至少具备：

| 字段 | 含义 | 缺失处理 |
| --- | --- | --- |
| `agent` | 唯一执行角色 | 必填 |
| `input`（notes 首段或 `reads`） | 读什么 | 必填（可写「无」） |
| `skills`（notes 中路径） | 方法：skills/rules/模板 | 产出型必填 |
| `output` | 落盘路径/形态 | 产出型必填；内部步用 `internal: true` + `reason` |
| `verify` / `gate` | 门/检查/证据 | 产出型必填；无机器门用 `gate_type: checklist` |
| `precondition` | 进入本步前必须已成立的前置状态 | 关键步必填（可写「无」）；不通过 → `on_fail` |
| `on_fail` | 失败回退/阻塞 | 关键产出/决策步必填（可写「回上一步/停下问」） |
| `escalate_to` | 升级对象 | 影响范围/风险时必填 |

- `gate_type: machine` 才可声称「机器过门」；`checklist` 必须给检查方法/证据。
- `chain: full` 终点必须有 `output` + 可核验终点（`verify`、`gate` 或收尾骨架 §2）；空终点不得标 full。
- `next` 只用于有意短链（如 report→handoff），不得用来绕过门。
- 禁止新增「只写 gate、无检查方法」的空门。
- **适用范围**：关键产出/决策步（影响门、交付、外部承诺、基线、发布/回滚/回写）必须齐；纯内部转换/只读步可用 notes 说明，不强制补空 `gate`/`on_fail`。高风险的实施、发布、回滚、回写步不可省 `on_fail`。

## 4. 计划同步（同轮）

| 事件 | 最小同步集 |
| --- | --- |
| 任务开始/状态变化/阻塞/收尾 | **开工先读**：`activeContext` 总览 + 本包 `### 进行中`（含运行状态）+ 本包 `### 生效中的偏好`（项目/包，≤3 行）+ 身份短读（同仓档案 §1 优先，否则基线「项目身份」+§1 要点+§2.1 目录行，见 `AGENTS.md` §0）。回写：`### 进行中`（任务 ID/状态/最后动作/未提交文件/下一步口令/待确认/运行状态）；只读分析除外（§1.2）。**若本轮使阶段/门/轮次/批次/焦点/下一动作/准出口径语义变化** → 另加测试计划 §0（及 §2/§3/§5/§6 必要行）；报告已建则同步报告准出摘要行；`INDEX` 仅入口文件增删/改名/归档时改 |
| 用户偏好/要求 | 本包 `### 生效中的偏好` 1 行 + 一句话回执；影响当前任务则同步进行中/计划；范围/期限/强度与升级见 `rules/core/context-memory.md` §3；与门/红线冲突先说明 |
| 任务收尾/复盘/计划关闭 | 按 `rules/core/context-memory.md` §4 五问评估：记 1 行 / 升级 / 不记；`待归位` 清零；【任务收尾】写「工作记忆」行 |
| 新需求/变更 | 测试计划 §0/§2/§5/§6 + 变更记录 + {workroot}/INDEX.md + `activeContext.md` |
| 范围/准出/环境 | §0/§2/§3/§5/§6/§7 + handoff-ledger.md |
| 进度/阻塞 | §0/§5/§6 + 导航层 + `activeContext.md` + 执行记录 + 工作日志（里程碑） |
| 缺陷 | 执行记录 + 计划 §5 + 测试报告 §3 + 平台回写回执 + **测试计划 §0（阶段/焦点变时）+ 导航层 + `activeContext.md`** |
| 交接 | handoff-ledger.md + §0/§6 + {workroot}/INDEX.md + `activeContext.md` |
| 报告/准出 | §0/§5/§6 + 测试报告 + `activeContext.md` + 工作日志（可供发版核对；不写根 CHANGELOG）+ **门面同步**（按需，见 `doc-facade-sync.md`） |
| 版本关闭 | `doc-governance.md` §7 + `{ver}/` 整夹归档 + 资料归档 + 报告快照（≠ 根发版史）+ **门面同步**（`doc-facade-sync.md`） |
| 版本 bump / 迭代关闭 / 对外可见事实变 | 最小集见上表相关行；**另**按 `rules/core/doc-facade-sync.md`（轻量对应句；禁全扫 README） |

**规则**：

0. **只读 / 最小充分档**不强制触达上表全量计划矩阵；只同步当前决策所需最小集。**仅当阶段/门/焦点/下一动作/准出口径语义未变**时，可只更 `activeContext`「进行中」或口头结论；语义已变却只改热层 = 违规。
1. 先列「受影响文档清单」，改完逐项标 `已更新/不适用/待补`；未标不得收尾。
2. 计划是控制面：任何「下一步」必须能从 §0/§5/§6 读出；读不出先修计划。
3. **单包**只改本包；**多包**只改本包分节 + 跨包同步一行；共用原件根 `inbound/`；不自动跑他包。
4. 变更 C2/C3：先重基线再实施；禁止拆成 C0/C1 绕过。
5. 收尾对比「计划下一步 vs 实际下一步」，不一致先修。
6. **进行中=跨会话快照**：任务开始、状态变化、阻塞、收尾前必须更新本包 `### 进行中`；不能只在收尾写。收尾时状态=已完成/待确认/阻塞，未提交文件写实际，下一步口令写下一条。**总览**须保持项目一句话定位（已接入禁止长期「无」）；与档案/基线身份冲突以档案（或基线「项目身份」）为准并同轮改总览。被测版本 / 焦点 / 下一步已变 → 同轮改总览·焦点·运行时命中句，**禁**只改 `### 进行中` 表。
7. **状态与导航（硬）**：只认 `global-rules.md` §8。续跑指针＝`activeContext`；`testing` 链且已有测试计划时阶段语义＝计划 §0，其余链/无计划＝`activeContext`。`INDEX` 只在入口文件增删/改名/归档时改链接，不搬阶段/门/状态。阶段语义变化 → 同轮改计划 §0 + `activeContext`（有计划时）；勿为切步改 INDEX。
8. **项目身份短读**：每新会话开工一次（见 `AGENTS.md` §0）；同会话文件未变不重读；日常优先身份短读，不预防性通读根 README。
9. **资料不足升级（硬）**：身份/基线空壳、占位、登录或设计输入不可用、与现网冲突、或缺支撑本任务的关键事实 → 入口判定 §5：有 README 则按实际结构择要，不够则探查仓库实情 → **同轮必回写**基线/`activeContext`（真源）→ 有缺口则按 `doc-facade-sync.md` 补已核实句 → 收尾【资料补强】。死守空资料继续执行=违规；升级读取计入 `reads=`。
10. **门面同步（硬·事件触发）**：被测版本 bump、迭代/版本关闭、准出后发布衔接、或本轮核实的对外可见事实变化 → 只认 `rules/core/doc-facade-sync.md`（含 §2.1 冷层定点：版本句、测试入口/怎么验句；≤3 次打开；禁全扫）。未命中不扫 README。命中必触发时 `sync=` 须含 `冷层:ok|na|deferred:<因>`；有门面句改动时第 6 点一句说明。**不另造** `facade=` 字段。

## 5. 时间 / Token 纪律

- 核心必读 ≤3～4（`global-rules.md`（每步）+ 当前步骤卡 + 当前 agent/当前关键产物）；开工另计身份短读（通常很小）；资料不足升级另计有界探查（仍守总量）；方法层按命中才读；单步增量目标 ≤8k（不含每步 `global-rules`）；复杂步可至 5 并在收尾 `reads=` 说明。
- 同一步内同一文件不重读；`global-rules.md` 按 §7 每步重读；其余 delta-only；大文件只读当前节。
- 不预防性通读rules/skills/模板；不复制正文；用路径引用。
- 超预算：只读当前节 + 收尾说明，**不得**为省预算跳过门/证据/红线。

## 6. 遵守自检（收尾必写）

```text
【遵守自检】route=workflow:step | mode=execute/analyze/stop | packet=rules/packets/<wf>/<step>.md | skills=name=done|na,... | reads=... | gates=... | confirm=gate=approved@yyyy-MM-dd HH:mm,...|无 | sync=... | skip=... | deviation=...
```

- `packet` 必须是本轮实际步骤包；`skills` 列必开/条件开技能结果；`confirm` 列本轮确认门 `gate=结论@时间`（无则写无）。
- `route` 必须是实际执行入口；`reads` 列实际读过的文件；`gates` 列门 id/结果；`sync` 列已更新的计划/索引/台账（或 `无`/`na`）；命中门面必触发时还须含 `冷层:ok|na|deferred:<因>`；`skip` 列跳过步骤 + 理由；`deviation` 按实际情况如实记录取舍（无则写无）。
- 缺此项 = 未完成收尾；不得只写「已完成」。

## 7. 规则心跳（中段重锚）

- 格式/触发/与 §8 关系：**只认** `rules/core/global-rules.md §8`。
- **切 step/轨、过门前后：必做**一行【规则心跳】；长会话约 5～8 轮同一步时**可选**。运行状态刷新时同轮写回 `activeContext` 进行中。
- 心跳只重锚身份与当前步约束，**禁止**借此通读全书、跨轨契约或全本 `AGENTS.md` §0。
