# 入口判定（无显式口令时）

> 定位：任意自然语言 → 选最小可用 workflow/step。靠「信号抽取 + 意图类 + 计划状态」判定。
> 读取时机：`AGENTS.md` §2 未命中、口令模糊、或用户用描述句提出任务时。
> 边界：本包不改业务代码；缺陷走 `defect`；修代码属开发包。

## 0. 原则

1. 看意图与对象，不抠关键词。
2. **分析必做**：有 PRD/方案/原型要测时，先分析来源/AC/设计点/意图/风险，再写计划；分析未确认不执行。
3. 有计划先续跑：「继续/按计划执行」优先计划 §0，不另起链。
4. 能脚本不 AI、能轻量不完整；补丁口语不要默认版本级全量。
5. 首条可纠正：`reason=` 写清依据。
6. 示例不是白名单；同义表述按五元组路由，不得拒做。
7. 复合意图：先识别当前决策点，选最小入口；其余写入 `next_action`。
8. A～L 是判定框架，不是穷尽清单；新说法落到最近类。

## 1. 每条消息先抽五元组

| 轴 | 问什么 | 取值示例 |
| --- | --- | --- |
| 动作 | 分析、定计划、执行、报告、缺陷、治理？ | plan / execute / report / defect / govern |
| 对象 | 需求依据 / 分析 / 计划 / 执行记录 / 报告 / 缺陷 / 交接 | … |
| 结果 | 结束时交付什么 | 分析+计划 / 执行记录 / 准出 / 平台提交 / 交接 |
| 连续 | 新开、续跑、回归、纠正？ | new / resume / regress / correct |
| 体量 | 补丁/模块/版本/高风险？哪条轨？ | 不选级别；只有补丁/单模块且不承担版本准出才轻量 |

**快速启发**：

- 附件=需求文档 + 要测/计划/准出 → `testing.plan`（分析+计划同一步）。
- 已有 `test-plan.md` + 继续/执行语义 → 按 §0 续跑。
- 失败证据要入库/查重 → `defect`。
- 「再跑一遍/回归」→ 按计划重跑；平台单回归走 `defect`。
- 性能/安全/兼容/探索/接口 → 定轨，仍落 `testing.execute`。

## 2. 意图类 → workflow

| 意图类 | 判定要点 | 入口 |
| --- | --- | --- |
| A 分析+计划 | 要版本/轻量计划、范围、准出、轨道、期中变更 | `testing.plan`（内部先分析） |
| B 执行 | 跑测/冒烟/专题/按计划执行 | `testing.execute` |
| C 回归重测 | 对已有意图/场景再测 | `testing.execute`；平台指派回归 → `defect` |
| D 报告 | 出报告/准出/能否发 | `testing.report` |
| E 缺陷协作 | 查重、交平台、补充澄清、巡检 | `defect` |
| F 状态只读 | 测到哪了、下一步、计划状态 | `testing.status` |
| G 协作交接 | 发包/收包/变更通知/重规划 | `handoff` |
| H 仓库治理 | 接入、基线、资料、清理、技能体检 | `onboard` / `skill-audit` |
| I 解释/咨询 | 理解结果/覆盖/缺陷/质量趋势/方案取舍 | 只读分析；不套 workflow |

> A～L 不可跨包直译；复合意图只取当前决策点。

## 3. 计划与级别修正

1. 项目身份「流程偏好」覆盖启发式；未填按事实推断。
2. 有计划且 §0 可路由 + 继续/执行 → 优先计划驱动。
3. 无计划：仅 T0 或补丁且 `版本准出=否` 允许同轮轻量分析+计划；T1（本轮出准出结论）与 T2/T3/发布列车必须完整分析+计划（可同会话）。
4. 轨选择：用户点名或对象暗示 → 对应轨契约；未点名默认功能轨。
5. 随机业务流程 = 计划外独立轨，不进计划/准出。
6. 无基线/未接入 → 先摸底；只读分析可不阻塞。

## 4. 置信度与一问

| 情况 | 做法 |
| --- | --- |
| 唯一意图类 | 直接路由 + `reason=` |
| 只差轻量/完整计划 | 拿不准选完整；仅 T0/补丁且明确不承担准出才轻量 |
| 影响准出范围/是否交平台/是否全量 | 一问 + 推荐 |
| 像修代码而非测试 | 说明边界，推荐开发包或只记缺陷 |
| 缺环境/账号且要执行 | 门2；关键事实一问 |
| 连续 3 轮无新信息 | 按推荐或缩到 P0 冒烟 |

## 5. 首条格式

```text
route=workflow:<id> | step=<id> | role=<agent> | mode=… | reason=<意图类+信号> | next_action=…
```

- 纯只读分析可写 `route=readonly:analysis | step=explain | mode=analyze | reason=…`。
- 可附 `intent=`、`level=T0-T3`、`track=`、`input=`。
- 不跳过分析、P0 准出、证据；交平台仍门3。

## 6. 反模式

- 口令同义词表字符串匹配，未命中就拒绝或硬套。
- 未分析就写计划/执行/改预期迁就现网。
- 有计划却无视 §0 另起执行。
- 无计划宣称准出或「按计划执行」。
- 把修代码当本包职责。
- 加隐藏门或跳过分析/计划门/报告门/技能；`reason` 缺失。
