# 冲突与优先级（测试轨）

> **定位**：只解决「同一件事在多处出现时以谁为准」；不重复规则正文，不新增门槛。
> **读法**：命中冲突时打开本节；未命中不读。

| 冲突面 | 以谁为准 | 说明 |
| --- | --- | --- |
| 计划 §3.1 批次形态 ↔ 子代理档位 | 阈值 = `collaboration/subagents.md` §2；批次 = 计划 §3.1（须落在阈值内） | 冲突时隔离/写域红线优先，回退并记 `plan_batch_conflict` |
| 计划「全部」↔ 逐条意图范围 | 逐条或区间（`INT-X-01~09`）；「全部」须附覆盖清单 | 闸按展开后集合校验 |
| 步骤卡 ↔ 技能 | 步骤卡 = 本步门槛/产出/门；技能 = 方法 | 技能不得另造平行流程 |
| 步骤卡 ↔ `global-rules` | 本步专属门槛以步骤卡为准；跨步场规则以 `global-rules` 为准 | 无覆盖关系，各司其职 |
| 模板 ↔ 步骤卡 | 步骤卡定必填节；模板只是壳 | 模板不得减少门槛 |
| 参考层（`workflow.md`/`special/`）↔ 步骤卡 | 步骤卡 | 参考层不作执行依据，运行时不拼流程 |
| 报告 ↔ 计划/分析 | 报告引用分析与计划计数 | 不一致 = 报告门 FAIL，不得自造口径 |
| 能力降级 ↔ 准出 | 降级须用户确认；发版口径下安全/容量门槛须可测或书面接受 | 见 `special/multi-track-quality.md` §2.3/§3 |
| 实例基线 ↔ 计划 §2.2 | 基线为环境/账号真值；差异写计划 §2.2 并核验 | 不得在计划里另建一套环境真值 |
