# 工作记忆沉淀（偏好 / 洞见 / 易踩坑）

> **定位**：`activeContext.md` 的热记忆只存「跨会话仍有用、尚未被档案 / 根 AGENTS / 决策记录承载」的条目；本文是捕获、读取、升级、清理的单一出处。
> **不替代**：状态（计划 §0）、项目事实（档案 / 基线）、决策（decisions / ADR）、里程碑（work-log）、规则（根 AGENTS / 包规则）。
> **读取时机**：开工短读（项目 / 包范围偏好）；收尾、复盘、计划关闭时按 §4 做沉淀判断。
> **防过拟合**：只写判断维度与证据，不写通用最佳实践；判断沿用 `execution-contract.md` §1.1 与 `rule-governance.md` §2.1。

## 1. 三类条目与边界

| 类型 | 判据（满足其一） | 示例 | 不记 |
| --- | --- | --- | --- |
| 偏好 | 用户明确要求；或多次选择同一做法；影响默认入口 / 产出形态 / 协作方式 | 「提测前先跑 smoke」「README 用 B 档」 | 一次性任务指令；门 / 红线；档案已承载的流程档位 |
| 洞见 | 从实际执行（探查 / 失败 / 验证 / 缺陷 / 测试）得出，能改变下次判断，且非显然 | 「该仓路由集中在一个文件，新增页先查它」 | 通用最佳实践；代码里一眼可见的事实；未验证推断（标「推断」） |
| 易踩坑 | 可复现的环境 / 工具 / 流程陷阱，已造成返工或阻塞 | 「Node 18 构建 OOM，用 Node 20」 | 一次性偶发；已进档案对应节的重复条目 |

不记：状态 / 进度、需求正文、长文、秘密、账号、决策（→decisions / ADR）、项目事实（→档案）、通用建议。

## 2. 谁来记（用户 + AI 自主）

- **用户明确偏好 / 要求**：同轮记 1 行 + 一句回执（“已记：…（范围 / 期限）”）；与门 / 红线冲突 → 先说明风险，不静默记成有效规则。
- **AI 自主沉淀（硬）**：收尾、复盘、计划关闭 / 迭代切换、发布后、用户纠正后，按 §4 五问评估；有证据且满足判据 → 记；否则写「无」。**禁止**为凑数编洞见、把示例当规则、把推断写成用户确认。
- **置信分级**：用户明确=确认；从证据归纳=推断；影响范围 / 验收 / 对外承诺时先问一次，不静默升格。
- **即时捕获**：执行中发现符合判据的结论 / 坑（不必等收尾），可当轮记 1 行并回执；收尾只做归位 / 清理。
- **频次**：每个任务默认 ≤1 条新增；同一事实只留一处；已有档案承载的只留指针或不记。

## 3. 记到哪（范围 / 期限 / 升级）

| 范围 | 落点 | 期限 | 升级 |
| --- | --- | --- | --- |
| 本轮任务 | `进行中` 的下一步口令或任务备注 | 本轮 | 不升级 |
| 当前计划 / 版本 | 本包 `生效中的偏好` `[计划:{版本}]`；必要时同步计划 §0 / §8 | 计划关闭 | 关闭时删或并入档案 / 决策 |
| 本包长期 | 本包 `生效中的偏好` `[包]` | 长期 | 跨会话默认读取；再扩大则升级根 AGENTS |
| 项目 / 跨包 | 根 `AGENTS.md`（用户确认后写正文）；`activeContext` 只留指针 | 长期 | — |
| 流程档位 | 档案 §1 `流程偏好`（开发 / 产品）或基线「项目身份」（测试） | 长期 | — |
| 技术坑 / 事实 | 档案对应节（开发 §2 已知坑；产品 §3；测试基线对应节） | 长期 | — |
| 决策 / 口径 | `{workroot}/00-governance/decisions.md`、ADR、计划 §8 | 长期 | — |

> 能在档案 / 根 AGENTS 承载的，不留在 `activeContext`；它只留「热缓存 + 收件箱」。

## 4. 何时评估（AI 自主，五问）

触发（任一）：任务收尾；复盘；计划关闭 / 换代；发布后；用户纠正 / 同一问题第二次出现；资料不足升级回写。

1. 这次实际发生了什么？（证据：diff / 日志 / 门 / 测试 / 缺陷 / 用户原话）
2. 下次同类任务会不会因此改变判断或做法？
3. 是否已被档案 / 根 AGENTS / 决策记录承载？
4. 适用范围与期限是什么（任务 / 计划 / 包 / 项目）？
5. 该记 1 行、升级，还是不记？

判定：五问有明确答案且有证据 → 记 1 行；属于长期 / 跨包 → 提议升级（用户确认）；证据不足或只影响本轮 → 不记。无新增写「无」。

## 5. 写法（1 行 1 条）

格式：`[类型|范围|期限|强度] 内容（来源 / 日期）`

- `[偏好|项目|长期|硬] 提交信息用中文主题+范围（用户 2026-11-04；已升级根 AGENTS，本条仅指针）`
- `[偏好|计划:v2.3|至关闭|软] 提测前先跑 smoke（用户 2026-11-04）`
- `[洞见|包|长期] 新增页面先查 src/routes/index.ts（2026-11 探查）`
- `[坑|项目|长期] pnpm build 在 Node 18 OOM，用 Node 20（构建失败证据）`

写法：≤1 行 / ≤60 字；先结论后依据；不抄长文、不写过程、不重复；过期 / 已升级即删；硬偏好只留指针，正文进根 AGENTS。

- **强度**：`硬`=用户明确要求、需长期执行（最终应升级根 AGENTS）；`软`=默认取向，可被本轮明确指令覆盖。
- **待归位**：暂未决定升级去向的条目标 `待归位`；收尾 / 复盘时升级或删除，不留悬空。

**示例（非穷尽）**：

```text
用户：这个计划里提测前必须先跑 smoke。
AI：已记 [偏好|计划:v2.3|至关闭|硬] 提测前先跑 smoke（用户 2026-11-04）；要长期生效可升级根 AGENTS。

收尾：同一构建坑第二次出现，且上次已造成返工。
AI：记 [坑|项目|长期] pnpm build 在 Node 18 OOM，用 Node 20（两次构建失败证据）；档案 §2 已有则只留指针。
```

## 6. 读取与权威

- **开工读**：`activeContext` 总览 + 本包 `进行中` + 本包 `生效中的偏好` 中范围=项目 / 包（≤3 行）；命中当前计划 / 任务时再加对应行。
- **权威顺序**：用户本轮明确指令 > 根 `AGENTS.md` > 档案 §1 / §7 > `activeContext` 偏好（仅默认取向 / 免问） > 包默认。硬偏好仍不越门 / 红线，除非用户再次明确确认。
- **冲突**：偏好与现行规则 / 代码 / CI 冲突 → 先指出依据与影响再改；不得静默覆盖（同 `AGENTS.md` §0 第 5 条）。
- **兼容读取**：实例仍用合并节 `### 洞见 / 偏好 / 易踩坑` 时按同义读取；下一次写入 / 接入按 §3 拆分归位。

## 7. 清理与容量

- 每包 `生效中的偏好` ≤5 条、`洞见与易踩坑` ≤3 条；超了先删旧 / 升级再写新。
- 收尾 / 复盘把带 `待归位` 的条目清零：升级或删除，不留悬空。
- 计划关闭 / 换代：删该计划范围条目；长期条目保留或升级。
- 期限到、被替代、已升级 → 删；不写「已废弃 / 旧方案」。
