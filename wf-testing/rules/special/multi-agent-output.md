## 1. 执行形态与角色（功能/探索式轨）

### 1.1 执行形态四档

| 档 | 适用（按 §1.5 决策树；用户可点名强制） | 形态 | 落盘 |
| --- | --- | --- | --- |
| **脚本档** | 清单=已脚本化 + **功能稳定主链路/回归** + 接口确定性用例（`rules/special/script-execution.md` §1） | `node {workroot}/scripts/executor.mjs --plan=… [--tag=smoke|regression] [--suite=…]` 确定性回放；失败项升级 AI 复核 | 执行器 jsonl ＋ 证据（同拆分档格式） |
| **直跑档** | 「继续」单模块装填；单模块小批（≈≤20 条）；探索小场；宿主无子代理 | 编排本会话直接执行＋批末自查；不派子代理 | **直写本模块执行记录**（逐条）＋证据；无 jsonl |
| **模块子代理档** | 同轮多模块（阈值唯一出处：`collaboration/subagents.md` §2） | **一模块一子代理**（`subagents.md` §0：**新开**独占上下文）；模块内执行＋批末自查；编排核验后下一模块（默认再新开）。主收益=**上下文卸载**，墙钟其次 | 同上（各子代理只写本模块） |
| **拆分档** | 单模块 ≈>20 条 / 多批 / P0/长链、写密集/ 需隔离核验 / 用户点名 | Worker（jsonl → DraftPath）→ 同回合 **fresh** Reviewer（禁 resume Worker）→ 编排合并（批流见 §2） | jsonl ＋ 执行记录 |

- **取档**：默认按 §1.5 决策树；**禁**用「派工前 3 问」把已达阈值的多模块开跑压成直跑。**禁**对已脚本化用例用 MCP 逐条重跑（`rules/special/script-execution.md` §3）。
- **择优**：用户点名优先；未点名时默认按 §1.5 决策树，AI 可依项目实际、宿主能力、共享资源与净收益调整，须在开跑声明写理由；禁为省事压成直跑，也禁为并行而并行。
- **开跑声明（不可省）**：execute 出示 suite 时多一行：`exec_mode=脚本|直跑|模块子代理|拆分` + 决策树一句；并行则 `pg=PG-xx`，否则 `pg=na`；收尾【遵守自检】须带回执（execute 包见 `check_compliance`）。
- 探索式：小批（≈≤10 条或单场）直跑；多场同轮或单场大步骤 → 拆分/分场子代理。接口轨 **单 Agent**（见轨契约）。**计划驱动跨轨**按计划 §3/§4 阶段 + §3 批次取轨，阶段内仍按本表（§4）。
- **自查清单**（模块档/直跑档共用，＝ Reviewer 核心项）：`result` 合法 ｜ 失败人可复现 ｜ 证据钉断言点 ｜ 计数与执行记录对账 ｜ 写操作 Network 核对 ｜ **截图已同帧视觉检**（工作流 §3.0）｜ UI 文案减法已记。  
- **落账前四问（硬）**：① 被测入口本轮已定位（`入口指纹` ui/network/contract 三选一）？② 证据可开且钉断言点？③ 结果态按 `classification.md` §0.4（未定位禁写「入口不存在」）？④ 写操作 METHOD+path **且回查字段=值**？四问未过不落账；通过不得只凭“没报错”。  
- **模块档派发**：`B-Vx-xx`/卷、模块、分析/计划/执行记录路径、并行组/隔离套/写域、capabilities 绑定（及基线 §8 索引指针）摘录（不附整本）、证据目录、返回格式（模块小结素材）；子代理只写本模块执行记录与证据；**子代理自带浏览器工具**（绑定表登记套中已挂载者），编排**不**代点浏览器。  
- **编排核验（模块档）**：文件在、逐条落盘、计数一致、抽查失败证据；通过后进入下一模块（或并行批下一批）。  
- **并行（适当提效）**：见 §1.5「并行与隔离」——只读/生成 draft/隔离执行套可并行（≤3）；同 MCP 实例需支持独立会话/路由或独占实例；**共享** browser profile / 账号 / 写域 → **必须串行或隔离**。

### 1.1.1 冒烟前置闸（功能装填/专项轮 · 开跑纪律）

> 等价企业「提测冒烟 / 冒烟准入」：装填轮开跑前先做**数据准备（⓪）**再跑冒烟行（suite=core），判定是否值得展开——防「主链路已断仍跑装填域」的白跑（见本文件与 `skills/test-execution-and-exploration/SKILL.md`）。
> 冒烟判定行 = 各模块执行记录 §1.1「P0/P1 核心冒烟集」中标 **P0 冒烟** 的行（每模块 ≥1；跨模块 E2E 含 1 条；无标法时取每模块主链路首条）；已脚本化优先**脚本档**。  
> 适用：功能装填/专项（**≠** 每迭代 suite=full）。探索式/接口/发布前按各轨契约。  
> 轮次：R0 冒烟(core) → R1 装填域(module；发版/完整项目 full) → R2+ 回归；准出对照计划 §3。  

| 段 | 纪律 |
| --- | --- |
| ⓪ 数据准备 | `confirm_execution_scope` 后扫**本批装填域**前置三件套；缺者集中造齐；**未齐不进冒烟**。已齐或小批（≈≤20 条）→ 免集中造数段，但须在执行记录「数据准备」写结论（已齐 / 现场补造项+来源）；>20 且未齐 → 先集中造齐。 |
| ① 冒烟轮 | suite=core：先跑 P0 冒烟（脚本优先）；落账顺序 P0 冒烟 → P0 → … |
| ② 判定 | **全绿** → 转计划 §3 **装填域续跑**（suite=module；发版/完整项目/点名才 full；冒烟已终态不重跑）；**有失败** → §1.3 有界复核后按根因分流 ↓ |
| ②a 环境级 | 登录/站点/网关/基础数据不可得且穷尽 → **停轮**；修复后「继续」先复跑冒烟未过行 |
| ②b 产品级主链路 | 评估阻断面；被阻断下游记 `阻塞`；独立面照常跑装填域；修复后回归＝冒烟行＋被阻断组 |
| ②c 脚本漂移 | 修脚本重跑冒烟 |
| ③ 报告 | 冒烟写入【执行收尾】汇报段；此后回归按 `workflow.md` §3.1（原单+冒烟子集+影响面；禁默认全库重跑） |

- **条件放行**：用户点名「跳过冒烟 / 带病续跑」→ 放行，收尾须记「冒烟未跑/未过＋影响面」。  
- 冒烟行与装填域同标准落账留证；续跑不重跑已终态冒烟行。

### 1.3 准确度红线（易疏忽）

1. **真失败**：拟落失败须本轮走完 UI 主路径并见可见偏差；禁仅 list 探活即判失败。  
2. **写操作**通过/失败须本轮 Network 见过对应 METHOD+path；**UI 看似成功但主业务请求非预期异常 → 记失败并附【接口判定】**；禁纯 API 冒充页面结论。点名菜单/页面的用例：须 **E1**（浏览器 MCP/脚本 UI；UI 证据等级 E1/E0）；未走 E1 不得写 pass/fail/待实现终态（接口轨或入口本就纯 API 除外）。菜单 JSON/前端包扫=**E0**，只可辅助。HTTP 404/405 终态按 `classification.md` §0.4（被测入口自身 vs 前置不可达），禁混标。  
3. 失败摘要/截图**钉断言点**；通过可不强制截图；**凡已截目标页 → 同帧视觉检**（工作流 §3.0），禁截完只当留证不看界面。  
4. **阻塞判定**（运行时；终态表=`classification.md` §0.4）：`blocked` 仅限**非产品缺陷**的前置/外部不可用（过渡态）。**默认先打通再测**：造数/换样、建号/赋权、换角色/换入口/换账号、重置状态、基线选样。**缺数据/缺账号/临时权限不足 ≠ 直接 blocked**；任一自助手段仍可能打通 → **必须先做**，短路径通了继续测、**不开平台自指派单**。构造中暴露的被测缺陷记 `fail`。有界与 404 分界见 §0.4。  
   **升级（与 `classification.md` §0 同向）**：有界自助穷尽后仍卡 → AI 比成本并主推；需外力 → 平台**盯办**；现网≠硬 AC → `fail`。**禁**一遇卡点就 blocked；**禁**为进平台把本当 blocked/本地准备的项改标 `fail`；**禁**把门禁正确仅缺种子开成「改门禁」实现缺陷。  
   **blocked 四问（逐项过；①②任一为「能」→ 先打通再测，不得写 blocked；④ 未达有界 → 不得写 blocked）**：① 能否造数/换样/建号？② 能否换入口/角色/账号/赋权？③ 是否被测入口自身缺陷（→`fail`，见 §0.4）？④ 互异手段与总尝试是否已达有界且摘要含已尝试+恢复条件（§0.4）？  
5. **链式阻断**：上游缺陷致链路不可建且**无法换样/绕过** → 下游记 `blocked` 且摘要点名上游用例与根因（禁重复记 `fail`）；可换样/可独立执行的面照跑，禁套 blocked。上游数据已落库或另有可换样本 → 换样执行。全量轮冒烟未过的阻断面按 §1.1.1②b 处置。  
6. 已在目标页且未漂则续测，勿无故重登。  
7. **一条一写（全档通则）**：逐条落盘、禁攒批；失败证据落约定目录且叶名含 caseId。  
8. **选样与冲突**：造数/换样/改权前——①查基线**样本节**（命中 → list 核对 ENABLED；无 → 构造）②查**造数/冲突节** ③筛选全净；写 400/唯一性先查冲突节；有新可复用信息收尾按基线**同步规则**回写，无则禁改基线（节号以实例为准；模板常样本§14/造数§11/同步§12）。  
9. **状态先后**：同一样本上既有负向阻断探测又有正向写操作 → **先负向**（写后状态已变，负向结论不可再得）；被写操作改变状态的实例不得跨条按变更前口径断言——后续用例须换样或新建实例，禁沿用旧断言面落终态。  
10. 同方案无效 2 次换路径：**换根因假设或验证手段，禁同命令空重跑**。  
11. **审查范围**：只报影响正确性/需求覆盖的缺口；不追风格偏好、不为假想场景要求加防御（防过度设计）。  
12. **脚本失败升级**（脚本档）：`fail` 先按**有界复核**（`rules/special/script-execution.md` §3：一次为限、同批同因合并、可定性即停）复核再定性；结论=产品/实现缺陷→落 fail；脚本漂移/执行器问题→修脚本重跑；环境问题→按环境处理。**禁**脚本失败直接交平台，**禁**为凑复现率反复深挖。  
13. **意图是覆盖底线，不是执行天花板**：三步序与禁只读分析见 execute 步骤卡 / §6 执行技能。可按本轮原文+构建新增边界/路径/工具/数据，不得删 P0/负向、不得静默降范围；新增意图回写分析 §2.1。旧用例/旧边界只作线索。影响 Oracle/范围/准出 → 一次一问；不私改断言凑绿。  
14. **额外发现 / 视觉**：用例外 UI/UX/console/network → 记位置/现象/证据/影响；截图顺带视觉检见 §1.1 自查与工作流 §3.0；能复现进缺陷，不静默忽略，不替代用例结果。  

### 1.4 子代理边界（全档）

- 不 git / 不交平台 / **不改他模块文件 / 不写 test-plan·test-report·主执行记录**；模块档与直跑档只写本模块执行记录与证据；拆分档 Worker 仅写 DraftPath。  
- 派发提示必含：对应契约 must 要点、模块、批次、caseId、路径、`DraftPath`（拆分档）、绑定隔离套/写域及本批相关节摘录（**不附整本**）。  
- 编排回收核验：文件在、落盘完整（模块/直跑档＝执行记录逐条；拆分档＝jsonl 齐全后合并）、计数一致、`result` 合法；失败则同回合补跑；不采信口头完成。

### 1.5 子代理编排（决策树 · 阈值 · 并行 · 降级 · 派工）

> **短口径入口**：`../collaboration/subagents.md`（§0 实例生命周期硬表 + 档位摘要）。本节为决策树/并行详版。  
> 目的：高收益处隔离上下文并**适当并行**提效；**不盲目拆**。净收益＝上下文卸载＋墙钟加速＋质量增益−（重复读取＋合并核验＋漂移风险）。  
> 原则：**先脚本/工具 → 再决策树取档**；宿主无子代理能力 → 全程直做并收尾注明；分片/模块/核验实例生命周期见 `subagents.md` §0。

#### 1.5.1 取档决策树（自上而下，命中即停）

1. 已脚本化且非复核 → **脚本档**  
2. 用户点名强制档 → 从其点名  
3. 接口轨 / 入口本就纯 API → **单 Agent**（轨契约）  
4. 宿主无 Task/子代理 → **直跑档**（`subagent=unavailable`）  
5. 口令「继续」且本批装填域 = **1 个模块** → **直跑档**（合法；不强制为拆而拆）  
6. 同轮开跑装填域 **≥2 个模块**，或单批 >35 意图 → **模块子代理档 / 拆批**（阈值唯一出处：`subagents.md` §2）  
7. 单模块 ≈>20 条，或P0/写密集/长链，或需独立核验，或用户点名 → **拆分档**  
8. 其余单模块小批 / 探索小场 → **直跑档**

**派工前 3 问**（仅用于**未达**上表阈值时的可选拆分；**不得**用来否决已命中的第 6/7 步）：① 脚本/校验器能否完成？② 单元独立且写集不相交（含生成物/配置/迁移/测试数据/账号/端口/profile；或只读）？③ 合并核验机械且返回 ≤30 行？三问皆否 → 维持直跑。

#### 1.5.2 触发阈值（**执行档位阈值不在此重复**：唯一出处 `collaboration/subagents.md` §2）

| 场景 | 阈值 | 取档 |
| --- | --- | --- |
| 执行档位（脚本/直跑/模块子代理/拆分/批次容量） | 见 `collaboration/subagents.md` §2 | 按该表 |
| 报告对账 | 执行记录/证据计数、可打开性 | **脚本优先**；仅语义归因派核验子代理 |
| 大范围调查 / 分析扇出 | ≥20k token 或 ≥5 文件/来源 | **只读扇出**（可并行≤3）；主上下文只收摘要 |
| 同一文件/同一条用例/同一单据/共享写域 | — | **禁并行写** |

达阈值默认拆；若合并成本高于收益、共享资源无法隔离或用户点名直做 → 可直做/串行，收尾记 `deviation=subagent_skipped:<理由>`（`unavailable`/`user` 除外须写清）；未达阈值但 2 个高价值独立单元净收益为正也可拆。

#### 1.5.3 并行与隔离

> **决策序**：① 工具/脚本能做 → 不派子代理；② 能直跑 → 不拆；③ 已拆 → 写集不相交才可并行，否则串行；④ UI 默认串行，绑定互斥隔离套 + 写域不交叉才并行。**子代理 ≠ 并行**。

| 类型 | 可否并行 | 条件 |
| --- | --- | --- |
| 只读侦察/文档抽取/证据核对 | **可** | 并发 ≤3；返回各 ≤30 行 |
| 生成分片（各写不同 `.draft/{域}`） | **可** | 并发 ≤3；**禁**并行写同一正式域文件 |
| 模块子代理执行（UI） | **默认否** | 共享页面状态/写域 → 串行；仅当只读、独占 tab、不改登录态/页面状态，且 MCP 支持独立会话/路由或独占 server → 可并行 |
| 模块子代理执行（隔离套） | **可** | 绑定已登记互斥隔离套 + 计划同 PG + 账号/写域不交叉；并发 ≤ 套数且 ≤3；UI 默认 ≤2 |
| 计划 §3 批次（显式并行组） | **可** | 同 PG + 隔离套/账号/写域不交叉；未列 PG 默认串行；冲突记 `plan_batch_conflict` |
| 脚本档多标签/多 plan（无 UI） | **可** | 写域/库表不冲突；冲突则串行 |
| 拆分档 Worker∥Reviewer | **否** | 同回合串行：Worker 完 → **新开 fresh** Reviewer（禁 resume Worker；见 `subagents.md` §0） |
| 跨会话 | **可** | 共享可写状态串行或隔离；MCP 无独立会话/路由 → 串行 |

- **共享写域**：文件/生成物/锁/迁移/schema/全局配置/路由/索引/tokens/DB/测试数据/账号/端口/profile/下载目录/外部单据 + MCP 会话/登录态/页面状态；任一共享可写 → 串行或隔离套。性能/压测窗口不并行 UI。
- 并行冲突/污染 → 立即串行并记偏差；不把并行失败当产品失败。

#### 1.5.4 失败降级（不可让）

出现任一项 → **同回合降级直做/串行补齐**，禁空转重派同一方案：

- 超时 / deadline / 无产物 / 返回空  
- `rules=violation` 或 `scope=over` 且无法当场收敛  
- 连续 2 批负收益（返回 >30 行、合并冲突、返工、主上下文回读原始证据、超范围）

收尾：`deviation=subagent_degraded:<timeout|empty|violation|neg_roi>`；产物以编排直做结果为准。不为「多 Agent」而拆；不把确定性校验交给 LLM。

#### 1.5.5 扇出读 · 汇聚写 · 派工 · 回收

- 读可扇出；写须单写手或文件集不相交；同一执行记录/模块执行记录/报告/计划/单据禁并行写。  
- 判断、终态、门禁、平台回写、合并结论留在编排；子代理不得过 `hitl`/`gate`、不得 git/交平台/改他模块。  
- 分片生成只写 draft；编排合并后跑一次意图覆盖/深度检查；子代理不改主执行记录。  

**派工包（7 项，缺一不派）**：①任务与验收（含 `B-Vx-xx`/卷/模块）②边界（允许路径/写域/隔离套/并行组）③输入节选（**不附整本**）④规则摘录 3～5 条＋契约路径 ⑤输出契约 ⑥返回 ≤30 行固定字段 ⑦禁止事项（git/平台/门/超范围/同命令空重跑）。

**回收**：文件在、逐条落盘、计数一致、`result` 合法、证据可打开；规则回执 `rules`/`scope`/`evidence`；不采信口头完成；批末核验通过再下一批。

**上下文卫生**：主上下文只留派工/返回/核验摘要；子代理不通读整本；delta-only；Reviewer 不收 Worker 推理（防锚定）；失败同回合重测 ≤1，同方案无效 2 次换路径。

**成本批末一行**：`batch | mode | units | parallel | returns≤30 | conflicts | rework | verdict=keep|direct|degraded`。

## 2. 批流（拆分档）

```text
`confirm_execution_scope` → Draft → Worker 一批 → 同回合 fresh Reviewer（新开；禁 resume Worker）
→ 格式问题当场改 → 不可信则同回合重测≤1
→ 合并执行记录 → 下一批（默认新开 Worker）或失败汇总 → 工作流 §4
```

禁止 Worker↔Reviewer 多轮乒乓。仍不通 → 失败/阻塞落账后下一条。无对应场景 的额外发现执行中可 ≤4 行，其余进执行记录/§4。

**修正边界**：只可当场修正笔误与编排侧文案；终态判定与证据问题须回修（重测/重拍），不得以改文案替代；误报嫌疑或证据缺失且无法闭环 → 停止并报告。

### 2.1 续跑 · 回归 · 结论卫生

- **续跑（「继续」）**：额度/中断后接未完成；沿用本会话 `DraftPath`、`confirm_execution_scope` 与本轮 runId；不重跑已有**本轮**终态行；已读稳定规则不重贴（delta-only）。  
- **新 run / 换构建开跑**：装填内→重置 `未执行`（或仅修改/rerun）；装填外旧通过/失败→`未本轮验证`；准出只计 §1.1。路径 `{workroot}/{ver}/{轨}/{NN}-{短名}-执行记录.md` 或 `*-执行记录.md`。  
- **回归执行（「回归 / 重跑 {全量|域|条目}」）**：按点名范围**重测既有场景**；结果**就地覆盖**本轮执行记录行与证据（验证构建=本轮）；**只保留最新确认结论，不写过程**；旧轮留档仅用户点名（轨内 `_archive/`）。与缺陷轨「平台单回归」不同轨。  
- **计划驱动连续回归**：每个缺陷修复后立即回归，不等批末；范围＝原单复测＋冒烟子集＋影响面组（计划 §5.2）；P0/连环缺陷提示升级；结果就地覆盖本轮行，报告 §3/§4 汇总。  
- 缺终态（拆分档 jsonl / 模块·直跑档执行记录行）时先对账页面/Network：已成功 → 补写结果；未成功 → 定点重测——**禁未对账直接重复写操作**。未出 §4 先补 §4；不自动开其它模块；全量 draft 与 `S-*` 互不接力。  
- 续跑中途不退程、不关调试 Chrome。

### 2.2 MCP（纪律）

绑定与选型 SSOT：`{workroot}/capabilities/00-能力清单.md` 槽 `browser-automation`（别名 `browser-mcp`）及按需 `{workroot}/capabilities/bindings/browser-automation.md`；`env-baseline.md` §8 **仅索引**。接口轨可不启用。纪律总则见 `rules/capabilities/instance-discipline.md`。

**稳态（执行默读）**：

- **选用**：清单 `启用=是`；按 `kind`/绑定取**优先套**（须当前 agent 已挂载）；占用/并发 → 绑定表内其它已挂载空闲套，收尾记 `browser_mcp=`；表外实现 → 停问。  
- **未挂载**优先套 → 请用户重载/装配后继续（可改用绑定内其它已挂载套，仍须记 `browser_mcp=`）。  
- **`kind=mcp` 且端口未开（工具在、仅连不上浏览器）≠ 未挂载**：仅本轮确有 UI 任务时，按绑定「拉起命令」拉起（只替换绑定内端口/profile），轮询 `{browserUrl}/json/version` ≤15s → 原会话重试；仍失败 → Restart 本行 MCP 一次；再失败 → 停报。  
- **`kind=skill-cli`**：按绑定/实现手册；不适用 CDP 则勿套拉起 Chrome 句。  
- **自愈边界（不可让）**：只限「按绑定拉起」「Restart 本行 MCP」、以及改用绑定表内已挂载空闲套；**禁**改表外端口/profile/server/impl、禁杀占用进程、禁改宿主配置与清单选型。  
- **中断与续跑不关浏览器、不退程**；会话重启后先恢复页上下文再 snapshot，禁默认整页重开。  
- 跨模块：复用浏览器进程 ≠ 复用页面上下文；须重新 snapshot、核对模块/路由/登录域与 Network。  
- **禁**反复 `new_page`、禁关他模块页、禁执行中为救红点关浏览器。  
- **全链终局退程（不可让）**：本轮若已拉起/使用调试浏览器，须在**本任务链全部结束后**退程关闭（关 tab 不够）。「全部结束」＝执行结论已确认，且缺陷协作、入库提交、点名部署等后续均已做完或明确不做。由最后一步收尾角色退程（通常 `report-agent` / `handoff`）；若仍进 defect / `confirm_platform` 待确认 / 入口即止将续跑 → **延后不退**。下次按绑定再拉起。本轮未用浏览器 → 不操作。  
- **退程怎么做**：优先执行绑定文件「退程命令」（只替换端口/profile）；无退程命令时按绑定可复现方式结束**本套**调试 Chrome 进程（禁杀他套/日常浏览器）。退程后核 `{browserUrl}/json/version` 应连不上或进程已退出。  
- **运行态可见（不可让）**：凡本轮用过浏览器或拉起过进程/工具，完整【执行收尾】/【任务收尾】必须有独立「运行态：」行（见 `closeout-skeleton.md`）；态只许：`已退程`｜`延后·{允许原因}`｜`仍在运行`｜`未用`。允许延后原因仅：`待进defect`｜`confirm_platform待确认`｜`入口即止将续跑`｜`用户要求保持`。禁把「忘了退程」写成延后。  
- **残留须明示**：`仍在运行`（含退程失败/未执行退程且无合法延后）→ 第 4 点必有一行供拍板（关闭 / 保持），建议默认「关闭」；禁静默残留。合法 `延后·…` 可不进第 4 点，但「运行态：」必须写清仍开着。声称已退程但核验仍可连 → 改标 `仍在运行` 并列入第 4 点。

**异常点读**（仅红点/无工具/端口失效/多套并行冲突时再读；**禁**顺跑预防性通读）：

- **红点**：Settings 本行 MCP 红点/报错 → 只 Restart 该 MCP，**禁止**因此关调试浏览器；同端口占用同样禁关浏览器/换端口。  
- **同会话排障**：Restart 后先在本会话核对工具列表与端口；仍无工具 → **停止并请用户** Restart/重载后说「继续」；**禁止**规则驱动的无差别「新开对话」空转。  
- **端口**：失效有限等待，禁无限等待与静默切换。  
- **多套/跨会话并行**：默认正常改项目；共享可写状态只一个写会话；同一 MCP 按隔离能力与冲突面判断，需独立会话/请求级路由或每 worker 独占 server 进程才可并行，否则串行；绑定内互斥字段自检不过 → 停止报告。终局只退**本套**，禁动他套。

## 3. 过程输出

**启动**：`route=workflow:testing | step=execute | agent=test-orchestrator | next_action=… | DraftPath=… | 模块=…`；计划驱动加 `plan={workroot}/{ver}/test-plan.md | phase=P0～P9 | batch=B-Vx-xx | track=功能/接口/探索式/发布前/回归`。

**Worker jsonl（拆分档 · 每行）**（脚本档同格式：由 `{workroot}/scripts/executor.mjs` 产出，附 `source=script`；合并规则同下表）：

```json
{"caseId":"…","result":"pass|fail|blocked|na|pending","summary":"…","evidencePaths":[]}
```

fail：`summary` 写清现象+关键路径/主键；禁密钥。  
`pending`=**方案/AC/计划范围内应实现而未实现（菜单无入口且无接口）**（实现缺陷，计入缺陷并进入批次提交；非外部阻塞）。入口存在但 404/500/空壳/假成功→`fail`。明确范围外/后续池→`na`，不标 pending。**禁止**「方案未写死数值但系统已有实现规则」→ pending；此类须先探查现网口径再判 pass/fail（工作流 §3.0）。

**jsonl `result` → 执行记录结果（拆分档合并必用）**

| jsonl | 执行记录结果 |
| --- | --- |
| `pass` | 通过 |
| `fail` | 失败 |
| `blocked` | 阻塞 |
| `na` | 不适用 |
| `pending` | 待实现 |
| 缺行 / 无合法 `result` / `todo`（同义容忍） | **未执行**（先对账补写或定点重测，禁止默认为通过） |

合并时按上表写结果列；计数六态与工作流 §4 一致；**`pending`=待实现（实现缺陷），计入缺陷合计，必须进入批次提交**。由 AI 按 jsonl 汇总执行记录 §2；模块结论仍由 AI 按专规补写。模块结论含「待实现」时：任一条 `pending` 且无 `fail`/`blocked` 主导风险 → 模块结论可用「待实现（实现缺陷）」；有失败则「失败」优先。

**模块档/直跑档自查**：执行者按 §1.1 自查清单逐项过，输出一句自检结论（并入模块小结/失败汇总）。

**Reviewer（拆分档）**：模块/batch/verdict；计数；当场修改；当场重测（≤1）；核对失败是否人可复现、证据是否钉断言点。

**合并一句**：`已合并 → 执行记录=… | 本批计数 | 累计通过率=P%（通过/总数）| next_action=…`

**失败/阻塞/待实现行成稿**：落盘当时（拆分/脚本档在复核或合并时）按执行记录失败详情槽位成稿（功能 §2 / 接口 §3）；槽位与厚度真源：`defect-writeup-template.md` **§5.0.1a / §5.0.1b**；素材=本轮实测+evidence（全码同步），缺则当场补采；禁空壳、禁留到缺陷轨回补、禁交平台时现查补事实。

**失败汇总**（并入 report·§3）：条数 + 一句摘要 + 交平台建议；是否交平台只在 report 问一次；不拉平台、不改状态。

终稿：工作流 §4。

## 4. 计划驱动编排（跨轨 · 唯一编排口径）

> 适用：口令「按计划执行 / 执行测试计划」，或计划已确认的多轨执行。计划 §3 是轮次/并行真值、§4 是准出真值；单轨口令仍按 §1～§3。  
> 原则：**计划定阶段/轨道/依赖/门禁；阶段内仍按对应轨契约与四档执行；不跨轨通读**。

### 4.1 角色与真值

- 编排（`test-orchestrator`）逐阶段推进；每阶段只读当前轨契约（功能/探索式、接口、发布前），不预读其它轨。
- **批次真值**：计划 §3 批次表是计划驱动执行的批次/并行/子代理真值；§1.5 决策树用于未列入批次或批次内取档。两者冲突时隔离/写域红线优先，回退并记 `deviation=plan_batch_conflict`。
- 计划 §5.2 回归、§5 缺陷、§2 探索；执行记录/证据为真值。
- 过程状态落 `{workroot}/{ver}/test-plan.md` §0/§6（阶段/状态/偏差/阻塞）；正式对照落报告 §2，不把过程写成正式结论。

### 4.2 阶段执行与门禁

> **SSOT**：阶段/轮次/入口/出口/门禁只认 `rules/templates/10-planning/test-plan-template.md` §3～§4（与 `rules/workflow.md` §3.6 同步）。本文不重复大表；改编排先改计划模板，再对工作流/本节指针。

- **不跳阶段**；计划标注并行的阶段可按 §4.3 并行；未标注默认串行。  
- 未列/不适用的阶段由计划写明（如无接口/无 UAT），不默认全做；跳过须有依据。  
- P2 功能 = **装填域**（suite=module；发版/完整项目才 full）；≠库内全文件必跑；冒烟分流见 §1.1.1。  
- P7 UAT/P8 发布前/灰度若由业务/Ops 执行，编排只协调与收证，不冒充执行。  
- 阶段出口未过 → 停在该阶段或按阻断面分流；不得静默降范围/跳下游。  

### 4.3 并行与隔离

- 阶段/轨道并行：仅计划 §3 批次表/§3 并行标注「可并行」；细则与子代理并发见 **§1.5.3**。  
- **一次一个 PG**：PG=一个并发波次；同一时刻只跑一个 PG，PG 内并发 ≤3；下一 PG 等本波合并核验后再开。  
- **同一条用例禁并行**；共享写数据/同一业务主键 / 共享 browser profile → 串行。  
- 接口/非功能可与功能并行（不共享写域、构建稳定）；探索可在对应面稳定后穿插；回归随修复触发。  
- 有隔离套时模块子代理可并行（§1.5.3）；冲突/污染 → 立即串行，记录偏差。  
- 未列入计划 §3 的批次默认串行；确需并行须先补批次表/并行组并确认隔离，不得先跑后补。  

### 4.4 缺陷-回归闭环

`fail → 定性/查重 → 提交（计划 §5 策略）→ 开发修复 → 回归（原单+冒烟子集+影响面组）→ 关闭/激活 → 执行记录/报告更新`

- 优先 P0 冒烟 脚本 + 受影响模块用例；未受影响用例不重跑；新功能/变更按迭代用例执行。  
- 提交策略见 `rules/defects/collaboration.md` §6.1（计划 §5）。  
- P0/连环缺陷 → 提示升级（模块局部全量/扩大邻接回归），用户确认后执行。  
- 同因不重复提交；同批修复合并一次回归；结果就地覆盖只留最新。  

### 4.5 探索式穿插（细节/体验深挖 · Q14）

- 按计划 §2/分析 §2/§3：一场只领状态=本场的那一条；会话记录→debrief→分流（含沉淀清单）。不替代功能装填。  
- 探索纳入计划则闭环（已跑=非空记录+检查点结论，Q18）；不替代功能/接口覆盖。  
- 分流：产品缺陷→缺陷+回归；覆盖缺口→补用例/补风险面；误报→记录。  
- 探索式不脚本化；证据按会话留；收尾写风险面完成/覆盖/缺口；不替代功能装填/准出范围。  

### 4.6 停止/恢复/变更

- 停止：P0 冒烟 未过、环境不可用、数据/合规风险、计划实质偏差 → 按计划 §4 暂停或回计划门。  
- 恢复：先复跑冒烟未过项，再续未完成阶段；不重跑已终态。  
- 计划变更：范围/准出/排期/缺陷策略变更 → 更新计划并回计划门；小改就地记录在报告偏差。  
- 未授权提交/计划外提交 → 仍按 `confirm_platform`；禁以「计划驱动」为由绕过确认。
