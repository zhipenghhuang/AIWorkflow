# 多轨质量标准（测试轨）

> **单一出处**：功能 / 接口 / 发布前 / 探索式（及计划外随机）的共用质量门槛与准出组合。各 `tracks/` 只写本轨细节，不得低于本文。
> **原则**：来源对账 · 意图完整 · P0 深度 · 证据先于结论 · 不静默降档 · 缺口显式 · 发现问题优先于通过率。
>
> **迭代完整（硬 · 本期范围）**：差量 + 影响面 + 回归内——方案每一个应测细节/设计点入账（规则/字段/状态/权限/入口/异常/配置/NFR/UI/布局/文案/提示/空态等）；覆盖面矩阵与方法矩阵（等价/边界/判定/状态/场景/算例等）无未接受空格；功能 ≥`module`；接口 depth ≥`standard`（整轨否仅 §0 白名单）；T1+ 探索章程闭环；发布前必须纳入（性能·安全·兼容硬映射；深度按风险分级）；范围内 P0/P1/P2 意图全终态。整轨「否」只认 §0 白名单事实 + 接受人。
> **发版完整**：suite=`full` + depth=`full`（接口轨纳入时）+ 发布前按风险分级硬映射 + 探索 T1+ ≥4 章程。
> **补丁口径**：才允许 suite/depth=`core` 且发布前可按计划裁剪；不得冒充迭代/发版准出。

## 0. 轨道纳入（迭代/提测 · 硬）

> **读法**：纳入默认硬；弹性只在 suite / depth / 风险级与**维·项级**裁剪。开放理由（小改 / 无文档 / 时间紧 / 功能已测）= 禁止。计划 §2「纳入=否」须同时满足：白名单事实句 + `接受人=`。

| 轨道 | 迭代默认 | 整轨「否」仅当（白名单） | 弹性落点 |
| --- | --- | --- | --- |
| 功能 | **必须纳入** | 无（无行为面则改准出口径/补丁，不写「否」冒充迭代准出） | suite≥`module` |
| 接口/契约 | **必须纳入** | 已核实：**无**服务端 / HTTP / RPC / WS / 消息契约面（无 XHR·fetch·WS、无 OpenAPI/契约、无后端）。**禁**：「无接口文档」「UI 已测」「Network 顺手看过」「内嵌探针」 | depth≥`standard`；维级可 `不适用+依据` |
| 回归 | **必须纳入** | 本期零变更且零邻接影响 + 接受人（极少） | R2 范围宽窄 |
| 探索式 | **T1+ 必须纳入** | 仅 T0/补丁口径，或**无运行时交付**（纯文档包）+ 接受人。**禁**：「功能测完」「无可探索面」 | 章程数；轴可「书面不测+接受人」（≠整轨否） |
| 发布前 | **必须纳入** | 仅永不部署且无运行时客户端/服务面 + 接受人。**禁**：「小改」「无 NFR」「本期不做性能」「无运行时变更」 | 风险级=基础/标准/高；**项**可硬映射缺口+接受人；三专项方案/报告须建 |
| 迁移/回滚 | 有升级/存量则纳入 | 无升级路径且无存量 → N/A+依据 | 可并入发布前 |
| UAT/灰度 | 有上线签字则登记 | 无上线验收流程 → 登记不适用 | 责任人/证据；本包不冒充已测 |

**钉死**：① UI 内嵌 API 探针 ≠ 接口轨完成（须 `api/` 记录+depth）。② 文档未写 NFR ≠ 发布前免测。③ 单项裁剪 ≠ 整轨取消。④ 探索轴「不测」≠ 整轨 N/A（T1+）。⑤ 补丁口径才可整轨裁探索/降 suite·depth=`core`。

## 2. 分轨执行深度

### 2.1 功能 / 专项

| 档 | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅补丁/热修且报告标明“补丁口径” | P0 冒烟 + 窄影响面 |
| `module` | 迭代/提测默认 | 命中意图 + 逐邻接影响面 + P0 深度 + 必要视觉/UI；本期应测细节/方法矩阵无未接受空格 |
| `full` | 发版/完整项目/大版本 | 范围内模块全跑 + Q12 全范围 |

### 2.2 接口（depth）

| depth | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅 T0/补丁口径 | 命中写/关键读的 P0 维可执行+脚本（或 N/A+依据） |
| `standard` | 迭代/提测默认 | 命中接口的适用维可执行+脚本（或 N/A+依据） |
| `full` | 发版/完整项目/点名 | 范围内全部必测接口 × 全部适用维可执行+脚本 |

### 2.3 发布前（性能 · 安全 · 兼容；迁移按适用）

| 风险级 | 何时 | 最低 |
| --- | --- | --- |
| 基础级 | 小改/低风险 | 性能·安全·兼容契约最小集 + 硬映射无空 |
| 标准级 | 版本级/多模块 | 标准级最小集 + 硬映射 + 指标有目标值/来源 |
| 高风险级 | 资金/权限/数据/公共 API/大促 | 高风险级最小集 + 硬映射 |

- **硬覆盖映射**：每条必测面 → `方案章节 | 工具/跑次 | 结果(达标/未达标/缺口)`；空行=未完成。性能/安全/兼容各自有方案+报告（或索引指向）。
- **迭代/提测（非补丁）**：计划 §2 发布前必须纳入并完成硬映射；整轨「否」仅 §0 白名单 + 接受人。发版：按上表风险分级完成硬映射。补丁：可按计划裁剪并标明「补丁口径」。
- 风险分级见 `tracks/pre-release.md`。裁剪项写入硬映射「缺口」+ 报告并由用户书面接受；安全 critical/high 未闭环不得发布/迭代准出通过。小改 → 仍纳入，风险级用**基础级**（不是整轨否）。

### 2.4 探索式（T1+ 纳入）

| 档 | 何时 | 最低 |
| --- | --- | --- |
| 建议 | 补丁/T0 或 §0 允许整轨 N/A | 可独立跑一场；章程一句 + 会话记录；发现可复现或写「无」 |
| 计划纳入 | T1+ / 版本级（非补丁） | ≥3 条章程（T2/T3 ≥4，≤6）；必选轴 S6/S7/S11/状态误读至少各 1 条或书面不测；一轮一文件 |
| 准出引用 | 报告引用探索结论 | 结论须可复现/有证据；T1+ 未闭环不得准出 |

### 2.4.1 P2 功能收口探针（T1+）

| 轴 | 最小探针 | 通过条件 |
| --- | --- | --- |
| S6 入口/可见/失败下一步 | 失败/不适用时是否给出原因或下一步 | `INT-…`/章程/不测+接受人，三选一 |
| S7 门禁假可点/禁用原因/全选≠确认 | 命中确认/发布/启用面至少一项 | 有可指到的意图/章程/不测+接受人 |
| S11 提示/空态/同源一致 | 空态/错误提示不误导；多载体 KPI/状态/术语一致 | 有可指到的意图/章程/不测+接受人 |

> 三行任一未填 = P2 出口未过；只写模块名不算。

### 2.4.2 全意图闭环

- 分析 §2.1 中每个 `处置=测` 的 P0/P1/P2 意图，必须进入执行记录 §3 并形成终态。
- P1/P2 未测不能用“低优先级/下版”跳过；确有范围外/N/A，必须在分析中写依据+接受人。
- 报告 §2.2 意图结论表与执行记录一致；无未测（或未测有接受人）。

### 2.5 随机业务流程

计划外；不参与准出，不进计划，不调度于「按计划执行」。不得用随机结果替代功能/接口/发布前覆盖或准出。

## 3. 准出组合条件

| 准出口径 | 功能 suite | 接口 depth | 发布前 | 探索式 | 分析/计划 |
| --- | --- | --- | --- | --- | --- |
| **迭代/提测可准出** | ≥`module`（命中+邻接+上下游；细节/方法矩阵无缺口） | ≥`standard`（整轨否仅 §0 白名单+接受人） | 必须纳入；硬映射完成或缺口已接受；整轨 N/A 仅 §0 白名单+接受人 | T1+ ≥3 章程且必选轴闭环；整轨 N/A 仅 §0 | 已确认；全部意图终态；S6/S7/S11 有落点 |
| **发版/完整项目可发布** | `full` | `full`（接口纳入时） | 按风险分级最小集完成 + 硬映射无未接受空行 | T1+ ≥4 章程且必选轴闭环 | 已确认 + 发布门槛 + 全部意图终态 |
| **补丁口径** | `core`+窄面 | `core` 可 | 按计划；未跑标明 | 不强制 | 标“补丁口径”，不得冒充版本准出 |
| **仅 core / 仅接口 P0 维未声明补丁** | — | — | — | — | 不得称迭代/版本可准出 |

有条件通过：仅限 P0 全过 + 非 P0 缺口用户书面接受 + 报告列遗留/接受人/复审点。
> **点/场景门槛**：P0/负向/计算类意图结论 100%；P0/P1/P2 均须有终态；未结论/未执行不计通过；场景通过率不得替代意图结论率；报告以发现问题与缺口为准。

## 4. 反模式（禁止）

- 用「软覆盖」空话代替来源/意图/AC 设计点账本。
- 用「有没有接口面 / 无接口文档 / UI 已测」跳过接口轨；或用功能内嵌 API 探针冒充接口轨。
- 用「小改 / 无 NFR / 本期不做性能 / 无运行时变更」整轨取消发布前；小改应降风险级为**基础级**，不是整轨否。
- 用「功能测完 / 无可探索面 / 时间紧」取消 T1+ 探索整轨。
- 迭代准出仍按接口「只跑 P0 维」且不声明 depth=`core`/补丁。
- 未纳入发布前或硬映射未闭环却称迭代完整（性能·安全·兼容任一空映射=缺口）。
- 发布前无指标目标值却写「达标」；或一句「非功能 OK」代替三专项硬映射。
- 无来源/Oracle 却称意图完整；或只读分析摘要不回原文对账。
- 随机/探索结论冒充功能或发版准出。
- 静默降 suite/depth/风险级，或口头改准出不回写计划。
- 非本轮场景仍显示「通过」并计入报告通过率。
- 同一意图跨轨重复记通过/失败，导致通过率虚高。
- 用配置缺失的绿色页面、空样本或页面取整冒充通过。
- 只有百分比没有分母、公式与独立复算。
- 为抬通过率删除负向/边界/入口/幂等场景，或把假成功判为通过。
- 用 P1/P2“低优先级”跳过未测；或把 P0 裸写成唯一覆盖口径。
- 只测改动模块，不测上游/下游/共享数据/核心链路却称迭代完整。
- 把探索/随机上轮记录当功能式常青库复跑。
- 迭代只测模块标题主路径，方案字段规则/门禁/入口/UI/文案等细节或方法矩阵未映射却称完整覆盖。
- 用「意图已终态/场景很少」掩盖未按深度档展开的边界/负向/状态/权限/适用维。
- 计划含接口轨时，仅在功能记录里顺手打 API、无 `api/` 契约记录+depth 适用维，却称接口已完成。
- 把「顺延/下批再看」写成覆盖完成；无接受人的顺延=缺口。
- 缺数据/账号不对/入口一时找不到就标阻塞，却未先自助造数/换样/换角/换入口。
