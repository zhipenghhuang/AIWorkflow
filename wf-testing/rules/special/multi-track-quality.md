# 多轨质量标准（测试轨 · 高质量门槛）

> **单一出处**：功能 / 接口 / 发布前 / 探索式（及计划外随机）的**共用高质量门槛**与**准出组合条件**。各 `tracks/` 只写本轨细节，不得低于本文。  
> **读取**：生成/执行/报告/准出前读本文当前相关节；勿通读他包。  
> **原则**：宁多勿漏（命中+邻接）· **发现问题与正确性优先于通过率** · 证据先于结论 · 无来源不写断言 · 禁静默降档 · 缺口必须显式。  
> **漏测谱系**：生成/探索/随机错误推测见 `defect-findings-spectrum.md`（S1–S13）；勿在各轨复制长表。  
> **轨清单非穷尽**：功能/接口/发布前/探索/随机为常用轨；新专项按同质量门槛挂载，禁把本文轨名当成唯一合法路径。  
> **依据覆盖 / UI 证据 E1·E0**：细则 SSOT 见 `rules/core/verification.md` §3.1.1；本文只定准出组合与分轨深度。

## 1. 共用硬门槛（所有正式轨）

| # | 门槛 | 不满足则 |
| --- | --- | --- |
| Q0 | 已有 `{workroot}/test-analysis.md` 且 **§0 Brief+差量表** 已确认（或本轮明示不适用+依据） | 禁宣称「本期已对齐/可准出」；生成前先 analyze |
| Q1 | 用例/方案/断言可追溯到主读或分析表（RQ/AC/F/R/TP/章/接口） | 禁臆造预期；无来源标 GAP 或问清 |
| Q2 | P0-Smoke / P0-HighRisk / GATE / 阻断项未过 → 不得整体通过（P0 刻度见 `core/verification.md` TEST-VER-02） | 报告门 FAIL |
| Q3 | 覆盖映射无空行：有点必有用例 ID 或「不适用+依据」 | 禁称已覆盖 |
| Q4 | 可脚本化确定性用例：**同轮产出脚本**或书面不可脚本化理由 | 接口/功能 P0 默认未完成 |
| Q5 | 评审：T1+ 落地产物须选 A/B；进准出的接口/纳入计划的发布前·探索式不得跳过 | 禁「未审即准出」 |
| Q6 | 报告声明本轮 `runId/构建` + `suite` + 各轨 `depth`/风险级 + 装填域 + 本轮实测计数 + 缺口清单 | 缺声明不得准出 |
| Q7 | 准出只认本轮装填；`未本轮验证` 不计通过率；目录按 §1.3.0（`*-功能|接口用例/台账`，发布前带专项前缀） | 光秃用例.md / 旧通过冒充本构建 → 不得称已对齐 |
| Q8 | 同一验证点只在一个阶段/轨/卷出结论；他处经过只作前置/造数，引用结论不重算通过率 | 通过率虚高/重复计通过 → 报告门 FAIL |
| Q9 | 负向/禁止类要求有可观测反向断言；配置/样本/权限前提有“前提缺失不得显示合格/不计分母/不催办”断言 | 覆盖缺口，不得称完整 |
| Q10 | 统计/评分/占量/能力指数有最小分母集 + 独立复算；页面取整不得单独作为通过依据 | 不得称“统计可复算/准出” |
| Q11 | **常青库 ≠ 本轮列车**：inbound **ACTIVE** 方案/契约须有**功能/接口**域常青资产（可执行用例或「不适用+依据」）；计划可不装填，**禁**整版空库/永不生成。装填与 CI 扳机见 `release-train-load.md`。**不含**探索戳夹/随机会话（见 Q13） | 以「本期不测」删库或空域冒充完整 → 不得称库已对齐 |
| Q12 | **方案细节完整映射**：范围内每个可验收细节（字段规则/门禁/入口/提示/状态跃迁/对象级明细）有验证点或「不适用+依据」；写操作含终态重复调用或幂等断言（谱系 S1–S4）；命中特征须满足 `testcase-design` §2.2（含同源多表面、确认门禁负向）；**禁**标题级映射或「有汇总即覆盖」；**禁**为抬通过率删负向/边界 | 仅主路径绿、细节空映射或深度档缺行 → 不得称迭代/完整已覆盖 |
| Q13 | **探索常青 ≠ Domain 常青**：探索轨常青的是目录纪律+SBTM+谱系选题方法；单轮戳夹非常青库。章程须按 §0×本项目近窗缺陷簇×谱系重选（`tracks/exploratory.md`）；禁把上轮 EXP 原样当本轮全量 | 冻章程复跑 / 探索冒充域库装填 → 不得称探索已跟实战面 |
| Q14 | **细节/体验深挖（P4）准出硬门**：T1+ 迭代/提测与 T2+/发版（非补丁口径）须计划纳入 P4（§12）；最少章程数与必选轴见 §2.4；每条待办有会话证据或「不测+理由+接受人」；稳定发现须分流补功能/接口 Domain（或写下轮） | §12 空表、跳过 P4、或只写「探索通过」→ 不得称迭代/发版可准出 |

## 2. 分轨执行深度

### 2.1 功能 / 专项

| 档 | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅补丁/热修且报告标明「补丁口径」 | P0-Smoke + 窄影响面 |
| `module` | **迭代/提测默认** | 命中域 + **逐邻接影响面**（宁多勿漏）+ **范围内方案细节无空映射（Q12）** + 视觉/UI 基础 + 覆盖三闸 |
| `full` | 发版/完整项目/大版本 | 范围内 Module 全跑（含邻接策略按计划）+ Q12 全范围 |

### 2.2 接口（depth）

| depth | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅 T0/补丁口径 | 命中写/关键读的**高风险维**可执行+脚本（或 不适用+依据） |
| `standard` | **迭代/提测默认**（有接口在范围时） | 命中接口 × **全部适用维**均有可执行用例+脚本（或 不适用+依据）；覆盖对照禁空 |
| `full` | 发版/完整项目/点名 | 范围内全部必测接口 × 全部适用维可执行+脚本 |

> 对照表可先列全维；**迭代执行默认 standard**。仅补丁口径才允许停在 depth=`core`。

### 2.3 发布前

| 风险级 | 何时 | 最低 |
| --- | --- | --- |
| 基础级 | 小改/低风险且计划选用 | 契约最小集全做完 + **硬覆盖映射**无空 |
| 标准级 | **版本级默认**（不确定上靠） | 标准级最小集全做完 + 硬映射 + 指标有目标值与来源 |
| 高风险级 | 资金/权限/数据/公共 API/大促 | 高风险级最小集 + 硬映射 |

- **硬覆盖映射**：每条必测面 → `方案章节 | 工具/跑次 | 结果(达标/未达标/缺口)`；空行=未完成。 
- 裁剪须写入报告并由用户书面接受；禁静默不做。  
- 安全 critical/high 未闭环 → 不得发布通过。

### 2.4 探索式（含细节/体验深挖 · P4）

> **定位不变**：不替代功能/接口全量与 Q12；专挖不便固化的误读、提示/空态、入口下一步、门禁假可点、跨载体状态冲突等。T1+ **不得**用「未列探索」静默跳过准出深挖。

| 档 | 何时 | 最低 |
| --- | --- | --- |
| 建议（仅 T0/补丁） | 补丁口径或 T0 且计划未纳入 | 可独立跑一场。章程一句 + 会话记录；发现可复现或写「无」。未跑**不降低**功能 suite / 接口 depth |
| **准出强制（T1+）** | 迭代/提测默认；T2+/发版同 | 计划 §12 **必填**。章程数：T1 ≥**3**、T2/T3 ≥**4**（仍 ≤6）。**必选轴**（每轴 ≥1 条章程，或该轴「不测+理由+接受人」）：①入口/可见/失败下一步（S6）②提示/空态诚实（S11）③状态误读或跨载体冲突 ④门禁假可点/禁用原因（S7；无 UI 门禁面可 N/A+依据）。选题回溯 §0 / 缺陷簇 / 谱系。本场条有会话证据；其余待办下场或不测+理由（留空=未闭环）。一轮一戳夹。已稳定进功能/接口负向的不重复挖 |
| T3 / 准出引用 | 报告引用探索结论 | 须评审放行（A/B）后才可写入准出依据 |

> 成败看可复现发现与缺口。不要求功能轨深度档，不计入功能覆盖三闸。适用 Q13/Q14。  
> **沉淀（硬）**：debrief 须写「拟补功能/接口 Domain」清单（caseId/主题）或「无稳定可沉淀」；禁止只留观察、下轮无着落。

### 2.4.1 功能 P2 出口 · 谱系细节核对（不另开阶段）

P2 装填收口前，命中域须对 **S6 / S7 / S11**（及 Q12 已要求的入口/提示/门禁）逐项标明：`已映射功能用例`｜`已排入 §12 章程`｜`不测+接受人`。三空任一未填 = P2 出口未过，不得宣称功能阶段完成或进入准出倒计时。

**最小探针（硬 · 防空表）**：写「已映射」时，处置列须能指到用例/章程 ID，且该条覆盖下表对应探针（无该 UI 面 → `不测+接受人` + 一句依据；禁只写模块名）。

| 轴 | 最小探针（命中则至少一条） |
| --- | --- |
| S6 | 失败/不适用时下一步诚实（有原因或动作，禁假可点空转） |
| S7 | 勾选/全选≠确认仍可提交；或禁用入口无原因；或不可比/不适用仍诱导可点——命中域有确认·发布·启用面时至少覆盖其一 |
| S11 | 空态/错误提示不误导；或同源 KPI/状态/术语跨载体一致——命中域有多载体展示时至少覆盖其一 |

### 2.5 随机业务流程

计划外；**不参与准出，不进计划，不调度于「按计划执行」**。办结判定与分流见 `tracks/random-flows.md`（含谱系 §3 四件：办错或看错业务状态才开缺陷）。不得用随机结果替代功能/接口/发布前覆盖或准出。

## 3. 准出组合条件（报告门对齐）

| 准出口径 | 功能 suite | 接口 depth（范围含接口时） | 发布前 | 探索式（P4·Q14） | 分析表 |
| --- | --- | --- | --- | --- | --- |
| **迭代/提测可准出** | ≥`module` + P2 出口 S6/S7/S11 核对齐 | ≥`standard` | 计划未列可不跑；已列则映射完成或缺口已接受 | **强制**：§12 达 §2.4 条数/轴；待办闭环（会话或书面不测） | §0 已确认 |
| **发版/完整项目可发布** | `full` + 同上 P2 核对 | `full` | 按风险级最小集完成 + 硬映射无未接受空行 | **强制**（同左；报告引用探索结论须已评审） | §0 已确认 |
| **补丁口径** | `core`+窄面 | `core` 可 | 按计划；未跑须标明 | 不强制（建议一场） | §0 或补丁说明 |
| **仅 core / 仅接口高风险维未声明补丁** | — | — | — | — | **不得**称迭代/版本可准出 |

有条件通过：仅限 P0-Smoke/P0-HighRisk 全过 + 非 P0-Smoke/P0-HighRisk 缺口用户书面接受 + 报告列遗留/接受人。

> **点/批次门槛**：P0/GATE/负向/计算类验证点结论 100%；计划 §3.9 批次合并通过；未结论点/未合并批次不计通过。用例通过率不得替代点结论率。

## 4. 生成与评审强制面

| 产物 | 生成后 | 进准出前 |
| --- | --- | --- |
| 功能/专项 | 覆盖三闸 + T1+ A/B 评审 | 本轮装填对应评审已放行（合卷或单域卷） |
| 接口 | 按 `api-test-case-template.md` + 对照禁空 + depth 可执行/脚本 + `validate_api_testcase.py` | T1+ 或进准出 → A/B 评审（I1–I6） |
| 发布前方案/报告 | 硬映射表齐 | T2+ 或发版准出 → A/B 评审 |
| 探索式（T1+ 计划必纳 / Q14） | §12 条数·轴达标；本场章程一句 + 会话；待办有交代；沉淀清单 | T2+ 或准出引用 → A/B 评审 |

**评审批次**（细则 `工作流` §2.5）：默认按本轮装填成卷；同轨同主读可多域合卷；跨轨不合卷；未放行域禁入执行装填。

## 5. 反模式（禁止）

- 用「软覆盖」空话代替映射表空行。  
- 迭代准出仍按接口「只跑高风险维」且不声明 depth=`core`/补丁。  
- 发布前无指标目标值却写「达标」。  
- 无分析表 §0 却称多轨已对齐本期。  
- 随机/探索结论冒充功能或发版准出。  
- 静默降 suite/depth/风险级。  
- 非装填行仍显示「通过」并计入报告通过率。
- 同一验证点跨轨重复记通过/失败，导致通过率虚高。
- 用配置缺失的绿色页面、空样本或页面取整冒充通过。
- 只有百分比没有分母、公式与独立复算。
- 新资产不用域夹、或用光秃 `用例.md`/`方案.md`；功能/接口文件名不带「功能/接口」区分。
- 每个域夹机械强制单独一整套 A/B（同轮同主读应合卷）；跨轨硬合卷；未审域混进执行装填。
- 把「计划排除 / 有界对照 / 非本轮重点」写成常青库整版空域，或用本轮未装填证明「无用例需求」。
- 用全量回归占用 PR 冒烟事件，或冒烟红仍宣称 suite=`full` 可准出（列车纪律见 `release-train-load.md`）。
- 为抬高通过率删除负向/终态/入口/门禁用例，或把假成功判为通过。
- 把探索/随机上轮戳夹当功能式 Domain 常青复跑，或跨版本默认复用未重选的 §12。
- 迭代只测模块标题主路径，方案字段规则/门禁/入口细节未映射却称「迭代已完整覆盖」。
- P2「已映射」无用例 ID、或不含 §2.4.1 最小探针却称功能阶段完成。
- T1+ 空着 §12 / 跳过 P4 / 无 S6·S7·S11 核对却称迭代可准出；或探索发现只记观察、不补功能/接口 Domain。
