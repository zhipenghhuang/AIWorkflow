# 多轨质量标准（测试轨）

> **单一出处**：功能 / 接口 / 发布前 / 探索式（及计划外随机）的共用质量门槛与准出组合。各 `tracks/` 只写本轨细节，不得低于本文。
> **原则**：来源对账 · 意图完整 · P0 深度 · 证据先于结论 · 不静默降档 · 缺口显式 · 发现问题优先于通过率。

## 1. 共用硬门槛（所有正式轨）

| # | 门槛 | 不满足则 |
| --- | --- | --- |
| Q0 | `test-analysis.md` 已确认：来源盘点/章节回执/依据覆盖/AC 设计点账本/意图/风险/覆盖矩阵/方法矩阵/细节维/影响面/核心链路无未接受缺口；`test-plan.md` 已确认 | 禁称“本期已对齐/可准出” |
| Q1 | 每个意图可追溯主读/AC/契约/用户裁决；Oracle 有来源；执行以原文对应段为准，分析只作索引，不作 Oracle 来源 | 禁臆造预期；无来源标 GAP 或问清 |
| Q2 | P0 未过 → 不得整体通过（P0 以分析 §2.1 为准，执行记录优先级不一致无效） | 报告门 FAIL |
| Q3 | 来源项每个有意图或「N/A+业务依据+接受人」；**来源计数须被账本行数支撑，空表不算覆盖**；AC/设计点账本无未解释缺口；功能/接口执行记录 §0 原文对账行已填（可验收单元 N、已覆盖+补录≥N、未关0/接受人）；**每场景三步序：方案原文逐项 → 结合分析理解 → 现场择优（有互补源则对照；分析不作互补源；无则单源+理由+接受人）**；本轮范围来源条目有 INT/场景结论；P0 有不可接受失败/深度；覆盖矩阵/方法矩阵/影响面/核心链路无未接受空格且 INT 回指台账 | 禁称“已覆盖” |
| Q4 | 确定性/P0/接口可脚本化项：同轮脚本或书面不可脚本化理由 | 默认未完成 |
| Q5 | 计划门：分析 + 计划已确认；执行中范围/准出实质变化回计划门 | 未确认不得执行 |
| Q6 | 报告声明本轮 runId/构建 + suite + depth/风险级 + 意图/场景计数 + 缺口 | 缺声明不得准出 |
| Q7 | 准出只认本轮执行记录/锚点；`未执行`/`未本轮验证` 不计通过 | 旧通过冒充本构建 → 不得称已对齐 |
| Q8 | 同一意图只在一个轮次/轨出结论；他处经过只作前置/造数 | 通过率虚高/重复计通过 → FAIL |
| Q9 | 负向/禁止类有可观测反向断言；配置/样本/权限前提有“前提缺失不得显示合格/不计分母/不催办”断言；危险/占位/脏资产不得走正式发布或启用；不可比/不适用不得露出可点入口 | 覆盖缺口，不得称完整 |
| Q10 | 统计/评分/占量/能力指数有最小分母集 + 独立复算；单位/精度/整数约束/小数截断/日期先后/期限/时效有边界与拒绝语义；页面取整不得单独作为通过依据 | 不得称“统计可复算/准出” |
| Q11 | **锚点常青**：P0 冒烟 + 高价值锚点跨版本保留；旧执行记录随版本归档 |
| Q12 | **细节完整映射**：范围内每个可验收细节（字段规则/门禁/入口/提示/状态跃迁/对象级明细/资产治理/数据血缘/对象证据/当前版本/影响清单/关联候选/层级/数值单位时效）有意图或「N/A+依据」；P0/关键项有证伪或反向验证（按轨适用，不适用+依据）；写操作含终态重复调用/幂等断言（适用时） |
| Q13 | **探索方法常青**：命名纪律+SBTM+谱系选题；单轮记录文件非常青库；章程按本轮风险/缺陷簇重选 |
| Q14 | **探索触发与强制**：T1+ / 版本级（非补丁）必须有 ≥3 条章程（T2/T3 ≥4，≤6）或 N/A+业务依据+接受人；T0/补丁可 N/A；T1+ 未闭环不得准出 |
| Q15 | **全意图闭环**：分析中每个 `处置=测` 的 P0/P1/P2 意图必须在执行记录场景中出现且有终态；§3 只声明不跑场景不算；P1/P2 未测不等于可跳过 | 缺任一 → 报告门 FAIL |
| Q16 | **优先级不豁免**：P0/P1/P2 只是顺序/深度/门禁强度，不是覆盖裁剪刀；N/A 必须有依据+接受人 | 用低优先级跳测 → 覆盖缺口 |
| Q17 | **终态≠浅测**：意图终态须满足本轨深度档（功能见 §2.1/`testcase-design` §3；接口见 §2.2/`tracks/api`）。本批触及的设计点/适用维未落场景或未写「不适用+依据」=未覆盖。单条主路径/UI 内嵌 API 探针不得冒充完整。用户当轮要求全覆盖时，以 Q12+各轨 DoD 为准，禁止用「不预生成用例/条数少」降深度 | 浅打勾冒充覆盖 → 禁称已覆盖/可准出 |

## 2. 分轨执行深度

### 2.1 功能 / 专项

| 档 | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅补丁/热修且报告标明“补丁口径” | P0 冒烟 + 窄影响面 |
| `module` | 迭代/提测默认 | 命中意图 + 逐邻接影响面 + P0 深度 + 必要视觉/UI |
| `full` | 发版/完整项目/大版本 | 范围内模块全跑 + Q12 全范围 |

### 2.2 接口（depth）

| depth | 何时 | 最低 |
| --- | --- | --- |
| `core` | 仅 T0/补丁口径 | 命中写/关键读的 P0 维可执行+脚本（或 N/A+依据） |
| `standard` | 迭代/提测默认 | 命中接口的适用维可执行+脚本（或 N/A+依据） |
| `full` | 发版/完整项目/点名 | 范围内全部必测接口 × 全部适用维可执行+脚本 |

### 2.3 发布前

| 风险级 | 何时 | 最低 |
| --- | --- | --- |
| 基础级 | 小改/低风险且计划选用 | 契约最小集 + 硬映射无空 |
| 标准级 | 版本级默认 | 标准级最小集 + 硬映射 + 指标有目标值/来源 |
| 高风险级 | 资金/权限/数据/公共 API/大促 | 高风险级最小集 + 硬映射 |

- **硬覆盖映射**：每条必测面 → `方案章节 | 工具/跑次 | 结果(达标/未达标/缺口)`；空行=未完成。
- 裁剪须写入报告并由用户书面接受；安全 critical/high 未闭环不得发布通过。

### 2.4 探索式（T1+ 纳入）

| 档 | 何时 | 最低 |
| --- | --- | --- |
| 建议 | 补丁/T0 或计划未纳入 | 可独立跑一场；章程一句 + 会话记录；发现可复现或写「无」 |
| 计划纳入 | T1+ / 版本级（非补丁） | ≥3 条章程（T2/T3 ≥4，≤6）；必选轴 S6/S7/S11/状态误读至少各 1 条或书面不测；一轮一文件 |
| 准出引用 | 报告引用探索结论 | 结论须可复现/有证据；T1+ 未闭环不得准出 |

### 2.4.1 P2 功能收口探针（T1+）

| 轴 | 最小探针 | 通过条件 |
| --- | --- | --- |
| S6 入口/可见/失败下一步 | 失败/不适用时是否给出原因或下一步 | `INT-…`/章程/不测+接受人，三选一 |
| S7 门禁假可点/禁用原因/全选≠确认 | 命中确认/发布/启用面至少一项 | 有可指到的意图/章程/不测+接受人 |
| S11 提示/空态/同源一致 | 空态/错误提示不误导；多载体 KPI/状态/术语一致 | 有可指到的意图/章程/不测+接受人 |

> 三行任一未填 = P2 出口未过；只写模块名不算。

### 2.4.2 全意图闭环

- 分析 §2.1 中每个 `处置=测` 的 P0/P1/P2 意图，必须进入执行记录 §3 并形成终态。
- P1/P2 未测不能用“低优先级/下版”跳过；确有范围外/N/A，必须在分析中写依据+接受人。
- 报告 §2.2 意图结论表与执行记录一致；无未测（或未测有接受人）。

### 2.5 随机业务流程

计划外；不参与准出，不进计划，不调度于「按计划执行」。不得用随机结果替代功能/接口/发布前覆盖或准出。

## 3. 准出组合条件

| 准出口径 | 功能 suite | 接口 depth（范围含接口时） | 发布前 | 探索式 | 分析/计划 |
| --- | --- | --- | --- | --- | --- |
| **迭代/提测可准出** | ≥`module`（命中+邻接+上下游） | ≥`standard` | 计划未列可不跑；已列则映射完成或缺口已接受 | T1+ ≥3 章程且必选轴闭环；T0/补丁 N/A+依据 | 已确认；全部意图终态；S6/S7/S11 有落点 |
| **发版/完整项目可发布** | `full` | `full` | 按风险级最小集完成 + 硬映射无未接受空行 | T1+ ≥4 章程且必选轴闭环 | 已确认 + 发布门槛 + 全部意图终态 |
| **补丁口径** | `core`+窄面 | `core` 可 | 按计划；未跑标明 | 不强制 | 标“补丁口径”，不得冒充版本准出 |
| **仅 core / 仅接口 P0 维未声明补丁** | — | — | — | — | 不得称迭代/版本可准出 |

有条件通过：仅限 P0 全过 + 非 P0 缺口用户书面接受 + 报告列遗留/接受人/复审点。
> **点/场景门槛**：P0/负向/计算类意图结论 100%；P0/P1/P2 均须有终态；未结论/未执行不计通过；场景通过率不得替代意图结论率。

## 4. 反模式（禁止）

- 用「软覆盖」空话代替来源/意图/AC 设计点账本。
- 迭代准出仍按接口「只跑 P0 维」且不声明 depth=`core`/补丁。
- 发布前无指标目标值却写「达标」。
- 无来源/Oracle 却称意图完整。
- 随机/探索结论冒充功能或发版准出。
- 静默降 suite/depth/风险级。
- 非本轮场景仍显示「通过」并计入报告通过率。
- 同一意图跨轨重复记通过/失败，导致通过率虚高。
- 用配置缺失的绿色页面、空样本或页面取整冒充通过。
- 只有百分比没有分母、公式与独立复算。
- 为抬通过率删除负向/边界/入口/幂等场景，或把假成功判为通过。
- 用 P1/P2“低优先级”跳过未测；或把 P0 裸写成唯一覆盖口径。
- 只测改动模块，不测上游/下游/共享数据/核心链路却称迭代完整。
- 把探索/随机上轮记录当功能式常青库复跑。
- 迭代只测模块标题主路径，方案字段规则/门禁/入口细节未映射却称「迭代已完整覆盖」。
- 用「意图已终态/场景很少」掩盖未按深度档展开的边界/负向/状态/权限/适用维。
- 计划含接口轨时，仅在功能记录里顺手打 API、无 `api/` 契约记录+depth 适用维，却称接口已完成。
- 把「顺延/下批再看」写成覆盖完成；无接受人的顺延=缺口。
