# 细节设计覆盖清单（常青）

> **定位**：功能意图之外，逐维检查“设计文档/AC 没写死、但用户一定会遇到”的细节。用于分析、执行记录、计划门/报告门复核；不替代功能/接口覆盖。
> **原则**：设计/AC/原型明确写了 → 意图/场景；未写但影响可用性/一致性/判断 → 探索/补意图；影响主路径/数据正确/权限 → P0/P1。
> **通用性**：不绑定具体项目、模块、术语或实现；示例只作说明。

## 1. 十三维清单

| # | 细节维 | 必查问题 | 判定面/oracle 示例 |
| ---: | --- | --- | --- |
| D01 | 列表/筛选/搜索/排序/分页 | 条件组合、清空、重置、无匹配、超量、默认排序；筛选控件显示条件与实际请求是否一致；时间范围/时效/期限筛选是否自洽 | 结果集与条件一致；控件不回显过期条件；空态区分“无数据/无权限/无匹配”；日期/时段/时效边界正确 |
| D02 | 列/字段/长文本/候选表 | 列显隐、顺序、密度、超长截断、悬停全文、复制；候选/关联表是否过宽、难跟读；关键字段/必填星号/单位是否可见 | 列配置持久化；超长不撑破布局；可复制原值；候选表可搜索/筛选/分组；必填/单位/口径可见 |
| D03 | 空态/错误态/无权限/缺关系 | 空数据、加载失败、无权限、无匹配是否区分并可下一步；关联输入为空时是否说明缺什么 | 文案给原因+动作；不得把无权限写成无数据；空关系给补录/下一步，不只报错 |
| D04 | 状态与跨载体一致性 | 列表/详情/运行页/首页徽标、预览/撤回、停止/关闭/作废/重开；当前生效/已发布/已替代/停投/失效；历史/别名状态；同源 KPI/术语 | 同一对象多处状态·用词一致；终止后不显示进行中；状态刷新后正确流转；别名/历史类型归一 |
| D05 | 按钮/入口/位置/门禁 | 主次按钮、危险操作相邻、入口位置统一、禁用原因、诱导可点；占位/脏资产发布/启用是否拦截；改方案/记执行等覆盖型动作是否分区 | 禁用有可见原因或隐藏；占位资产不得走正式发布；危险操作需二次确认；保存/确认不覆盖已确认方案 |
| D06 | 交互反馈/连点/异步 | loading、禁用、重复提交、异步任务入口/进度/失败、分步未进阶；后端契约/状态码与前端提示是否同源 | 点击后状态自洽；失败/未进阶有可见原因；异步有任务入口可查；连点只生效一次；400/成功契约不得提示成另一种异步态 |
| D07 | 响应式/窄屏/长文本/层级 | 390px 宽、缩放、长名称、多语言；详情分区（如基础/明细/关系/状态）是否有清晰标题与顺序 | 关键动作不被挤出；可换行/折叠/吸底；分区标题可定位；层级不混排 |
| D08 | 文案/术语一致性 | 同一概念多叫法、错别字、提示是否给下一步；跨模块术语/编号/权限种子/路由是否可对应；徽标颜色/语义是否混淆 | 术语与方案/PRD 一致；提示含原因+动作；未定义关系先确认；同名不同义或同义不同名可发现 |
| D09 | 跳转/返回/刷新/上下文 | 跳转失效、返回丢状态、刷新后保持；关联对象/对账对象/来源是否可跳转；返回后筛选/滚动/上下文是否保留 | 目标存在且权限一致；刷新不丢筛选/页签；关联对象可追溯；返回保留上下文 |
| D10 | 批量/部分失败 | 混合合法/非法条目、部分成功、分条结果；批量转交/关闭/导出是否逐条返回 | 逐条返回结果；不得整体假成功或静默漏项；非法条目有原因 |
| D11 | 导出/下载/文件 | 超限转异步、任务入口、进度、失败、危险/损坏文件、文件摘要；批量导出结果 | 异步有入口；危险/损坏文件不进正式版本；文件摘要/来源可查；失败可重试/下载 |
| D12 | 规则/配置/数值/时效 | 启用规则后新数据、标准化/发布后刷新、缓存；单位是否允许小数、整数是否拒绝小数；小数位/截断/四舍五入；采样/抽检间隔；日期先后、原/当前期限、时效/账龄；固定映射/校验配置 | 配置对新数据生效；整数单位不出现小数；小数不被静默截断；日期倒置拒绝；期限/时效可判定；未配置明确阻断 |
| D13 | 数据可信与可追溯 | 汇总/原始 JSON 之外是否有对象级明细/证据/下钻；计算/指标/样例的口径/来源/公式/版本/方法适用性；下线/回滚/停投/删除/关闭前是否点名当前生效版本/引用资产/影响渠道；认证/发布/撤销后后果与处理入口；文件摘要/受控版本元数据 | 能解释“数从哪来、怎么算、谁认证、影响谁”；只有汇总/JSON=缺口；方法不支持时提示而非静默降级；撤销后禁新引用/有停投说明；破坏性操作有影响清单 |

## 2. 用法

1. **分析**：逐维填 `适用/意图/判定面/依据`；不适用写业务依据；S6/S7/S11 同表。
2. **执行**：适用维至少 1 条场景；N/A 需理由；场景记录指到对应意图；可新增/替换。
3. **计划门/报告门**：逐维核“有没有、能不能判、证据在哪”；缺维=缺口。
4. **探索**：未写进设计的细节风险进探索章程；发现稳定后补意图/锚点。
5. **报告**：写“细节维覆盖 x/16、缺口清单”（D01–D13 + S6/S7/S11）。

## 3. 与功能/探索的划分

| 情形 | 归属 |
| --- | --- |
| 设计/AC/原型明确要求（含筛选条件、列、状态、权限） | 意图/场景（覆盖） |
| 设计未写，但属同一功能面的可用性/一致性/边界体验 | 探索式，发现后回填意图/锚点 |
| 影响数据正确、权限、主路径、资金/合规 | 直接升意图 P0/P1 |
| 纯文案/视觉偏好 | 探索式或产品评审，不单独立 P0 |
