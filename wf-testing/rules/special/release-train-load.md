# 发布列车装填（速查）

> **用途**：把「库完整」与「本轮跑什么」拆开；计划 §3.7 / 执行 / CI 只读本页，不另造平行体系。  
> **对齐**：市面 smoke → regression → release；GitHub Actions 常见 **PR 冒烟 / 合入或定时回归 / 发版全量**。  
> **细则**：质量门槛见 `multi-track-quality.md`；分层词见计划模板 §3.6～§3.7。

## 1. 两层模型（硬）

| 层 | 是什么 | 不是什么 |
| --- | --- | --- |
| **常青库** | `functional/`·`api/` 等域主档；对 inbound **ACTIVE** 方案/契约有可追溯用例 | 本轮必跑全集 |
| **本轮列车** | 计划 §3.7 装填 = suite + 命中域 + 批次 | 库的子集；裁剪≠删库 |

**禁止**：用「本期不测 / 有界对照 / 非本轮重点」把某 ACTIVE 整版方案写成库内空域或永不生成。  
**允许**：计划 §2 排除、§3.7 不装填该域；库内仍须有域主档（至少 P0-Smoke/主链可执行条，或「不适用+依据」占位并挂 ISSUE）。

## 2. suite ↔ CI 扳机（通用映射）

| suite / depth | 本轮最低 | 建议 CI 扳机（实例自选，非母版强制） |
| --- | --- | --- |
| Core / `core` | `smoke-checklist` + P0-Smoke | `pull_request` / 每次构建；目标数分钟级 |
| Domain 命中 / `module`·`standard` | 命中域 + 邻接 | 合入 `main` 或变更路径触发；可 `needs: smoke` |
| 发版 / `full` | 范围内 Module/接口维全跑 + 发布前风险级 | `workflow_dispatch` / tag / 发版门；贵套避免与 PR 重叠 |

> 贵套（全回归、发布前）勿与 PR 冒烟同事件重复跑；失败证据 `if: always()` 上传；分支保护只认**具名** gate job。

## 3. 变更 → Delta → 装填（一条链）

1. 产品/开发变更或 `handoff` 变更通知 → 分析表 **§0 差量**（有 ID 则对账，禁口头替代）。  
2. 差量 → 计划 **§3.7** 命中域 + 层（Core/Domain/Delta）+ suite/depth。  
3. 生成：命中域**增量**保 caseId；新 ACTIVE 无域文件 → 冷启动首生进常青库。  
4. 执行：冒烟未绿不进本轮全库；装填外标 `未本轮验证`，不计准出。

## 4. 迭代 vs 完整项目（覆盖完整 · 同质量）

| 口径 | 库 | 列车 | 细节完整 |
| --- | --- | --- | --- |
| **迭代/提测** | 命中+邻接域常青更新；ACTIVE 不空域 | suite≥`module`（禁默认可准出用 core） | 本期主读**每个**可验收单元有点/用例或不适用依据；谱系风险面按命中裁剪 |
| **发版/完整项目** | 范围内 ACTIVE 域齐 | suite=`full` + 接口 `full` + 发布前风险级 | 同上且高频谱系在 P0/回归有代表；探索章程覆盖高风险差量 |

> 细节漏测对照 `defect-findings-spectrum.md`；完整=映射无空+深度达标+装填跑完，≠「条数多/通过率高」。

## 5. 一眼自检

- [ ] ACTIVE inbound 方案均有域资产或显式不适用依据  
- [ ] §3.7 写清跑哪些；未写的不默认「库不存在」  
- [ ] 范围内方案细节点已映射（非仅主路径）  
- [ ] P0 可脚本项有脚本或书面不可脚本化理由  
- [ ] CI/脚本门与 suite 档一致，未静默降档
